فرض کن دستگاهت تمام شده و داخل سقف کاذب نصبش کرده‌ای تا چراغ‌ها را کنترل کند. یک هفته بعد یک باگ پیدا می‌کنی. بدون ابزارهای این درس باید نردبان بیاوری، سقف را باز کنی و لپ‌تاپ را با کابل USB بالا ببری. این درس دومین درس از سه درس مسیر «اسکچ سرگرمی» تا «دستگاه واقعی» است. OTA (آپدیت بی‌سیم) را یاد می‌گیری تا برنامه جدید را از پشت میزت و از طریق Wi-Fi بفرستی، و LittleFS را، یک سیستم فایل کوچک داخل حافظه فلش ESP32 که صفحه وب، تنظیمات و لاگ در آن هم از قطع برق جان سالم به در می‌برند و هم از برنامه جدید. در این مسیر می‌بینی حافظه فلش چطور به پارتیشن‌ها تقسیم شده و برگشت خودکار (Rollback) چطور تو را از یک آپدیت خراب نجات می‌دهد.

  • از برگشت خودکار استفاده کنی تا آپدیت خراب خودبه‌خود به نسخه قبلی برگردد
  • فایل را در حافظه فلش بنویسی، به آخرش اضافه کنی، بخوانی و فهرست بگیری، و صفحه وب را از LittleFS سرو کنی
  • برای هر نوع داده بین Preferences، LittleFS و کارت SD انتخاب کنی

آپدیت بی‌سیم (OTA)، برنامه‌ریزی بدون کابل

دستگاهت را داخل سقف کاذب نصب کرده‌ای تا چراغ‌ها را کنترل کند. یک هفته بعد یک باگ پیدا می‌کنی. بدون OTA باید نردبان بیاوری، سقف را باز کنی، لپ‌تاپ را با کابل USB بالا ببری. با OTA (Over-The-Air، «از راه هوا») برنامه جدید را از پشت میزت، از طریق همان Wi-Fi، روی برد می‌ریزی.

OTA پشت صحنه چطور کار می‌کند؟ (پارتیشن‌ها)

حافظه فلش ۴ مگابایتی ESP32 مثل یک هارد دیسک به چند «پارتیشن» تقسیم شده است. نقشه این تقسیم را در منوی Tools › Partition Scheme انتخاب می‌کنی. نکته کلیدی OTA این است: برای آپدیت امن باید دو جای برنامه (app0 و app1) وجود داشته باشد. برنامه جدید در جای خالی نوشته می‌شود، در حالی که برنامه فعلی هنوز در حال اجراست. فقط وقتی دانلود کامل و سالم تمام شد، یک «یادداشت» کوچک (پارتیشن otadata) عوض می‌شود که «از دفعه بعد از جای دیگر بوت کن». اگر وسط آپدیت برق برود، برنامه قدیمی دست‌نخورده باقی است.

وقتی برنامه بزرگ می‌شود (Wi-Fi + بلوتوث + HTTPS)، خطای Sketch too big می‌گیری و بسیاری از آموزش‌ها می‌گویند «Huge APP را انتخاب کن». آن کار خطا را برطرف می‌کند ولی OTA را برای همیشه می‌کشد، چون فقط یک جای برنامه دارد. برای دستگاهی که OTA لازم دارد، Minimal SPIFFS را انتخاب کن: برنامه تا ۱٫۹ مگابایت و OTA سالم. فقط فضای فایل به ۱۲۸ کیلوبایت کم می‌شود که برای یک صفحه تنظیمات کافی است. یادت باشد تغییر Partition Scheme فقط با آپلود USB اعمال می‌شود.

روش اول: ArduinoOTA، آپلود از خود Arduino IDE

کتابخانه ArduinoOTA داخل core است. برد را روی شبکه «اعلام» می‌کند (با mDNS، همان درس ۴.۲) و روی پورت 3232 منتظر برنامه جدید می‌ماند. اول فایل secrets.h درس ۴.۱ را کامل‌تر کن؛ این نسخه همه رمزهای این درس را دارد:

#pragma once
#define WIFI_SSID "MyHomeWiFi"
#define WIFI_PASS "my-strong-password"
#define OTA_PASS  "ota-pass-2026"      // رمز آپدیت بی‌سیم
#define WEB_USER  "admin"              // نام کاربری صفحه آپدیت وب
#define WEB_PASS  "change-me-now"      // رمز صفحه آپدیت وب
#define NTFY_TOPIC "home-alert-7f3k9q" // اسم Topic ی ntfy: حدس‌ناپذیر
  1. رمز Wi-Fi. همان دو خط درس ۴.۱. یک فایل رمز برای همه برنامه‌های درس‌های ۵.۵ و ۵.۶؛ هر برنامه فقط خط‌هایی را که لازم دارد استفاده می‌کند.
  2. رمز OTA. کسی که این رمز را نداند نمی‌تواند برنامه برد را عوض کند. OTA بدون رمز یعنی هر کسی که به Wi-Fi تو وصل است (مهمان، همسایه‌ای که رمز را دارد، یک گوشی آلوده) می‌تواند هر برنامه‌ای روی دستگاهت بریزد.
  3. نام کاربری و رمز صفحه آپدیت وب. برای روش دوم، کمی بعدتر در همین درس. جدا از رمز OTA، تا اگر یکی لو رفت دیگری امن بماند.
  4. اسم Topic ی ntfy. برای بخش هشدار به گوشی در درس ۵.۶. همین حالا اضافه‌اش می‌کنیم تا همین یک فایل برای هر دو درس کافی باشد. در ntfy.sh اسم Topic خودش حکم رمز را دارد؛ پس جای آن هم در secrets.h است.
#include <WiFi.h>
#include <ArduinoOTA.h>
#include "secrets.h"             // WIFI_SSID، WIFI_PASS، OTA_PASS
#ifndef OTA_PASS                 // اگر در secrets.h نبود، هشدار بده
#warning "OTA_PASS is not defined in secrets.h"
#define OTA_PASS "change-me"
#endif

const int LED_PIN = 4;

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) {   // برای سادگی؛ نسخه پایدار در درس ۴.۱
    delay(500);
    Serial.print(".");
  }
  Serial.printf("\nIP: %s\n", WiFi.localIP().toString().c_str());

  ArduinoOTA.setHostname("esp32-kitchen");  // اسم در منوی Port
  ArduinoOTA.setPassword(OTA_PASS);         // بدون رمز، هر کسی می‌تواند فلش کند
  ArduinoOTA
    .onStart([]() { Serial.println("OTA start"); })
    .onEnd([]() { Serial.println("\nOTA done, rebooting"); })
    .onProgress([](unsigned int done, unsigned int total) {
      Serial.printf("OTA %u%%\r", done * 100 / total);
    })
    .onError([](ota_error_t err) { Serial.printf("OTA error %u\n", err); });
  ArduinoOTA.begin();                       // از اینجا به بعد منتظر آپدیت است
  Serial.println("OTA ready");
}

void loop() {
  ArduinoOTA.handle();                      // هر دور: «آپدیت نیامده؟»
  static unsigned long last = 0;            // چشمک بدون delay (درس ۳.۱)
  static bool on = false;
  if (millis() - last >= 500) {
    last = millis();
    on = !on;
    digitalWrite(LED_PIN, on);
  }
}
  1. کتابخانه ArduinoOTA. جزو core است، نصب لازم ندارد. WiFi.h را هم لازم داریم چون OTA روی شبکه کار می‌کند.
  2. محافظ #ifndef. اگر در secrets.h خط OTA_PASS را ننوشته باشی، کامپایلر یک هشدار نارنجی نشان می‌دهد و رمز موقت change-me گذاشته می‌شود. برنامه با secrets.h قدیمی درس ۴.۱ هم کامپایل می‌شود، ولی هشدار یادت می‌اندازد که رمز واقعی بگذاری. هشدارهای کامپایلر را هرگز نادیده نگیر.
  3. وصل شدن به Wi-Fi. نسخه ساده برای کوتاه ماندن مثال. در دستگاه واقعی از نسخه پایدار درس ۴.۱ با سقف زمان و اتصال دوباره خودکار استفاده کن. OTA بدون Wi-Fi کار نمی‌کند.
  4. setHostname. اسم برد روی شبکه؛ همان چیزی که در منوی Port می‌بینی. اگر اسم ندهی، چیزی مثل esp32-a0b1c2d3e4f5 (بر اساس MAC) می‌گیرد. وقتی سه دستگاه در خانه داری، «esp32-kitchen» خیلی بهتر است. فقط از حروف کوچک انگلیسی، عدد و خط تیره استفاده کن.
  5. setPassword. رمز OTA. Arduino IDE موقع آپلود آن را از تو می‌پرسد. در core 3.3 احراز هویت OTA با SHA-256 است (نسخه‌های قدیمی MD5 داشتند که دیگر امن حساب نمی‌شود). اگر نمی‌خواهی رمز خام در برنامه باشد، از setPasswordHash با هش SHA-256 رمز استفاده کن.
  6. رویدادها (Callback). چهار تابع کوچک برای شروع، پایان، پیشرفت و خطا. []() { ... } یک «تابع بی‌نام» (lambda) در C++ است (گوشه C++ درس ۵.۴ را ببین). در onStart در پروژه واقعی موتورها و رله‌ها را خاموش کن و فایل‌ها را ببند؛ چند ثانیه بعد برد ریست می‌شود و نباید چیزی نیمه‌کاره بماند.
  7. ArduinoOTA.begin. از اینجا به بعد برد روی شبکه اعلام حضور می‌کند و منتظر آپدیت است. باید بعد از وصل شدن Wi-Fi صدا زده شود.
  8. ArduinoOTA.handle در هر دور loop. بررسی می‌کند آیا کسی می‌خواهد آپدیت بفرستد. اگر loop جایی با delay طولانی یا حلقه انتظار گیر کند، OTA جواب نمی‌دهد و IDE خطای «No response from device» می‌گیرد. برای همین چشمک LED را با millis() نوشتیم، نه delay.

قدم‌به‌قدم: اولین آپدیت بی‌سیم

  1. بار اول حتما با کابل USB. برد هنوز کد OTA را ندارد، پس نمی‌تواند برنامه را از هوا بگیرد. برنامه بالا را مثل همیشه با USB آپلود کن. (Partition Scheme باید OTA داشته باشد؛ Default کافی است.)
  2. Serial Monitor را ببین. باید IP و OTA ready را ببینی.
  3. کامپیوتر و برد روی یک شبکه. لپ‌تاپ باید به همان مودم وصل باشد (نه اینترنت گوشی، نه شبکه مهمان مودم که دستگاه‌ها را از هم جدا می‌کند).
  4. پورت شبکه را انتخاب کن. کابل USB را جدا کن (یا بگذار بماند) و منوی Tools › Port را باز کن. زیر عنوان Network ports چیزی مثل esp32-kitchen at 192.168.1.50 ظاهر می‌شود. اگر نیست، ۳۰ ثانیه صبر کن و منو را دوباره باز کن؛ IDE هر چند ثانیه شبکه را می‌گردد.
  5. یک تغییر کوچک بده (مثلا 500 را 100 کن تا LED سریع‌تر چشمک بزند) و دکمه Upload را بزن. IDE رمز را می‌پرسد: همان OTA_PASS.
  6. نتیجه. نوار پیشرفت Uploading: [==== ] 45% را می‌بینی. بعد برد خودش ریست می‌شود و LED با سرعت جدید چشمک می‌زند. Serial Monitor شبکه‌ای وجود ندارد؛ برای دیدن پیام‌ها هنوز کابل لازم است (یا لاگ را از طریق وب یا MQTT بفرست).
مهم: هر برنامه جدید هم باید کد OTA داشته باشد

اگر برنامه‌ای را از هوا بریزی که ArduinoOTA.begin و handle ندارد (یا در setup گیر می‌کند، یا Wi-Fi اشتباه دارد)، این آخرین آپدیت بی‌سیم تو بود! دفعه بعد باید نردبان و کابل بیاوری. عادت کن: کد OTA را اول از همه در هر برنامه بگذار و قبل از فرستادن به دستگاه سقفی، آن را روی یک برد روی میز تست کن.

روش دوم: صفحه آپدیت در مرورگر (Update + WebServer)

ArduinoOTA فقط از داخل Arduino IDE و در همان شبکه کار می‌کند. گاهی می‌خواهی فایل برنامه را به کس دیگری بدهی (مثلا به مشتری) تا بدون نصب Arduino IDE آپدیت کند. راه حل: یک صفحه وب روی خود ESP32 که فایل .bin را می‌گیرد. کتابخانه Update (داخل core) نوشتن در پارتیشن دوم را انجام می‌دهد.

ساختن فایل .bin

  1. در Arduino IDE منوی Sketch › Export Compiled Binary را بزن (میان‌بر Alt+Ctrl+S).
  2. بعد از کامپایل، در پوشه پروژه یک پوشه build ساخته می‌شود و داخل آن پوشه‌ای با اسم برد (مثلا esp32.esp32.esp32). با Sketch › Show Sketch Folder بازش کن.
  3. چند فایل .bin می‌بینی. فایل درست همان است که اسمش فقط اسم‌پروژه.ino.bin است. فایل‌های .bootloader.bin، .partitions.bin و .merged.bin را برای OTA نفرست؛ آن‌ها برای فلش کامل با کابل هستند.
#include <WiFi.h>
#include <WebServer.h>
#include <Update.h>
#include "secrets.h"
#ifndef WEB_USER
#warning "WEB_USER/WEB_PASS are not defined in secrets.h"
#define WEB_USER "admin"
#define WEB_PASS "change-me"
#endif

WebServer server(80);

const char UPDATE_PAGE[] PROGMEM = R"HTML(
<!doctype html><meta charset="utf-8">
<h3>Firmware update</h3>
<form method="POST" action="/update" enctype="multipart/form-data">
  <input type="file" name="firmware" accept=".bin">
  <button>Upload</button>
</form>)HTML";

void handlePage() {
  if (!server.authenticate(WEB_USER, WEB_PASS)) {
    return server.requestAuthentication();          // پنجره نام کاربری و رمز
  }
  server.send(200, "text/html", UPDATE_PAGE);
}

void handleUploadDone() {                           // بعد از تمام شدن آپلود
  if (!server.authenticate(WEB_USER, WEB_PASS)) {
    return server.requestAuthentication();
  }
  bool ok = !Update.hasError();
  server.send(200, "text/plain", ok ? "OK, rebooting..." : Update.errorString());
  if (ok) {
    delay(500);
    ESP.restart();                                  // با برنامه جدید بالا بیا
  }
}

void handleUploadChunk() {                          // برای هر تکه از فایل
  if (!server.authenticate(WEB_USER, WEB_PASS)) return;
  HTTPUpload &up = server.upload();
  if (up.status == UPLOAD_FILE_START) {
    Serial.printf("Update: %s\n", up.filename.c_str());
    if (!Update.begin(UPDATE_SIZE_UNKNOWN)) Update.printError(Serial);
  } else if (up.status == UPLOAD_FILE_WRITE) {
    if (Update.write(up.buf, up.currentSize) != up.currentSize) {
      Update.printError(Serial);
    }
  } else if (up.status == UPLOAD_FILE_END) {
    if (Update.end(true)) Serial.printf("Done: %u bytes\n", up.totalSize);
    else Update.printError(Serial);
  }
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.printf("Open http://%s/\n", WiFi.localIP().toString().c_str());
  server.on("/", HTTP_GET, handlePage);
  server.on("/update", HTTP_POST, handleUploadDone, handleUploadChunk);
  server.begin();
}

void loop() {
  server.handleClient();
}
  1. کتابخانه Update. رابط ساده برای نوشتن برنامه جدید در پارتیشن OTA خالی. خود ArduinoOTA هم در پشت صحنه از همین کتابخانه استفاده می‌کند. ما فقط راه رسیدن فایل را (به جای IDE، مرورگر) عوض کرده‌ایم.
  2. صفحه HTML با فرم آپلود. enctype="multipart/form-data" یعنی «این فرم فایل می‌فرستد». R"HTML( ... )HTML" همان رشته خام درس ۴.۲ است. بدون enctype مرورگر فقط اسم فایل را می‌فرستد، نه محتوای آن را. accept=".bin" فقط پنجره انتخاب فایل را به فایل‌های bin محدود می‌کند (امنیت نیست، راحتی است).
  3. صفحه اصلی با رمز. server.authenticate نام کاربری و رمز را بررسی می‌کند؛ اگر غلط بود، requestAuthentication پنجره ورود مرورگر را باز می‌کند. صفحه آپدیت بدون رمز یعنی هر کسی در شبکه می‌تواند دستگاهت را صاحب شود. این احراز هویت ساده (Basic/Digest) روی HTTP رمزنگاری نشده است، پس فقط در شبکه خانگی مورد اعتماد استفاده کن و هرگز این صفحه را با Port Forwarding روی اینترنت باز نکن.
  4. server.on با دو تابع. برای آپلود فایل، WebServer دو تابع می‌خواهد: handleUploadChunk که برای هر تکه از فایل صدا زده می‌شود، و handleUploadDone که بعد از تمام شدن کل آپلود جواب را به مرورگر می‌فرستد. فایل bin حدود یک مگابایت است و RAM آزاد ESP32 حدود ۳۰۰ کیلوبایت. پس نمی‌شود کل فایل را اول در RAM گرفت؛ باید آن را تکه‌تکه (هر بار چند کیلوبایت) گرفت و فورا در فلش نوشت.
  5. شروع: Update.begin. در اولین تکه، پارتیشن OTA خالی آماده (پاک) می‌شود. UPDATE_SIZE_UNKNOWN یعنی «اندازه را نمی‌دانم، تا جای خالی هست بنویس». اگر پارتیشن OTA وجود نداشته باشد (Huge APP)، همین‌جا خطا می‌گیری و Update.printError علتش را در Serial چاپ می‌کند.
  6. نوشتن هر تکه. Update.write تکه را در فلش می‌نویسد و تعداد بایت نوشته‌شده را برمی‌گرداند. اگر عدد با اندازه تکه یکی نبود، یعنی نوشتن خراب شد. بررسی کن، حدس نزن.
  7. پایان: Update.end(true). بررسی می‌کند فایل کامل و سالم است (سربرگ و checksum برنامه) و اگر بود، otadata را عوض می‌کند تا دفعه بعد از برنامه جدید بوت شود. اگر فایل اشتباهی (مثلا یک عکس یا فایل merged) فرستاده باشی، همین‌جا رد می‌شود و برنامه قبلی سالم می‌ماند. این همان امنیت دو پارتیشن است.
  8. جواب و ریست. اگر خطایی نبود، «OK» را برای مرورگر می‌فرستد، نیم ثانیه صبر می‌کند تا پیام برسد، و ESP.restart(). برنامه جدید فقط بعد از ریست اجرا می‌شود. بدون delay، ممکن است برد قبل از رسیدن جواب به مرورگر ریست شود و تو فکر کنی آپدیت شکست خورده.

استفاده: آدرس IP برد را در مرورگر باز کن، نام کاربری و رمز را بزن، فایل .ino.bin را انتخاب و Upload کن. حدود ۱۰ تا ۲۰ ثانیه بعد «OK, rebooting...» را می‌بینی.

میان‌بر: کتابخانه آماده HTTPUpdateServer

core 3.x یک کتابخانه به اسم HTTPUpdateServer هم دارد که همین صفحه را با دو خط به WebServer تو اضافه می‌کند. ما عمدا نسخه دستی را نوشتیم تا بفهمی پشت صحنه چه می‌گذرد. در آموزش‌های اینترنتی کتابخانه‌هایی مثل ElegantOTA را هم می‌بینی؛ نسخه‌های قدیمی آن (AsyncElegantOTA) منسوخ شده‌اند.

کشیدن آپدیت از یک سرور: HTTPUpdate

هر دو روش بالا «هل دادن» هستند: تو برنامه را به برد می‌فرستی. وقتی چند دستگاه داری، «کشیدن» راحت‌تر است: هر دستگاه هر وقت تو بگویی (با یک دکمه، یک پیام MQTT، یا روزی یک بار) یک فایل .bin جدید را از یک آدرس وب دانلود می‌کند. کتابخانه داخلی HTTPUpdate این کار را با یک فراخوانی انجام می‌دهد. برای امتحان، فایل .ino.bin را در یک پوشه روی کامپیوترت بگذار و در همان پوشه python -m http.server 8000 را اجرا کن. اگر موفق شود، برد خودش با برنامه جدید ریست می‌شود. برای محصول واقعی از HTTPS (درس ۵.۶) استفاده کن و نسخه فعلی را به عنوان ورودی سوم update() بده تا سرور بتواند جواب «آپدیت نداریم» بدهد، به جای این که هر بار همان فایل را دوباره بفرستد.

#include <HTTPUpdate.h>
// ... بعد از وصل شدن Wi-Fi:
WiFiClient client;
t_httpUpdate_return r = httpUpdate.update(client, "http://192.168.1.10:8000/firmware.bin");
if (r == HTTP_UPDATE_FAILED) {
  Serial.printf("Update failed: %s\n", httpUpdate.getLastErrorString().c_str());
}

برگشت خودکار (Rollback): اگر برنامه جدید خراب بود چه؟

فرض کن برنامه جدید باگی دارد که باعث می‌شود به Wi-Fi وصل نشود. حالا دیگر OTA هم کار نمی‌کند! ESP-IDF برای این حالت «برگشت خودکار» دارد و در core آردوینو ۳ هم روشن است (CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y). ایده: برنامه جدید بعد از اولین بوت «در حال آزمایش» است. اگر خودش اعلام کند «من سالمم»، ماندگار می‌شود؛ اگر قبل از آن ریست شود یا خودش بگوید «خرابم»، bootloader به برنامه قبلی برمی‌گردد.

به طور پیش‌فرض core آردوینو برنامه جدید را بلافاصله در شروع کار «سالم» اعلام می‌کند. برای این که خودت تصمیم بگیری:

#include <WiFi.h>
#include "esp_ota_ops.h"
#include "secrets.h"

// به core می‌گوییم: «تأیید برنامه جدید را خودم انجام می‌دهم»
extern "C" bool verifyRollbackLater() {
  return true;
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  unsigned long t0 = millis();
  while (WiFi.status() != WL_CONNECTED && millis() - t0 < 30000) delay(500);

  if (WiFi.status() == WL_CONNECTED) {
    esp_ota_mark_app_valid_cancel_rollback();   // «این نسخه سالم است»
    Serial.println("New firmware confirmed");
  } else {
    Serial.println("No Wi-Fi: rolling back");
    esp_ota_mark_app_invalid_rollback_and_reboot();  // برگرد به نسخه قبلی
  }
}

void loop() {
  delay(1000);
}
  1. verifyRollbackLater. core این تابع را به شکل «ضعیف» (weak) تعریف کرده که false برمی‌گرداند. وقتی خودت آن را با true بنویسی، نسخه تو جایگزین می‌شود و core تأیید خودکار را انجام نمی‌دهد. extern "C" ضروری است: تابع core در یک فایل C تعریف شده و بدون آن، کامپایلر C++ اسم تابع تو را تغییر می‌دهد (name mangling)؛ برنامه بدون هیچ خطایی کامپایل می‌شود ولی نسخه تو هرگز صدا زده نمی‌شود. این الگوی «تابع weak» در core آردوینو زیاد است: راهی برای تغییر رفتار داخلی بدون دست زدن به فایل‌های core.
  2. تأیید. اگر Wi-Fi در ۳۰ ثانیه وصل شد، esp_ota_mark_app_valid_cancel_rollback() می‌گوید «این نسخه ماندگار است». معیار سلامت را خودت انتخاب کن: وصل شدن به Wi-Fi، جواب دادن سرور MQTT، یا هر چیزی که برای ادامه OTA لازم است.
  3. رد کردن. esp_ota_mark_app_invalid_rollback_and_reboot() برد را ریست می‌کند و bootloader نسخه قبلی را اجرا می‌کند. اگر برنامه با کابل USB ریخته شده باشد، نسخه قبلی معتبری نیست و این تابع فقط خطا برمی‌گرداند؛ پس روی میز با آن کاری نمی‌شود. این مکانیزم فقط بعد از یک آپدیت OTA معنا دارد.
امنیت OTA را جدی بگیر

OTA یعنی «راهی برای عوض کردن مغز دستگاه از راه دور». اگر این راه باز باشد، مهاجم هم می‌تواند از آن استفاده کند. حداقل‌ها: ۱) همیشه رمز بگذار؛ ۲) پورت 3232 و صفحه آپدیت را هرگز با Port Forwarding روی اینترنت باز نکن؛ ۳) برای دستگاهی که به دیگران می‌فروشی، OTA امضاشده (Signed OTA، مثال SignedOTA در کتابخانه ArduinoOTA) و Secure Boot را مطالعه کن تا فقط برنامه امضاشده با کلید خصوصی خودت پذیرفته شود.

OTA و آپلود فایل LittleFS در Wokwi شبیه‌سازی نمی‌شوند (Wokwi برنامه را مستقیم در حافظه شبیه‌ساز می‌گذارد و پورت شبکه‌ای برای IDE ندارد). این دو را روی برد واقعی تمرین کن.

LittleFS، یک فلش‌مموری کوچک داخل ESP32

در درس ۴.۲ صفحه وب را به شکل یک رشته بزرگ داخل کد C++ نوشتیم. کار می‌کرد، ولی هر تغییر کوچک در رنگ یک دکمه یعنی کامپایل و آپلود دوباره کل برنامه. و اگر بخواهی تنظیمات (مثلا شهر انتخابی کاربر) یا لاگ چند روزه را نگه داری، متغیرها با ریست پاک می‌شوند. LittleFS یک «سیستم فایل» است: بخشی از حافظه فلش (همان پارتیشن spiffs در شکل بالا) را مثل یک فلش‌مموری کوچک با پوشه و فایل در اختیارت می‌گذارد. فایل‌ها با خاموش شدن برق و حتی با آپلود برنامه جدید (با USB یا OTA) باقی می‌مانند.

مثال از زندگی روزمره

برنامه تو مثل آشپز است و RAM مثل میز کارش: سریع ولی با تعطیلی رستوران (قطع برق) پاک می‌شود. LittleFS مثل قفسه دفترها در آشپزخانه است: دستور غذاها (صفحه وب) و دفتر حساب (لاگ) آنجا می‌ماند، حتی اگر آشپز عوض شود (برنامه جدید).

چرا LittleFS و نه SPIFFS؟

SPIFFS سیستم فایل قدیمی‌تر ESP32 است که پوشه واقعی ندارد و با قطع برق وسط نوشتن آسیب‌پذیرتر است؛ Espressif آن را دیگر توسعه نمی‌دهد. LittleFS برای میکروکنترلر طراحی شده: در برابر قطع برق مقاوم است (Power-loss resilient) و نوشتن را روی کل حافظه پخش می‌کند تا یک نقطه از فلش زود فرسوده نشود (Wear leveling). اسم پارتیشن هنوز «spiffs» است ولی LittleFS به راحتی از همان استفاده می‌کند.

نوشتن، اضافه کردن، خواندن و فهرست فایل‌ها

#include <LittleFS.h>

void listFiles(const char *dir) {
  File root = LittleFS.open(dir);
  File f = root.openNextFile();
  while (f) {
    Serial.printf("  %-20s %6u bytes\n", f.name(), (unsigned)f.size());
    f = root.openNextFile();
  }
}

void setup() {
  Serial.begin(115200);
  delay(500);
  if (!LittleFS.begin(true)) {               // true = اگر خراب بود، فرمت کن
    Serial.println("LittleFS mount failed");
    return;
  }
  Serial.printf("FS: %u of %u bytes used\n",
                (unsigned)LittleFS.usedBytes(), (unsigned)LittleFS.totalBytes());

  File f = LittleFS.open("/note.txt", "w");  // w = بساز یا از اول بنویس
  f.println("Hello from ESP32!");
  f.close();                                 // بستن = ذخیره قطعی

  f = LittleFS.open("/log.txt", "a");        // a = به آخر فایل اضافه کن
  f.printf("boot at %lu ms\n", millis());
  f.close();

  f = LittleFS.open("/log.txt", "r");        // r = فقط خواندن
  Serial.println("--- log.txt ---");
  while (f.available()) {
    Serial.write(f.read());
  }
  f.close();

  Serial.println("--- files ---");
  listFiles("/");
}

void loop() {}
  1. کتابخانه LittleFS. داخل core است. نصب جدا لازم نیست. کتابخانه‌های قدیمی مثل «LITTLEFS by lorol» را نصب نکن؛ آن‌ها مال core 1.x بودند و با core 3 تداخل دارند.
  2. LittleFS.begin(true). سیستم فایل را «سوار» (mount) می‌کند. ورودی true یعنی «اگر نتوانستی سوار کنی (مثلا بار اول که هنوز فرمت نشده)، فرمت کن». بار اولی که روی برد نو اجرا می‌کنی، پارتیشن خالی و فرمت‌نشده است و بدون true همیشه «mount failed» می‌گیری. ولی دقت کن: اگر فایل‌ها واقعا خراب شده باشند، true همه را پاک می‌کند. برای دستگاهی با داده ارزشمند، اول با false امتحان کن و فرمت را آگاهانه انجام بده.
  3. فضای کل و مصرف‌شده. totalBytes و usedBytes. با Partition Scheme پیش‌فرض حدود ۱٫۳ تا ۱٫۴ مگابایت می‌بینی؛ با Minimal SPIFFS فقط ۱۲۸ کیلوبایت. قبل از ذخیره لاگ طولانی، همیشه جای خالی را بدان.
  4. حالت "w": نوشتن از اول. فایل را می‌سازد؛ اگر از قبل بود، محتوایش را پاک می‌کند. بعد مثل Serial با println و printf در آن می‌نویسی. اسم فایل همیشه با / شروع می‌شود (مسیر کامل). close() را فراموش نکن: تا فایل بسته نشود، ممکن است آخرین تکه داده هنوز در RAM باشد و با قطع برق از بین برود.
  5. حالت "a": اضافه کردن. به انتهای فایل اضافه می‌کند و قبلی‌ها را نگه می‌دارد. برای لاگ همیشه "a". با هر بار ریست، یک خط boot at ... اضافه می‌شود. دکمه EN را چند بار بزن و ببین فایل بلندتر می‌شود؛ این ثابت می‌کند داده بعد از ریست مانده است.
  6. حالت "r": خواندن. available() می‌گوید چند بایت دیگر مانده و read() یک بایت برمی‌گرداند. خواندن بایت به بایت برای فایل‌های کوچک ساده و کم‌حافظه است. برای فایل بزرگ، f.readStringUntil('\n') خط به خط می‌خواند.
  7. فهرست فایل‌ها. پوشه را باز می‌کنیم و با openNextFile() یکی‌یکی جلو می‌رویم تا فایل خالی (false) برگردد. ابزار عیب‌یابی عالی: وقتی صفحه وب پیدا نمی‌شود، اول ببین فایل واقعا روی برد هست و اسمش دقیقا چیست (حروف بزرگ و کوچک فرق دارند).

  2. داده زنده با fetch. صفحه ثابت است، ولی دما را از آدرس /api/temp که برنامه ESP32 می‌سازد می‌گیرد (همان الگوی درس ۴.۲). جداسازی تمیز: «ظاهر» در فایل‌ها، «داده» در کد. طراح وب و برنامه‌نویس ESP32 می‌توانند جدا کار کنند.
body { font-family: sans-serif; max-width: 480px; margin: 2em auto; }
h1   { color: #2f7af0; }
  1. ظاهر صفحه در فایل جدا. فونت، عرض حداکثر ۴۸۰ پیکسل (برای گوشی) و رنگ آبی تیتر. فایل CSS را مرورگر جدا درخواست می‌کند (/style.css)، پس برنامه ESP32 باید برای این آدرس هم جواب داشته باشد؛ خط ۱۹ برنامه پایین همین کار را می‌کند.
#include <WiFi.h>
#include <WebServer.h>
#include <LittleFS.h>
#include "secrets.h"

WebServer server(80);

void setup() {
  Serial.begin(115200);
  if (!LittleFS.begin(true)) {
    Serial.println("LittleFS mount failed");
  }
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.printf("Open http://%s/\n", WiFi.localIP().toString().c_str());

  // فایل‌های ثابت مستقیم از LittleFS (بعد از LittleFS.begin)
  server.serveStatic("/", LittleFS, "/index.html");
  server.serveStatic("/style.css", LittleFS, "/style.css", "max-age=3600");

  // داده زنده از کد
  server.on("/api/temp", []() {
    float t = temperatureRead();               // دمای داخلی تراشه (تقریبی)
    server.send(200, "application/json", "{\"t\":" + String(t, 1) + "}");
  });
  server.onNotFound([]() { server.send(404, "text/plain", "Not found"); });
  server.begin();
}

void loop() {
  server.handleClient();
}
  1. سوار کردن LittleFS قبل از هر چیز. serveStatic در لحظه تعریف بررسی می‌کند که مسیر یک فایل است یا پوشه؛ اگر LittleFS هنوز سوار نشده باشد، اشتباه تشخیص می‌دهد.
  2. serveStatic برای صفحه اصلی. «هر کس آدرس / را خواست، فایل /index.html را از LittleFS بفرست». نوع محتوا (text/html) را از پسوند فایل حدس می‌زند. یک خط به جای یک تابع کامل. نکته ریز: اگر به جای فایل یک پوشه بدهی (مثلا serveStatic("/", LittleFS, "/"))، کتابخانه برای آدرس / دنبال index.htm (بدون l) می‌گردد، نه index.html. ما برای جلوگیری از این دام، مسیر فایل را دقیق دادیم.
  3. فایل CSS با Cache. ورودی چهارم "max-age=3600" به مرورگر می‌گوید «این فایل را تا یک ساعت دوباره نخواه». ESP32 یک سرور ضعیف است؛ هر درخواست کمتر یعنی جواب سریع‌تر به بقیه. برای index.html کش نگذاشتیم تا تغییراتت فورا دیده شود.
  4. مسیر داده زنده. temperatureRead() دمای داخلی تراشه را می‌دهد (دقیق نیست، فقط برای نمایش) و به شکل JSON فرستاده می‌شود. در پروژه واقعی به جای آن دمای DHT22 یا هر سنسور دیگر را بگذار.

آپلود پوشه data روی برد (Arduino IDE 2)

Arduino IDE 2 برای ریختن پوشه data روی LittleFS یک افزونه لازم دارد: arduino-littlefs-upload از Earle Philhower (سازنده core ی RP2040). از Arduino IDE نسخه 2.2.1 به بعد کار می‌کند.

  1. دانلود. به صفحه Releases برو و آخرین فایل arduino-littlefs-upload-x.y.z.vsix را دانلود کن (از حالت zip خارجش نکن).
  2. پوشه plugins. در ویندوز به C:\Users\اسم‌کاربر\.arduinoIDE\ برو و اگر پوشه plugins نیست، بسازش. در مک و لینوکس: ~/.arduinoIDE/plugins/. دقت کن اسم پوشه با نقطه شروع می‌شود (.arduinoIDE) و در ویندوز ممکن است پنهان باشد.
  3. کپی و راه‌اندازی دوباره. فایل vsix را در پوشه plugins بگذار و Arduino IDE را کامل ببند و باز کن.
  4. Serial Monitor را ببند. اگر باز باشد، آپلود با خطای «port doesn't exist» شکست می‌خورد.
  5. اجرا. Ctrl+Shift+P (در مک ⌘+Shift+P) را بزن و فرمان Upload LittleFS to Pico/ESP8266/ESP32 را انتخاب کن. افزونه از روی Partition Scheme انتخابی تو، اندازه و محل پارتیشن را می‌فهمد، یک تصویر LittleFS از پوشه data می‌سازد و با کابل USB روی برد می‌ریزد.
  6. حالا برنامه را آپلود کن (یا قبلش؛ ترتیب مهم نیست). این دو آپلود جدا از هم هستند: آپلود برنامه فایل‌ها را پاک نمی‌کند و آپلود LittleFS برنامه را.
دو دام رایج

آزمون این درس

برنامه‌ات «Sketch too big» می‌دهد و دستگاه باید OTA داشته باشد. کدام Partition Scheme را انتخاب می‌کنی؟

  1. Huge APP (3MB No OTA/1MB SPIFFS)
  2. No OTA (2MB APP/2MB SPIFFS)
  3. Default 4MB with spiffs
  4. Minimal SPIFFS (1.9MB APP with OTA/128KB SPIFFS)
Minimal SPIFFS دو جای برنامه ۱٫۹ مگابایتی دارد: هم برنامه بزرگ‌تر جا می‌شود هم OTA می‌ماند. فقط فضای فایل ۱۲۸ کیلوبایت می‌شود.

دستگاهت در سقف است. بعد از یک آپدیت OTA دیگر در منوی Port دیده نمی‌شود و Wi-Fi هم وصل نیست. کدام کار از قبل می‌توانست جلوی این را بگیرد؟

  1. برداشتن رمز OTA
  2. انتخاب Huge APP
  3. تست برنامه جدید روی یک برد روی میز، و استفاده از Rollback که فقط بعد از وصل شدن Wi-Fi نسخه جدید را تأیید می‌کند
  4. خاموش کردن Watchdog
با verifyRollbackLater() و تأیید دستی بعد از وصل شدن Wi-Fi، نسخه خراب خودبه‌خود به نسخه قبلی برمی‌گردد. و هیچ چیز جای تست روی میز را نمی‌گیرد.

در صفحه آپدیت وب، کدام فایل از پوشه build را انتخاب می‌کنی؟

  1. ProjectName.ino.merged.bin
  2. ProjectName.ino.bin
  3. ProjectName.ino.partitions.bin
  4. ProjectName.ino.bootloader.bin
OTA فقط خود برنامه را عوض می‌کند، پس فایل ساده .ino.bin را می‌خواهد. Update.end(true) فایل را بررسی می‌کند و فایل اشتباه را رد می‌کند و برنامه قبلی سالم می‌ماند.

فایل لاگ تو باید همه خط‌های قبلی را نگه دارد و در هر بوت یک خط تازه اضافه کند. آن را با کدام حالت باز می‌کنی؟

  1. LittleFS.open("/log.txt", "a")
  2. LittleFS.open("/log.txt", "w")
  3. LittleFS.open("/log.txt", "r")
  4. فایل را پاک کن و دوباره بساز
حالت "a" (append) به آخر فایل اضافه می‌کند و محتوای قبلی را نگه می‌دارد. حالت "w" از یک فایل خالی شروع می‌کند.

پوشه data را با Partition Scheme پیش‌فرض (Default) آپلود کردی و برنامه را با Minimal SPIFFS. برنامه می‌گوید LittleFS mount failed. چرا؟

  1. افزونه آپلود LittleFS خراب است
  2. index.html خیلی بزرگ است
  3. دو آپلود از دو نقشه پارتیشن متفاوت استفاده کرده‌اند، پس برنامه سیستم فایل را جای دیگری جست‌وجو می‌کند
  4. باید LittleFS.begin(false) را صدا بزنی
آپلود LittleFS و آپلود برنامه باید با یک Partition Scheme انجام شوند. یک بار انتخابش کن و دیگر عوضش نکن.

تمرین ۱: دفترچه بوت در صفحه وب

LittleFS_Basics و LittleFS_Web را ترکیب کن: در هر بوت یک خط با شماره بوت به آخر /log.txt اضافه کن، و یک آدرس /log بساز که کل فایل را به صورت متن ساده در مرورگر نشان بدهد. چند بار EN را بزن و صفحه را تازه کن: فهرست باید هر بار یک خط بلندتر شود.

راهنمایی

برای پیدا کردن شماره بوت، فایل را یک بار موقع روشن شدن بخوان و خط‌هایش را بشمار (هر '\n' یک خط است)، بعد یکی اضافه کن. برای /log فایل را با "r" باز کن و با server.streamFile(f, "text/plain") بفرست، بعد f.close(). آن را کش نکن، چون عوض می‌شود.

چه باید ببینی؟

روی برد واقعی (نسخه رایگان Wokwi نمی‌تواند صفحه وب را برای مرورگر تو باز کند). بعد از آپلود، Serial Monitor این را نشان می‌دهد (شماره روشن شدن و IP تو فرق دارد):

This is boot #1
Open http://192.168.1.42/log

آن آدرس را باز کن. مرورگر فایل را به صورت متن ساده نشان می‌دهد؛ بعد از دو بار زدن EN و تازه کردن صفحه:

boot #1 at 312 ms
boot #2 at 309 ms
boot #3 at 311 ms
  • هر بار زدن EN و تازه کردن صفحه دقیقا یک خط اضافه می‌کند و شماره‌ها بدون جای خالی یکی یکی بالا می‌روند.
  • زمان‌ها همه کوچک‌اند (چند صد میلی‌ثانیه)، چون خط درست در ابتدای setup و قبل از Wi-Fi نوشته می‌شود.
  • اگر قبلا LittleFS_Basics را اجرا کرده‌ای، خط‌های آن (boot at ... ms) از قبل در فایل هستند و آن‌ها هم شمرده می‌شوند، پس دفترچه‌ات شاید از ‎#2 یا ‎#3 شروع شود. این درست است: شماره یعنی «خط‌های فایل + ۱».
  • صفحه اصلی (/) هم کار می‌کند، اگر پوشه data از LittleFS_Web روی برد باشد. عیب‌یابی: no log yet یعنی فایل نوشته نشده؛ خط LittleFS mount failed و Partition Scheme را بررسی کن.
جواب کامل با توضیح

برنامه کامل: LittleFS_Web به اضافه یک شمارنده خط، یک خط اضافه در هر روشن شدن و آدرس /log.

#include <WiFi.h>
#include <WebServer.h>
#include <LittleFS.h>
#include "secrets.h"

WebServer server(80);

int countLines(const char *path) {           // هر '\n' یعنی پایان یک خط
  File f = LittleFS.open(path, "r");
  if (!f) return 0;                          // هنوز فایلی نیست: ۰ خط
  int lines = 0;
  while (f.available()) {
    if (f.read() == '\n') lines++;
  }
  f.close();
  return lines;
}

void handleLog() {
  File f = LittleFS.open("/log.txt", "r");
  if (!f) {
    server.send(404, "text/plain", "no log yet");
    return;
  }
  server.sendHeader("Cache-Control", "no-store");   // عوض می‌شود: هرگز کش نکن
  server.streamFile(f, "text/plain");        // فایل را تکه‌تکه می‌فرستد
  f.close();
}

void setup() {
  Serial.begin(115200);
  if (!LittleFS.begin(true)) {
    Serial.println("LittleFS mount failed");
  }
  int boot = countLines("/log.txt") + 1;     // خط‌های تا حالا + ۱
  File f = LittleFS.open("/log.txt", "a");   // a یعنی اضافه به آخر
  if (f) {
    f.printf("boot #%d at %lu ms\n", boot, millis());
    f.close();                               // بسته شد = ذخیره شد
  }
  Serial.printf("This is boot #%d\n", boot);

  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.printf("Open http://%s/log\n", WiFi.localIP().toString().c_str());

  server.serveStatic("/", LittleFS, "/index.html");
  server.serveStatic("/style.css", LittleFS, "/style.css", "max-age=3600");
  server.on("/api/temp", []() {
    float t = temperatureRead();             // دمای داخلی تراشه (تقریبی)
    server.send(200, "application/json", "{\"t\":" + String(t, 1) + "}");
  });
  server.on("/log", HTTP_GET, handleLog);    // ★ دفترچه روشن شدن‌ها
  server.onNotFound([]() { server.send(404, "text/plain", "Not found"); });
  server.begin();
}

void loop() {
  server.handleClient();
}
  1. شمردن خط‌ها. فایل را بایت به بایت بخوان و کاراکترهای '\n' را بشمار. اگر فایل هنوز نیست، جواب ۰ است. هیچ شمارنده جدایی ذخیره نکردیم: خود فایل حافظه است. هر خطی که می‌نویسیم با \n تمام می‌شود، پس «تعداد خط‌جدیدها» همان «تعداد روشن شدن‌ها تا حالا» است. خواندن چند صد بایت یکی یکی برای یک لاگ کوچک به اندازه کافی سریع است.
  2. فرستادن فایل به مرورگر. با "r" بازش کن؛ اگر نیست، 404 جواب بده؛ وگرنه streamFile آن را به صورت text/plain می‌فرستد و بعد می‌بندیمش. streamFile فایل را تکه‌تکه می‌فرستد، پس حتی لاگ بلند هم لازم نیست در RAM جا شود. Cache-Control: no-store به مرورگر می‌گوید هرگز نسخه قدیمی نگه ندارد، چون فایل در هر روشن شدن عوض می‌شود؛ فایل استایل که هیچ‌وقت عوض نمی‌شود به جایش max-age می‌گیرد.
  3. یک خط برای هر روشن شدن. شماره = خط‌ها + ۱؛ با "a" (اضافه به آخر) باز کن، boot #N at T ms را بنویس و ببند. "a" به آخر فایل اضافه می‌کند و خط‌های قبلی را نگه می‌دارد ("w" فایل را پاک می‌کرد). close() لحظه‌ای است که داده واقعا در فلش است؛ LittleFS در برابر قطع برق مقاوم است، پس قطع برق یا فایل قدیمی را باقی می‌گذارد یا جدید را، هرگز فایل خراب.
  4. LittleFS_Web، بدون تغییر. صفحه ثابت، فایل استایل و /api/temp. تمرین یک قابلیت اضافه می‌کند؛ هر چیزی که قبلا کار می‌کرد همان‌طور می‌ماند.
  5. آدرس تازه. /log برای درخواست‌های GET، با handleLog. مثل بقیه مسیرها باید قبل از server.begin() ثبت شود.
تمرین ۲: اولین تعمیر بی‌سیم واقعی

ArduinoOTA را به LittleFS_Web اضافه کن (نام میزبان esp32-files و رمز از secrets.h) و یک بار با USB آپلودش کن. بعد برد را با شارژر گوشی و دور از کامپیوتر روشن کن. با OTA آدرس /api/temp را طوری تغییر بده که زمان روشن بودن (به ثانیه) را هم برگرداند، و در مرورگر بررسی کن صفحه هنوز باز می‌شود. این آزمایش درباره فایل‌های LittleFS چه چیزی را ثابت می‌کند؟

راهنمایی

ArduinoOTA.begin() را بعد از وصل شدن Wi-Fi صدا بزن و ArduinoOTA.handle() را کنار server.handleClient() در loop بگذار. Partition Scheme را بین آپلود USB و آپلودهای OTA عوض نکن. JSON می‌تواند این شکلی شود: {"t":41.2,"up":1234}.

چه باید ببینی؟

بعد از اولین آپلود با USB، Serial Monitor آدرس را چاپ می‌کند؛ در Arduino IDE، منوی Tools → Port حالا یک پورت شبکه هم دارد، مثل esp32-files at 192.168.1.42. در حین آپلود OTA، IDE رمز را می‌پرسد و برد (اگر هنوز به یک Serial Monitor وصل باشد) چاپ می‌کند:

OTA start
OTA done, rebooting
Open http://192.168.1.42/

بعد از آپدیت، http://192.168.1.42/api/temp چیزی شبیه این برمی‌گرداند (عددهای تو فرق دارند):

{"t":47.3,"up":12}
  • صفحه / هنوز با عنوان آبی‌اش (فایل استایل از LittleFS) باز می‌شود، با اینکه پوشه data را دوباره آپلود نکرده‌ای.
  • up بلافاصله بعد از آپدیت کوچک است (برد ریست شده) و با هر بار تازه کردن، ثانیه‌ای یکی بالا می‌رود.
  • عیب‌یابی: پورت شبکه نیست؟ کامپیوتر و برد باید روی یک شبکه Wi-Fi باشند و بعضی شبکه‌های مهمان یا مدرسه جلوی آن را می‌گیرند. OTA error یا رد شدن رمز: OTA_PASS را در secrets.h بررسی کن. LittleFS mount failed بعد از آپدیت: Partition Scheme بین دو آپلود عوض شده است.
جواب کامل با توضیح

چه چیزی ثابت می‌شود: آپدیت OTA (مثل آپلود با USB) فقط پارتیشن برنامه را بازنویسی می‌کند. پارتیشن LittleFS با index.html و style.css بخش جدایی از فلش است که کسی به آن دست نزده، پس فایل‌ها با هر برنامه تازه باقی می‌مانند. آن‌ها فقط وقتی عوض می‌شوند که یک ایمیج LittleFS تازه آپلود کنی، به شرطی که Partition Scheme ثابت بماند.

این نسخه نهایی است، همانی که با OTA فرستاده می‌شود. نسخه اول USB همین برنامه است بدون خط ۳۵ و با جواب اصلی /api/temp.

#include <WiFi.h>
#include <WebServer.h>
#include <LittleFS.h>
#include <ArduinoOTA.h>                      // ★
#include "secrets.h"                         // WIFI_SSID, WIFI_PASS, OTA_PASS
#ifndef OTA_PASS
#warning "OTA_PASS is not defined in secrets.h"
#define OTA_PASS "change-me"
#endif

WebServer server(80);

void setup() {
  Serial.begin(115200);
  if (!LittleFS.begin(true)) {
    Serial.println("LittleFS mount failed");
  }
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.printf("Open http://%s/\n", WiFi.localIP().toString().c_str());

  ArduinoOTA.setHostname("esp32-files");     // ★ اسم در منوی Port
  ArduinoOTA.setPassword(OTA_PASS);          // ★ بدون آن هر کسی می‌تواند فلش کند
  ArduinoOTA
    .onStart([]() { Serial.println("OTA start"); })
    .onEnd([]() { Serial.println("\nOTA done, rebooting"); })
    .onError([](ota_error_t err) { Serial.printf("OTA error %u\n", err); });
  ArduinoOTA.begin();                        // ★ بعد از وصل شدن Wi-Fi

  server.serveStatic("/", LittleFS, "/index.html");
  server.serveStatic("/style.css", LittleFS, "/style.css", "max-age=3600");
  server.on("/api/temp", []() {
    float t = temperatureRead();             // دمای داخلی تراشه (تقریبی)
    unsigned long up = millis() / 1000;      // ★ تازه در نسخه OTA: زمان روشن بودن به ثانیه
    server.send(200, "application/json",
                "{\"t\":" + String(t, 1) + ",\"up\":" + String(up) + "}");
  });
  server.onNotFound([]() { server.send(404, "text/plain", "Not found"); });
  server.begin();
}

void loop() {
  ArduinoOTA.handle();                       // ★ هر دور: «آپدیتی هست؟»
  server.handleClient();
}
  1. کتابخانه OTA و رمز. اگر OTA_PASS در secrets.h نباشد، کامپایلر هشدار می‌دهد و یک مقدار موقت می‌گذارد. رمز بیرون از اسکچ می‌ماند، پس می‌توانی کد را به اشتراک بگذاری بدون اینکه کلید بردت را به کسی بدهی.
  2. راه‌اندازی OTA، بعد از Wi-Fi. اسم میزبان، رمز، سه پیام کوتاه و بعد begin(). begin() برای اعلام برد با اسمش به شبکه‌ای فعال نیاز دارد، پس بعد از حلقه Wi-Fi می‌آید. پیام‌ها کمک می‌کنند وقتی Serial Monitor وصل است آپدیت را دنبال کنی.
  3. اصلاح کوچکی که بی‌سیم فرستاده می‌شود. /api/temp حالا زمان روشن بودن را هم به ثانیه برمی‌گرداند. یک تغییر قابل دیدن ثابت می‌کند برنامه تازه واقعا رسیده: کلید up فقط در نسخه تازه هست و مقدار کوچکش نشان می‌دهد برد همین الان ریست شده.
  4. هر دو کار در loop. ArduinoOTA.handle() کنار server.handleClient()، بدون delay. برد فقط وقتی درخواست آپدیت را می‌بیند که handle() اجرا شود. هر نسخه بعدی باید این خط‌ها را نگه دارد، وگرنه آپدیت بعدی باید دوباره با USB انجام شود.
خلاصه درس در سه خط

OTA دو پارتیشن برنامه (Default یا Minimal SPIFFS، هرگز Huge APP) و یک رمز می‌خواهد؛ اولین آپلود همیشه با USB است و هر برنامه جدید باید دوباره کد OTA را داشته باشد. با Rollback نسخه جدید فقط وقتی می‌ماند که ثابت کند به Wi-Fi وصل می‌شود. LittleFS یک درایو کوچک و مقاوم در برابر قطع برق داخل فلش است برای صفحه وب، تنظیمات JSON و لاگ کوتاه؛ با برنامه جدید پاک نمی‌شود، ولی با آپلود دوباره LittleFS پاک می‌شود.

در درس بعد (۵.۶) ESP32 کلاینت می‌شود: با HTTPS از APIهای اینترنتی داده می‌گیرد، به گوشی‌ات هشدار می‌فرستد و یاد می‌گیرد ماه‌ها خودش کار کند. در آخر Taskها، OTA و LittleFS را در یک ایستگاه هوا کنار هم می‌گذاری.
