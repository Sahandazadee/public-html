دستگاهت حالا می‌تواند چند کار را هم‌زمان انجام دهد (درس ۵.۴)، از طریق Wi-Fi به‌روز شود و فایل نگه دارد (درس ۵.۵). در این آخرین درس از این سه درس، دستگاه دستش را به سمت دنیا دراز می‌کند. تا حالا ESP32 سرور بود و دیگران از آن چیزی می‌خواستند؛ حالا کلاینت می‌شود و از سرویس‌های اینترنتی از طریق یک API و با HTTPS رمزنگاری‌شده داده می‌گیرد و به گوشی‌ات هشدار می‌فرستد. بعد یک چک‌لیست برای دستگاهی می‌آید که ماه‌ها بدون دخالت کسی کار می‌کند، و در آخر پروژه‌ای که همه چیز این سه درس را کنار هم می‌گذارد: یک ایستگاه هوای بی‌سیم.

فراخوانی API اینترنتی (HTTPS و JSON)

تا حالا ESP32 سرور بود (دیگران از او چیزی می‌خواستند). حالا برعکس: ESP32 مشتری (Client) می‌شود و از یک سرویس اینترنتی چیزی می‌پرسد. به آدرسی که یک سرویس برای جواب دادن به برنامه‌ها (نه انسان‌ها) آماده کرده API می‌گویند. جواب معمولا JSON است، همان قالبی که در درس ۵.۱ دیدی.

مثال از زندگی روزمره

API مثل پنجره سفارش یک نانوایی است. لازم نیست بدانی داخل نانوایی چه خبر است؛ فقط باید زبان سفارش را بدانی («دو تا بربری») و نانوا جواب را در شکل مشخصی (کیسه نان) تحویل می‌دهد. آدرس URL سفارش توست و JSON کیسه نان.

هوای شهر تو از Open-Meteo

Open-Meteo یک سرویس هواشناسی رایگان است که برای استفاده غیرتجاری کلید (API Key) و ثبت‌نام نمی‌خواهد. قبل از هر کدی، آدرس زیر را در مرورگر کامپیوترت باز کن تا ببینی جواب چه شکلی است؛ این عادت حرفه‌ای‌هاست:

https://api.open-meteo.com/v1/forecast?latitude=43.65&longitude=-79.38&current=temperature_2m,wind_speed_10m

آدرس سه بخش دارد: latitude و longitude (این‌جا عرض و طول جغرافیایی تورنتو؛ برای پیدا کردن عدد شهر خودت، در Google Maps یا OpenStreetMap روی شهرت راست‌کلیک کن: عدد اول عرض جغرافیایی و عدد دوم طول جغرافیایی است؛ غرب و جنوب منفی‌اند)، و current (کدام مقدارهای «همین الان» را می‌خواهی: دمای ۲ متری زمین و سرعت باد در ارتفاع ۱۰ متری). جواب چیزی شبیه این است (کوتاه‌شده):

{
  "latitude": 43.64,
  "longitude": -79.38,
  "timezone": "GMT",
  "current_units": { "time": "iso8601", "interval": "seconds",
                     "temperature_2m": "°C", "wind_speed_10m": "km/h" },
  "current": {
    "time": "2026-09-23T10:15",
    "interval": 900,
    "temperature_2m": 21.3,
    "wind_speed_10m": 14.8
  }
}

ما فقط دو عدد می‌خواهیم: current.temperature_2m و current.wind_speed_10m. بقیه اضافه است و RAM را هدر می‌دهد.

کتابخانه لازم: ArduinoJson 7

  1. Arduino IDE → Tools › Manage Libraries (آیکون کتاب).
  2. عبارت ArduinoJson را جست‌وجو کن و ArduinoJson by Benoit Blanchon را نصب کن؛ مطمئن شو نسخه 7.x است. وابستگی ندارد.
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>
#include "secrets.h"

const char *URL =
  "https://api.open-meteo.com/v1/forecast"
  "?latitude=43.65&longitude=-79.38"
  "&current=temperature_2m,wind_speed_10m";

bool fetchWeather(float &temp, float &wind) {
  WiFiClientSecure client;
  client.setInsecure();              // فقط برای یادگیری! پایین‌تر روش درست را ببین
  HTTPClient http;
  http.setConnectTimeout(5000);      // حداکثر ۵ ثانیه برای وصل شدن
  http.setTimeout(5000);             // حداکثر ۵ ثانیه برای جواب
  http.useHTTP10(true);              // بدون chunked، برای خواندن جریانی
  if (!http.begin(client, URL)) return false;

  int code = http.GET();
  if (code != HTTP_CODE_OK) {
    Serial.printf("HTTP error: %d %s\n", code, http.errorToString(code).c_str());
    http.end();
    return false;
  }

  JsonDocument filter;               // فقط همین دو عدد را نگه دار
  filter["current"]["temperature_2m"] = true;
  filter["current"]["wind_speed_10m"] = true;

  JsonDocument doc;
  DeserializationError err = deserializeJson(doc, http.getStream(),
                               DeserializationOption::Filter(filter));
  http.end();
  if (err) {
    Serial.printf("JSON error: %s\n", err.c_str());
    return false;
  }
  temp = doc["current"]["temperature_2m"] | NAN;   // اگر نبود: NAN
  wind = doc["current"]["wind_speed_10m"] | NAN;
  return !isnan(temp);
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.println("Wi-Fi OK");
}

void loop() {
  float t, w;
  if (fetchWeather(t, w)) {
    Serial.printf("Now: %.1f C, wind %.1f km/h\n", t, w);
  }
  delay(10UL * 60 * 1000);           // هر ۱۰ دقیقه، نه هر ثانیه
}
  1. سه کتابخانه. WiFiClientSecure برای اتصال رمزنگاری‌شده (HTTPS)، HTTPClient برای ساختن درخواست و خواندن جواب HTTP، و ArduinoJson برای تجزیه JSON. در core 3.x اسم اصلی کلاس NetworkClientSecure است و WiFiClientSecure یک اسم مستعار سازگار با قبل است؛ هر دو یکی‌اند. ما اسم آشناتر را نگه داشتیم.
  2. آدرس API. رشته‌های کنار هم در C++ خودشان به هم می‌چسبند؛ آدرس را برای خوانایی در سه خط شکستیم. پارامترها را با & از هم جدا کن و فاصله نگذار. یک حرف اشتباه (مثلا temperature_2) باعث جواب خطای 400 می‌شود.
  3. setInsecure: رمزنگاری بدون بررسی هویت. اتصال رمز می‌شود ولی ESP32 بررسی نمی‌کند که طرف مقابل واقعا open-meteo.com است. حقیقت صادقانه (مثل درس ۵.۱): برای گرفتن دمای عمومی که رازی نیست، خطرش کم است؛ بدترین حالت این است که کسی دمای دروغ به تو بدهد. ولی برای هر چیزی که رمز یا فرمان جابه‌جا می‌کند، هرگز setInsecure نگذار. روش درست (useBuiltinCACertBundle) را در مثال بعدی می‌بینی.
  4. سقف زمان. setConnectTimeout برای وصل شدن و setTimeout برای انتظار جواب، هر دو به میلی‌ثانیه. بدون سقف زمان، اگر اینترنت کند یا سرور شلوغ باشد، برنامه ممکن است مدت زیادی منتظر بماند. دستگاه واقعی هیچ‌وقت نباید بی‌نهایت منتظر چیزی بماند.
  5. useHTTP10. درخواست را با HTTP نسخه 1.0 می‌فرستد. در HTTP/1.1 سرور ممکن است جواب را «تکه‌تکه» (chunked) بفرستد و بین تکه‌ها عددهای اندازه بگذارد. چون ما جواب را مستقیم از جریان شبکه (getStream) به ArduinoJson می‌دهیم، آن عددها JSON را خراب می‌کنند. HTTP/1.0 تکه‌تکه ندارد. این توصیه رسمی مستندات ArduinoJson است.
  6. GET و بررسی کد جواب. HTTP_CODE_OK یعنی 200. عدد منفی یعنی اصلا به سرور نرسیدیم؛ errorToString آن را به متن تبدیل می‌کند (مثلا connection refused یا read Timeout). کدهای مهم: 200 موفق، 400 آدرس غلط، 429 «زیادی درخواست دادی» (Rate limit)، 5xx خطای سرور. همیشه قبل از خواندن جواب، کد را بررسی کن و http.end() را در هر مسیری فراموش نکن تا حافظه آزاد شود.
  7. فیلتر JSON. یک سند کوچک که شکلش می‌گوید «از جواب فقط این دو فیلد را نگه دار». جواب کامل چند صد بایت است و در APIهای دیگر (مثلا پیش‌بینی ۷ روزه ساعتی) ده‌ها کیلوبایت. با فیلتر، ArduinoJson بقیه را هنگام خواندن دور می‌ریزد و RAM کمی مصرف می‌شود.
  8. deserializeJson مستقیم از شبکه. جواب بدون ذخیره در یک String بزرگ، مستقیم از جریان شبکه خوانده می‌شود. اگر JSON ناقص یا خراب بود، err مقدار دارد و err.c_str() علت را می‌گوید (مثلا IncompleteInput یا NoMemory). در نسخه ۷ فقط JsonDocument داریم که اندازه‌اش را خودش تنظیم می‌کند. در نسخه ۶ باید StaticJsonDocument<512> یا DynamicJsonDocument با اندازه دستی می‌نوشتی؛ کدهای قدیمی اینترنت با نسخه ۷ هشدار یا خطا می‌دهند.
  9. عملگر | برای مقدار پیش‌فرض. «اگر این فیلد بود مقدارش را بده، وگرنه NAN (نه‌عدد)». اگر سرویس روزی اسم فیلد را عوض کند، به جای صفر دروغین (که شبیه دمای واقعی است!) NAN می‌گیری و می‌فهمی مشکلی هست.
  10. هر ۱۰ دقیقه. 10UL * 60 * 1000 میلی‌ثانیه؛ UL یعنی عدد بزرگ بدون علامت تا ضرب سرریز نکند. Open-Meteo خودش داده «current» را حدودا هر ۱۵ دقیقه به‌روز می‌کند (فیلد interval: 900)؛ درخواست هر ثانیه فقط سرور را اذیت می‌کند و ممکن است IP تو را محدود کند. طبق شرایط Open-Meteo، استفاده رایگان فقط برای کار غیرتجاری است، با سقف کمتر از ۱۰ هزار درخواست در روز (و ۶۰۰ در دقیقه)، و داده با مجوز CC BY 4.0 است (اگر جایی منتشرش کردی، اسم Open-Meteo را بیاور). هر ۱۰ دقیقه یعنی ۱۴۴ درخواست در روز.

هشدار به گوشی: POST با JSON به ntfy

حالا برعکس: ESP32 خبری را ارسال می‌کند. ntfy.sh یک سرویس اعلان رایگان و بدون ثبت‌نام است: اپ ntfy را روی گوشی (اندروید یا iOS) نصب می‌کنی، یک «Topic» با اسم دلخواه را Subscribe می‌کنی، و هر پیامی که به آن Topic فرستاده شود، به شکل نوتیفیکیشن روی گوشی‌ات ظاهر می‌شود.

اسم Topic همان رمز است

در ntfy.sh ثبت‌نامی نیست، پس هر کس اسم Topic تو را بداند می‌تواند پیام‌هایت را بخواند و برایت پیام جعلی بفرستد. اسمی مثل test یا ali انتخاب نکن؛ یک اسم طولانی و تصادفی مثل home-alert-7f3k9q بگذار و آن را در secrets.h نگه دار (فایل درس ۵.۵ خط #define NTFY_TOPIC "..." را از قبل دارد؛ اگر فایل تو ندارد، اضافه‌اش کن). محدودیت ntfy.sh رایگان: حدود ۲۵۰ پیام در روز و هر پیام حداکثر ۴۰۹۶ بایت.

مدار: یک دکمه فشاری بین GPIO27 و GND (مقاومت Pull-up داخلی را روشن می‌کنیم؛ درس ۳.۱).

#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>
#include "secrets.h"
#ifndef NTFY_TOPIC
#warning "NTFY_TOPIC is not defined in secrets.h"
#define NTFY_TOPIC "change-me-to-a-random-name"
#endif

const int BUTTON_PIN = 27;          // دکمه بین GPIO27 و GND

bool sendAlert(const char *title, const char *message) {
  WiFiClientSecure client;
  client.useBuiltinCACertBundle();  // بررسی واقعی هویت سرور
  HTTPClient http;
  http.setTimeout(5000);
  if (!http.begin(client, "https://ntfy.sh/")) return false;
  http.addHeader("Content-Type", "application/json");

  JsonDocument msg;                 // {"topic":..,"title":..,"message":..}
  msg["topic"] = NTFY_TOPIC;
  msg["title"] = title;
  msg["message"] = message;
  msg["priority"] = 4;              // ۱ تا ۵؛ ۴ یعنی «مهم»
  msg["tags"].add("warning");
  String body;
  serializeJson(msg, body);

  int code = http.POST(body);
  http.end();
  Serial.printf("ntfy -> %d\n", code);
  return code == 200;
}

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.println("Press the button to send an alert");
}

void loop() {
  static unsigned long lastSent = 0;
  if (digitalRead(BUTTON_PIN) == LOW && millis() - lastSent > 30000) {
    lastSent = millis();            // حداکثر هر ۳۰ ثانیه یک هشدار
    sendAlert("Door", "Front door opened!");
  }
  delay(20);
}
  1. useBuiltinCACertBundle. این بار هویت سرور ntfy.sh واقعا بررسی می‌شود. این پیام به گوشی تو می‌رود و ممکن است روزی «در باز شد» یا «نشت گاز» باشد؛ نمی‌خواهی کسی وسط راه آن را عوض کند.
  2. آدرس ریشه و نوع محتوا. برای فرستادن JSON باید به آدرس ریشه https://ntfy.sh/ POST کنی (نه https://ntfy.sh/topic) و بگویی بدنه JSON است. طبق مستندات ntfy، JSON فقط در آدرس ریشه پذیرفته می‌شود و اسم Topic داخل خود JSON می‌آید. روش ساده‌تر هم هست: POST متن خام به https://ntfy.sh/اسم-topic که کل متن می‌شود پیام.
  3. ساختن JSON. این بار برعکس deserialize: سند را پر می‌کنیم و serializeJson آن را به متن تبدیل می‌کند. msg["tags"].add("warning") یک آرایه می‌سازد که ntfy آن را به ایموجی ⚠️ تبدیل می‌کند. هرگز JSON را با چسباندن رشته‌ها دستی نساز ("{\"title\":\"" + ...)؛ اگر متن پیام یک " داشته باشد، JSON خراب می‌شود. ArduinoJson علامت‌های خاص را خودش درست می‌کند.
  4. اولویت ۱ تا ۵. ۳ پیش‌فرض است، ۴ «بالا» با لرزش طولانی، ۵ «فوری». برای هشدار واقعی ۴ یا ۵؛ برای گزارش روزانه ۲ که بی‌صدا در لیست اعلان‌ها می‌نشیند. اگر همه چیز فوری باشد، دیگر هیچ چیز فوری نیست.
  5. POST و کد جواب. ntfy در صورت موفقیت 200 برمی‌گرداند. اگر 429 دیدی، یعنی از سقف درخواست عبور کرده‌ای؛ اگر عدد منفی، مشکل از شبکه یا گواهی است.
  6. محدودیت ارسال. بعد از هر هشدار تا ۳۰ ثانیه هشدار دیگری فرستاده نمی‌شود، حتی اگر دکمه نگه داشته شود. بدون این، نگه داشتن دکمه برای ۲ ثانیه یعنی ده‌ها درخواست و ده‌ها نوتیفیکیشن، و چند دقیقه بعد سرویس تو را مسدود می‌کند. هر دستگاهی که به سرویس بیرونی پیام می‌دهد باید «ترمز» داشته باشد (Rate limiting).
تلگرام و سرویس‌های دیگر

کتابخانه UniversalTelegramBot (از Brian Lough) امکان ساختن ربات تلگرام با ESP32 را می‌دهد تا با پیام دادن به ربات، رله را خاموش و روشن کنی. هر سرویسی که انتخاب کنی، اول آدرسش را در مرورگری روی همان شبکه‌ای که دستگاه از آن استفاده می‌کند امتحان کن (بعضی شبکه‌های اداره و مدرسه سرویس‌ها را مسدود می‌کنند)، و یادت باشد سرویس بیرونی ممکن است قوانینش را عوض کند یا تعطیل شود. جایگزین‌های مستقل‌تر: MQTT روی سرور شخصی (درس ۵.۱)، یا نصب ntfy روی سرور خودت (ntfy متن‌باز است).

چک‌لیست دستگاهی که ماه‌ها روشن می‌ماند

برنامه‌ای که ۱۰ دقیقه روی میز کار می‌کند با برنامه‌ای که ۶ ماه بدون دخالت کار می‌کند فرق دارد. مشکلاتی که در ۱۰ دقیقه دیده نمی‌شوند: حافظه‌ای که ذره‌ذره تکه‌تکه می‌شود، Wi-Fi ای که ساعت ۳ صبح قطع می‌شود، برقی که وسط نوشتن فایل می‌رود. قانون مهندسی: فرض کن هر چیزی که ممکن است خراب شود، بالاخره خراب می‌شود، و دستگاه باید خودش را جمع کند.

خطرعلامتدرمان
گیر کردن برنامه در یک حلقه یا انتظاردستگاه «زنده» است ولی جواب نمی‌دهدWatchdog: loop و Taskهای مهم را به نگهبان معرفی کن تا در صورت گیر کردن، ریست شود
قطع Wi-Fi یا اینترنتبعد از قطعی مودم، دیگر داده نمی‌فرستداتصال دوباره خودکار با رویدادها و نگهبان millis (درس ۴.۱)؛ هر عمل شبکه‌ای سقف زمان داشته باشد
تکه‌تکه شدن حافظه (Heap fragmentation)بعد از چند روز کرش یا خطای NoMemory، در حالی که «حافظه آزاد» زیاد به نظر می‌رسددر کد طولانی‌مدت از ساختن و خراب کردن مداوم String بپرهیز؛ reserve() کن یا از char[] و snprintf استفاده کن
برق ضعیف (Brownout)ریست هنگام روشن شدن Wi-Fi یا رلهمنبع ۵ ولت ۱ آمپر، کابل کوتاه، خازن ۱۰۰ تا ۴۷۰ میکروفاراد (درس ۴.۱)؛ هرگز Brownout Detector را خاموش نکن
قطع برق وسط نوشتن فایلفایل تنظیمات نصفه، دستگاه با تنظیمات خراب بالا می‌آیداول در فایل موقت بنویس، بعد rename کن؛ همیشه مقدار پیش‌فرض داشته باش
ندانستن علت ریست‌ها«گاهی خودش ریست می‌شود» بدون سرنخesp_reset_reason() را در شروع بخوان، چاپ کن و شمارنده‌اش را در Preferences نگه دار
مثال از زندگی روزمره: جعبه سیاه هواپیما

هواپیما بعد از هر حادثه می‌گوید چه شد، چون جعبه سیاه دارد. دستگاه تو هم باید «جعبه سیاه» داشته باشد: هر بار که روشن می‌شود بگوید چرا ریست شده و تا حالا چند بار کرش کرده. بدون این، عیب‌یابی دستگاهی که در سقف است یعنی حدس زدن.

#include <Preferences.h>
#include "esp_system.h"
#include "esp_task_wdt.h"

Preferences prefs;

const char *resetReasonText(esp_reset_reason_t r) {
  switch (r) {
    case ESP_RST_POWERON:   return "power on";
    case ESP_RST_SW:        return "software (ESP.restart)";
    case ESP_RST_PANIC:     return "PANIC (crash / Guru Meditation)";
    case ESP_RST_INT_WDT:   return "interrupt watchdog";
    case ESP_RST_TASK_WDT:  return "TASK WATCHDOG";
    case ESP_RST_WDT:       return "other watchdog";
    case ESP_RST_DEEPSLEEP: return "wake from deep sleep";
    case ESP_RST_BROWNOUT:  return "BROWNOUT (weak power)";
    default:                return "other/unknown";
  }
}

void workerTask(void *param) {
  esp_task_wdt_add(NULL);                      // این Task را به نگهبان معرفی کن
  for (;;) {
    // ... کار اصلی Task اینجاست ...
    esp_task_wdt_reset();                      // «من زنده‌ام»
    vTaskDelay(pdMS_TO_TICKS(1000));
  }
}

void setup() {
  Serial.begin(115200);
  delay(500);
  esp_reset_reason_t why = esp_reset_reason();

  prefs.begin("sys", false);                   // فضای نام "sys" در NVS
  uint32_t boots = prefs.getUInt("boots", 0) + 1;
  prefs.putUInt("boots", boots);
  if (why == ESP_RST_PANIC || why == ESP_RST_TASK_WDT || why == ESP_RST_BROWNOUT) {
    prefs.putUInt("crashes", prefs.getUInt("crashes", 0) + 1);
  }
  Serial.printf("Boot #%lu, reason: %s, crashes so far: %lu\n",
                (unsigned long)boots, resetReasonText(why),
                (unsigned long)prefs.getUInt("crashes", 0));
  prefs.end();

  enableLoopWDT();                             // اگر loop بیش از ۵ ثانیه گیر کرد: ریست
  xTaskCreatePinnedToCore(workerTask, "worker", 3072, NULL, 1, NULL, 1);
}

String line;                                   // سراسری، یک بار رزرو شده

void loop() {
  line.reserve(64);                            // بعد از اولین بار کاری نمی‌کند
  line = "uptime=";
  line += millis() / 1000;
  line += "s heap=";
  line += ESP.getFreeHeap();
  Serial.println(line);
  delay(2000);                                 // اگر این را 6000 کنی، WDT ریست می‌کند
}
  1. ترجمه علت ریست به متن. esp_reset_reason() یک عدد از نوع esp_reset_reason_t برمی‌گرداند و ما مهم‌ترین‌ها را به متن خوانا تبدیل می‌کنیم. سه علت که همیشه باید نگرانت کنند: PANIC (کرش، مثل Guru Meditation یا Stack overflow)، TASK_WDT (یک Task گیر کرده)، و BROWNOUT (برق ضعیف). POWERON یعنی برق وصل شد و SW یعنی خود برنامه ESP.restart() زده (مثلا بعد از OTA). نکته: فشار دادن دکمه EN روی ESP32 معمولا به شکل POWERON گزارش می‌شود.
  2. معرفی یک Task به نگهبان. esp_task_wdt_add(NULL) یعنی «Task فعلی را زیر نظر بگیر» و esp_task_wdt_reset() یعنی «من زنده‌ام». از این لحظه اگر این Task بیش از ۵ ثانیه reset نکند، برد ریست می‌شود. reset را در جایی بگذار که فقط وقتی کار واقعا جلو می‌رود اجرا شود، نه در یک Task جداگانه که همیشه زنده است (آن وقت نگهبان را فریب داده‌ای). Taskی که کار طولانی مثل HTTPS دارد را با دقت اضافه کن، چون یک درخواست کند ممکن است از ۵ ثانیه بیشتر شود.
  3. شمارنده‌ها در Preferences. تعداد کل روشن شدن‌ها و تعداد ریست‌های «بد» در NVS ذخیره می‌شوند و با قطع برق پاک نمی‌شوند. اگر بعد از یک هفته دیدی crashes عدد ۴۰ است، می‌دانی مشکلی هست، حتی اگر دستگاه «ظاهرا کار می‌کند». فقط در بوت می‌نویسیم، نه در loop، تا فلش فرسوده نشود. در پروژه واقعی این عددها را در صفحه وب یا با MQTT گزارش کن.
  4. enableLoopWDT. تابع آماده core که loopTask را به نگهبان معرفی می‌کند. خود core قبل از هر دور loop() نگهبان را reset می‌کند. پس اگر یک دور loop بیش از ۵ ثانیه طول بکشد (مثلا در یک while منتظر سنسوری که قطع شده گیر کند)، برد خودش ریست می‌شود و کار از نو شروع می‌شود. ریست بهتر از یخ زدن همیشگی است.
  5. String با reserve. متغیر سراسری line یک بار ۶۴ بایت جا می‌گیرد و هر دور همان جا دوباره پر می‌شود. هر بار که یک String بزرگ‌تر می‌شود، ممکن است جای جدیدی در Heap بگیرد و جای قبلی را خالی بگذارد. بعد از هزاران بار، Heap مثل پنیر سوراخ‌سوراخ می‌شود: جمع فضای آزاد زیاد است ولی هیچ تکه بزرگ پیوسته‌ای نمانده (و HTTPS یک تکه پیوسته چند ده کیلوبایتی لازم دارد). reserve جا را یک بار و از اول می‌گیرد. برای رشته‌های ثابت هم char buf[64] با snprintf امن‌ترین است. برای دیدن مشکل، علاوه بر ESP.getFreeHeap() عدد ESP.getMaxAllocHeap() (بزرگ‌ترین تکه آزاد) را هم چاپ کن.
  6. آزمایش نگهبان. اگر delay را به 6000 تغییر دهی، هر دور loop بیش از ۵ ثانیه می‌شود و برد ریست می‌شود؛ بعد از ریست، پیام reason: TASK WATCHDOG را می‌بینی. هر مکانیزم ایمنی را یک بار عمدا تحریک کن تا مطمئن شوی واقعا کار می‌کند. نگهبانی که هرگز تست نشده، نگهبان نیست.

فرض کن داری config.json را بازنویسی می‌کنی و درست وسط کار برق می‌رود. حالت "w" فایل قبلی را اول خالی کرده بود؛ حالا نه تنظیمات قدیمی داری نه جدید. الگوی درست (در پروژه پایین می‌بینی): ۱) در config.tmp بنویس، ۲) ببند، ۳) قبلی را پاک کن و tmp را به config.json تغییر نام بده. تغییر نام در LittleFS تقریبا لحظه‌ای است. و در هر حال، برنامه وقتی فایل تنظیمات نبود یا خراب بود، باید با مقدار پیش‌فرض بالا بیاید، نه این که کرش کند. برای مقدارهای کوچک، Preferences خودش این امنیت را دارد.

struct Weather { float temp; float wind; unsigned long at; };
struct Config  { float lat; float lon; };

WebServer server(80);
Adafruit_SSD1306 display(128, 64, &Wire, -1);
QueueHandle_t weatherBox;          // صندوق یک‌خانه‌ای: همیشه آخرین هوا
SemaphoreHandle_t cfgMutex;        // قفل تنظیمات مشترک

// ---------- LittleFS: خواندن و ذخیره امن تنظیمات ----------
void loadConfig() {
  File f = LittleFS.open("/config.json", "r");
  if (!f) return;                                  // هنوز ذخیره نشده
  JsonDocument doc;
  if (!deserializeJson(doc, f)) {
    cfg.lat = doc["lat"] | cfg.lat;
    cfg.lon = doc["lon"] | cfg.lon;
  }
  f.close();
}

bool saveConfig(const Config &c) {
  JsonDocument doc;
  doc["lat"] = c.lat;
  doc["lon"] = c.lon;
  File f = LittleFS.open("/config.tmp", "w");      // اول در فایل موقت
  if (!f) return false;
  bool ok = serializeJson(doc, f) > 0;
  f.close();
  if (!ok) return false;
  LittleFS.remove("/config.json");
  return LittleFS.rename("/config.tmp", "/config.json");  // بعد جابه‌جا
}

// ---------- Task هوا: هر ۱۰ دقیقه یا وقتی تنظیمات عوض شد ----------
bool fetchWeather(float lat, float lon, Weather &w) {
  char url[160];
  snprintf(url, sizeof(url),
           "https://api.open-meteo.com/v1/forecast?latitude=%.2f&longitude=%.2f"
           "&current=temperature_2m,wind_speed_10m", lat, lon);
  WiFiClientSecure client;
  client.useBuiltinCACertBundle();
  HTTPClient http;
  http.setConnectTimeout(5000);
  http.setTimeout(5000);
  http.useHTTP10(true);
  if (!http.begin(client, url)) return false;
  int code = http.GET();
  bool ok = false;
  if (code == HTTP_CODE_OK) {
    JsonDocument filter;
    filter["current"]["temperature_2m"] = true;
    filter["current"]["wind_speed_10m"] = true;
    JsonDocument doc;
    if (!deserializeJson(doc, http.getStream(), DeserializationOption::Filter(filter))) {
      w.temp = doc["current"]["temperature_2m"] | NAN;
      w.wind = doc["current"]["wind_speed_10m"] | NAN;
      w.at = millis();
      ok = !isnan(w.temp);
    }
  }
  http.end();
  return ok;
}

void weatherTask(void *param) {
  for (;;) {
    if (WiFi.status() == WL_CONNECTED) {
      xSemaphoreTake(cfgMutex, portMAX_DELAY);
      Config c = cfg;                              // کپی، بعد قفل را پس بده
      xSemaphoreGive(cfgMutex);
      Weather w;
      if (fetchWeather(c.lat, c.lon, w)) {
        xQueueOverwrite(weatherBox, &w);           // جای مقدار قبلی
      }
    }
    // ۱۰ دقیقه بخواب، مگر این که کسی زودتر بیدارمان کند
    ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(10UL * 60 * 1000));
  }
}

// ---------- Task نمایش: هر ۲ ثانیه آخرین هوا روی OLED ----------
void displayTask(void *param) {
  Weather w;
  for (;;) {
    display.clearDisplay();
    display.setCursor(0, 0);
    display.println(WiFi.localIP());
    if (xQueuePeek(weatherBox, &w, 0) == pdPASS) {  // نگاه کن، برندار
      display.setTextSize(2);
      display.printf("%.1f C\n", w.temp);
      display.setTextSize(1);
      display.printf("wind %.1f km/h\n", w.wind);
      display.printf("%lu min ago", (millis() - w.at) / 60000);
    } else {
      display.println("waiting for data...");
    }
    display.display();
    vTaskDelay(pdMS_TO_TICKS(2000));
  }
}

// ---------- وب: صفحه از LittleFS، داده از کد ----------
void handleState() {
  Weather w = {NAN, NAN, 0};
  xQueuePeek(weatherBox, &w, 0);
  JsonDocument doc;
  xSemaphoreTake(cfgMutex, portMAX_DELAY);
  doc["lat"] = cfg.lat;
  doc["lon"] = cfg.lon;
  xSemaphoreGive(cfgMutex);
  doc["temp"] = w.temp;
  doc["wind"] = w.wind;
  String out;
  serializeJson(doc, out);
  server.send(200, "application/json", out);
}

void handleSave() {
  Config c = {server.arg("lat").toFloat(), server.arg("lon").toFloat()};
  if (c.lat < -90 || c.lat > 90 || c.lon < -180 || c.lon > 180) {
    return server.send(400, "text/plain", "bad lat/lon");
  }
  xSemaphoreTake(cfgMutex, portMAX_DELAY);
  cfg = c;
  xSemaphoreGive(cfgMutex);
  saveConfig(c);
  xTaskNotifyGive(weatherHandle);                  // «همین الان دوباره بگیر»
  server.sendHeader("Location", "/");
  server.send(303);
}

  2. صف یک‌خانه‌ای به عنوان «صندوق نامه» (Mailbox). صفی با طول ۱ که با xQueueOverwrite پر می‌شود و با xQueuePeek خوانده می‌شود. در صف معمولی (درس ۵.۴) هر داده یک بار خوانده و برداشته می‌شد. این‌جا دو خواننده داریم (OLED و وب) و هر دو فقط «آخرین هوا» را می‌خواهند؛ Peek نگاه می‌کند و برنمی‌دارد، Overwrite همیشه جای قبلی را می‌گیرد و هرگز «صف پر» نمی‌شود.
  3. خواندن تنظیمات در بوت. اگر فایل نبود یا JSON خراب بود، مقدار پیش‌فرض تورنتو (خط ۲۵) می‌ماند. همان اصل چک‌لیست پایداری: دستگاه همیشه باید با تنظیمات ناقص هم بالا بیاید.
  4. ذخیره امن. اول config.tmp، بعد پاک کردن قبلی و تغییر نام. اگر برق وسط serializeJson برود، config.json قبلی سالم است. serializeJson(doc, f) مستقیم در فایل می‌نویسد و تعداد بایت‌ها را برمی‌گرداند؛ صفر یعنی شکست.

  6. weatherTask. تنظیمات را زیر قفل کپی می‌کند، قفل را فورا پس می‌دهد، بعد درخواست کند HTTPS را انجام می‌دهد و نتیجه را در صندوق می‌گذارد. هرگز قفل را در طول یک کار کند (چند ثانیه HTTPS) نگه ندار، وگرنه صفحه وب هم که cfg را می‌خواهد همان‌قدر منتظر می‌ماند. «کپی کن، رها کن، بعد کار کن».
  7. ulTaskNotifyTake با سقف ۱۰ دقیقه. Task می‌خوابد تا یا ۱۰ دقیقه بگذرد، یا کسی با xTaskNotifyGive بیدارش کند. «اعلان Task» (Task Notification) سبک‌ترین ابزار FreeRTOS برای «هی، بیدار شو» است. با vTaskDelay ی ساده، بعد از تغییر شهر باید تا ۱۰ دقیقه منتظر هوای جدید می‌ماندی.
  8. displayTask. هر ۲ ثانیه صفحه را از نو می‌کشد: IP، دما با حروف درشت، باد، و این که داده چند دقیقه پیش گرفته شده. فقط همین Task به OLED (و I2C) دست می‌زند، پس برای نمایشگر Mutex لازم نیست. قانون ساده‌تر از قفل: هر سخت‌افزار یک صاحب. نمایش «چند دقیقه پیش» مهم است: اگر اینترنت یک روز قطع باشد، کاربر دمای دیروز را به جای امروز باور نمی‌کند.
  9. /api/state. آخرین هوا را از صندوق Peek می‌کند و تنظیمات را زیر قفل می‌خواند و همه را به شکل JSON برمی‌گرداند. این تابع در loopTask اجرا می‌شود (داخل server.handleClient)، در حالی که weatherTask ممکن است هم‌زمان cfg را بخواند یا عوض شدنش را منتظر باشد؛ برای همین قفل لازم است.
  10. /api/config. ورودی را اعتبارسنجی می‌کند، در cfg و فایل ذخیره می‌کند، weatherTask را بیدار می‌کند و مرورگر را با کد 303 به صفحه اصلی برمی‌گرداند. هرگز به ورودی کاربر اعتماد نکن: toFloat() برای متن نامعتبر صفر برمی‌گرداند و عرض جغرافیایی ۵۰۰ معنی ندارد. 303 باعث می‌شود رفرش صفحه فرم را دوباره نفرستد.
  11. setup به ترتیب درست. LittleFS و تنظیمات، بعد صف و قفل (قبل از هر Task)، OLED، Wi-Fi با سقف ۲۰ ثانیه، OTA، وب سرور، و در آخر Taskها. اگر Wi-Fi در ۲۰ ثانیه وصل نشد، دستگاه متوقف نمی‌شود: setAutoReconnect بعدا وصلش می‌کند و weatherTask تا وصل شدن فقط منتظر می‌ماند. Stack ی weatherTask عمدا ۱۲ کیلوبایت است چون HTTPS سنگین است؛ بعد از چند روز با uxTaskGetStackHighWaterMark مقدار واقعی را اندازه بگیر.
  12. loop کوچک. فقط OTA و وب سرور، با یک delay(2). چون کار کند در Task جداست، loop همیشه در چند میلی‌ثانیه می‌چرخد و OTA و صفحه وب همیشه سریع جواب می‌دهند، حتی وسط یک درخواست HTTPS کند. این همان مشکلی بود که درس ۵.۴ را با آن شروع کردیم.
در Wokwi چه چیزی را می‌توانی امتحان کنی؟

Wokwi Wi-Fi (با Wokwi-GUEST)، HTTPS، OLED و FreeRTOS را شبیه‌سازی می‌کند، پس بخش هوا و نمایش کار می‌کند. ولی OTA و آپلود پوشه data در Wokwi وجود ندارند؛ بدون فایل index.html، صفحه اصلی خالی است ولی /api/state جواب می‌دهد. پروژه کامل را روی برد واقعی بساز.

دو قانون را با خودت ببر. یک، دستگاهی که علت ریست‌هایش را ثبت نمی‌کند، دستگاه حرفه‌ای نیست. از امروز در هر پروژه‌ای که بیش از یک روز روشن می‌ماند، کد «جعبه سیاه» چک‌لیست پایداری را بگذار. بعد از یک هفته که شمارنده کرش صفر ماند، آن وقت می‌توانی بگویی «کار می‌کند». دو، روی سرور دیگران مهمان مؤدبی باش: فاصله منطقی بین درخواست‌ها، سقف زمان برای هر درخواست، و ترمز برای هر هشدار. دستگاهی که هر ثانیه به یک API هجوم می‌برد مسدود می‌شود و آن وقت اصلا کار نمی‌کند.

آزمون این درس

چرا در مثال هوا قبل از deserializeJson(doc, http.getStream(), ...) خط http.useHTTP10(true) را گذاشتیم؟

  1. چون HTTP 1.0 سریع‌تر است
  2. تا سرور جواب را chunked (تکه‌تکه با عددهای اندازه) نفرستد و JSON خوانده‌شده از جریان خراب نشود
  3. چون HTTPS فقط با HTTP 1.0 کار می‌کند
  4. تا گواهی سرور بررسی نشود
وقتی مستقیم از getStream() می‌خوانی، HTTPClient تکه‌ها را سرهم نمی‌کند. HTTP/1.0 این مشکل را از ریشه حذف می‌کند.

دستگاهت از طریق ntfy هشدار «در باز شد» را به گوشی‌ات می‌فرستد. کدام تنظیم اتصال درست است؟

  1. setInsecure()، چون ساده‌تر است
  2. http:// ساده بدون رمزنگاری
  3. برای یک اعلان فرقی نمی‌کند
  4. useBuiltinCACertBundle()
برای هر چیزی که فرمان، رمز یا هشدار مهم حمل می‌کند، هویت سرور را بررسی کن. بسته داخلی این کار را بدون کپی کردن گواهی انجام می‌دهد.

بعد از یک هفته، صفحه دستگاهت «crashes: 40» را نشان می‌دهد و علت آخرین ریست TASK WATCHDOG است. این به تو چه می‌گوید؟

  1. یک Task (یا loop) بارها بیش از ۵ ثانیه گیر کرده؛ باید پیدا کنی کدام
  2. منبع تغذیه خیلی ضعیف است
  3. همه چیز خوب است؛ نگهبان فقط سخت‌گیر است
  4. کسی ۴۰ بار دکمه EN را زده
نگهبان با ریست کردن دستگاه را زنده نگه داشته، ولی باگ هنوز هست. خط CPU 0: ... در پیام نگهبان اسم مجرم را می‌گوید.

در ایستگاه هوا، چرا weatherTask تنظیمات را زیر قفل کپی می‌کند و قفل را قبل از درخواست HTTPS پس می‌دهد؟

  1. برای صرفه‌جویی در RAM
  2. چون HTTPS وقتی Mutex گرفته شده کار نمی‌کند
  3. تا صفحه وب، که آن هم تنظیمات را لازم دارد، مجبور نشود چند ثانیه منتظر یک درخواست کند بماند
  4. چون Mutex بعد از یک ثانیه منقضی می‌شود
«کپی کن، رها کن، بعد کار کن»: قفل را فقط همان لحظه‌ای نگه دار که به داده مشترک دست می‌زنی، هرگز در طول یک کار کند.

جواب کامل با توضیح

برنامه کامل: fetchWeather از WeatherNow، sendAlert از برنامه ntfy، و یک checkHeat کوچک که تصمیم می‌گیرد. در Wokwi هم با همان ترفند secrets.h برنامه WeatherNow اجرا می‌شود (به اضافه یک خط #define NTFY_TOPIC).

#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>
#include <Preferences.h>
#include "secrets.h"
#ifndef NTFY_TOPIC
#warning "NTFY_TOPIC is not defined in secrets.h"
#define NTFY_TOPIC "change-me-to-a-random-name"
#endif

const char *URL =
  "https://api.open-meteo.com/v1/forecast"
  "?latitude=43.65&longitude=-79.38"
  "&current=temperature_2m,wind_speed_10m";
const float ALERT_ABOVE = 30.0;          // وقتی گرم‌تر از این شد هشدار بده
const float REARM_BELOW = 28.0;          // وقتی خنک‌تر از این شد دوباره آماده
const unsigned long CHECK_MS = 10UL * 60 * 1000;   // هر ۱۰ دقیقه

Preferences prefs;

bool fetchWeather(float &temp, float &wind) {
  WiFiClientSecure client;
  client.useBuiltinCACertBundle();       // بررسی هویت سرور
  HTTPClient http;
  http.setConnectTimeout(5000);
  http.setTimeout(5000);
  http.useHTTP10(true);
  if (!http.begin(client, URL)) return false;
  int code = http.GET();
  if (code != HTTP_CODE_OK) {
    Serial.printf("HTTP error: %d %s\n", code, http.errorToString(code).c_str());
    http.end();
    return false;
  }
  JsonDocument filter;
  filter["current"]["temperature_2m"] = true;
  filter["current"]["wind_speed_10m"] = true;
  JsonDocument doc;
  DeserializationError err = deserializeJson(doc, http.getStream(),
                               DeserializationOption::Filter(filter));
  http.end();
  if (err) {
    Serial.printf("JSON error: %s\n", err.c_str());
    return false;
  }
  temp = doc["current"]["temperature_2m"] | NAN;
  wind = doc["current"]["wind_speed_10m"] | NAN;
  return !isnan(temp);
}

bool sendAlert(const char *title, const char *message) {
  WiFiClientSecure client;
  client.useBuiltinCACertBundle();
  HTTPClient http;
  http.setTimeout(5000);
  if (!http.begin(client, "https://ntfy.sh/")) return false;
  http.addHeader("Content-Type", "application/json");
  JsonDocument msg;
  msg["topic"] = NTFY_TOPIC;
  msg["title"] = title;
  msg["message"] = message;
  msg["priority"] = 4;
  msg["tags"].add("warning");
  String body;
  serializeJson(msg, body);
  int code = http.POST(body);
  http.end();
  Serial.printf("ntfy -> %d\n", code);
  return code == 200;
}

void checkHeat(float t) {
  prefs.begin("alert", false);
  bool sent = prefs.getBool("sent", false);     // بعد از ریست هم می‌ماند
  if (!sent && t > ALERT_ABOVE) {
    char text[48];
    snprintf(text, sizeof(text), "It is %.1f C outside", t);
    if (sendAlert("Heat", text)) {
      prefs.putBool("sent", true);              // فقط وقتی واقعا فرستاده شد
      Serial.printf("Alert sent; next one after it drops below %.1f C\n", REARM_BELOW);
    }
  } else if (sent && t < REARM_BELOW) {
    prefs.putBool("sent", false);               // آماده هشدار بعدی
    Serial.println("Cooled down: ready for the next alert");
  }
  prefs.end();
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  prefs.begin("alert", false);                  // false یعنی خواندن/نوشتن (بار اول می‌سازدش)
  Serial.printf("Wi-Fi OK, alert already sent: %s\n", prefs.getBool("sent", false) ? "yes" : "no");
  prefs.end();
}

void loop() {
  float t, w;
  if (fetchWeather(t, w)) {
    Serial.printf("Now: %.1f C, wind %.1f km/h\n", t, w);
    checkHeat(t);
  }
  delay(CHECK_MS);                              // هوا آرام عوض می‌شود
}
  1. دو حد و فاصله زمانی. هشدار بالای ۳۰، آماده شدن دوباره زیر ۲۸، بررسی هر ۱۰ دقیقه. فاصله بین ۳۰ و ۲۸ همان «پسماند» (hysteresis) است: دمایی که حول ۳۰ نوسان می‌کند (۳۰٫۱، ۲۹٫۹، ۳۰٫۲...) نمی‌تواند ده‌ها هشدار بسازد، چون بعد از هشدار باید اول ۲ درجه کامل پایین بیاید. ثابت‌های اسم‌دار آزمایش را راحت می‌کنند.
  2. گرفتن آب‌وهوا، مثل WeatherNow. یک فرق: useBuiltinCACertBundle() به جای setInsecure(). این برنامه بر اساس داده کاری انجام می‌دهد (به تو هشدار می‌دهد)، پس ارزش دارد بررسی کنیم جواب واقعا از Open-Meteo می‌آید. بسته گواهی‌ها برای ntfy به هر حال هست.
  3. فرستادن، مثل برنامه ntfy. فقط وقتی true برمی‌گرداند که سرور 200 جواب داده باشد. صدازننده باید بداند هشدار واقعا رفته یا نه، تا «فرستاده شد» فقط بعد از موفقیت ذخیره شود.
  4. حافظه‌ای که از ریست جان سالم به در می‌برد. پرچم «فرستاده شد» در Preferences، در namespace به اسم alert است. یک متغیر معمولی با هر ریست به false برمی‌گردد و بردی که وسط موج گرما ریست شود بارها و بارها هشدار می‌داد. یک bool در NVS کافی است.
  5. گرم و هنوز فرستاده‌نشده: هشدار. متن را با دمای واقعی بساز و بفرست؛ فقط در صورت موفقیت sent = true را ذخیره کن. اگر اینترنت لحظه‌ای قطع باشد، پرچم false می‌ماند و بررسی بعدی دوباره امتحان می‌کند: هیچ هشداری گم نمی‌شود.
  6. دوباره خنک: آماده شو. فقط وقتی sent درست است و دما زیر ۲۸ است. فلش فقط وقتی نوشته می‌شود که مقدار عوض شود، نه هر ۱۰ دقیقه؛ خانه‌های فلش تعداد محدودی نوشتن را تحمل می‌کنند، پس بهتر است از نوشتن بی‌فایده پرهیز کرد.
  7. نشان دادن وضعیت ذخیره‌شده در شروع. به تو اجازه می‌دهد بخش «بعد از ریست هم یادش می‌ماند» تمرین را مستقیم وارسی کنی.
  8. یک loop ساده. بگیر، چاپ کن، تصمیم بگیر، ۱۰ دقیقه صبر کن. برنامه کار دیگری ندارد، پس یک delay طولانی اینجا اشکالی ندارد؛ سرویس هواشناسی تقریبا هر ۱۵ دقیقه به‌روز می‌شود، پس پرسیدن بیشتر فایده‌ای ندارد.
تمرین ۲: جعبه سیاه در صفحه وب

«جعبه سیاه» چک‌لیست پایداری را به پروژه ایستگاه هوا اضافه کن: علت آخرین ریست، تعداد بوت‌ها و تعداد کرش‌ها را در /api/state برگردان و در index.html نشان بده. سپس با تغییر عمدی (مثلا یک حلقه بی‌پایان در loop بعد از ۱ دقیقه با enableLoopWDT) یک ریست نگهبان بساز و ببین در صفحه ثبت می‌شود. در آخر نسخه سالم را با OTA بفرست.

راهنمایی

علت ریست را یک بار در setup بخوان و در یک متغیر سراسری const char * نگه دار؛ در handleState فقط آن را در JSON بگذار. برای تست OTA، مطمئن شو نسخه خراب هم هنوز ArduinoOTA.handle() را در ۱ دقیقه اول صدا می‌زند، وگرنه باید با کابل درستش کنی. (همین تجربه، توصیه مربی درباره OTA در درس ۵.۵ را برایت واقعی می‌کند.)

جواب کامل با توضیح

ایستگاه کامل با جعبه سیاه. بیشتر برنامه بدون تغییر است؛ توضیح خط‌به‌خط فقط بخش‌های تازه را پوشش می‌دهد. یک تله که خوب است بدانی: ArduinoOTA.handle() کل برنامه تازه را در یک فراخوانی دریافت می‌کند که ۱۰ تا ۳۰ ثانیه طول می‌کشد. در این مدت loop برنمی‌گردد، پس با enableLoopWDT() نگهبان وسط آپدیت برد را ریست می‌کرد، مگر اینکه در حین آپلود سیرش کنیم.

#include <WiFi.h>
#include <WebServer.h>
#include <ArduinoOTA.h>
#include <LittleFS.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <Preferences.h>                   // ★ جعبه سیاه: شمارنده‌ها در NVS
#include "esp_system.h"                    // ★ esp_reset_reason()
#include "secrets.h"
#ifndef OTA_PASS
#warning "OTA_PASS is not defined in secrets.h"
#define OTA_PASS "change-me"
#endif
#define CRASH_TEST 1   // ★ ۱ = نسخه عمدا خراب؛ ۰ = نسخه درست (با OTA)

struct Weather { float temp; float wind; unsigned long at; };
struct Config  { float lat; float lon; };

WebServer server(80);
Adafruit_SSD1306 display(128, 64, &Wire, -1);
QueueHandle_t weatherBox;          // صندوق یک‌خانه‌ای: همیشه آخرین هوا
SemaphoreHandle_t cfgMutex;        // قفل تنظیمات مشترک
TaskHandle_t weatherHandle = NULL;
Config cfg = {43.65, -79.38};      // پیش‌فرض: تورنتو
const char *resetText = "?";       // ★ این بار چرا (دوباره) روشن شدیم
uint32_t bootCount = 0, crashCount = 0;

const char *resetReasonText(esp_reset_reason_t r) {
  switch (r) {
    case ESP_RST_POWERON:   return "power on";
    case ESP_RST_SW:        return "software (ESP.restart)";
    case ESP_RST_PANIC:     return "PANIC (crash / Guru Meditation)";
    case ESP_RST_INT_WDT:   return "interrupt watchdog";
    case ESP_RST_TASK_WDT:  return "TASK WATCHDOG";
    case ESP_RST_WDT:       return "other watchdog";
    case ESP_RST_DEEPSLEEP: return "wake from deep sleep";
    case ESP_RST_BROWNOUT:  return "BROWNOUT (weak power)";
    default:                return "other/unknown";
  }
}

void recordBoot() {                 // ★ یک بار، در ابتدای setup
  esp_reset_reason_t why = esp_reset_reason();
  resetText = resetReasonText(why);
  Preferences prefs;
  prefs.begin("sys", false);
  bootCount = prefs.getUInt("boots", 0) + 1;
  prefs.putUInt("boots", bootCount);
  crashCount = prefs.getUInt("crashes", 0);
  if (why == ESP_RST_PANIC || why == ESP_RST_TASK_WDT || why == ESP_RST_BROWNOUT) {
    crashCount++;
    prefs.putUInt("crashes", crashCount);
  }
  prefs.end();
  Serial.printf("Boot #%lu, reason: %s, crashes: %lu\n", (unsigned long)bootCount,
                resetText, (unsigned long)crashCount);
}

// ---------- LittleFS: خواندن و ذخیره امن تنظیمات ----------
void loadConfig() {
  File f = LittleFS.open("/config.json", "r");
  if (!f) return;                                  // هنوز ذخیره نشده
  JsonDocument doc;
  if (!deserializeJson(doc, f)) {
    cfg.lat = doc["lat"] | cfg.lat;
    cfg.lon = doc["lon"] | cfg.lon;
  }
  f.close();
}

bool saveConfig(const Config &c) {
  JsonDocument doc;
  doc["lat"] = c.lat;
  doc["lon"] = c.lon;
  File f = LittleFS.open("/config.tmp", "w");      // اول در فایل موقت
  if (!f) return false;
  bool ok = serializeJson(doc, f) > 0;
  f.close();
  if (!ok) return false;
  LittleFS.remove("/config.json");
  return LittleFS.rename("/config.tmp", "/config.json");  // بعد جابه‌جا
}

// ---------- Task هوا: هر ۱۰ دقیقه یا وقتی تنظیمات عوض شد ----------
bool fetchWeather(float lat, float lon, Weather &w) {
  char url[160];
  snprintf(url, sizeof(url),
           "https://api.open-meteo.com/v1/forecast?latitude=%.2f&longitude=%.2f"
           "&current=temperature_2m,wind_speed_10m", lat, lon);
  WiFiClientSecure client;
  client.useBuiltinCACertBundle();
  HTTPClient http;
  http.setConnectTimeout(5000);
  http.setTimeout(5000);
  http.useHTTP10(true);
  if (!http.begin(client, url)) return false;
  int code = http.GET();
  bool ok = false;
  if (code == HTTP_CODE_OK) {
    JsonDocument filter;
    filter["current"]["temperature_2m"] = true;
    filter["current"]["wind_speed_10m"] = true;
    JsonDocument doc;
    if (!deserializeJson(doc, http.getStream(), DeserializationOption::Filter(filter))) {
      w.temp = doc["current"]["temperature_2m"] | NAN;
      w.wind = doc["current"]["wind_speed_10m"] | NAN;
      w.at = millis();
      ok = !isnan(w.temp);
    }
  }
  http.end();
  return ok;
}

void weatherTask(void *param) {
  for (;;) {
    if (WiFi.status() == WL_CONNECTED) {
      xSemaphoreTake(cfgMutex, portMAX_DELAY);
      Config c = cfg;                              // کپی، بعد قفل را پس بده
      xSemaphoreGive(cfgMutex);
      Weather w;
      if (fetchWeather(c.lat, c.lon, w)) {
        xQueueOverwrite(weatherBox, &w);           // جای مقدار قبلی
      }
    }
    // ۱۰ دقیقه بخواب، مگر این که کسی زودتر بیدارمان کند
    ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(10UL * 60 * 1000));
  }
}

// ---------- Task نمایش: هر ۲ ثانیه آخرین هوا روی OLED ----------
void displayTask(void *param) {
  Weather w;
  for (;;) {
    display.clearDisplay();
    display.setCursor(0, 0);
    display.println(WiFi.localIP());
    if (xQueuePeek(weatherBox, &w, 0) == pdPASS) {  // نگاه کن، برندار
      display.setTextSize(2);
      display.printf("%.1f C\n", w.temp);
      display.setTextSize(1);
      display.printf("wind %.1f km/h\n", w.wind);
      display.printf("%lu min ago", (millis() - w.at) / 60000);
    } else {
      display.println("waiting for data...");
    }
    display.display();
    vTaskDelay(pdMS_TO_TICKS(2000));
  }
}

// ---------- وب: صفحه از LittleFS، داده از کد ----------
void handleState() {
  Weather w = {NAN, NAN, 0};
  xQueuePeek(weatherBox, &w, 0);
  JsonDocument doc;
  xSemaphoreTake(cfgMutex, portMAX_DELAY);
  doc["lat"] = cfg.lat;
  doc["lon"] = cfg.lon;
  xSemaphoreGive(cfgMutex);
  doc["temp"] = w.temp;
  doc["wind"] = w.wind;
  doc["reset"] = resetText;                         // ★ جعبه سیاه
  doc["boots"] = bootCount;
  doc["crashes"] = crashCount;
  String out;
  serializeJson(doc, out);
  server.send(200, "application/json", out);
}

void handleSave() {
  Config c = {server.arg("lat").toFloat(), server.arg("lon").toFloat()};
  if (c.lat < -90 || c.lat > 90 || c.lon < -180 || c.lon > 180) {
    return server.send(400, "text/plain", "bad lat/lon");
  }
  xSemaphoreTake(cfgMutex, portMAX_DELAY);
  cfg = c;
  xSemaphoreGive(cfgMutex);
  saveConfig(c);
  xTaskNotifyGive(weatherHandle);                  // «همین الان دوباره بگیر»
  server.sendHeader("Location", "/");
  server.send(303);
}

void setup() {
  Serial.begin(115200);
  recordBoot();                                    // ★ اولین کار بعد از Serial
  LittleFS.begin(true);
  loadConfig();
  weatherBox = xQueueCreate(1, sizeof(Weather));
  cfgMutex = xSemaphoreCreateMutex();

  Wire.begin(21, 22);
  display.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  display.setTextColor(SSD1306_WHITE);

  WiFi.mode(WIFI_STA);
  WiFi.setAutoReconnect(true);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  unsigned long t0 = millis();
  while (WiFi.status() != WL_CONNECTED && millis() - t0 < 20000) delay(250);

  ArduinoOTA.setHostname("weather-station");
  ArduinoOTA.setPassword(OTA_PASS);
  ArduinoOTA.onProgress([](unsigned int done, unsigned int total) {
    feedLoopWDT();                                 // ★ OTA جلوی loop را می‌گیرد: نگهبان را سیر نگه دار
  });
  ArduinoOTA.begin();

  server.serveStatic("/", LittleFS, "/index.html");
  server.on("/api/state", HTTP_GET, handleState);
  server.on("/api/config", HTTP_POST, handleSave);
  server.begin();

  xTaskCreatePinnedToCore(weatherTask, "weather", 12288, NULL, 1, &weatherHandle, 1);
  xTaskCreatePinnedToCore(displayTask, "display", 4096, NULL, 1, NULL, 1);
  enableLoopWDT();                                 // ★ اگر loop بیش از ۵ ثانیه گیر کرد: ریست
}

void loop() {
  ArduinoOTA.handle();
  server.handleClient();
#if CRASH_TEST
  if (millis() > 60000) {                          // ★ بعد از یک دقیقه...
    Serial.println("CRASH_TEST: loop is stuck now");
    while (true) {}                                // ★ ...برای همیشه گیر، بدون سیر کردن
  }
#endif
  delay(2);
}
  1. دو هدر بیشتر. Preferences برای شمارنده‌ها و esp_system.h برای دلیل ریست. شمارنده‌هایی که باید از ریست جان سالم به در ببرند در NVS زندگی می‌کنند، دقیقا مثل چک‌لیست قابلیت اطمینان.
  2. یک کلید برای آزمایش. CRASH_TEST 1 نسخه خراب را می‌سازد و ۰ نسخه درست را. یک عدد تعیین می‌کند باگ کامپایل شود یا نه (#if کد را کاملا حذف می‌کند)، پس نسخه درست همان برنامه است، نه یک کپی که ممکن است به‌روز کردنش یادت برود.
  3. جعبه سیاه در RAM. متن دلیل و دو شمارنده به صورت سراسری. یک بار در setup خوانده می‌شوند و بعد فقط فرستاده می‌شوند. handleState در loop اجرا می‌شود، پس بدون قفل می‌تواند آن‌ها را بخواند.
  4. کد دلیل به متن. کپی از RobustBoot. صفحه باید بگوید «TASK WATCHDOG»، نه «6».
  5. recordBoot()‎. دلیل را بخوان، به boots یکی اضافه کن، و فقط برای panic، نگهبان یا brownout به crashes یکی اضافه کن؛ بعد یک خط خلاصه چاپ کن. روشن شدن، ریست نرم‌افزاری (OTA) یا بیدار شدن از خواب عادی است؛ فقط خرابی‌های واقعی باید کرش حساب شوند. شمارنده فقط وقتی عوض می‌شود نوشته می‌شود.
  6. سه فیلد بیشتر در ‎/api/state. صفحه همین حالا این JSON را می‌گیرد، پس جعبه سیاه آدرس تازه لازم ندارد؛ صفحه فقط باید کلیدهای تازه را نشان دهد.
  7. اول ثبت کن. recordBoot() اولین کار بعد از Serial.begin است. اگر چیزی بعدا در setup کرش کند، این روشن شدن از قبل شمرده شده است.
  8. سیر کردن نگهبان در حین OTA. onProgress بعد از هر تکه دریافتی صدا زده می‌شود؛ feedLoopWDT() به نگهبان می‌گوید «loop زنده است». بدون این خط‌ها نسخه درست هرگز نمی‌توانست بی‌سیم برسد: نگهبان هر آپلود را بعد از ۵ ثانیه قطع می‌کرد. سیر کردن (به جای خاموش کردن نگهبان) محافظت را نگه می‌دارد: گیر کردن واقعی در حین آپلود باز هم ریست می‌کند.
  9. روشن کردن نگهبان loop. از این به بعد اگر loop یک دورش را در ۵ ثانیه تمام نکند، برد ریست می‌شود. در آخر setup می‌آید، چون انتظار Wi-Fi بالاتر ممکن است تا ۲۰ ثانیه طول بکشد.
  10. باگ عمدی. بعد از یک دقیقه، loop در یک while بی‌پایان گیر می‌کند. در دقیقه اول ArduinoOTA.handle() هنوز اجرا می‌شود، پس نسخه درست هنوز می‌تواند با OTA برسد؛ بعد از آن، نگهبان حدود ۵ ثانیه بعد برد را ریست می‌کند و دقیقه بعدی شروع می‌شود.

APIها را با HTTPS، سقف زمان، فیلتر JSON و فاصله منطقی صدا بزن، و هر جا چیز مهمی رد و بدل می‌شود هویت سرور را با بسته گواهی داخلی بررسی کن. دستگاهی که ماه‌ها کار می‌کند علت ریستش را ثبت می‌کند، کرش‌هایش را می‌شمارد، اجازه می‌دهد نگهبان وقتی گیر کرد ریستش کند، از تکه‌تکه شدن Heap دوری می‌کند و فایل‌ها را امن ذخیره می‌کند. ایستگاه هوا همه را کنار هم می‌گذارد: کار کند در Task خودش، داده در یک صندوق پستی تک‌خانه، تنظیمات در LittleFS و آپدیت با OTA.

این پایان فصل ۵ است. در درس ۶.۱ یاد می‌گیری دستگاهی مثل همین را با خواب عمیق و خواب سبک ماه‌ها با باتری روشن نگه داری.
