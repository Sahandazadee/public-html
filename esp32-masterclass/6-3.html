این درس امتحان نهایی توست، ولی امتحانی که با هم می‌نویسیم. یک ایستگاه پایش محیط کامل می‌سازیم: دما، رطوبت و نور را اندازه می‌گیرد، روی نمایشگر نشان می‌دهد، اگر هوا بیش از حد گرم شد با چراغ و بوق هشدار می‌دهد، و همه چیز را از طریق اینترنت به یک داشبورد ابری می‌فرستد. تقریبا همه چیزهایی که در این دوره یاد گرفتی اینجا کنار هم قرار می‌گیرند. مهم‌تر از خود پروژه، روش ساختن آن است: قدم به قدم، و هر قدم آزمایش‌شده.

🎯 بعد از این درس می‌توانی

  • قبل از کدنویسی، نیازمندی‌ها و معماری یک پروژه را روی کاغذ بیاوری
  • پین‌ها را با دلیل انتخاب کنی و فهرست قطعات بنویسی
  • یک پروژه بزرگ را در گام‌های کوچک آزمایش‌پذیر بسازی
  • با millis() چند کار هم‌زمان را بدون مسدود کردن برنامه زمان‌بندی کنی
  • هشداری بسازی که با هیسترزیس نوسان نکند و با محدودیت نرخ پیام اسپم نفرستد
  • داده‌ها را با MQTT به HiveMQ یا Adafruit IO بفرستی و روی داشبورد ببینی

قدم صفر: نیازمندی‌ها (یک PRD کوچک)

حرفه‌ای‌ها قبل از کد، یک سند کوتاه می‌نویسند که بگوید محصول دقیقا چه کاری باید بکند. به آن PRD (سند نیازمندی‌های محصول) می‌گویند. بدون آن، پروژه مدام بزرگ‌تر می‌شود و هیچ‌وقت «تمام» نمی‌شود، چون نمی‌دانی «تمام» یعنی چه.

مثال از زندگی: نقشه ساختمان

هیچ بنایی بدون نقشه شروع به آجرچینی نمی‌کند. اگر وسط کار صاحبخانه بگوید «راستی یک طبقه دیگر هم می‌خواهم»، ستون‌ها از قبل برای آن طراحی نشده‌اند. PRD نقشه پروژه توست: کوتاه، ولی روشن.

معماری سیستم

سه «جریان» داریم: خواندن سنسور (سریع و محلی)، تصمیم هشدار (محلی)، و ارسال به ابر (کند و با احتمال شکست). معماری طوری است که جریان سوم هرگز دو تای اول را معطل نکند.

روش ساختن: گام‌های کوچک، هر گام آزمایش‌شده

بزرگ‌ترین اشتباه مبتدی‌ها: همه قطعه‌ها را وصل می‌کنند، ۲۰۰ خط کد می‌نویسند، آپلود می‌کنند و... هیچ چیز کار نمی‌کند. حالا مشکل کجاست؟ سنسور؟ نمایشگر؟ Wi-Fi؟ کد؟ نمی‌دانی. ما شش گام برمی‌داریم و تا گام قبلی کار نکرده، به گام بعد نمی‌رویم:

  1. سنسورها ← عدد درست در Serial Monitor
  2. نمایشگر ← همان عددها روی OLED
  3. هشدار محلی ← LED و بازر با هیسترزیس، بدون delay
  4. Wi-Fi ← اتصال و اتصال دوباره بدون مسدود کردن
  5. MQTT ← پیام آزمایشی در کلاینت MQTT
  6. ادغام و هشدار ابری ← برنامه نهایی با زمان‌بندی millis
Wokwi برای همه گام‌ها

مدار Wokwi پایین گام ۳ (و همان مدار در انتهای گام ۶) همه قطعه‌های پروژه را دارد. برای امتحان هر گام در Wokwi، همان diagram.json را نگه دار و فقط کد آن گام را در sketch.ino بچسبان؛ قطعه‌هایی که کد گام از آن‌ها استفاده نمی‌کند، کاری نمی‌کنند. کتابخانه‌های لازم را هم در تب Library Manager خود Wokwi اضافه کن.

مثل پختن غذا

آشپز خوب هر ماده را جدا می‌چشد: آیا نمک کافی است؟ آیا گوشت پخته؟ بعد آن‌ها را با هم مخلوط می‌کند. اگر همه را با هم در دیگ بریزی و آخرش مزه‌اش بد شد، نمی‌دانی تقصیر کدام بود.

گام ۱: سنسورها

// گام ۱: فقط سنسورها؛ خروجی در Serial Monitor
#include <DHT.h>

const int PIN_DHT = 13;
const int PIN_LDR = 35;                  // ADC1: با Wi-Fi هم کار می‌کند
DHT dht(PIN_DHT, DHT22);

void setup() {
  Serial.begin(115200);
  dht.begin();
  analogReadResolution(12);              // خروجی 0 تا 4095
}

void loop() {
  float t = dht.readTemperature();       // سانتی‌گراد
  float h = dht.readHumidity();          // درصد
  int raw = analogRead(PIN_LDR);
  int lightPct = map(raw, 4095, 0, 0, 100);   // نور بیشتر = ولتاژ کمتر
  if (isnan(t) || isnan(h)) Serial.println("DHT22 error!");
  else Serial.printf("T=%.1f C  H=%.0f %%  LDR raw=%d  light=%d %%\n", t, h, raw, lightPct);
  delay(2000);                           // در این گام آزمایشی delay اشکالی ندارد
}
  1. پین‌ها و شیء سنسور. DHT22 روی GPIO13 و LDR روی GPIO35، دقیقا مثل جدول پین‌ها. از همین گام اول پین‌های نهایی را استفاده می‌کنیم. اگر الان پین موقتی بگذاری، در ادغام نهایی یک جای دیگر برای خطا ساخته‌ای.
  2. دقت ADC. ۱۲ بیت یعنی عدد ۰ تا ۴۰۹۵. این پیش‌فرض ESP32 است، ولی نوشتنش صریحا نشان می‌دهد به چه بازه‌ای تکیه کرده‌ایم و بعدا در map از آن استفاده می‌کنیم.
  3. خواندن DHT22. دما به سانتی‌گراد و رطوبت به درصد. اگر خواندن شکست بخورد، NaN (یعنی «عدد نیست») برمی‌گردد. DHT22 کند است و حداکثر هر ۲ ثانیه یک بار داده تازه می‌دهد. برای همین کل سیستم را روی دوره ۲ ثانیه‌ای طراحی کرده‌ایم.
  4. نور به درصد. map(raw, 4095, 0, 0, 100) بازه را برعکس تبدیل می‌کند: ۴۰۹۵ (تاریک) ← ۰ درصد، ۰ (روشن) ← ۱۰۰ درصد. در ماژول‌های رایج LDR (و ماژول Wokwi)، با زیاد شدن نور ولتاژ AO کم می‌شود. اگر ماژول تو برعکس است (با پوشاندن سنسور، درصد زیاد می‌شود)، فقط ترتیب را عوض کن: map(raw, 0, 4095, 0, 100). این عدد «درصد نسبی» است، نه لوکس واقعی.
  5. چاپ با بررسی خطا. اگر هر کدام NaN بود پیام خطا، وگرنه همه مقادیر در یک خط. چاپ raw کنار درصد، در عیب‌یابی کمک می‌کند: اگر raw همیشه ۰ یا ۴۰۹۵ است، سیم‌کشی LDR مشکل دارد، نه فرمول.
آزمون قبول گام ۱

دما و رطوبت عدد معقول (مثلا ۲۰ تا ۳۰ درجه و ۲۰ تا ۶۰ درصد) نشان دهند؛ با گرفتن سنسور در دست دما کم‌کم بالا برود؛ با پوشاندن LDR درصد نور کم شود. سیم DATA را جدا کن: باید «DHT22 error!» ببینی. همه درست؟ برو گام ۲.

گام ۲: نمایشگر OLED

// گام ۲: نمایش روی OLED
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>

DHT dht(13, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);   // -1: پایه ریست ندارد

void setup() {
  Serial.begin(115200);
  dht.begin();
  Wire.begin(21, 22);                          // SDA, SCL
  if (!oled.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    Serial.println("OLED not found! check wiring/address");
    while (true) delay(1000);                  // بدون نمایشگر، این گام معنی ندارد
  }
  oled.setTextColor(SSD1306_WHITE);
}

void loop() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  oled.clearDisplay();
  oled.setTextSize(2);
  oled.setCursor(0, 0);
  if (isnan(t)) oled.print("T: ERR"); else { oled.print(t, 1); oled.print(" C"); }
  oled.setCursor(0, 24);
  if (isnan(h)) oled.print("H: ERR"); else { oled.print(h, 0); oled.print(" %"); }
  oled.display();                              // تا این خط، چیزی روی صفحه نمی‌آید
  delay(2000);
}
  1. کتابخانه‌ها. Wire برای I2C (جزو هسته)، Adafruit GFX برای رسم متن و شکل، Adafruit SSD1306 برای خود نمایشگر. GFX «زبان رسم» مشترک بین نمایشگرهای Adafruit است؛ SSD1306 مترجم آن برای این نمایشگر خاص. هر دو را از Library Manager نصب کن.
  2. ساخت شیء نمایشگر. عرض ۱۲۸، ارتفاع ۶۴، روی باس Wire، بدون پایه ریست. ماژول‌های چهارپایه پایه ریست ندارند؛ -1 یعنی «ریست را نرم‌افزاری انجام بده».
  3. راه‌اندازی I2C و نمایشگر. آدرس رایج 0x3C است. اگر begin شکست بخورد، پیام می‌دهیم و متوقف می‌شویم. در این گام آزمایشی، توقف درست است: می‌خواهیم مشکل نمایشگر را فورا ببینیم. در برنامه نهایی این کار را نمی‌کنیم، چون خرابی نمایشگر نباید هشدار و ارسال را هم از کار بیندازد (R8). اگر پیدا نشد، آدرس 0x3D را امتحان کن یا با برنامه اسکنر I2C درس ۳.۳ آدرس را پیدا کن.
  4. رسم. پاک کردن بافر، اندازه متن ۲ (حروف ۱۲×۱۶ پیکسل)، رفتن به مختصات، چاپ، و در آخر display(). همه دستورهای رسم فقط در یک بافر در RAM نوشته می‌شوند؛ display() کل بافر را یک‌جا از طریق I2C می‌فرستد. این باعث می‌شود صفحه چشمک نزند. print(t, 1) یعنی یک رقم اعشار.

هیسترزیس: مثل ترموستات بخاری

اگر هشدار را با یک عدد (۳۵ درجه) روشن و با همان عدد خاموش کنی، وقتی دما حوالی ۳۵ درجه است (۳۴٫۹، ۳۵٫۱، ۳۴٫۹...) هشدار مدام روشن و خاموش می‌شود و بازر دیوانه‌ات می‌کند. ترموستات بخاری هم همین را حل کرده: در ۲۰ درجه روشن می‌شود ولی تا ۲۲ درجه نشود خاموش نمی‌شود. به این «فاصله امن» هیسترزیس می‌گویند. ما هشدار را بالای ۳۵ روشن و زیر ۳۳ خاموش می‌کنیم.

مفهوم دوم: زمان‌بندی بدون delay (درس ۳.۱). چون LED باید چشمک بزند، بازر بوق بزند و دکمه هم‌زمان خوانده شود، نمی‌توانیم با delay(2000) برنامه را قفل کنیم. به جایش هر کار را با «آیا وقتش رسیده؟» (millis()) انجام می‌دهیم.

// گام ۳: هشدار محلی با هیسترزیس و بدون delay
#include <DHT.h>

const int PIN_LED = 4, PIN_BUZ = 25, PIN_BTN = 27;
const float TEMP_HIGH = 35.0, TEMP_CLEAR = 33.0;
DHT dht(13, DHT22);

float tempC = NAN;
bool alarmOn = false, muted = false;
uint32_t tSensor = 0;

void setup() {
  Serial.begin(115200);
  dht.begin();
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  ledcAttach(PIN_BUZ, 2000, 8);           // API هسته 3.x
}

void loop() {
  if (millis() - tSensor >= 2000) {       // هر ۲ ثانیه، بدون متوقف کردن برنامه
    tSensor = millis();
    float t = dht.readTemperature();
    if (!isnan(t)) tempC = t;
    if (!alarmOn && tempC > TEMP_HIGH) { alarmOn = true;  muted = false; Serial.println("ALARM ON"); }
    if (alarmOn && tempC < TEMP_CLEAR) { alarmOn = false; Serial.println("ALARM OFF"); }
  }
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;   // دکمه = بی‌صدا

  bool blink = (millis() / 250) % 2;      // هر ۲۵۰ میلی‌ثانیه صفر و یک می‌شود
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {              // فقط وقتی لازم است LEDC را عوض کن
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}
  1. دو آستانه. ۳۵ برای روشن شدن و ۳۳ برای خاموش شدن. فاصله ۲ درجه از نوسان طبیعی خواندن DHT22 (حدود نیم درجه) و نوسان‌های کوتاه دمای اتاق بزرگ‌تر است. فاصله خیلی کم = نوسان؛ فاصله خیلی زیاد = هشدار دیر خاموش می‌شود.
  2. وضعیت برنامه. آخرین دمای معتبر (اول NaN)، روشن بودن هشدار، بی‌صدا بودن، و زمان آخرین خواندن. این متغیرها «حافظه» برنامه‌اند. چون loop هزاران بار در ثانیه اجرا می‌شود، هر تصمیم باید بر اساس وضعیت ذخیره‌شده باشد، نه منتظر ماندن.
  3. ledcAttach برای بازر. پین ۲۵ را به PWM با فرکانس اولیه ۲۰۰۰ هرتز و دقت ۸ بیت وصل می‌کند. بازر پسیو خودش صدا تولید نمی‌کند؛ باید با یک موج مربعی در فرکانس صوتی به لرزه بیفتد. این API هسته ۳.x است؛ در ۲.x باید ledcSetup و ledcAttachPin می‌نوشتی (درس ۳.۲).
  4. خواندن زمان‌بندی‌شده و منطق هیسترزیس. هر ۲ ثانیه دما خوانده می‌شود؛ فقط اگر معتبر بود جایگزین می‌شود. هشدار خاموش + دما بالای ۳۵ ← روشن (و بی‌صدا لغو). هشدار روشن + دما زیر ۳۳ ← خاموش. شرط‌ها «وضعیت فعلی» را هم چک می‌کنند؛ پس پیام «ALARM ON» فقط یک بار، در لحظه تغییر، چاپ می‌شود. این همان الگویی است که بعدا برای پیام ابری بدون اسپم استفاده می‌کنیم. اگر دما NaN باشد، هر مقایسه‌ای با آن false است و وضعیت عوض نمی‌شود.
  5. دکمه بی‌صدا. اگر در حال هشدار دکمه فشرده شد، بازر ساکت می‌شود؛ LED همچنان چشمک می‌زند. بی‌صدا کردن فقط صدا را قطع می‌کند، نه خود هشدار را؛ خطر هنوز وجود دارد و باید دیده شود. با شروع هشدار بعدی، muted دوباره false می‌شود (خط ۲۵).
  6. چشمک بدون delay. millis() / 250 هر ۲۵۰ میلی‌ثانیه یکی زیاد می‌شود؛ باقیمانده تقسیم بر ۲ یکی در میان ۰ و ۱ است. یک ترفند یک‌خطی برای چشمک زدن بدون هیچ متغیر اضافی. LED فقط وقتی روشن است که هشدار روشن باشد و blink یک باشد.
  7. بازر فقط هنگام تغییر. ledcWriteTone(pin, 2000) بوق ۲ کیلوهرتز، ledcWriteTone(pin, 0) سکوت. ولی فقط وقتی خواسته با وضعیت فعلی فرق دارد. loop هزاران بار در ثانیه می‌چرخد. تنظیم دوباره PWM در هر دور بی‌فایده است و ممکن است صدای بازر را خش‌دار کند. متغیر static وضعیت قبلی را بین دورها به خاطر می‌سپارد.

مدار کامل ایستگاه (همان مدار گام ۶). در تب Library Manager خود Wokwi کتابخانه DHT sensor library را اضافه کن، ▶ را بزن و آزمون قبول پایین را قدم به قدم انجام بده. Wokwi صدای بازر را هم پخش می‌کند.

آزمون قبول گام ۳

در Wokwi روی DHT22 کلیک کن و دما را به ۳۶ ببر: LED باید چشمک بزند و بازر بوق بزند. دکمه را بزن: بازر ساکت، LED همچنان چشمک. دما را به ۳۴ بیاور: هشدار نباید خاموش شود (هیسترزیس!). به ۳۲ بیاور: خاموش. روی برد واقعی، سنسور را برای چند ثانیه نزدیک (نه چسبیده به) یک سشوار با باد ملایم بگیر، یا موقتا TEMP_HIGH را کمی بالاتر از دمای اتاق بگذار.

گام ۴: Wi-Fi بدون مسدود کردن

در درس ۴.۱ اتصال و اتصال دوباره را یاد گرفتی. نکته این گام: هرگز در loop با while منتظر Wi-Fi نمانیم، چون در آن مدت هشدار محلی کار نمی‌کند (R8).

// گام ۴: Wi-Fi غیرمسدودکننده
#include <WiFi.h>

const char* WIFI_SSID = "Wokwi-GUEST";         // برد واقعی: اسم Wi-Fi خودت
const char* WIFI_PASS = "";                    // برد واقعی: رمز Wi-Fi خودت
uint32_t tWifi = 0;
bool wasConnected = false;

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);        // شروع اتصال؛ منتظر نمی‌مانیم
}

void loop() {
  bool ok = (WiFi.status() == WL_CONNECTED);
  if (ok && !wasConnected) {
    Serial.print("WiFi connected, IP = ");
    Serial.println(WiFi.localIP());
  }
  if (!ok && wasConnected) Serial.println("WiFi lost!");
  if (!ok && millis() - tWifi >= 15000) {  // هر ۱۵ ثانیه یک تلاش دوباره
    tWifi = millis();
    Serial.println("WiFi not connected, retrying...");
    WiFi.reconnect();
  }
  wasConnected = ok;
  // ... اینجا بقیه کارها بدون معطلی اجرا می‌شوند ...
}
  1. شروع اتصال و رفتن. WiFi.begin فقط اتصال را شروع می‌کند و فورا برمی‌گردد. اتصال در پس‌زمینه (توسط سیستم‌عامل FreeRTOS داخل ESP32) انجام می‌شود. ما فقط هر وقت لازم شد وضعیت را نگاه می‌کنیم.
  2. تشخیص تغییر وضعیت. با مقایسه وضعیت فعلی و قبلی (wasConnected)، فقط لحظه وصل شدن و لحظه قطع شدن پیام چاپ می‌شود. این همان الگوی «لبه» است که در هشدار هم دیدی: کار را در لحظه تغییر انجام بده، نه در هر دور loop.
  3. تلاش دوباره دوره‌ای. اگر وصل نیستیم، هر ۱۵ ثانیه یک بار WiFi.reconnect(). هسته ESP32 به‌طور پیش‌فرض خودش هم برای اتصال دوباره تلاش می‌کند؛ این تلاش دستی یک لایه اطمینان اضافه است. فاصله ۱۵ ثانیه جلوی «کوبیدن» مودم با درخواست‌های پشت سر هم را می‌گیرد.

گام ۵: MQTT

بروکر عمومی broker.hivemq.com روی پورت ۱۸۸۳ بدون ثبت‌نام کار می‌کند (درس ۵.۱). چون عمومی است، هر کسی می‌تواند پیام‌های تو را ببیند؛ پس topic را با یک پیشوند یکتا بساز (مثلا با نام و یک عدد تصادفی) و هیچ داده خصوصی نفرست.

// گام ۵: ارسال پیام آزمایشی به MQTT
#include <WiFi.h>
#include <PubSubClient.h>

const char* MQTT_HOST = "broker.hivemq.com";
const char* BASE = "esp32fa/station-42/";      // این را یکتا کن!
WiFiClient net;
PubSubClient mqtt(net);
uint32_t tMqtt = 0, tPub = 0;

void setup() {
  Serial.begin(115200);
  WiFi.begin("Wokwi-GUEST", "");             // برد واقعی: اسم و رمز Wi-Fi خودت
  mqtt.setServer(MQTT_HOST, 1883);
}

void loop() {
  if (WiFi.status() != WL_CONNECTED) return;   // بدون Wi-Fi کاری نکن
  if (!mqtt.connected()) {
    if (millis() - tMqtt < 5000) return;      // حداکثر هر ۵ ثانیه یک تلاش
    tMqtt = millis();
    String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX) + "-" + String(esp_random() & 0xFFFF, HEX);
    Serial.println(mqtt.connect(id.c_str()) ? "MQTT connected" : "MQTT failed");
    return;
  }
  mqtt.loop();                                 // اتصال را زنده نگه دار
  if (millis() - tPub >= 10000) {
    tPub = millis();
    String topic = String(BASE) + "test";
    String msg = String(millis() / 1000);
    mqtt.publish(topic.c_str(), msg.c_str());
    Serial.println("Published " + topic + " = " + msg);
  }
}
  1. پیشوند topic. همه topicهای این پروژه با esp32fa/station-42/ شروع می‌شوند. یک پیشوند یعنی می‌توانی در کلاینت با esp32fa/station-42/# همه پیام‌های ایستگاه را یک‌جا ببینی. و اگر به Adafruit IO رفتی، فقط همین یک خط را عوض می‌کنی.
  2. اتصال با فاصله. اگر Wi-Fi نیست، فورا از loop برمی‌گردیم. اگر MQTT وصل نیست، حداکثر هر ۵ ثانیه یک بار تلاش می‌کنیم. شناسه کلاینت از آدرس MAC ساخته می‌شود. شناسه باید یکتا باشد؛ اگر دو دستگاه با یک شناسه وصل شوند، بروکر اولی را بیرون می‌اندازد و آن‌ها مدام همدیگر را قطع می‌کنند. توجه: خود mqtt.connect ممکن است وقتی سرور در دسترس نیست چند ثانیه طول بکشد؛ این تنها نقطه‌ای است که کمی مسدود می‌شویم.
  3. mqtt.loop(). باید مرتب صدا زده شود. پیام‌های «زنده‌ام» (keep-alive) را به بروکر می‌فرستد و پیام‌های ورودی را پردازش می‌کند. اگر loop با delay طولانی قفل شود، بروکر فکر می‌کند دستگاه مرده و اتصال را قطع می‌کند.
  4. انتشار هر ۱۰ ثانیه. زمان روشن بودن برد (ثانیه) را به topic .../test می‌فرستد. یک پیام آزمایشی ساده و همیشه‌متغیر؛ اگر عدد در کلاینت زیاد می‌شود، کل زنجیره (Wi-Fi، DNS، TCP، MQTT) سالم است.
پیام‌ها را کجا ببینم؟

در یک کلاینت MQTT (مثلا کلاینت وب HiveMQ یا برنامه‌ای که در درس ۵.۱ استفاده کردی) به broker.hivemq.com وصل شو و topic esp32fa/station-42/# را subscribe کن (# یعنی «همه زیرشاخه‌ها»). آزمون قبول گام ۵: هر ۱۰ ثانیه یک عدد جدید ببینی.

گام ۶: برنامه نهایی یکپارچه

حالا همه گام‌ها را در یک برنامه با ساختار تمیز کنار هم می‌گذاریم. ساختار برنامه:

  • تنظیمات همه در بالا؛ برای تغییر رفتار، لازم نیست در کد بگردی.
  • هر مسئولیت یک تابع: خواندن سنسور، منطق هشدار، خروجی‌ها، نمایشگر، شبکه، ارسال.
  • loop فقط زمان‌بندی می‌کند: «آیا وقت خواندن است؟ آیا وقت ارسال است؟» و بقیه را به توابع می‌سپارد.
// ایستگاه پایش محیط با هشدار ابری — درس ۶.۳
#include <WiFi.h>
#include <PubSubClient.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>

// ================== ۱. تنظیمات ==================
const char* WIFI_SSID = "Wokwi-GUEST";         // برد واقعی: اسم Wi-Fi خودت
const char* WIFI_PASS = "";                    // برد واقعی: رمز Wi-Fi خودت
const char* MQTT_HOST = "broker.hivemq.com";
const uint16_t MQTT_PORT = 1883;
const char* MQTT_USER = nullptr;               // Adafruit IO: نام کاربری
const char* MQTT_KEY  = nullptr;               // Adafruit IO: AIO Key
const char* BASE      = "esp32fa/station-42/"; // پیشوند یکتای topicها

const float TEMP_HIGH  = 35.0;                 // بالاتر از این: هشدار
const float TEMP_CLEAR = 33.0;                 // پایین‌تر از این: پایان هشدار
const uint32_t SENSOR_MS  = 2000;              // هر ۲ ثانیه خواندن
const uint32_t PUBLISH_MS = 30000;             // هر ۳۰ ثانیه ارسال
const uint32_t REMIND_MS  = 600000;            // یادآوری هشدار: حداکثر هر ۱۰ دقیقه

// ================== ۲. پین‌ها ==================
const int PIN_DHT = 13;
const int PIN_LDR = 35;                        // ADC1: با Wi-Fi کار می‌کند
const int PIN_LED = 4;
const int PIN_BUZ = 25;
const int PIN_BTN = 27;                        // دکمه بی‌صدا

// ================== ۳. اشیا و وضعیت ==================
DHT dht(PIN_DHT, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);
WiFiClient net;
PubSubClient mqtt(net);

float tempC = NAN, hum = NAN;
int lightPct = 0;
bool alarmOn = false, muted = false, oledOk = false;
uint32_t tSensor = 0, tPublish = 0, tAlert = 0, tWifi = 0, tMqtt = 0;
float fakeTemp = NAN;                          // کمک تست: NAN = سنسور واقعی

// ================== ۴. سنسورها ==================
void readSensors() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) { tempC = t; hum = h; }
  else Serial.println("DHT22 read failed, keeping last value");
  if (!isnan(fakeTemp)) tempC = fakeTemp;      // کمک تست (بخش ۱۰)
  int raw = analogRead(PIN_LDR);               // 0..4095
  lightPct = map(raw, 4095, 0, 0, 100);        // نور بیشتر = ولتاژ کمتر
}

// ================== ۵. ارسال به ابر ==================
void publishValue(const char* name, float v, int decimals) {
  char topic[64], payload[16];
  snprintf(topic, sizeof(topic), "%s%s", BASE, name);
  snprintf(payload, sizeof(payload), "%.*f", decimals, v);
  mqtt.publish(topic, payload);
}

void publishAll() {
  if (!mqtt.connected() || isnan(tempC)) return;
  publishValue("temp", tempC, 1);
  publishValue("hum", hum, 0);
  publishValue("light", lightPct, 0);
  Serial.println("Published to MQTT");
}

void publishAlert(const char* msg) {
  tAlert = millis();                           // شمارش یادآوری از نو
  Serial.println(msg);
  if (!mqtt.connected()) return;
  char topic[64];
  snprintf(topic, sizeof(topic), "%salert", BASE);
  mqtt.publish(topic, msg);
}

// ================== ۶. منطق هشدار (هیسترزیس + محدودیت نرخ) ==================
void updateAlarm() {
  if (isnan(tempC)) return;
  if (!alarmOn && tempC > TEMP_HIGH) {
    alarmOn = true;
    muted = false;
    publishAlert("ALERT: temperature high");
  } else if (alarmOn && tempC < TEMP_CLEAR) {
    alarmOn = false;
    publishAlert("OK: temperature back to normal");
  } else if (alarmOn && millis() - tAlert >= REMIND_MS) {
    publishAlert("ALERT: still high");         // یادآوری، نه اسپم
  }
}

void driveOutputs() {
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;
  bool blink = (millis() / 250) % 2;
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}

// ================== ۷. نمایشگر ==================
void drawDisplay() {
  if (!oledOk) return;                         // نمایشگر نیست؟ بقیه کارها ادامه دارد
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setCursor(0, 0);
  oled.print(WiFi.status() == WL_CONNECTED ? "WiFi OK  " : "WiFi --  ");
  oled.print(mqtt.connected() ? "MQTT OK" : "MQTT --");
  oled.setTextSize(2);
  oled.setCursor(0, 14);
  if (isnan(tempC)) oled.print("T: ERR");
  else { oled.print(tempC, 1); oled.print(" C"); }
  oled.setCursor(0, 34);
  if (isnan(hum)) oled.print("H: ERR");
  else { oled.print(hum, 0); oled.print(" %"); }
  oled.setTextSize(1);
  oled.setCursor(0, 56);
  oled.printf("Light %d%%  %s", lightPct, alarmOn ? (muted ? "ALARM(m)" : "ALARM!") : "normal");
  oled.display();
}

// ================== ۸. شبکه (بدون مسدود کردن) ==================
void keepWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  if (millis() - tWifi < 15000) return;        // هر ۱۵ ثانیه یک تلاش
  tWifi = millis();
  Serial.println("WiFi: reconnecting...");
  WiFi.reconnect();
}

  tMqtt = millis();
  String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX) + "-" + String(esp_random() & 0xFFFF, HEX);
  String will = String(BASE) + "status";
  if (mqtt.connect(id.c_str(), MQTT_USER, MQTT_KEY, will.c_str(), 0, true, "offline")) {
    mqtt.publish(will.c_str(), "online", true);
    Serial.println("MQTT connected");
  } else {
    Serial.printf("MQTT failed, state=%d\n", mqtt.state());
  }
}

// ================== ۹. setup و loop ==================
void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  ledcAttach(PIN_BUZ, 2000, 8);                // API هسته 3.x
  analogReadResolution(12);
  dht.begin();
  Wire.begin(21, 22);
  oledOk = oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  if (oledOk) oled.setTextColor(SSD1306_WHITE);
  else Serial.println("OLED not found, continuing without display");
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  mqtt.setServer(MQTT_HOST, MQTT_PORT);
  net.setConnectionTimeout(1000);              // TCP: بعد از ۱ ثانیه بی‌خیال شو (پیش‌فرض ۳)
  mqtt.setSocketTimeout(2);                    // جواب بروکر: بعد از ۲ ثانیه (پیش‌فرض ۱۵)
  tWifi = millis();
}

void loop() {
  readSerialCommands();                        // کمک تست (بخش ۱۰)
  uint32_t now = millis();
  if (now - tSensor >= SENSOR_MS) {
    tSensor = now;
    readSensors();
    updateAlarm();
    drawDisplay();
  }
  if (now - tPublish >= PUBLISH_MS) {
    tPublish = now;
    publishAll();
  }
  keepWiFi();
  keepMqtt();
  driveOutputs();
}

// ================== ۱۰. کمک تست: دمای ساختگی از Serial ==================
void readSerialCommands() {
  if (!Serial.available()) return;
  String line = Serial.readStringUntil('\n');  // مثلا "t 36" یا "real"
  line.trim();
  if (line.startsWith("t ")) {
    fakeTemp = line.substring(2).toFloat();
    Serial.printf("Fake temperature: %.1f C\n", fakeTemp);
  } else if (line == "real") {
    fakeTemp = NAN;
    Serial.println("Using the real sensor again");
  }
}

برنامه را بخش به بخش مرور می‌کنیم. روی هر کارت بزن تا خط‌هایش در کد بالا پررنگ شود.

  1. بخش ۱: تنظیمات. شبکه، بروکر، نام کاربری و کلید (برای HiveMQ عمومی nullptr یعنی «ندارد»)، پیشوند topic، آستانه‌ها و فاصله‌های زمانی. دو خط Wi-Fi برای Wokwi است؛ روی برد واقعی اسم و رمز شبکه خودت را آنجا بنویس (یا به secrets.h ببر). هر عددی که ممکن است روزی بخواهی عوض کنی، باید اسم داشته باشد و بالای برنامه باشد. «عدد جادویی» ۶۰۰۰۰۰ وسط کد را شش ماه بعد هیچ‌کس نمی‌فهمد؛ REMIND_MS را همه می‌فهمند. در پروژه واقعی رمزها را به فایل secrets.h ببر (درس ۶.۲).
  2. بخش ۲: پین‌ها. دقیقا مطابق جدول پین‌ها و نقشه‌های سیم‌کشی. یک منبع حقیقت: اگر سیمی را جابه‌جا کردی، فقط این‌جا را عوض می‌کنی.
  3. بخش ۳: اشیا و وضعیت. سنسور، نمایشگر، کلاینت شبکه و MQTT؛ بعد آخرین مقدارها، وضعیت هشدار، سالم بودن نمایشگر، و «زمان آخرین بار» برای هر کار زمان‌بندی‌شده. متغیر آخر، fakeTemp، مال کمک تست بخش ۱۰ است. پنج متغیر t... پنج «ساعت» مستقل‌اند: هر کار ساعت خودش را دارد و بقیه را معطل نمی‌کند. این قلب زمان‌بندی بدون delay است.
  4. بخش ۴: خواندن سنسورها. مثل گام ۱، با یک تفاوت: اگر DHT22 خطا داد، آخرین مقدار معتبر نگه داشته می‌شود. خط آخر فقط موقع تست مهم است: اگر دمای ساختگی تایپ کرده باشی (بخش ۱۰)، جای دمای واقعی می‌نشیند. DHT22 گاهی یک خواندن را از دست می‌دهد. پاک کردن عدد با هر خطای تکی، باعث پرش «ERR» روی نمایشگر و قطع داده ابری می‌شود. تا اولین خواندن موفق، مقدار NaN است و نمایشگر ERR نشان می‌دهد (R1). در تمرین ۲ این را هوشمندتر می‌کنی.
  5. بخش ۵ (الف): یک تابع برای ارسال هر عدد. نام topic با BASE ساخته می‌شود و عدد با تعداد رقم اعشار دلخواه به متن تبدیل می‌شود (%.*f). سه بار تکرار یک کد، یعنی سه جا برای باگ. یک تابع کوچک یعنی یک جا. از snprintf با آرایه ثابت به جای String استفاده کردیم تا حافظه را تکه‌تکه نکنیم؛ در برنامه‌ای که ماه‌ها روشن است مهم است.
  6. بخش ۵ (ب): ارسال همه مقادیر. اگر MQTT وصل نیست یا هنوز هیچ دمای معتبری نداریم، ارسال نمی‌شود. فرستادن «nan» به داشبورد نمودارها را خراب می‌کند. سه topic جدا (temp، hum، light) با Adafruit IO سازگارند که هر feed یک عدد می‌خواهد. با ۳ مقدار هر ۳۰ ثانیه، یعنی ۶ پیام در دقیقه، زیر محدودیت نرخ نسخه رایگان Adafruit IO (حدود ۳۰ داده در دقیقه) می‌مانیم.
  7. بخش ۵ (ج): پیام هشدار. زمان را ثبت می‌کند، در Serial چاپ می‌کند و اگر وصل هستیم به .../alert می‌فرستد. tAlert حتی اگر ارسال ناموفق باشد به‌روز می‌شود؛ یعنی قطع شبکه باعث تلاش مکرر و انبوه پیام در لحظه وصل شدن نمی‌شود. نقطه ضعف آگاهانه: اگر شبکه در لحظه شروع هشدار قطع باشد، اولین پیام گم می‌شود و یادآوری ۱۰ دقیقه بعد جبرانش می‌کند (تمرین ۱ این را بهتر می‌کند).
  8. بخش ۶ (الف): هیسترزیس و محدودیت نرخ. سه حالت: شروع هشدار (بالای ۳۵ و قبلا خاموش)، پایان هشدار (زیر ۳۳ و قبلا روشن)، یادآوری (هنوز روشن و ۱۰ دقیقه از پیام قبلی گذشته). این سه شاخه دقیقا R5 و R7 را پیاده می‌کنند. بدون شاخه سوم، کاربری که پیام اول را ندیده هرگز نمی‌فهمد مشکل ادامه دارد. بدون محدودیت زمانی، هر ۲ ثانیه یک پیام می‌آمد: ۱۸۰۰ پیام در ساعت! آخرش گوشی‌ات را بی‌صدا می‌کنی و وقتی واقعا لازم است، دیگر هشدار را نمی‌بینی.
  9. بخش ۶ (ب): خروجی‌های محلی. همان منطق گام ۳: دکمه بی‌صدا، چشمک LED و بازر فقط هنگام تغییر. این تابع در هر دور loop اجرا می‌شود تا چشمک و دکمه روان باشند؛ برخلاف خواندن سنسور که فقط هر ۲ ثانیه است. کار سبک، زیاد؛ کار سنگین، کم.
  10. بخش ۷: نمایشگر. خط بالا وضعیت شبکه؛ وسط دما و رطوبت با حروف درشت؛ پایین نور و وضعیت هشدار (ALARM(m) یعنی بی‌صدا شده). اگر نمایشگر پیدا نشده بود، تابع فورا برمی‌گردد. نمایش وضعیت Wi-Fi و MQTT روی صفحه، عیب‌یابی در محل را بدون لپ‌تاپ ممکن می‌کند. oledOk یعنی خرابی نمایشگر (مثلا یک سیم شل) هشدار و ارسال را از کار نمی‌اندازد؛ برخلاف گام ۲ که عمدا متوقف می‌شد.
  11. بخش ۸ (الف): نگهداری Wi-Fi. مثل گام ۴. اگر وصل هستیم، تابع تقریبا بلافاصله برمی‌گردد؛ پس صدا زدنش در هر دور loop هزینه‌ای ندارد.
  12. بخش ۸ (ب): نگهداری MQTT با «وصیت‌نامه» (LWT). هنگام اتصال به بروکر می‌گوییم: «اگر من بی‌خبر قطع شدم، از طرف من پیام offline را با retain روی .../status منتشر کن». بلافاصله بعد از اتصال خودمان online را با retain می‌فرستیم. با این ترفند، داشبورد همیشه می‌داند ایستگاه زنده است یا نه؛ حتی اگر برق ایستگاه قطع شود و فرصت خداحافظی نداشته باشد. retain یعنی هر کس بعدا subscribe کند، آخرین وضعیت را فورا می‌گیرد. mqtt.state() در صورت شکست، کد خطا را می‌دهد (مثلا منفی یعنی مشکل شبکه، ۴ و ۵ یعنی نام کاربری یا کلید غلط). Adafruit IO از پرچم retain پشتیبانی نمی‌کند (درس ۵.۱)؛ ولی چون هر Feed آخرین مقدارش را خودش ذخیره می‌کند، داشبورد باز هم آخرین وضعیت را نشان می‌دهد. اگر با Adafruit IO دیدی اتصال مدام قطع و وصل می‌شود، در دو خط ۱۴۳ و ۱۴۴ مقدار true (retain) را false کن تا این عامل حذف شود.
    قطعی شبکه نباید هشدار محلی را قفل کند (R8)، پس برای طول هر تلاش اتصال سقف می‌گذاریم. mqtt.connect اول یک اتصال TCP به بروکر باز می‌کند و بعد منتظر جواب بروکر می‌ماند. در setup انتظار اول را به ۱ ثانیه (setConnectionTimeout) و دومی را به ۲ ثانیه (setSocketTimeout) محدود کرده‌ایم؛ پیش‌فرض‌ها ۳ و ۱۵ ثانیه‌اند و ۱۵ ثانیه سکوت وسط یک هشدار مشکل واقعی است. با فاصله ۵ ثانیه بین تلاش‌ها، بدترین حالت گاهی یکی دو ثانیه مکث در چشمک است، نه هشداری که قفل شده باشد. آزمایش T11 دقیقا همین را می‌سنجد. راه کاملا حرفه‌ای این است که کل بخش شبکه را در یک Task جدای FreeRTOS بگذاری تا خروجی‌های محلی هرگز معطل نشوند؛ همان کاری که در درس ۵.۴ یاد گرفتی (تمرین اختیاری).
  13. بخش ۹ (الف): setup. پین‌ها، بازر با API هسته ۳.x، ADC، سنسور، I2C و نمایشگر (بدون توقف در صورت خرابی)، شروع اتصال Wi-Fi (بدون انتظار) و تنظیم بروکر. دو خط آخر مشخص می‌کنند یک تلاش اتصال MQTT حداکثر چقدر می‌تواند برنامه را نگه دارد (بخش ۸ (ب) را ببین). setup هیچ حلقه انتظاری ندارد؛ یعنی دستگاه در کسری از ثانیه وارد loop می‌شود و هشدار محلی از همان ابتدا کار می‌کند، حتی اگر مودم خاموش باشد (R8).
  14. بخش ۹ (ب): loop، زمان‌بند مرکزی. هر ۲ ثانیه: خواندن، تصمیم هشدار، به‌روزرسانی نمایشگر. هر ۳۰ ثانیه: ارسال. در هر دور: نگهداری Wi-Fi و MQTT و خروجی‌ها. خط اول دنبال یک فرمان تست از Serial Monitor می‌گردد (بخش ۱۰). کل منطق برنامه در حدود ۱۵ خط قابل خواندن است. اگر فردا ویژگی جدیدی خواستی (مثلا ذخیره در کارت SD هر ۵ دقیقه)، فقط یک متغیر زمان و یک شرط if دیگر اضافه می‌کنی. now - tX >= فاصله حتی بعد از سرریز millis (حدود ۴۹ روز) درست کار می‌کند.
  15. بخش ۱۰: کمک تست، دمای ساختگی از Serial. در Serial Monitor بنویس t 36 و Enter بزن: از آن به بعد ایستگاه به جای عدد سنسور از ۳۶ درجه استفاده می‌کند. بنویس real تا به سنسور واقعی برگردد. از ورودی Serial که در درس ۳.۱ یاد گرفتی استفاده می‌کند؛ پایان خط Serial Monitor را روی Newline بگذار. در Wokwi کافی است روی DHT22 کلیک کنی و اسلایدر دما را بکشی؛ روی برد واقعی باید سنسور را با سشوار گرم کنی و صبر کنی تا دوباره خنک شود. با این کمک، آزمایش‌های T4 تا T8 روی برد واقعی هم چند دقیقه طول می‌کشند. چنین قلاب‌های تستی در محصولات واقعی رایج‌اند؛ نگهش دار، وقتی استفاده‌اش نکنی هزینه‌ای ندارد.

حالت باتری (اختیاری): ترکیب با درس ۶.۱

برنامه بالا همیشه روشن است و حدود ۱۰۰ میلی‌آمپر مصرف دارد؛ با باتری فقط یکی دو روز دوام می‌آورد. برای حالت باتری (R9) باید طراحی را عوض کنی، نه فقط یک خط اضافه کنی:

  • همه کار در setup(): بیدار شو، سنسور را بخوان، اگر لازم است پیام بفرست، بخواب (مثلا ۵ دقیقه). loop خالی می‌ماند.
  • وضعیت هشدار و زمان آخرین پیام در RTC_DATA_ATTR؛ چون millis() بعد از هر بیداری از صفر شروع می‌شود، برای محدودیت نرخ به جای زمان، «تعداد بیداری‌ها» را بشمار.
  • بازر و LED چشمک‌زن در خواب کار نمی‌کنند؛ هشدار محلی عملا به یک بوق کوتاه در هر بیداری تبدیل می‌شود. این یک مصالحه است که باید در PRD بنویسی.
  • OLED را قبل از خواب خاموش کن (oled.ssd1306_command(SSD1306_DISPLAYOFF)) وگرنه روشن می‌ماند و باتری می‌خورد.
  • دکمه روی GPIO27 (پین RTC) با EXT0 برد را برای نمایش فوری بیدار کند.

سخت‌افزار باتری (شارژر محافظ‌دار، رگولاتور کم‌مصرف، جریان خواب برد توسعه) را در ۶.۱ و ۱.۴ دیدی؛ همان‌جا را دوباره بخوان. پیاده‌سازی کامل این حالت تمرین ۳ است.

جعبه و محل نصب

  • سنسور را از ESP32 دور کن. ESP32 و رگولاتور روی برد، به‌خصوص با Wi-Fi روشن، گرم می‌شوند. DHT22 چسبیده به برد، چند درجه بیشتر از دمای واقعی اتاق نشان می‌دهد. دست‌کم چند سانتی‌متر فاصله بده یا سنسور را با سیم بیرون جعبه بگذار.
  • هوا باید جریان داشته باشد. جعبه دربسته، رطوبت و دمای داخل خودش را اندازه می‌گیرد. برای سنسور سوراخ‌های تهویه بگذار.
  • نور مستقیم خورشید ممنوع. خورشید مستقیم روی DHT22، دمای «خود سنسور» را اندازه می‌گیرد نه هوا. LDR را ولی باید جایی گذاشت که نور محیط را ببیند.
  • دور از منابع گرما و رطوبت (بخاری، کتری، آشپزخانه) مگر این که دقیقا همان را بخواهی بپایی.
  • برای بیرون از خانه جعبه ضدآب و یک «سایه‌بان تشعشع» (مثل پوسته‌های بشقابی ایستگاه‌های هواشناسی) لازم است؛ و ESP32 را از آب و میعان دور نگه دار.
  • آنتن Wi-Fi را نپوشان. آنتن روی ماژول WROOM (بخش موج‌دار انتهای ماژول) نباید نزدیک فلز یا زیر سیم‌ها باشد.

آزمون این درس

چرا LDR را به GPIO35 وصل کردیم و نه مثلا به GPIO25؟

  1. GPIO25 فقط خروجی است
  2. GPIO35 روی ADC1 است؛ ADC2 (مثل GPIO25) وقتی Wi-Fi روشن است کار نمی‌کند
  3. GPIO35 دقت بیشتری دارد
  4. GPIO35 تنها پین I2C است
ADC2 با رادیوی Wi-Fi مشترک است. در پروژه‌ای که Wi-Fi دارد، ورودی آنالوگ فقط روی ADC1 (GPIO32 تا 39).

هشدار با TEMP_HIGH=35 و TEMP_CLEAR=33 روشن است. دما به ۳۴ درجه می‌رسد. چه می‌شود؟

  1. هشدار خاموش می‌شود
  2. پیام «OK» فرستاده می‌شود
  3. هشدار روشن می‌ماند
  4. هشدار سریع روشن و خاموش می‌شود
این همان هیسترزیس است: بین ۳۳ و ۳۵ وضعیت قبلی حفظ می‌شود.

اگر شاخه «یادآوری» و متغیر tAlert را حذف کنیم و در هر خواندن که دما بالای ۳۵ است پیام هشدار بفرستیم، در یک ساعت هشدار چند پیام فرستاده می‌شود؟

  1. حدود ۱۸۰۰ پیام (هر ۲ ثانیه یکی)
  2. ۶ پیام
  3. ۱۲۰ پیام
  4. ۱ پیام
۳۶۰۰ ÷ ۲ = ۱۸۰۰. محدودیت نرخ این را به ۱ پیام شروع + حداکثر ۶ یادآوری در ساعت کاهش می‌دهد.

چرا در setup برنامه نهایی با while منتظر وصل شدن Wi-Fi نمی‌مانیم؟

  1. چون while در setup خطای کامپایل می‌دهد
  2. چون بدون while، Wi-Fi هرگز وصل نمی‌شود
  3. چون while مصرف برق را زیاد می‌کند
  4. چون اگر مودم خاموش باشد، هشدار محلی هم هرگز شروع به کار نمی‌کند
R8: کارهای محلی هرگز منتظر شبکه نمی‌مانند. اتصال در پس‌زمینه انجام می‌شود.

  2. وقتی بروکر بفهمد دستگاه بدون خداحافظی قطع شده (مثلا قطع برق)
  3. وقتی دما از ۳۵ بالاتر برود
  4. هر ۳۰ ثانیه
LWT را دستگاه هنگام اتصال به بروکر می‌سپارد و بروکر فقط در صورت قطع ناگهانی آن را منتشر می‌کند.

تمرین‌ها

تمرین ۱: هشدار گم‌نشدنی

در برنامه فعلی، اگر شبکه در لحظه شروع هشدار قطع باشد، پیام «ALERT» گم می‌شود. برنامه را طوری تغییر بده که پیام هشدار در یک متغیر «در انتظار ارسال» بماند و به محض وصل شدن MQTT فرستاده شود.

راهنمایی

یک متغیر const char* pendingAlert = nullptr; بساز. در publishAlert، اگر وصل نیستی، پیام را در آن بگذار. در keepMqtt، بلافاصله بعد از اتصال موفق، اگر pendingAlert خالی نیست، آن را بفرست و خالی کن. چون پیام‌ها رشته‌های ثابت‌اند، نگه داشتن اشاره‌گر به آن‌ها امن است.

چه باید ببینی؟

آزمایش: کاری کن که هشدار قبل از وصل شدن MQTT شروع شود. در Wokwi اگر DHT22 با ۳۶ درجه شروع کند، این خودبه‌خود اتفاق می‌افتد (دیاگرام جواب همین کار را می‌کند): اولین خواندن در ثانیه ۲ است، ولی اولین تلاش MQTT تازه بعد از ۵ ثانیه. روی برد واقعی: روتر را خاموش کن، در Serial Monitor بنویس t 36، صبر کن تا ALERT: temperature high بیاید، بعد روتر را روشن کن.

  • همین آزمایش را با برنامه نهایی اصلی تکرار کن: خط ALERT در سریال می‌آید، ولی تا یادآوری ۱۰ دقیقه بعد چیزی به کلاینت نمی‌رسد. این همان باگی است که درست کردی.
  • اگر هشدار در یک قطعی هم شروع و هم تمام شود (t 36 و بعد t 30)، فقط OK: temperature back to normal می‌رسد: یک جای خالی، تازه‌ترین پیام را نگه می‌دارد که همان وضعیت فعلی است.

// ================== ۱. تنظیمات ==================

const char* WIFI_PASS = "";                    // برد واقعی: رمز Wi-Fi خودت

const float TEMP_HIGH  = 35.0;                 // بالاتر از این: هشدار
const float TEMP_CLEAR = 33.0;                 // پایین‌تر از این: پایان هشدار
const uint32_t SENSOR_MS  = 2000;              // هر ۲ ثانیه خواندن
const uint32_t PUBLISH_MS = 30000;             // هر ۳۰ ثانیه ارسال
const uint32_t REMIND_MS  = 600000;            // یادآوری هشدار: حداکثر هر ۱۰ دقیقه

// ================== ۲. پین‌ها ==================
const int PIN_DHT = 13;
const int PIN_LDR = 35;                        // ADC1: با Wi-Fi کار می‌کند
const int PIN_LED = 4;
const int PIN_BUZ = 25;
const int PIN_BTN = 27;                        // دکمه بی‌صدا

// ================== ۳. اشیا و وضعیت ==================
DHT dht(PIN_DHT, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);
WiFiClient net;
PubSubClient mqtt(net);

float tempC = NAN, hum = NAN;
int lightPct = 0;
bool alarmOn = false, muted = false, oledOk = false;
uint32_t tSensor = 0, tPublish = 0, tAlert = 0, tWifi = 0, tMqtt = 0;
float fakeTemp = NAN;                          // کمک تست: NAN = سنسور واقعی
const char* pendingAlert = nullptr;            // هشداری که منتظر شبکه است

// ================== ۴. سنسورها ==================
void readSensors() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) { tempC = t; hum = h; }
  else Serial.println("DHT22 read failed, keeping last value");
  if (!isnan(fakeTemp)) tempC = fakeTemp;      // کمک تست (بخش ۱۰)
  int raw = analogRead(PIN_LDR);               // 0..4095
  lightPct = map(raw, 4095, 0, 0, 100);        // نور بیشتر = ولتاژ کمتر
}

// ================== ۵. ارسال به ابر ==================
void publishValue(const char* name, float v, int decimals) {
  char topic[64], payload[16];
  snprintf(topic, sizeof(topic), "%s%s", BASE, name);
  snprintf(payload, sizeof(payload), "%.*f", decimals, v);
  mqtt.publish(topic, payload);
}

void publishAll() {
  if (!mqtt.connected() || isnan(tempC)) return;
  publishValue("temp", tempC, 1);
  publishValue("hum", hum, 0);
  publishValue("light", lightPct, 0);
  Serial.println("Published to MQTT");
}

void sendAlert(const char* msg) {              // خود ارسال MQTT
  char topic[64];
  snprintf(topic, sizeof(topic), "%salert", BASE);
  mqtt.publish(topic, msg);
}

void publishAlert(const char* msg) {
  tAlert = millis();                           // شمارش یادآوری از نو
  Serial.println(msg);
  if (mqtt.connected()) sendAlert(msg);
  else pendingAlert = msg;                     // شبکه نیست: برای بعد نگهش دار
}

// ================== ۶. منطق هشدار (هیسترزیس + محدودیت نرخ) ==================
void updateAlarm() {
  if (isnan(tempC)) return;
  if (!alarmOn && tempC > TEMP_HIGH) {
    alarmOn = true;
    muted = false;
    publishAlert("ALERT: temperature high");
  } else if (alarmOn && tempC < TEMP_CLEAR) {
    alarmOn = false;
    publishAlert("OK: temperature back to normal");
  } else if (alarmOn && millis() - tAlert >= REMIND_MS) {
    publishAlert("ALERT: still high");         // یادآوری، نه اسپم
  }
}

void driveOutputs() {
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;
  bool blink = (millis() / 250) % 2;
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}

// ================== ۷. نمایشگر ==================
void drawDisplay() {
  if (!oledOk) return;                         // نمایشگر نیست؟ بقیه کارها ادامه دارد
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setCursor(0, 0);
  oled.print(WiFi.status() == WL_CONNECTED ? "WiFi OK  " : "WiFi --  ");
  oled.print(mqtt.connected() ? "MQTT OK" : "MQTT --");
  oled.setTextSize(2);
  oled.setCursor(0, 14);
  if (isnan(tempC)) oled.print("T: ERR");
  else { oled.print(tempC, 1); oled.print(" C"); }
  oled.setCursor(0, 34);
  if (isnan(hum)) oled.print("H: ERR");
  else { oled.print(hum, 0); oled.print(" %"); }
  oled.setTextSize(1);
  oled.setCursor(0, 56);
  oled.printf("Light %d%%  %s", lightPct, alarmOn ? (muted ? "ALARM(m)" : "ALARM!") : "normal");

}

// ================== ۸. شبکه (بدون مسدود کردن) ==================
void keepWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  if (millis() - tWifi < 15000) return;        // هر ۱۵ ثانیه یک تلاش
  tWifi = millis();
  Serial.println("WiFi: reconnecting...");
  WiFi.reconnect();
}

void keepMqtt() {
  if (WiFi.status() != WL_CONNECTED) return;
  if (mqtt.connected()) { mqtt.loop(); return; }
  if (millis() - tMqtt < 5000) return;         // هر ۵ ثانیه یک تلاش
  tMqtt = millis();
  String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX) + "-" + String(esp_random() & 0xFFFF, HEX);
  String will = String(BASE) + "status";
  if (mqtt.connect(id.c_str(), MQTT_USER, MQTT_KEY, will.c_str(), 0, true, "offline")) {
    mqtt.publish(will.c_str(), "online", true);
    Serial.println("MQTT connected");
    if (pendingAlert != nullptr) {             // هشداری که در قطعی جا مانده؟
      sendAlert(pendingAlert);
      Serial.printf("Sent pending: %s\n", pendingAlert);
      pendingAlert = nullptr;
    }
  } else {
    Serial.printf("MQTT failed, state=%d\n", mqtt.state());
  }
}

// ================== ۹. setup و loop ==================
void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  ledcAttach(PIN_BUZ, 2000, 8);                // API هسته 3.x
  analogReadResolution(12);
  dht.begin();
  Wire.begin(21, 22);
  oledOk = oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  if (oledOk) oled.setTextColor(SSD1306_WHITE);
  else Serial.println("OLED not found, continuing without display");
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  mqtt.setServer(MQTT_HOST, MQTT_PORT);
  net.setConnectionTimeout(1000);              // TCP: بعد از ۱ ثانیه بی‌خیال شو (پیش‌فرض ۳)
  mqtt.setSocketTimeout(2);                    // جواب بروکر: بعد از ۲ ثانیه (پیش‌فرض ۱۵)
  tWifi = millis();
}

void loop() {
  readSerialCommands();                        // کمک تست (بخش ۱۰)
  uint32_t now = millis();
  if (now - tSensor >= SENSOR_MS) {
    tSensor = now;
    readSensors();
    updateAlarm();
    drawDisplay();
  }
  if (now - tPublish >= PUBLISH_MS) {
    tPublish = now;
    publishAll();
  }
  keepWiFi();
  keepMqtt();
  driveOutputs();
}

// ================== ۱۰. کمک تست: دمای ساختگی از Serial ==================
void readSerialCommands() {
  if (!Serial.available()) return;
  String line = Serial.readStringUntil('\n');  // مثلا "t 36" یا "real"
  line.trim();
  if (line.startsWith("t ")) {
    fakeTemp = line.substring(2).toFloat();
    Serial.printf("Fake temperature: %.1f C\n", fakeTemp);
  } else if (line == "real") {
    fakeTemp = NAN;
    Serial.println("Using the real sensor again");
  }
}
  1. یک «جای انتظار» برای هشدار. nullptr یعنی «چیزی منتظر نیست». یک اشاره‌گر کافی است چون هر هشدار یک رشته ثابت نوشته‌شده در برنامه است ("ALERT: ...")؛ این رشته‌ها تمام مدت اجرا در فلش هستند، پس اشاره‌گر هیچ‌وقت به چیزی که از بین رفته اشاره نمی‌کند.
  2. sendAlert(): فقط فرستادن MQTT. ساختن topic و publish از publishAlert بیرون آمده‌اند. حالا دو جا باید هشدار بفرستند: همان لحظه، و بعدا پس از وصل شدن دوباره. یک تابع کوچک یعنی topic در هر دو جا یک‌جور ساخته می‌شود.
  3. publishAlert(): الان بفرست یا برای بعد نگه دار. وصل هستیم ← بفرست. وصل نیستیم ← در جای انتظار بگذار. تایمر یادآوری و خط سریال مثل قبل می‌مانند، پس رفتار محلی (و قانون «بدون اسپم») عوض نمی‌شود. هشدار تازه‌تر روی هشدار منتظر قبلی می‌نشیند: بعد از قطعی، وضعیت فعلی مهم است نه تاریخچه.
  4. بلافاصله بعد از اتصال موفق: منتظر را بفرست و جا را خالی کن. این اولین لحظه‌ای است که می‌دانیم پیام می‌تواند برود. خالی کردن جا بعدش یعنی پیام دقیقا یک بار می‌رود، نه با هر اتصال دوباره.
  5. updateAlarm() عوض نشده. هنوز publishAlert را صدا می‌زند که حالا قطعی را خودش مدیریت می‌کند. اصلاح فقط در یک جا، یعنی تابع ارسال، انجام شده؛ منطق هشدار لازم نیست چیزی درباره شبکه بداند.

چهار کتابخانه را از تب Library Manager خود Wokwi اضافه کن (مثل برنامه نهایی). در این دیاگرام DHT22 با ۳۶ درجه شروع می‌کند، پس هشدار قبل از وصل شدن MQTT شروع می‌شود. BASE را به پیشوند خودت تغییر بده و topic هشدار را در کلاینت MQTT نگاه کن.

تمرین ۲: سنسور مرده

اگر DHT22 برای همیشه جدا شود، برنامه فعلی آخرین دمای معتبر را تا ابد نشان می‌دهد و ارسال می‌کند؛ این دروغ است. تغییری بده که اگر ۵ خواندن پشت سر هم شکست خورد، tempC و hum دوباره NaN شوند و یک پیام "ERROR: sensor" (فقط یک بار) به topic هشدار برود.

راهنمایی

یک شمارنده failStreak در readSensors: با موفقیت صفر، با شکست یکی زیاد. وقتی دقیقا به ۵ رسید (نه بزرگ‌تر یا مساوی، تا پیام فقط یک بار برود)، مقدارها را NaN کن و publishAlert را صدا بزن. publishAll از قبل با NaN چیزی نمی‌فرستد و نمایشگر «ERR» نشان می‌دهد.

روی برد واقعی، وقتی ایستگاه کار می‌کند سیم DATA سنسور DHT22 را بکش. در Wokwi شبیه‌سازی را متوقف کن، خط dht1:SDA را از diagram.json پاک کن و دوباره اجرا کن. هر ۲ ثانیه یک خط:

  • از آن به بعد هیچ مقدار دما، رطوبت یا نوری فرستاده نمی‌شود (publishAll با NaN متوقف می‌شود).

جواب کامل با توضیح

برنامه نهایی کامل با readSensors جدید. فقط خط‌هایی که در کارت‌ها آمده‌اند عوض شده‌اند.

// ایستگاه پایش محیط، تمرین ۲: سنسور مرده گزارش می‌شود، نه پنهان
#include <WiFi.h>
#include <PubSubClient.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>

// ================== ۱. تنظیمات ==================
const char* WIFI_SSID = "Wokwi-GUEST";         // برد واقعی: اسم Wi-Fi خودت
const char* WIFI_PASS = "";                    // برد واقعی: رمز Wi-Fi خودت
const char* MQTT_HOST = "broker.hivemq.com";
const uint16_t MQTT_PORT = 1883;
const char* MQTT_USER = nullptr;               // Adafruit IO: نام کاربری
const char* MQTT_KEY  = nullptr;               // Adafruit IO: AIO Key
const char* BASE      = "esp32fa/station-42/"; // پیشوند یکتای topicها

const float TEMP_HIGH  = 35.0;                 // بالاتر از این: هشدار
const float TEMP_CLEAR = 33.0;                 // پایین‌تر از این: پایان هشدار
const uint32_t SENSOR_MS  = 2000;              // هر ۲ ثانیه خواندن
const uint32_t PUBLISH_MS = 30000;             // هر ۳۰ ثانیه ارسال
const uint32_t REMIND_MS  = 600000;            // یادآوری هشدار: حداکثر هر ۱۰ دقیقه

// ================== ۲. پین‌ها ==================
const int PIN_DHT = 13;
const int PIN_LDR = 35;                        // ADC1: با Wi-Fi کار می‌کند
const int PIN_LED = 4;
const int PIN_BUZ = 25;
const int PIN_BTN = 27;                        // دکمه بی‌صدا

// ================== ۳. اشیا و وضعیت ==================
DHT dht(PIN_DHT, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);
WiFiClient net;
PubSubClient mqtt(net);

float tempC = NAN, hum = NAN;
int lightPct = 0;
bool alarmOn = false, muted = false, oledOk = false;
uint32_t tSensor = 0, tPublish = 0, tAlert = 0, tWifi = 0, tMqtt = 0;
float fakeTemp = NAN;                          // کمک تست: NAN = سنسور واقعی
int failStreak = 0;                            // تعداد خطاهای پشت سر هم

// ================== ۴. سنسورها ==================
void readSensors() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) {
    tempC = t; hum = h;
    failStreak = 0;                            // موفق: شمارش از صفر
  } else {
    failStreak++;
    Serial.printf("DHT22 read failed (%d in a row)\n", failStreak);
    if (failStreak == 5) {                     // دقیقا یک بار، بعد از ۱۰ ثانیه خطا
      tempC = NAN; hum = NAN;                  // عدد قدیمی را تازه جا نزن
      publishAlert("ERROR: sensor");
    }
  }
  if (!isnan(fakeTemp)) tempC = fakeTemp;      // کمک تست (بخش ۱۰)
  int raw = analogRead(PIN_LDR);               // 0..4095
  lightPct = map(raw, 4095, 0, 0, 100);        // نور بیشتر = ولتاژ کمتر
}

// ================== ۵. ارسال به ابر ==================
void publishValue(const char* name, float v, int decimals) {
  char topic[64], payload[16];
  snprintf(topic, sizeof(topic), "%s%s", BASE, name);
  snprintf(payload, sizeof(payload), "%.*f", decimals, v);
  mqtt.publish(topic, payload);
}

void publishAll() {
  if (!mqtt.connected() || isnan(tempC)) return;
  publishValue("temp", tempC, 1);
  publishValue("hum", hum, 0);
  publishValue("light", lightPct, 0);
  Serial.println("Published to MQTT");
}

void publishAlert(const char* msg) {
  tAlert = millis();                           // شمارش یادآوری از نو
  Serial.println(msg);
  if (!mqtt.connected()) return;
  char topic[64];
  snprintf(topic, sizeof(topic), "%salert", BASE);
  mqtt.publish(topic, msg);
}

// ================== ۶. منطق هشدار (هیسترزیس + محدودیت نرخ) ==================
void updateAlarm() {
  if (isnan(tempC)) return;
  if (!alarmOn && tempC > TEMP_HIGH) {
    alarmOn = true;
    muted = false;
    publishAlert("ALERT: temperature high");
  } else if (alarmOn && tempC < TEMP_CLEAR) {
    alarmOn = false;
    publishAlert("OK: temperature back to normal");
  } else if (alarmOn && millis() - tAlert >= REMIND_MS) {
    publishAlert("ALERT: still high");         // یادآوری، نه اسپم
  }
}

void driveOutputs() {
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;
  bool blink = (millis() / 250) % 2;
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}

// ================== ۷. نمایشگر ==================
void drawDisplay() {
  if (!oledOk) return;                         // نمایشگر نیست؟ بقیه کارها ادامه دارد
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setCursor(0, 0);
  oled.print(WiFi.status() == WL_CONNECTED ? "WiFi OK  " : "WiFi --  ");
  oled.print(mqtt.connected() ? "MQTT OK" : "MQTT --");
  oled.setTextSize(2);
  oled.setCursor(0, 14);
  if (isnan(tempC)) oled.print("T: ERR");
  else { oled.print(tempC, 1); oled.print(" C"); }
  oled.setCursor(0, 34);
  if (isnan(hum)) oled.print("H: ERR");
  else { oled.print(hum, 0); oled.print(" %"); }
  oled.setTextSize(1);
  oled.setCursor(0, 56);
  oled.printf("Light %d%%  %s", lightPct, alarmOn ? (muted ? "ALARM(m)" : "ALARM!") : "normal");
  oled.display();
}

// ================== ۸. شبکه (بدون مسدود کردن) ==================
void keepWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  if (millis() - tWifi < 15000) return;        // هر ۱۵ ثانیه یک تلاش
  tWifi = millis();
  Serial.println("WiFi: reconnecting...");
  WiFi.reconnect();
}

void keepMqtt() {
  if (WiFi.status() != WL_CONNECTED) return;
  if (mqtt.connected()) { mqtt.loop(); return; }
  if (millis() - tMqtt < 5000) return;         // هر ۵ ثانیه یک تلاش
  tMqtt = millis();
  String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX) + "-" + String(esp_random() & 0xFFFF, HEX);
  String will = String(BASE) + "status";
  if (mqtt.connect(id.c_str(), MQTT_USER, MQTT_KEY, will.c_str(), 0, true, "offline")) {
    mqtt.publish(will.c_str(), "online", true);
    Serial.println("MQTT connected");
  } else {
    Serial.printf("MQTT failed, state=%d\n", mqtt.state());
  }
}

void setup() {
  Serial.begin(115200);

void loop() {

    updateAlarm();
    drawDisplay();

  2. موفقیت شمارنده را صفر می‌کند. یعنی فقط خطاهای پشت سر هم شمرده می‌شوند؛ یک خطای تکی گاه‌به‌گاه برای DHT22 طبیعی است و نباید هشدار بدهد.
  3. شکست: بشمارش و در سریال بگو. عدد داخل پرانتز اجازه می‌دهد موقع تست، شمارش معکوس تا هشدار را ببینی.
  4. در پنجمین شکست، خرابی را گزارش کن. مقدارها NaN می‌شوند و یک پیام خطا از راه publishAlert می‌رود. شرط == 5 به جای >= 5 یعنی پیام فقط یک بار می‌رود، نه در هر خواندن بعدی؛ همان قانون «بدون اسپم». پنج خواندن یعنی ۱۰ ثانیه که با یک اختلال تصادفی اشتباه گرفته نمی‌شود. با NaN، نمایشگر ERR نشان می‌دهد، publishAll چیزی نمی‌فرستد و updateAlarm هشدار را همان‌طور که بود نگه می‌دارد: هشدار روشن به چشمک زدن ادامه می‌دهد که امن‌تر از خاموش شدن بی‌صدا است. readSensors تابع publishAlert را صدا می‌زند با این که پایین‌تر نوشته شده؛ در فایل .ino مشکلی نیست، چون Arduino IDE قبل از کامپایل اعلان‌ها را خودش اضافه می‌کند.
  5. کمک تست هنوز آخر از همه است. دمای ساختگی (t 36) هنوز جای سنسور را می‌گیرد، پس تست‌های هشدار حتی با سنسور جداشده هم کار می‌کنند.

تمرین ۳: حالت باتری

نسخه باتری ایستگاه را بساز (بخش «حالت باتری» را ببین): هر ۵ دقیقه بیدار شود، بخواند، روی OLED برای ۳ ثانیه نشان دهد، اگر هشدار شروع یا تمام شد پیام بفرست، هر ۶ بیداری یک بار مقادیر را بفرستد، و بخوابد. دکمه GPIO27 برد را برای نمایش فوری بیدار کند. بعد با فرمول درس ۶.۱ عمر یک باتری ۲۰۰۰ میلی‌آمپر ساعت را تخمین بزن.

راهنمایی

یک تغییر مهم در طراحی: همه چیز در setup() اتفاق می‌افتد و هر چیزی که باید از خواب جان سالم به در ببرد در حافظه RTC است. Wi-Fi فقط وقتی روشن می‌شود که چیزی برای فرستادن هست.

// ایستگاه در حالت باتری: بیدار شو، بخوان، نشان بده، فقط در صورت لزوم بفرست، بخواب (۶.۳، تمرین ۳)
#include <WiFi.h>
#include <PubSubClient.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>
#include "driver/rtc_io.h"

// ---------- تنظیمات ----------
const char* WIFI_SSID = "Wokwi-GUEST";         // برد واقعی: اسم Wi-Fi خودت
const char* WIFI_PASS = "";
const char* MQTT_HOST = "broker.hivemq.com";
const char* BASE      = "esp32fa/station-42/"; // پیشوند یکتای topicها
const float TEMP_HIGH = 35.0, TEMP_CLEAR = 33.0;
const uint64_t SLEEP_SEC = 300;                // ۵ دقیقه (برای تست ۱۰)
const uint32_t WIFI_TIMEOUT_MS = 8000;
const uint32_t SHOW_MS = 3000;                 // OLED سه ثانیه روشن می‌ماند
const int PIN_DHT = 13, PIN_LDR = 35, PIN_BUZ = 25;
const gpio_num_t PIN_BTN = GPIO_NUM_27;        // پین RTC: می‌تواند برد را بیدار کند

DHT dht(PIN_DHT, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);
WiFiClient net;
PubSubClient mqtt(net);
bool oledOk = false;

// ---------- حافظه RTC: بعد از خواب عمیق باقی می‌ماند ----------
RTC_DATA_ATTR bool alarmOn = false;
RTC_DATA_ATTR uint32_t wakeCount = 0;          // بیداری‌های تایمری (و اولین روشن شدن)
RTC_DATA_ATTR uint32_t lastAlertWake = 0;      // wakeCount آخرین هشداری که واقعا رفت
RTC_DATA_ATTR uint8_t savedChannel = 0;        // میان‌بر Wi-Fi از درس ۶.۱
RTC_DATA_ATTR uint8_t savedBssid[6];

bool connectWiFiFast() {                       // درس ۶.۱، بدون تغییر
  WiFi.mode(WIFI_STA);
  WiFi.persistent(false);
  if (savedChannel != 0) WiFi.begin(WIFI_SSID, WIFI_PASS, savedChannel, savedBssid);
  else WiFi.begin(WIFI_SSID, WIFI_PASS);
  uint32_t start = millis();
  while (WiFi.status() != WL_CONNECTED) {
    if (millis() - start > WIFI_TIMEOUT_MS) { savedChannel = 0; return false; }
    delay(20);
  }
  savedChannel = WiFi.channel();
  memcpy(savedBssid, WiFi.BSSID(), 6);
  return true;
}

void publishValue(const char* name, float v, int decimals) {
  char topic[64], payload[16];
  snprintf(topic, sizeof(topic), "%s%s", BASE, name);
  snprintf(payload, sizeof(payload), "%.*f", decimals, v);
  mqtt.publish(topic, payload);
}

void show(float t, float h, int light, bool byButton) {
  if (!oledOk) return;
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setCursor(0, 0);
  oled.print(byButton ? "Button reading" : "Wake #");
  if (!byButton) oled.print(wakeCount);
  oled.setTextSize(2);
  oled.setCursor(0, 14);
  if (isnan(t)) oled.print("T: ERR"); else { oled.print(t, 1); oled.print(" C"); }
  oled.setCursor(0, 34);
  if (isnan(h)) oled.print("H: ERR"); else { oled.print(h, 0); oled.print(" %"); }
  oled.setTextSize(1);
  oled.setCursor(0, 56);
  oled.printf("Light %d%%  %s", light, alarmOn ? "ALARM!" : "normal");
  oled.display();
}

void goToSleep() {
  WiFi.disconnect(true);
  WiFi.mode(WIFI_OFF);
  if (oledOk) oled.ssd1306_command(SSD1306_DISPLAYOFF);   // وگرنه باتری را می‌خورد
  pinMode(27, INPUT_PULLUP);
  while (digitalRead(27) == LOW) delay(10);   // صبر تا دکمه رها شود
  esp_sleep_enable_timer_wakeup(SLEEP_SEC * 1000000ULL);
  esp_sleep_enable_ext0_wakeup(PIN_BTN, 0);
  rtc_gpio_pullup_en(PIN_BTN);
  rtc_gpio_pulldown_dis(PIN_BTN);
  Serial.printf("Awake %lu ms. Sleep %llu s\n", millis(), SLEEP_SEC);
  Serial.flush();
  esp_deep_sleep_start();
}

void setup() {
  Serial.begin(115200);
  esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause();
  bool byButton = (cause == ESP_SLEEP_WAKEUP_EXT0);
  dht.begin();
  Wire.begin(21, 22);
  oledOk = oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);   // نمایشگر را دوباره روشن هم می‌کند
  if (oledOk) oled.setTextColor(SSD1306_WHITE);
  if (cause != ESP_SLEEP_WAKEUP_TIMER && !byButton) delay(2000);  // اولین روشن شدن: DHT22 هنوز آماده نیست

  float t = dht.readTemperature();
  float h = dht.readHumidity();
  int light = map(analogRead(PIN_LDR), 4095, 0, 0, 100);
  const char* alert = nullptr;
  if (!byButton) {
    wakeCount++;
    // ---- ۱) منطق هشدار: هیسترزیس، یادآوری هر ۲ بیداری (۱۰ دقیقه) ----
    if (!isnan(t)) {
      if (!alarmOn && t > TEMP_HIGH)       { alarmOn = true;  alert = "ALERT: temperature high"; }
      else if (alarmOn && t < TEMP_CLEAR)  { alarmOn = false; alert = "OK: temperature back to normal"; }
      else if (alarmOn && wakeCount - lastAlertWake >= 2) alert = "ALERT: still high";
    }
  }
  show(t, h, light, byButton);
  uint32_t tShown = millis();
  Serial.printf("%s  T=%.1f C  H=%.0f %%  light=%d %%  alarm=%s\n",
                byButton ? "Button" : ("Wake #" + String(wakeCount)).c_str(), t, h, light, alarmOn ? "ON" : "off");

  if (!byButton) {
    if (alarmOn) {                             // هشدار محلی: در هر بیداری یک بوق کوتاه
      ledcAttach(PIN_BUZ, 2000, 8);
      ledcWriteTone(PIN_BUZ, 2000);
      delay(150);
      ledcWriteTone(PIN_BUZ, 0);
    }
    bool sendValues = (wakeCount % 6 == 0) && !isnan(t);   // هر ششمین بیداری = هر ۳۰ دقیقه

    // ---- ۲) شبکه فقط وقتی چیزی برای فرستادن هست ----
    if (alert == nullptr && !sendValues) {
      Serial.println("Nothing to send, Wi-Fi stays off");
    } else if (!connectWiFiFast()) {
      Serial.println("Wi-Fi failed, will retry next wake");
    } else {
      mqtt.setServer(MQTT_HOST, 1883);
      String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX) + "-" + String(esp_random() & 0xFFFF, HEX);
      if (mqtt.connect(id.c_str())) {
        if (alert != nullptr) {
          String topic = String(BASE) + "alert";
          mqtt.publish(topic.c_str(), alert);
          lastAlertWake = wakeCount;           // فقط وقتی واقعا رفت حساب می‌شود
          Serial.printf("Sent alert: %s\n", alert);
        }
        if (sendValues) {
          publishValue("temp", t, 1);
          publishValue("hum", h, 0);
          publishValue("light", light, 0);
          Serial.println("Sent values");
        }
        mqtt.loop();
        delay(50);                             // فرصت کوتاه برای خروج بسته‌ها
        mqtt.disconnect();
      } else {
        Serial.println("MQTT failed, will retry next wake");
      }
    }
  }
  while (millis() - tShown < SHOW_MS) delay(10);   // باقی ۳ ثانیه روی صفحه
  goToSleep();
}

void loop() {}
  1. تنظیمات. زمان خواب بر حسب ثانیه، حد زمانی Wi-Fi، ۳ ثانیه نمایش و پین‌های ایستگاه (دکمه از نوع gpio_num_t است چون EXT0 این را می‌خواهد). ثانیه به جای دقیقه، تا تست با ۱۰ ثانیه به هیچ تغییر دیگری نیاز نداشته باشد.
  2. حافظه RTC. وضعیت هشدار، شمارنده بیداری، شماره بیداری آخرین هشداری که واقعا رفت، و میان‌بر Wi-Fi. millis() بعد از هر بیداری از صفر شروع می‌شود، پس یادآوری را نمی‌شود با میلی‌ثانیه زمان‌بندی کرد؛ به جایش بیداری‌ها را می‌شماریم (راهنمایی: هر ۲ بیداری = ۱۰ دقیقه).
  3. connectWiFiFast() از ۶.۱ و publishValue() از برنامه نهایی، بدون تغییر. میان‌بر کانال و BSSID ذخیره‌شده، گران‌ترین بخش بیداری را کوتاه می‌کند.
  4. show(): نمایشگر برای یک بیداری. شماره بیداری (یا «Button reading»)، دما و رطوبت با حروف درشت، نور و وضعیت هشدار در پایین. همان چیدمان ایستگاه همیشه‌روشن، تا دستگاه در هر دو حالت یک‌جور به نظر برسد.
  5. goToSleep(): همه چیز خاموش، دو منبع بیداری. Wi-Fi خاموش، OLED خاموش، صبر تا رها شدن دکمه، بعد تایمر و EXT0 روی GPIO27 با بالاکش RTC. یک OLED روشن به تنهایی باتری را خالی می‌کند. تایمر و دکمه هر دو می‌توانند برد را بیدار کنند؛ هر کدام زودتر بیاید برنده است.
  6. شروع setup: چرا بیدار شدم؟ دکمه، تایمر یا روشن شدن تازه. oled.begin نمایشگر را دوباره روشن هم می‌کند. فقط روشن شدن تازه ۲ ثانیه برای DHT22 صبر می‌کند. در خواب عمیق سنسور برق دارد، پس در بیداری با تایمر و دکمه فورا آماده است؛ صبر کردن آن‌جا فقط باتری هدر می‌داد.
  7. بخوان، بعد درباره هشدار تصمیم بگیر (فقط بیداری تایمری). همان هیسترزیس برنامه نهایی؛ شرط یادآوری wakeCount - lastAlertWake >= 2 است. بیداری با دکمه فقط برای نگاه کردن است: بیداری حساب نمی‌شود و هشدار را عوض نمی‌کند، پس زمان‌بندی یادآوری‌ها و ارسال مقادیر منظم می‌ماند.
  8. نمایش و چاپ، و یادداشت زمان. ۳ ثانیه نمایش از همین حالا شروع می‌شود؛ کارهای شبکه پایین‌تر وقتی انجام می‌شوند که نمایشگر مقادیر را نشان می‌دهد.
  9. یک بوق کوتاه وقتی هشدار روشن است؛ مقادیر هر ششمین بیداری. این همان معامله بخش «حالت باتری» است: در خواب نه چشمکی هست نه بوق پیوسته، فقط یک بوق در هر بیداری.
  10. شبکه فقط در صورت نیاز. چیزی برای فرستادن نیست ← Wi-Fi خاموش می‌ماند. وگرنه: اتصال سریع، فرستادن هشدار و/یا مقادیر، یک لحظه فرصت برای بسته‌ها، قطع اتصال. lastAlertWake فقط وقتی به‌روز می‌شود که هشدار واقعا رفته باشد. بیشتر بیداری‌ها (۵ از ۶ بدون هشدار) اصلا به Wi-Fi دست نمی‌زنند؛ عمر باتری از همین‌جا می‌آید. اگر هشداری نرسید، بیداری بعدی یادآوری می‌فرستد، پس مشکل فراموش نمی‌شود.
  11. باقی ۳ ثانیه را صبر کن و بخواب. ارسال داخل همان ۳ ثانیه نمایش انجام می‌شود، پس فرستادن بیداری را طولانی‌تر نمی‌کند، مگر این که Wi-Fi کند باشد.

مدار ایستگاه. چهار کتابخانه را از تب Library Manager اضافه کن و SLEEP_SEC را ۱۰ بگذار. خواب عمیق با تایمر و با EXT0 در Wokwi کار می‌کند؛ در حال خواب دکمه زرد را بزن تا عدد فوری را ببینی.

تخمین باتری. یک دور کامل ۶ بیداری است = ۳۰ دقیقه = ۱۸۰۰ ثانیه. فرض‌ها (عددهای خودت را اندازه بگیر): بیداری معمولی ۳٫۳ ثانیه با حدود ۵۰ میلی‌آمپر (ESP32 به‌علاوه OLED روشن)؛ بیداری ارسال حدود ۴ ثانیه با حدود ۱۲۰ میلی‌آمپر (Wi-Fi).

  • بار بیداری در هر دور: ۵ × ۳٫۳ × ۵۰ + ۱ × ۴ × ۱۲۰ = ۸۲۵ + ۴۸۰ = ۱۳۰۵ میلی‌آمپرثانیه. زمان بیداری: ۵ × ۳٫۳ + ۴ = ۲۰٫۵ ثانیه، پس ۱۷۷۹٫۵ ثانیه خواب.
  • برد کم‌مصرف (خواب حدود ۰٫۲ میلی‌آمپر، با DHT22 و OLED خاموش): ۱۷۷۹٫۵ × ۰٫۲ ≈ ۳۵۶. I_avg = (۱۳۰۵ + ۳۵۶) ÷ ۱۸۰۰ ≈ ۰٫۹۲ میلی‌آمپر. عمر = ۲۰۰۰ ÷ ۰٫۹۲ ≈ ۲۱۷۰ ساعت ≈ ۹۰ روز؛ واقع‌بینانه (× ۰٫۷۵) حدود ۶۸ روز.
  • DevKitC (خواب حدود ۶ میلی‌آمپر): ۱۷۷۹٫۵ × ۶ ≈ ۱۰۶۸۰. I_avg = (۱۳۰۵ + ۱۰۶۸۰) ÷ ۱۸۰۰ ≈ ۶٫۶۶ میلی‌آمپر. عمر = ۲۰۰۰ ÷ ۶٫۶۶ ≈ ۳۰۰ ساعت ≈ ۱۲٫۵ روز؛ واقع‌بینانه حدود ۹ روز.
  • بزرگ‌ترین هزینه بیداری، ۳ ثانیه نمایش در هر بیداری است (۸۲۵ از ۱۳۰۵). نشان دادن مقادیر فقط در بیداری با دکمه، بار بیداری را تقریبا نصف می‌کند.

پروژه تمرینی: آستانه‌ای که از گوشی عوض می‌شود

حد هشدار ایستگاهت، ۳۵ درجه، داخل کد نوشته شده است. یک دوست می‌خواهد همین ایستگاه را در یک گلخانه استفاده کند، جایی که ۳۰ درجه هم زیادی گرم است؛ و نمی‌تواند برد را دوباره برنامه‌ریزی کند. پس حد باید از راه شبکه بیاید: او یک عدد را روی یک topic در MQTT منتشر می‌کند، و ایستگاه آن را بررسی می‌کند، به کار می‌برد و دریافتش را تأیید می‌کند. به‌عنوان جایزه، ایستگاه روزی یک بار یک خلاصه کوچک هم برایش می‌فرستد: کمترین و بیشترین دمای آن روز.

نیازمندی‌ها

  1. بعد از هر اتصال (یا اتصال دوباره) به بروکر، ایستگاه به <BASE>cfg/high subscribe می‌کند. چون این پیام با retain فرستاده شده، آخرین مقدار کمی بعد از اتصال می‌رسد، حتی درست بعد از ریست.
  2. فقط عددی از 20.0 تا 60.0 پذیرفته می‌شود. هر چیز دیگری (abc، 35x، پیام خالی، 99) با یک خط در Serial Monitor رد می‌شود و هیچ چیز را عوض نمی‌کند.
  3. مقدار پذیرفته‌شده فورا حد هشدار می‌شود، حد «رفع هشدار» ۲ درجه پایین‌تر از آن قرار می‌گیرد، و ایستگاه حدی را که به کار می‌برد روی <BASE>cfg/high/state (با retain) تأیید می‌کند.
  4. ایستگاه کمترین و بیشترین دمای معتبر را دنبال می‌کند. هر DAY_MS (۲۴ ساعت؛ برای تست ۶۰ ثانیه) پیام {"min":..,"max":..} را به <BASE>daily می‌فرستد و دوره تازه‌ای را شروع می‌کند.
  5. بدون هیچ شبکه‌ای، LED هشدار محلی با آخرین حد پذیرفته‌شده به کارش ادامه می‌دهد (R8 در PRD).
  6. Serial Monitor هر قدم را نشان می‌دهد: مقدار پذیرفته یا ردشده، روشن و خاموش شدن هشدار، و خلاصه روزانه.

قطعه‌ها

  • برد ESP32 DevKitC، سنسور DHT22 (به‌اضافه بالاکش ۱۰ کیلواهم برای سنسور خام چهارپایه)، LED هشدار با مقاومت ۲۲۰ اهم
  • یک شبکه Wi-Fi ۲٫۴ گیگاهرتز (در Wokwi: Wokwi-GUEST) و یک کلاینت MQTT که بتواند با retain منتشر کند، مثل کلاینت وب HiveMQ درس ۵.۱
  • OLED، LDR، بازر و دکمه ایستگاه کامل روی برد بورد می‌مانند؛ این پروژه فقط از آن‌ها استفاده نمی‌کند

کد شروع

راهنمایی ۱

payload یک رشته C نیست: در انتهایش '\0' ندارد. اول آن را در یک آرایه کوچک char کپی کن، دقیقا مثل onMessage درس ۵.۱؛ و یادت باشد payloadی که از آرایه‌ات بلندتر است، خودش دلیلی برای رد کردن است.

راهنمایی ۲

String("35x").toFloat() بی‌سروصدا ۳۵ برمی‌گرداند، و toFloat() برای abc صفر برمی‌گرداند: هیچ‌کدام نمی‌گویند متن خراب بوده. تابع استاندارد C یعنی strtof(text, &end) عدد را تبدیل می‌کند و می‌گوید کجا متوقف شد (end). اگر end هنوز سر جای اول است، عددی نبوده؛ اگر *end همان '\0' انتها نیست، بعد از عدد چیز اضافه‌ای آمده.

راهنمایی ۳

از داخل callback چیزی منتشر نکن؛ یک پرچم بگذار (cfgChanged = true) و تأیید را از loop بفرست. برای خلاصه روزانه از همان الگوی بقیه کارها استفاده کن: if (now - tDay >= DAY_MS) { tDay = now; ... }، و min/max را با NAN شروع کن.

// ایستگاه سبک (۶.۳) + آستانه از راه دور با MQTT + min/max روزانه
#include <WiFi.h>
#include <PubSubClient.h>
#include <DHT.h>

const char* WIFI_SSID = "Wokwi-GUEST";         // برد واقعی: اسم Wi-Fi خودت
const char* WIFI_PASS = "";
const char* MQTT_HOST = "broker.hivemq.com";
const char* BASE      = "esp32course/station-42/"; // پیشوند یکتای خودت
const uint32_t SENSOR_MS  = 2000;              // هر ۲ ثانیه بخوان
const uint32_t PUBLISH_MS = 30000;             // هر ۳۰ ثانیه دما را بفرست
const uint32_t DAY_MS     = 86400000UL;        // ۲۴ ساعت (برای تست 60000)

const int PIN_DHT = 13;
const int PIN_LED = 4;                         // LED هشدار

DHT dht(PIN_DHT, DHT22);
WiFiClient net;
PubSubClient mqtt(net);

float tempHigh = 35.0, tempClear = 33.0;       // حالا متغیرند: می‌توانند عوض شوند
float tempC = NAN;
bool alarmOn = false;
uint32_t tSensor = 0, tPublish = 0, tWifi = 0, tMqtt = 0;
float dayMin = NAN, dayMax = NAN;              // NAN یعنی هنوز خواندن معتبری نداریم
uint32_t tDay = 0;
bool cfgChanged = false;                       // در callback روشن می‌شود، در loop استفاده

void onMessage(char* topic, byte* payload, unsigned int length) {
  char buf[16];
  unsigned int n = (length < sizeof(buf) - 1) ? length : sizeof(buf) - 1;
  memcpy(buf, payload, n);
  buf[n] = '\0';                               // payload خودش '\0' ندارد
  char* end;
  float v = strtof(buf, &end);                 // end = جایی که عدد تمام شد
  while (*end == ' ' || *end == '\r' || *end == '\n') end++;   // فاصله و خط جدید در انتها مجاز
  bool valid = (end != buf) && (*end == '\0') && (length < sizeof(buf)) && v >= 20.0 && v <= 60.0;
  if (!valid) {
    Serial.printf("cfg/high <- \"%s\" : rejected (need a number from 20 to 60)\n", buf);
    return;                                    // آستانه قبلی می‌ماند
  }
  tempHigh = v;
  tempClear = v - 2.0;
  cfgChanged = true;
  Serial.printf("cfg/high <- \"%s\" : accepted, alarm at %.1f C, clear at %.1f C\n",
                buf, tempHigh, tempClear);
}

void readSensor() {
  float t = dht.readTemperature();
  if (isnan(t)) { Serial.println("DHT22 read failed"); return; }
  tempC = t;
  if (isnan(dayMin) || t < dayMin) dayMin = t;
  if (isnan(dayMax) || t > dayMax) dayMax = t;
}

void updateAlarm() {
  if (isnan(tempC)) return;
  if (!alarmOn && tempC > tempHigh) { alarmOn = true; Serial.println("ALARM on"); }
  else if (alarmOn && tempC < tempClear) { alarmOn = false; Serial.println("ALARM off"); }
}

void publishTemp() {
  if (!mqtt.connected() || isnan(tempC)) return;
  char topic[80], payload[16];
  snprintf(topic, sizeof(topic), "%stemp", BASE);
  snprintf(payload, sizeof(payload), "%.1f", tempC);
  mqtt.publish(topic, payload);
}

void publishDaily() {
  if (isnan(dayMin)) return;                   // در این دوره خواندن معتبری نبود
  char topic[80], payload[40];
  snprintf(topic, sizeof(topic), "%sdaily", BASE);
  snprintf(payload, sizeof(payload), "{\"min\":%.1f,\"max\":%.1f}", dayMin, dayMax);
  bool sent = mqtt.connected() && mqtt.publish(topic, payload, true);
  Serial.printf("Daily: min=%.1f max=%.1f (%s)\n", dayMin, dayMax, sent ? "sent" : "offline, lost");
  dayMin = NAN;                                // شروع دوره تازه
  dayMax = NAN;
}

void confirmCfg() {
  if (!mqtt.connected()) return;               // true می‌ماند: بعدا تأیید می‌کنیم
  cfgChanged = false;
  char topic[80], payload[16];
  snprintf(topic, sizeof(topic), "%scfg/high/state", BASE);
  snprintf(payload, sizeof(payload), "%.1f", tempHigh);
  mqtt.publish(topic, payload, true);          // retained: داشبورد همیشه خبر دارد
}

void keepWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  if (millis() - tWifi < 15000) return;        // هر ۱۵ ثانیه یک تلاش
  tWifi = millis();
  WiFi.reconnect();
}

void keepMqtt() {
  if (WiFi.status() != WL_CONNECTED) return;
  if (mqtt.connected()) { mqtt.loop(); return; }
  if (millis() - tMqtt < 5000) return;         // هر ۵ ثانیه یک تلاش
  tMqtt = millis();
  String id = "station-" + WiFi.macAddress() + "-" + String(esp_random() & 0xFFFF, HEX);
  if (mqtt.connect(id.c_str())) {
    Serial.println("MQTT connected");
    String cfg = String(BASE) + "cfg/high";
    mqtt.subscribe(cfg.c_str());               // مقدار retained بلافاصله می‌رسد
  } else {
    Serial.printf("MQTT failed, state=%d\n", mqtt.state());
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
  dht.begin();
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  mqtt.setServer(MQTT_HOST, 1883);
  mqtt.setCallback(onMessage);
  net.setConnectionTimeout(1000);              // TCP: بعد از ۱ ثانیه بی‌خیال شو
  mqtt.setSocketTimeout(2);                    // جواب بروکر: بعد از ۲ ثانیه بی‌خیال شو
  tWifi = millis();
}

void loop() {
  uint32_t now = millis();
  if (now - tSensor >= SENSOR_MS) { tSensor = now; readSensor(); updateAlarm(); }
  if (now - tPublish >= PUBLISH_MS) { tPublish = now; publishTemp(); }
  if (cfgChanged) confirmCfg();
  if (now - tDay >= DAY_MS) { tDay = now; publishDaily(); }
  keepWiFi();
  keepMqtt();
  digitalWrite(PIN_LED, alarmOn && (millis() / 250) % 2);   // محلی: به شبکه نیاز ندارد
}
  1. وضعیت تازه. کمینه و بیشینه دوره فعلی (با شروع از NAN)، ساعت دوره، و پرچم «حد تازه را تأیید کن». NAN یعنی «هنوز خواندنی نداریم»؛ پس دوره‌ای بدون خواندن معتبر قابل تشخیص است و چیز غلطی منتشر نمی‌شود.
  2. payload به یک رشته C واقعی. حداکثر ۱۵ بایت کپی کن و '\0' را اضافه کن. کتابخانه بایت‌های خام و یک طول به تو می‌دهد. بدون پایان‌دهنده، strtof و printf از انتها رد می‌شوند و هر چه در حافظه هست را می‌خوانند.
  3. «کل» متن را بررسی کن. strtof تبدیل می‌کند و end را روی اولین نویسه‌ای می‌گذارد که استفاده نکرده؛ فاصله یا خط جدید انتهایی رد می‌شوند. معتبر یعنی: چند رقم خوانده شده، بعدش جز انتها چیزی نیست، پیام بریده نشده، و مقدار بین ۲۰ و ۶۰ است. این ابزار تازه این پروژه است (از کتابخانه استاندارد C). روی بروکر عمومی هر کسی می‌تواند هر چیزی بفرستد؛ حد ۰ یا ۹۹۹ هشدار را بی‌فایده می‌کند، پس دستگاه از خودش محافظت می‌کند.
  4. رد شد: بگو و هیچ چیز را عوض نکن. حد قبلی سر جایش می‌ماند؛ یک پیام بد هرگز ایستگاه را بدون هشدار سالم رها نمی‌کند.
  5. پذیرفته شد: فورا اعمال کن، حد رفع ۲ درجه پایین‌تر، پرچم را بگذار. نگه داشتن فاصله ۲ درجه، هیسترزیس درس ۶.۳ را حفظ می‌کند (بدون چشمک‌زدن بی‌جا). updateAlarm() بعدی، حداکثر ۲ ثانیه بعد، از حد تازه استفاده می‌کند.
  6. کمینه و بیشینه فقط از خواندن‌های معتبر. بعد از بررسی NaN با return. اولین خواندن معتبر یک دوره هر دو را تعیین می‌کند؛ خواندن ناموفق هرگز به این خط‌ها نمی‌رسد.
  7. خلاصه روزانه. یک پیام JSON با retain، یک خط Serial که می‌گوید رفت یا نه، و بعد دوره تازه. retained است تا داشبوردی که فردا صبح باز می‌شود هنوز خلاصه دیروز را نشان بدهد. اگر شبکه در آن لحظه قطع باشد، این خلاصه از دست می‌رود؛ با «offline, lost» در Serial نوشته می‌شود تا بدانی (ماندگار کردنش همان ایده تمرین ۱ است).
  8. تأیید حدی که به کار می‌رود. فقط وقتی وصل هستیم؛ پرچم تا موفقیت روشن می‌ماند. منتشر کردن از داخل callback در PubSubClient خطرناک است، چون هر دو از یک بافر مشترک استفاده می‌کنند. گذاشتن پرچم و منتشر کردن از loop الگوی امن است. topic وضعیت با retain همان راهی است که گوشی می‌فهمد ایستگاه واقعا از کدام حد استفاده می‌کند.
  9. subscribe بعد از هر اتصال موفق. بروکر مقدار retained را درست بعد از subscribe می‌فرستد. اتصال دوباره آن را دوباره می‌رساند، و اعمال دوباره همان مقدار ضرری ندارد.
  10. دو کار دیگر در زمان‌بند. در صورت نیاز حد را تأیید کن؛ هر DAY_MS یک بار خلاصه را بفرست. همان الگوی «برای هر کار یک ساعت» ایستگاه کامل؛ پس اضافه کردن قابلیت هیچ‌وقت انتظار اضافه نمی‌کند.
حدی که هر کسی می‌تواند عوضش کند

روی بروکر عمومی، هر کسی که topic تو را حدس بزند می‌تواند حد تازه منتشر کند. بررسی ۲۰ تا ۶۰ آسیب را محدود می‌کند، ولی برای یک گلخانه واقعی از یک بروکر خصوصی با نام کاربری و رمز استفاده کن (HiveMQ Cloud یا Adafruit IO، درس ۵.۱).

این «کارنامه» روی کاغذ نیست؛ در پروژه‌ای است که روی میزت کار می‌کند. عکسش را بگیر و نگه دار.

قدم بعدی: درس ۶.۴، حالا نوبت توست

تا اینجا هر پروژه را با هم ساختیم: پین، کتابخانه و کد را من انتخاب کردم. دوره هنوز تمام نشده؛ یک درس دیگر مانده که مهم‌ترین مهارت را می‌دهد: ساختن پروژه خودت، بدون معلم، روی هر مدل ESP32. در درس ۶.۴ یاد می‌گیری:

  • روشی را که در همین درس دیدی (PRD، پین با دلیل، گام‌های آزمایش‌شده) برای هر ایده تازه تکرار کنی (بخش ۱)
  • بین ESP32، S2، S3، C3، C6، H2 و P4 با دلیل فنی انتخاب کنی و همین ایستگاه را به مدل دیگری منتقل کنی (بخش ۲ و ۳)
  • قطعه‌ای را که هرگز ندیده‌ای از روی دیتاشیت راه بیندازی و با یک روش منظم عیب‌یابی کنی (بخش ۴ و ۵)
  • پروژه بعدی‌ات را از «نردبان پروژه‌ها» انتخاب کنی و بدانی بعد از این دوره کجا بروی (بخش ۶ و ۷)

گواهی پایان دوره هم در انتهای همان درس است. تا آن را نگذرانده‌ای، دوره را «تمام‌شده» حساب نکن.

خلاصه درس در سه خط

پروژه بزرگ را با نیازمندی روشن (PRD)، معماری و جدول پین با دلیل شروع کن و در گام‌های کوچک آزمایش‌شده بساز: سنسور، نمایشگر، هشدار، Wi-Fi، MQTT، ادغام. برنامه نهایی با توابع جدا و زمان‌بندی millis() هیچ‌وقت منتظر شبکه نمی‌ماند؛ هشدار با هیسترزیس نوسان نمی‌کند و با محدودیت نرخ اسپم نمی‌فرستد. قبل از «تمام شد»، همه آزمایش‌های پذیرش را بگذران و سنسور را از گرمای ESP32 دور نصب کن.
