این درس امتحان نهایی توست، ولی امتحانی که با هم می‌نویسیم. یک ایستگاه پایش محیط کامل می‌سازیم: دما، رطوبت و نور را اندازه می‌گیرد، روی نمایشگر نشان می‌دهد، اگر هوا بیش از حد گرم شد با چراغ و بوق هشدار می‌دهد، و همه چیز را از طریق اینترنت به یک داشبورد ابری می‌فرستد. تقریبا همه چیزهایی که در این دوره یاد گرفتی اینجا کنار هم قرار می‌گیرند. مهم‌تر از خود پروژه، روش ساختن آن است: قدم به قدم، و هر قدم آزمایش‌شده.

🎯 بعد از این درس می‌توانی

  • قبل از کدنویسی، نیازمندی‌ها و معماری یک پروژه را روی کاغذ بیاوری
  • پین‌ها را با دلیل انتخاب کنی و فهرست قطعات بنویسی
  • یک پروژه بزرگ را در گام‌های کوچک آزمایش‌پذیر بسازی
  • با millis() چند کار هم‌زمان را بدون مسدود کردن برنامه زمان‌بندی کنی
  • هشداری بسازی که با هیسترزیس نوسان نکند و با محدودیت نرخ پیام اسپم نفرستد
  • داده‌ها را با MQTT به HiveMQ یا Adafruit IO بفرستی و روی داشبورد ببینی

🧰 پیش‌نیاز و وسایل

  • درس‌های ۳.۱ (LDR، دکمه)، ۳.۲ (PWM)، ۳.۳ (OLED، DHT22)، ۴.۱ (Wi-Fi)، ۵.۱ (MQTT) و ۶.۱ (خواب)

  • نمایشگر OLED SSD1306 با رابط I2C
  • LED قرمز + مقاومت ۲۲۰ اهم، بازر پیزو پسیو، دکمه فشاری
  • دو برد بورد یا یک برد بورد بزرگ، سیم جامپر

قدم صفر: نیازمندی‌ها (یک PRD کوچک)

حرفه‌ای‌ها قبل از کد، یک سند کوتاه می‌نویسند که بگوید محصول دقیقا چه کاری باید بکند. به آن PRD (سند نیازمندی‌های محصول) می‌گویند. بدون آن، پروژه مدام بزرگ‌تر می‌شود و هیچ‌وقت «تمام» نمی‌شود، چون نمی‌دانی «تمام» یعنی چه.

مثال از زندگی: نقشه ساختمان

هیچ بنایی بدون نقشه شروع به آجرچینی نمی‌کند. اگر وسط کار صاحبخانه بگوید «راستی یک طبقه دیگر هم می‌خواهم»، ستون‌ها از قبل برای آن طراحی نشده‌اند. PRD نقشه پروژه توست: کوتاه، ولی روشن.

سیم‌کشی کامل

سیم‌کشی را در دو نقشه آورده‌ایم تا شلوغ نشود: اول ورودی‌ها و نمایشگر، بعد خروجی‌های هشدار و دکمه. همه قطعه‌ها با ۳٫۳ ولت تغذیه می‌شوند، نه ۵ ولت؛ چون خروجی سنسورها مستقیم به پین‌های ESP32 می‌رود.

روش ساختن: گام‌های کوچک، هر گام آزمایش‌شده

بزرگ‌ترین اشتباه مبتدی‌ها: همه قطعه‌ها را وصل می‌کنند، ۲۰۰ خط کد می‌نویسند، آپلود می‌کنند و... هیچ چیز کار نمی‌کند. حالا مشکل کجاست؟ سنسور؟ نمایشگر؟ Wi-Fi؟ کد؟ نمی‌دانی. ما شش گام برمی‌داریم و تا گام قبلی کار نکرده، به گام بعد نمی‌رویم:

  1. سنسورها ← عدد درست در Serial Monitor
  2. نمایشگر ← همان عددها روی OLED
  3. هشدار محلی ← LED و بازر با هیسترزیس، بدون delay
  4. Wi-Fi ← اتصال و اتصال دوباره بدون مسدود کردن
  5. MQTT ← پیام آزمایشی در کلاینت MQTT
  6. ادغام و هشدار ابری ← برنامه نهایی با زمان‌بندی millis
مثل پختن غذا

آشپز خوب هر ماده را جدا می‌چشد: آیا نمک کافی است؟ آیا گوشت پخته؟ بعد آن‌ها را با هم مخلوط می‌کند. اگر همه را با هم در دیگ بریزی و آخرش مزه‌اش بد شد، نمی‌دانی تقصیر کدام بود.

گام ۱: سنسورها

// گام ۱: فقط سنسورها؛ خروجی در Serial Monitor
#include <DHT.h>

const int PIN_DHT = 4;
const int PIN_LDR = 34;                  // ADC1: با Wi-Fi هم کار می‌کند
DHT dht(PIN_DHT, DHT22);

void setup() {
  Serial.begin(115200);
  dht.begin();
  analogReadResolution(12);              // خروجی 0 تا 4095
}

void loop() {
  float t = dht.readTemperature();       // سانتی‌گراد
  float h = dht.readHumidity();          // درصد
  int raw = analogRead(PIN_LDR);
  int lightPct = map(raw, 4095, 0, 0, 100);   // نور بیشتر = ولتاژ کمتر
  if (isnan(t) || isnan(h)) Serial.println("DHT22 error!");
  else Serial.printf("T=%.1f C  H=%.0f %%  LDR raw=%d  light=%d %%\n", t, h, raw, lightPct);
  delay(2000);                           // در این گام آزمایشی delay اشکالی ندارد
}
  1. پین‌ها و شیء سنسور. DHT22 روی GPIO4 و LDR روی GPIO34، دقیقا مثل جدول پین‌ها. از همین گام اول پین‌های نهایی را استفاده می‌کنیم. اگر الان پین موقتی بگذاری، در ادغام نهایی یک جای دیگر برای خطا ساخته‌ای.
  2. دقت ADC. ۱۲ بیت یعنی عدد ۰ تا ۴۰۹۵. این پیش‌فرض ESP32 است، ولی نوشتنش صریحا نشان می‌دهد به چه بازه‌ای تکیه کرده‌ایم و بعدا در map از آن استفاده می‌کنیم.
  3. خواندن DHT22. دما به سانتی‌گراد و رطوبت به درصد. اگر خواندن شکست بخورد، NaN (یعنی «عدد نیست») برمی‌گردد. DHT22 کند است و حداکثر هر ۲ ثانیه یک بار داده تازه می‌دهد. برای همین کل سیستم را روی دوره ۲ ثانیه‌ای طراحی کرده‌ایم.
  4. نور به درصد. map(raw, 4095, 0, 0, 100) بازه را برعکس تبدیل می‌کند: ۴۰۹۵ (تاریک) ← ۰ درصد، ۰ (روشن) ← ۱۰۰ درصد. در ماژول‌های رایج LDR (و ماژول Wokwi)، با زیاد شدن نور ولتاژ AO کم می‌شود. اگر ماژول تو برعکس است (با پوشاندن سنسور، درصد زیاد می‌شود)، فقط ترتیب را عوض کن: map(raw, 0, 4095, 0, 100). این عدد «درصد نسبی» است، نه لوکس واقعی.
  5. چاپ با بررسی خطا. اگر هر کدام NaN بود پیام خطا، وگرنه همه مقادیر در یک خط. چاپ raw کنار درصد، در عیب‌یابی کمک می‌کند: اگر raw همیشه ۰ یا ۴۰۹۵ است، سیم‌کشی LDR مشکل دارد، نه فرمول.
آزمون قبول گام ۱

دما و رطوبت عدد معقول (مثلا ۲۰ تا ۳۰ درجه و ۲۰ تا ۶۰ درصد) نشان دهند؛ با گرفتن سنسور در دست دما کم‌کم بالا برود؛ با پوشاندن LDR درصد نور کم شود. سیم DATA را جدا کن: باید «DHT22 error!» ببینی. همه درست؟ برو گام ۲.

گام ۲: نمایشگر OLED

// گام ۲: نمایش روی OLED
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>

DHT dht(4, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);   // -1: پایه ریست ندارد

void setup() {
  Serial.begin(115200);
  dht.begin();
  Wire.begin(21, 22);                          // SDA, SCL
  if (!oled.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    Serial.println("OLED not found! check wiring/address");
    while (true) delay(1000);                  // بدون نمایشگر، این گام معنی ندارد
  }
  oled.setTextColor(SSD1306_WHITE);
}

void loop() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  oled.clearDisplay();
  oled.setTextSize(2);
  oled.setCursor(0, 0);
  if (isnan(t)) oled.print("T: ERR"); else { oled.print(t, 1); oled.print(" C"); }
  oled.setCursor(0, 24);
  if (isnan(h)) oled.print("H: ERR"); else { oled.print(h, 0); oled.print(" %"); }
  oled.display();                              // تا این خط، چیزی روی صفحه نمی‌آید
  delay(2000);
}
  1. کتابخانه‌ها. Wire برای I2C (جزو هسته)، Adafruit GFX برای رسم متن و شکل، Adafruit SSD1306 برای خود نمایشگر. GFX «زبان رسم» مشترک بین نمایشگرهای Adafruit است؛ SSD1306 مترجم آن برای این نمایشگر خاص. هر دو را از Library Manager نصب کن.
  2. ساخت شیء نمایشگر. عرض ۱۲۸، ارتفاع ۶۴، روی باس Wire، بدون پایه ریست. ماژول‌های چهارپایه پایه ریست ندارند؛ ۱- یعنی «ریست را نرم‌افزاری انجام بده».
  3. راه‌اندازی I2C و نمایشگر. آدرس رایج 0x3C است. اگر begin شکست بخورد، پیام می‌دهیم و متوقف می‌شویم. در این گام آزمایشی، توقف درست است: می‌خواهیم مشکل نمایشگر را فورا ببینیم. در برنامه نهایی این کار را نمی‌کنیم، چون خرابی نمایشگر نباید هشدار و ارسال را هم از کار بیندازد (R8). اگر پیدا نشد، آدرس 0x3D را امتحان کن یا با برنامه اسکنر I2C درس ۳.۳ آدرس را پیدا کن.
  4. رسم. پاک کردن بافر، اندازه متن ۲ (حروف ۱۲×۱۶ پیکسل)، رفتن به مختصات، چاپ، و در آخر display(). همه دستورهای رسم فقط در یک بافر در RAM نوشته می‌شوند؛ display() کل بافر را یک‌جا از طریق I2C می‌فرستد. این باعث می‌شود صفحه چشمک نزند. print(t, 1) یعنی یک رقم اعشار.

گام ۳: هشدار محلی با هیسترزیس (بدون delay)

قبل از کد، دو مفهوم کلیدی:

هیسترزیس: مثل ترموستات بخاری

اگر هشدار را با یک عدد (۳۵ درجه) روشن و با همان عدد خاموش کنی، وقتی دما حوالی ۳۵ درجه است (۳۴٫۹، ۳۵٫۱، ۳۴٫۹...) هشدار مدام روشن و خاموش می‌شود و بازر دیوانه‌ات می‌کند. ترموستات بخاری هم همین را حل کرده: در ۲۰ درجه روشن می‌شود ولی تا ۲۲ درجه نشود خاموش نمی‌شود. به این «فاصله امن» هیسترزیس می‌گویند. ما هشدار را بالای ۳۵ روشن و زیر ۳۳ خاموش می‌کنیم.

مفهوم دوم: زمان‌بندی بدون delay (درس ۳.۱). چون LED باید چشمک بزند، بازر بوق بزند و دکمه هم‌زمان خوانده شود، نمی‌توانیم با delay(2000) برنامه را قفل کنیم. به جایش هر کار را با «آیا وقتش رسیده؟» (millis()) انجام می‌دهیم.

// گام ۳: هشدار محلی با هیسترزیس و بدون delay
#include <DHT.h>

const int PIN_LED = 25, PIN_BUZ = 26, PIN_BTN = 33;
const float TEMP_HIGH = 35.0, TEMP_CLEAR = 33.0;
DHT dht(4, DHT22);

float tempC = NAN;
bool alarmOn = false, muted = false;
uint32_t tSensor = 0;

void setup() {
  Serial.begin(115200);
  dht.begin();
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  ledcAttach(PIN_BUZ, 2000, 8);           // API هسته 3.x
}

void loop() {
  if (millis() - tSensor >= 2000) {       // هر ۲ ثانیه، بدون متوقف کردن برنامه
    tSensor = millis();
    float t = dht.readTemperature();
    if (!isnan(t)) tempC = t;
    if (!alarmOn && tempC > TEMP_HIGH) { alarmOn = true;  muted = false; Serial.println("ALARM ON"); }
    if (alarmOn && tempC < TEMP_CLEAR) { alarmOn = false; Serial.println("ALARM OFF"); }
  }
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;   // دکمه = بی‌صدا

  bool blink = (millis() / 250) % 2;      // هر ۲۵۰ میلی‌ثانیه صفر و یک می‌شود
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {              // فقط وقتی لازم است LEDC را عوض کن
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}
  1. دو آستانه. ۳۵ برای روشن شدن و ۳۳ برای خاموش شدن. فاصله ۲ درجه از نوسان طبیعی خواندن DHT22 (حدود نیم درجه) و نوسان‌های کوتاه دمای اتاق بزرگ‌تر است. فاصله خیلی کم = نوسان؛ فاصله خیلی زیاد = هشدار دیر خاموش می‌شود.
  2. وضعیت برنامه. آخرین دمای معتبر (اول NaN)، روشن بودن هشدار، بی‌صدا بودن، و زمان آخرین خواندن. این متغیرها «حافظه» برنامه‌اند. چون loop هزاران بار در ثانیه اجرا می‌شود، هر تصمیم باید بر اساس وضعیت ذخیره‌شده باشد، نه منتظر ماندن.
  3. ledcAttach برای بازر. پین ۲۶ را به PWM با فرکانس اولیه ۲۰۰۰ هرتز و دقت ۸ بیت وصل می‌کند. بازر پسیو خودش صدا تولید نمی‌کند؛ باید با یک موج مربعی در فرکانس صوتی به لرزه بیفتد. این API هسته ۳.x است؛ در ۲.x باید ledcSetup و ledcAttachPin می‌نوشتی (درس ۳.۲).
  4. خواندن زمان‌بندی‌شده و منطق هیسترزیس. هر ۲ ثانیه دما خوانده می‌شود؛ فقط اگر معتبر بود جایگزین می‌شود. هشدار خاموش + دما بالای ۳۵ ← روشن (و بی‌صدا لغو). هشدار روشن + دما زیر ۳۳ ← خاموش. شرط‌ها «وضعیت فعلی» را هم چک می‌کنند؛ پس پیام «ALARM ON» فقط یک بار، در لحظه تغییر، چاپ می‌شود. این همان الگویی است که بعدا برای پیام ابری بدون اسپم استفاده می‌کنیم. اگر دما NaN باشد، هر مقایسه‌ای با آن false است و وضعیت عوض نمی‌شود.
  5. دکمه بی‌صدا. اگر در حال هشدار دکمه فشرده شد، بازر ساکت می‌شود؛ LED همچنان چشمک می‌زند. بی‌صدا کردن فقط صدا را قطع می‌کند، نه خود هشدار را؛ خطر هنوز وجود دارد و باید دیده شود. با شروع هشدار بعدی، muted دوباره false می‌شود (خط ۲۵).
  6. چشمک بدون delay. millis() / 250 هر ۲۵۰ میلی‌ثانیه یکی زیاد می‌شود؛ باقیمانده تقسیم بر ۲ یکی در میان ۰ و ۱ است. یک ترفند یک‌خطی برای چشمک زدن بدون هیچ متغیر اضافی. LED فقط وقتی روشن است که هشدار روشن باشد و blink یک باشد.
  7. بازر فقط هنگام تغییر. ledcWriteTone(pin, 2000) بوق ۲ کیلوهرتز، ledcWriteTone(pin, 0) سکوت. ولی فقط وقتی خواسته با وضعیت فعلی فرق دارد. loop هزاران بار در ثانیه می‌چرخد. تنظیم دوباره PWM در هر دور بی‌فایده است و ممکن است صدای بازر را خش‌دار کند. متغیر static وضعیت قبلی را بین دورها به خاطر می‌سپارد.
آزمون قبول گام ۳

در Wokwi روی DHT22 کلیک کن و دما را به ۳۶ ببر: LED باید چشمک بزند و بازر بوق بزند. دکمه را بزن: بازر ساکت، LED همچنان چشمک. دما را به ۳۴ بیاور: هشدار نباید خاموش شود (هیسترزیس!). به ۳۲ بیاور: خاموش. روی برد واقعی، سنسور را برای چند ثانیه نزدیک (نه چسبیده به) یک سشوار با باد ملایم بگیر، یا موقتا TEMP_HIGH را کمی بالاتر از دمای اتاق بگذار.

گام ۴: Wi-Fi بدون مسدود کردن

در درس ۴.۱ اتصال و اتصال دوباره را یاد گرفتی. نکته این گام: هرگز در loop با while منتظر Wi-Fi نمانیم، چون در آن مدت هشدار محلی کار نمی‌کند (R8).

// گام ۴: Wi-Fi غیرمسدودکننده
#include <WiFi.h>

const char* WIFI_SSID = "Wokwi-GUEST";
const char* WIFI_PASS = "";
uint32_t tWifi = 0;
bool wasConnected = false;

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);        // شروع اتصال؛ منتظر نمی‌مانیم
}

void loop() {
  bool ok = (WiFi.status() == WL_CONNECTED);
  if (ok && !wasConnected) {
    Serial.print("WiFi connected, IP = ");
    Serial.println(WiFi.localIP());
  }
  if (!ok && wasConnected) Serial.println("WiFi lost!");
  if (!ok && millis() - tWifi >= 15000) {  // هر ۱۵ ثانیه یک تلاش دوباره
    tWifi = millis();
    Serial.println("WiFi not connected, retrying...");
    WiFi.reconnect();
  }
  wasConnected = ok;
  // ... اینجا بقیه کارها بدون معطلی اجرا می‌شوند ...
}
  1. شروع اتصال و رفتن. WiFi.begin فقط اتصال را شروع می‌کند و فورا برمی‌گردد. اتصال در پس‌زمینه (توسط سیستم عامل FreeRTOS داخل ESP32) انجام می‌شود. ما فقط هر وقت لازم شد وضعیت را نگاه می‌کنیم.
  2. تشخیص تغییر وضعیت. با مقایسه وضعیت فعلی و قبلی (wasConnected)، فقط لحظه وصل شدن و لحظه قطع شدن پیام چاپ می‌شود. این همان الگوی «لبه» است که در هشدار هم دیدی: کار را در لحظه تغییر انجام بده، نه در هر دور loop.
  3. تلاش دوباره دوره‌ای. اگر وصل نیستیم، هر ۱۵ ثانیه یک بار WiFi.reconnect(). هسته ESP32 به‌طور پیش‌فرض خودش هم برای اتصال دوباره تلاش می‌کند؛ این تلاش دستی یک لایه اطمینان اضافه است. فاصله ۱۵ ثانیه جلوی «کوبیدن» مودم با درخواست‌های پشت سر هم را می‌گیرد.

گام ۵: MQTT

بروکر عمومی broker.hivemq.com روی پورت ۱۸۸۳ بدون ثبت‌نام کار می‌کند (درس ۵.۱). چون عمومی است، هر کسی می‌تواند پیام‌های تو را ببیند؛ پس topic را با یک پیشوند یکتا بساز (مثلا با نام و یک عدد تصادفی) و هیچ داده خصوصی نفرست.

// گام ۵: ارسال پیام آزمایشی به MQTT
#include <WiFi.h>
#include <PubSubClient.h>

const char* MQTT_HOST = "broker.hivemq.com";
const char* BASE = "esp32fa/station-42/";      // این را یکتا کن!
WiFiClient net;
PubSubClient mqtt(net);
uint32_t tMqtt = 0, tPub = 0;

void setup() {
  Serial.begin(115200);
  WiFi.begin("Wokwi-GUEST", "");
  mqtt.setServer(MQTT_HOST, 1883);
}

void loop() {
  if (WiFi.status() != WL_CONNECTED) return;   // بدون Wi-Fi کاری نکن
  if (!mqtt.connected()) {
    if (millis() - tMqtt < 5000) return;      // حداکثر هر ۵ ثانیه یک تلاش
    tMqtt = millis();
    String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX);
    Serial.println(mqtt.connect(id.c_str()) ? "MQTT connected" : "MQTT failed");
    return;
  }
  mqtt.loop();                                 // اتصال را زنده نگه دار
  if (millis() - tPub >= 10000) {
    tPub = millis();
    String topic = String(BASE) + "test";
    String msg = String(millis() / 1000);
    mqtt.publish(topic.c_str(), msg.c_str());
    Serial.println("Published " + topic + " = " + msg);
  }
}
  1. پیشوند topic. همه topicهای این پروژه با esp32fa/station-42/ شروع می‌شوند. یک پیشوند یعنی می‌توانی در کلاینت با esp32fa/station-42/# همه پیام‌های ایستگاه را یک‌جا ببینی. و اگر به Adafruit IO رفتی، فقط همین یک خط را عوض می‌کنی.
  2. اتصال با فاصله. اگر Wi-Fi نیست، فورا از loop برمی‌گردیم. اگر MQTT وصل نیست، حداکثر هر ۵ ثانیه یک بار تلاش می‌کنیم. شناسه کلاینت از آدرس MAC ساخته می‌شود. شناسه باید یکتا باشد؛ اگر دو دستگاه با یک شناسه وصل شوند، بروکر اولی را بیرون می‌اندازد و آن‌ها مدام همدیگر را قطع می‌کنند. توجه: خود mqtt.connect ممکن است وقتی سرور در دسترس نیست چند ثانیه طول بکشد؛ این تنها نقطه‌ای است که کمی مسدود می‌شویم.
  3. mqtt.loop(). باید مرتب صدا زده شود. پیام‌های «زنده‌ام» (keep-alive) را به بروکر می‌فرستد و پیام‌های ورودی را پردازش می‌کند. اگر loop با delay طولانی قفل شود، بروکر فکر می‌کند دستگاه مرده و اتصال را قطع می‌کند.
  4. انتشار هر ۱۰ ثانیه. زمان روشن بودن برد (ثانیه) را به topic .../test می‌فرستد. یک پیام آزمایشی ساده و همیشه‌متغیر؛ اگر عدد در کلاینت زیاد می‌شود، کل زنجیره (Wi-Fi، DNS، TCP، MQTT) سالم است.
پیام‌ها را کجا ببینم؟

در یک کلاینت MQTT (مثلا کلاینت وب HiveMQ یا برنامه‌ای که در درس ۵.۱ استفاده کردی) به broker.hivemq.com وصل شو و topic esp32fa/station-42/# را subscribe کن (# یعنی «همه زیرشاخه‌ها»). آزمون قبول گام ۵: هر ۱۰ ثانیه یک عدد جدید ببینی.

گام ۶: برنامه نهایی یکپارچه

حالا همه گام‌ها را در یک برنامه با ساختار تمیز کنار هم می‌گذاریم. ساختار برنامه:

  • تنظیمات همه در بالا؛ برای تغییر رفتار، لازم نیست در کد بگردی.
  • هر مسئولیت یک تابع: خواندن سنسور، منطق هشدار، خروجی‌ها، نمایشگر، شبکه، ارسال.
  • loop فقط زمان‌بندی می‌کند: «آیا وقت خواندن است؟ آیا وقت ارسال است؟» و بقیه را به توابع می‌سپارد.
// ایستگاه پایش محیط با هشدار ابری — درس ۶.۳
#include <WiFi.h>
#include <PubSubClient.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>

// ================== ۱. تنظیمات ==================
const char* WIFI_SSID = "Wokwi-GUEST";
const char* WIFI_PASS = "";
const char* MQTT_HOST = "broker.hivemq.com";
const uint16_t MQTT_PORT = 1883;
const char* MQTT_USER = nullptr;               // Adafruit IO: نام کاربری
const char* MQTT_KEY  = nullptr;               // Adafruit IO: AIO Key
const char* BASE      = "esp32fa/station-42/"; // پیشوند یکتای topicها

const float TEMP_HIGH  = 35.0;                 // بالاتر از این: هشدار
const float TEMP_CLEAR = 33.0;                 // پایین‌تر از این: پایان هشدار
const uint32_t SENSOR_MS  = 2000;              // هر ۲ ثانیه خواندن
const uint32_t PUBLISH_MS = 30000;             // هر ۳۰ ثانیه ارسال
const uint32_t REMIND_MS  = 600000;            // یادآوری هشدار: حداکثر هر ۱۰ دقیقه

// ================== ۲. پین‌ها ==================
const int PIN_DHT = 4;
const int PIN_LDR = 34;                        // ADC1: با Wi-Fi کار می‌کند
const int PIN_LED = 25;
const int PIN_BUZ = 26;
const int PIN_BTN = 33;                        // دکمه بی‌صدا

// ================== ۳. اشیا و وضعیت ==================
DHT dht(PIN_DHT, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);
WiFiClient net;
PubSubClient mqtt(net);

float tempC = NAN, hum = NAN;
int lightPct = 0;
bool alarmOn = false, muted = false, oledOk = false;
uint32_t tSensor = 0, tPublish = 0, tAlert = 0, tWifi = 0, tMqtt = 0;

// ================== ۴. سنسورها ==================
void readSensors() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) { tempC = t; hum = h; }
  else Serial.println("DHT22 read failed, keeping last value");
  int raw = analogRead(PIN_LDR);               // 0..4095
  lightPct = map(raw, 4095, 0, 0, 100);        // نور بیشتر = ولتاژ کمتر
}

// ================== ۵. ارسال به ابر ==================
void publishValue(const char* name, float v, int decimals) {
  char topic[64], payload[16];
  snprintf(topic, sizeof(topic), "%s%s", BASE, name);
  snprintf(payload, sizeof(payload), "%.*f", decimals, v);
  mqtt.publish(topic, payload);
}

void publishAll() {
  if (!mqtt.connected() || isnan(tempC)) return;
  publishValue("temp", tempC, 1);
  publishValue("hum", hum, 0);
  publishValue("light", lightPct, 0);
  Serial.println("Published to MQTT");
}

void publishAlert(const char* msg) {
  tAlert = millis();                           // شمارش یادآوری از نو
  Serial.println(msg);
  if (!mqtt.connected()) return;
  char topic[64];
  snprintf(topic, sizeof(topic), "%salert", BASE);
  mqtt.publish(topic, msg);
}

// ================== ۶. منطق هشدار (هیسترزیس + محدودیت نرخ) ==================
void updateAlarm() {
  if (isnan(tempC)) return;
  if (!alarmOn && tempC > TEMP_HIGH) {
    alarmOn = true;
    muted = false;
    publishAlert("ALERT: temperature high");
  } else if (alarmOn && tempC < TEMP_CLEAR) {
    alarmOn = false;
    publishAlert("OK: temperature back to normal");
  } else if (alarmOn && millis() - tAlert >= REMIND_MS) {
    publishAlert("ALERT: still high");         // یادآوری، نه اسپم
  }
}

void driveOutputs() {
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;
  bool blink = (millis() / 250) % 2;
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}

// ================== ۷. نمایشگر ==================
void drawDisplay() {
  if (!oledOk) return;                         // نمایشگر نیست؟ بقیه کارها ادامه دارد
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setCursor(0, 0);
  oled.print(WiFi.status() == WL_CONNECTED ? "WiFi OK  " : "WiFi --  ");
  oled.print(mqtt.connected() ? "MQTT OK" : "MQTT --");
  oled.setTextSize(2);
  oled.setCursor(0, 14);
  if (isnan(tempC)) oled.print("T: ERR");
  else { oled.print(tempC, 1); oled.print(" C"); }
  oled.setCursor(0, 34);
  if (isnan(hum)) oled.print("H: ERR");
  else { oled.print(hum, 0); oled.print(" %"); }
  oled.setTextSize(1);
  oled.setCursor(0, 56);
  oled.printf("Light %d%%  %s", lightPct, alarmOn ? (muted ? "ALARM(m)" : "ALARM!") : "normal");
  oled.display();
}

// ================== ۸. شبکه (بدون مسدود کردن) ==================
void keepWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  if (millis() - tWifi < 15000) return;        // هر ۱۵ ثانیه یک تلاش
  tWifi = millis();
  Serial.println("WiFi: reconnecting...");
  WiFi.reconnect();
}

void keepMqtt() {
  if (WiFi.status() != WL_CONNECTED) return;
  if (mqtt.connected()) { mqtt.loop(); return; }
  if (millis() - tMqtt < 5000) return;         // هر ۵ ثانیه یک تلاش
  tMqtt = millis();
  String id = "esp32-station-" + String((uint32_t)ESP.getEfuseMac(), HEX);
  String will = String(BASE) + "status";
  if (mqtt.connect(id.c_str(), MQTT_USER, MQTT_KEY, will.c_str(), 0, true, "offline")) {
    mqtt.publish(will.c_str(), "online", true);
    Serial.println("MQTT connected");
  } else {
    Serial.printf("MQTT failed, state=%d\n", mqtt.state());
  }
}

// ================== ۹. setup و loop ==================
void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  ledcAttach(PIN_BUZ, 2000, 8);                // API هسته 3.x
  analogReadResolution(12);
  dht.begin();
  Wire.begin(21, 22);
  oledOk = oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  if (oledOk) oled.setTextColor(SSD1306_WHITE);
  else Serial.println("OLED not found, continuing without display");
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  mqtt.setServer(MQTT_HOST, MQTT_PORT);
  tWifi = millis();
}

void loop() {
  uint32_t now = millis();
  if (now - tSensor >= SENSOR_MS) {
    tSensor = now;
    readSensors();
    updateAlarm();
    drawDisplay();
  }
  if (now - tPublish >= PUBLISH_MS) {
    tPublish = now;
    publishAll();
  }
  keepWiFi();
  keepMqtt();
  driveOutputs();
}

برنامه را بخش به بخش مرور می‌کنیم. روی هر کارت بزن تا خط‌هایش در کد بالا پررنگ شود.

  1. بخش ۱: تنظیمات. شبکه، بروکر، نام کاربری و کلید (برای HiveMQ عمومی nullptr یعنی «ندارد»)، پیشوند topic، آستانه‌ها و فاصله‌های زمانی. هر عددی که ممکن است روزی بخواهی عوض کنی، باید اسم داشته باشد و بالای برنامه باشد. «عدد جادویی» ۶۰۰۰۰۰ وسط کد را شش ماه بعد هیچ‌کس نمی‌فهمد؛ REMIND_MS را همه می‌فهمند. در پروژه واقعی رمزها را به فایل secrets.h ببر (درس ۶.۲).
  2. بخش ۲: پین‌ها. دقیقا مطابق جدول پین‌ها و نقشه‌های سیم‌کشی. یک منبع حقیقت: اگر سیمی را جابه‌جا کردی، فقط این‌جا را عوض می‌کنی.
  3. بخش ۳: اشیا و وضعیت. سنسور، نمایشگر، کلاینت شبکه و MQTT؛ بعد آخرین مقدارها، وضعیت هشدار، سالم بودن نمایشگر، و «زمان آخرین بار» برای هر کار زمان‌بندی‌شده. پنج متغیر t... پنج «ساعت» مستقل‌اند: هر کار ساعت خودش را دارد و بقیه را معطل نمی‌کند. این قلب زمان‌بندی بدون delay است.
  4. بخش ۴: خواندن سنسورها. مثل گام ۱، با یک تفاوت: اگر DHT22 خطا داد، آخرین مقدار معتبر نگه داشته می‌شود. DHT22 گاهی یک خواندن را از دست می‌دهد. پاک کردن عدد با هر خطای تکی، باعث پرش «ERR» روی نمایشگر و قطع داده ابری می‌شود. تا اولین خواندن موفق، مقدار NaN است و نمایشگر ERR نشان می‌دهد (R1). در تمرین ۲ این را هوشمندتر می‌کنی.
  5. بخش ۵ (الف): یک تابع برای ارسال هر عدد. نام topic با BASE ساخته می‌شود و عدد با تعداد رقم اعشار دلخواه به متن تبدیل می‌شود (%.*f). سه بار تکرار یک کد، یعنی سه جا برای باگ. یک تابع کوچک یعنی یک جا. از snprintf با آرایه ثابت به جای String استفاده کردیم تا حافظه را تکه‌تکه نکنیم؛ در برنامه‌ای که ماه‌ها روشن است مهم است.
  6. بخش ۵ (ب): ارسال همه مقادیر. اگر MQTT وصل نیست یا هنوز هیچ دمای معتبری نداریم، ارسال نمی‌شود. فرستادن «nan» به داشبورد نمودارها را خراب می‌کند. سه topic جدا (temp، hum، light) با Adafruit IO سازگارند که هر feed یک عدد می‌خواهد. با ۳ مقدار هر ۳۰ ثانیه، یعنی ۶ پیام در دقیقه، زیر محدودیت نرخ نسخه رایگان Adafruit IO (حدود ۳۰ داده در دقیقه) می‌مانیم.
  7. بخش ۵ (ج): پیام هشدار. زمان را ثبت می‌کند، در Serial چاپ می‌کند و اگر وصل هستیم به .../alert می‌فرستد. tAlert حتی اگر ارسال ناموفق باشد به‌روز می‌شود؛ یعنی قطع شبکه باعث تلاش مکرر و انبوه پیام در لحظه وصل شدن نمی‌شود. نقطه ضعف آگاهانه: اگر شبکه در لحظه شروع هشدار قطع باشد، اولین پیام گم می‌شود و یادآوری ۱۰ دقیقه بعد جبرانش می‌کند (تمرین ۱ این را بهتر می‌کند).
  8. بخش ۶ (الف): هیسترزیس و محدودیت نرخ. سه حالت: شروع هشدار (بالای ۳۵ و قبلا خاموش)، پایان هشدار (زیر ۳۳ و قبلا روشن)، یادآوری (هنوز روشن و ۱۰ دقیقه از پیام قبلی گذشته). این سه شاخه دقیقا R5 و R7 را پیاده می‌کنند. بدون شاخه سوم، کاربری که پیام اول را ندیده هرگز نمی‌فهمد مشکل ادامه دارد. بدون محدودیت زمانی، هر ۲ ثانیه یک پیام می‌آمد: ۱۸۰۰ پیام در ساعت! گوشی‌ات بی‌صدا می‌شود و وقتی واقعا لازم است، دیگر هشدار را نمی‌بینی.
  9. بخش ۶ (ب): خروجی‌های محلی. همان منطق گام ۳: دکمه بی‌صدا، چشمک LED و بازر فقط هنگام تغییر. این تابع در هر دور loop اجرا می‌شود تا چشمک و دکمه روان باشند؛ برخلاف خواندن سنسور که فقط هر ۲ ثانیه است. کار سبک، زیاد؛ کار سنگین، کم.
  10. بخش ۷: نمایشگر. خط بالا وضعیت شبکه؛ وسط دما و رطوبت با حروف درشت؛ پایین نور و وضعیت هشدار (ALARM(m) یعنی بی‌صدا شده). اگر نمایشگر پیدا نشده بود، تابع فورا برمی‌گردد. نمایش وضعیت Wi-Fi و MQTT روی صفحه، عیب‌یابی در محل را بدون لپ‌تاپ ممکن می‌کند. oledOk یعنی خرابی نمایشگر (مثلا یک سیم شل) هشدار و ارسال را از کار نمی‌اندازد؛ برخلاف گام ۲ که عمدا متوقف می‌شد.
  11. بخش ۸ (الف): نگهداری Wi-Fi. مثل گام ۴. اگر وصل هستیم، تابع در کسری از میکروثانیه برمی‌گردد؛ پس صدا زدنش در هر دور loop هزینه‌ای ندارد.
  12. بخش ۸ (ب): نگهداری MQTT با «وصیت‌نامه» (LWT). هنگام اتصال به بروکر می‌گوییم: «اگر من بی‌خبر قطع شدم، از طرف من پیام offline را با retain روی .../status منتشر کن». بلافاصله بعد از اتصال خودمان online را با retain می‌فرستیم. با این ترفند، داشبورد همیشه می‌داند ایستگاه زنده است یا نه؛ حتی اگر برق ایستگاه قطع شود و فرصت خداحافظی نداشته باشد. retain یعنی هر کس بعدا subscribe کند، آخرین وضعیت را فورا می‌گیرد. mqtt.state() در صورت شکست، کد خطا را می‌دهد (مثلا منفی یعنی مشکل شبکه، ۴ و ۵ یعنی نام کاربری یا کلید غلط). اگر Adafruit IO از retain پشتیبانی نکرد، فقط همان بخش بی‌اثر می‌شود.
  13. بخش ۹ (الف): setup. پین‌ها، بازر با API هسته ۳.x، ADC، سنسور، I2C و نمایشگر (بدون توقف در صورت خرابی)، شروع اتصال Wi-Fi (بدون انتظار) و تنظیم بروکر. setup هیچ حلقه انتظاری ندارد؛ یعنی دستگاه در کسری از ثانیه وارد loop می‌شود و هشدار محلی از همان ابتدا کار می‌کند، حتی اگر مودم خاموش باشد (R8).
  14. بخش ۹ (ب): loop، زمان‌بند مرکزی. هر ۲ ثانیه: خواندن، تصمیم هشدار، به‌روزرسانی نمایشگر. هر ۳۰ ثانیه: ارسال. در هر دور: نگهداری Wi-Fi و MQTT و خروجی‌ها. کل منطق برنامه در حدود ۱۵ خط قابل خواندن است. اگر فردا ویژگی جدیدی خواستی (مثلا ذخیره در کارت SD هر ۵ دقیقه)، فقط یک متغیر زمان و یک شرط if دیگر اضافه می‌کنی. now - tX >= فاصله حتی بعد از سرریز millis (حدود ۴۹ روز) درست کار می‌کند.

کل ایستگاه در Wokwi: در تب Library Manager این کتابخانه‌ها را اضافه کن: DHT sensor library، Adafruit SSD1306، Adafruit GFX Library و PubSubClient. Wi-Fi مجازی Wokwi-GUEST به اینترنت واقعی وصل است، پس پیام‌ها واقعا به broker.hivemq.com می‌رسند و می‌توانی در کلاینت MQTT خودت ببینی‌شان. روی DHT22 کلیک کن و دما را بالای ۳۵ ببر؛ روی سنسور نور کلیک کن و مقدار لوکس را عوض کن. حتما BASE را به یک پیشوند مخصوص خودت تغییر بده.

برنامه بالا همیشه روشن است و حدود ۱۰۰ میلی‌آمپر مصرف دارد؛ با باتری فقط یکی دو روز دوام می‌آورد. برای حالت باتری (R9) باید طراحی را عوض کنی، نه فقط یک خط اضافه کنی:

  • همه کار در setup(): بیدار شو، سنسور را بخوان، اگر لازم است پیام بفرست، بخواب (مثلا ۵ دقیقه). loop خالی می‌ماند.
  • وضعیت هشدار و زمان آخرین پیام در RTC_DATA_ATTR؛ چون millis() بعد از هر بیداری از صفر شروع می‌شود، برای محدودیت نرخ به جای زمان، «تعداد بیداری‌ها» را بشمار.
  • بازر و LED چشمک‌زن در خواب کار نمی‌کنند؛ هشدار محلی عملا به یک بوق کوتاه در هر بیداری تبدیل می‌شود. این یک مصالحه است که باید در PRD بنویسی.
  • OLED را قبل از خواب خاموش کن (oled.ssd1306_command(SSD1306_DISPLAYOFF)) وگرنه روشن می‌ماند و باتری می‌خورد.
  • دکمه روی GPIO33 (پین RTC) با EXT0 برد را برای نمایش فوری بیدار کند.

جعبه و محل نصب

  • سنسور را از ESP32 دور کن. ESP32 و رگولاتور روی برد، به‌خصوص با Wi-Fi روشن، گرم می‌شوند. DHT22 چسبیده به برد، چند درجه بیشتر از دمای واقعی اتاق نشان می‌دهد. دست‌کم چند سانتی‌متر فاصله بده یا سنسور را با سیم بیرون جعبه بگذار.
  • هوا باید جریان داشته باشد. جعبه دربسته، رطوبت و دمای داخل خودش را اندازه می‌گیرد. برای سنسور سوراخ‌های تهویه بگذار.
  • نور مستقیم خورشید ممنوع. خورشید مستقیم روی DHT22، دمای «خود سنسور» را اندازه می‌گیرد نه هوا. LDR را ولی باید جایی گذاشت که نور محیط را ببیند.
  • دور از منابع گرما و رطوبت (بخاری، کتری، آشپزخانه) مگر این که دقیقا همان را بخواهی بپایی.
  • برای بیرون از خانه جعبه ضدآب و یک «سایه‌بان تشعشع» (مثل پوسته‌های بشقابی ایستگاه‌های هواشناسی) لازم است؛ و ESP32 را از آب و میعان دور نگه دار.
  • آنتن Wi-Fi را نپوشان. آنتن روی ماژول WROOM (بخش موج‌دار انتهای ماژول) نباید نزدیک فلز یا زیر سیم‌ها باشد.

ایده‌هایی برای ادامه

  • ذخیره روی کارت SD هر ۵ دقیقه، تا اگر اینترنت قطع بود داده گم نشود (درس ۳.۳).
  • صفحه وب محلی که مقادیر را در شبکه خانه نشان دهد (درس ۴.۲).
  • سنسورهای ماهواره‌ای با ESP-NOW: چند ESP32 کوچک باتری‌خور در اتاق‌های مختلف، داده را به این ایستگاه بفرستند (درس ۵.۲).
  • ربات تلگرام برای فرستادن هشدار به گوشی.
  • تنظیم آستانه از راه دور با subscribe کردن به یک topic (روی بروکر خصوصی و امن!).

ویدیوی کمکی

  • این ویدیو قدیمی است و با ESP8266 کار می‌کند، نه ESP32؛ ولی مفهوم MQTT و Adafruit IO همان است. آن را برای فهم معماری ببین، نه برای کپی کد.
  • دقت کن feedها و داشبورد در Adafruit IO چطور ساخته می‌شوند و نام کاربری و کلید کجا استفاده می‌شوند. ظاهر سایت از آن زمان عوض شده است.
  • ببین چطور پیام‌ها از دستگاه به بروکر و از بروکر به سرویس‌های دیگر (مثل IFTTT و Node-RED) می‌روند؛ این همان جعبه «ابر» در نمودار معماری ماست.

اگر این پروژه را قدم به قدم ساختی و همه دوازده آزمایش پذیرش را گذراندی، به تو تبریک می‌گویم؛ صادقانه. ولی یک هشدار: وسوسه می‌شوی مستقیم برنامه نهایی را کپی کنی و گام‌ها را رد کنی. این کار را نکن. ارزش این درس در برنامه نهایی نیست (آن را هر هوش مصنوعی می‌نویسد)؛ ارزشش در روش است: نیازمندی روشن، پین با دلیل، گام کوچک، آزمایش قبل از ادامه، و طراحی برای روزی که اینترنت قطع است. این روش را در هر پروژه بعدی تکرار کن تا عادتت شود. مهندس خوب کسی نیست که هیچ‌وقت باگ ندارد؛ کسی است که می‌داند باگ دقیقا در کدام گام است.

آزمون این درس

چرا LDR را به GPIO34 وصل کردیم و نه مثلا به GPIO26؟

  1. GPIO26 فقط خروجی است
  2. GPIO34 روی ADC1 است؛ ADC2 (مثل GPIO26) وقتی Wi-Fi روشن است کار نمی‌کند
  3. GPIO34 دقت بیشتری دارد
  4. GPIO34 تنها پین I2C است
ADC2 با رادیوی Wi-Fi مشترک است. در پروژه‌ای که Wi-Fi دارد، ورودی آنالوگ فقط روی ADC1 (GPIO32 تا 39).

هشدار با TEMP_HIGH=35 و TEMP_CLEAR=33 روشن است. دما به ۳۴ درجه می‌رسد. چه می‌شود؟

  1. هشدار خاموش می‌شود
  2. پیام «OK» فرستاده می‌شود
  3. هشدار روشن می‌ماند
  4. هشدار سریع روشن و خاموش می‌شود
این همان هیسترزیس است: بین ۳۳ و ۳۵ وضعیت قبلی حفظ می‌شود.

اگر شاخه «یادآوری» و متغیر tAlert را حذف کنیم و در هر خواندن که دما بالای ۳۵ است پیام هشدار بفرستیم، در یک ساعت هشدار چند پیام فرستاده می‌شود؟

  1. حدود ۱۸۰۰ پیام (هر ۲ ثانیه یکی)
  2. ۶ پیام
  3. ۱۲۰ پیام
  4. ۱ پیام
۳۶۰۰ ÷ ۲ = ۱۸۰۰. محدودیت نرخ این را به ۱ پیام شروع + حداکثر ۶ یادآوری در ساعت کاهش می‌دهد.

چرا در setup برنامه نهایی با while منتظر وصل شدن Wi-Fi نمی‌مانیم؟

  1. چون while در setup خطای کامپایل می‌دهد
  2. چون بدون while، Wi-Fi هرگز وصل نمی‌شود
  3. چون while مصرف برق را زیاد می‌کند
  4. چون اگر مودم خاموش باشد، هشدار محلی هم هرگز شروع به کار نمی‌کند
R8: کارهای محلی هرگز منتظر شبکه نمی‌مانند. اتصال در پس‌زمینه انجام می‌شود.

پیام «وصیت‌نامه» (LWT) با مقدار offline روی topic وضعیت، چه زمانی منتشر می‌شود؟

  1. هر بار که دستگاه وصل می‌شود
  2. وقتی بروکر بفهمد دستگاه بدون خداحافظی قطع شده (مثلا قطع برق)
  3. وقتی دما از ۳۵ بالاتر برود
  4. هر ۳۰ ثانیه
LWT را دستگاه هنگام اتصال به بروکر می‌سپارد و بروکر فقط در صورت قطع ناگهانی آن را منتشر می‌کند.

ایستگاه دما را ۴ درجه بیشتر از دماسنج دیواری نشان می‌دهد. اولین چیزی که بررسی می‌کنی چیست؟

  1. عدد TEMP_HIGH
  2. کتابخانه DHT را عوض می‌کنی
  3. فاصله سنسور از ESP32 و منابع گرما و نور خورشید
  4. Wi-Fi را خاموش می‌کنی تا تداخل رادیویی نباشد
گرمای خود ESP32 و رگولاتور رایج‌ترین علت است. سنسور باید هوای آزاد اتاق را حس کند، نه گرمای برد را.

تمرین‌ها

تمرین ۱: هشدار گم‌نشدنی

در برنامه فعلی، اگر شبکه در لحظه شروع هشدار قطع باشد، پیام «ALERT» گم می‌شود. برنامه را طوری تغییر بده که پیام هشدار در یک متغیر «در انتظار ارسال» بماند و به محض وصل شدن MQTT فرستاده شود.

راهنمایی

یک متغیر const char* pendingAlert = nullptr; بساز. در publishAlert، اگر وصل نیستی، پیام را در آن بگذار. در keepMqtt، بلافاصله بعد از اتصال موفق، اگر pendingAlert خالی نیست، آن را بفرست و خالی کن. چون پیام‌ها رشته‌های ثابت‌اند، نگه داشتن اشاره‌گر به آن‌ها امن است.

تمرین ۲: سنسور مرده

اگر DHT22 برای همیشه جدا شود، برنامه فعلی آخرین دمای معتبر را تا ابد نشان می‌دهد و ارسال می‌کند؛ این دروغ است. تغییری بده که اگر ۵ خواندن پشت سر هم شکست خورد، tempC و hum دوباره NaN شوند و یک پیام "ERROR: sensor" (فقط یک بار) به topic هشدار برود.

راهنمایی

یک شمارنده failStreak در readSensors: با موفقیت صفر، با شکست یکی زیاد. وقتی دقیقا به ۵ رسید (نه بزرگ‌تر یا مساوی، تا پیام فقط یک بار برود)، مقدارها را NaN کن و publishAlert را صدا بزن. publishAll از قبل با NaN چیزی نمی‌فرستد و نمایشگر «ERR» نشان می‌دهد.

جواب 
// جایگزین تابع readSensors در برنامه نهایی (بخشی از برنامه)
int failStreak = 0;

void readSensors() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) {
    tempC = t; hum = h;
    failStreak = 0;
  } else {
    failStreak++;
    if (failStreak == 5) {                   // دقیقا یک بار
      tempC = NAN; hum = NAN;
      publishAlert("ERROR: sensor");
    }
  }
  int raw = analogRead(PIN_LDR);
  lightPct = map(raw, 4095, 0, 0, 100);
}
  1. موفقیت شمارنده را صفر می‌کند. یعنی فقط شکست‌های پشت سر هم شمرده می‌شوند؛ یک خطای تکی گاه‌به‌گاه عادی است.
  2. در شکست پنجم، اعلام خرابی. مقدارها NaN و یک پیام خطا. شرط == 5 به جای >= 5 یعنی پیام فقط یک بار می‌رود، نه در هر خواندن بعدی؛ همان اصل «بدون اسپم». پنج خواندن یعنی ۱۰ ثانیه، که با یک خطای تصادفی اشتباه گرفته نمی‌شود. publishAlert باید قبل از این تابع تعریف شده باشد (مثل برنامه نهایی که بخش ۵ قبل از استفاده است، یا با یک اعلان پیشاپیش).
تمرین ۳: حالت باتری

نسخه باتری ایستگاه را بساز (بخش «حالت باتری» را ببین): هر ۵ دقیقه بیدار شود، بخواند، روی OLED برای ۳ ثانیه نشان دهد، اگر هشدار شروع یا تمام شد پیام بفرست، هر ۶ بیداری یک بار مقادیر را بفرستد، و بخوابد. دکمه GPIO33 برد را برای نمایش فوری بیدار کند. بعد با فرمول درس ۶.۱ عمر یک باتری ۲۰۰۰ میلی‌آمپر ساعت را تخمین بزن.

راهنمایی

متغیرهای RTC_DATA_ATTR bool alarmOn و RTC_DATA_ATTR uint32_t wakeCount. شرط ارسال مقادیر: wakeCount % 6 == 0. یادآوری هشدار: هر ۲ بیداری (۱۰ دقیقه). برای Wi-Fi از connectWiFiFast() درس ۶.۱ با حد زمانی استفاده کن و فقط وقتی چیزی برای فرستادن داری Wi-Fi را روشن کن. قبل از خواب OLED را با SSD1306_DISPLAYOFF خاموش کن و EXT0 را روی GPIO33 با سطح LOW و بالاکش RTC تنظیم کن. برای بیداری با دکمه، ارسال را رد کن و فقط نمایش بده.

گواهی پایان دوره مستر کلاس ESP32 فارسی

اگر این دوره را خوانده و پروژه‌هایش را خودت ساخته‌ای، حالا می‌توانی:

  • بردهای ESP32 را بشناسی، پین درست را با دلیل انتخاب کنی و از پین‌های خطرناک دوری کنی
  • برنامه بنویسی، آپلود کنی و با Serial Monitor و Wokwi عیب‌یابی کنی
  • ورودی و خروجی دیجیتال و آنالوگ، PWM، و پروتکل‌های I2C، SPI و UART را به کار ببری
  • دستگاهت را به Wi-Fi وصل کنی، وب سرور بسازی و با بلوتوث حرف بزنی
  • با MQTT و ESP-NOW دستگاه‌های اینترنت اشیا بسازی
  • مصرف انرژی را حساب و اندازه‌گیری کنی و دستگاه باتری‌خور طراحی کنی
  • از هوش مصنوعی مثل یک مهندس استفاده کنی: دقیق بپرسی و سخت‌گیرانه بازبینی کنی
  • یک پروژه کامل را از نیازمندی تا آزمایش پذیرش، قدم به قدم بسازی

این «گواهی» روی کاغذ نیست؛ در پروژه‌ای است که روی میزت کار می‌کند. عکسش را بگیر و نگه دار.

قدم‌های بعدی یادگیری

  • ESP-IDF: چارچوب رسمی Espressif که هسته آردوینو روی آن ساخته شده. کنترل کامل‌تر، مدیریت توان پیشرفته، و ابزارهای حرفه‌ای. از راهنمای شروع ESP-IDF شروع کن.
  • FreeRTOS و Taskها: ESP32 دو هسته دارد و زیر هسته آردوینو، FreeRTOS اجرا می‌شود. با xTaskCreatePinnedToCore می‌توانی مثلا شبکه را روی یک هسته و هشدار را روی هسته دیگر اجرا کنی. قدم طبیعی بعد از زمان‌بندی با millis است.
  • طراحی PCB: وقتی پروژه روی برد بورد کار کرد، نسخه واقعی و قابل اعتماد آن روی یک برد مدار چاپی است؛ بدون سیم شل، کوچک‌تر و با رگولاتور کم‌مصرف برای باتری. آموزش فارسی طراحی PCB با KiCad 9 در همین سایت را ببین.
  • امنیت اینترنت اشیا: MQTT روی TLS (پورت ۸۸۸۳)، بروکر خصوصی، و به‌روزرسانی نرم‌افزار از راه دور (OTA).
  • تراشه‌های جدیدتر: ESP32-S3 (هوش مصنوعی روی دستگاه، USB مستقیم) و ESP32-C6 (Wi-Fi 6 و Thread/Zigbee) در درس ۱.۲ معرفی شدند.
خلاصه درس در سه خط

پروژه بزرگ را با نیازمندی روشن (PRD)، معماری و جدول پین با دلیل شروع کن و در گام‌های کوچک آزمایش‌شده بساز: سنسور، نمایشگر، هشدار، Wi-Fi، MQTT، ادغام. برنامه نهایی با توابع جدا و زمان‌بندی millis() هیچ‌وقت منتظر شبکه نمی‌ماند؛ هشدار با هیسترزیس نوسان نمی‌کند و با محدودیت نرخ اسپم نمی‌فرستد. قبل از «تمام شد»، همه آزمایش‌های پذیرش را بگذران و سنسور را از گرمای ESP32 دور نصب کن.
