تا این‌جا هر قطعه یک سیم جدا داشت و ESP32 فقط «ولتاژ» آن را می‌خواند یا می‌نوشت. ولی نمایشگر، کارت حافظه و GPS «حرف» می‌زنند: عدد، متن و دستور رد و بدل می‌کنند. برای این کار سه زبان استاندارد هست: I2C، SPI و UART. در این درس هر سه را از پایه یاد می‌گیری و با هر کدام یک پروژه واقعی می‌سازی. این طولانی‌ترین درس فصل است؛ بخش به بخش جلو برو و هر بخش را قبل از بعدی امتحان کن.

تصویر بزرگ: چرا «پروتکل»؟

پروتکل یعنی «قرارداد گفت‌وگو»: چند سیم داریم، چه کسی اول حرف می‌زند، هر بیت چقدر طول می‌کشد و دستگاه‌ها چطور همدیگر را صدا می‌زنند. هر سه پروتکل این درس سریال هستند: بیت‌ها را یکی‌یکی پشت سر هم روی یک سیم می‌فرستند، نه هشت‌تا هشت‌تا روی هشت سیم. این کار سیم‌ها را کم می‌کند.

سه جور گفت‌وگو در زندگی

UART مثل تلفن بین دو نفر است: هر کدام یک دهان (TX) و یک گوش (RX) دارد و فقط همین دو نفر با هم حرف می‌زنند. I2C مثل کلاس درس است: یک معلم (Master) و چند شاگرد روی یک خط مشترک؛ معلم اسم (آدرس) هر شاگرد را صدا می‌زند و فقط همان جواب می‌دهد. SPI مثل معلمی است که با هر شاگرد یک سیم «دست بلند کن» جدا (CS) دارد؛ سریع‌تر است چون لازم نیست اسم صدا بزند، ولی به ازای هر شاگرد یک سیم بیشتر لازم دارد.

I2C: دو سیم، ده‌ها دستگاه

I2C (بخوان «آی‌تو‌سی» یا «آی‌اسکوئرسی») دو سیم دارد: SDA برای داده و SCL برای ساعت. ESP32 نقش Master (رئیس) را دارد: فقط او می‌تواند گفت‌وگو را شروع کند و ساعت را می‌سازد. دستگاه‌ها (Slave یا Target) فقط وقتی آدرسشان صدا زده شود جواب می‌دهند.

گفت‌وگوی I2C قدم به قدم

  participant M as ESP32 (Master)
  participant O as OLED (0x3C)
  participant B as BME280 (0x76)

  O-->>M: ACK (I am here)
  Note over B: address does not match, stays silent

  M->>O: STOP

ESP32 اول آدرس را روی خط می‌فرستد. همه دستگاه‌ها آن را می‌شنوند، ولی فقط دستگاهی که آدرسش همین است با یک بیت «ACK» (بله، این‌جام) جواب می‌دهد. اگر هیچ‌کس جواب ندهد، ESP32 «NACK» می‌بیند و می‌فهمد دستگاهی با این آدرس نیست. همین ترفند، پایه «اسکنر I2C» است.

چرا I2C به مقاومت Pull-up نیاز دارد؟

در I2C هیچ دستگاهی سیم را به ۳٫۳ ولت «هل» نمی‌دهد؛ دستگاه‌ها فقط می‌توانند سیم را به GND «بکشند» (به این «Open-Drain» می‌گویند). پس یک مقاومت Pull-up (معمولا ۴٫۷ یا ۱۰ کیلو) باید سیم را در حالت عادی به ۳٫۳ ولت برگرداند؛ همان ایده درس ۳.۱. خبر خوب: تقریبا همه ماژول‌های آماده (OLED، BME280 و…) این مقاومت‌ها را روی خودشان دارند، پس معمولا لازم نیست چیزی اضافه کنی. این طراحی باعث می‌شود اگر دو دستگاه هم‌زمان بخواهند حرف بزنند، اتصال کوتاه پیش نیاید.

ماژول ۵ ولتی و I2C

اگر یک ماژول I2C را با 5V تغذیه کنی و Pull-up های روی آن به همان ۵ ولت وصل باشند، خطوط SDA و SCL ۵ ولت می‌شوند و به ESP32 آسیب می‌زنند. OLED و BME280 را همیشه با 3V3 تغذیه کن. برای ماژول‌هایی که حتما ۵ ولت می‌خواهند، مبدل سطح (Level Shifter) لازم است (درس ۱.۴).

اسکنر I2C: اولین قدم با هر ماژول جدید

قبل از هر کتابخانه‌ای، اول مطمئن شو ESP32 دستگاه را «می‌بیند». این برنامه همه آدرس‌های ممکن را یکی‌یکی صدا می‌زند و آن‌هایی را که جواب می‌دهند چاپ می‌کند.

// اسکنر I2C: چه دستگاه‌هایی روی باس هستند؟
#include <Wire.h>

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);                 // SDA=21, SCL=22 (پیش‌فرض ESP32)
  Serial.println("I2C scanner...");
}

void loop() {
  int found = 0;
  for (uint8_t addr = 1; addr < 127; addr++) {
    Wire.beginTransmission(addr);     // «کسی با این آدرس هست؟»
    uint8_t err = Wire.endTransmission();
    if (err == 0) {                   // 0 = جواب داد (ACK)
      Serial.printf("Found device at 0x%02X\n", addr);
      found++;
    }
  }
  if (found == 0) Serial.println("No I2C devices found. Check wiring!");
  Serial.println("----");
  delay(5000);
}
  1. کتابخانه Wire. کتابخانه داخلی I2C در آردوینو. نصب لازم ندارد. اسمش از «سیم» می‌آید چون I2C را «Two-Wire» هم می‌گویند.
  2. Wire.begin(SDA، SCL). باس I2C را روی پین‌های ۲۱ و ۲۲ راه می‌اندازد و ESP32 را Master می‌کند. در ESP32 تقریبا هر پینی می‌تواند I2C باشد (ماتریس GPIO). ۲۱ و ۲۲ پیش‌فرض‌اند و Wire.begin() خالی هم همین‌ها را استفاده می‌کند؛ ولی نوشتن صریح پین‌ها باعث می‌شود اگر روزی پین دیگری لازم شد، بدانی کجا را عوض کنی.
  3. حلقه روی همه آدرس‌ها. از ۱ تا ۱۲۶. آدرس I2C هفت بیتی است (۰ تا ۱۲۷)؛ آدرس ۰ برای «همه» (General Call) و ۱۲۷ و چند آدرس دیگر رزرو هستند. uint8_t یعنی عدد ۸ بیتی مثبت (۰ تا ۲۵۵).
  4. در زدن. beginTransmission آدرس را آماده می‌کند و endTransmission واقعا آن را می‌فرستد و نتیجه را برمی‌گرداند. بدون فرستادن هیچ داده‌ای فقط می‌پرسیم «هستی؟». این کار برای هیچ دستگاهی ضرر ندارد.
  5. نتیجه ۰ یعنی ACK. آدرس به صورت هگزادسیمال چاپ می‌شود؛ %02X یعنی «مبنای ۱۶، دو رقمی، با حروف بزرگ». دیتاشیت‌ها و کتابخانه‌ها آدرس را همیشه هگز می‌نویسند (0x3C)، پس ما هم همین‌طور چاپ می‌کنیم تا مستقیم قابل مقایسه باشد. کدهای خطای دیگر: ۲ یعنی NACK برای آدرس (کسی نیست).
  6. گزارش و تکرار هر ۵ ثانیه. تکرار باعث می‌شود بتوانی وسط کار سیم را درست کنی و بدون ریست کردن نتیجه را ببینی.

نمایشگر OLED ی ۰٫۹۶ اینچ (SSD1306)

این نمایشگر کوچک ۱۲۸ × ۶۴ پیکسل دارد و هر پیکسل خودش نور می‌دهد (پس نور پس‌زمینه ندارد، کنتراستش عالی است و کم‌مصرف است). تراشه راه‌انداز آن SSD1306 است و نسخه ۴ پایه آن با I2C کار می‌کند. آدرس تقریبا همیشه 0x3C است؛ بعضی مدل‌ها با جابه‌جا کردن یک مقاومت پشت برد 0x3D می‌شوند. (پشت برد گاهی «0x78» نوشته شده؛ این همان 0x3C است که یک بیت به چپ شیفت داده شده، یعنی آدرس ۸ بیتی. در کد همیشه 0x3C بنویس.)

ترتیب پایه‌ها را از روی خود ماژول بخوان

بعضی OLED ها GND VCC SCL SDA هستند و بعضی VCC GND SCL SDA. جابه‌جا وصل کردن VCC و GND می‌تواند ماژول را بسوزاند. قبل از وصل کردن، نوشته کنار پایه‌ها را بخوان، نه عکس اینترنت را.

کتابخانه‌ها: از Sketch › Include Library › Manage Libraries… عبارت SSD1306 را جست‌وجو کن و Adafruit SSD1306 by Adafruit را نصب کن (نتیجه‌های شبیه مثل «ESP8266 and ESP32 OLED driver for SSD1306» از ThingPulse دستورهای دیگری دارند و با کد این درس کار نمی‌کنند). هنگام نصب پنجره‌ای باز می‌شود که می‌پرسد وابستگی‌ها (Adafruit GFX Library و Adafruit BusIO) را هم نصب کند؛ بگو Install All. اگر آن پنجره را بستی، این دو را جدا با همین اسم‌ها نصب کن؛ وگرنه خطای Adafruit_GFX.h: No such file or directory می‌گیری. کتابخانه SSD1306 با تراشه صحبت می‌کند و GFX ابزار رسم (متن، خط، مستطیل، دایره) را می‌دهد.

دستگاه مختصات صفحه

#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

const int SCREEN_W = 128;
const int SCREEN_H = 64;
Adafruit_SSD1306 display(SCREEN_W, SCREEN_H, &Wire, -1);   // -1 = بدون پین ریست

int counter = 0;

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);
  if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    Serial.println("SSD1306 not found!");
    while (true) delay(1000);        // این‌جا بایست
  }
  display.clearDisplay();
  display.setTextColor(SSD1306_WHITE);
}

void loop() {
  display.clearDisplay();             // ۱) بافر را پاک کن
  display.setTextSize(1);             // حروف 6×8 پیکسل
  display.setCursor(0, 0);
  display.println("Hello ESP32!");
  display.setTextSize(2);             // حروف 12×16 پیکسل
  display.setCursor(0, 24);
  display.print("n = ");
  display.println(counter);
  display.drawRect(0, 50, 128, 14, SSD1306_WHITE);                 // قاب نوار
  display.fillRect(2, 52, (counter % 25) * 5, 10, SSD1306_WHITE);  // نوار پیشرفت
  display.display();                  // ۲) بافر را روی صفحه بفرست
  counter++;
  delay(500);
}
  1. سه کتابخانه. Wire برای I2C، GFX برای رسم، SSD1306 برای خود نمایشگر. این تقسیم کار باعث می‌شود همان دستورهای رسم GFX را روی ده‌ها نمایشگر دیگر (TFT رنگی و…) هم استفاده کنی.
  2. ساختن شیء نمایشگر. اندازه صفحه، باس I2C (&Wire) و پین ریست (-1 یعنی ندارد). علامت & یعنی «آدرس» شیء Wire؛ به کتابخانه می‌گوییم از کدام باس استفاده کند (ESP32 دو باس I2C دارد). ماژول‌های ۴ پایه پین ریست ندارند.
  3. راه‌اندازی با بررسی خطا. begin آدرس 0x3C را می‌گیرد؛ SSD1306_SWITCHCAPVCC یعنی ولتاژ بالای پنل را مدار داخلی خود ماژول بسازد. اگر نشد، پیام می‌دهد و در یک حلقه بی‌پایان می‌ایستد. بدون این بررسی، برنامه با نمایشگر ناموجود ادامه می‌داد و تو فقط یک صفحه سیاه می‌دیدی بدون هیچ سرنخی. begin همچنین ۱ کیلوبایت RAM برای بافر (۱۲۸ × ۶۴ ÷ ۸) رزرو می‌کند.
  4. رنگ متن. SSD1306 تک‌رنگ است: SSD1306_WHITE یعنی پیکسل روشن (رنگ واقعی بسته به مدل سفید، آبی یا زرد است). پیش‌فرض رنگ متن در GFX ممکن است با پس‌زمینه یکی باشد؛ بدون این خط متن نامرئی می‌شود. یک بار در setup کافی است.
  5. مرحله ۱: پاک کردن بافر. همه دستورهای رسم روی یک «بوم» در RAM ی ESP32 نقاشی می‌کنند، نه مستقیم روی صفحه. اگر پاک نکنی، عدد جدید روی عدد قبلی نوشته می‌شود و درهم می‌شود.
  6. متن با اندازه و مکان. setTextSize بزرگی، setCursor(x, y) گوشه بالا چپ حرف اول، و print/println خود متن یا عدد. دقیقا مثل Serial؛ چون کلاس نمایشگر از Print ارث می‌برد، همان print و println را دارد. y=24 را انتخاب کردیم تا زیر خط اول (ارتفاع ۸) فاصله داشته باشد.
  7. شکل‌ها. drawRect(x, y, عرض، ارتفاع، رنگ) قاب و fillRect مستطیل توپر. عرض نوار با (counter % 25) * 5 از ۰ تا ۱۲۰ پیکسل تغییر می‌کند. % باقیمانده تقسیم است، پس عدد بعد از ۲۴ به ۰ برمی‌گردد و نوار از اول پر می‌شود. ۱۲۰ + ۲ کمتر از عرض داخلی قاب است، پس از قاب بیرون نمی‌زند.
  8. مرحله ۲: display(). کل بافر را از طریق I2C به نمایشگر می‌فرستد. فراموش کردن این خط رایج‌ترین دلیل «صفحه خالی» است. ارسال ۱۰۲۴ بایت در ۴۰۰ کیلوهرتز حدود ۲۵ میلی‌ثانیه طول می‌کشد، پس بهتر است همه تغییرات را اول در بافر انجام بدهی و یک بار display کنی.

در Wokwi از زبانه Library Manager کتابخانه Adafruit SSD1306 را اضافه کن (GFX را خودش می‌آورد؛ اگر خطای Adafruit_GFX دیدی، آن را هم جدا اضافه کن). کد اسکنر I2C را هم می‌توانی در همین مدار اجرا کنی تا 0x3C را ببینی.

DHT22: دما و رطوبت (و یک اعتراف صادقانه)

DHT22 (که با اسم AM2302 هم فروخته می‌شود) دما را از ۴۰− تا ۸۰ درجه با دقت حدود ۰٫۵± درجه و رطوبت نسبی را از ۰ تا ۱۰۰٪ با دقت حدود ۲ تا ۵٪ اندازه می‌گیرد. ارزان و محبوب است.

DHT22 یک سنسور I2C نیست

در برنامه این دوره DHT22 کنار I2C آمده، چون معمولا با OLED ی I2C استفاده می‌شود. ولی باید صادق باشیم: DHT22 از یک پروتکل اختصاصی تک‌سیمه استفاده می‌کند که نه I2C است و نه پروتکل 1-Wire شرکت Dallas. ESP32 یک پالس شروع می‌فرستد و سنسور با ۴۰ بیت جواب می‌دهد که مقدار هر بیت با طول پالس HIGH مشخص می‌شود (حدود ۲۶ تا ۲۸ میکروثانیه = ۰، حدود ۷۰ میکروثانیه = ۱). کتابخانه این زمان‌ها را دقیق اندازه می‌گیرد. نتیجه عملی: DHT22 سیم مخصوص به خودش را لازم دارد و نمی‌تواند روی SDA/SCL با بقیه شریک شود.

اگر یک سنسور محیطی واقعا I2C می‌خواهی، BME280 را ببین: دما، رطوبت و فشار هوا، دقیق‌تر و سریع‌تر، روی همان دو سیم OLED با آدرس 0x76 یا 0x77. (مراقب باش: BMP280 ی ارزان‌تر شبیه آن است ولی رطوبت ندارد.)

پایه‌های DHT22 چهار پایه (از چپ، وقتی مشبک رو به توست): ۱ = VCC، ۲ = DATA، ۳ = وصل نیست (NC)، ۴ = GND. خط DATA مثل I2C «Open-Drain» است و یک مقاومت Pull-up ۱۰ کیلو بین DATA و VCC لازم دارد. ماژول‌های ۳ پایه (سنسور سفید روی یک برد کوچک) این مقاومت را خودشان دارند؛ پشت برد یک مقاومت SMD ریز با کد 103 (۱۰ کیلو) یا 472 (۴٫۷ کیلو) می‌بینی، پس مقاومت بیرونی نگذار. ترتیب پایه‌های ماژول‌ها یکسان نیست (+ out − یا VCC DATA GND یا حتی − + S)؛ نوشته روی برد را بخوان. DHT22 با ۳٫۳ تا ۶ ولت کار می‌کند؛ ما آن را با 3V3 تغذیه می‌کنیم تا خط DATA هرگز بیش از ۳٫۳ ولت نشود.

#include <DHT.h>

const int DHT_PIN = 13;
DHT dht(DHT_PIN, DHT22);         // نوع سنسور: DHT22 (AM2302)

void setup() {
  Serial.begin(115200);
  dht.begin();
}

void loop() {
  delay(2000);                     // DHT22 حداکثر هر 2 ثانیه یک خواندن
  float h = dht.readHumidity();
  float t = dht.readTemperature(); // سلسیوس
  if (isnan(h) || isnan(t)) {
    Serial.println("DHT read failed!");
    return;                        // این دور را رها کن
  }
  Serial.printf("T=%.1f C  H=%.1f %%\n", t, h);
}
  1. کتابخانه DHT. در Library Manager عبارت DHT22 را جست‌وجو کن و DHT sensor library by Adafruit را نصب کن. پنجره وابستگی‌ها Adafruit Unified Sensor را پیشنهاد می‌کند؛ Install All را بزن. (کتابخانه‌های هم‌خانواده مثل «DHT sensor library for ESPx» یا «DHTesp» دستورهای دیگری دارند؛ آن‌ها را انتخاب نکن.) پیاده‌سازی زمان‌بندی میکروثانیه‌ای پروتکل کار ساده‌ای نیست؛ کتابخانه جاافتاده آن را انجام می‌دهد.
  2. شیء سنسور روی GPIO13. نوع سنسور را DHT22 می‌گوییم. DHT11 و DHT22 قالب داده متفاوت دارند؛ نوع اشتباه یعنی اعداد بی‌معنی. GPIO13 پایه ثابت DHT22 در این دوره است: GPIO4 برای LED وضعیت کنار گذاشته شده، پس اگر LED درس ۳.۱ هنوز روی بردبوردت است، می‌توانی همان‌جا بگذاری‌اش.
  3. صبر ۲ ثانیه‌ای. DHT22 هر ۲ ثانیه یک اندازه‌گیری جدید انجام می‌دهد. خواندن سریع‌تر یا خطا می‌دهد یا عدد قبلی را تکرار می‌کند. (کتابخانه خودش هم خواندن‌های زیر ۲ ثانیه را با عدد قبلی جواب می‌دهد.)
  4. خواندن رطوبت و دما. هر دو float (عدد اعشاری) هستند. readTemperature(true) فارنهایت می‌دهد؛ بدون ورودی سلسیوس است.
  5. بررسی NaN. اگر خواندن شکست بخورد، کتابخانه به جای عدد مقدار ویژه NaN (Not a Number) برمی‌گرداند. isnan آن را تشخیص می‌دهد و return بقیه loop را رها می‌کند. بدون این بررسی، nan روی صفحه و در لاگ ذخیره می‌شد یا در محاسبه‌ها همه چیز را NaN می‌کرد. قانون حرفه‌ای: هر عدد سنسور را قبل از استفاده اعتبارسنجی کن.
  6. چاپ با یک رقم اعشار. %.1f یعنی عدد اعشاری با یک رقم بعد از ممیز. دقت سنسور حدود نیم درجه است؛ چاپ ۲۵٫۳۴۷۱ درجه فقط دقت دروغین نشان می‌دهد.

پروژه: ایستگاه هواشناسی کوچک (DHT22 روی OLED)

// ایستگاه هواشناسی کوچک: DHT22 روی OLED
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>

Adafruit_SSD1306 display(128, 64, &Wire, -1);
DHT dht(13, DHT22);

unsigned long lastRead = 0;

void showMessage(const char *msg) {
  display.clearDisplay();
  display.setTextSize(1);
  display.setCursor(0, 0);
  display.println(msg);
  display.display();
}

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);
  if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    Serial.println("OLED not found!");
    while (true) delay(1000);
  }
  display.setTextColor(SSD1306_WHITE);
  dht.begin();
  showMessage("Waiting for DHT22...");
}

void loop() {
  if (millis() - lastRead < 2000) return;   // هنوز ۲ ثانیه نشده
  lastRead = millis();

  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (isnan(t) || isnan(h)) {
    showMessage("DHT22 read error!");
    Serial.println("DHT22 read error");
    return;
  }

  display.clearDisplay();
  display.setTextSize(1);
  display.setCursor(0, 0);
  display.println("Temperature");
  display.setTextSize(2);
  display.setCursor(0, 12);
  display.printf("%.1f C", t);
  display.setTextSize(1);
  display.setCursor(0, 36);
  display.println("Humidity");
  display.setTextSize(2);
  display.setCursor(0, 48);
  display.printf("%.1f %%", h);
  display.display();

  Serial.printf("T=%.1f C  H=%.1f %%\n", t, h);
}
  1. چهار کتابخانه با هم. همان کتابخانه‌های دو برنامه قبلی. ترکیب پروژه‌ها در میکروکنترلر معمولا همین است: include ها و شیءها کنار هم، setup ها پشت سر هم، loop ها در هم.
  2. دو شیء: نمایشگر و سنسور. این بار اعداد را مستقیم نوشتیم (۱۲۸، ۶۴، ۱۳). برای کوتاهی؛ در پروژه بزرگ‌تر همان ثابت‌های نام‌دار بهترند.
  3. تابع کمکی showMessage. یک متن کوچک را در بالای صفحه نشان می‌دهد. const char *msg یعنی «یک متن ثابت». پیام «منتظر باش» و «خطا» هر دو همین کار را لازم دارند؛ یک تابع، دو استفاده. نمایش خطا روی خود دستگاه مهم است، چون دستگاه نهایی به کامپیوتر وصل نیست که Serial را ببینی.
  4. زمان‌بندی با millis و return. اگر ۲ ثانیه نگذشته، فورا از loop برگرد. این یک شکل کوتاه از الگوی millis درس ۳.۱ است: «نگهبان در ورودی». loop آزاد می‌ماند و بعدا می‌توانی دکمه یا کار دیگری را قبل از این خط اضافه کنی.
  5. خواندن و اعتبارسنجی. در صورت خطا، پیام روی OLED و Serial. صفحه نباید عدد قدیمی را طوری نشان بدهد که انگار تازه است؛ کاربر باید بفهمد سنسور مشکل دارد.
  6. چیدمان صفحه. عنوان کوچک (اندازه ۱) و عدد بزرگ (اندازه ۲) برای دما در بالا و رطوبت در پایین. display.printf مثل Serial.printf کار می‌کند. مختصات y را حساب کردیم: عنوان در y=0 (ارتفاع ۸)، عدد در y=12 (ارتفاع ۱۶ تا y=28)، عنوان دوم در y=36، عدد دوم در y=48 تا y=64، دقیقا لبه پایین صفحه. همیشه جمع ارتفاع‌ها را با ۶۴ مقایسه کن.
  7. گزارش سریال. نمایشگر برای کاربر، Serial برای تو هنگام عیب‌یابی.

دو دستگاه روی یک باس: اضافه کردن BME280

جادوی واقعی I2C این‌جاست: دستگاه دوم هیچ پین تازه‌ای نمی‌خواهد. BME280 به همان سیم‌های SDA و SCL ی OLED وصل می‌شود (روی بردبورد کافی است SDA هر دو ماژول را در یک ردیف بگذاری و SCL را هم همین‌طور). ESP32 با هر کدام از طریق آدرسش حرف می‌زند: OLED با 0x3C و BME280 با 0x76 (یا بسته به ماژول 0x77). مثل دو واحد در یک ساختمان: یک خیابان، دو پلاک. این بخش اختیاری است؛ اگر BME280 داری، جایگزین دقیق‌تر DHT22 است.

کتابخانه: در Library Manager عبارت BME280 را جست‌وجو کن و Adafruit BME280 Library را نصب کن (برای وابستگی‌ها Install All را بزن).

// دو دستگاه روی یک باس I2C: OLED (0x3C) + BME280 (0x76)
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <Adafruit_BME280.h>

Adafruit_SSD1306 display(128, 64, &Wire, -1);
Adafruit_BME280 bme;

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);                       // یک باس برای هر دو دستگاه
  if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) Serial.println("OLED not found!");
  if (!bme.begin(0x76, &Wire)) Serial.println("BME280 not found! Try 0x77");
  display.setTextColor(SSD1306_WHITE);
}

void loop() {
  float t = bme.readTemperature();          // درجه سانتی‌گراد
  float h = bme.readHumidity();             // %
  float p = bme.readPressure() / 100.0;     // Pa -> hPa
  display.clearDisplay();
  display.setTextSize(1);
  display.setCursor(0, 0);
  display.printf("T: %.1f C\nH: %.1f %%\nP: %.0f hPa", t, h, p);
  display.display();
  Serial.printf("T=%.1f C  H=%.1f %%  P=%.0f hPa\n", t, h, p);
  delay(2000);
}
  1. کتابخانه BME280. یک include بیشتر؛ کتابخانه‌های OLED همان‌طور می‌مانند. هر دستگاه کتابخانه خودش را دارد، ولی همه زیر کار از همان باس Wire استفاده می‌کنند.
  2. دو شیء. نمایشگر و سنسور. به هر دو همان باس Wire داده می‌شود؛ چیزی که آن‌ها را از هم جدا می‌کند آدرس است.
  3. یک Wire.begin برای همه. باس یک بار راه می‌افتد و همه دستگاه‌های روی آن شریکش هستند.
  4. هر دستگاه با آدرس خودش شروع می‌شود. اگر BME280 پیدا نشود، پیام آدرس دیگر را پیشنهاد می‌کند. خیلی از بردهای BME280 آدرس 0x76 دارند و بعضی 0x77. اسکنر می‌گوید مال تو کدام است. به جای توقف، خطا چاپ می‌کنیم تا ببینی کدام یک از دو دستگاه غایب است.
  5. سه خواندن. دما، رطوبت و فشار هوا که از پاسکال به هکتوپاسکال تبدیل می‌شود (hPa، واحد گزارش‌های هواشناسی: حدود ۱۰۱۳ در سطح دریا). برخلاف DHT22، BME280 بین خواندن‌ها ۲ ثانیه وقت نمی‌خواهد و فشار هوا را هم می‌دهد؛ برای روند آب‌وهوا یا حتی ارتفاع به کار می‌آید.
  6. سه خط روی OLED. \n داخل printf روی نمایشگر خط تازه شروع می‌کند. همان چرخه clear ← draw ← display. ESP32 فقط از حرف زدن با 0x76 به حرف زدن با 0x3C رفت و هیچ‌کدام از دو دستگاه ناراحت نشدند.

در زمان نوشتن این درس Wokwi قطعه BME280 ندارد، پس این یکی را با سخت‌افزار واقعی امتحان کن.

SPI: سریع، با یک سیم انتخاب برای هر دستگاه

SPI چهار سیم دارد:

  • SCK (ساعت): ESP32 می‌سازد؛ هر تیک یک بیت.
  • MOSI (Master Out, Slave In): داده از ESP32 به دستگاه.
  • MISO (Master In, Slave Out): داده از دستگاه به ESP32.
  • CS (Chip Select، گاهی SS): وقتی ESP32 این سیم را LOW کند، یعنی «با تو هستم». هر دستگاه CS جدای خودش را دارد.

چون داده در دو سیم جدا هم‌زمان رفت و برگشت می‌کند (Full-Duplex) و آدرس‌دهی لازم نیست، SPI خیلی سریع‌تر از I2C است. برای همین کارت حافظه و نمایشگرهای رنگی (که حجم داده زیاد دارند) SPI هستند. ESP32 کلاسیک دو باس SPI آزاد دارد: VSPI (پیش‌فرض آردوینو، پین‌های ۱۸، ۱۹، ۲۳ و ۵) و HSPI.

ماژول کارت microSD

سه تله رایج قبل از شروع

۱) ولتاژ ماژول: کارت SD فقط ۳٫۳ ولت است. ماژول‌های آبی رایج (با تراشه رگولاتور AMS1117 و مبدل سطح 74LVC125 روی برد) برای ورودی VCC شان ۵ ولت می‌خواهند؛ اگر 3V3 بدهی، بعد از رگولاتور ولتاژ کافی نمی‌ماند و کارت گاهی کار می‌کند و گاهی نه. ماژول‌های ساده بدون رگولاتور باید 3V3 بگیرند و ۵ ولت آن‌ها و کارت را می‌سوزاند. روی برد ماژول را نگاه کن: تراشه سه پایه رگولاتور دارد؟ ← 5V. ندارد؟ ← 3V3.

۲) فرمت: کتابخانه SD ی ESP32 کارت FAT32 (یا FAT16) می‌خواهد. کارت‌های ۶۴ گیگ به بالا معمولا exFAT فرمت شده‌اند و کار نمی‌کنند. ساده‌ترین راه: کارت ۴ تا ۳۲ گیگ، فرمت FAT32 با ابزار رسمی SD Card Formatter.

۳) CS: شماره پین CS در کد باید دقیقا همان پینی باشد که سیم CS به آن وصل است (این‌جا GPIO5).

// ثبت داده روی کارت microSD با SPI (VSPI)
#include <SPI.h>
#include <SD.h>

const int SD_CS = 5;              // CS؛ بقیه: SCK=18, MISO=19, MOSI=23
const char *LOG_FILE = "/log.csv";

void setup() {
  Serial.begin(115200);
  if (!SD.begin(SD_CS)) {
    Serial.println("SD mount failed! (wiring, CS, FAT32?)");
    while (true) delay(1000);
  }
  uint8_t type = SD.cardType();
  if (type == CARD_NONE) {
    Serial.println("No SD card inserted");
    while (true) delay(1000);
  }
  Serial.printf("Card size: %llu MB\n", SD.cardSize() / (1024 * 1024));

  if (!SD.exists(LOG_FILE)) {                 // فایل نیست؟ سرتیتر بنویس
    File f = SD.open(LOG_FILE, FILE_WRITE);
    f.println("millis,value");
    f.close();
  }

  File f = SD.open(LOG_FILE, FILE_APPEND);    // به ته فایل اضافه کن
  if (f) {
    f.printf("%lu,%d\n", millis(), 42);
    f.close();                                // بستن = ذخیره واقعی
    Serial.println("Line appended.");
  }

  f = SD.open(LOG_FILE, FILE_READ);           // خواندن کل فایل
  Serial.println("---- log.csv ----");
  while (f.available()) Serial.write(f.read());
  f.close();
}

  2. پین CS و اسم فایل. اسم فایل در ESP32 باید با / شروع شود. کتابخانه SD ی ESP32 مسیر کامل از ریشه کارت می‌خواهد؛ "log.csv" بدون اسلش خطا می‌دهد. پسوند CSV یعنی «مقادیر جداشده با کاما» که اکسل و گوگل‌شیت مستقیم باز می‌کنند.
  3. SD.begin(CS). باس SPI پیش‌فرض (18/19/23) را راه می‌اندازد، با کارت صحبت می‌کند و سیستم فایل را «سوار» (Mount) می‌کند. اگر شکست خورد، سه مظنون اصلی را در پیام نوشتیم: سیم‌کشی، CS و فرمت. پیام خطای خوب نصف عیب‌یابی است.
  4. نوع و اندازه کارت. cardType نوع (MMC، SD، SDHC) را می‌دهد و cardSize اندازه را به بایت (عدد ۶۴ بیتی؛ برای همین %llu). دیدن اندازه درست (مثلا ۱۵۰۰۰ مگابایت برای کارت ۱۶ گیگ) ثابت می‌کند ارتباط SPI کاملا سالم است.
  5. فایل جدید؟ سرتیتر. اگر فایل وجود ندارد، با FILE_WRITE ساخته می‌شود و خط اول (نام ستون‌ها) نوشته می‌شود. FILE_WRITE در ESP32 فایل موجود را از اول بازنویسی می‌کند (پاک می‌کند). برای همین فقط وقتی فایل نیست از آن استفاده می‌کنیم.
  6. اضافه کردن یک خط. FILE_APPEND فایل را باز می‌کند و به ته آن اضافه می‌کند. خط CSV: زمان و یک مقدار نمونه (۴۲). if (f) یعنی «اگر فایل باز شد». در یک لاگر واقعی به جای ۴۲ دمای DHT22 را می‌نویسی (تمرین ۲). close() ضروری است: داده اول در بافر RAM جمع می‌شود و فقط با close (یا flush) واقعا روی کارت نوشته می‌شود. قطع برق قبل از close = داده گم‌شده.
  7. خواندن و چاپ کل فایل. تا وقتی بایتی مانده (available)، یکی بخوان و عینا به Serial بفرست. این ثابت می‌کند نوشتن واقعا انجام شده. Serial.write بایت را همان‌طور که هست می‌فرستد (برخلاف print که عدد را به متن تبدیل می‌کند).
  8. loop خالی. همه کار یک بار در setup انجام شد. هر بار دکمه EN را بزنی، یک خط جدید اضافه می‌شود.

UART: قدیمی‌ترین و ساده‌ترین

تو از روز اول با UART کار کرده‌ای: Serial.print از طریق UART0 (پین‌های TX0=GPIO1 و RX0=GPIO3) به تراشه USB برد و از آن‌جا به کامپیوتر می‌رود. UART ساعت مشترک ندارد؛ به جایش دو طرف از قبل روی یک سرعت (Baud Rate) توافق می‌کنند، مثلا ۹۶۰۰ بیت در ثانیه. هر بایت با یک بیت شروع (Start) و یک بیت پایان (Stop) بسته‌بندی می‌شود تا گیرنده بفهمد کجا شروع و تمام می‌شود.

TX به RX: دهان به گوش

TX (فرستنده) یک دستگاه باید به RX (گیرنده) دستگاه دیگر برود، و برعکس. اگر TX را به TX وصل کنی، مثل این است که دو نفر دهان به دهان حرف بزنند و هیچ‌کدام نشنوند. این «ضربدری» بودن رایج‌ترین اشتباه UART است.

Serial2: یک UART آزاد برای ماژول‌ها

ESP32 کلاسیک سه UART دارد: Serial (UART0، مشغول USB)، Serial1 و Serial2. به لطف ماتریس GPIO، هر UART را می‌توان به تقریبا هر پینی وصل کرد. روی خیلی از بردها کنار GPIO16 و GPIO17 نوشته شده RX2 و TX2 و بیشتر آموزش‌ها همین‌ها را استفاده می‌کنند؛ ما هم برای GPS از Serial2 روی ۱۶ و ۱۷ استفاده می‌کنیم.

پین‌ها را همیشه صریح بنویس

در هسته ۳، اگر Serial2.begin(9600) را بدون پین صدا بزنی، پیش‌فرض ESP32 کلاسیک GPIO4 و GPIO25 است، نه ۱۶ و ۱۷ (پیش‌فرض Serial1 هم GPIO26 و GPIO27 است). این تغییر برای دور ماندن از پین‌های PSRAM در ماژول‌های WROVER انجام شده. کدهای قدیمی که پین نمی‌دهند و GPS را روی ۱۶/۱۷ فرض می‌کنند، در هسته ۳ هیچ داده‌ای نمی‌گیرند. پس همیشه چهار ورودی کامل بنویس:

Serial2.begin(9600, SERIAL_8N1, 16, 17);   // baud, قالب, RX, TX
  1. چهار ورودی. سرعت ۹۶۰۰، قالب 8N1، پین RX ی ESP32 (۱۶) و پین TX ی ESP32 (۱۷). ترتیب «اول RX، بعد TX» است و از دید ESP32 نوشته می‌شود. ۹۶۰۰ سرعت پیش‌فرض کارخانه NEO-6M است. (روی ماژول‌های WROVER، GPIO16 و ۱۷ به PSRAM وصل‌اند؛ آن‌جا مثلا ۴ و ۲۵ را انتخاب کن و سیم‌کشی را هم عوض کن.)

UART را بدون هیچ ماژولی امتحان کن: آزمایش Loopback

قبل از این که GPS بخری یا سیم‌کشی کنی، می‌توانی کار کردن UART را با یک سیم جامپر ببینی. GPIO17 (TX2) را مستقیم به GPIO16 (RX2) وصل کن. حالا هر چه Serial2 بگوید، خود Serial2 هم می‌شنود؛ مثل حرف زدن در لوله‌ای که سر دیگرش کنار گوش خودت است. این در Wokwi هم کار می‌کند، پس اولین تمرین UART عالی است.

// Loopback ی UART: Serial2 با خودش حرف می‌زند (یک سیم: GPIO17 -> GPIO16)
const int RX2_PIN = 16;
const int TX2_PIN = 17;
unsigned long lastSend = 0;
int counter = 0;

void setup() {
  Serial.begin(115200);
  Serial2.begin(9600, SERIAL_8N1, RX2_PIN, TX2_PIN);
  Serial.println("Loopback test: GPIO17 -> GPIO16");
}

void loop() {
  if (millis() - lastSend >= 1000) {        // هر ثانیه یک بار بفرست
    lastSend = millis();
    counter++;
    Serial2.printf("hello %d\n", counter);  // از TX2 بیرون می‌رود...
  }
  while (Serial2.available()) {             // ...و از RX2 برمی‌گردد
    Serial.write(Serial2.read());           // روی کامپیوتر نشانش بده
  }
}
  1. Serial2 روی ۱۶ و ۱۷. همان چهار آرگومان بالا: سرعت، قالب، RX، TX. دقیقا همان خطی که برای GPS به کار می‌بری؛ پس این آزمایش کد راه‌اندازی‌ات را هم امتحان می‌کند.
  2. هر ثانیه یک پیام شماره‌دار بفرست. Serial2.printf مثل Serial.printf است، ولی متن از GPIO17 بیرون می‌رود. شماره هر بار عوض می‌شود تا ببینی هر خط یک پیام تازه است، نه چیزی که روی صفحه گیر کرده.
  3. همان پل بخش GPS. هر بایتی که روی RX2 می‌رسد به Serial Monitor فرستاده می‌شود. اگر hello 1، hello 2 و ... دیدی، بایت‌ها واقعا از سیم رفته و برگشته‌اند.
Loopback test: GPIO17 -> GPIO16 hello 1 hello 2 hello 3

در Wokwi سیم Loopback از پایه ۱۷ برد به پایه ۱۶ خود برد می‌رود. آزمایش‌های زیر را همین‌جا هم امتحان کن.

امتحان کن: عمدا خرابش کن

۱) وسط اجرا سیم GPIO17 ← GPIO16 را دربیاور: پیام‌ها قطع می‌شوند، ولی برنامه از کار نمی‌افتد. ۲) سرعت را در Serial2.begin به 4800 تغییر بده و آپلود کن: باز هم کار می‌کند، چون هر دو سر همان یک UART هستند. ۳) حالا با Serial2 بفرست و با Serial1 دریافت کن: Serial1.begin(4800, SERIAL_8N1, 26, 14); را اضافه کن، سیم را طوری جابه‌جا کن که از GPIO17 به GPIO26 برود و به جای Serial2 از Serial1 بخوان. با 9600 در یک طرف و 4800 در طرف دیگر کاراکترهای درهم می‌بینی: همان مشکل «سرعت ناهمسان» جدول عیب‌یابی، با چشم خودت. (GPIO26 و GPIO14 در این درس آزادند؛ بعد از آزمایش سیم را جدا کن.)

ماژول GPS NEO-6M

ماژول GY-NEO6MV2 تراشه u-blox NEO-6M، یک آنتن سرامیکی مربعی، یک باتری یا خازن پشتیبان (برای به خاطر سپردن اطلاعات ماهواره‌ها) و یک LED دارد. خروجی آن روی UART متن ساده است: هر ثانیه چند «جمله» NMEA.

فقط خواندن؟ یک سیم کافی است

برای گرفتن موقعیت، ESP32 فقط گوش می‌دهد. پس سیم GPIO17 → RX ماژول اختیاری است (برای تنظیمات پیشرفته مثل تغییر سرعت یا نرخ به‌روزرسانی لازم می‌شود).

قدم ۱: جمله‌های خام را ببین

// دیدن جمله‌های خام NMEA از GPS
const int GPS_RX = 16;   // RX2 ی ESP32 ← TX ماژول GPS
const int GPS_TX = 17;   // TX2 ی ESP32 → RX ماژول GPS

void setup() {
  Serial.begin(115200);                                  // USB به کامپیوتر
  Serial2.begin(9600, SERIAL_8N1, GPS_RX, GPS_TX);       // UART2 به GPS
  Serial.println("Waiting for NMEA...");
}

void loop() {
  while (Serial2.available()) {        // هر بایتی از GPS رسید
    Serial.write(Serial2.read());      // عینا به Serial Monitor بفرست
  }
}
  1. دو UART با دو سرعت. Serial با ۱۱۵۲۰۰ به کامپیوتر و Serial2 با ۹۶۰۰ به GPS. هر UART سرعت خودش را دارد. سرعت GPS را ماژول تعیین می‌کند (۹۶۰۰)؛ سرعت USB را ما. چون سمت کامپیوتر سریع‌تر است، هیچ داده‌ای عقب نمی‌ماند.
  2. پل ساده. تا وقتی بایتی در صف دریافت Serial2 هست، بخوان و به Serial بفرست. while (نه if) تا همه بایت‌های رسیده در یک دور خالی شوند. این برنامه «پل» بهترین ابزار عیب‌یابی هر ماژول UART است: اول ببین ماژول اصلا حرف می‌زند یا نه.

قدم ۲: TinyGPSPlus، تجزیه خودکار

کتابخانه TinyGPSPlus (از Mikal Hart؛ در Library Manager عبارت TinyGPSPlus را جست‌وجو کن و TinyGPSPlus by Mikal Hart را نصب کن؛ وابستگی ندارد) حروف را یکی‌یکی می‌گیرد، جمله‌ها را تشخیص می‌دهد، checksum را بررسی می‌کند و عددها را آماده تحویل می‌دهد.

#include <TinyGPSPlus.h>

TinyGPSPlus gps;
unsigned long lastPrint = 0;

void setup() {
  Serial.begin(115200);
  Serial2.begin(9600, SERIAL_8N1, 16, 17);
}

void loop() {
  while (Serial2.available()) {
    gps.encode(Serial2.read());        // هر حرف را به تجزیه‌گر بده
  }

  if (millis() - lastPrint >= 1000) {
    lastPrint = millis();
    if (gps.location.isValid()) {
      Serial.printf("Lat=%.6f  Lon=%.6f  Sats=%lu  Alt=%.1fm\n",
                    gps.location.lat(), gps.location.lng(),
                    (unsigned long)gps.satellites.value(), gps.altitude.meters());
    } else {
      Serial.printf("No fix yet... sats=%lu chars=%lu\n",
                    (unsigned long)gps.satellites.value(), (unsigned long)gps.charsProcessed());
    }
    if (millis() > 5000 && gps.charsProcessed() < 10) {
      Serial.println("No data from GPS: check TX->RX wiring and baud!");
    }
  }
}
  1. کتابخانه و شیء gps. یک شیء همه داده‌ها را نگه می‌دارد: gps.location، gps.satellites، gps.altitude، gps.time، gps.speed و…
  2. تغذیه تجزیه‌گر. هر بایت رسیده به gps.encode داده می‌شود. این حلقه باید مدام و سریع اجرا شود. اگر در loop یک delay(1000) بگذاری، صف دریافت UART (حدود ۱۲۸ تا ۲۵۶ بایت) پر می‌شود و بخشی از جمله‌ها گم می‌شوند. برای همین چاپ را با millis زمان‌بندی کردیم، نه delay.
  3. گزارش هر یک ثانیه. الگوی millis. GPS به طور پیش‌فرض ثانیه‌ای یک بار موقعیت می‌دهد؛ چاپ سریع‌تر فایده‌ای ندارد.
  4. اگر موقعیت معتبر است. isValid() می‌گوید آیا تا حالا یک موقعیت درست دریافت شده. lat() و lng() درجه اعشاری (منفی برای S و W) می‌دهند؛ %.6f شش رقم اعشار، یعنی حدود ۱۰ سانتی‌متر. دقت واقعی NEO-6M حدود ۲٫۵ متر است، ولی شش رقم اعشار استاندارد رایج نقشه‌هاست. خط ۱۹ تا ۲۱ در واقع یک دستور است که برای خوانایی در سه خط شکسته شده.
  5. هنوز Fix نداریم. تعداد ماهواره‌های دیده‌شده و تعداد حروف پردازش‌شده را نشان می‌دهد. «chars» که بالا می‌رود یعنی سیم‌کشی درست است و فقط باید صبر کنی. این دو عدد، دو مشکل کاملا متفاوت را از هم جدا می‌کنند.
  6. هشدار سیم‌کشی. اگر بعد از ۵ ثانیه کمتر از ۱۰ حرف رسیده، مشکل در سیم یا سرعت است. پیام خطای مشخص بهتر از سکوت است. رایج‌ترین علت: TX و RX جابه‌جا.

GPS آسمان می‌خواهد و صبر

سیگنال ماهواره‌های GPS بسیار ضعیف است و از سقف بتنی عبور نمی‌کند. آنتن را کنار پنجره باز یا بهتر، بیرون ساختمان زیر آسمان باز بگذار (سمت سرامیکی آنتن رو به بالا). اولین روشن شدن (Cold Start) ممکن است از حدود نیم دقیقه در شرایط ایدئال تا چند دقیقه یا بیشتر طول بکشد، چون ماژول باید فهرست ماهواره‌ها را از خود سیگنال دانلود کند. دفعه‌های بعد (اگر باتری پشتیبان پر باشد) خیلی سریع‌تر است. روی بیشتر ماژول‌های GY-NEO6MV2، LED وقتی Fix گرفت شروع به چشمک زدن ثانیه‌ای می‌کند. داخل خانه و پشت میز؟ به احتمال زیاد هرگز Fix نمی‌گیری. این خرابی ماژول نیست.

GPS در Wokwi؟

Wokwi قطعه رسمی NEO-6M ندارد. چند پروژه ساخته کاربران با «Custom Chip» (تراشه سفارشی که با زبان C نوشته می‌شود) در Wokwi پیدا می‌شود که جمله‌های NMEA ساختگی تولید می‌کنند؛ این‌ها رسمی نیستند و کیفیتشان تضمین‌شده نیست. پیشنهاد این دوره: بخش GPS را با سخت‌افزار واقعی انجام بده. برای تمرین تجزیه بدون سخت‌افزار، می‌توانی جمله نمونه بالا را در کد به صورت یک رشته بنویسی و حرف‌به‌حرف به gps.encode() بدهی.

آزمون این درس

روی باس I2C یک OLED و یک BME280 داری. ESP32 چطور مشخص می‌کند با کدام حرف می‌زند؟

  1. با یک سیم CS جدا برای هر کدام
  2. با فرستادن آدرس ۷ بیتی هر دستگاه در ابتدای پیام
  3. هر کدام SDA جدا دارند
  4. با سرعت‌های مختلف
هر دستگاه I2C یک آدرس دارد (مثلا OLED 0x3C و BME280 0x76) و فقط به آدرس خودش جواب می‌دهد.

اسکنر I2C آدرس 0x3C را پیدا کرده، کد OLED بدون خطا اجرا می‌شود ولی صفحه هیچ چیزی نشان نمی‌دهد. محتمل‌ترین اشکال؟

  1. SDA و SCL جابه‌جا هستند
  2. مقاومت Pull-up لازم است
  3. آدرس اشتباه است
  4. display.display() صدا زده نشده
دستورهای رسم فقط در بافر RAM نقاشی می‌کنند؛ display() بافر را به صفحه می‌فرستد.

کدام جمله درباره DHT22 درست است؟

  1. پروتکل تک‌سیمه اختصاصی دارد و I2C نیست؛ حداقل ۲ ثانیه بین خواندن‌ها لازم است
  2. یک سنسور I2C با آدرس 0x76 است
  3. می‌توان آن را هر ۱۰ میلی‌ثانیه خواند
  4. هرگز به مقاومت Pull-up نیاز ندارد
DHT22 بیت‌ها را با طول پالس رمز می‌کند. برای سنسور محیطی I2C واقعی، BME280.

در SPI، سیم MISO چه کاری می‌کند؟

  1. ساعت را می‌سازد
  2. دستگاه را انتخاب می‌کند
  3. داده را از دستگاه به ESP32 می‌آورد
  4. داده را از ESP32 به دستگاه می‌برد
MISO = Master In, Slave Out. در ESP32 پیش‌فرض VSPI آن GPIO19 است.

کد SD روی کارت ۱۲۸ گیگ جدید SD mount failed می‌دهد، ولی همان سیم‌کشی با کارت ۸ گیگ قدیمی کار می‌کند. چرا؟

  1. MISO و MOSI جابه‌جا هستند
  2. کارت بزرگ احتمالا exFAT فرمت شده و کتابخانه FAT32 می‌خواهد
  3. ESP32 کارت‌های بزرگ‌تر از ۴ گیگ را نمی‌شناسد
  4. CS باید GPIO15 باشد
کارت‌های بالای ۳۲ گیگ معمولا exFAT هستند. کارت ۳۲ گیگ یا کمتر با FAT32 مطمئن‌ترین انتخاب است.

در Serial2.begin(9600, SERIAL_8N1, 16, 17)، پایه TX ماژول GPS باید به کدام پین ESP32 وصل شود؟

  1. GPIO17
  2. GPIO1
  3. GPIO3
  4. GPIO16
ورودی سوم (۱۶) RX ی ESP32 است. فرستنده ماژول ← گیرنده ESP32: ضربدری.

تمرین ۲: لاگر دما روی کارت SD

DHT22 و کارت SD را ترکیب کن: هر ۱۰ ثانیه یک خط millis,temp,humidity به /weather.csv اضافه کن. خواندن‌های nan را ننویس. فایل را بعدا در اکسل باز کن و نمودار بکش.

راهنمایی

DHT22 روی GPIO13 است و با پین‌های SPI (۵، ۱۸، ۱۹، ۲۳) تداخلی ندارد. در loop با millis هر ۱۰۰۰۰ms: بخوان، با isnan چک کن، SD.open(..., FILE_APPEND)، f.printf("%lu,%.1f,%.1f\n", millis(), t, h) و close.

جواب 
#include <SPI.h>
#include <SD.h>
#include <DHT.h>

DHT dht(13, DHT22);
unsigned long lastLog = 0;

void setup() {
  Serial.begin(115200);
  dht.begin();
  if (!SD.begin(5)) {
    Serial.println("SD mount failed!");
    while (true) delay(1000);
  }
  if (!SD.exists("/weather.csv")) {
    File f = SD.open("/weather.csv", FILE_WRITE);
    f.println("millis,temp,humidity");
    f.close();
  }
}

void loop() {
  if (millis() - lastLog < 10000) return;
  lastLog = millis();
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (isnan(t) || isnan(h)) { Serial.println("DHT error, skipped"); return; }
  File f = SD.open("/weather.csv", FILE_APPEND);
  if (!f) { Serial.println("open failed"); return; }
  f.printf("%lu,%.1f,%.1f\n", millis(), t, h);
  f.close();
  Serial.printf("logged %.1f C %.1f %%\n", t, h);
}
  1. سرتیتر فقط یک بار. مثل برنامه SD_Log. اگر هر بار سرتیتر بنویسی، وسط داده‌ها خط متنی می‌افتد و اکسل نمودار را خراب می‌کشد.
  2. نگهبان زمان. هر ۱۰ ثانیه یک بار. هر نوشتن روی کارت SD کمی عمر آن را مصرف می‌کند؛ لاگ کردن سریع‌تر از نیاز، فقط فایل را بزرگ و کارت را فرسوده می‌کند.
  3. نوشتن امن. nan رد می‌شود، اگر فایل باز نشد رد می‌شود، و بعد از هر خط close. لاگر معمولا ساعت‌ها بدون نظارت کار می‌کند؛ باید با هر خطای تکی کنار بیاید و قطع برق ناگهانی حداکثر یک خط را از بین ببرد.
تمرین ۳: سرعت‌سنج GPS روی OLED

با TinyGPSPlus سرعت (gps.speed.kmph()) را با اندازه متن ۳ و تعداد ماهواره‌ها را با اندازه ۱ روی OLED نشان بده. تا Fix نگرفته، «Searching...» و تعداد حروف دریافتی را نشان بده. با یک پاوربانک در ماشین یا دوچرخه امتحان کن.

راهنمایی

OLED روی I2C (۲۱، ۲۲) و GPS روی UART2 (۱۶، ۱۷) هیچ پین مشترکی ندارند. حلقه gps.encode را بدون delay نگه دار و صفحه را فقط هر ۵۰۰ms با millis به‌روز کن. از gps.speed.isValid() هم استفاده کن.

خلاصه درس در سه خط

I2C دو سیم (SDA=21، SCL=22) با Pull-up و آدرس برای هر دستگاه دارد؛ اول اسکنر، بعد کتابخانه؛ OLED در 0x3C با چرخه clear ← رسم ← display(). DHT22 پروتکل تک‌سیمه خودش را دارد (نه I2C)، Pull-up ی ۱۰ کیلو و حداقل ۲ ثانیه فاصله می‌خواهد و خروجی‌اش را با isnan چک کن. SPI (VSPI: 23/19/18 و CS=5) سریع است و برای کارت SD ی FAT32 با FILE_APPEND و close()؛ UART ضربدری است (TX به RX)، سرعت دو طرف باید یکسان باشد، و GPS روی Serial2.begin(9600, SERIAL_8N1, 16, 17) جمله NMEA می‌فرستد که TinyGPSPlus آن را به درجه اعشاری تبدیل می‌کند؛ فقط زیر آسمان باز.
