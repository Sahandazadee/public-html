PWM چیست؟ روشن و خاموش خیلی سریع

PWM مخفف Pulse Width Modulation یعنی «مدولاسیون پهنای پالس». اسمش ترسناک است ولی ایده‌اش ساده است: پین را در هر ثانیه هزاران بار روشن و خاموش می‌کنیم و فقط نسبت زمان روشن به کل زمان را تغییر می‌دهیم. به این نسبت Duty Cycle (چرخه کار) می‌گویند.

مثال: شیر آب و لیوان

فرض کن شیر آب فقط دو حالت دارد: کاملا باز یا کاملا بسته. اگر بخواهی لیوان «آرام» پر شود، شیر را یک ثانیه باز و سه ثانیه بسته می‌کنی و این را تکرار می‌کنی. در کل، لیوان با یک‌چهارم سرعت پر می‌شود. PWM دقیقا همین است، فقط با ولتاژ و هزاران بار در ثانیه.

با عدد: ولتاژ میانگین

ولتاژ میانگین = ولتاژ روشن × Duty Cycle.

Duty ۲۵٪: 3.3 × 0.25 ≈ 0.83V · Duty ۵۰٪: 3.3 × 0.50 = 1.65V · Duty ۷۵٪: 3.3 × 0.75 ≈ 2.48V.

اگر مولتی‌متر را روی پین PWM بگذاری، تقریبا همین اعداد را نشان می‌دهد، چون مولتی‌متر هم کند است و میانگین می‌گیرد. ولی یادت باشد: در هر لحظه واقعا یا ۰ است یا ۳٫۳ ولت.

چرا LED کم‌نورتر به نظر می‌رسد؟

LED برخلاف لامپ رشته‌ای، خیلی سریع (در حد نانوثانیه) روشن و خاموش می‌شود. پس با PWM ۲۵٪، LED واقعا ۲۵٪ زمان با نور کامل روشن است و ۷۵٪ زمان خاموش. کم‌نوری در چشم و مغز تو اتفاق می‌افتد: چشم انسان تغییرات سریع‌تر از حدود ۵۰ تا ۱۰۰ بار در ثانیه را از هم جدا نمی‌کند و نور را میانگین می‌گیرد؛ همان پدیده‌ای که باعث می‌شود ۲۴ عکس ثابت در ثانیه در سینما «فیلم متحرک» دیده شود.

چرا فرکانس ۵ کیلوهرتز برای LED؟

زیر حدود ۱۰۰ هرتز، سوسو زدن (Flicker) دیده می‌شود، به خصوص با گوشه چشم یا وقتی سر را تکان می‌دهی. دوربین گوشی حتی در چند صد هرتز هم نوار سیاه ضبط می‌کند. ۵۰۰۰ هرتز آن‌قدر بالاست که نه چشم و نه دوربین چیزی نمی‌بینند و هنوز آن‌قدر پایین است که دقت خوبی داشته باشیم (بخش بعد).

فرکانس و دقت (Resolution): یک معامله

دو عدد، PWM را تعریف می‌کنند:

  • فرکانس: در هر ثانیه چند دوره روشن/خاموش داریم (مثلا ۵۰۰۰ هرتز یعنی هر دوره ۰٫۲ میلی‌ثانیه).
  • دقت (Resolution): هر دوره به چند پله تقسیم می‌شود. ۸ بیت یعنی 28 = 256 پله (Duty از ۰ تا ۲۵۵)؛ ۱۲ بیت یعنی ۴۰۹۶ پله (۰ تا ۴۰۹۵).

سخت‌افزار LEDC این پله‌ها را با یک ساعت داخلی می‌شمارد. در ESP32 کلاسیک این ساعت ۸۰ مگاهرتز است. پس برای هر دوره باید 2بیت تیک ساعت وقت داشته باشد. قانون طلایی:

فرض کن در هر ثانیه فقط ۸۰ میلیون «تیک» وقت داری. اگر هر دوره را به ۲۵۶ قسمت تقسیم کنی، می‌توانی خیلی دوره در ثانیه بسازی (فرکانس بالا). اگر بخواهی هر دوره ۶۵۵۳۶ قسمت ریز داشته باشد، دوره‌های کمتری جا می‌شوند. دقت بیشتر = فرکانس کمتر؛ همیشه.

حد پایین فرکانس هم وجود دارد

تقسیم‌کننده ساعت LEDC محدود است، پس برای هر دقت یک حداقل فرکانس هم هست. مثلا فرکانس خیلی پایین با دقت خیلی کم ممکن است قبول نشود. طبق مستندات، اگر فرکانس پایین لازم داری، دقت را بیشتر کن، نه کمتر. برای کارهای این درس (۵ کیلوهرتز و ۵۰ هرتز) نگرانی نیست.

LEDC: کارخانه PWM داخل ESP32

ESP32 برای ساختن PWM از CPU استفاده نمی‌کند؛ یک بخش سخت‌افزاری مستقل به اسم LEDC (LED Control) دارد. وقتی Duty را تنظیم کردی، LEDC خودش موج را می‌سازد و CPU آزاد است هر کار دیگری انجام بدهد. با وجود اسمش، LEDC برای موتور، سروو و بازر هم استفاده می‌شود.

  • ESP32 کلاسیک ۱۶ کانال دارد (دو گروه ۸تایی، هر گروه ۴ تایمر). یعنی تا ۱۶ پین PWM مستقل هم‌زمان. (ESP32-S2 و S3 هشت کانال و C3 شش کانال دارند.)
  • هر GPIO که بتواند خروجی باشد، می‌تواند PWM داشته باشد. پس GPIO34 تا 39 (فقط ورودی) نه.
  • کانال‌هایی که فرکانس و دقت یکسان دارند، یک تایمر را شریک می‌شوند. پس اگر ۵ LED با ۵ کیلوهرتز ۸ بیت داری، همه یک تایمر مصرف می‌کنند.

پروژه ۱: LED نفس‌کشنده (Breathing)

همان مدار LED درس ۲.۲: GPIO4 ← مقاومت ۲۲۰ اهم ← LED ← GND. هیچ تغییری در سخت‌افزار لازم نیست؛ فقط به جای digitalWrite از PWM استفاده می‌کنیم.

// LED نفس‌کشنده (Breathing) با LEDC
const int LED_PIN = 4;
const int PWM_FREQ = 5000;      // 5kHz: خیلی بالاتر از حد تشخیص چشم
const int PWM_RES  = 8;         // 8 بیت: duty از 0 تا 255

void setup() {
  Serial.begin(115200);
  if (!ledcAttach(LED_PIN, PWM_FREQ, PWM_RES)) {
    Serial.println("ledcAttach failed!");
  }
}

void loop() {
  for (int duty = 0; duty <= 255; duty++) {   // کم‌کم روشن
    ledcWrite(LED_PIN, duty);
    delay(8);
  }
  for (int duty = 255; duty >= 0; duty--) {   // کم‌کم خاموش
    ledcWrite(LED_PIN, duty);
    delay(8);
  }
}
  1. دو ثابت PWM. فرکانس ۵۰۰۰ هرتز و دقت ۸ بیت. 5000 × 256 = 1.28MHz خیلی زیر سقف ۸۰ مگاهرتز است. ۲۵۶ پله برای چشم کافی است؛ اسم دادن به این اعداد باعث می‌شود بعدا برای آزمایش راحت عوضشان کنی.
  2. ledcAttach با بررسی خطا. پین ۴ را به یک کانال LEDC با تنظیمات بالا وصل می‌کند. اگر نشد (مثلا ترکیب فرکانس و دقت غیرممکن بود)، false برمی‌گرداند و ما پیام چاپ می‌کنیم. ! یعنی «نه». بررسی مقدار برگشتی عادت خوبی است: اگر روزی PWM_RES را ۱۴ کنی، به جای LED خاموش و سردرگمی، یک پیام واضح می‌بینی. توجه کن که دیگر pinMode لازم نیست؛ ledcAttach خودش پین را خروجی می‌کند.
  3. حلقه روشن شدن. Duty از ۰ تا ۲۵۵، هر پله ۸ میلی‌ثانیه. ۲۵۶ پله × ۸ms ≈ ۲ ثانیه برای روشن شدن کامل؛ سرعتی آرام و شبیه نفس کشیدن. عدد ۸ را کم کنی تندتر نفس می‌کشد.
  4. ledcWrite(پین، duty). Duty را روی سخت‌افزار تنظیم می‌کند. از این لحظه LEDC خودش موج را می‌سازد تا دستور بعدی. در هسته ۳ عدد اول پین است، نه کانال. این را با کدهای قدیمی اشتباه نگیر.
  5. حلقه خاموش شدن. برعکس: از ۲۵۵ تا ۰. duty-- یعنی یکی کم کن. شرط duty >= 0 (و نه > 0) باعث می‌شود LED واقعا به صفر برسد و کاملا خاموش شود.
چرا نیمه اول تنفس سریع‌تر به نظر می‌رسد؟

چشم انسان به نور کم خیلی حساس‌تر از نور زیاد است (پاسخ چشم تقریبا لگاریتمی است). پس تغییر Duty از ۱۰ به ۲۰ خیلی بیشتر از ۲۱۰ به ۲۲۰ دیده می‌شود. برای تنفس «طبیعی‌تر»، به جای خود Duty از مربع آن استفاده کن: ledcWrite(LED_PIN, duty * duty / 255);. به این اصلاح «گاما» می‌گویند.

نسخه سخت‌افزاری: ledcFade

در کد بالا CPU خودش پله‌پله Duty را عوض می‌کند و در delayها گیر است. LEDC می‌تواند این کار را خودش انجام دهد:

const int LED_PIN = 4;

void setup() {
  ledcAttach(LED_PIN, 5000, 8);
}

void loop() {
  ledcFade(LED_PIN, 0, 255, 1500);   // سخت‌افزار در ۱٫۵ ثانیه روشن می‌کند
  delay(2000);                       // CPU اینجا آزاد است؛ delay فقط برای سادگی مثال
  ledcFade(LED_PIN, 255, 0, 1500);   // و در ۱٫۵ ثانیه خاموش
  delay(2000);
}
  1. ledcFade(پین، شروع، پایان، میلی‌ثانیه). به LEDC می‌گوید Duty را از ۰ تا ۲۵۵ در ۱۵۰۰ میلی‌ثانیه نرم بالا ببرد و فورا برمی‌گردد. این تابع منتظر تمام شدن محو شدن نمی‌ماند. پس در یک برنامه واقعی به جای delay می‌توانی دکمه بخوانی یا به Wi-Fi جواب بدهی و LED خودش نرم عوض می‌شود.
  2. delay بلندتر از زمان fade. ۲۰۰۰ms صبر تا fade (۱۵۰۰ms) تمام شود و نیم ثانیه در نور کامل بماند. اگر fade بعدی را قبل از تمام شدن قبلی شروع کنی، قبلی قطع می‌شود. نسخه‌های پیشرفته‌تر (ledcFadeWithInterrupt) می‌توانند تمام شدن fade را با یک تابع خبر بدهند.

analogWrite هم هست؛ رابطه‌اش با LEDC چیست؟

در آردوینو اونو برای PWM از analogWrite(pin, 0..255) استفاده می‌شود. هسته ۳ ESP32 هم این تابع را دارد تا کدهای آردوینو راحت اجرا شوند. پشت پرده، analogWrite دفعه اول خودش ledcAttach(pin, 1000, 8) را صدا می‌زند (پیش‌فرض: ۱۰۰۰ هرتز، ۸ بیت) و بعد ledcWrite می‌کند. با analogWriteFrequency(pin, freq) و analogWriteResolution(pin, bits) می‌توانی تنظیماتش را عوض کنی.

کدام را استفاده کنم؟

برای کد سریع و سازگار با آردوینو: analogWrite. برای کنترل کامل روی فرکانس و دقت و بررسی خطا: ledcAttach + ledcWrite. فقط روی یک پین هر دو را قاطی نکن. (توجه: نام analogWrite گمراه‌کننده است؛ خروجی آنالوگ واقعی نیست، همان PWM است. خروجی آنالوگ واقعی DAC روی GPIO25 و 26 است.)

پروژه ۲: پتانسیومتر، نور LED را تنظیم می‌کند

پتانسیومتر روی GPIO34 (مثل درس ۳.۱) و LED روی GPIO4. یک ترفند زیبا: ADC عدد ۱۲ بیتی (۰ تا ۴۰۹۵) می‌دهد؛ اگر PWM را هم ۱۲ بیتی تنظیم کنیم، می‌توانیم عدد را مستقیم و بدون map به LED بدهیم.

// پتانسیومتر، نور LED را تنظیم می‌کند
const int POT_PIN = 34;
const int LED_PIN = 4;

void setup() {
  Serial.begin(115200);
  ledcAttach(LED_PIN, 5000, 12);      // 12 بیت: 0 تا 4095، هم‌اندازه ADC
}

void loop() {
  int raw = analogRead(POT_PIN);      // 0 تا 4095
  ledcWrite(LED_PIN, raw);            // همان عدد، مستقیم به PWM
  Serial.printf("raw=%d  duty=%d%%\n", raw, raw * 100 / 4095);
  delay(20);
}
  1. PWM دوازده بیتی. ۵ کیلوهرتز با ۴۰۹۶ پله. 5000 × 4096 = 20.48MHz زیر سقف ۸۰ است. هم‌اندازه بودن ADC و PWM یعنی هیچ تبدیلی لازم نیست و هیچ دقتی هم دور ریخته نمی‌شود.
  2. خواندن و نوشتن مستقیم. عدد پتانسیومتر همان Duty می‌شود. اگر PWM را ۸ بیتی گذاشته بودی، باید map(raw, 0, 4095, 0, 255) یا raw >> 4 (تقسیم بر ۱۶) می‌نوشتی. نوشتن ۴۰۹۵ روی PWM هشت بیتی اشتباه رایجی است: هر عدد بالای ۲۵۵ یعنی «کاملا روشن» و پیچ فقط در ۶٪ اول مسیرش کار می‌کند.
  3. نمایش درصد. raw * 100 / 4095 درصد Duty را حساب می‌کند. %% خود علامت ٪ را چاپ می‌کند. اول ضرب بعد تقسیم: اگر اول تقسیم می‌کردی (raw / 4095 * 100)، تقسیم صحیح همیشه ۰ می‌داد (جز در انتها).
  4. مکث ۲۰ms. ۵۰ به‌روزرسانی در ثانیه برای حس «فوری» کافی است و Serial Monitor را غرق نمی‌کند.

پتانسیومتر را بچرخان و ببین LED نرم کم و زیاد می‌شود. کد Breathing_LED را هم می‌توانی در همین مدار امتحان کنی.

سروو موتور: PWM برای «زاویه»

سروو موتور (مثل SG90 آبی کوچک) یک موتور DC کوچک، یک جعبه‌دنده، یک پتانسیومتر داخلی و یک مدار کنترل است که همه در یک جعبه جمع شده‌اند. تو به آن نمی‌گویی «بچرخ»؛ می‌گویی «به زاویه ۹۰ درجه برو و همان‌جا بمان». مدار داخلی با پتانسیومتر خودش زاویه فعلی را می‌خواند و موتور را آن‌قدر می‌چرخاند تا به زاویه خواسته‌شده برسد.

مثال: فرمان ماشین با راننده خودکار

تو فقط می‌گویی «فرمان ۳۰ درجه به راست». راننده (مدار داخلی) نگاه می‌کند فرمان الان کجاست، می‌چرخاند و وقتی رسید نگه می‌دارد. اگر کسی بخواهد فرمان را به زور بچرخاند، راننده مقاومت می‌کند. این «بازخورد» (Feedback) است.

زبان سروو: پهنای پالس، نه Duty

سروو هر ۲۰ میلی‌ثانیه (یعنی ۵۰ بار در ثانیه، ۵۰ هرتز) یک پالس انتظار دارد. پهنای این پالس زاویه را تعیین می‌کند. برای SG90 در عمل:

عددهای دیتاشیت با واقعیت فرق دارند

دیتاشیت‌های SG90 معمولا ۱ تا ۲ میلی‌ثانیه را برای حرکت کامل ذکر می‌کنند، ولی آن بازه در عمل فقط حدود ۹۰ درجه حرکت می‌دهد. بیشتر سازندگان و کتابخانه‌ها ۰٫۵ تا ۲٫۴ میلی‌ثانیه را برای ۰ تا ۱۸۰ درجه استفاده می‌کنند. هر سروو کمی فرق دارد؛ اگر سروو در یکی از دو انتها «وزوز» کرد، یعنی پالس از حد مکانیکی آن فراتر رفته و باید بازه را کمی تنگ‌تر کنی (پایین‌تر در عیب‌یابی).

تغذیه سروو: مهم‌ترین قسمت این درس

مشخصه SG90 (تقریبی)مقدار
ولتاژ کار۴٫۸ تا ۶ ولت (۵ ولت ایدئال)

سیگنال ۳٫۳ ولتی ESP32 برای فرمان دادن به SG90 کافی است. ولی برق سروو هرگز نباید از پین 3V3 یا یک GPIO بیاید. دو روش:

روش ۱ (فقط برای یک سروو کوچک و آزمایش): پین 5V برد

پین 5V برد DevKitC تقریبا مستقیم (در بعضی بردها از طریق یک دیود) به ۵ ولت USB وصل است. روی بردهای ۳۰ پایه (مثل DOIT DevKit V1) همین پایه با اسم VIN چاپ شده است؛ هر جا در این دوره 5V دیدی، روی آن بردها VIN را بگیر. پورت USB کامپیوتر معمولا ۵۰۰ میلی‌آمپر می‌دهد و خود ESP32 هم ۱۰۰ تا ۲۵۰ میلی‌آمپر (با Wi-Fi) مصرف می‌کند. یک SG90 بدون بار معمولا جا می‌شود، ولی جهش جریان لحظه شروع حرکت، ولتاژ را افت می‌دهد. (مسیر کامل برق از USB تا پایه‌ها و بودجه جریان را در درس ۱.۴ دیدی؛ چرا بار پرمصرف را نمی‌شود مستقیم از برد تغذیه کرد، در درس ۳.۴ با عدد می‌بینی.)

روش ۲ (درست و مطمئن): منبع جدا + زمین مشترک

برای بیش از یک سروو، سروو زیر بار، یا هر پروژه جدی، سروو را از یک منبع ۵ ولت جدا (آداپتور ۵ ولت ۲ آمپر، یا پاوربانک) تغذیه کن. زمین منبع و زمین ESP32 باید به هم وصل شوند.

چرا زمین مشترک ضروری است؟

ولتاژ همیشه «نسبت به یک نقطه» سنجیده می‌شود. سیگنال ۳٫۳ ولتی ESP32 یعنی «۳٫۳ ولت بالاتر از GND خود ESP32». اگر GND سروو به GND خود ESP32 وصل نباشد، سروو نقطه مرجعی ندارد که این ۳٫۳ ولت را با آن بسنجد و سیگنال برایش بی‌معنی است. مثل این است که بگویی «سه طبقه بالاتر» بدون این که بگویی از کدام ساختمان.

Brownout: وقتی سروو برد را ریست می‌کند

اگر هر بار که سروو حرکت می‌کند ESP32 ریست می‌شود و در Serial Monitor پیام Brownout detector was triggered می‌بینی، یعنی جهش جریان سروو ولتاژ را آن‌قدر پایین آورده که محافظ داخلی ESP32 برای جلوگیری از رفتار غیرقابل پیش‌بینی آن را ریست کرده. راه حل: روش ۲ (منبع جدا)، و یک خازن الکترولیت ۴۷۰ تا ۱۰۰۰ میکروفاراد (۱۰ ولت یا بیشتر) بین + و − سروو، نزدیک خود سروو (پایه منفی خازن به GND). خازن مثل یک مخزن کوچک جهش‌های لحظه‌ای را تأمین می‌کند.

کتابخانه ESP32Servo

کتابخانه Servo معروف آردوینو برای ESP32 کار نمی‌کند. به جایش از ESP32Servo استفاده می‌کنیم که همان دستورها را دارد و پشت پرده از LEDC استفاده می‌کند.

  1. نصب: در Arduino IDE از Sketch › Include Library › Manage Libraries… عبارت ESP32Servo را جست‌وجو کن و کتابخانه‌ای با دقیقا همین اسم، ESP32Servo by Kevin Harrington, John K. Bennett، را نصب کن (نسخه 3.x یا جدیدتر که با هسته ۳ سازگار است؛ نسخه‌های 1.x و 0.x با هسته ۳ خطای کامپایل می‌دهند). این کتابخانه وابستگی دیگری نمی‌خواهد. کتابخانه‌های هم‌اسم دیگر (مثل ServoESP32) را نصب نکن؛ دستورهایشان فرق دارد.
  2. در Wokwi: زبانه Library Manager را باز کن، روی + بزن و ESP32Servo را اضافه کن. (Wokwi این را در فایلی به اسم libraries.txt ذخیره می‌کند.)
#include <ESP32Servo.h>

Servo myServo;                  // یک شیء سروو
const int SERVO_PIN = 32;

void setup() {
  Serial.begin(115200);
  myServo.setPeriodHertz(50);             // سروو استاندارد: 50Hz
  myServo.attach(SERVO_PIN, 500, 2400);   // پالس 0.5ms تا 2.4ms
}

void loop() {
  for (int angle = 0; angle <= 180; angle++) {
    myServo.write(angle);
    delay(15);                  // به سروو فرصت حرکت بده
  }
  for (int angle = 180; angle >= 0; angle--) {
    myServo.write(angle);
    delay(15);
  }
}
  1. include. کد کتابخانه را به برنامه اضافه می‌کند. <...> یعنی «در پوشه کتابخانه‌ها بگرد». اگر خطای No such file or directory دیدی، کتابخانه نصب نشده.
  2. ساختن یک شیء. Servo myServo; یک «سروو مجازی» به اسم myServo می‌سازد. هر سروو واقعی یک شیء جدا لازم دارد. برای دو سروو: Servo s1, s2;. شیء مثل یک کنترل تلویزیون است که فقط با یک تلویزیون جفت شده.
  3. setPeriodHertz(50). فرکانس ۵۰ هرتز (دوره ۲۰ms). پیش‌فرض کتابخانه هم ۵۰ است ولی نوشتنش کد را روشن‌تر می‌کند. بعضی سرووهای دیجیتال فرکانس بالاتر (مثلا ۳۳۰ هرتز) را هم می‌پذیرند.
  4. attach(پین، حداقل، حداکثر). سروو را به GPIO32 وصل می‌کند و می‌گوید زاویه ۰ = ۵۰۰ میکروثانیه و ۱۸۰ = ۲۴۰۰ میکروثانیه. پیش‌فرض کتابخانه ۵۴۴ تا ۲۴۰۰ است. ما بازه SG90 را صریح نوشتیم تا اگر سروو دیگری داشتی بدانی کجا را عوض کنی. GPIO32 یک خروجی امن و همه‌کاره است و در این دوره پایه ثابت سروو (یا سیم داده NeoPixel) است تا دکمه، LED و پتانسیومتر سر جای خودشان بمانند.
  5. چرخش ۰ تا ۱۸۰. write(angle) زاویه را به درجه می‌گیرد و کتابخانه آن را به پهنای پالس تبدیل می‌کند. ۱۵ms بین هر درجه به سروو فرصت می‌دهد حرکت کند؛ ۱۸۱ پله × ۱۵ms ≈ ۲٫۷ ثانیه برای نیم دور. سرعت حداکثر SG90 حدود ۰٫۱ ثانیه برای ۶۰ درجه است، پس بی‌دلیل سریع‌ترش نکن.
  6. برگشت ۱۸۰ به ۰. همان حلقه برعکس. حرکت نرم رفت و برگشت، کمترین جهش جریان را دارد. پریدن ناگهانی از ۰ به ۱۸۰ بیشترین جریان را می‌کشد و بیشترین احتمال Brownout را دارد.

بدون کتابخانه: سروو فقط PWM است (رازگشایی)

کتابخانه جادو نمی‌کند. بیا خودمان حساب کنیم. با ۵۰ هرتز و دقت ۱۶ بیت، یک دوره ۲۰۰۰۰ میکروثانیه است و به ۶۵۵۳۶ پله تقسیم می‌شود:

حساب Duty برای سروو

duty = پهنای پالس (µs) × 65536 ÷ 20000

۰ درجه: 500 × 65536 ÷ 20000 ≈ 1638 | ۹۰ درجه: 1450 × 65536 ÷ 20000 ≈ 4751 | ۱۸۰ درجه: 2400 × 65536 ÷ 20000 ≈ 7864.

(۹۰ درجه وسط ۵۰۰ و ۲۴۰۰ یعنی ۱۴۵۰ میکروثانیه است، نزدیک ۱٫۵ms استاندارد.) یعنی سروو در بدترین حالت فقط حدود ۱۲٪ Duty می‌بیند؛ بقیه دوره LOW است.

// سروو بدون کتابخانه: فقط LEDC و کمی حساب
const int SERVO_PIN = 32;
const int FREQ = 50;            // 50Hz = هر 20ms یک پالس
const int RES  = 16;            // 16 بیت: 0 تا 65535
const int MIN_US = 500;         // پالس زاویه 0 درجه
const int MAX_US = 2400;        // پالس زاویه 180 درجه

uint32_t usToDuty(int us) {
  return (uint32_t)us * 65536UL / 20000UL;   // سهم پالس از 20000 میکروثانیه
}

void writeAngle(int angle) {
  angle = constrain(angle, 0, 180);
  int us = map(angle, 0, 180, MIN_US, MAX_US);
  ledcWrite(SERVO_PIN, usToDuty(us));
  Serial.printf("angle=%3d  pulse=%4dus  duty=%lu\n", angle, us, (unsigned long)usToDuty(us));
}

void setup() {
  Serial.begin(115200);
  ledcAttach(SERVO_PIN, FREQ, RES);
}

void loop() {
  const int angles[] = {0, 90, 180, 90};
  for (int i = 0; i < 4; i++) {
    writeAngle(angles[i]);
    delay(1000);
  }
}
  1. پارامترهای سروو. ۵۰ هرتز، ۱۶ بیت و بازه پالس. 50 × 65536 ≈ 3.3MHz، خیلی زیر سقف. دقت ۱۶ بیت یعنی هر پله حدود ۰٫۳ میکروثانیه؛ با ۸ بیت هر پله ۷۸ میکروثانیه می‌شد و بین ۰ تا ۱۸۰ درجه فقط حدود ۲۴ پله داشتیم (حرکت پله‌پله و زمخت).
  2. تبدیل میکروثانیه به Duty. همان فرمول بالا. (uint32_t) عدد را قبل از ضرب ۳۲ بیتی می‌کند و UL یعنی «عدد ثابت unsigned long». 2400 × 65536 = 157,286,400 از بازه int شانزده بیتی بعضی بردها بیرون است. عادت کن ضرب‌های بزرگ را صریحا در نوع بزرگ انجام دهی. اول ضرب، بعد تقسیم؛ تا دقت از دست نرود.
  3. constrain(مقدار، کم، زیاد). زاویه را بین ۰ و ۱۸۰ محدود می‌کند. اگر اشتباها ۲۵۰ بدهی، بدون این خط پالس از حد مجاز بیرون می‌رود و سروو به ته مکانیکی فشار می‌آورد، جریان زیاد می‌کشد و ممکن است دنده‌هایش بشکند.
  4. زاویه ← میکروثانیه ← Duty ← سخت‌افزار. map زاویه را به پهنای پالس و usToDuty آن را به Duty تبدیل می‌کند. این دقیقا همان کاری است که myServo.write() پشت پرده انجام می‌دهد.
  5. ledcAttach با ۵۰ هرتز و ۱۶ بیت. همان تابعی که برای LED استفاده کردیم، فقط با اعداد متفاوت. PWM یک ابزار است؛ LED و سروو فقط دو جور استفاده از آن.
  6. لیست زاویه‌ها. یک آرایه چهارتایی که به ترتیب اجرا می‌شود، هر کدام یک ثانیه. آرایه (Array) یعنی چند مقدار هم‌نوع پشت سر هم؛ angles[0] اولی است. این کار از نوشتن چهار بار writeAngle تمیزتر است.
angle= 0 pulse= 500us duty=1638 angle= 90 pulse=1450us duty=4751 angle=180 pulse=2400us duty=7864 angle= 90 pulse=1450us duty=4751

پروژه ۳: پتانسیومتر، زاویه سروو را تعیین می‌کند

مدار: همان نقشه «روش ۱» بالا (سروو روی GPIO32، پتانسیومتر روی GPIO34). پیچ را بچرخانی، بازوی سروو هم‌زمان می‌چرخد؛ مثل یک بازوی رباتیک ساده.

#include <ESP32Servo.h>

const int POT_PIN = 34;
const int SERVO_PIN = 32;
Servo myServo;
int lastAngle = -1;             // هنوز زاویه‌ای ننوشته‌ایم

void setup() {
  Serial.begin(115200);
  myServo.setPeriodHertz(50);
  myServo.attach(SERVO_PIN, 500, 2400);
}

void loop() {
  long sum = 0;
  for (int i = 0; i < 16; i++) sum += analogRead(POT_PIN);   // میانگین ۱۶ نمونه
  int raw = sum / 16;
  int angle = map(raw, 0, 4095, 0, 180);

  if (abs(angle - lastAngle) >= 2) {    // منطقه مرده: لرزش ۱ درجه‌ای را نادیده بگیر
    myServo.write(angle);
    lastAngle = angle;
    Serial.printf("raw=%d  angle=%d\n", raw, angle);
  }
  delay(20);
}
  1. حافظه آخرین زاویه با مقدار اولیه ۱−. عدد ۱− هرگز زاویه واقعی نیست؛ پس در اولین دور loop شرط حتما درست می‌شود و سروو به محل پیچ می‌رود.
  2. میانگین ۱۶ نمونه. همان تکنیک درس ۳.۱، این بار در سه خط. نویز ADC بدون میانگین، زاویه را مدام ±۱ درجه تغییر می‌دهد و سروو «می‌لرزد» و وزوز می‌کند.
  3. تبدیل به زاویه. ۰ تا ۴۰۹۵ ← ۰ تا ۱۸۰.
  4. منطقه مرده (Deadband). فقط وقتی زاویه دست‌کم ۲ درجه تغییر کرده، سروو را حرکت بده. abs قدر مطلق است (منفی را مثبت می‌کند). حتی با میانگین، عدد گاهی بین دو زاویه مجاور نوسان می‌کند. منطقه مرده، برادر Hysteresis درس قبل است: تغییرات ریز و بی‌معنی را نادیده بگیر. مزیت دیگر: Serial Monitor فقط وقتی چاپ می‌کند که واقعا چیزی عوض شده.
  5. مکث ۲۰ms. سروو فقط هر ۲۰ms یک پالس جدید می‌بیند؛ به‌روزرسانی سریع‌تر فایده‌ای ندارد.

قبل از اجرا، در Wokwi از زبانه Library Manager کتابخانه ESP32Servo را اضافه کن، وگرنه خطای کامپایل می‌گیری. در شبیه‌ساز سروو مستقیما از 5V تغذیه می‌شود و مشکل جریان پیش نمی‌آید؛ این مشکل فقط در دنیای واقعی است، پس بخش تغذیه را جدی بگیر. کدهای Servo_Sweep و Servo_Raw_LEDC را هم در همین مدار امتحان کن.

اضافه: صدا با بازر و ledcWriteTone

بازر دو نوع است: اکتیو (داخلش نوسان‌ساز دارد و با ولتاژ ثابت خودش بوق یکنواخت می‌زند) و پسیو (مثل یک بلندگوی کوچک است و صدا فقط با موج مربعی ساخته می‌شود). برای ساختن نت‌های مختلف بازر پسیو لازم داری. فرکانس PWM همان ارتفاع صدا (نت) است: ۴۴۰ هرتز = نت «لا».

اگر بازر اکتیو داری

بازر اکتیو اصلا PWM نمی‌خواهد: digitalWrite(pin, HIGH) آن را به صدا درمی‌آورد و LOW ساکتش می‌کند، همیشه با یک صدای ثابت، مثل بوق مایکروویو. برای آلارم‌های ساده عالی است. دو نکته: خیلی از بازرهای اکتیو برای ۵ ولت ساخته شده‌اند و حدود ۳۰ میلی‌آمپر می‌کشند که بیشتر از توان یک GPIO است؛ پس نوع ۳٫۳ ولتی بگیر یا آن را با ترانزیستور راه بینداز (درس ۳.۴). و ledcWriteTone روی بازر اکتیو فقط یک خش‌خش زمخت می‌دهد. راه تشخیص: بازر اکتیو معمولا زیرش مشکی و بسته است و رویش برچسب دارد و اگر مستقیم به ۳٫۳ ولت وصلش کنی بوق می‌زند؛ پسیو فقط تق می‌کند.

const int BUZZER_PIN = 25;
const int notes[] = {262, 294, 330, 349, 392, 440, 494, 523};  // دو ر می فا سل لا سی دو

void setup() {
  ledcAttach(BUZZER_PIN, 2000, 10);   // اول پین را به LEDC وصل کن
}

void loop() {
  for (int i = 0; i < 8; i++) {
    ledcWriteTone(BUZZER_PIN, notes[i]);   // موج مربعی 50% با این فرکانس
    delay(250);
  }
  ledcWriteTone(BUZZER_PIN, 0);            // فرکانس صفر = سکوت
  delay(2000);
}
  1. آرایه فرکانس نت‌ها. هشت نت گام «دو» بر حسب هرتز (گرد شده). هر نت یک فرکانس مشخص دارد. «دو»ی بالا (۵۲۳) تقریبا دو برابر «دو»ی پایین (۲۶۲) است؛ یک اکتاو یعنی دو برابر شدن فرکانس.
  2. attach قبل از تون. در هسته ۳، ledcWriteTone روی پینی که attach نشده کاری نمی‌کند و صفر برمی‌گرداند. فرکانس و دقت اولیه مهم نیست؛ ledcWriteTone خودش آن‌ها را برای هر نت عوض می‌کند.
  3. نواختن هر نت ۲۵۰ms. ledcWriteTone یک موج مربعی ۵۰٪ با فرکانس نت می‌سازد. این‌جا Duty ثابت ۵۰٪ است و فرکانس تغییر می‌کند؛ برعکس LED که فرکانس ثابت بود و Duty تغییر می‌کرد.
  4. فرکانس صفر = سکوت. طبق مستندات، فرکانس صفر Duty را صفر می‌کند. بدون این خط، بازر آخرین نت را تا ابد می‌نوازد.

تمرین ۱: تنفس بدون delay

برنامه LED نفس‌کشنده را بدون هیچ delay با millis بازنویسی کن: هر ۸ میلی‌ثانیه Duty یک واحد در جهت فعلی عوض شود و در ۰ و ۲۵۵ جهت برعکس شود. بعد دکمه درس ۳.۱ (GPIO27) را اضافه کن که تنفس را متوقف و شروع کند.

راهنمایی

دو متغیر لازم داری: int duty = 0; و int step = 1;. هر بار که وقتش رسید: duty += step; if (duty <= 0 || duty >= 255) step = -step;. || یعنی «یا».

چه باید ببینی؟

این برنامه چیزی چاپ نمی‌کند؛ نتیجه را روی LED ببین:

  • LED در حدود ۲ ثانیه نرم روشن و در ۲ ثانیه نرم خاموش می‌شود: ۲۵۵ قدم × ۸ms ≈ ۲٫۰۴ ثانیه در هر جهت، یعنی هر «نفس» حدود ۴٫۱ ثانیه. در ۲۰ ثانیه تقریبا ۵ نفس کامل می‌بینی.
  • وسط تنفس دکمه (GPIO27) را بزن: نور در همان روشنایی می‌ایستد (نه خاموش می‌شود، نه کامل روشن).
  • دوباره بزن: تنفس از همان نقطه و در همان جهت ادامه می‌یابد، بدون پرش.
  • هر فشار فقط یک بار اثر دارد؛ اگر با یک فشار تنفس یک لحظه ایستاد و دوباره راه افتاد، Debounce درست نیست.
جواب کامل با توضیح 
const int LED_PIN = 4;
const int BUTTON_PIN = 27;
int duty = 0, step = 1;
unsigned long lastStep = 0;
bool paused = false;
int stableState = HIGH, lastReading = HIGH;
unsigned long lastChangeTime = 0;

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  ledcAttach(LED_PIN, 5000, 8);
}

void loop() {
  unsigned long now = millis();

  // دکمه (با Debounce)، مثل درس ۳.۱
  int reading = digitalRead(BUTTON_PIN);
  if (reading != lastReading) { lastChangeTime = now; lastReading = reading; }
  if (now - lastChangeTime > 30 && reading != stableState) {
    stableState = reading;
    if (stableState == LOW) paused = !paused;
  }

  // تنفس: هر ۸ms یک قدم، مگر در حالت مکث
  if (!paused && now - lastStep >= 8) {
    lastStep = now;
    duty += step;
    if (duty <= 0 || duty >= 255) step = -step;
    ledcWrite(LED_PIN, duty);
  }
}
  1. وضعیت تنفس. duty نور فعلی و step جهت (۱+ بالا، ۱− پایین). به جای دو حلقه for، یک «ماشین حالت» کوچک داریم که در هر دور loop فقط یک قدم برمی‌دارد.
  2. حافظه مکث و دکمه. paused می‌گوید تنفس متوقف است یا نه؛ سه متغیر دیگر همان متغیرهای Debounce درس ۳.۱ هستند. دکمه و تنفس دو کار جدا هستند و هر کدام متغیرهای خودش را دارد.
  3. دکمه با Debounce. همان منطق Toggle_Debounce درس ۳.۱، فقط هر فشار تأییدشده paused را برعکس می‌کند. فقط لحظه فشار دادن (LOW) را حساب می‌کنیم، نه رها کردن را؛ پس هر فشار = یک توقف یا ادامه.
  4. یک قدم هر ۸ms، مگر در حالت مکث. Duty یک واحد جلو می‌رود و در دو انتها جهت برعکس می‌شود. الگوی millis درس ۳.۱ عینا؛ loop هرگز منتظر نمی‌ماند، پس هیچ فشار دکمه‌ای گم نمی‌شود. در حالت مکث، LED همان نور فعلی را نگه می‌دارد.

دکمه سبز را در شبیه‌ساز بزن تا تنفس بایستد و دوباره ادامه یابد.

تمرین ۲: عقربه نور

مدار چراغ خواب درس ۳.۱ (LDR روی GPIO35) و سروو روی GPIO32 را ترکیب کن. سروو مثل عقربه یک نورسنج، مقدار نور را بین ۰ (تاریک) و ۱۸۰ (روشن) نشان بدهد.

راهنمایی

در مدار ما تاریکی = ولتاژ زیاد. پس map را برعکس بنویس: map(mv, 300, 3100, 180, 0) و بعد constrain. منطقه مرده ۲ درجه فراموش نشود.

چه باید ببینی؟

یک نمونه خروجی (عددهای میلی‌ولت به نور اتاقت بستگی دارند، ولی رابطه میلی‌ولت و زاویه باید دقیقا همین باشد):

LDR=1700 mV  angle=90
LDR=2400 mV  angle=45
LDR=2950 mV  angle=10
LDR=650 mV  angle=158
  • حساب کن: ۱۷۰۰mV باید ۹۰ درجه، ۲۴۰۰mV باید ۴۵ و ۲۹۵۰mV باید ۱۰ درجه بدهد. اگر عددهای تو با این رابطه نمی‌خوانند، map را اشتباه نوشته‌ای.
  • LDR را با دست بپوشان: عقربه به سمت ۰ می‌رود. چراغ قوه گوشی را رویش بگیر: به سمت ۱۸۰.
  • وقتی نور ثابت است، خط جدیدی چاپ نمی‌شود و سروو آرام است (منطقه مرده کار می‌کند).
  • زاویه هرگز از ۰ کمتر یا از ۱۸۰ بیشتر نمی‌شود، حتی در تاریکی کامل یا نور خیلی شدید.
جواب کامل با توضیح 
#include <ESP32Servo.h>

const int LDR_PIN = 35;                 // وسط تقسیم ولتاژ LDR (درس ۳.۱)
const int SERVO_PIN = 32;
Servo needle;                           // سروو همان «عقربه» ماست
int lastAngle = -1;                     // هنوز زاویه‌ای نوشته نشده

uint32_t readLdrMv() {
  uint32_t sum = 0;
  for (int i = 0; i < 8; i++) sum += analogReadMilliVolts(LDR_PIN);
  return sum / 8;                       // میانگین ۸ نمونه
}

void setup() {
  Serial.begin(115200);
  needle.setPeriodHertz(50);
  needle.attach(SERVO_PIN, 500, 2400);
}

void loop() {
  uint32_t mv = readLdrMv();
  int angle = map(mv, 300, 3100, 180, 0);   // تاریک = ولتاژ زیاد = ۰ درجه
  angle = constrain(angle, 0, 180);

  if (abs(angle - lastAngle) >= 2) {        // منطقه مرده ۲ درجه
    needle.write(angle);
    lastAngle = angle;
    Serial.printf("LDR=%lu mV  angle=%d\n", (unsigned long)mv, angle);
  }
  delay(50);
}
  1. دو قطعه آشنا. LDR روی GPIO35 از درس ۳.۱ و سروو روی GPIO32 از همین درس. lastAngle = -1 یعنی «هنوز چیزی ننوشته‌ایم». هر زاویه از ۱ تا ۱۸۰ دست‌کم ۲ درجه با ۱- فاصله دارد، پس اولین خواندن فورا نوشته می‌شود. تنها استثنا ۰ است (تاریکی کامل در لحظه روشن شدن)؛ آن وقت سروو همان‌جا که بود می‌ماند.
  2. میانگین ۸ نمونه. دقیقا همان تابع چراغ خواب. یک عقربه لرزان خواندنش سخت است؛ میانگین، نویز ADC را قبل از رسیدن به سروو کم می‌کند.
  3. map برعکس و constrain. ۳۰۰mV (نور زیاد) ← ۱۸۰ درجه و ۳۱۰۰mV (تاریک) ← ۰ درجه. مثلا ۱۷۰۰mV دقیقا ۹۰ درجه می‌شود. در مدار ما تاریکی ولتاژ را بالا می‌برد؛ پس جای ۱۸۰ و ۰ را عوض کردیم. map خروجی را محدود نمی‌کند (مثلا ۱۰۰mV به ۱۹۲ می‌رسد)، پس constrain لازم است تا سروو دستور غیرممکن نگیرد.
  4. منطقه مرده ۲ درجه. فقط وقتی زاویه دست‌کم ۲ درجه عوض شد، سروو حرکت می‌کند و یک خط چاپ می‌شود. همان روش Pot_Servo: بدون آن، سروو دائم یک درجه این‌ور و آن‌ور می‌لرزد و وزوز می‌کند.

قبل از اجرا کتابخانه ESP32Servo را از Library Manager ویکوی اضافه کن. روی ماژول نور کلیک کن و اسلایدر lux را حرکت بده؛ سروو باید دنبالش برود.

تمرین ۳: آژیر

با بازر یک آژیر بساز که فرکانس آن در ۱ ثانیه نرم از ۶۰۰ به ۱۲۰۰ هرتز برود و برگردد. بعد فکر کن: چرا این کار با تغییر Duty ممکن نبود؟

راهنمایی

یک حلقه for از ۶۰۰ تا ۱۲۰۰ با گام ۱۰ و delay(8)، و یک حلقه برعکس. ارتفاع صدا به فرکانس بستگی دارد؛ Duty فقط شدت و «رنگ» صدا را کمی عوض می‌کند.

  • صدا نرم بالا و پایین می‌رود، بدون پله‌های قابل شنیدن و بدون مکث در دو انتها.

جواب سؤال فکری: ارتفاع صدا (زیر و بمی) یعنی چند بار در ثانیه پرده بازر جلو و عقب می‌رود؛ این همان فرکانس است. Duty فقط پهنای هر پالس را در همان فرکانس ثابت عوض می‌کند؛ تعداد پالس‌ها در ثانیه همان می‌ماند، پس نت همان می‌ماند و فقط بلندی و «رنگ» صدا کمی عوض می‌شود (Duty پنجاه درصد بلندترین صدا را می‌دهد).

جواب کامل با توضیح 
// آژیر: ۶۰۰ ← ۱۲۰۰ هرتز و برگشت، حدود یک بار در ثانیه
const int BUZZER_PIN = 25;

void setup() {
  Serial.begin(115200);
  ledcAttach(BUZZER_PIN, 2000, 10);
}

void loop() {
  unsigned long start = millis();
  for (int f = 600; f < 1200; f += 10) {    // بالا: ۶۰۰، ۶۱۰ ... ۱۱۹۰ (۶۰ قدم)
    ledcWriteTone(BUZZER_PIN, f);
    delay(8);
  }
  for (int f = 1200; f > 600; f -= 10) {    // پایین: ۱۲۰۰، ۱۱۹۰ ... ۶۱۰ (۶۰ قدم)
    ledcWriteTone(BUZZER_PIN, f);
    delay(8);
  }
  Serial.printf("One cycle: %lu ms\n", millis() - start);
}
  1. همان آماده‌سازی بازر. بازر پسیو روی GPIO25 و ledcAttach مثل برنامه ملودی. پین باید قبل از ledcWriteTone به LEDC وصل شده باشد.
  2. رفتن به بالا. فرکانس از ۶۰۰ تا ۱۱۹۰ با گام ۱۰ هرتز، هر قدم ۸ms: ۶۰ قدم × ۸ms = ۴۸۰ms. گام ۱۰ هرتزی آن‌قدر کوچک است که گوش پله‌ها را نمی‌شنود و صدا «سُر» می‌خورد.
  3. برگشت و اندازه‌گیری. از ۱۲۰۰ تا ۶۱۰، باز ۶۰ قدم و ۴۸۰ms. در پایان زمان یک دور کامل چاپ می‌شود. شرط‌ها را < و > نوشتیم (نه ≤ و ≥) تا ۶۰۰ و ۱۲۰۰ دو بار پشت سر هم پخش نشوند. جمعا ۱۲۰ قدم × ۸ms = ۹۶۰ms، یعنی حدود یک ثانیه؛ چاپ زمان راهی است که خودت این را ثابت کنی.

صدای مرورگر را روشن کن؛ ویکوی صدای بازر را پخش می‌کند.

خلاصه درس در سه خط

PWM یعنی روشن و خاموش سریع با Duty متغیر؛ ولتاژ میانگین = ۳٫۳ × Duty، و قانون ESP32 کلاسیک: فرکانس × 2بیت ≤ 80MHz. در هسته ۳ فقط ledcAttach(pin, freq, res) و ledcWrite(pin, duty)؛ کد ledcSetup مال هسته ۲ است. سروو پالس ۵۰ هرتز با پهنای حدود ۰٫۵ تا ۲٫۴ms می‌خواهد (ESP32Servo یا حساب دستی ۱۶ بیتی)، و برقش را از منبع ۵ ولت کافی با زمین مشترک بگیر، نه از 3V3.
