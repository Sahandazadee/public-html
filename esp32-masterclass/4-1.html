شبکه از صفر: مودم، IP و DHCP

قبل از هر کدی باید بدانی وقتی می‌گوییم «ESP32 به Wi-Fi وصل شد» دقیقا چه اتفاقی می‌افتد. نگران نباش؛ فقط چند مفهوم ساده است.

شبکه یعنی چه؟

شبکه یعنی چند دستگاه که می‌توانند به هم پیام بفرستند. در خانه تو احتمالا گوشی، لپ‌تاپ و تلویزیون همه در یک شبکه هستند. وسط این شبکه یک جعبه هست که معمولا به آن «مودم» می‌گوییم. در واقع این جعبه دو کار انجام می‌دهد:

  • مودم (Modem): خط تلفن، فیبر یا سیم‌کارت را به اینترنت وصل می‌کند. در ارتباط با شرکت اینترنت (ISP) است.
  • روتر (Router): شبکه داخل خانه را می‌سازد، به هر دستگاه یک آدرس می‌دهد و پیام‌ها را بین دستگاه‌ها و اینترنت جابه‌جا می‌کند. آنتن‌های Wi-Fi هم مربوط به همین بخش است.

در بیشتر خانه‌ها هر دو کار در یک جعبه انجام می‌شود (مثلا مودم ADSL/VDSL یا مودم 4G). در این دوره هر جا «مودم» یا «روتر» گفتیم، منظور همان جعبه است.

مثال از زندگی روزمره: یک مجتمع آپارتمانی

شبکه خانه را مثل یک مجتمع مسکونی تصور کن. روتر، نگهبان ساختمان است. هر واحد (هر دستگاه) یک شماره واحد دارد (آدرس IP داخلی). کل مجتمع برای دنیای بیرون فقط یک آدرس پستی دارد (IP عمومی). وقتی نامه‌ای از بیرون می‌آید، به نگهبان می‌رسد و نگهبان می‌داند مال کدام واحد است. شماره سریال ثابت در هر واحد هم آدرس MAC است: هرگز عوض نمی‌شود، حتی اگر ساکن به واحد دیگری برود.

آدرس IP: شماره واحد هر دستگاه

هر دستگاه در شبکه یک آدرس IP دارد: چهار عدد بین ۰ تا ۲۵۵ که با نقطه جدا شده‌اند، مثل 192.168.1.37. هر پیامی که در شبکه می‌رود، آدرس فرستنده و گیرنده را با خودش دارد، درست مثل پاکت نامه.

DHCP: چه کسی شماره واحد را می‌دهد؟

تو هیچ‌وقت به گوشی‌ات نگفتی IP تو 192.168.1.23 باشد. روتر یک سرویس به اسم DHCP دارد که به هر دستگاه تازه‌وارد به طور خودکار یک IP آزاد «قرض» می‌دهد. این قرض مدت دارد (مثلا ۲۴ ساعت)؛ برای همین ممکن است IP برد تو فردا کمی فرق کند.

مثال با عدد: چهار قدم DHCP

ESP32 روشن می‌شود و فریاد می‌زند: «کسی به من IP می‌دهد؟» (Discover). روتر جواب می‌دهد: «192.168.1.37 آزاد است» (Offer). ESP32 می‌گوید: «همان را می‌خواهم» (Request). روتر تأیید می‌کند: «مال تو، برای ۸۶۴۰۰ ثانیه» (Ack). همه این‌ها معمولا زیر یک ثانیه طول می‌کشد. در کد ما، لحظه تمام شدن همین مرحله همان رویداد GOT_IP است.

می‌خواهی برد همیشه همان IP را داشته باشد؟

ساده‌ترین و تمیزترین راه در خود روتر است: بیشتر روترها صفحه‌ای به اسم «DHCP Reservation» (یا «Static Lease») دارند که در آن ESP32 را با آدرس MAC اش انتخاب می‌کنی و یک عدد ثابت به آن می‌دهی. کدت هیچ تغییری نمی‌کند. راه دیگر تنظیم در کد است، قبل از WiFi.begin: WiFi.config(IPAddress(192,168,1,50), IPAddress(192,168,1,1), IPAddress(255,255,255,0), IPAddress(192,168,1,1)); (آدرس، Gateway، ماسک زیرشبکه و یک سرور DNS). عددی بیرون از بازه‌ای که روتر با DHCP پخش می‌کند انتخاب کن، وگرنه ممکن است دو دستگاه یک آدرس بگیرند. در درس ۴.۲ با mDNS هم آشنا می‌شوی که اجازه می‌دهد برد را با اسم پیدا کنی، پس عدد کمتر مهم می‌شود.

SSID، رمز و MAC

  • SSID اسم شبکه Wi-Fi است؛ همان چیزی که در لیست Wi-Fi گوشی می‌بینی (مثلا Home یا Home_5G). به بزرگی و کوچکی حروف حساس است: Home و home دو شبکه متفاوت‌اند.
  • رمز (Password) در شبکه‌های WPA2 باید بین ۸ تا ۶۳ حرف باشد. ESP32 هم دقیقا حرف به حرف مقایسه می‌کند.
  • آدرس MAC یک شناسه ۶ بایتی است که در کارخانه روی چیپ نوشته شده، مثل 24:0A:C4:12:34:56. روتر با آن دستگاه‌ها را از هم تشخیص می‌دهد. بعضی روترها فقط به MACهای «مجاز» اجازه ورود می‌دهند (MAC Filtering).

۲٫۴ گیگاهرتز: مهم‌ترین دام مبتدی‌ها

Wi-Fi روی دو «باند» فرکانسی کار می‌کند: ۲٫۴ گیگاهرتز (برد بیشتر، سرعت کمتر، از دیوار بهتر رد می‌شود) و ۵ گیگاهرتز (سرعت بیشتر، برد کمتر). ESP32 فقط ۲٫۴ گیگاهرتز را پشتیبانی می‌کند (استاندارد 802.11 b/g/n). یعنی شبکه ۵ گیگاهرتزی را اصلا نمی‌بیند؛ نه این که ببیند و وصل نشود.

دقت کن: شبکه ۵ گیگاهرتزی در اسکن ESP32 ظاهر نمی‌شود

بسیاری از مودم‌های جدید دو شبکه می‌سازند، مثلا Home و Home_5G. ESP32 را همیشه به همان که ۵G ندارد وصل کن. اگر مودم تو هر دو باند را با یک اسم پخش می‌کند (Band Steering)، معمولا مشکلی نیست و ESP32 به بخش ۲٫۴ وصل می‌شود؛ ولی اگر باند ۲٫۴ در تنظیمات مودم خاموش باشد، ESP32 هرگز وصل نمی‌شود. هات‌اسپات آیفون هم گاهی روی ۵ گیگاهرتز می‌رود؛ گزینه Maximize Compatibility را روشن کن. (استثنای نادر: تراشه جدید ESP32-C5 دوباندی است، ولی برد این دوره ESP32 معمولی است.)

RSSI: قدرت سیگنال به زبان عدد

RSSI قدرت سیگنال دریافتی است و واحدش dBm است. عددها منفی هستند و هر چه به صفر نزدیک‌تر، قوی‌تر. یعنی ‎−45 از ‎−80 خیلی بهتر است. هر ۳ dB یعنی نصف یا دو برابر شدن توان؛ پس فرق ‎−60 با ‎−70 خیلی بیشتر از «کمی» است: توان حدود ۱۰ برابر کمتر شده.

سه نقش ESP32 در Wi-Fi: STA، AP و AP+STA

ESP32 می‌تواند در Wi-Fi سه نقش بازی کند:

  • Station یا STA (ایستگاه): مثل گوشی تو به مودم خانه وصل می‌شود. از مودم IP می‌گیرد و به اینترنت دسترسی دارد. ۹۰٪ پروژه‌ها این حالت‌اند.
  • Access Point یا AP (نقطه دسترسی): خود ESP32 یک شبکه Wi-Fi می‌سازد. گوشی تو مستقیم به ESP32 وصل می‌شود. اینترنت ندارد، ولی برای جاهایی که مودم نیست (باغ، کارگاه) یا برای صفحه تنظیمات اولیه عالی است. IP پیش‌فرض خود ESP32 در این حالت 192.168.4.1 است.
  • AP+STA: هر دو با هم. به مودم وصل است و هم‌زمان شبکه خودش را هم دارد. کتابخانه WiFiManager (پایین‌تر) از همین استفاده می‌کند.

چرا بیشتر وقت‌ها STA؟

در حالت STA، ESP32 به اینترنت دسترسی دارد (ساعت، MQTT، ابر) و همه دستگاه‌های خانه می‌توانند آن را پیدا کنند. در حالت AP، هر کس بخواهد با برد حرف بزند باید از Wi-Fi خودش جدا شود و به ESP32 وصل شود؛ یعنی گوشی‌اش اینترنت ندارد. برای همین AP بیشتر برای «راه‌اندازی اولیه» و جاهای بدون مودم است.

این برنامه کوتاه ESP32 را در حالت AP می‌برد تا ببینی چقدر ساده است:

#include <WiFi.h>

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_AP);                              // فقط Access Point
  bool ok = WiFi.softAP("ESP32-Setup", "12345678"); // اسم و رمز (حداقل ۸ حرف)
  Serial.println(ok ? "AP started" : "AP failed");
  Serial.print("AP IP: ");
  Serial.println(WiFi.softAPIP());                 // معمولا 192.168.4.1
}

void loop() {
  Serial.printf("Clients connected: %d\n", WiFi.softAPgetStationNum());
  delay(3000);
}
  1. کتابخانه WiFi. WiFi.h همراه پکیج ESP32 نصب شده؛ لازم نیست از Library Manager چیزی نصب کنی. همه کارهای Wi-Fi (STA، AP، اسکن، رویدادها) از همین یک کتابخانه و از شیء آماده‌ای به اسم WiFi انجام می‌شود.
  2. WiFi.mode(WIFI_AP). نقش برد را «فقط نقطه دسترسی» می‌کند. گزینه‌های دیگر WIFI_STA و WIFI_AP_STA هستند. صریح گفتن نقش، رفتار را قابل پیش‌بینی می‌کند. ESP32 تنظیمات قبلی Wi-Fi را در حافظه نگه می‌دارد؛ اگر نقش را نگویی، ممکن است با نقشی که از برنامه قبلی مانده شروع کند.
  3. WiFi.softAP(اسم، رمز). شبکه‌ای به اسم ESP32-Setup با رمز 12345678 می‌سازد و اگر موفق شود true برمی‌گرداند. رمز WPA2 باید حداقل ۸ حرف باشد. اگر کوتاه‌تر بدهی، softAP شکست می‌خورد. همیشه نتیجه را چاپ کن تا اگر شکست خورد، بدانی.
  4. WiFi.softAPIP(). آدرس خود ESP32 در شبکه‌ای که ساخته، معمولا 192.168.4.1. در این حالت ESP32 خودش نقش روتر را دارد و DHCP هم اجرا می‌کند؛ گوشی تو IPهایی مثل 192.168.4.2 می‌گیرد.
  5. شمارش مهمان‌ها. softAPgetStationNum() تعداد دستگاه‌های وصل را می‌دهد. با گوشی به ESP32-Setup وصل شو و ببین عدد زیاد می‌شود. یک آزمایش ساده که ثابت می‌کند شبکه واقعا کار می‌کند. پیش‌فرض ESP32 حداکثر ۴ مهمان هم‌زمان است.

از این به بعد در این درس فقط حالت STA را کار می‌کنیم.

قدم اول: ببین ESP32 چه شبکه‌هایی می‌بیند (اسکنر Wi-Fi)

قبل از وصل شدن، بهتر است مطمئن شوی ESP32 اصلا شبکه تو را می‌بیند. این برنامه هر ۱۰ ثانیه شبکه‌های اطراف را فهرست می‌کند. مثل وقتی که لیست Wi-Fi گوشی را باز می‌کنی.

#include <WiFi.h>                 // کتابخانه داخلی Wi-Fi (نصب لازم ندارد)

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);            // حالت ایستگاه (مثل گوشی)
  WiFi.disconnect();              // اگر از قبل به جایی وصل بود، قطع کن
  delay(100);
  Serial.print("My MAC address: ");
  Serial.println(WiFi.macAddress());
}

void loop() {
  Serial.println("Scanning...");
  int n = WiFi.scanNetworks();    // حدود ۲ تا ۴ ثانیه طول می‌کشد

  if (n <= 0) {
    Serial.println("No networks found");
  } else {
    Serial.printf("%d networks found:\n", n);
    for (int i = 0; i < n; i++) {
      Serial.printf("%2d | %-24s | %4d dBm | ch %2d | %s\n",
                    i + 1,
                    WiFi.SSID(i).c_str(),
                    WiFi.RSSI(i),
                    WiFi.channel(i),
                    WiFi.encryptionType(i) == WIFI_AUTH_OPEN ? "open" : "locked");
    }
  }
  WiFi.scanDelete();              // حافظه نتیجه اسکن را آزاد کن
  Serial.println();
  delay(10000);                   // ۱۰ ثانیه بعد دوباره اسکن
}
  1. حالت STA و قطع اتصال قبلی. برای اسکن باید برد در حالت ایستگاه باشد. WiFi.disconnect() اتصال احتمالی قبلی را قطع می‌کند و delay(100) فرصت کوتاهی برای آماده شدن رادیو می‌دهد. اگر برد وسط تلاش برای وصل شدن باشد، اسکن ممکن است شکست بخورد یا نتیجه ناقص بدهد. «اول آرام، بعد اسکن».
  2. چاپ آدرس MAC. WiFi.macAddress() آدرس MAC برد را به صورت متن برمی‌گرداند. اگر روتر تو MAC Filtering دارد، باید همین عدد را در تنظیمات روتر اضافه کنی. بهتر است همین اول کار آن را یادداشت کنی.
  3. WiFi.scanNetworks(). رادیو را روی همه کانال‌های ۲٫۴ گیگاهرتز می‌چرخاند و تعداد شبکه‌های پیدا شده را برمی‌گرداند. در این مدت (حدود ۲ تا ۴ ثانیه) برنامه منتظر می‌ماند. برای یک ابزار عیب‌یابی، منتظر ماندن اشکالی ندارد. اگر عدد منفی برگردد (−۱ یعنی هنوز در حال اسکن، −۲ یعنی شکست) آن را «چیزی پیدا نشد» حساب می‌کنیم؛ برای همین شرط n <= 0 است، نه n == 0.
  4. چاپ هر شبکه در یک خط. Serial.printf مثل print است ولی با الگو: %d جای عدد صحیح، %s جای متن، %-24s یعنی متن را در ۲۴ خانه چپ‌چین کن. برای هر شبکه اسم (SSID(i))، قدرت سیگنال (RSSI(i))، کانال و قفل بودن را چاپ می‌کنیم. جدول مرتب خیلی راحت‌تر از خط‌های درهم خوانده می‌شود. .c_str() لازم است چون %s متن سبک C می‌خواهد نه شیء String. عبارت شرط ? الف : ب یک if کوتاه است: اگر شبکه باز بود «open» وگرنه «locked».
  5. WiFi.scanDelete(). حافظه‌ای را که نتیجه اسکن گرفته بود آزاد می‌کند. اگر در یک حلقه بی‌پایان اسکن کنی و حافظه را آزاد نکنی، به مرور حافظه پر می‌شود. عادت خوب: هر چه گرفتی، پس بده.

قدم دوم: وصل شدن با سقف زمان

ساده‌ترین کد اتصال که در اینترنت می‌بینی این است: while (WiFi.status() != WL_CONNECTED) delay(500);. مشکلش؟ اگر رمز اشتباه باشد، برد تا ابد در این حلقه می‌ماند و هیچ پیامی هم نمی‌دهد. ما نسخه بهتری می‌نویسیم که حداکثر ۱۵ ثانیه صبر کند و علت شکست را بگوید.

#include <WiFi.h>

const char* WIFI_SSID = "Wokwi-GUEST";    // نام شبکه خودت را اینجا بنویس
const char* WIFI_PASS = "";               // رمز شبکه (برای Wokwi خالی)
const unsigned long TIMEOUT_MS = 15000;   // حداکثر ۱۵ ثانیه صبر

// عدد وضعیت را به یک اسم قابل فهم تبدیل می‌کند
const char* statusName(wl_status_t s) {
  switch (s) {
    case WL_IDLE_STATUS:     return "IDLE (0)";
    case WL_NO_SSID_AVAIL:   return "NO_SSID_AVAIL (1)";
    case WL_CONNECTED:       return "CONNECTED (3)";
    case WL_CONNECT_FAILED:  return "CONNECT_FAILED (4)";
    case WL_CONNECTION_LOST: return "CONNECTION_LOST (5)";
    case WL_DISCONNECTED:    return "DISCONNECTED (6)";
    default:                 return "OTHER";
  }
}

bool connectWiFi() {
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  Serial.printf("Connecting to %s", WIFI_SSID);

  unsigned long start = millis();
  while (WiFi.status() != WL_CONNECTED) {
    if (millis() - start > TIMEOUT_MS) {            // سقف زمان
      Serial.printf("\nFailed! status = %s\n", statusName(WiFi.status()));
      return false;
    }
    Serial.print(".");
    delay(500);
  }
  Serial.println("\nConnected!");
  return true;
}

void setup() {
  Serial.begin(115200);
  if (connectWiFi()) {
    Serial.print("IP address : "); Serial.println(WiFi.localIP());
    Serial.print("Gateway    : "); Serial.println(WiFi.gatewayIP());
    Serial.print("MAC address: "); Serial.println(WiFi.macAddress());
    Serial.printf("RSSI       : %d dBm\n", WiFi.RSSI());
  } else {
    Serial.println("Check SSID, password, and that the network is 2.4 GHz");
  }
}

void loop() {
  static unsigned long last = 0;
  if (millis() - last >= 5000) {                    // هر ۵ ثانیه
    last = millis();
    Serial.printf("status=%s  RSSI=%d dBm\n", statusName(WiFi.status()), WiFi.RSSI());
  }
}
  1. اسم شبکه، رمز و سقف زمان. const char* یعنی «یک متن ثابت». برای Wokwi اسم Wokwi-GUEST و رمز خالی است؛ روی برد واقعی اسم و رمز شبکه خودت را بنویس. unsigned long نوع مناسب برای میلی‌ثانیه است. گذاشتن این‌ها بالای برنامه یعنی برای تغییر شبکه لازم نیست در کد بگردی. (کمی بعد یاد می‌گیری چرا بهتر است رمز اصلا در این فایل نباشد.)
  2. تبدیل کد وضعیت به اسم. WiFi.status() یک عدد برمی‌گرداند. این تابع با switch آن عدد را به یک اسم قابل فهم تبدیل می‌کند. «status = 1» چیزی به تو نمی‌گوید؛ «NO_SSID_AVAIL» یعنی «شبکه‌ای با این اسم پیدا نشد». لاگ خوانا یعنی عیب‌یابی سریع.
  3. شروع اتصال. WiFi.mode(WIFI_STA) نقش ایستگاه را انتخاب می‌کند و WiFi.begin(اسم، رمز) تلاش برای اتصال را شروع می‌کند و فورا برمی‌گردد. نکته کلیدی: begin منتظر نمی‌ماند تا اتصال تمام شود. اتصال در پس‌زمینه ادامه دارد و ما باید وضعیت را بپرسیم. همین ویژگی است که بعدا اجازه می‌دهد برنامه‌ای بنویسیم که هیچ‌وقت گیر نکند.
  4. حلقه انتظار با سقف. زمان شروع را در start نگه می‌داریم. تا وقتی وصل نشده‌ایم، هر ۵۰۰ میلی‌ثانیه یک نقطه چاپ می‌کنیم؛ ولی اگر millis() - start از ۱۵۰۰۰ بیشتر شد، با پیام خطا و مقدار false بیرون می‌آییم. این همان الگوی millis() درس ۳.۱ است. نقطه‌ها نشان می‌دهند برنامه زنده است. سقف زمان تضمین می‌کند برد هرگز بی‌صدا گیر نکند. ۱۵ ثانیه کافی است: اتصال عادی معمولا ۲ تا ۵ ثانیه طول می‌کشد.
  5. چاپ اطلاعات شبکه. اگر وصل شد: IP خود برد (localIP)، IP روتر (gatewayIP)، MAC و قدرت سیگنال (RSSI). اگر نشد، یک راهنمای کوتاه چاپ می‌کنیم. IP را در درس بعد لازم داری تا از مرورگر به برد وصل شوی. RSSI اولین عددی است که وقتی اتصال ناپایدار است باید نگاهش کنی.
  6. loop غیرمسدود. هر ۵ ثانیه وضعیت و RSSI را چاپ می‌کند. کلمه static یعنی متغیر last فقط یک بار صفر می‌شود و بین دورهای loop مقدارش حفظ می‌شود. با این لاگ می‌توانی برد را در خانه جابه‌جا کنی و ببینی سیگنال کجا ضعیف می‌شود؛ یک «سیگنال‌سنج» مجانی.

رمز Wi-Fi را از کد بیرون بکش (الگوی secrets.h)

تا الان رمز را مستقیم در کد نوشتیم. حالا تصور کن کد را در GitHub می‌گذاری یا برای دوستت در تلگرام می‌فرستی تا کمکت کند: رمز Wi-Fi خانه‌ات هم با آن رفته است! راه حل حرفه‌ای این است که رمزها در یک فایل جدا باشند که هیچ‌وقت منتشر نمی‌شود.

مثال از زندگی روزمره

دستور پخت یک کیک را می‌توانی به همه بدهی، ولی کلید خانه‌ات را لای کتاب آشپزی نمی‌گذاری. کد برنامه همان دستور پخت است و secrets.h همان کلید که جدا در جیبت نگه می‌داری.

  1. فایل جدید بساز. در Arduino IDE روی فلش کوچک ⋯ کنار اسم تب‌ها (بالا سمت راست ویرایشگر) بزن و New Tab را انتخاب کن. اسمش را دقیقا secrets.h بگذار. این فایل کنار فایل .ino در همان پوشه ذخیره می‌شود.
  2. رمزها را در آن بنویس:
#pragma once
// رمزها فقط اینجا. این فایل را هرگز در GitHub یا گروه تلگرام نگذار.
#define WIFI_SSID "MyHomeWiFi"
#define WIFI_PASS "my-strong-password"
  1. #pragma once. به کامپایلر می‌گوید این فایل را حتی اگر چند بار include شد، فقط یک بار بخوان. بدون آن، اگر دو فایل مختلف secrets.h را include کنند، خطای «تعریف تکراری» می‌گیری.
  2. #define. یک «جایگزین متنی» می‌سازد: هر جا کامپایلر WIFI_SSID دید، آن را با "MyHomeWiFi" عوض می‌کند. ساده‌ترین روش برای ثابت‌هایی که فقط یک بار تعریف می‌شوند. اگر رمزت علامت " یا \ دارد، باید قبلش یک \ بگذاری: مثلا رمز ab"c را "ab\"c" بنویس.
  1. در برنامه اصلی بنویس #include "secrets.h" (با گیومه، نه <>؛ گیومه یعنی «در پوشه خود پروژه دنبالش بگرد»).
  2. اگر از Git استفاده می‌کنی، یک فایل .gitignore در پوشه پروژه بساز و این خط را در آن بنویس تا Git هیچ‌وقت secrets.h را برندارد:
secrets.h
  1. اسم فایلی که نباید منتشر شود. Git هر فایلی را که اسمش در .gitignore است نادیده می‌گیرد. برای این که دیگران بدانند چه فایلی بسازند، معمولا یک نسخه نمونه با اسم secrets_example.h و مقادیر ساختگی منتشر می‌کنند (پایین).
#pragma once
// این نسخه نمونه است و در GitHub می‌رود؛ مقادیر واقعی در secrets.h

#define WIFI_PASS "YOUR_WIFI_PASSWORD"
  1. مقادیر ساختگی. هر کس پروژه را دانلود کند، این فایل را کپی می‌کند، اسمش را secrets.h می‌گذارد و رمز خودش را می‌نویسد. پروژه برای همه قابل ساخت می‌ماند و رمز هیچ‌کس لو نمی‌رود.
رمز روی خود برد مخفی نیست

secrets.h فقط جلوی لو رفتن رمز از طریق کد منبع را می‌گیرد. رمز هنوز داخل برنامه کامپایل‌شده روی فلش برد است و کسی که برد را در دست داشته باشد می‌تواند آن را بخواند (مگر با Flash Encryption که موضوع پیشرفته‌ای است). پس برد را در جای عمومی رها نکن.

WiFiManager: تنظیم Wi-Fi از روی گوشی (معرفی کوتاه)

اگر دستگاهی بسازی و به کس دیگری بدهی، او نمی‌تواند رمز Wi-Fi خانه‌اش را در کد بنویسد و دوباره آپلود کند. کتابخانه WiFiManager (در Library Manager عبارت WiFiManager را جست‌وجو کن و از میان چند نتیجه هم‌اسم، دقیقا WiFiManager by tzapu نسخه 2.0.17 یا جدیدتر را نصب کن؛ وابستگی دیگری نمی‌خواهد) این مشکل را حل می‌کند: اگر برد نتواند وصل شود، در حالت AP یک شبکه باز می‌کند؛ کاربر با گوشی به آن وصل می‌شود، یک صفحه تنظیمات خودکار باز می‌شود (Captive Portal، مثل Wi-Fi هتل‌ها)، شبکه و رمز را انتخاب می‌کند و برد آن‌ها را در حافظه خودش ذخیره می‌کند.

#include <WiFiManager.h>              // کتابخانه tzapu/WiFiManager

void setup() {
  Serial.begin(115200);
  WiFiManager wm;
  wm.setConfigPortalTimeout(180);     // حداکثر ۳ دقیقه منتظر تنظیم بمان
  // اگر رمز ذخیره‌شده کار کند، مستقیم وصل می‌شود؛
  // وگرنه یک Wi-Fi به اسم ESP32-Setup می‌سازد و منتظر تنظیم از گوشی می‌ماند
  bool ok = wm.autoConnect("ESP32-Setup", "setup1234");
  Serial.println(ok ? "Connected!" : "Config portal timed out");
}

void loop() {}
  1. کتابخانه و شیء مدیر. WiFiManager wm; یک مدیر Wi-Fi می‌سازد. همه کار پیچیده (AP، صفحه وب، ذخیره رمز) داخل این کتابخانه است؛ تو فقط چند خط می‌نویسی.
  2. سقف زمان پورتال. اگر در ۱۸۰ ثانیه کسی تنظیم نکرد، autoConnect با false برمی‌گردد. بدون این خط، برد تا ابد منتظر تنظیم می‌ماند؛ همان «گیر کردن» که در این درس با آن می‌جنگیم.
  3. autoConnect. اول با رمز ذخیره‌شده امتحان می‌کند؛ اگر نشد شبکه ESP32-Setup با رمز setup1234 را می‌سازد. با گوشی به آن وصل شو؛ اگر صفحه خودش باز نشد، در مرورگر 192.168.4.1 را بزن. این همان حالت AP+STA است که بالاتر دیدی، در عمل.

قدم سوم: اتصال پایدار و اتصال دوباره خودکار

حالا مهم‌ترین بخش درس. در دنیای واقعی Wi-Fi قطع می‌شود: مودم شب‌ها ریست می‌شود، برق می‌رود و می‌آید، کسی مایکروویو را روشن می‌کند (مایکروویو هم روی ۲٫۴ گیگاهرتز کار می‌کند!). برنامه خوب سه ویژگی دارد:

  1. هیچ‌وقت منتظر Wi-Fi نمی‌ماند. اگر برد علاوه بر Wi-Fi دکمه، سنسور یا موتور هم دارد، آن‌ها باید حتی وقتی شبکه قطع است کار کنند.
  2. خودش برمی‌گردد. بدون نیاز به ریست دستی.
  3. می‌گوید چه شده. علت قطعی را چاپ می‌کند.
مثال از زندگی روزمره: زنگ در به جای سر زدن مدام به در

فرض کن منتظر پستچی هستی. روش بد: هر ۱۰ ثانیه بروی در را باز کنی ببینی آمده یا نه، و در این مدت هیچ کار دیگری نکنی. روش خوب: کارهایت را بکنی و وقتی زنگ در به صدا درآمد، واکنش نشان بدهی. «رویدادهای Wi-Fi» (Events) همان زنگ در هستند: کتابخانه Wi-Fi هر وقت اتفاقی افتاد (وصل شد، IP گرفت، قطع شد) تابعی را که تو معرفی کرده‌ای صدا می‌زند.

سه ابزار ما

  • WiFi.setAutoReconnect(true): به خود کتابخانه می‌گوید اگر اتصال قطع شد، خودش دوباره تلاش کند. (در core 3.x پیش‌فرض روشن است؛ ما صریح می‌نویسیم تا مطمئن باشیم.)
  • WiFi.onEvent(تابع): تابع ما را به عنوان «زنگ در» ثبت می‌کند.
  • نگهبان با millis(): اگر با وجود همه این‌ها مدتی آفلاین ماندیم، هر ۱۰ ثانیه یک بار خودمان تلاش مجدد را هل می‌دهیم؛ بدون این که loop را متوقف کنیم.

نقشه سیم‌کشی: LED وضعیت شبکه

یک LED روی GPIO4 می‌گذاریم تا بدون Serial Monitor هم وضعیت را ببینی: ثابت روشن = وصل، چشمک سریع = قطع. سیم‌کشی دقیقا همان درس ۲.۲ است.

برنامه زیر به فایل secrets.h که بالاتر ساختی نیاز دارد:

#include <WiFi.h>
#include <time.h>
#include "secrets.h"                          // WIFI_SSID و WIFI_PASS اینجا هستند

const int LED_PIN = 4;                        // LED وضعیت شبکه
const unsigned long RETRY_MS = 10000;         // هر ۱۰ ثانیه یک بار تلاش دستی
const char* TZ_INFO = "EST5EDT,M3.2.0,M11.1.0"; // تورنتو/نیویورک: مال خودت را بگذار

volatile bool wifiUp = false;                 // آیا الان IP داریم؟
unsigned long lastRetry = 0, lastBlink = 0, lastPrint = 0;
bool ledState = false;

// این تابع را خود کتابخانه Wi-Fi صدا می‌زند، هر وقت اتفاقی بیفتد
void onWiFiEvent(WiFiEvent_t event, WiFiEventInfo_t info) {
  switch (event) {
    case ARDUINO_EVENT_WIFI_STA_CONNECTED:
      Serial.println("[WiFi] Linked to router, waiting for IP...");
      break;
    case ARDUINO_EVENT_WIFI_STA_GOT_IP:
      wifiUp = true;
      Serial.print("[WiFi] Got IP: ");
      Serial.println(IPAddress(info.got_ip.ip_info.ip.addr));
      break;
    case ARDUINO_EVENT_WIFI_STA_DISCONNECTED:
      wifiUp = false;
      Serial.printf("[WiFi] Disconnected, reason %d (%s)\n",
                    info.wifi_sta_disconnected.reason,
                    WiFi.disconnectReasonName((wifi_err_reason_t)info.wifi_sta_disconnected.reason));
      break;
    default:
      break;
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);

  WiFi.onEvent(onWiFiEvent);                  // قبل از begin ثبت کن
  WiFi.setHostname("esp32-lab");              // اسم برد در لیست مودم
  WiFi.mode(WIFI_STA);
  WiFi.setAutoReconnect(true);                // بعد از قطعی، خودش دوباره وصل شود
  WiFi.begin(WIFI_SSID, WIFI_PASS);           // منتظر نمی‌مانیم!
  Serial.println("[WiFi] Connecting in background...");

  configTzTime(TZ_INFO, "pool.ntp.org", "time.google.com");
}

void loop() {
  unsigned long now = millis();

  // ۱) نگهبان: اگر هنوز آفلاینیم، هر ۱۰ ثانیه یک هل کوچک بده
  if (!wifiUp && now - lastRetry >= RETRY_MS) {
    lastRetry = now;
    Serial.println("[WiFi] Still offline -> reconnect()");
    WiFi.disconnect();
    WiFi.reconnect();
  }

  // ۲) LED: وصل = ثابت روشن، قطع = چشمک سریع
  if (wifiUp) {
    ledState = true;
  } else if (now - lastBlink >= 200) {
    lastBlink = now;
    ledState = !ledState;
  }
  digitalWrite(LED_PIN, ledState ? HIGH : LOW);

  // ۳) هر ۵ ثانیه ساعت و قدرت سیگنال را چاپ کن
  if (now - lastPrint >= 5000) {
    lastPrint = now;
    struct tm t;
    if (getLocalTime(&t, 10)) {               // حداکثر ۱۰ میلی‌ثانیه صبر
      char buf[24];
      strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M:%S", &t);
      Serial.printf("[Time] %s  RSSI %d dBm\n", buf, WiFi.RSSI());
    } else {
      Serial.println("[Time] not synced yet");
    }
  }
}

  2. ثابت‌ها. پین LED، فاصله تلاش مجدد (۱۰ ثانیه) و رشته منطقه زمانی (این‌جا تورنتو و نیویورک؛ رشته شهر خودت را می‌گذاری و پایین‌تر مفصل توضیح می‌دهیم). ۱۰ ثانیه تعادل خوبی است: آن‌قدر کوتاه که بعد از برگشتن مودم زود وصل شویم، آن‌قدر بلند که با تلاش‌های پشت سر هم مودم و خودمان را خسته نکنیم.
  3. متغیرهای وضعیت. wifiUp می‌گوید الان IP داریم یا نه. کلمه volatile به کامپایلر می‌گوید «این متغیر ممکن است از جای دیگری عوض شود، هر بار واقعا از حافظه بخوانش». تابع رویداد در یک Task (رشته اجرایی) جدا از loop اجرا می‌شود. volatile جلوی این را می‌گیرد که loop یک نسخه قدیمی از مقدار را در ثبات‌های پردازنده نگه دارد و تغییر را نبیند.
  4. تابع رویداد. امضای آن در core 3.x دقیقا (WiFiEvent_t event, WiFiEventInfo_t info) است. event می‌گوید چه اتفاقی افتاده و info جزئیات آن را دارد. با switch فقط به سه رویداد مهم واکنش می‌دهیم و بقیه را (default) نادیده می‌گیریم. کتابخانه ده‌ها رویداد دارد (شروع اسکن، شروع AP و…). لازم نیست همه را بشناسی؛ این سه برای یک ایستگاه کافی است.
  5. STA_CONNECTED. ESP32 با روتر «دست داد» و رمز پذیرفته شد، ولی هنوز IP ندارد. فرق CONNECTED و GOT_IP مهم است: بدون IP هنوز نمی‌توانی هیچ پیامی بفرستی. اگر این خط را دیدی ولی GOT_IP نیامد، مشکل از DHCP روتر است، نه رمز.
  6. STA_GOT_IP: حالا واقعا آنلاینیم. wifiUp را true می‌کنیم و IP را از داخل info چاپ می‌کنیم. IPAddress(...) عدد خام را به شکل آشنای 192.168.1.37 درمی‌آورد. «آنلاین بودن» را به GOT_IP گره می‌زنیم نه به CONNECTED، چون فقط از این لحظه ارسال داده ممکن است.

  8. ثبت زنگ در. WiFi.onEvent(onWiFiEvent) تابع ما را معرفی می‌کند. این کار قبل از begin انجام می‌شود. اگر بعد از begin ثبت کنی، ممکن است اتصال آن‌قدر سریع برقرار شود که رویداد GOT_IP را از دست بدهی و wifiUp تا ابد false بماند.
  9. اسم میزبان، حالت، اتصال خودکار و شروع. setHostname اسمی است که در لیست دستگاه‌های مودم می‌بینی. setAutoReconnect(true) تلاش مجدد خودکار را روشن می‌کند. begin اتصال را شروع می‌کند و برنامه بدون صبر ادامه می‌دهد. به جای «esp32-A1B2C3» در لیست مودم، «esp32-lab» می‌بینی و دستگاهت را راحت پیدا می‌کنی. اسم میزبان باید قبل از mode و begin تنظیم شود، وگرنه اعمال نمی‌شود. و مهم‌تر: هیچ حلقه انتظاری در setup نیست؛ برد در همان ثانیه اول وارد loop می‌شود.
  10. راه‌اندازی NTP. configTzTime منطقه زمانی و دو سرور ساعت را تنظیم می‌کند. از این به بعد ESP32 خودش، در پس‌زمینه، ساعت را از اینترنت می‌گیرد (همین که اتصال برقرار شد) و هر یک ساعت یک بار دوباره تنظیم می‌کند. آن را بعد از WiFi.mode صدا می‌زنیم تا پشته شبکه (TCP/IP) راه افتاده باشد. دو سرور می‌دهیم که اگر یکی جواب نداد، دیگری جواب بدهد. توضیح کامل در بخش NTP.
  11. نگهبان. اگر آفلاینیم و ۱۰ ثانیه از آخرین تلاش گذشته، disconnect() و بعد reconnect() را صدا می‌زنیم. این دو تابع فوری برمی‌گردند. auto-reconnect در بیشتر موارد کافی است، ولی در بعضی حالت‌ها (مثلا مودمی که مدت طولانی خاموش بوده) کتابخانه از تلاش دست می‌کشد. این نگهبان تضمین می‌کند برد هرگز «برای همیشه» آفلاین نماند. چون فقط هر ۱۰ ثانیه یک بار اجرا می‌شود، loop هزاران بار در ثانیه آزادانه می‌چرخد.
  12. LED وضعیت بدون delay. وصل: LED ثابت روشن. قطع: هر ۲۰۰ میلی‌ثانیه وضعیت LED برعکس می‌شود (چشمک ۲٫۵ بار در ثانیه). این بخش ثابت می‌کند loop هرگز گیر نمی‌کند: حتی وقتی شبکه قطع است، چشمک زدن منظم ادامه دارد. اگر جایی از برنامه delay طولانی یا حلقه انتظار بود، چشمک‌ها می‌ایستادند. متغیر ledState را خودمان نگه می‌داریم به جای این که وضعیت پین را بخوانیم؛ ساده‌تر و مطمئن‌تر است.
  13. چاپ ساعت هر ۵ ثانیه. getLocalTime(&t, 10) ساعت فعلی را در ساختار t می‌ریزد. عدد ۱۰ یعنی حداکثر ۱۰ میلی‌ثانیه صبر کن. strftime ساعت را با الگوی %Y-%m-%d %H:%M:%S به متن تبدیل می‌کند. پیش‌فرض getLocalTime تا ۵۰۰۰ میلی‌ثانیه صبر است؛ یعنی وقتی اینترنت نیست، loop هر بار ۵ ثانیه گیر می‌کند و LED از چشمک زدن می‌ایستد! با عدد ۱۰ این دام را برداشتیم. اگر ساعت هنوز همگام نشده، false برمی‌گرداند و ما «not synced yet» چاپ می‌کنیم.

ساعت دقیق از اینترنت: NTP و منطقه زمانی تو

ESP32 ساعت باتری‌دار ندارد. هر بار که روشن می‌شود، فکر می‌کند سال ۱۹۷۰ است! ولی وقتی به اینترنت وصل است، می‌تواند از سرورهای NTP (Network Time Protocol) ساعت دقیق جهانی را بپرسد. pool.ntp.org یک مجموعه جهانی و رایگان از هزاران سرور ساعت است.

مثال از زندگی روزمره

مثل وقتی که ساعت مچی‌ات را با اعلام ساعت رادیو تنظیم می‌کنی. رادیو ساعت گرینویچ (UTC) را اعلام می‌کند و تو باید بدانی شهرت چقدر با آن فاصله دارد و آیا الان ساعت تابستانی است یا نه. NTP همان رادیو است و «رشته منطقه زمانی» همان دانسته‌ها که یک بار نوشته می‌شود.

NTP همیشه UTC می‌دهد. برای تبدیل آن به ساعت محلی، ESP32 یک رشته منطقه زمانی در قالب POSIX لازم دارد. رمزآلود به نظر می‌رسد، ولی فقط چند تکه است. تورنتو و نیویورک را ببین، EST5EDT,M3.2.0,M11.1.0:

تکهمعنی
ESTاسم ساعت استاندارد (زمستانی)؛ فقط برای نمایش.
5اختلاف با UTC. علامت برعکس است! در قالب POSIX یعنی «چقدر باید به ساعت محلی اضافه کنی تا UTC شود». تورنتو ۵ ساعت عقب‌تر از UTC است، پس ۵ اضافه می‌کنی: یک 5 ساده. برلین ۱ ساعت جلوتر است، پس -1 نوشته می‌شود.

برای ثبت زمان خواندن سنسور (لاگ دما در کارت SD)، روشن کردن چراغ حیاط سر ساعت ۷ شب، و برای این که لاگ‌ها و پیام‌هایی که در فصل ۵ به اینترنت می‌فرستی (MQTT، HTTP) زمان واقعی داشته باشند. یک نکته دقیق: در بسیاری از دستگاه‌ها و کتابخانه‌ها، اتصال امن (HTTPS یا MQTT با TLS) تاریخ اعتبار گواهی را با ساعت دستگاه چک می‌کند و بدون ساعت درست شکست می‌خورد. تمرین ۱: سیگنال‌سنج با LED

برنامه WiFiConnect را طوری تغییر بده که بعد از اتصال، LED روی GPIO4 سرعت چشمکش به قدرت سیگنال بستگی داشته باشد: RSSI بهتر از ‎−60 → ثابت روشن؛ بین ‎−60 و ‎−75 → چشمک آهسته (هر ۵۰۰ میلی‌ثانیه)؛ بدتر از ‎−75 → چشمک سریع (هر ۱۰۰ میلی‌ثانیه). بدون delay.

راهنمایی

در loop، RSSI را بخوان و با if یک متغیر interval تعیین کن. بعد همان الگوی now - lastBlink >= interval درس ۳.۱. یادت باشد RSSI منفی است: «بهتر از ‎−60» یعنی rssi > -60.

جواب 
// بالای برنامه:  const int LED_PIN = 4;   و در setup:  pinMode(LED_PIN, OUTPUT);
void loop() {
  static unsigned long lastBlink = 0;
  static bool ledState = false;
  int rssi = WiFi.RSSI();                 // وقتی وصل نیست، 0 برمی‌گرداند

  if (WiFi.status() == WL_CONNECTED && rssi > -60) {
    ledState = true;                      // سیگنال خوب: ثابت روشن
  } else {
    unsigned long interval = (rssi > -75 && rssi != 0) ? 500 : 100;
    if (millis() - lastBlink >= interval) {
      lastBlink = millis();
      ledState = !ledState;
    }
  }
  digitalWrite(LED_PIN, ledState ? HIGH : LOW);
}
  1. یادداشت برای بقیه برنامه. این فقط loop است؛ include، connectWiFi و setup همان برنامه WiFiConnect می‌مانند و فقط این دو خط به آن اضافه می‌شود. در تمرین‌ها فقط بخشی را که عوض می‌شود می‌نویسیم تا تغییر واقعی گم نشود.
  2. حافظه LED و خواندن RSSI. static یعنی مقدار بین دورهای loop حفظ می‌شود. RSSI را یک بار در هر دور می‌خوانیم و در همه شرط‌ها از همان عدد استفاده می‌کنیم؛ مثل «یک بار ساعت را بخوان» در درس ۳.۱.
  3. سیگنال خوب: ثابت روشن. فقط اگر واقعا وصل است و RSSI از ‎−60 بهتر است. بررسی WL_CONNECTED لازم است چون وقتی قطع هستیم RSSI صفر است و صفر از ‎−60 «بزرگ‌تر» است؛ بدون آن، قطع بودن با «سیگنال عالی» اشتباه گرفته می‌شد.
  4. چشمک آهسته یا سریع. بین ‎−60 و ‎−75 فاصله ۵۰۰ms، بدتر از آن یا قطع، ۱۰۰ms؛ بعد همان الگوی millis. rssi != 0 حالت قطع را به گروه «سریع» می‌فرستد تا با نگاه به LED بفهمی مشکل جدی است.
  5. نوشتن روی پین. یک بار در انتهای loop. تصمیم در چند شاخه، نوشتن در یک جا: کد مرتب‌تر و پیدا کردن اشکال راحت‌تر است.
