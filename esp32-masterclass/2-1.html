تصویر بزرگ: از کد تا چشمک LED چه اتفاقی می‌افتد؟

قبل از نصب هر چیزی، بدان قرار است چه کاری انجام بدهیم. ESP32 زبان C++ را نمی‌فهمد؛ فقط دستورهای ماشین (عددهای باینری) را می‌فهمد. پس زنجیره کار این است:

مثال از زندگی روزمره

فرض کن یک دستور پخت غذا به فارسی نوشته‌ای ولی آشپز فقط ژاپنی بلد است. یک مترجم (کامپایلر) متن را ترجمه می‌کند، یک پیک (esptool و کابل USB) برگه ترجمه‌شده را به آشپزخانه می‌برد، و آشپز (ESP32) آن را در دفترچه‌اش (حافظه Flash) می‌چسباند و هر بار که روشن می‌شود از رویش آشپزی می‌کند. Arduino IDE و PlatformIO هر دو «دفتر کاری» هستند که مترجم و پیک را برایت صدا می‌زنند.

دو بسته نرم‌افزاری در این زنجیره نقش اصلی دارند:

  • برنامه ویرایشگر (IDE): جایی که کد را می‌نویسی و دکمه‌ها را می‌زنی. مثل Arduino IDE یا VS Code.
  • هسته (Core) ESP32: بسته‌ای که Espressif (سازنده ESP32) منتشر می‌کند و شامل کامپایلر مخصوص ESP32، ابزار آپلود esptool و کتابخانه‌هایی مثل WiFi.h است. اسم رسمی‌اش Arduino-ESP32 است و نسخه فعلی آن 3.x است.
چرا این تفکیک مهم است؟

وقتی خطایی می‌بینی، اول باید بفهمی مال کدام مرحله است. خطای was not declared in this scope مال مرحله ۲ (کامپایل) است: کد تو مشکل دارد. خطای Failed to connect مال مرحله ۴ (آپلود) است: کد سالم است ولی کابل، درایور یا پورت مشکل دارد. این تشخیص ساده نصف عیب‌یابی است.

بخش الف: نصب Arduino IDE 2

Arduino IDE برنامه رسمی و رایگان شرکت Arduino است. نسخه ۲ (مثلا 2.3.x) ظاهری مدرن، تکمیل خودکار کد و Serial Monitor داخلی دارد. نسخه قدیمی 1.8.x هنوز در اینترنت هست ولی برای این دوره از نسخه 2.x استفاده کن تا تصویرها و منوها با توضیح‌های ما یکی باشد.

ویندوز (۱۰ و ۱۱)

  1. برو به صفحه دانلود رسمی. آدرس arduino.cc/en/software را باز کن. زیر عنوان Arduino IDE 2.x، گزینه Windows Win 10 and newer, 64 bits را بزن.
  2. دانلود رایگان است. صفحه‌ای باز می‌شود که درخواست کمک مالی (Contribute) دارد. اگر نمی‌خواهی پرداخت کنی، روی Just Download بزن. ممکن است یک صفحه دیگر برای عضویت در خبرنامه هم بیاید؛ دوباره Just Download.
  3. فایل نصب را اجرا کن. فایلی با اسمی شبیه arduino-ide_2.3.x_Windows_64bit.exe دانلود می‌شود. اجرایش کن، شرایط (License) را بپذیر و گزینه‌های پیش‌فرض را نگه دار.
  4. به سؤال‌های درایور «بله» بگو. در حین نصب، ویندوز ممکن است بپرسد «آیا این درایور را نصب می‌کنی؟» (مثلا از Arduino یا Adafruit). همه را Install بزن. این‌ها درایورهای عمومی USB هستند و ضرری ندارند.
  5. اولین اجرا. بار اول ممکن است فایروال ویندوز درباره دسترسی شبکه سؤال کند؛ اجازه بده (IDE برای دانلود بسته‌ها به اینترنت نیاز دارد). همچنین بار اول چند ثانیه تا یک دقیقه طول می‌کشد تا فهرست بردها و کتابخانه‌ها را به‌روز کند؛ صبور باش.
نسخه بدون نصب (ZIP)

اگر روی کامپیوتر دسترسی مدیر (Administrator) نداری، مثلا کامپیوتر دانشگاه، نسخه ZIP را بگیر، در یک پوشه باز کن و Arduino IDE.exe را اجرا کن. فقط دقت کن در این حالت درایورها خودکار نصب نمی‌شوند.

macOS

  1. نسخه درست را انتخاب کن. در همان صفحه دانلود دو گزینه هست: macOS Apple Silicon (برای مک‌های M1، M2، M3 و جدیدتر) و macOS Intel. اگر نمی‌دانی مک تو کدام است: منوی سیب (Apple) › About This Mac. اگر جلوی Chip نوشته Apple M…، نسخه Apple Silicon را بگیر.
  2. فایل .dmg را باز کن و آیکون Arduino IDE را داخل پوشه Applications بکش.
  3. اولین اجرا. اگر macOS گفت «این برنامه از اینترنت دانلود شده، مطمئنی؟»، روی Open بزن.

لینوکس (اوبونتو و مشابه)

  1. فایل AppImage را بگیر. گزینه Linux AppImage 64 bits (X86-64) را دانلود کن. AppImage یعنی «یک فایل که خودش کل برنامه است»؛ نصب لازم ندارد.
  2. اجازه اجرا بده. روی فایل راست‌کلیک › Properties › Permissions › تیک Allow executing file as program. یا در ترمینال: chmod +x arduino-ide_*.AppImage.
  3. اجرا کن. دوبار کلیک یا در ترمینال ./arduino-ide_*.AppImage. اگر در اوبونتو ۲۲.۰۴ یا جدیدتر خطایی درباره libfuse.so.2 دیدی، بسته آن را نصب کن: sudo apt install libfuse2 (در اوبونتو ۲۴.۰۴ اسم بسته libfuse2t64 است).
  4. دسترسی به پورت سریال را فراموش نکن. در لینوکس کاربر معمولی اجازه ندارد به پورت USB سریال بنویسد. این را در بخش درایورها درست می‌کنیم.

یک تنظیم مفید قبل از شروع

از File › Preferences (در مک: Arduino IDE › Settings) تیک Show verbose output during: upload را بزن. این کار باعث می‌شود هنگام آپلود جزئیات بیشتری در پنل Output ببینی؛ وقتی چیزی خراب شد، همین جزئیات سرنخ اصلی است. همان‌جا اندازه فونت ویرایشگر را هم می‌توانی بزرگ‌تر کنی.

افزودن ESP32 به Arduino IDE

Arduino IDE بعد از نصب فقط بردهای خود آردوینو (مثل Uno) را می‌شناسد. ESP32 را شرکت دیگری (Espressif) ساخته، پس باید «بسته ESP32» را جداگانه اضافه کنیم. این کار دو مرحله دارد: اول به IDE می‌گوییم فهرست بسته‌های Espressif کجاست، بعد بسته را نصب می‌کنیم.

مثال از زندگی روزمره

Boards Manager مثل یک فروشگاه اپلیکیشن است که فقط اپ‌های یک شرکت را نشان می‌دهد. آدرسی که در Preferences وارد می‌کنی مثل این است که «کاتالوگ فروشگاه Espressif» را هم به آن اضافه کنی. تا کاتالوگ را اضافه نکنی، ESP32 در فهرست نیست.

مرحله ۱: اضافه کردن آدرس فهرست بسته‌ها

  1. Preferences را باز کن. ویندوز و لینوکس: File › Preferences. مک: Arduino IDE › Settings.
  2. کادر Additional boards manager URLs را پیدا کن (پایین پنجره) و این آدرس را دقیقا در آن بچسبان:
https://espressif.github.io/arduino-esp32/package_esp32_index.json
  1. آدرس رسمی نسخه‌های پایدار. این یک فایل JSON روی سایت Espressif در GitHub است که فهرست همه نسخه‌های هسته ESP32 و لینک دانلود ابزارها را دارد. این آدرس دقیقا همان است که در مستندات رسمی نصب Espressif آمده. آموزش‌های قدیمی اینترنت آدرس دیگری دارند (مثلا dl.espressif.com/dl/package_esp32_index.json یا لینک raw.githubusercontent.com/...). آن‌ها منسوخ‌اند و ممکن است نسخه‌های جدید را نشان ندهند. همیشه آدرس را از مستندات رسمی بردار، نه از یک ویدیوی چند سال پیش.
اگر قبلا آدرس دیگری آنجا بود

اگر در آن کادر آدرس برد دیگری (مثلا ESP8266) هست، پاکش نکن. روی آیکون کنار کادر بزن تا پنجره بزرگ‌تری باز شود و هر آدرس را در یک خط جدا بنویس. سپس OK.

مرحله ۲: نصب بسته از Boards Manager

  1. Boards Manager را باز کن: آیکون دوم نوار چپ (شماره ۶ در نقشه) یا Tools › Board › Boards Manager….
  2. جستجو کن: esp32.
  3. بسته درست را انتخاب کن: esp32 by Espressif Systems. آخرین نسخه 3.x را انتخاب کن و Install بزن.
  4. صبر کن. این بسته برای همه خانواده ESP32 (ESP32، S2، S3، C3، C6، H2 و …) کامپایلر دارد، پس دانلودش چند صد مگابایت است. با اینترنت کند ممکن است نیم ساعت یا بیشتر طول بکشد. در پایین پنجره پیشرفت را می‌بینی.
  5. تأیید. وقتی کنار اسم بسته نوشت INSTALLED، کار تمام است.
دام رایج: دو بسته با اسم شبیه

در نتایج جستجو ممکن است بسته‌ای به اسم Arduino ESP32 Boards (ساخت خود Arduino) هم ببینی. آن بسته فقط برای بردهای ESP32 با برند آردوینو (مثل Arduino Nano ESP32) است. برای بردهای معمولی ESP32 حتما esp32 by Espressif Systems را نصب کن.

نسخه 3.x در برابر 2.x: چرا مهم است؟

در سال ۲۰۲۴ هسته ESP32 از نسخه 2.x به 3.x رفت و بعضی دستورها عوض شد. مهم‌ترین نمونه PWM است: در 3.x می‌نویسی ledcAttach(pin, freq, resolution) و ledcWrite(pin, duty)، ولی آموزش‌های قدیمی از ledcSetup و ledcAttachPin استفاده می‌کنند که در 3.x دیگر وجود ندارند و خطای کامپایل می‌دهند. همه کدهای این دوره برای 3.x نوشته شده‌اند. اگر کدی از اینترنت کپی کردی و خطای «not declared» گرفتی، اول به تفاوت نسخه شک کن.

مرحله ۳: انتخاب برد

از منوی Tools › Board › esp32 گزینه ESP32 Dev Module را انتخاب کن. (یا در کادر انتخاب برد، شماره ۳ در نقشه، بنویس ESP32 Dev Module.)

چرا ESP32 Dev Module و نه اسم دقیق برد من؟

فهرست بردها صدها گزینه دارد (DOIT ESP32 DEVKIT V1، NodeMCU-32S، …). بیشتر این‌ها از نظر نرم‌افزار تقریبا یکی هستند: همه یک ماژول ESP32-WROOM با ۴ مگابایت Flash دارند. «ESP32 Dev Module» تنظیمات عمومی و امن برای همه این بردهاست. فقط اگر بردت چیز خاصی دارد (مثل PSRAM یا تراشه S3)، باید گزینه دقیق‌تر را انتخاب کنی.

بعد از انتخاب برد، در منوی Tools گزینه‌های جدیدی ظاهر می‌شود. فعلا به آن‌ها دست نزن؛ پیش‌فرض‌ها درست هستند. فقط دو تا را بشناس:

  • Upload Speed (پیش‌فرض 921600): سرعت ارسال برنامه. اگر آپلود وسط کار خطا داد، آن را روی 115200 بگذار؛ کندتر ولی مطمئن‌تر است، مخصوصا با کابل‌های بلند یا ارزان.
  • Port: پورت USB برد. در بخش بعد درباره‌اش حرف می‌زنیم.

درایور USB: چرا پورت ظاهر نمی‌شود؟

این بخش مهم‌ترین قسمت درس است، چون بیشتر مبتدی‌ها همین‌جا گیر می‌کنند. تراشه ESP32 روی بردهای کلاسیک مستقیم USB بلد نیست؛ فقط یک درگاه سریال ساده (UART) دارد. پس روی برد یک تراشه کوچک «مبدل USB به سریال» هست که بین کامپیوتر و ESP32 ترجمه می‌کند.

مثال از زندگی روزمره

تراشه مبدل مثل یک مترجم در سفارت است. کامپیوتر فقط «زبان USB» حرف می‌زند و ESP32 فقط «زبان سریال». ولی برای این که کامپیوتر بفهمد این مترجم کیست و چطور با او حرف بزند، باید «کارت شناسایی» او را داشته باشد. آن کارت همان درایور است. بدون درایور، کامپیوتر مترجم را می‌بیند ولی نمی‌داند با او چه کند؛ نتیجه: پورتی در Arduino IDE ظاهر نمی‌شود.

بردهای جدیدتر ممکن است اصلا درایور نخواهند

بردهای ESP32-S3 و ESP32-C3 که پورت USB را مستقیم به خود تراشه وصل کرده‌اند (USB بومی) معمولا بدون هیچ درایوری در ویندوز ۱۰/۱۱، مک و لینوکس شناخته می‌شوند. این درس روی ESP32 کلاسیک با تراشه مبدل تمرکز دارد، چون رایج‌ترین برد بازار است.

ویندوز: بررسی در Device Manager

  1. Device Manager را باز کن: کلید Win+X › Device Manager.
  2. برد را با کابل دیتا وصل کن و به بخش Ports (COM & LPT) نگاه کن. اگر چیزی مثل Silicon Labs CP210x USB to UART Bridge (COM5) یا USB-SERIAL CH340 (COM6) دیدی، درایور نصب است. عدد داخل پرانتز همان پورتی است که در Arduino IDE انتخاب می‌کنی.
  3. اگر در Ports چیزی نیست، بخش Other devices را نگاه کن. دستگاهی با مثلث زرد و اسمی مثل CP2102 USB to UART Bridge Controller یا USB2.0-Serial یعنی سخت‌افزار دیده شده ولی درایور نیست. درایور مناسب را از لینک‌های جدول بالا نصب کن، برد را جدا و دوباره وصل کن. نصب دقیق: برای CP2102 فایل ZIP را از سایت Silicon Labs بگیر (مثلا CP210x Universal Windows Driver) و اول Extract All کن (از داخل ZIP اجرا نکن)؛ اگر داخلش فایل CP210xVCPInstaller_x64.exe بود اجرایش کن، وگرنه روی silabser.inf راست‌کلیک › Install (در ویندوز ۱۱ اول Show more options). برای CH340 فایل CH341SER.EXE را اجرا کن و دکمه INSTALL را بزن؛ پیام «Driver install success» یعنی تمام.
  4. اگر هیچ چیز در هیچ بخشی تغییر نکرد، مشکل از درایور نیست؛ کابل تو فقط شارژی است (پایین‌تر توضیح داده‌ایم).
  5. ترفند شناسایی: اگر مطمئن نیستی کدام دستگاه مال برد توست، برد را جدا کن و ببین کدام ردیف ناپدید می‌شود. برای دیدن شناسه دقیق: راست‌کلیک روی دستگاه › Properties › Details › Hardware Ids. اگر VID_10C4&PID_EA60 دیدی، CP2102 است؛ اگر VID_1A86 بود، تراشه WCH است.
ویندوز ۱۰ و ۱۱ اغلب خودش درایور را پیدا می‌کند

اگر کامپیوتر به اینترنت وصل باشد، Windows Update معمولا درایور CP210x و CH340 را خودکار نصب می‌کند. پس اول یک دقیقه صبر کن و Device Manager را دوباره نگاه کن، بعد سراغ نصب دستی برو.

لینوکس: پورت و گروه dialout

در لینوکس درایور هر دو تراشه (cp210x و ch341) داخل خود هسته لینوکس هست و نصب لازم ندارد. ولی دو مشکل رایج هست: اجازه دسترسی، و یک برنامه مزاحم در اوبونتو. این دستورها را یکی‌یکی در ترمینال بزن:

ls /dev/ttyUSB* /dev/ttyACM*
sudo dmesg | tail -n 15
groups
sudo usermod -a -G dialout $USER
sudo apt remove brltty
  1. فهرست پورت‌های سریال. بردهایی با CP2102 یا CH340 معمولا به اسم /dev/ttyUSB0 ظاهر می‌شوند؛ بردهای USB بومی (S3، C3) به اسم /dev/ttyACM0. اگر پیام No such file or directory دیدی، یعنی هیچ پورتی نیست. این سریع‌ترین آزمون است: قبل و بعد از وصل کردن برد اجرایش کن. اگر اسم جدیدی اضافه شد، سخت‌افزار و درایور سالم‌اند.
  2. پیام‌های هسته لینوکس. ۱۵ خط آخر گزارش سیستم را نشان می‌دهد. بلافاصله بعد از وصل کردن برد باید چیزی شبیه cp210x converter now attached to ttyUSB0 یا ch341-uart converter now attached to ttyUSB0 ببینی. اگر اینجا هیچ خبری از USB نبود، کابل شارژی است. اگر دیدی وصل شد و بلافاصله disconnected شد، دستور ۵ را ببین.
  3. گروه‌های کاربر تو. فهرست گروه‌هایی که عضوشان هستی. باید کلمه dialout در آن باشد. در لینوکس فایل /dev/ttyUSB0 مال گروه dialout است. اگر عضو نباشی، آپلود با خطای Permission denied شکست می‌خورد.
  4. اضافه کردن خودت به dialout. -a -G یعنی «به گروه‌های فعلی اضافه کن» و $USER اسم کاربری توست. بعد از این دستور یک بار Log out و دوباره Log in کن (یا کامپیوتر را ری‌استارت کن). عضویت گروه فقط هنگام ورود به سیستم خوانده می‌شود. خیلی‌ها دستور را می‌زنند، بلافاصله امتحان می‌کنند و فکر می‌کنند کار نکرده. در آرچ‌لینوکس اسم این گروه uucp است. هرگز برای حل این مشکل Arduino IDE را با sudo اجرا نکن؛ فایل‌های تنظیماتت مال root می‌شوند و این کار مشکل‌های بدتری می‌سازد.
  5. حذف brltty (فقط اگر لازم شد). brltty برنامه‌ای برای نمایشگرهای بریل است. در بعضی نسخه‌های اوبونتو (مثل ۲۲.۰۴) به اشتباه دستگاه CH340 را «تصاحب» می‌کند و پورت بلافاصله ناپدید می‌شود. فقط وقتی این دستور را بزن که در dmesg دیدی پورت وصل و فورا جدا می‌شود و به brltty اشاره شده. اگر از نمایشگر بریل استفاده می‌کنی، این کار را نکن.

macOS

در ترمینال مک بزن ls /dev/cu.*. برد تو معمولا با اسمی شبیه /dev/cu.usbserial-0001، /dev/cu.SLAB_USBtoUART (اگر درایور Silicon Labs نصب باشد) یا /dev/cu.wchusbserial… ظاهر می‌شود. در Arduino IDE همیشه گزینه‌ای را انتخاب کن که با cu. شروع می‌شود، نه tty.. در نسخه‌های جدید macOS بسیاری از این تراشه‌ها بدون درایور جداگانه شناخته می‌شوند. اگر پورتی ظاهر نشد، درایور را از سایت سازنده (جدول بالا) نصب کن و بعد در System Settings › Privacy & Security اجازه اجرای آن را بده (macOS معمولا یک دکمه Allow آنجا نشان می‌دهد).

دام بزرگ: کابل فقط شارژی

اول کابل را عوض کن، بعد درایور

بسیاری از کابل‌های micro-USB و USB-C ارزان (مثلا کابلی که همراه پاوربانک یا اسپیکر بلوتوثی آمده) فقط دو سیم برق دارند و سیم‌های داده (D+ و D−) را ندارند. با این کابل‌ها LED برق روی برد روشن می‌شود و فکر می‌کنی همه چیز درست است، ولی کامپیوتر هیچ دستگاهی نمی‌بیند؛ نه در Ports و نه در Other devices. آزمون ساده: با همان کابل گوشی‌ات را به کامپیوتر وصل کن. اگر نتوانستی فایل منتقل کنی، کابل فقط شارژی است. یک کابل مطمئن را برچسب بزن و فقط برای برنامه‌ریزی استفاده کن.

اولین آپلود: ESP32 خودش را معرفی می‌کند

شاید انتظار داشته باشی اولین برنامه Blink باشد. Arduino IDE یک مثال آماده Blink دارد (File › Examples › 01.Basics › Blink) ولی با برد ESP32 Dev Module این خطا را می‌دهد:

error: 'LED_BUILTIN' was not declared in this scope

چرا؟ LED_BUILTIN اسمی است که هر برد برای «پین LED داخلی‌اش» تعریف می‌کند. برد رسمی DevKitC اصلا LED قابل برنامه‌ریزی ندارد، پس Espressif این اسم را برای ESP32 Dev Module تعریف نکرده است (ما فایل تعریف پین‌های این برد را در هسته 3.x بررسی کردیم). اگر برد تو یک LED آبی روی GPIO2 دارد، کافی است این خط را بالای مثال Blink اضافه کنی:

#define LED_BUILTIN 2   // فقط اگر برد تو LED آبی روی GPIO2 دارد
  1. تعریف یک اسم. #define به کامپایلر می‌گوید «هر جا LED_BUILTIN دیدی، به جایش عدد ۲ بگذار». این جایگزینی قبل از کامپایل اصلی انجام می‌شود. به جای دست بردن در کد مثال یا فایل‌های هسته، کمبود را همین‌جا جبران کردیم. ولی بهتر است همان روش درس ۲.۲ را عادت کنی: const int LED_PIN = 2; که نوع‌دار و امن‌تر است.

ولی ما اولین آزمون را با برنامه‌ای شروع می‌کنیم که روی هر برد ESP32 کار می‌کند، حتی بدون LED: برنامه‌ای که از طریق Serial Monitor مشخصات تراشه را چاپ می‌کند. این‌طوری هم آپلود را آزمایش کرده‌ای و هم ارتباط سریال را.

  1. یک Sketch جدید بساز: File › New Sketch. هر چه در آن هست را پاک کن و کد زیر را بچسبان.
  2. ذخیره کن: Ctrl+S، اسم را hello_esp32 بگذار. Arduino IDE خودش یک پوشه هم‌نام می‌سازد (هر Sketch باید در پوشه‌ای با اسم خودش باشد).
// اولین تست: ESP32 خودش را معرفی می‌کند
void setup() {
  Serial.begin(115200);
  delay(1000);                          // صبر تا Serial Monitor آماده شود
  Serial.println();
  Serial.println("Salam! ESP32 is alive :)");
  Serial.print("Chip model: ");
  Serial.println(ESP.getChipModel());
  Serial.print("Chip revision: ");
  Serial.println(ESP.getChipRevision());
  Serial.print("CPU MHz: ");
  Serial.println(ESP.getCpuFreqMHz());
  Serial.print("Flash MB: ");
  Serial.println(ESP.getFlashChipSize() / (1024 * 1024));
}

void loop() {
  Serial.print("Uptime (s): ");
  Serial.println(millis() / 1000);      // چند ثانیه از روشن شدن گذشته
  delay(2000);
}
  1. توضیح. یادداشتی برای انسان؛ کامپایلر نادیده‌اش می‌گیرد. عادت کن بالای هر برنامه یک خط بنویسی که «این برنامه چه کار می‌کند».
  2. تابع setup. یک بار، بعد از روشن شدن یا ریست، اجرا می‌شود. همه معرفی‌نامه را اینجا چاپ می‌کنیم. مشخصات تراشه عوض نمی‌شود؛ لازم نیست هر دو ثانیه دوباره چاپش کنیم.
  3. Serial.begin(115200). ارتباط سریال را با سرعت ۱۱۵۲۰۰ بیت بر ثانیه روشن می‌کند. این عدد باید با عدد پایین پنجره Serial Monitor یکی باشد؛ وگرنه حروف درهم می‌بینی. ۱۱۵۲۰۰ استاندارد دنیای ESP32 است.
  4. delay(1000). یک ثانیه صبر. بعد از آپلود، برد ریست می‌شود و چند لحظه طول می‌کشد تا Serial Monitor دوباره به پورت وصل شود. بدون این مکث، ممکن است پیام‌های اول را از دست بدهی و فکر کنی برنامه کار نمی‌کند.
  5. یک خط خالی و سلام. println() بدون ورودی فقط به خط بعد می‌رود. موقع روشن شدن، ESP32 چند خط پیام بوت (گاهی با حروف عجیب) می‌فرستد. خط خالی پیام ما را از آن‌ها جدا می‌کند. متن را انگلیسی نوشتیم چون ترکیب فارسی و انگلیسی در Serial Monitor گاهی به‌هم‌ریخته نمایش داده می‌شود.
  6. مدل تراشه. ESP.getChipModel() اسم دقیق تراشه را برمی‌گرداند، مثلا ESP32-D0WD-V3 که داخل ماژول WROOM-32E است. ESP یک شیء آماده در هسته ESP32 است که اطلاعات سخت‌افزار را می‌دهد. اگر بردی خریدی و شک داری واقعا ESP32 است، همین خط جواب می‌دهد.
  7. نسخه ساخت تراشه (Revision). در هسته 3.x عددی مثل 301 برمی‌گرداند که یعنی نسخه v3.1 (رقم اول نسخه اصلی، دو رقم بعد نسخه فرعی). تراشه‌های v3 باگ‌های سخت‌افزاری نسخه‌های قدیمی را ندارند. آموزش‌های قدیمی (هسته 2.x) عددی مثل ۱ یا ۳ نشان می‌دادند؛ تعجب نکن.
  8. فرکانس پردازنده. معمولا 240 مگاهرتز. در درس ۶.۱ یاد می‌گیری برای صرفه‌جویی در باتری این عدد را کم کنی. الان فقط ببین پیش‌فرض چیست.
  9. اندازه حافظه Flash. getFlashChipSize() اندازه را به بایت می‌دهد؛ تقسیم بر 1024 * 1024 آن را به مگابایت تبدیل می‌کند. برای WROOM معمولی: 4. Flash جایی است که برنامه تو ذخیره می‌شود. اگر روزی برنامه‌ات جا نشد، این عدد سقف توست.
  10. loop: گزارش زنده بودن. هر دو ثانیه، تعداد ثانیه‌های گذشته از روشن شدن را چاپ می‌کند. millis() تعداد میلی‌ثانیه‌های گذشته را می‌دهد و تقسیم بر ۱۰۰۰ آن را ثانیه می‌کند. یک عدد در حال افزایش ثابت می‌کند برد گیر نکرده و مدام ریست نمی‌شود. اگر عدد مدام به ۰ یا ۱ برگشت، برد ریست می‌شود (مثلا به خاطر Brownout؛ جدول عیب‌یابی را ببین).

آپلود و دیدن نتیجه

  1. برد و پورت را در کادر بالا (شماره ۳) چک کن: ESP32 Dev Module و پورتی که در بخش درایور پیدا کردی (مثلا COM5 یا /dev/ttyUSB0).
  2. Upload (→) را بزن. بار اول کامپایل کل هسته ESP32 یک تا چند دقیقه طول می‌کشد؛ دفعه‌های بعد خیلی سریع‌تر است چون نتیجه ذخیره می‌شود.
  3. پنل Output را تماشا کن. ترتیب طبیعی: Sketch uses … bytes ← Connecting.... ← Writing at 0x… (100%) ← Hard resetting via RTS pin....
  4. اگر Connecting....___.... طولانی شد، دکمه BOOT روی برد را نگه دار تا نوشتن شروع شود، بعد رها کن.
  5. Serial Monitor را باز کن (شماره ۴) و پایین پنجره سرعت را روی 115200 baud بگذار. اگر پیام معرفی را ندیدی، یک بار دکمه EN (ریست) برد را بزن.

یک آزمایش کوچک

دکمه EN را بزن. عدد Uptime دوباره از ۱ شروع می‌شود و پیام معرفی دوباره چاپ می‌شود. حالا با چشم خودت دیدی که «ریست» یعنی اجرای دوباره setup از اول. قبل از پیام ما چند خط مثل rst:0x1 (POWERON_RESET) هم می‌بینی؛ این‌ها پیام‌های بوت خود ESP32 هستند و علت ریست را می‌گویند. بعدا برای عیب‌یابی خیلی به کارت می‌آیند.

اگر دانلود هسته کند بود یا خطا داد

فایل‌های هسته ESP32 (کامپایلرها و ابزارها) چند صد مگابایت‌اند و از سرورهای GitHub دانلود می‌شوند. گاهی این دانلود کند است، وسط کار قطع می‌شود، یا با خطاهایی مثل Error downloading …، context deadline exceeded یا connection reset متوقف می‌شود؛ مثل دانلود یک فیلم بزرگ که وسطش اینترنت قطع شود. این روش‌ها را به ترتیب امتحان کن:

  1. دوباره تلاش کن. بسیاری از خطاها موقتی‌اند. Boards Manager را ببند، دوباره باز کن و Install را بزن. فایل‌هایی که کامل دانلود شده‌اند در پوشه staging (پایین‌تر) می‌مانند و معمولا دوباره دانلود نمی‌شوند.
  2. یک شبکه دیگر را امتحان کن. شبکه‌های مدرسه، دانشگاه یا محل کار گاهی دانلودهای بزرگ را محدود می‌کنند؛ با اینترنت خانه یا هات‌اسپات گوشی امتحان کن.
  3. تنظیم Proxy در خود IDE. اگر شبکه‌ات (معمولا شبکه اداری) پراکسی دارد، در File › Preferences تب Network را باز کن، Manual proxy configuration را بزن و نشانی و پورتی را که بخش IT به تو داده وارد کن.
  4. کپی از یک کامپیوتر دیگر (روش آفلاین). اگر دوستی هسته ESP32 را روی کامپیوتری با همان سیستم‌عامل نصب کرده، پوشه packages/esp32 را از پوشه Arduino15 او (جدول زیر) در همان مسیر کامپیوتر خودت کپی کن، و فایل package_esp32_index.json را هم از ریشه Arduino15 او بردار. بعد Arduino IDE را باز کن. روش جایگزین: پوشه staging/packages او را کپی کن؛ آن‌جا فایل‌های فشرده دانلودشده هستند و IDE موقع Install معمولا از همان‌ها استفاده می‌کند به جای دانلود دوباره.

PlatformIO یک افزونه (Extension) برای ویرایشگر رایگان VS Code مایکروسافت است. همان کامپایلر و همان هسته Arduino را استفاده می‌کند، پس کدهای تو تقریبا بدون تغییر در آن اجرا می‌شوند. فرقش در «مدیریت پروژه» است.

مثال از زندگی روزمره

Arduino IDE مثل یک آشپزخانه کوچک و مرتب خانه است: برای درست کردن یک غذای ساده عالی است. PlatformIO مثل آشپزخانه یک رستوران است: هر غذا (پروژه) دستور پخت مکتوب خودش را دارد که دقیقا می‌گوید کدام مواد با کدام برند و کدام نسخه. اگر فردا آشپز دیگری بیاید، همان غذا را دقیقا همان‌طور درست می‌کند.

چرا و کی سراغ PlatformIO برویم؟

  • نسخه کتابخانه‌ها در خود پروژه ثبت می‌شود. در Arduino IDE کتابخانه‌ها بین همه پروژه‌ها مشترک‌اند؛ اگر برای پروژه جدید یک کتابخانه را به‌روز کنی، ممکن است پروژه قدیمی خراب شود. در PlatformIO هر پروژه کتابخانه‌های خودش را با نسخه مشخص دارد.
  • IntelliSense قوی. VS Code هنگام تایپ، نام توابع، پارامترها و خطاها را زیر کد نشان می‌دهد؛ روی هر تابع Ctrl+کلیک کنی، به تعریفش می‌روی.
  • پروژه چندفایلی و Git. تقسیم کد به چند فایل و نگه داشتن تاریخچه با Git در VS Code طبیعی است.
  • عیب: شروعش سخت‌تر است، نصب اول سنگین‌تر است و چند مفهوم جدید دارد.
حرف مربی: کی سوییچ کنم؟

فصل‌های ۲ و ۳ را با Arduino IDE برو تا تمرکزت روی خود ESP32 باشد، نه ابزار. وقتی پروژه‌ات بیش از یک فایل یا بیش از دو کتابخانه داشت (از فصل ۴ به بعد)، PlatformIO را جدی بگیر. ولی همین حالا یک بار نصبش کن تا بدانی چیست.

نصب

  1. VS Code را نصب کن از code.visualstudio.com. در ویندوز هنگام نصب تیک Add to PATH را نگه دار.
  2. افزونه را نصب کن. در VS Code آیکون Extensions (چهار مربع، نوار چپ) یا Ctrl+Shift+X. جستجو کن PlatformIO IDE و Install بزن.
  3. صبر کن. PlatformIO بار اول یک محیط Python مخصوص خودش و ابزارهای پایه را دانلود می‌کند. پایین-راست پنجره پیشرفت را می‌بینی. در پایان می‌خواهد VS Code را دوباره باز کنی (Reload).
  4. در لینوکس علاوه بر گروه dialout، PlatformIO توصیه می‌کند فایل قوانین udev خودش را نصب کنی؛ دستور دقیقش در مستندات udev rules هست.

ساخت اولین پروژه

  1. PlatformIO Home را باز کن: آیکون PlatformIO در نوار چپ (شبیه سر یک مورچه) › Open › دکمه + New Project.
  2. فرم را پر کن: Name: hello_pio. Board: تایپ کن ESP32 Dev و Espressif ESP32 Dev Module را انتخاب کن (شناسه داخلی آن esp32dev است). Framework: Arduino.
  3. Finish. بار اول چند دقیقه طول می‌کشد چون پلتفرم ESP32 را دانلود می‌کند.

ساختار پوشه پروژه

hello_pio/
├── .pio/            خروجی کامپایل (دست نزن)
├── .vscode/         تنظیمات VS Code (خودکار)
├── include/         فایل‌های سرآیند .h خودت
├── lib/             کتابخانه‌های خصوصی این پروژه
├── src/
│   └── main.cpp     کد اصلی برنامه
├── test/            تست‌های خودکار (فعلا نه)
└── platformio.ini   شناسنامه پروژه
  1. پوشه‌های خودکار. .pio فایل‌های کامپایل‌شده و کتابخانه‌های دانلودشده را نگه می‌دارد؛ .vscode تنظیمات ویرایشگر است. نقطه اول اسم یعنی «پوشه فنی». اگر پروژه را برای کسی فرستادی یا در Git گذاشتی، این دو را نفرست؛ با اولین Build دوباره ساخته می‌شوند.
  2. include و lib. include برای فایل‌های .h خودت است؛ lib برای کتابخانه‌ای که خودت نوشتی یا دستی دانلود کردی و فقط این پروژه از آن استفاده می‌کند (هر کتابخانه در یک زیرپوشه). جدا کردن کد اصلی از کدهای کمکی باعث می‌شود پروژه بزرگ هم مرتب بماند.
  3. src/main.cpp. معادل فایل .ino در Arduino IDE. برنامه تو اینجاست. پسوند .cpp یعنی C++ استاندارد. PlatformIO برخلاف Arduino IDE کد را «جادویی» پیش‌پردازش نمی‌کند (توضیح پایین‌تر).
  4. test. برای تست‌های خودکار واحد (Unit Test). در این دوره لازمش نداریم؛ ولی بدان برای چیست که پاکش نکنی و نترسی.
  5. platformio.ini. مهم‌ترین فایل: برد، پلتفرم، سرعت‌ها و کتابخانه‌ها اینجا تعریف می‌شوند. این همان «دستور پخت مکتوب» است. هر کس این فایل و پوشه src را داشته باشد، دقیقا همان برنامه را می‌سازد.

تک‌تک خط‌های platformio.ini

فایلی که PlatformIO برای تو ساخته را با این نسخه کامل‌تر عوض کن:

; hello_pio - PlatformIO project configuration
[env:esp32dev]
platform = https://github.com/pioarduino/platform-espressif32/releases/download/stable/platform-espressif32.zip
board = esp32dev
framework = arduino

monitor_speed = 115200
monitor_filters = esp32_exception_decoder
upload_speed = 921600
; upload_port = COM5

lib_deps =
    adafruit/Adafruit SSD1306 @ ^2.5.7
    adafruit/DHT sensor library @ ^1.4.6
  1. توضیح. در فایل ini هر خطی که با ; (یا #) شروع شود توضیح است. همان کاربرد // در C++.
  2. یک «محیط» (environment). [env:esp32dev] یعنی مجموعه تنظیماتی به اسم esp32dev. اسم بعد از دونقطه را خودت انتخاب می‌کنی. یک پروژه می‌تواند چند محیط داشته باشد، مثلا یکی برای ESP32 و یکی برای ESP32-S3، و با یک کلیک برای هر دو بسازی. کاری که در Arduino IDE ممکن نیست.
  3. platform: کدام بسته ESP32. اینجا پلتفرم جامعه‌محور pioarduino را انتخاب کرده‌ایم که هسته Arduino-ESP32 نسخه 3.x را دارد. در حالت پیش‌فرض PlatformIO می‌نویسد platform = espressif32 (بخش بعد را بخوان). همه کدهای این دوره برای هسته 3.x است. با پلتفرم رسمی فعلی PlatformIO هسته 2.x نصب می‌شود و کدهای PWM، ESP-NOW و خواب عمیق ما کامپایل نمی‌شوند.
  4. board. شناسه برد؛ esp32dev معادل «ESP32 Dev Module» در Arduino IDE است. این شناسه به PlatformIO می‌گوید اندازه Flash، نوع تراشه و تنظیمات آپلود چیست.
  5. framework. arduino یعنی از توابع آشنای آردوینو (pinMode، Serial، …) استفاده می‌کنیم. گزینه دیگر espidf است: فریم‌ورک بومی Espressif که قدرتمندتر ولی بسیار سخت‌تر است. برای این دوره Arduino کافی است.
  6. monitor_speed. سرعت Serial Monitor داخلی PlatformIO. پیش‌فرض PlatformIO 9600 است ولی کد ما Serial.begin(115200) دارد. اگر این خط را ننویسی، حروف درهم می‌بینی. رایج‌ترین اشتباه تازه‌واردهای PlatformIO همین است.
  7. monitor_filters. فیلتر esp32_exception_decoder وقتی برنامه کرش کرد، آدرس‌های نامفهوم (Backtrace) را به اسم تابع و شماره خط کد تو ترجمه می‌کند. بدون این فیلتر پیام کرش فقط یک مشت عدد هگز است. با آن، مستقیم می‌فهمی کدام خط مقصر است.
  8. upload_speed. سرعت آپلود؛ ۹۲۱۶۰۰ سریع است. اگر آپلود با خطا قطع شد، این عدد را ۴۶۰۸۰۰ یا ۱۱۵۲۰۰ کن. کابل بلند یا بی‌کیفیت سرعت‌های بالا را تحمل نمی‌کند.
  9. upload_port (غیرفعال). چون با ; شروع شده، اجرا نمی‌شود. PlatformIO معمولا پورت را خودکار پیدا می‌کند. اگر چند برد هم‌زمان وصل داری یا خودکار پیدا نکرد، ; را بردار و پورت خودت را بنویس (در لینوکس مثلا /dev/ttyUSB0).
  10. lib_deps: کتابخانه‌ها با نسخه. قالب هر خط: سازنده/اسم @ نسخه. علامت ^2.5.7 یعنی «نسخه 2.5.7 یا هر نسخه جدیدتر 2.x، ولی نه 3.0». PlatformIO موقع اولین Build این‌ها و وابستگی‌هایشان (مثلا Adafruit GFX) را خودکار دانلود می‌کند. این دو خط فقط مثال‌اند (برای نمایشگر OLED و سنسور DHT22 در درس ۳.۳)؛ برای پروژه سلام لازم نیستند و می‌توانی پاکشان کنی. نسخه اصلی (عدد اول) معمولا وقتی عوض می‌شود که سازنده تغییرات ناسازگار داده. ^ به‌روزرسانی‌ها و رفع باگ‌ها را می‌پذیرد ولی جلوی شکستن ناگهانی کد را می‌گیرد. خط‌های ادامه باید با فاصله (تورفتگی) شروع شوند.

نکته مهم: PlatformIO رسمی و هسته 3.x

این قسمت کمی فنی است ولی اگر نخوانی، بعدا گیج می‌شوی. تیم PlatformIO اعلام کرده که پشتیبانی رسمی از هسته Arduino-ESP32 نسخه 3.x را اضافه نمی‌کند. در زمان نوشتن این درس (۲۰۲۶) پلتفرم رسمی platform = espressif32 هنوز هسته 2.0.17 را نصب می‌کند (این را در فایل تعریف پلتفرم رسمی بررسی کردیم). به همین دلیل جامعه کاربران یک نسخه مستقل به اسم pioarduino ساخته که هسته 3.x را می‌آورد و به‌روز نگه داشته می‌شود.

  • راه ۱ (پیشنهاد ما): همان خط platform = https://github.com/pioarduino/…/platform-espressif32.zip بالا را در افزونه معمولی PlatformIO بنویس. این آدرس از README رسمی pioarduino است و همیشه به آخرین نسخه پایدار اشاره می‌کند.
  • راه ۲: تیم pioarduino یک افزونه VS Code جداگانه به اسم pioarduino IDE هم دارد که همین کار را پیش‌فرض می‌کند. نصب هم‌زمان هر دو افزونه توصیه نمی‌شود؛ یکی را انتخاب کن.
صادقانه: pioarduino رسمی نیست

pioarduino توسط تیم کوچکی از داوطلبان نگهداری می‌شود، نه خود PlatformIO یا Espressif. تا امروز فعال و پرکاربرد بوده، ولی اگر روزی چیزی عوض شد، صفحه GitHub آن را برای آخرین دستورالعمل ببین. اگر فقط Arduino IDE استفاده می‌کنی، این موضوع هیچ ربطی به تو ندارد.

برای مقایسه، شکل ساده پیش‌فرض این است (هسته 2.x، فقط برای شناختن آن در آموزش‌های دیگر):

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
  1. پلتفرم رسمی. فقط یک کلمه: espressif32. بقیه خط‌ها مثل قبل. اگر در آموزشی این خط را دیدی و کدش از ledcSetup استفاده می‌کرد، حالا می‌دانی چرا با تنظیمات ما کامپایل نمی‌شود: آن آموزش برای هسته 2.x است.

main.cpp: یک خط که نباید فراموش شود

محتوای src/main.cpp را با این کد عوض کن:

#include <Arduino.h>          // در PlatformIO این خط اجباری است

void setup() {
  Serial.begin(115200);
  delay(1000);
  Serial.println("Hello from PlatformIO!");
}

void loop() {
  Serial.printf("Uptime: %lu s\n", millis() / 1000);
  delay(2000);
}
  1. #include <Arduino.h>. فایل تعریف همه توابع آردوینو (Serial، pinMode، delay، …) را به برنامه اضافه می‌کند. Arduino IDE این خط را پنهانی به فایل .ino اضافه می‌کند، ولی در فایل .cpp باید خودت بنویسی. بدون آن، خطای 'Serial' was not declared in this scope می‌گیری.
  2. setup. مثل قبل: شروع سریال، یک ثانیه صبر، یک پیام. سرعت ۱۱۵۲۰۰ با monitor_speed در platformio.ini هماهنگ است. اگر یکی را عوض کنی، دیگری را هم باید عوض کنی.
  3. Serial.printf. چاپ با قالب: %lu جای یک عدد بزرگ بدون علامت (نوع unsigned long که millis() برمی‌گرداند) می‌نشیند و \n یعنی برو خط بعد. printf یک خط را با یک دستور می‌سازد، به جای چند print پشت هم. این تابع در هسته ESP32 هست ولی در آردوینو Uno نیست.
  4. delay(2000). دو ثانیه مکث. بدون مکث، هزاران خط در ثانیه چاپ می‌شود و Serial Monitor غیرقابل خواندن می‌شود.
تفاوت پنهان دوم: ترتیب توابع

در .ino می‌توانی تابعی را پایین فایل تعریف کنی و بالاتر صدایش بزنی؛ Arduino IDE خودش «اعلان» (Prototype) آن را بالای فایل می‌سازد. در .cpp این جادو نیست. اگر تابعی مثل void blinkTwice(); را بعد از loop نوشتی و در loop صدایش زدی، باید یک خط اعلان void blinkTwice(); بالای فایل بنویسی، یا کل تابع را بالای loop ببری.

// hello_esp32 + تعداد هسته و MAC: شناسنامه کامل‌تر
void setup() {
  Serial.begin(115200);
  delay(1000);                          // صبر تا Serial Monitor آماده شود
  Serial.println();
  Serial.println("Salam! ESP32 is alive :)");
  Serial.print("Chip model: ");
  Serial.println(ESP.getChipModel());
  Serial.print("Chip revision: ");
  Serial.println(ESP.getChipRevision());
  Serial.print("CPU MHz: ");
  Serial.println(ESP.getCpuFreqMHz());
  Serial.print("Flash MB: ");
  Serial.println(ESP.getFlashChipSize() / (1024 * 1024));
  Serial.print("Cores: ");
  Serial.println(ESP.getChipCores());   // برای ESP32 کلاسیک: 2
  Serial.printf("eFuse MAC: %012llX\n", ESP.getEfuseMac());
}

void loop() {
  Serial.print("Uptime (s): ");
  Serial.println(millis() / 1000);      // چند ثانیه از روشن شدن گذشته
  delay(2000);
}
  1. بخش قبلی بدون تغییر. همان معرفی برنامه اصلی. خط‌های تازه را به انتهای setup اضافه می‌کنیم تا خروجی قبلی دست نخورد و راحت ببینی چه چیزی اضافه شده.
  2. تعداد هسته. ESP32 کلاسیک دو هسته دارد (در درس ۱.۱ دیدی). نسخه‌های تک‌هسته هم وجود دارد (مثل ESP32-C3)؛ این خط فوری تفاوت را نشان می‌دهد.
  3. شناسه یکتا از eFuse. عدد ۴۸ بیتی که کارخانه در تراشه «سوزانده». %012llX یعنی عدد ۶۴ بیتی را ۱۲ رقم هگز با صفرهای پیشرو چاپ کن. ترتیب بایت‌ها در این عدد برعکس ترتیب معمول نمایش MAC است؛ نگران نباش. در درس ۵.۲ (ESP-NOW) روش استاندارد خواندن MAC با کتابخانه WiFi را یاد می‌گیری.
  4. loop بدون تغییر. هر دو ثانیه Uptime. عدد بالارونده نشان می‌دهد برد بعد از چاپ شناسنامه گیر نکرده است.

انتقال به PlatformIO: همین کد را در src/main.cpp بچسبان و یک خط به بالای فایل اضافه کن: #include <Arduino.h>. در platformio.ini هم باید monitor_speed = 115200 باشد؛ بدون آن Monitor با سرعت پیش‌فرض ۹۶۰۰ باز می‌شود و حروف درهم می‌بینی.
