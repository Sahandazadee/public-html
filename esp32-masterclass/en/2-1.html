For that we need a "translator": software that turns code written in a human-readable language into the ESP32's language of ones and zeros, and pours it into the chip over the USB cable. In this lesson you'll install two tools from scratch: the Arduino IDE (simple and ideal for getting started) and VS Code + PlatformIO (more professional, for bigger projects). By the end of the lesson, the ESP32 will introduce itself to you in the Serial Monitor.

The big picture: what happens between your code and a blinking LED?

Before installing anything, it helps to know what we're about to do. The ESP32 doesn't understand C++; it only understands machine instructions (binary numbers). So the chain of work looks like this:

An everyday example

Imagine you've written a recipe in English, but the cook only speaks Japanese. A translator (the compiler) translates the text, a courier (esptool and the USB cable) carries the translated sheet to the kitchen, and the cook (the ESP32) pastes it into their notebook (the Flash memory) and cooks from it every time they start work. The Arduino IDE and PlatformIO are both "offices" that call the translator and the courier for you.

Two software packages play the main roles in this chain:

  • The editor program (IDE): where you write code and press the buttons. For example, the Arduino IDE or VS Code.
  • The ESP32 core: a package published by Espressif (the maker of the ESP32) that contains the ESP32-specific compiler, the esptool upload tool and libraries such as WiFi.h. Its official name is Arduino-ESP32, and the current version is 3.x.
Why does this split matter?

When you see an error, the first thing to figure out is which stage it belongs to. A was not declared in this scope error belongs to stage 2 (compiling): your code has a problem. A Failed to connect error belongs to stage 4 (uploading): the code is fine, but the cable, the driver or the port has a problem. This simple diagnosis is half of all troubleshooting.

Part A: installing Arduino IDE 2

The Arduino IDE is the official, free program from the Arduino company. Version 2 (for example 2.3.x) has a modern look, code autocompletion and a built-in Serial Monitor. The old 1.8.x version is still around on the internet, but use version 2.x for this course so the screenshots and menus match our explanations.

Windows (10 and 11)

  1. Go to the official download page. Open arduino.cc/en/software. Under the Arduino IDE 2.x heading, click Windows Win 10 and newer, 64 bits.
  2. The download is free. A page opens asking for a donation (Contribute). If you don't want to pay, click Just Download. Another page asking you to sign up for the newsletter may appear; click Just Download again.
  3. Run the installer. A file with a name like arduino-ide_2.3.x_Windows_64bit.exe downloads. Run it, accept the license and keep the default options.
  4. Say "yes" to the driver prompts. During installation, Windows may ask "Would you like to install this device software?" (for example from Arduino or Adafruit). Click Install for all of them. These are generic USB drivers and do no harm.
  5. First launch. The first time, Windows Firewall may ask about network access; allow it (the IDE needs the internet to download packages). Also, the first launch takes a few seconds to a minute while it updates its list of boards and libraries; be patient.
The no-install version (ZIP)

If you don't have administrator rights on the computer (a university computer, for example), get the ZIP version, extract it into a folder and run Arduino IDE.exe. Just be aware that in this case the drivers aren't installed automatically.

macOS

  1. Pick the right version. The same download page has two options: macOS Apple Silicon (for M1, M2, M3 and newer Macs) and macOS Intel. If you don't know which Mac you have: Apple menu › About This Mac. If the Chip line says Apple M…, get the Apple Silicon version.
  2. Open the .dmg file and drag the Arduino IDE icon into the Applications folder.
  3. First launch. If macOS says "This app was downloaded from the internet. Are you sure?", click Open.

Linux (Ubuntu and similar)

  1. Get the AppImage file. Download Linux AppImage 64 bits (X86-64). An AppImage is "a single file that is the whole program"; it doesn't need installing.
  2. Allow it to run. Right-click the file › Properties › Permissions › tick Allow executing file as program. Or in a terminal: chmod +x arduino-ide_*.AppImage.
  3. Run it. Double-click it, or in a terminal run ./arduino-ide_*.AppImage. If you see an error about libfuse.so.2 on Ubuntu 22.04 or newer, install its package: sudo apt install libfuse2 (on Ubuntu 24.04 the package is called libfuse2t64).

Adding the ESP32 to the Arduino IDE

Right after installation, the Arduino IDE only knows Arduino's own boards (such as the Uno). The ESP32 is made by a different company (Espressif), so we have to add the "ESP32 package" separately. This takes two steps: first we tell the IDE where Espressif's package list lives, then we install the package.

An everyday example

The Boards Manager is like an app store that only shows one company's apps. The URL you enter in Preferences is like adding "Espressif's catalog" to that store. Until you add the catalog, the ESP32 isn't on the list.

Step 1: add the package list URL

  1. Open Preferences. Windows and Linux: File › Preferences. Mac: Arduino IDE › Settings.
  2. Find the Additional boards manager URLs box (at the bottom of the window) and paste this URL into it exactly:
https://espressif.github.io/arduino-esp32/package_esp32_index.json
  1. The official URL for stable releases. This is a JSON file on Espressif's GitHub site that lists every version of the ESP32 core along with download links for the tools. It's exactly the URL given in Espressif's official installation docs. Older tutorials on the internet use different URLs (for example dl.espressif.com/dl/package_esp32_index.json or a raw.githubusercontent.com/... link). Those are obsolete and may not show the new versions. Always take the URL from the official docs, not from a video that's several years old.
If there was already another URL in there

If that box already has a URL for another board (for example the ESP8266), don't delete it. Click the icon next to the box to open a bigger window, and put each URL on its own line. Then click OK.

Step 2: install the package from the Boards Manager

  1. Open the Boards Manager: the second icon in the left sidebar (number 6 on the map), or Tools › Board › Boards Manager….
  2. Search for: esp32.
  3. Pick the right package: esp32 by Espressif Systems. Choose the latest 3.x version and click Install.
  4. Wait. This package includes compilers for the whole ESP32 family (ESP32, S2, S3, C3, C6, H2 and more), so the download is several hundred megabytes. On a slow connection it can take half an hour or more. You can watch the progress at the bottom of the window.
  5. Confirm. When it says INSTALLED next to the package name, you're done.
A common trap: two packages with similar names

In the search results you may also see a package called Arduino ESP32 Boards (made by Arduino itself). That package is only for Arduino-branded ESP32 boards (such as the Arduino Nano ESP32). For ordinary ESP32 boards, be sure to install esp32 by Espressif Systems.

Version 3.x versus 2.x: why does it matter?

In 2024 the ESP32 core moved from version 2.x to 3.x, and some functions changed. The most important example is PWM: in 3.x you write ledcAttach(pin, freq, resolution) and ledcWrite(pin, duty), but older tutorials use ledcSetup and ledcAttachPin, which no longer exist in 3.x and cause compile errors. All the code in this course is written for 3.x. If you copy code from the internet and get a "not declared" error, suspect a version difference first.

Step 3: select the board

From the Tools › Board › esp32 menu, choose ESP32 Dev Module. (Or type ESP32 Dev Module into the board selector, number 3 on the map.)

Why ESP32 Dev Module and not my board's exact name?

The board list has hundreds of entries (DOIT ESP32 DEVKIT V1, NodeMCU-32S, …). Most of them are practically identical as far as the software is concerned: they all have an ESP32-WROOM module with 4 MB of Flash. "ESP32 Dev Module" is a safe, general setting for all of these boards. Only if your board has something special (such as PSRAM or an S3 chip) do you need to pick a more specific entry.

After you select the board, new options appear in the Tools menu. Leave them alone for now; the defaults are correct. Just get to know two of them:

  • Upload Speed (default 921600): how fast the program is sent. If an upload fails partway through, set it to 115200; it's slower but more reliable, especially with long or cheap cables.
  • Port: the board's USB port. We'll talk about it in the next section.

The USB driver: why doesn't the port show up?

This is the most important part of the lesson, because this is where most beginners get stuck. On classic boards, the ESP32 chip doesn't speak USB directly; it only has a simple serial port (UART). So the board carries a small "USB-to-serial converter" chip that translates between the computer and the ESP32.

An everyday example

The converter chip is like an interpreter at an embassy. The computer only speaks "USB" and the ESP32 only speaks "serial". But for the computer to know who this interpreter is and how to talk to them, it needs the interpreter's "ID card". That ID card is the driver. Without a driver, the computer sees the interpreter but doesn't know what to do with them; the result is that no port appears in the Arduino IDE.

Two converter chips are common on inexpensive boards. Look next to the board's USB port (you may need a magnifying glass):

Newer boards may not need a driver at all

ESP32-S3 and ESP32-C3 boards that connect the USB port directly to the chip itself (native USB) are usually recognized without any driver on Windows 10/11, macOS and Linux. This lesson focuses on the classic ESP32 with a converter chip, because it's the most common board on the market.

Windows: checking in Device Manager

  1. Open Device Manager: press Win+X › Device Manager.
  2. Connect the board with a data cable and look at the Ports (COM & LPT) section. If you see something like Silicon Labs CP210x USB to UART Bridge (COM5) or USB-SERIAL CH340 (COM6), the driver is installed. The number in parentheses is the port you'll select in the Arduino IDE.
  3. If there's nothing under Ports, look at the Other devices section. A device with a yellow triangle and a name like CP2102 USB to UART Bridge Controller or USB2.0-Serial means the hardware was detected but there's no driver. Install the right driver from the links in the table above, then unplug the board and plug it back in. Exact install steps: for the CP2102, get the ZIP file from the Silicon Labs site (for example CP210x Universal Windows Driver) and Extract All first (don't run it from inside the ZIP); if there's a CP210xVCPInstaller_x64.exe file inside, run it, otherwise right-click silabser.inf › Install (on Windows 11, choose Show more options first). For the CH340, run CH341SER.EXE and click the INSTALL button; the message "Driver install success" means you're done.
  4. If nothing changed in any section, the problem isn't the driver; your cable is charge-only (explained further down).
  5. An identification trick: if you're not sure which device is your board, unplug the board and see which row disappears. To see the exact ID: right-click the device › Properties › Details › Hardware Ids. If you see VID_10C4&PID_EA60, it's a CP2102; if it's VID_1A86, it's a WCH chip.
Windows 10 and 11 often find the driver on their own

If the computer is connected to the internet, Windows Update usually installs the CP210x and CH340 drivers automatically. So first wait a minute and look at Device Manager again, and only then move on to installing manually.

Linux: the port and the dialout group

On Linux, the drivers for both chips (cp210x and ch341) are built into the Linux kernel itself and need no installation. But there are two common problems: access permissions, and an interfering program on Ubuntu. Run these commands in a terminal, one at a time:

ls /dev/ttyUSB* /dev/ttyACM*
sudo dmesg | tail -n 15
groups
sudo usermod -a -G dialout $USER
sudo apt remove brltty
  1. List the serial ports. Boards with a CP2102 or CH340 usually show up as /dev/ttyUSB0; native-USB boards (S3, C3) as /dev/ttyACM0. If you see the message No such file or directory, there's no port at all. This is the quickest test: run it before and after plugging in the board. If a new name appears, the hardware and the driver are fine.
  2. Linux kernel messages. Shows the last 15 lines of the system log. Right after plugging in the board you should see something like cp210x converter now attached to ttyUSB0 or ch341-uart converter now attached to ttyUSB0. If there's no sign of USB activity here, the cable is charge-only. If you see it attach and then immediately disconnected, see command 5.
  3. Your user's groups. Lists the groups you belong to. The word dialout should be in it. On Linux, the /dev/ttyUSB0 file belongs to the dialout group. If you're not a member, uploads fail with a Permission denied error.
  4. Add yourself to dialout. -a -G means "add to my current groups", and $USER is your user name. After this command, log out once and log back in (or restart the computer). Group membership is only read when you log in. Many people run the command, try again straight away and think it didn't work. On Arch Linux this group is called uucp. Never run the Arduino IDE with sudo to get around this problem; your settings files end up owned by root, and that causes worse problems.
  5. Remove brltty (only if needed). brltty is a program for braille displays. On some Ubuntu versions (such as 22.04) it mistakenly "grabs" the CH340 device, and the port disappears immediately. Only run this command if dmesg shows the port attaching and then detaching right away, with a mention of brltty. If you use a braille display, don't do this.

macOS

In the Mac terminal, type ls /dev/cu.*. Your board usually shows up with a name like /dev/cu.usbserial-0001, /dev/cu.SLAB_USBtoUART (if the Silicon Labs driver is installed) or /dev/cu.wchusbserial…. In the Arduino IDE, always pick the entry that starts with cu., not tty.. Recent versions of macOS recognize many of these chips without a separate driver. If no port appears, install the driver from the maker's site (table above), then allow it to run in System Settings › Privacy & Security (macOS usually shows an Allow button there).

The big trap: a charge-only cable

Change the cable first, then the driver

Many cheap micro-USB and USB-C cables (for example the one that came with a power bank or a Bluetooth speaker) only have the two power wires and lack the data wires (D+ and D−). With these cables the power LED on the board lights up and you think everything is fine, but the computer sees no device at all, neither under Ports nor under Other devices. A simple test: connect your phone to the computer with the same cable. If you can't transfer files, the cable is charge-only. Label one reliable cable and use it only for programming.

First upload: the ESP32 introduces itself

You might expect the first program to be Blink. The Arduino IDE does have a ready-made Blink example (File › Examples › 01.Basics › Blink), but with the ESP32 Dev Module board it gives this error:

error: 'LED_BUILTIN' was not declared in this scope

Why? LED_BUILTIN is a name each board defines for "the pin of its built-in LED". The official DevKitC board has no programmable LED at all, so Espressif doesn't define this name for the ESP32 Dev Module (we checked this board's pin definition file in core 3.x). If your board has a blue LED on GPIO2, just add this line at the top of the Blink example:

#define LED_BUILTIN 2   // only if your board has a blue LED on GPIO2
  1. Defining a name. #define tells the compiler "wherever you see LED_BUILTIN, put the number 2 in its place". This substitution happens before the actual compilation. Instead of tinkering with the example code or the core's files, we filled the gap right here. But it's better to get used to the approach from lesson 2.2: const int LED_PIN = 2;, which has a type and is safer.

Instead, we'll start our first test with a program that works on any ESP32 board, even without an LED: a program that prints the chip's details over the Serial Monitor. That way you test both the upload and the serial connection.

  1. Create a new sketch: File › New Sketch. Delete everything in it and paste in the code below.
  2. Save it: Ctrl+S, and name it hello_esp32. The Arduino IDE creates a folder with the same name for you (every sketch must live in a folder named after itself).
// First test: the ESP32 introduces itself
void setup() {
  Serial.begin(115200);
  delay(1000);                          // wait for the Serial Monitor to get ready
  Serial.println();
  Serial.println("Hello! ESP32 is alive :)");
  Serial.print("Chip model: ");
  Serial.println(ESP.getChipModel());
  Serial.print("Chip revision: ");
  Serial.println(ESP.getChipRevision());
  Serial.print("CPU MHz: ");
  Serial.println(ESP.getCpuFreqMHz());
  Serial.print("Flash MB: ");
  Serial.println(ESP.getFlashChipSize() / (1024 * 1024));
}

void loop() {
  Serial.print("Uptime (s): ");
  Serial.println(millis() / 1000);      // seconds since power-up
  delay(2000);
}
  1. A comment. A note for humans; the compiler ignores it. Get into the habit of writing one line at the top of every program that says "what this program does".
  2. The setup function. Runs once, after power-up or a reset. We print the whole introduction here. The chip's details don't change; there's no need to print them again every two seconds.
  3. Serial.begin(115200). Turns on serial communication at 115,200 bits per second. This number must match the one at the bottom of the Serial Monitor window; otherwise you see scrambled characters. 115200 is the standard in the ESP32 world.
  4. delay(1000). Waits one second. After an upload the board resets, and it takes a moment for the Serial Monitor to reconnect to the port. Without this pause you might miss the first messages and think the program isn't working.
  5. A blank line and a hello. println() with nothing inside just moves to the next line. At power-up the ESP32 sends a few lines of boot messages (sometimes with strange characters). The blank line separates our message from them. We keep Serial text in plain English because non-Latin text (such as Persian) sometimes shows up garbled in the Serial Monitor.
  6. Chip model. ESP.getChipModel() returns the chip's exact name, for example ESP32-D0WD-V3, which is what sits inside the WROOM-32E module. ESP is a ready-made object in the ESP32 core that reports hardware information. If you bought a board and doubt it's really an ESP32, this line gives you the answer.
  7. Chip revision. In core 3.x it returns a number like 301, which means revision v3.1 (the first digit is the major version, the next two the minor version). v3 chips don't have the hardware bugs of the older revisions. Older tutorials (core 2.x) showed a number like 1 or 3; don't be surprised.
  8. CPU frequency. Usually 240 MHz. In lesson 6.1 you'll learn to lower this number to save battery. For now, just see what the default is.
  9. Flash memory size. getFlashChipSize() gives the size in bytes; dividing by 1024 * 1024 turns it into megabytes. For a regular WROOM: 4. Flash is where your program is stored. If your program ever doesn't fit, this number is your ceiling.
  10. loop: a sign of life. Every two seconds it prints how many seconds have passed since power-up. millis() gives the number of milliseconds that have passed, and dividing by 1000 turns it into seconds. A number that keeps going up proves the board isn't stuck and isn't constantly resetting. If the number keeps going back to 0 or 1, the board is resetting (for example because of a brownout; see the troubleshooting table).

Uploading and seeing the result

  1. Check the board and port in the selector at the top (number 3): ESP32 Dev Module and the port you found in the driver section (for example COM5 or /dev/ttyUSB0).
  2. Click Upload (→). The first time, compiling the whole ESP32 core takes one to several minutes; later uploads are much faster because the result is cached.
  3. Watch the Output panel. The normal order is: Sketch uses … bytes → Connecting.... → Writing at 0x… (100%) → Hard resetting via RTS pin....
  4. If Connecting....___.... goes on for a long time, hold the BOOT button on the board until writing starts, then let go.
  5. Open the Serial Monitor (number 4) and set the speed at the bottom of the window to 115200 baud. If you don't see the introduction message, press the board's EN (reset) button once.

The output should look something like this (the model and numbers may be a little different for your board):

Hello! ESP32 is alive :) Chip model: ESP32-D0WD-V3 Chip revision: 301 CPU MHz: 240 Flash MB: 4 Uptime (s): 1 Uptime (s): 3 Uptime (s): 5
A small experiment

Press the EN button. The Uptime number starts again from 1 and the introduction is printed again. Now you've seen with your own eyes that a "reset" means running setup again from the beginning. Before our message you'll also see a few lines like rst:0x1 (POWERON_RESET); these are the ESP32's own boot messages, and they tell you the reason for the reset. They'll come in very handy for troubleshooting later.

If the core download is slow or fails

The ESP32 core files (compilers and tools) add up to a few hundred megabytes and are downloaded from GitHub servers. Sometimes this download is slow, drops out partway, or stops with errors such as Error downloading …, context deadline exceeded or connection reset, a bit like a big movie download that breaks off when your Wi-Fi hiccups. Try these methods in order:

  1. Try again. Many errors are temporary. Close the Boards Manager, open it again and click Install. Files that finished downloading stay in the staging folder (see below) and usually aren't downloaded again.
  2. Try a different network. School, university and office networks sometimes limit big downloads; try your home internet or your phone's hotspot.
  3. The IDE's own proxy setting. If your network (usually an office network) uses a proxy, open File › Preferences, go to the Network tab, choose Manual proxy configuration and enter the address and port your IT department gave you.
  4. Copy from another computer (the offline method). If a friend has installed the ESP32 core on a computer with the same operating system, copy the packages/esp32 folder from their Arduino15 folder (table below) to the same path on your computer, and also take the package_esp32_index.json file from the root of their Arduino15 folder. Then open the Arduino IDE. Alternative: copy their staging/packages folder; it holds the downloaded archives, and the IDE usually uses them during Install instead of downloading again.

Part B: VS Code + PlatformIO

PlatformIO is an extension for Microsoft's free VS Code editor. It uses the same compiler and the same Arduino core, so your code runs in it almost unchanged. The difference is in "project management".

An everyday example

The Arduino IDE is like a small, tidy home kitchen: perfect for making a simple meal. PlatformIO is like a restaurant kitchen: every dish (project) has its own written recipe that says exactly which ingredients, of which brand and which version. If a different cook comes in tomorrow, they make the same dish exactly the same way.

Why and when to move to PlatformIO?

  • Library versions are recorded in the project itself. In the Arduino IDE, libraries are shared across all projects; if you update a library for a new project, an old project may break. In PlatformIO, every project has its own libraries at specific versions.
  • Powerful IntelliSense. As you type, VS Code shows function names, parameters and errors under your code; Ctrl+click any function to jump to its definition.
  • Multi-file projects and Git. Splitting code into several files and keeping its history with Git feels natural in VS Code.
  • Downside: it's harder to get started, the first install is heavier, and there are a few new concepts.
Coach's advice: when should I switch?

Do chapters 2 and 3 with the Arduino IDE so your focus stays on the ESP32 itself, not on the tools. Once your project has more than one file or more than two libraries (from chapter 4 on), take PlatformIO seriously. But install it once right now, so you know what it is.

Installation

  1. Install VS Code from code.visualstudio.com. On Windows, keep the Add to PATH option ticked during installation.
  2. Install the extension. In VS Code, click the Extensions icon (four squares, left sidebar) or press Ctrl+Shift+X. Search for PlatformIO IDE and click Install.
  3. Wait. The first time, PlatformIO downloads its own Python environment and basic tools. You can watch the progress at the bottom right of the window. At the end it asks you to reload VS Code (Reload).
  4. On Linux, in addition to the dialout group, PlatformIO recommends installing its own udev rules file; the exact command is in the udev rules documentation.

Creating your first project

  1. Open PlatformIO Home: the PlatformIO icon in the left sidebar (it looks like an ant's head) › Open › the + New Project button.
  2. Fill in the form: Name: hello_pio. Board: type ESP32 Dev and choose Espressif ESP32 Dev Module (its internal ID is esp32dev). Framework: Arduino.
  3. Finish. The first time takes a few minutes, because it downloads the ESP32 platform.

├── test/            automated tests (not for now)
└── platformio.ini   the project's ID card
  1. Automatic folders. .pio holds the compiled files and downloaded libraries; .vscode holds the editor settings. A dot at the start of the name means "technical folder". If you send the project to someone or put it in Git, leave these two out; they're recreated on the first build.
  2. include and lib. include is for your own .h files; lib is for a library you wrote yourself or downloaded by hand that only this project uses (one subfolder per library). Keeping the main code separate from helper code keeps even a big project tidy.
  3. src/main.cpp. The equivalent of the .ino file in the Arduino IDE. Your program lives here. The .cpp extension means standard C++. Unlike the Arduino IDE, PlatformIO doesn't "magically" preprocess your code (explained below).
  4. test. For automated unit tests. We don't need it in this course; but know what it's for, so you don't delete it or worry about it.
  5. platformio.ini. The most important file: the board, the platform, the speeds and the libraries are defined here. This is the "written recipe". Anyone who has this file and the src folder builds exactly the same program.

Every line of platformio.ini

Replace the file PlatformIO created for you with this more complete version:

; hello_pio - PlatformIO project configuration
[env:esp32dev]
platform = https://github.com/pioarduino/platform-espressif32/releases/download/stable/platform-espressif32.zip
board = esp32dev
framework = arduino

monitor_speed = 115200
monitor_filters = esp32_exception_decoder
upload_speed = 921600
; upload_port = COM5

lib_deps =
    adafruit/Adafruit SSD1306 @ ^2.5.7
    adafruit/DHT sensor library @ ^1.4.6
  1. A comment. In an ini file, any line that starts with ; (or #) is a comment. It does the same job as // in C++.
  2. An "environment". [env:esp32dev] means a set of settings called esp32dev. You choose the name after the colon yourself. A project can have several environments, for example one for the ESP32 and one for the ESP32-S3, and you can build for both with one click. That's something the Arduino IDE can't do.
  3. platform: which ESP32 package. Here we've chosen the community-maintained pioarduino platform, which ships version 3.x of the Arduino-ESP32 core. By default, PlatformIO writes platform = espressif32 (read the next section). All the code in this course is for core 3.x. The current official PlatformIO platform installs core 2.x, and our PWM, ESP-NOW and deep sleep code won't compile with it.
  4. board. The board ID; esp32dev is the equivalent of "ESP32 Dev Module" in the Arduino IDE. This ID tells PlatformIO the Flash size, the chip type and the upload settings.
  5. framework. arduino means we use the familiar Arduino functions (pinMode, Serial, …). The other option is espidf: Espressif's native framework, which is more powerful but much harder. For this course, Arduino is enough.
  6. monitor_speed. The speed of PlatformIO's built-in Serial Monitor. PlatformIO's default is 9600, but our code has Serial.begin(115200). If you leave this line out, you see scrambled characters. This is the most common mistake PlatformIO newcomers make.
  7. monitor_filters. When the program crashes, the esp32_exception_decoder filter translates the cryptic addresses (the backtrace) into function names and line numbers in your code. Without this filter, a crash message is just a bunch of hex numbers. With it, you see straight away which line is to blame.
  8. upload_speed. The upload speed; 921600 is fast. If uploads keep failing with errors, change this number to 460800 or 115200. A long or poor-quality cable can't handle high speeds.
  9. upload_port (disabled). Because it starts with ;, it has no effect. PlatformIO usually finds the port on its own. If you have several boards connected at once, or it doesn't find the port automatically, remove the ; and write your own port (on Linux, for example, /dev/ttyUSB0).
  10. lib_deps: libraries with versions. The format of each line is owner/name @ version. ^2.5.7 means "version 2.5.7 or any newer 2.x version, but not 3.0". On the first build, PlatformIO automatically downloads these and their dependencies (for example Adafruit GFX). These two lines are only examples (for the OLED display and the DHT22 sensor in lesson 3.3); the hello project doesn't need them and you can delete them. The major version (the first number) usually changes when the author has made incompatible changes. ^ accepts updates and bug fixes, but protects your code from suddenly breaking. Continuation lines must start with spaces (indentation).

Important: official PlatformIO and core 3.x

This part is a bit technical, but if you skip it, you'll get confused later. The PlatformIO team has announced that it won't add official support for version 3.x of the Arduino-ESP32 core. At the time of writing (2026), the official platform = espressif32 platform still installs core 2.0.17 (we checked this in the official platform's definition file). That's why the community built an independent fork called pioarduino, which brings core 3.x and is kept up to date.

  • Option 1 (our recommendation): write the platform = https://github.com/pioarduino/…/platform-espressif32.zip line from above in the regular PlatformIO extension. This URL comes from the official pioarduino README and always points to the latest stable release.
  • Option 2: the pioarduino team also has a separate VS Code extension called pioarduino IDE that does this by default. Installing both extensions at the same time isn't recommended; pick one.
To be honest: pioarduino isn't official

pioarduino is maintained by a small team of volunteers, not by PlatformIO or Espressif themselves. So far it has been active and widely used, but if something changes one day, check its GitHub page for the latest instructions. If you only use the Arduino IDE, none of this concerns you.

For comparison, here's the simple default form (core 2.x, only so you recognize it in other tutorials):

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
  1. The official platform. Just one word: espressif32. The other lines are the same as before. If you see this line in a tutorial and its code uses ledcSetup, now you know why it won't compile with our settings: that tutorial was written for core 2.x.

main.cpp: one line you mustn't forget

Replace the contents of src/main.cpp with this code:

#include <Arduino.h>          // this line is required in PlatformIO

void setup() {
  Serial.begin(115200);
  delay(1000);
  Serial.println("Hello from PlatformIO!");
}

void loop() {
  Serial.printf("Uptime: %lu s\n", millis() / 1000);
  delay(2000);
}
  1. #include <Arduino.h>. Adds the file that declares all the Arduino functions (Serial, pinMode, delay, …) to the program. The Arduino IDE quietly adds this line to .ino files, but in a .cpp file you have to write it yourself. Without it you get the error 'Serial' was not declared in this scope.
  2. setup. Same as before: start serial, wait one second, print a message. The 115200 speed matches monitor_speed in platformio.ini. If you change one, you have to change the other too.
  3. Serial.printf. Formatted printing: %lu is a placeholder for a large unsigned number (the unsigned long type that millis() returns), and \n means "go to the next line". printf builds a whole line with one call, instead of several print calls in a row. This function exists in the ESP32 core, but not on the Arduino Uno.
  4. delay(2000). A two-second pause. Without a pause, thousands of lines per second get printed and the Serial Monitor becomes unreadable.
The second hidden difference: function order

In an .ino file you can define a function at the bottom of the file and call it higher up; the Arduino IDE creates its "declaration" (prototype) at the top of the file for you. In a .cpp file there's no such magic. If you write a function like void blinkTwice(); after loop and call it inside loop, you have to add a declaration line void blinkTwice(); at the top of the file, or move the whole function above loop.

Coach's advice

When an upload fails, three things are off-limits: reinstalling the Arduino IDE, buying a new board, and blindly copying fixes from forums. First, read the whole error message and work out which stage it belongs to: compiling (your code) or uploading (cable, driver, port, BOOT). Then go from simple to hard: cable → port → driver → BOOT → upload speed. Ninety percent of problems are solved in the first two steps. And one iron rule: change only one thing at a time, or you'll never know which change fixed the problem.

Lesson quiz

You've plugged in the board and the red power LED is on, but nothing changes in Device Manager (neither under Ports nor under Other devices). What's the most likely cause?

  1. The CH340 driver isn't installed
  2. The cable is charge-only and has no data wires
  3. The wrong board is selected in the Tools menu
  4. The ESP32 chip is burned out
"No change at all" means Windows didn't see a USB device at all. A charge-only cable carries power but not data. If only the driver were missing, an unknown device would appear.

In the Boards Manager, which package do you install for an ordinary ESP32 DevKitC board?

  1. Arduino ESP32 Boards by Arduino
  2. Arduino AVR Boards
  3. esp8266 by ESP8266 Community
  4. esp32 by Espressif Systems (version 3.x)
Espressif's official package covers all generic ESP32 boards, and its 3.x version matches the code in this course.

You uploaded a PlatformIO project and the monitor shows scrambled characters such as ⸮⸮x⸮⸮. The code has Serial.begin(115200). What did you forget?

  1. The monitor_speed = 115200 line in platformio.ini
  2. The #include <Arduino.h> line
  3. The upload_speed = 921600 line
  4. The lib_deps line
The PlatformIO monitor defaults to 9600. When the two sides talk at different speeds, the characters come out scrambled.

You compiled code from an old tutorial in the Arduino IDE (with core 3.x) and got the error 'ledcSetup' was not declared in this scope. What's the best thing to do?

  1. Reinstall the CP2102 driver
  2. Downgrade the core to 2.x and carry on
  3. Recognize that the code was written for core 2.x and rewrite it with the 3.x ledcAttach and ledcWrite
  4. Set the board to ESP32-S3 Dev Module
A "not declared" error belongs to the compile stage. ledcSetup was removed in 3.x. Rewrite the code for the new API.

On Linux, you ran sudo usermod -a -G dialout $USER and uploaded straight away, but you still got Permission denied. Why?

  1. The command is wrong
  2. Group membership only takes effect after you log out and log back in
  3. You have to run the Arduino IDE with sudo
  4. The CP2102 driver isn't installed on Linux
Groups are read when you log in. Log out and back in once (or restart).

Why do you have to write #include <Arduino.h> in a PlatformIO project's src/main.cpp, but not in an .ino file?

  1. Because PlatformIO has a different core
  2. Because it makes compiling faster
  3. Because an .ino file doesn't use Arduino.h
  4. Because the Arduino IDE quietly adds this line to .ino files, but nobody does that for .cpp files
Before compiling, the Arduino IDE preprocesses the .ino file: it adds the include and generates the function declarations. In standard .cpp files, those are your job.

  • The MAC number is exactly 12 hex digits. A test: the upload's Output panel has a line like MAC: 24:0a:c4:12:34:56. Read your printed number in pairs from the right (24 0A C4 12 34 56); it should be that same MAC.

Full answer with explanation 
// hello_esp32 + cores and MAC: a more complete ID card
void setup() {
  Serial.begin(115200);
  delay(1000);                          // wait for the Serial Monitor to get ready
  Serial.println();
  Serial.println("Hello! ESP32 is alive :)");
  Serial.print("Chip model: ");
  Serial.println(ESP.getChipModel());
  Serial.print("Chip revision: ");
  Serial.println(ESP.getChipRevision());
  Serial.print("CPU MHz: ");
  Serial.println(ESP.getCpuFreqMHz());
  Serial.print("Flash MB: ");
  Serial.println(ESP.getFlashChipSize() / (1024 * 1024));
  Serial.print("Cores: ");
  Serial.println(ESP.getChipCores());   // for the classic ESP32: 2
  Serial.printf("eFuse MAC: %012llX\n", ESP.getEfuseMac());
}

void loop() {
  Serial.print("Uptime (s): ");
  Serial.println(millis() / 1000);      // seconds since power-up
  delay(2000);
}
  1. The earlier part, unchanged. The same introduction as the original program. We add the new lines at the end of setup so the earlier output stays the same and you can easily see what was added.
  2. Number of cores. The classic ESP32 has two cores (you saw this in lesson 1.1). Single-core versions exist too (such as the ESP32-C3); this line shows the difference instantly.
  3. A unique ID from the eFuse. A 48-bit number that the factory "burned" into the chip. %012llX means "print the 64-bit number as 12 hex digits with leading zeros". The byte order in this number is the reverse of the usual way a MAC is written; don't worry about it. In lesson 5.2 (ESP-NOW) you'll learn the standard way to read the MAC with the WiFi library.
  4. loop, unchanged. Uptime every two seconds. A rising number shows the board didn't get stuck after printing its ID card.

Moving to PlatformIO: paste the same code into src/main.cpp and add one line at the top of the file: #include <Arduino.h>. platformio.ini must also have monitor_speed = 115200; without it the Monitor opens at the default 9600 and you see scrambled characters.

This program has no external parts, so it runs in Wokwi too (the same three steps as in lesson 1.1). The simulator's model, revision and MAC differ from a real board; Cores should be 2.

Exercise 3: deliberate errors (the most important exercise)

Deliberately make these three mistakes, one at a time, and write down the exact error text or behavior in a notebook: (a) delete one ; from the code and click Verify. (b) Set the port to a wrong or empty port and click Upload. (c) Set the Serial Monitor speed to 9600. Next to each error, write which stage it belongs to: compiling, uploading or the monitor.

Hint

For (a), notice which line the word after before in the message belongs to; it's usually on the line after the real mistake. Why?

What should you see?

(a) If you delete the ; after Serial.begin(115200), the Output panel shows:

hello_esp32.ino:3:23: error: expected ';' before 'delay'
    3 |   Serial.begin(115200)
      |                       ^
      |                       ;
    4 |   delay(1000);
exit status 1
Compilation error: expected ';' before 'delay'

(b) A port that doesn't exist (on Windows, something like COM7 instead of /dev/ttyUSB5):

A fatal error occurred: Could not open /dev/ttyUSB5, the port is busy or doesn't exist.

A port that exists but isn't the ESP32 (for example, the computer's Bluetooth port): Failed to connect to ESP32: No serial data received. And if no port is selected at all: no upload port provided.

  • (a) shows up with Verify alone, before any upload; so it's the compiling stage. 3:23 means line 3, column 23.
  • (b) only appears after "Sketch uses … bytes"; so compiling succeeded and the problem is in uploading.
  • (c) the upload succeeds and the program runs; only the text is broken. Setting the speed back to 115200 and pressing EN fixes it.
Full answer with explanation

(a) Compiling: a message like expected ';' before 'delay'. The compiler only realizes the ; is missing when it reaches the next word (delay on line 4), because in C++ a statement may continue over several lines and the end of a line means nothing to the compiler. Today's compiler points at line 3 correctly, but the word it names is on the next line (and other errors are sometimes really reported on the next line); so always look at the reported line and the one before it. (b) Uploading: a message about the port not opening, or Failed to connect. (c) Monitor: no error at all, just scrambled characters; the board sends at 115,200 bits per second and the monitor reads at 9600, so the bits get cut in the wrong places. This notebook is your personal dictionary of errors; keep it.

  • The source file didn't change between the three builds; compare them with a diff tool or copy-paste to be sure.
  • The Uptime numbers go up by 2 and start at 1 (setup waits one second first).
  • If PlatformIO shows scrambled characters, monitor_speed is missing in that environment.
  • If the Arduino IDE says 'BUILT_WITH' was not declared, TODO 2 is missing; in the IDE, nobody else defines the name.
Full answer with explanation 
// One code, two tools: the same file builds in the Arduino IDE and PlatformIO
#include <Arduino.h>                 // needed in PlatformIO, harmless in the IDE

#ifndef BUILT_WITH                   // PlatformIO sets this in platformio.ini
#define BUILT_WITH "Arduino IDE"     // nobody set it, so this is the Arduino IDE
#endif

void printCard();                    // declaration: the body comes after loop()

void setup() {
  Serial.begin(115200);
  delay(1000);
  printCard();
}

void loop() {
  Serial.printf("Uptime: %lu s\n", millis() / 1000);
  delay(2000);
}

void printCard() {
  Serial.println();
  Serial.println("=== One code, two tools ===");
  Serial.printf("Built with : %s\n", BUILT_WITH);
  Serial.printf("Core       : %d.%d.%d\n", ESP_ARDUINO_VERSION_MAJOR,
                ESP_ARDUINO_VERSION_MINOR, ESP_ARDUINO_VERSION_PATCH);
  Serial.printf("Chip model : %s\n", ESP.getChipModel());
}
  1. #include <Arduino.h>. Declares Serial, delay, millis and friends. PlatformIO needs it in a .cpp file; the Arduino IDE adds it anyway, and including it twice is harmless. That's the first key to portability.
  2. A default tool name. If the build didn't define BUILT_WITH, define it as "Arduino IDE". The code never asks "which tool am I in?"; it just uses a name that the build may fill in. PlatformIO fills it in, the IDE doesn't, and the default covers that case.
  3. The declaration (prototype). Tells the compiler that a function printCard exists before setup uses it. This is the second hidden difference from this lesson: the IDE writes this line for you, PlatformIO doesn't. With it written by hand, both are happy.
  4. setup and loop. Serial, a one-second wait, the card, then the uptime every two seconds with printf and %lu. Identical to the programs in this lesson, so any difference in the output comes from the tools, not the code.
  5. printCard(). Prints the tool name, the core version and the chip model. ESP_ARDUINO_VERSION_MAJOR, _MINOR and _PATCH are numbers the core itself defines (in both 2.x and 3.x). Printing the core version at start-up is a professional habit: when a bug report says "it worked yesterday", this line tells you whether the core was updated.
; One code, two tools: two environments, one source file
[platformio]
; Build and Upload use this one unless you pick another
default_envs = core3

; community pioarduino platform: core 3.x
[env:core3]
platform = https://github.com/pioarduino/platform-espressif32/releases/download/stable/platform-espressif32.zip
board = esp32dev
framework = arduino
monitor_speed = 115200
build_flags = '-D BUILT_WITH="PlatformIO core3"'

; official PlatformIO platform: core 2.0.17
[env:core2]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
build_flags = '-D BUILT_WITH="PlatformIO core2"'
  1. default_envs. The Build and Upload buttons use core3. Without this line, PlatformIO builds every environment and Upload would flash the board twice in a row.
  2. env:core3. The pioarduino platform (core 3.x) plus build_flags. The single quotes around the whole flag keep the double quotes and the space inside the text. -D NAME="text" is the compiler's way of writing #define NAME "text", so the #ifndef in the sketch sees the name as already defined.
  3. env:core2. The same settings with the official espressif32 platform, which installs core 2.0.17. This is how you check whether an old tutorial's code (core 2.x) or yours (core 3.x) is behind a strange error: build the same file both ways. This simple sketch happens to work on both; the PWM code of lesson 3.2 would not.

Quick check in Wokwi (board only): the card appears with Built with : Arduino IDE, because Wokwi builds like the Arduino IDE.

The lesson in three lines

Install Arduino IDE 2, put the package_esp32_index.json URL in Preferences, install "esp32 by Espressif Systems" version 3.x and select ESP32 Dev Module. If there's no port: first a data cable, then the CP2102 or CH340 driver, and on Linux the dialout group. PlatformIO is for bigger projects: platformio.ini with the pioarduino platform (core 3.x), monitor_speed = 115200, and #include <Arduino.h> in main.cpp.
