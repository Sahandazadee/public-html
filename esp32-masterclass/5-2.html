تا حالا هر ارتباط بی‌سیمی که ساختی به یک مودم یا یک سرور وسط نیاز داشت. ولی اگر در حیاط، باغ یا کارگاه مودمی نباشد چه؟ اگر بخواهی یک دکمه در دست تو، در کمتر از چند میلی‌ثانیه چراغی را آن طرف ساختمان روشن کند چه؟ ESP-NOW پروتکل اختصاصی Espressif است که دو (یا چند) ESP32 را مستقیم و بدون هیچ مودمی به هم وصل می‌کند. در این درس یک ریموت می‌سازی: دکمه روی برد A، LED روی برد B، و برد B دمای خودش را به عنوان رسید برمی‌گرداند.

  • با struct یک «قالب پیام» بسازی و با sizeof و memcpy بفرستی و بگیری
  • امضای درست Callbackها در هسته ۳ را بنویسی و کد قدیمی ۲.x را تشخیص بدهی
  • ارتباط دوطرفه با تایید (ACK) و زمان انتظار (Timeout) بسازی
  • ESP-NOW را هم‌زمان با Wi-Fi روی یک کانال راه بیندازی

این درس دو برد ESP32 واقعی لازم دارد

ESP-NOW گفتگوی بین دو برد است، پس پروژه‌های ۱ و ۲ فقط با دو ESP32 کار می‌کنند (فهرست خرید دوره دقیقا برای همین درس یک برد دوم دارد). Wokwi ارتباط ESP-NOW بین دو برد را شبیه‌سازی نمی‌کند. با یک برد هم می‌توانی بخش اول درس (آدرس MAC و نمایش struct، هر دو در Wokwi هم) را انجام دهی و بقیه را بخوانی تا وقتی برد دوم رسید آماده باشی.

ESP-NOW چیست؟

ESP-NOW از همان رادیوی ۲٫۴ گیگاهرتز Wi-Fi که داخل ESP32 است استفاده می‌کند، ولی کل تشریفات Wi-Fi (اتصال به مودم، گرفتن IP، TCP، دست دادن و...) را کنار می‌گذارد. هر پیام یک بسته کوچک است که مستقیم با «آدرس MAC» برد مقصد فرستاده می‌شود؛ درست مثل این که به جای رفتن به اداره پست، نامه را مستقیم از پنجره به همسایه بدهی.

مثال از زندگی روزمره: بی‌سیم واکی‌تاکی در برابر تلفن

Wi-Fi و MQTT مثل تلفن زدن است: شماره می‌گیری، مرکز مخابرات (مودم و Broker) تو را وصل می‌کند و بعد حرف می‌زنی. از هر جای دنیا کار می‌کند، ولی بدون مرکز مخابرات هیچ. ESP-NOW مثل واکی‌تاکی است: دکمه را می‌زنی و صدا مستقیم به دستگاه دیگر می‌رسد. سریع است و مرکزی لازم ندارد، ولی فقط تا جایی که صدا برسد، و پیام‌ها باید کوتاه باشند.

قدم اول: آدرس MAC برد را پیدا کن

آدرس MAC یک شماره ۶ بایتی است که کارخانه روی هر تراشه ESP32 نوشته، مثل 24:6F:28:AB:CD:EF. مثل پلاک خانه است: ESP-NOW نامه را با همین پلاک به مقصد می‌رساند. هر عدد دو رقمی یک بایت در مبنای ۱۶ (هگز) است.

#include <WiFi.h>

void setup() {
  Serial.begin(115200);
  delay(1000);
  Serial.print("Before WiFi.mode: ");
  Serial.println(WiFi.macAddress());   // احتمالا 00:00:00:00:00:00

  WiFi.mode(WIFI_STA);                 // رادیوی Wi-Fi روشن می‌شود
  while (!WiFi.STA.started()) {
    delay(10);
  }
  Serial.print("STA MAC: ");
  Serial.println(WiFi.macAddress());
}

void loop() {}
  1. خواندن MAC قبل از روشن شدن Wi-Fi. عمدا یک بار MAC را قبل از WiFi.mode چاپ می‌کنیم. در هسته ۳ آردوینو، WiFi.macAddress() آدرس را از «رابط شبکه» (Network Interface) می‌خواند و این رابط تا Wi-Fi راه نیفتد وجود ندارد؛ برای همین 00:00:00:00:00:00 می‌گیری. خیلی از دانشجوها همین صفرها را در کد فرستنده کپی می‌کنند و بعد ساعت‌ها دنبال مشکل می‌گردند.
  2. WiFi.mode(WIFI_STA). رادیو را در حالت ایستگاه (Station) روشن می‌کند؛ لازم نیست به هیچ مودمی وصل شود. ESP-NOW روی رابط STA یا AP کار می‌کند و ما همیشه STA را انتخاب می‌کنیم. هر رابط MAC جدای خودش را دارد (MAC رابط AP معمولا یک واحد بیشتر است)؛ پس MAC همان رابطی را بردار که ESP-NOW رویش کار می‌کند.
  3. صبر تا رابط STA واقعا شروع شود. WiFi.STA.started() وقتی true می‌شود که راه‌اندازی رادیو تمام شده باشد. روشن شدن Wi-Fi روی یک Task جدا و چند میلی‌ثانیه طول می‌کشد. مثال‌های رسمی Espressif برای ESP-NOW هم دقیقا همین حلقه انتظار را دارند.
  4. MAC واقعی. حالا آدرس درست چاپ می‌شود. آن را روی یک تکه چسب کاغذی بنویس و روی برد بچسبان! در ادامه دو برد داری و MACها شبیه هم‌اند. برچسب زدن جلوی اشتباه گرفتن برد A و B را می‌گیرد.
Before WiFi.mode: 00:00:00:00:00:00 STA MAC: 24:6F:28:AB:CD:EF

این برنامه را روی برد B (گیرنده) آپلود کن و MAC آن را یادداشت کن. برای نوشتن در کد، هر بخش را با 0x شروع کن: 24:6F:28:AB:CD:EF می‌شود {0x24, 0x6F, 0x28, 0xAB, 0xCD, 0xEF}.

قالب پیام: struct، sizeof و memcpy

ESP-NOW فقط «یک مشت بایت» می‌فرستد و نمی‌داند معنی آن‌ها چیست. ما باید قراری بگذاریم که بایت اول تا چهارم یعنی شماره پیام، بایت پنجم یعنی روشن یا خاموش و... این قرار را در C++ با struct (ساختار) می‌نویسیم.

مثال از زندگی روزمره: فرم چاپی

struct مثل یک فرم اداری چاپی است: خانه اول «شماره»، خانه دوم «وضعیت». فرستنده فرم را پر می‌کند و می‌فرستد. گیرنده باید دقیقا همان فرم را داشته باشد تا بداند هر خانه چه معنی دارد. اگر گیرنده فرم نسخه قدیمی را داشته باشد که جای خانه‌ها فرق دارد، عدد دما را به جای شماره می‌خواند!

حساب کن: sizeof واقعا چند است؟

قالب فرمان ما: uint32_t seq (۴ بایت) + bool ledOn (۱ بایت). جمع = ۵ بایت؟ نه! sizeof(CommandMsg) روی ESP32 برابر ۸ است. کامپایلر بعد از bool سه بایت خالی (Padding) می‌گذارد تا اندازه کل مضرب ۴ شود، چون پردازنده ۳۲ بیتی عددهای ۴ بایتی را از آدرس‌های مضرب ۴ سریع‌تر می‌خواند. قالب جواب: ۴ + ۱ + ۳ (خالی) + float ۴ = ۱۲ بایت.

نتیجه عملی: اگر یک طرف ESP32 و طرف دیگر یک تراشه یا کامپایلر دیگر باشد (مثلا ESP8266)، Padding ممکن است فرق کند. بین دو ESP32 با یک هسته مشکلی نیست. برای اطمینان کامل می‌شود __attribute__((packed)) را بعد از struct نوشت تا Padding حذف شود.

  • sizeof(x) تعداد بایت‌های x را در زمان کامپایل می‌دهد. همیشه از آن استفاده کن، هرگز عدد را دستی ننویس.
  • memcpy(مقصد, مبدا, تعداد) تعدادی بایت را عینا از یک جای حافظه به جای دیگر کپی می‌کند. با آن بایت‌های رسیده را روی متغیر struct خودمان می‌ریزیم.
  • (uint8_t *)&cmd یعنی «آدرس متغیر cmd را به عنوان آرایه‌ای از بایت ببین». & آدرس می‌دهد و (uint8_t *) نوع را عوض می‌کند، بدون این که داده‌ای تغییر کند.

قبل از هر کد رادیویی، بیا همه این‌ها را با چشم خودمان ببینیم. برنامه زیر فقط یک برد و هیچ رادیویی لازم دارد: اندازه‌ها را چاپ می‌کند، بایت‌های واقعی یک پیام را نشان می‌دهد و آن‌ها را با memcpy دوباره «دریافت» می‌کند، دقیقا همان کاری که برد B خواهد کرد. آن را روی هر ESP32 یا در Wokwi اجرا کن (یک پروژه خالی ESP32؛ کد را در sketch.ino بچسبان و ▶ را بزن).

typedef struct {
  uint32_t seq;     // شماره پیام
  bool ledOn;       // LED روشن باشد؟
} CommandMsg;

typedef struct {
  uint32_t seq;
  bool ledOn;
  float tempC;
} ReplyMsg;

CommandMsg cmd;     // سراسری، پس همه بایت‌ها (حتی Padding) از صفر شروع می‌کنند

void printBytes(const char *label, const uint8_t *p, size_t n) {
  Serial.printf("%s (%u bytes):", label, (unsigned)n);
  for (size_t i = 0; i < n; i++) Serial.printf(" %02X", p[i]);
  Serial.println();
}

void setup() {
  Serial.begin(115200);
  delay(1000);
  Serial.printf("sizeof(CommandMsg) = %u\n", (unsigned)sizeof(CommandMsg));
  Serial.printf("sizeof(ReplyMsg)   = %u\n", (unsigned)sizeof(ReplyMsg));

  cmd.seq = 258;                        // 258 = 0x00000102
  cmd.ledOn = true;
  printBytes("cmd", (uint8_t *)&cmd, sizeof(cmd));

  uint8_t air[sizeof(cmd)];             // فرض کن این بایت‌ها از هوا رد شده‌اند
  memcpy(air, &cmd, sizeof(cmd));       // فرستنده: struct به بایت
  CommandMsg got;
  memcpy(&got, air, sizeof(got));       // گیرنده: بایت به struct
  Serial.printf("got.seq = %lu, got.ledOn = %d\n", (unsigned long)got.seq, got.ledOn);
}

void loop() {}
  1. دو قالب پیام. همان دو struct که در این درس با رادیو فرستاده می‌شوند: فرمان (A به B) و جواب (B به A). وقتی اول آن‌ها را در یک برنامه کوچک ببینی، بعدا که رادیو هم وارد ماجرا شد، به این بخش اطمینان داری.
  2. یک متغیر پیام سراسری. متغیر سراسری با همه بایت‌های صفر شروع می‌شود، حتی بایت‌های Padding. بایت‌های Padding یک متغیر محلی ممکن است مقدار باقی‌مانده حافظه را داشته باشند و در خروجی آن سه جا عددهای تصادفی ببینی. بی‌ضرر است، ولی گیج‌کننده.
  3. printBytes: هر حافظه‌ای را به شکل بایت نشان بده. یک آدرس و یک طول می‌گیرد و هر بایت را به مبنای ۱۶ چاپ می‌کند (%02X یعنی «دو رقم هگز»). این‌طوری پیام را همان‌طور می‌بینی که رادیو می‌بیند: فقط یک ردیف بایت، بدون اسم و بدون نوع.
  4. چاپ اندازه‌ها. باید ۸ و ۱۲ ببینی، نه ۵ و ۹. این همان Padding کادر بالاست، این بار اندازه‌گیری‌شده به جای حساب‌شده. sizeof همیشه راست می‌گوید؛ برای همین کد رادیو همه طول‌ها را با آن می‌دهد.
  5. پر کردن فرم و دیدن بایت‌هایش. seq = 258 و ledOn = true. خروجی: 02 01 00 00 01 00 00 00. ۲۵۸ در هگز می‌شود 0x00000102. ESP32 کوچک‌ترین بایت را اول ذخیره می‌کند (به این می‌گویند «Little-endian»)، برای همین 02 01 00 00 می‌بینی. بعد bool می‌آید (01) و سه بایت Padding (00 00 00). لازم نیست این ترتیب را حفظ کنی؛ هر دو ESP32 از یک ترتیب استفاده می‌کنند و فقط همین مهم است.
  6. یک سفر رادیویی خیالی. memcpy اول struct را به یک آرایه بایت ساده تبدیل می‌کند (کاری که esp_now_send می‌کند) و دومی بایت‌ها را در یک struct تازه می‌ریزد (کاری که Callback دریافت می‌کند). اگر got.seq برابر ۲۵۸ و got.ledOn برابر ۱ شد، «فرم» سالم رسیده است. در پروژه واقعی تنها فرق این است که آرایه بایت بین دو memcpy از هوا رد می‌شود.
sizeof(CommandMsg) = 8 sizeof(ReplyMsg) = 12 cmd (8 bytes): 02 01 00 00 01 00 00 00 got.seq = 258, got.ledOn = 1

#include <WiFi.h>
#include <esp_now.h>

// MAC برد B را اینجا بنویس (از برنامه GetMac)
uint8_t receiverMac[] = {0x24, 0x6F, 0x28, 0xAB, 0xCD, 0xEF};

const int BUTTON_PIN = 27;

// قالب پیام: باید در فرستنده و گیرنده دقیقا یکی باشد
typedef struct {
  uint32_t seq;     // شماره پیام
  bool ledOn;       // LED روشن باشد یا نه
} CommandMsg;

CommandMsg cmd = {0, false};
int lastReading = HIGH;
int stableState = HIGH;
unsigned long lastChange = 0;

// هسته 3.3 به بعد: ورودی اول از نوع wifi_tx_info_t است
void onSent(const wifi_tx_info_t *info, esp_now_send_status_t status) {
  Serial.println(status == ESP_NOW_SEND_SUCCESS ? "  delivered" : "  delivery FAILED");
}

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT_PULLUP);

  WiFi.mode(WIFI_STA);
  while (!WiFi.STA.started()) delay(10);

  if (esp_now_init() != ESP_OK) {
    Serial.println("ESP-NOW init failed");
    while (true) delay(1000);
  }
  esp_now_register_send_cb(onSent);

  esp_now_peer_info_t peer = {};
  memcpy(peer.peer_addr, receiverMac, 6);
  peer.channel = 0;          // 0 یعنی همان کانالی که الان رویش هستیم
  peer.encrypt = false;
  if (esp_now_add_peer(&peer) != ESP_OK) {
    Serial.println("Failed to add peer");
    while (true) delay(1000);
  }
  Serial.println("Sender ready. Press the button.");
}

void loop() {
  int reading = digitalRead(BUTTON_PIN);
  if (reading != lastReading) {        // تغییر جدید: زمان‌سنج لرزش از نو
    lastChange = millis();
    lastReading = reading;
  }
  if (millis() - lastChange > 30 && reading != stableState) {
    stableState = reading;
    if (stableState == LOW) {          // دکمه واقعا فشرده شد
      cmd.seq++;
      cmd.ledOn = !cmd.ledOn;
      esp_err_t r = esp_now_send(receiverMac, (uint8_t *)&cmd, sizeof(cmd));
      Serial.printf("Sent #%lu ledOn=%d (%s)\n", (unsigned long)cmd.seq, cmd.ledOn, r == ESP_OK ? "queued" : esp_err_to_name(r));
    }
  }
}
  1. دو کتابخانه. WiFi.h برای روشن کردن رادیو و esp_now.h که API اصلی ESP-NOW از ESP-IDF است. ESP-NOW رادیوی Wi-Fi را لازم دارد، حتی اگر هرگز به مودم وصل نشوی. هر دو کتابخانه همراه هسته ESP32 نصب شده‌اند؛ چیزی برای نصب نیست.
  2. آدرس گیرنده. آرایه ۶ بایتی با MAC برد B. اشتباه در حتی یک رقم یعنی پیام به هیچ‌کس نمی‌رسد و Callback ارسال «FAILED» می‌گوید. این رایج‌ترین خطای ESP-NOW است.
  3. تعریف قالب پیام. typedef struct {...} CommandMsg; یک نوع داده جدید به اسم CommandMsg می‌سازد با دو خانه. uint32_t یعنی عدد صحیح بی‌علامت دقیقا ۳۲ بیتی؛ برخلاف int اندازه‌اش روی همه تراشه‌ها یکی است، که برای فرستادن داده بین دستگاه‌ها مهم است. شماره پیام (seq) کمک می‌کند بفهمیم پیامی گم شده یا تکراری رسیده.
  4. متغیرهای سراسری. خود پیام با مقدار اولیه، و سه متغیر برای Debounce دکمه. مقدار این‌ها باید بین دورهای loop بماند، پس سراسری‌اند. منطق Debounce همان درس ۳.۱ است.
  5. Callback ارسال. بعد از هر ارسال، ESP-NOW این تابع را با نتیجه صدا می‌زند: ESP_NOW_SEND_SUCCESS یا ESP_NOW_SEND_FAIL. موفقیت یعنی رادیوی برد B بسته را در لایه MAC دریافت و تایید کرده؛ نه این که برنامه B آن را پردازش کرده. اگر B روشن نباشد یا MAC غلط باشد، FAIL می‌گیری. امضای این تابع در نسخه‌ها عوض شده؛ کادر زرد پایین را حتما بخوان.
  6. روشن کردن رادیو. حالت STA و صبر تا شروع کامل. esp_now_init باید بعد از روشن شدن Wi-Fi صدا زده شود؛ وگرنه خطا می‌دهد.
  7. راه‌اندازی ESP-NOW و ثبت Callback. اگر esp_now_init موفق نبود، برنامه را در یک حلقه بی‌پایان نگه می‌داریم. ادامه دادن بدون ESP-NOW فقط خطاهای گیج‌کننده بعدی می‌سازد. «زود و بلند شکست بخور» (Fail fast) عادت خوبی است.
  8. اضافه کردن همتا (Peer). یک ساختار esp_now_peer_info_t را صفر می‌کنیم (= {})، MAC را در آن کپی می‌کنیم، کانال را ۰ و رمزنگاری را خاموش می‌گذاریم و با esp_now_add_peer به دفترچه آدرس اضافه می‌کنیم. ESP-NOW فقط به MACهایی که در دفترچه هستند پیام تکی (Unicast) می‌فرستد. کانال ۰ یعنی «همان کانال فعلی رادیو»؛ دو برد به طور پیش‌فرض روی یک کانال (معمولا ۱) روشن می‌شوند. صفر کردن ساختار مهم است: بدون آن فیلدهایی که ننوشته‌ایم مقدار آشغال دارند.
  9. تشخیص هر تغییر خام دکمه. هر بار ورودی با قبلی فرق کند، زمان را ثبت می‌کنیم. کنتاکت دکمه در لحظه فشردن چند میلی‌ثانیه «می‌لرزد» و چند بار صفر و یک می‌شود. بدون Debounce یک فشار ممکن است دو فرمان بفرستد و LED روشن و فورا خاموش شود.
  10. وضعیت پایدار. اگر ۳۰ میلی‌ثانیه تغییری نبود و وضعیت با وضعیت پایدار قبلی فرق دارد، آن را قبول می‌کنیم؛ فقط لبه «فشرده شدن» (LOW) فرمان می‌فرستد. با این روش، لرزش موقع رها کردن دکمه هم فرمان اضافه نمی‌سازد.
  11. ساختن و فرستادن پیام. شماره یکی زیاد و وضعیت برعکس می‌شود. esp_now_send(مقصد, بایت‌ها, طول) پیام را در صف ارسال می‌گذارد و فورا برمی‌گردد. ESP_OK فقط یعنی «در صف گذاشته شد»؛ نتیجه واقعی چند میلی‌ثانیه بعد در onSent می‌آید. esp_err_to_name کد خطا را به اسم خوانا (مثلا ESP_ERR_ESPNOW_NOT_FOUND یعنی Peer اضافه نشده) تبدیل می‌کند.
امضای Callbackها در نسخه‌های مختلف (آموزش‌های اینترنت را با دقت بخوان)

Callback دریافت: در هسته ۳.x امضا void onRecv(const esp_now_recv_info_t *info, const uint8_t *data, int len) است و MAC فرستنده در info->src_addr است. در هسته ۲.x امضا void onRecv(const uint8_t *mac, const uint8_t *data, int len) بود. بیشتر آموزش‌های اینترنت (حتی ویدیوی همین درس) نسخه ۲ را دارند و روی هسته ۳ با خطای invalid conversion کامپایل نمی‌شوند.

Callback ارسال: در هسته ۲.x و ۳.۰ تا ۳.۲ امضا void onSent(const uint8_t *mac_addr, esp_now_send_status_t status) بود. از هسته ۳.۳.۰ (بر پایه ESP-IDF 5.5) امضا شد void onSent(const wifi_tx_info_t *info, esp_now_send_status_t status) و MAC مقصد در info->des_addr است. اگر خطای invalid conversion from 'void (*)(const uint8_t*, esp_now_send_status_t)' گرفتی، یعنی کد قدیمی را روی هسته جدید کامپایل می‌کنی. نسخه هسته‌ات را در Tools › Board › Boards Manager ببین. اگر کدی باید روی هر دو کار کند:

#if ESP_ARDUINO_VERSION >= ESP_ARDUINO_VERSION_VAL(3, 3, 0)
void onSent(const wifi_tx_info_t *info, esp_now_send_status_t status) {
#else
void onSent(const uint8_t *mac_addr, esp_now_send_status_t status) {
#endif
  Serial.println(status == ESP_NOW_SEND_SUCCESS ? "delivered" : "FAILED");
}
  1. انتخاب امضا در زمان کامپایل. #if پیش‌پردازنده است: قبل از کامپایل، بر اساس نسخه هسته فقط یکی از دو خط اول تابع باقی می‌ماند. ماکروهای ESP_ARDUINO_VERSION را خود هسته تعریف می‌کند. بدنه تابع مشترک است چون از ورودی اول استفاده نمی‌کنیم.
  2. بدنه مشترک. فقط وضعیت را چاپ می‌کند. اگر MAC را لازم داشتی، در شاخه جدید از info->des_addr و در شاخه قدیم از mac_addr بخوان.

کد برد B (گیرنده)

#include <WiFi.h>
#include <esp_now.h>

const int LED_PIN = 4;

typedef struct {
  uint32_t seq;
  bool ledOn;
} CommandMsg;

CommandMsg incoming;
volatile bool gotMsg = false;

// امضای هسته 3.x: اطلاعات فرستنده + داده + طول
void onRecv(const esp_now_recv_info_t *info, const uint8_t *data, int len) {
  if (len != sizeof(CommandMsg)) return;   // اندازه اشتباه؟ نادیده بگیر
  memcpy(&incoming, data, sizeof(incoming));
  gotMsg = true;                          // کار اصلی را loop انجام می‌دهد
}

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  WiFi.mode(WIFI_STA);
  while (!WiFi.STA.started()) delay(10);
  Serial.print("Receiver MAC: ");
  Serial.println(WiFi.macAddress());

  if (esp_now_init() != ESP_OK) {
    Serial.println("ESP-NOW init failed");
    while (true) delay(1000);
  }
  esp_now_register_recv_cb(onRecv);
}

void loop() {
  if (gotMsg) {
    gotMsg = false;
    digitalWrite(LED_PIN, incoming.ledOn ? HIGH : LOW);
    Serial.printf("Got #%lu -> LED %s\n", (unsigned long)incoming.seq, incoming.ledOn ? "ON" : "OFF");
  }
}
  1. همان قالب پیام. کپی دقیق struct فرستنده، با همان ترتیب و همان نوع‌ها. اگر در فرستنده ترتیب seq و ledOn را عوض کنی ولی اینجا نه، بایت‌ها سر جای اشتباه خوانده می‌شوند و هیچ خطایی هم نمی‌گیری؛ فقط رفتار عجیب. در پروژه‌های بزرگ این struct را در یک فایل .h مشترک می‌گذارند.
  2. جای پیام و پرچم. incoming آخرین پیام را نگه می‌دارد و gotMsg خبر می‌دهد پیام تازه رسیده. volatile به کامپایلر می‌گوید «این متغیر ممکن است از جای دیگری عوض شود؛ هر بار از حافظه بخوانش». Callback روی Task دیگری (Task رادیوی Wi-Fi) اجرا می‌شود، نه روی loop. بدون volatile کامپایلر ممکن است مقدار را کش کند و loop هرگز تغییرش را نبیند.
  3. Callback دریافت. اول طول را چک می‌کنیم، بعد بایت‌ها را روی incoming کپی می‌کنیم و پرچم را بالا می‌بریم. info اطلاعاتی مثل MAC فرستنده (info->src_addr) و قدرت سیگنال (info->rx_ctrl->rssi) دارد. چک طول جلوی خواندن پیام‌های ناقص یا پیام‌های برنامه دیگر را می‌گیرد. کار سنگین (چاپ، digitalWrite، خواندن سنسور) را در Callback نکن: مستندات Espressif می‌گوید این تابع در Task پراولویت Wi-Fi اجرا می‌شود و طولانی شدنش دریافت‌های بعدی را مختل می‌کند. الگوی «پرچم در Callback، کار در loop» را حفظ کن.
  4. روشن کردن رادیو و چاپ MAC. همان کار برنامه GetMac. چاپ MAC در خود گیرنده یعنی هر وقت برد را عوض کردی، آدرس جدید را بی‌دردسر می‌بینی.
  5. راه‌اندازی و ثبت Callback دریافت. گیرنده لازم نیست فرستنده را به عنوان Peer اضافه کند. طبق مستندات، بدون Peer هم پیام تکی رمزنگاری‌نشده و پیام همگانی (Broadcast) دریافت می‌شود. Peer فقط برای فرستادن (و دریافت رمزنگاری‌شده) لازم است.
  6. اجرای فرمان در loop. اگر پرچم بالا بود، پایینش می‌آوریم، LED را تنظیم و نتیجه را چاپ می‌کنیم. یک نکته صادقانه: اگر دو پیام خیلی پشت سر هم برسند، ممکن است پیام دوم وسط خواندن اولی روی incoming نوشته شود. برای ریموت دستی این اتفاق عملا نمی‌افتد؛ برای داده پرسرعت از صف FreeRTOS (xQueueSend) استفاده می‌کنند که در درس ۵.۴ یاد می‌گیری.

پروژه ۲: ارتباط دوطرفه با تایید و دما

در پروژه ۱ برد A فقط می‌دانست رادیوی B بسته را گرفته. ولی آیا LED واقعا روشن شد؟ در پروژه ۲، B بعد از اجرای فرمان یک جواب برمی‌گرداند: شماره همان فرمان، وضعیت واقعی LED و دمای محیط خودش. A اگر تا ۵۰۰ میلی‌ثانیه جواب نگرفت، اعلام خطا می‌کند. این الگوی «درخواست، جواب، مهلت» (Request/Response + Timeout) پایه همه پروتکل‌های قابل اعتماد است.

#include <WiFi.h>
#include <esp_now.h>

uint8_t boardB[] = {0x24, 0x6F, 0x28, 0xAB, 0xCD, 0xEF};   // MAC برد B
const int BUTTON_PIN = 27;
const int STATUS_LED = 4;      // LED وضعیت دوره (+۲۲۰ اهم)

typedef struct {
  uint32_t seq;
  bool ledOn;
} CommandMsg;

typedef struct {
  uint32_t seq;      // شماره فرمانی که این جواب مال آن است
  bool ledOn;        // وضعیت واقعی LED روی B
  float tempC;       // دمای B (یا NAN اگر سنسور خطا داد)
} ReplyMsg;

CommandMsg cmd = {0, false};
ReplyMsg reply;
volatile bool gotReply = false;
bool waiting = false;
unsigned long sentAt = 0;
int lastReading = HIGH, stableState = HIGH;
unsigned long lastChange = 0;

void onSent(const wifi_tx_info_t *info, esp_now_send_status_t status) {
  if (status != ESP_NOW_SEND_SUCCESS) Serial.println("  radio: not delivered");
}

void onRecv(const esp_now_recv_info_t *info, const uint8_t *data, int len) {
  if (len != sizeof(ReplyMsg)) return;
  if (memcmp(info->src_addr, boardB, 6) != 0) return;   // فقط از B قبول کن
  memcpy(&reply, data, sizeof(reply));
  gotReply = true;
}

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(STATUS_LED, OUTPUT);
  WiFi.mode(WIFI_STA);
  while (!WiFi.STA.started()) delay(10);
  if (esp_now_init() != ESP_OK) {
    Serial.println("ESP-NOW init failed");
    while (true) delay(1000);
  }
  esp_now_register_send_cb(onSent);
  esp_now_register_recv_cb(onRecv);
  esp_now_peer_info_t peer = {};
  memcpy(peer.peer_addr, boardB, 6);
  peer.channel = 0;
  peer.encrypt = false;
  esp_now_add_peer(&peer);
}

void sendCommand() {
  cmd.seq++;
  cmd.ledOn = !cmd.ledOn;
  digitalWrite(STATUS_LED, LOW);            // تا تایید نیامده، خاموش
  esp_now_send(boardB, (uint8_t *)&cmd, sizeof(cmd));
  Serial.printf("-> #%lu ledOn=%d\n", (unsigned long)cmd.seq, cmd.ledOn);
  waiting = true;
  sentAt = millis();
}

void loop() {
  int reading = digitalRead(BUTTON_PIN);
  if (reading != lastReading) { lastChange = millis(); lastReading = reading; }
  if (millis() - lastChange > 30 && reading != stableState) {
    stableState = reading;
    if (stableState == LOW) sendCommand();
  }

  if (gotReply) {
    gotReply = false;
    if (waiting && reply.seq == cmd.seq) {
      waiting = false;
      digitalWrite(STATUS_LED, HIGH);         // تایید رسید
      Serial.printf("<- ack #%lu, LED on B is %s, temp %.1f C (%lu ms)\n",
                    (unsigned long)reply.seq, reply.ledOn ? "ON" : "OFF",
                    reply.tempC, millis() - sentAt);
    }
  }
  if (waiting && millis() - sentAt > 500) {   // نیم ثانیه مهلت
    waiting = false;
    Serial.println("!! no reply from B within 500 ms");
  }
}
  1. MAC برد B و دو پین. دکمه روی GPIO27 و LED وضعیت روی GPIO4، همان پایه‌های همیشگی دوره. LED وضعیت همان LED بیرونی + مقاومت ۲۲۰ اهم است که از درس ۲.۲ استفاده کرده‌ای، پس روی هر بردی کار می‌کند. (بعضی بردها روی GPIO2 یک LED داخلی هم دارند، ولی ESP32-DevKitC ندارد.)
  2. دو قالب پیام. CommandMsg (۸ بایت) از A به B و ReplyMsg (۱۲ بایت) از B به A. چون دو قالب اندازه متفاوت دارند، گیرنده از روی len می‌فهمد کدام است. در پروژه‌های بزرگ‌تر یک بایت اول «نوع پیام» می‌گذارند.
  3. وضعیت برنامه. waiting یعنی «منتظر جوابم»، sentAt زمان ارسال برای محاسبه مهلت و تاخیر. این متغیرها یک «ماشین حالت» کوچک می‌سازند: یا منتظریم یا نه. بدون آن نمی‌شود فهمید جوابی که رسید مال کدام فرمان است یا مهلت کی تمام شد.
  4. Callback ارسال (هسته ۳.۳+). فقط شکست رادیویی را گزارش می‌کند. اینجا تایید اصلی ما جواب برنامه B است، نه تایید رادیو؛ برای همین موفقیت را چاپ نمی‌کنیم تا Serial شلوغ نشود.
  5. Callback دریافت با فیلتر فرستنده. memcmp شش بایت MAC فرستنده را با MAC برد B مقایسه می‌کند (۰ یعنی یکی‌اند). هر ESP32 دیگری در اطراف که روی همین کانال ESP-NOW بفرستد، پیامش به این تابع می‌رسد. فقط به پیام‌های B اعتماد کن.
  6. ثبت هر دو Callback و Peer. A هم می‌فرستد و هم می‌گیرد. یک برد می‌تواند هم‌زمان فرستنده و گیرنده باشد؛ رادیو بین این دو کار به طور خودکار جابه‌جا می‌شود.
  7. sendCommand. فرمان جدید می‌سازد، LED وضعیت را خاموش می‌کند، می‌فرستد و ساعت انتظار را روشن می‌کند. جدا کردن این کار در یک تابع، loop را خوانا نگه می‌دارد و بعدا می‌توانی از جای دیگری (مثلا یک تایمر) هم صدایش بزنی.
  8. Debounce فشرده. همان منطق پروژه ۱، این بار چند دستور در یک خط. منطق یکسان است؛ فقط برای کوتاهی فشرده نوشته شده.
  9. پردازش جواب. اگر منتظر بودیم و seq جواب با آخرین فرمان یکی بود، تایید را قبول می‌کنیم، LED وضعیت را روشن می‌کنیم و دما و زمان رفت‌وبرگشت را چاپ می‌کنیم. مقایسه seq جلوی قبول کردن جواب دیرهنگام یک فرمان قدیمی را می‌گیرد. زمان رفت‌وبرگشت معمولا چند تا چند ده میلی‌ثانیه است (بیشترش زمان خواندن DHT22 روی B است) و نشان می‌دهد ESP-NOW چقدر سریع است.
  10. مهلت (Timeout). اگر ۵۰۰ میلی‌ثانیه گذشت و جوابی نیامد، انتظار را تمام و خطا را اعلام می‌کنیم. در دنیای بی‌سیم «جواب نیامد» یک حالت عادی است (B خاموش است، دور است، پیام گم شد). برنامه خوب برای آن نقشه دارد؛ مثلا در تمرین ۲ خودت ارسال دوباره (Retry) را اضافه می‌کنی.
#include <WiFi.h>
#include <esp_now.h>
#include <DHT.h>

const int LED_PIN = 4;
DHT dht(13, DHT22);

typedef struct {
  uint32_t seq;
  bool ledOn;
} CommandMsg;

typedef struct {
  uint32_t seq;
  bool ledOn;
  float tempC;
} ReplyMsg;

CommandMsg incoming;
uint8_t senderMac[6];
volatile bool gotMsg = false;

void onRecv(const esp_now_recv_info_t *info, const uint8_t *data, int len) {
  if (len != sizeof(CommandMsg)) return;
  memcpy(&incoming, data, sizeof(incoming));
  memcpy(senderMac, info->src_addr, 6);   // جواب را به همین آدرس می‌فرستیم
  gotMsg = true;
}

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  dht.begin();
  WiFi.mode(WIFI_STA);
  while (!WiFi.STA.started()) delay(10);
  Serial.println(WiFi.macAddress());
  if (esp_now_init() != ESP_OK) {
    Serial.println("ESP-NOW init failed");
    while (true) delay(1000);
  }
  esp_now_register_recv_cb(onRecv);
}

void loop() {
  if (!gotMsg) return;
  gotMsg = false;
  digitalWrite(LED_PIN, incoming.ledOn ? HIGH : LOW);

  if (!esp_now_is_peer_exist(senderMac)) {   // بار اول؟ A را به دفترچه اضافه کن
    esp_now_peer_info_t peer = {};
    memcpy(peer.peer_addr, senderMac, 6);
    peer.channel = 0;
    peer.encrypt = false;
    esp_now_add_peer(&peer);
  }

  ReplyMsg reply;
  reply.seq = incoming.seq;
  reply.ledOn = incoming.ledOn;
  reply.tempC = dht.readTemperature();       // اگر خطا: NAN
  esp_now_send(senderMac, (uint8_t *)&reply, sizeof(reply));
  Serial.printf("#%lu LED %s, replied temp=%.1f\n", (unsigned long)reply.seq,
                reply.ledOn ? "ON" : "OFF", reply.tempC);
}

  2. دو قالب، کپی دقیق برد A. ترتیب و نوع خانه‌ها باید با A یکی باشد. اگر در B به جای float بنویسی double، اندازه ۱۶ بایت می‌شود و A (که ۱۲ بایت انتظار دارد) پیام را به خاطر چک طول دور می‌ریزد؛ خوشبختانه به جای خواندن عدد غلط!
  3. ذخیره MAC فرستنده. علاوه بر پیام، آدرس فرستنده را از info->src_addr کپی می‌کنیم. این‌طوری B لازم نیست MAC برد A را از قبل بداند؛ به هر کس که فرمان داد جواب می‌دهد. (برای امنیت بیشتر، مثل A یک فیلتر MAC اضافه کن.)
  4. اجرای فرمان. اگر پیامی نیامده، از loop برمی‌گردیم؛ وگرنه LED را تنظیم می‌کنیم. return زودهنگام از تو در تو شدن ifها جلوگیری می‌کند و کد را خواناتر می‌کند.
  5. اضافه کردن A به دفترچه، فقط بار اول. esp_now_is_peer_exist بررسی می‌کند آیا این MAC قبلا اضافه شده. برای فرستادن جواب، A باید Peer باشد. اضافه کردن تکراری خطای ESP_ERR_ESPNOW_EXIST می‌دهد؛ این چک جلویش را می‌گیرد. این کار را در loop انجام می‌دهیم نه در Callback، تا Callback کوتاه بماند.
  6. ساختن و فرستادن جواب. seq همان فرمان، وضعیت LED و دما را در ReplyMsg می‌گذاریم و به A می‌فرستیم. برگرداندن seq همان فرمان به A اجازه می‌دهد جواب را به فرمان درست وصل کند. اگر سنسور جواب ندهد، NAN فرستاده می‌شود و A عبارت nan چاپ می‌کند؛ یعنی خطا پنهان نمی‌شود.

ارسال همگانی (Broadcast)

اگر بخواهی یک پیام به همه ESP32های اطراف برسد (مثلا «همه چراغ‌ها خاموش»)، به آدرس ویژه FF:FF:FF:FF:FF:FF بفرست. این آدرس هم باید مثل هر Peer دیگر با esp_now_add_peer اضافه شود. دو تفاوت مهم با پیام تکی:

  • پیام همگانی تایید رادیویی ندارد. Callback ارسال معمولا موفقیت نشان می‌دهد، حتی اگر هیچ گیرنده‌ای روشن نباشد. پس اگر تایید مهم است، گیرنده‌ها باید جواب بدهند (مثل پروژه ۲).
  • پیام همگانی رمزنگاری نمی‌شود. هر ESP32 در اطراف آن را می‌گیرد.
کتابخانه جدید C++ در هسته ۳: ESP32_NOW.h

هسته ۳ آردوینو علاوه بر API کلاسیک esp_now.h (که در این درس یاد گرفتی) یک کتابخانه شیءگرا به اسم ESP_NOW (فایل ESP32_NOW.h) دارد. در آن یک شیء سراسری ESP_NOW هست (ESP_NOW.begin()، ESP_NOW.getMaxDataLen() و...) و برای هر همتا از کلاس ESP_NOW_Peer ارث‌بری می‌کنی و توابع onReceive و onSent آن را بازنویسی می‌کنی. مثال‌های آماده‌اش در File › Examples › ESP_NOW هستند (مثل ESP_NOW_Broadcast_Master و ESP_NOW_Serial). ما API کلاسیک را یاد دادیم چون ۹۰٪ کدهای اینترنت و مستندات ESP-IDF با آن است؛ وقتی آن را فهمیدی، کتابخانه جدید را در یک ساعت یاد می‌گیری.

ESP-NOW و Wi-Fi با هم: قانون کانال مشترک

رادیوی ESP32 فقط یکی است و در هر لحظه روی یک کانال (۱ تا ۱۳ در اروپا و بیشتر جاهای دنیا، ۱ تا ۱۱ در آمریکای شمالی) کار می‌کند. وقتی برد B به مودم وصل می‌شود (مثلا برای فرستادن داده به MQTT)، رادیوی آن مجبور است روی کانال مودم برود، مثلا کانال ۶. حالا اگر برد A هنوز روی کانال ۱ باشد، پیام‌هایش هرگز به B نمی‌رسد.

در ESP-NOW دو برنامه روی دو برد داری و وقتی کار نکند، وسوسه می‌شوی هر دو را هم‌زمان عوض کنی. این کار را نکن. همیشه اول مطمئن شو MAC درست است (از Serial خود گیرنده، نه از حافظه‌ات)، بعد با ساده‌ترین برنامه ممکن (پروژه ۱) ثابت کن ارتباط برقرار است، و فقط بعد پیچیده‌اش کن. روی هر برد برچسب A و B بزن و در Serial Monitor هر پنجره را مشخص کن کدام برد است. و یادت باشد: «delivered» یعنی رادیو گرفت، نه این که برنامه اجرا کرد. هر جا اجرای فرمان مهم است (قفل، پمپ، موتور)، جواب برنامه‌ای با seq بخواه. این تفاوت یک اسباب‌بازی با یک سیستم قابل اعتماد است.

// در loop:  Serial.printf("RSSI: %d dBm\n", lastRssi);
تمرین ۲: ارسال دوباره (Retry)

در برد A پروژه ۲، اگر در ۵۰۰ میلی‌ثانیه جواب نیامد، همان فرمان (با همان seq) را حداکثر ۳ بار دوباره بفرست و فقط بعد از شکست سوم اعلام خطا کن. چرا باید seq ثابت بماند؟

راهنمایی

یک شمارنده int tries اضافه کن. در بخش Timeout اگر tries < 3 بود، esp_now_send را با همان cmd صدا بزن، tries++ و sentAt = millis(). در sendCommand، tries = 0.

جواب

seq ثابت می‌ماند تا اگر پیام اول رسیده بود ولی فقط جوابش گم شده بود، B بفهمد این همان فرمان قبلی است و آن را دوباره اجرا نکند. در پروژه ما فرمان حالت مطلق را می‌برد («LED روشن»)، پس تکرارش اتفاقا بی‌ضرر است؛ ولی فرمانی مثل «برعکس کن» یا «زنگ را یک بار بزن» دو بار اجرا می‌شد. به این ویژگی «Idempotent» (تکرار بی‌ضرر) می‌گویند؛ همان مشکلی که QoS 2 در MQTT حل می‌کند. روی برد B آخرین seq اجراشده را نگه دار؛ اگر همان seq دوباره آمد، کار را انجام نده ولی باز هم جواب بفرست، چون به احتمال زیاد همان جواب بوده که گم شده:

uint32_t lastSeq = 0;                     // سراسری: آخرین فرمان اجراشده

void loop() {
  if (!gotMsg) return;
  gotMsg = false;
  bool repeat = (incoming.seq == lastSeq);
  if (!repeat) {                          // فرمان جدید: فقط یک بار اجرا کن
    lastSeq = incoming.seq;
    digitalWrite(LED_PIN, incoming.ledOn ? HIGH : LOW);
  }
  // ... اضافه کردن A به دفترچه در بار اول، دقیقا مثل قبل ...
  ReplyMsg reply;                         // هر بار جواب بده، حتی برای تکراری
  reply.seq = incoming.seq;
  reply.ledOn = digitalRead(LED_PIN);     // وضعیت واقعی پایه LED
  reply.tempC = dht.readTemperature();
  esp_now_send(senderMac, (uint8_t *)&reply, sizeof(reply));
  Serial.printf("#%lu %s\n", (unsigned long)incoming.seq, repeat ? "repeat: reply only" : "new: done");
}

seq در A از ۱ شروع می‌شود، پس lastSeq = 0 هیچ‌وقت با یک فرمان واقعی یکی نیست. اگر B ریست شود، lastSeq به ۰ برمی‌گردد و اشکالی ندارد: فرمان بعدی A به هر حال شماره تازه دارد.

تمرین ۳: پیدا کردن خودکار کانال

برد A را طوری بنویس که در setup شبکه مودم را با WiFi.scanNetworks() پیدا کند، کانالش را بخواند و خودش روی آن برود. دیگر لازم نیست عدد کانال را دستی بنویسی.

راهنمایی

int n = WiFi.scanNetworks(); سپس در یک حلقه for اگر WiFi.SSID(i) == "YourWiFi" بود، WiFi.channel(i) کانال آن شبکه است. بعد WiFi.setChannel(ch) و سپس esp_now_init().

جواب 
WiFi.mode(WIFI_STA);
while (!WiFi.STA.started()) delay(10);
int ch = 1;                              // اگر مودم پیدا نشد، کانال ۱
int n = WiFi.scanNetworks();             // حدود ۲ تا ۳ ثانیه طول می‌کشد
for (int i = 0; i < n; i++) {
  if (WiFi.SSID(i) == "YourWiFi") { ch = WiFi.channel(i); break; }
}
WiFi.scanDelete();                       // آزاد کردن حافظه نتیجه اسکن
WiFi.setChannel(ch);
Serial.printf("Using channel %d\n", ch);
esp_now_init();
// ... ثبت Callback و Peer مثل قبل

اسم شبکه به حروف بزرگ و کوچک حساس است. اگر مودم بعدا کانال عوض کند، کافی است A را ریست کنی تا دوباره اسکن کند (یا در Timeoutهای پشت سر هم، دوباره اسکن کن).

خلاصه درس در سه خط

ESP-NOW پیام‌های کوتاه (تا ۲۵۰ بایت در نسخه ۱) را با آدرس MAC و بدون مودم در چند میلی‌ثانیه بین ESP32ها جابه‌جا می‌کند؛ MAC را بعد از روشن شدن Wi-Fi بخوان و Peer را قبل از ارسال اضافه کن. قالب پیام یک struct یکسان در دو طرف است که با sizeof و memcpy فرستاده و خوانده می‌شود؛ Callbackها را کوتاه نگه دار و امضای هسته ۳ (esp_now_recv_info_t و از ۳.۳ به بعد wifi_tx_info_t) را به کار ببر. «delivered» فقط تایید رادیوست؛ برای اطمینان، جواب با seq و Timeout بساز، و اگر یک طرف به مودم وصل است، همه روی کانال مودم باشند.
