تا اینجا هر پروژه را با هم ساختیم: من پین را انتخاب کردم، کتابخانه را معرفی کردم و کد را خط به خط توضیح دادم. از این درس به بعد، تو تصمیم می‌گیری. این درس یک پروژه تازه نیست؛ یک «جعبه‌ابزار فکری» است: روشی که با آن هر ایده‌ای، ساده یا سخت، روی هر مدل ESP32، بدون معلم به یک دستگاه واقعی تبدیل می‌شود.

🎯 بعد از این درس می‌توانی

  • یک ایده را با روشی تکرارپذیر (نیازمندی ← پین ← تغذیه ← آزمایش تکه‌تکه ← ادغام) به دستگاه تبدیل کنی
  • با دلیل بین ESP32، S2، S3، C3، C6، H2 و P4 انتخاب کنی
  • یک اسکچ را از ESP32 به C3 یا S3 منتقل کنی و بدانی دقیقا چه چیزی خراب می‌شود
  • قطعه‌ای را که هرگز ندیده‌ای، از روی دیتاشیت و مثال کتابخانه راه بیندازی
  • ریست بی‌پایان، Guru Meditation، Brownout و «I2C پیدا نشد» را روشمند عیب‌یابی کنی
  • پروژه بعدی‌ات را از یک نردبان ۱۲ پله‌ای انتخاب کنی و مسیر یادگیری بعد از دوره را بدانی

حرف مربی، قبل از شروع

هیچ دوره‌ای همه قطعه‌ها و همه پروژه‌ها را پوشش نمی‌دهد. تفاوت کسی که «یک دوره دیده» با کسی که «مهندس» است، این نیست که همه چیز را از قبل بداند؛ این است که روش دارد. وقتی با چیز ناآشنا روبه‌رو می‌شود نمی‌ترسد، کپی‌پیست نمی‌کند و دعا نمی‌کند که کار کند. قدم‌به‌قدم می‌رود و هر قدم را ثابت می‌کند. این درس همان روش را به تو می‌دهد. آهسته بخوان.

۱. از ایده تا دستگاه: یک روش تکرارپذیر

در پروژه نهایی این روش را یک بار با هم اجرا کردیم. حالا آن را به صورت یک «دستور پخت» کلی درمی‌آوریم که برای هر پروژه‌ای جواب بدهد: از یک چراغ خواب ساده تا یک ربات.

مثل ساختن خانه

هیچ بنّایی اول سقف نمی‌زند. اول نقشه (نیازمندی)، بعد مصالح (قطعه‌ها)، بعد پی (تغذیه)، بعد دیوارها یکی‌یکی و هر کدام را با تراز چک می‌کند (آزمایش هر قطعه)، و آخر سر رنگ و نما (جعبه). اگر ترک در دیوار ببیند، می‌داند کدام دیوار است چون هر کدام را جدا ساخته. پروژه الکترونیک هم همین است: اگر همه چیز را یک‌جا وصل کنی و کار نکند، نمی‌دانی مشکل از کجاست.

قدم ۱ و ۲: ایده و نیازمندی (PRD کوچک)

«یک گلدان هوشمند می‌خواهم» نیازمندی نیست؛ آرزوست. نیازمندی باید قابل اندازه‌گیری باشد تا آخر کار بتوانی بگویی «تمام شد». این قالب را کپی کن و برای هر پروژه پر کن. نیم ساعت نوشتن آن، ده‌ها ساعت دوباره‌کاری را حذف می‌کند.

  2. Must در برابر Nice. فقط چیزهایی که بدون آن‌ها پروژه بی‌معنی است در Must می‌روند. مبتدی‌ها همه چیز را Must می‌کنند (نمایشگر، اپ گوشی، هشدار تلگرام...) و هیچ‌وقت تمام نمی‌کنند. اول Must را کامل کن؛ Nice جایزه نسخه ۲ است.
  3. محدودیت‌ها. تغذیه، عمر باتری، نوع ارتباط، محیط و بودجه. این خطوط مستقیما تراشه را انتخاب می‌کنند: «باتری ۶ ماه» یعنی خواب عمیق و برد کم‌مصرف؛ «بیرون از خانه» یعنی جعبه ضدآب و شاید LoRa به جای Wi-Fi.
  4. معیار پذیرش. آزمایش‌هایی که آخر کار انجام می‌دهی، مثل «اگر خاک خشک شد، پمپ حداکثر ۵ ثانیه روشن شود». بدون معیار پذیرش، پروژه یا هیچ‌وقت تمام نمی‌شود یا زودتر از موعد «تمام» اعلام می‌شود و در اولین شب خراب می‌شود.
  5. خارج از محدوده. صریحا بنویس چه کاری را نمی‌کنی. این خط از «خزش دامنه» جلوگیری می‌کند: وسوسه اضافه کردن «فقط یک قابلیت دیگر» که پروژه را هفته‌ها عقب می‌اندازد.

قدم ۳: سنسورها و عملگرها را انتخاب کن

برای هر Must بپرس: «برای فهمیدن این، چه چیزی را باید اندازه بگیرم؟» (سنسور) و «برای انجام این، چه چیزی را باید حرکت بدهم یا روشن کنم؟» (عملگر). بعد برای هر کدام سه سوال:

  1. با چه ولتاژی کار می‌کند؟ ۳٫۳ ولت، ۵ ولت یا ۱۲ ولت؟ اگر خروجی‌اش ۵ ولت است، مستقیم به پین ESP32 وصل نکن (پین‌ها ۵ ولت را تحمل نمی‌کنند؛ درس ۱.۳).
  2. با چه رابطی حرف می‌زند؟ دیجیتال ساده، آنالوگ، I2C، SPI، UART یا یک پروتکل تک‌سیمه مخصوص (مثل DHT22)؟ این تعیین می‌کند چند پین و کدام پین لازم داری.
  3. چقدر جریان می‌کشد؟ موتور و پمپ و رله را هرگز مستقیم از پین تغذیه نکن؛ ترانزیستور یا ماسفت لازم است (درس ۳.۴).

قدم ۴: تراشه و برد

این بخش آن‌قدر مهم است که بخش ۲ کامل به آن اختصاص دارد. فعلا قانون ساده: اگر دلیل خاصی نداری، ESP32 معمولی (DevKitC یا DOIT) انتخاب امنی است، چون همه درس‌های این دوره با آن نوشته شده.

قدم ۶: بودجه توان

بودجه توان یعنی جواب دادن به دو سوال با عدد: (۱) منبع تغذیه در بدترین لحظه چقدر جریان باید بدهد؟ (۲) باتری چند روز دوام می‌آورد؟

حساب کن: گلدان هوشمند با باتری

بیشینه جریان: ESP32 هنگام ارسال Wi-Fi لحظه‌ای تا حدود ۲۵۰ میلی‌آمپر می‌کشد، پمپ کوچک ۵ ولتی حدود ۲۰۰ میلی‌آمپر. پس منبع باید دست‌کم 250 + 200 ≈ 450mA را بدون افت ولتاژ بدهد؛ با حاشیه اطمینان، یک منبع ۱ آمپری.

میانگین جریان: دستگاه هر ۱۰ دقیقه (۶۰۰ ثانیه) بیدار می‌شود، ۵ ثانیه با میانگین ۱۲۰ میلی‌آمپر کار می‌کند و بقیه ۵۹۵ ثانیه در خواب عمیق با ۰٫۱۵ میلی‌آمپر (روی یک برد کم‌مصرف؛ یک DevKit معمولی به خاطر رگولاتور و تراشه USB چند میلی‌آمپر می‌کشد):

I_avg = (5 × 120 + 595 × 0.15) ÷ 600 ≈ 1.15mA

عمر باتری ۲۰۰۰ میلی‌آمپر ساعتی: 2000 ÷ 1.15 ≈ 1740h ≈ 72 روز. با ضریب اطمینان ۰٫۷ (باتری کامل خالی نمی‌شود، دما، پیری): حدود ۵۰ روز. جزئیات خواب عمیق در درس ۶.۱ است.

قدم ۷: برد بورد، یکی‌یکی، هر قطعه با یک اسکچ آزمایشی

برای هر قطعه یک اسکچ کوچک جدا بنویس (یا مثال کتابخانه‌اش را اجرا کن) که فقط همان قطعه را آزمایش کند. این اسکچ‌ها را دور نینداز؛ در پوشه‌ای مثل tests/ نگه‌شان دار. شش ماه بعد که دستگاه خراب شد، با همین‌ها در پنج دقیقه می‌فهمی کدام قطعه مرده. قالب آماده این کار را در بخش ۴ می‌بینی.

قدم ۸: ادغام بدون delay

وقتی همه قطعه‌ها تنهایی کار کردند، آن‌ها را یکی‌یکی به برنامه اصلی اضافه کن و بعد از هر اضافه، آزمایش کن. زمان‌بندی را با millis() بنویس (درس ۳.۱ و ۶.۳) یا کارهای کند مثل شبکه را در یک Task جدا بگذار (درس ۵.۴). یک delay(5000) وسط برنامه یعنی دکمه تو برای ۵ ثانیه کر است.

قدم ۹: جعبه یا PCB

برد بورد برای یادگیری عالی است و برای استفاده روزمره افتضاح: سیم‌ها شل می‌شوند، رطوبت اتصال‌ها را خراب می‌کند و لرزش همه چیز را قطع می‌کند. نسخه نهایی را یا روی برد سوراخ‌دار لحیم کن (درس ۱.۴) یا یک PCB واقعی طراحی کن. آموزش فارسی طراحی PCB با KiCad 9 در همین سایت قدم بعدی طبیعی است.

چرا این همه قدم برای یک پروژه ساده؟

برای پروژه‌ای با یک LED این روش زیادی است. ولی عادت را روی پروژه‌های ساده می‌سازی تا وقتی به پروژه‌ای با ده قطعه رسیدی، خودکار اجرایش کنی. آمار تجربی کارگاه‌ها ساده است: بیشتر پروژه‌هایی که نیمه‌کاره رها می‌شوند، در مرحله «همه را با هم وصل کردم و کار نکرد» می‌میرند.

خانواده ESP32 مثل خودروهای یک کارخانه

ESP32 معمولی یک ماشین سواری همه‌کاره است. S3 شاسی‌بلند قوی با صندوق بزرگ (PSRAM) برای بار سنگین مثل دوربین و صدا. C3 یک ماشین شهری کوچک و ارزان: برای رفت‌وآمد ساده عالی، ولی بار سنگین نمی‌برد. C6 همان ماشین شهری با رادیوی جدید (Wi-Fi 6 و Thread) برای خانه هوشمند. H2 موتورسیکلت پستی: Wi-Fi ندارد ولی در شبکه‌های کم‌مصرف Thread و Zigbee بی‌رقیب است. P4 کامیون قدرتمند بدون رادیو: پردازش تصویر و نمایشگر بزرگ، ولی برای اینترنت یک همراه بی‌سیم لازم دارد.

اول درخت تصمیم را طی کن، بعد برد بخر؛ نه برعکس. و همیشه دو عدد بخر: یکی برای ساختن، یکی برای وقتی که اولی را با اشتباه سیم‌کشی سوزاندی یا خواستی بفهمی مشکل از برد است یا از کد. برد دوم ارزان‌ترین ابزار عیب‌یابی دنیاست.

S3 و C3 و C6 «ESP32 بهتر» نیستند؛ «ESP32 متفاوت» هستند. پروژه‌ای که با BluetoothSerial به اپ ترمینال بلوتوث اندروید وصل می‌شد، روی هیچ‌کدام از آن‌ها کامپایل نمی‌شود. پروژه‌ای که با dacWrite صدا پخش می‌کرد، روی S3 و C3 و C6 DAC ندارد. قبل از عوض کردن تراشه، ستون قابلیت‌ها را برای همه چیزهایی که پروژه لازم دارد چک کن.

خرابی ۱: شماره پین‌ها

خرابی ۴: LED داخلی و LED رنگی

روی بردهای DOIT، LED آبی روی GPIO2 است. روی ESP32-S3-DevKitC-1 به جای آن یک LED رنگی آدرس‌پذیر (مثل WS2812) هست: در نسخه v1.0 برد روی GPIO48 و در نسخه v1.1 روی GPIO38. روی ESP32-C3-DevKitM-1 روی GPIO8 است. این LED با digitalWrite ساده روشن نمی‌شود چون داده سریالی لازم دارد. در هسته ۳.x تابع آماده rgbLedWrite(pin, r, g, b) این کار را می‌کند و ثابت RGB_BUILTIN برای بردهایی که چنین LEDی دارند تعریف شده. (اسم قدیمی این تابع neopixelWrite بود که هنوز کار می‌کند ولی منسوخ اعلام شده.)

نسخه برد S3 را از روی خود برد بخوان

هسته آردوینو در انتخاب «ESP32S3 Dev Module» فرض می‌کند LED روی GPIO48 است. اگر برد تو v1.1 است و LED روشن نمی‌شود، به جای RGB_BUILTIN مستقیم rgbLedWrite(38, ...) بنویس. بردهای کلون ارزان گاهی هر دو را عوض کرده‌اند؛ نقشه فروشنده را ببین.

خرابی ۵ (دام شماره ۱): Serial Monitor خالی است!

این رایج‌ترین مشکل کسانی است که از ESP32 به C3 یا S3 می‌روند. برنامه آپلود می‌شود، LED چشمک می‌زند، ولی Serial Monitor هیچ چیزی نشان نمی‌دهد. چرا؟

روی ESP32 معمولی، کابل USB به یک تراشه مبدل (CP2102 یا CH340) وصل است و آن تراشه به پین‌های UART0 (GPIO1 و GPIO3). Serial در آردوینو همان UART0 است؛ پس همه چیز خودکار کار می‌کند.

ولی C3 و S3 (و C6 و H2) داخل خودشان یک واحد USB بومی (Native USB) به اسم USB-Serial-JTAG دارند. بردهای کوچک مثل C3 SuperMini یا XIAO، کانکتور USB را مستقیم به پین‌های USB تراشه وصل کرده‌اند و هیچ تراشه مبدلی ندارند. حالا سوال این است: Serial در برنامه تو کدام است؟

  • اگر در منوی Tools › USB CDC On Boot گزینه Disabled باشد (پیش‌فرض «ESP32C3 Dev Module» و «ESP32S3 Dev Module»)، Serial همان UART0 است (C3: GPIO21 و GPIO20؛ S3: GPIO43 و GPIO44). متن تو روی آن پین‌ها می‌رود که به USB وصل نیستند. نتیجه: Serial Monitor خالی.
  • اگر Enabled باشد، Serial به USB بومی وصل می‌شود (به این می‌گویند USB CDC: کلاس استاندارد «پورت سریال مجازی» در USB) و متن در Serial Monitor ظاهر می‌شود.
دو صندوق پست

فرض کن خانه‌ات دو صندوق پست دارد: یکی دم در (USB) و یکی پشت خانه (UART0). نامه‌رسان (برنامه تو) به طور پیش‌فرض نامه‌ها را در صندوق پشتی می‌گذارد. تو دم در منتظری و فکر می‌کنی نامه‌ای نیامده. گزینه «USB CDC On Boot: Enabled» یعنی به نامه‌رسان بگویی «نامه‌ها را دم در بگذار».

بردهایی که تراشه مبدل جدا دارند فرق دارند: ESP32-S3-DevKitC-1 و ESP32-C3-DevKitM-1 رسمی یک تراشه مبدل USB به UART روی برد دارند. S3-DevKitC-1 حتی دو کانکتور USB دارد که روی برد نوشته «UART» و «USB». اگر کابل را به «UART» بزنی، مثل ESP32 معمولی کار می‌کند و CDC On Boot باید Disabled بماند. اگر به «USB» بزنی، باید Enabled باشد. قانون ساده: کابل به کانکتوری که مستقیم به تراشه می‌رود = CDC On Boot: Enabled.

پیام‌های اول setup گم می‌شوند؟

با USB بومی، کامپیوتر چند صد میلی‌ثانیه طول می‌کشد تا پورت را بشناسد. اگر در اولین خط setup چاپ کنی، ممکن است آن پیام از دست برود. برای همین در اسکچ پایین نوشته‌ایم: «تا ۳ ثانیه صبر کن تا Serial آماده شود، بعد ادامه بده». حد ۳ ثانیه لازم است، وگرنه دستگاهی که با باتری و بدون کامپیوتر کار می‌کند، برای همیشه منتظر می‌ماند.

چرا در بردهای USB بومی پورت «ناپدید» می‌شود؟

روی ESP32 معمولی، تراشه مبدل USB همیشه روشن است و پورت COM هیچ‌وقت نمی‌رود، حتی اگر برنامه تو کرش کند. ولی در USB بومی، خود ESP32 نقش دستگاه USB را بازی می‌کند. اگر برنامه‌ات کرش کند، به خواب عمیق برود یا پین‌های USB (مثلا GPIO19 و GPIO20 روی S3) را برای کار دیگری استفاده کند، پورت از کامپیوتر ناپدید می‌شود. ترکیب BOOT + RST تراشه را به بوت‌لودر داخل ROM می‌برد که همیشه سالم است و USB را دوباره راه می‌اندازد. بعد از آپلود یک بار RST را بزن تا برنامه جدید اجرا شود.

راه‌حل حرفه‌ای: یک اسکچ برای همه تراشه‌ها

به جای نگه داشتن سه نسخه جدا از برنامه، از دستورهای پیش‌پردازنده (#if) استفاده می‌کنیم. کامپایلر قبل از ترجمه کد، بر اساس تراشه‌ای که در منوی Board انتخاب کرده‌ای، فقط بخش‌های مربوط را نگه می‌دارد. دو نوع «پرچم» داریم:

  • CONFIG_IDF_TARGET_ESP32، CONFIG_IDF_TARGET_ESP32S3، CONFIG_IDF_TARGET_ESP32C3 و...: می‌گویند کدام تراشه است. برای شماره پین‌ها مناسب‌اند.
  • ماکروهای قابلیت SOC مثل SOC_DAC_SUPPORTED، SOC_TOUCH_SENSOR_SUPPORTED و SOC_BT_CLASSIC_SUPPORTED: می‌گویند تراشه چه چیزی دارد. این‌ها بهترند، چون اگر فردا تراشه جدیدی با DAC آمد، کد تو بدون تغییر درست کار می‌کند.

مدار برای نسخه ESP32 DevKitC (روی S3 و C3 فقط شماره پین‌ها طبق کد عوض می‌شود):

// PortableDemo.ino — یک اسکچ، سه تراشه: ESP32، ESP32-S3، ESP32-C3
#include <Arduino.h>
#include "soc/soc_caps.h"   // ماکروهای SOC_… (قابلیت‌های سخت‌افزاری هر تراشه)

// ---------- ۱) پین‌ها: فقط این بخش برای هر تراشه فرق می‌کند ----------
#if CONFIG_IDF_TARGET_ESP32
  const int LED_PIN    = 4;    // خروجی PWM
  const int BUTTON_PIN = 27;
  const int POT_PIN    = 34;   // ADC1_CH6
  const int TOUCH_PIN  = 32;   // T9
  const int DAC_PIN    = 25;   // DAC1
#elif CONFIG_IDF_TARGET_ESP32S3
  const int LED_PIN    = 5;
  const int BUTTON_PIN = 4;
  const int POT_PIN    = 1;    // ADC1_CH0
  const int TOUCH_PIN  = 7;    // T7
#elif CONFIG_IDF_TARGET_ESP32C3
  const int LED_PIN    = 6;
  const int BUTTON_PIN = 7;
  const int POT_PIN    = 3;    // ADC1_CH3
#else
  #error "This sketch supports ESP32, ESP32-S3 and ESP32-C3 only"
#endif

// ---------- ۲) گزارش قابلیت‌ها ----------
void printChipInfo() {
  Serial.printf("Chip: %s rev %d, %d core(s) @ %lu MHz\n",
                ESP.getChipModel(), ESP.getChipRevision(),
                ESP.getChipCores(), (unsigned long)ESP.getCpuFreqMHz());
  Serial.printf("Flash: %lu KB, PSRAM: %lu KB\n",
                (unsigned long)(ESP.getFlashChipSize() / 1024),
                (unsigned long)(ESP.getPsramSize() / 1024));
#if SOC_DAC_SUPPORTED
  Serial.println("DAC: yes");
#else
  Serial.println("DAC: no  -> PWM only");
#endif
#if SOC_TOUCH_SENSOR_SUPPORTED
  Serial.println("Touch: yes");
#else
  Serial.println("Touch: no");
#endif
#if SOC_BT_CLASSIC_SUPPORTED
  Serial.println("Bluetooth Classic: yes (BluetoothSerial OK)");
#else
  Serial.println("Bluetooth Classic: no  -> use BLE");
#endif
#if ARDUINO_USB_CDC_ON_BOOT
  Serial.println("Serial = native USB (CDC)");
#else
  Serial.println("Serial = UART0");
#endif
}

// ---------- ۳) setup ----------
void setup() {
  Serial.begin(115200);
  unsigned long t0 = millis();
  while (!Serial && millis() - t0 < 3000) delay(10);  // صبر برای USB، حداکثر ۳ ثانیه

  pinMode(BUTTON_PIN, INPUT_PULLUP);
  ledcAttach(LED_PIN, 5000, 8);        // core 3.x: پین، فرکانس، رزولوشن
  printChipInfo();
}

// ---------- ۴) loop ----------
void loop() {
  int raw  = analogRead(POT_PIN);      // 0..4095
  int duty = raw >> 4;                 // 0..255
  bool pressed = (digitalRead(BUTTON_PIN) == LOW);
  ledcWrite(LED_PIN, duty);

#if SOC_DAC_SUPPORTED
  dacWrite(DAC_PIN, duty);             // ولتاژ آنالوگ واقعی 0 تا 3.3V
#endif

  Serial.printf("pot=%4d  button=%s", raw, pressed ? "DOWN" : "up  ");
#if SOC_TOUCH_SENSOR_SUPPORTED
  Serial.printf("  touch=%lu", (unsigned long)touchRead(TOUCH_PIN));
#endif
#ifdef RGB_BUILTIN
  if (pressed) rgbLedWrite(RGB_BUILTIN, 40, 0, 0);  // قرمز
  else         rgbLedWrite(RGB_BUILTIN, 0, 40, 0);  // سبز
#endif
  Serial.println();
  delay(200);
}
  1. include کردن soc_caps.h. این فایل از ESP-IDF، برای هر تراشه فهرست قابلیت‌ها را به شکل ماکرو تعریف می‌کند. یک دام خطرناک: در C++ اگر در #if اسمی بیاوری که تعریف نشده، خطا نمی‌گیری؛ کامپایلر بی‌صدا آن را صفر فرض می‌کند. اگر این فایل include نشده باشد، #if SOC_DAC_SUPPORTED روی ESP32 هم «نه» می‌شود و تو هرگز نمی‌فهمی چرا DAC کار نمی‌کند. include صریح، این دام را می‌بندد.
  2. پین‌های ESP32 معمولی. اگر در منوی Board «ESP32 Dev Module» انتخاب شده باشد، فقط این پنج خط کامپایل می‌شوند. همه پین‌ها با قوانین درس ۱.۳ انتخاب شده‌اند: GPIO34 روی ADC1 است (با Wi-Fi مشکلی ندارد)، GPIO32 پین لمسی T9 و GPIO25 خروجی DAC1 است. هیچ‌کدام Strapping نیستند.
  3. پین‌های S3. GPIO1 روی ADC1_CH0 است و GPIO7 پین لمسی T7. DAC_PIN تعریف نشده، چون S3 DAC ندارد. از GPIO3، 45 و 46 (Strapping)، 19 و 20 (USB) و 26 تا 37 (فلش و PSRAM) دوری کرده‌ایم. پین‌های 1 تا 18 روی S3 امن‌ترین انتخاب‌ها هستند.
  4. پین‌های C3. GPIO3 روی ADC1_CH3 است. پین لمسی و DAC تعریف نشده‌اند چون C3 هیچ‌کدام را ندارد. از GPIO2، 8 و 9 (Strapping)، 12 تا 17 (فلش) و 18 و 19 (USB) دوری کرده‌ایم. GPIO6 و GPIO7 روی C3 پین‌های JTAG بیرونی هم هستند، ولی تا وقتی JTAG بیرونی استفاده نکنی، GPIO معمولی‌اند.
  5. #error برای تراشه ناشناخته. اگر کسی این کد را برای C6 کامپایل کند، کامپایل با یک پیام روشن متوقف می‌شود. خطای کامپایل بهتر از برنامه‌ای است که کامپایل شود و با پین‌های اشتباه روی برد اجرا شود. «زود و بلند شکست بخور» یک اصل مهندسی است.
  6. چاپ مشخصات تراشه. ESP.getChipModel() اسم تراشه، getChipCores() تعداد هسته، getFlashChipSize() حجم فلش و getPsramSize() حجم PSRAM را می‌دهد. وقتی یک برد ناشناخته از بازار می‌خری، این خطوط در یک ثانیه می‌گویند واقعا چه خریده‌ای. اگر PSRAM صفر بود ولی فروشنده گفته بود ۸ مگابایت، یا برد تقلبی است یا گزینه Tools › PSRAM را فعال نکرده‌ای.
  7. ماکروهای قابلیت. هر #if SOC_... فقط وقتی کامپایل می‌شود که تراشه آن قابلیت را داشته باشد. این خطوط هم به تو گزارش می‌دهند و هم الگوی اصلی را نشان می‌دهند: کد مخصوص یک قابلیت را همیشه داخل ماکروی همان قابلیت بگذار، نه داخل اسم تراشه.
  8. Serial کجا می‌رود؟ ماکروی ARDUINO_USB_CDC_ON_BOOT را خود Arduino IDE از روی گزینه «USB CDC On Boot» می‌سازد. اگر این خط «UART0» چاپ کرد و تو آن را در Serial Monitor دیدی، کابل به تراشه مبدل وصل است. اگر هیچ چیز ندیدی، برو سراغ همان دام شماره ۱.
  9. صبر محدود برای Serial. تا وقتی Serial آماده نیست و کمتر از ۳ ثانیه گذشته، هر ۱۰ میلی‌ثانیه صبر کن. روی USB بومی، !Serial یعنی «هنوز کامپیوتری پورت را باز نکرده». روی ESP32 معمولی این شرط تقریبا فورا رد می‌شود، پس ضرری ندارد. حد زمانی جلوی گیر کردن دستگاه بدون کامپیوتر را می‌گیرد.
  10. دکمه و PWM. INPUT_PULLUP برای دکمه و ledcAttach(pin, 5000, 8) برای PWM با فرکانس ۵ کیلوهرتز و ۸ بیت (۰ تا ۲۵۵). LEDC روی همه این تراشه‌ها وجود دارد، پس PWM قابل حمل‌ترین راه برای «خروجی شبه‌آنالوگ» است. این سینتکس هسته ۳.x است؛ در ۲.x باید ledcSetup و ledcAttachPin می‌نوشتی.
  11. خواندن و نوشتن مشترک. analogRead روی هر سه تراشه ۱۲ بیتی است (۰ تا ۴۰۹۵). raw >> 4 یعنی تقسیم بر ۱۶ تا به بازه ۰ تا ۲۵۵ برسیم. این خطوط هیچ #ifی ندارند چون روی همه تراشه‌ها یکسان‌اند. هدف همین است: بیشتر کد مشترک بماند و فقط تفاوت‌ها محصور شوند.
  12. DAC فقط جایی که هست. روی ESP32 ولتاژ GPIO25 با پتانسیومتر از ۰ تا حدود ۳٫۳ ولت تغییر می‌کند. روی C3 و S3 این خط اصلا کامپایل نمی‌شود، پس خطای «dacWrite was not declared» هم نمی‌گیری.
  13. لمس فقط جایی که هست. روی ESP32 و S3 مقدار لمسی چاپ می‌شود. نوع خروجی touchRead روی ESP32 شانزده بیتی و روی S3 سی‌ودو بیتی است. تبدیل به unsigned long باعث می‌شود یک printf برای هر دو درست باشد.
  14. LED رنگی داخلی، اگر هست. #ifdef RGB_BUILTIN فقط روی بردهایی که فایل تعریف برد (variant) آن‌ها این LED را اعلام کرده کامپایل می‌شود. این‌جا از #ifdef (آیا تعریف شده؟) استفاده کردیم نه #if، چون RGB_BUILTIN یک شماره پین است، نه یک پرچم ۰ یا ۱.

۴. یادگیری هر قطعه‌ای که هرگز ندیده‌ای (مهارت اصلی)

فردا سراغ قطعه‌ای می‌روی که در این دوره نبود: یک سنسور گاز، یک درایور موتور، یک نمایشگر جوهر الکترونیکی. هیچ درسی آماده نیست. این مسیر پنج‌مرحله‌ای همیشه جواب می‌دهد:

گام ۱: دیتاشیت را بخوان (بدون ترس)

دیتاشیت BME280 شصت صفحه است. لازم نیست همه‌اش را بخوانی. مثل منوی رستوران است: دنبال چند بخش مشخص می‌گردی. این «تور راهنما» برای هر قطعه‌ای کار می‌کند؛ مثال ما سنسور دما، رطوبت و فشار BME280 از شرکت Bosch است:

کجای دیتاشیتچه نوشته (BME280)برای تو یعنی چه
Electrical specification: Supply voltageVDD: ۱٫۷۱ تا ۳٫۶ ولتخود تراشه با ۵ ولت می‌سوزد. ماژول‌هایی که رگولاتور دارند ۵ ولت را هم می‌پذیرند؛ روی ماژول دنبال یک قطعه سه‌پایه کوچک (رگولاتور) بگرد. با ESP32 همیشه از 3V3 تغذیه‌اش کن.

برای یک سنسور مثل DHT22 همین پنج سوال را می‌پرسی: ولتاژ (۳٫۳ تا ۶ ولت)، رابط (یک سیم با پروتکل مخصوص)، زمان (حداقل ۲ ثانیه بین دو اندازه‌گیری)، و مقاومت Pull-up (معمولا ۱۰ کیلو؛ روی ماژول‌های سه‌پایه معمولا هست). این‌ها را در درس ۳.۳ دیدی.

دیتاشیت تراشه در برابر صفحه ماژول

دیتاشیت مال تراشه کوچک وسط ماژول است. ولی تو ماژول را می‌خری که رگولاتور، مقاومت Pull-up و LED دارد. پس همیشه دو سند را ببین: دیتاشیت تراشه (برای رجیسترها و محدودیت‌ها) و صفحه یا شماتیک ماژول از سایت سازنده‌اش (Adafruit، SparkFun، Waveshare...) برای این که بفهمی روی برد چه چیزی اضافه شده.

گام ۲ و ۳: سیم‌کشی حداقلی و «معاینه»

فقط چهار سیم: تغذیه، زمین و دو سیم داده. قبل از نصب هر کتابخانه‌ای، با یک اسکچ کوچک ثابت کن که قطعه زنده است و همان است که فکر می‌کنی. این قالب را برای هر قطعه I2C می‌توانی استفاده کنی؛ فقط آدرس‌ها، رجیستر ID و مقدار مورد انتظار را از دیتاشیت عوض کن.

// PartBringUp.ino — قالب راه‌اندازی هر قطعه I2C تازه (مثال: BME280)
#include <Wire.h>

const int SDA_PIN = 21;          // ESP32 DevKitC؛ روی S3/C3 عوض کن
const int SCL_PIN = 22;
const uint8_t ID_REG      = 0xD0;  // از دیتاشیت: رجیستر chip ID
const uint8_t EXPECTED_ID = 0x60;  // BME280 = 0x60 ، BMP280 = 0x58

uint8_t partAddr = 0;            // آدرسی که اسکنر پیدا می‌کند

// گام ۱: کل باس را بگرد
int scanBus() {
  int found = 0;
  for (uint8_t a = 1; a < 127; a++) {
    Wire.beginTransmission(a);
    if (Wire.endTransmission() == 0) {
      Serial.printf("  device at 0x%02X\n", a);
      if (a == 0x76 || a == 0x77) partAddr = a;   // آدرس‌های ممکن BME280
      found++;
    }
  }
  return found;
}

// گام ۲: خواندن یک بایت از یک رجیستر
bool readReg(uint8_t addr, uint8_t reg, uint8_t &val) {
  Wire.beginTransmission(addr);
  Wire.write(reg);
  if (Wire.endTransmission(false) != 0) return false;   // false = Repeated Start
  if (Wire.requestFrom(addr, (uint8_t)1) != 1) return false;
  val = Wire.read();
  return true;
}

void setup() {
  Serial.begin(115200);
  delay(1500);
  Wire.begin(SDA_PIN, SCL_PIN);
  Serial.println("\n[1] I2C scan:");
  if (scanBus() == 0) {
    Serial.println("  nothing found -> check VCC, GND, SDA/SCL swap, pull-ups");
    return;
  }
  if (partAddr == 0) { Serial.println("  part not at 0x76/0x77"); return; }

  uint8_t id;
  Serial.printf("[2] Reading ID register 0x%02X at 0x%02X...\n", ID_REG, partAddr);
  if (!readReg(partAddr, ID_REG, id)) { Serial.println("  read failed"); return; }
  Serial.printf("  ID = 0x%02X (expected 0x%02X) -> %s\n", id, EXPECTED_ID,
                id == EXPECTED_ID ? "OK, this is the right chip" : "DIFFERENT chip!");
  Serial.println("[3] Now install the library and run its example.");
}

void loop() {
  // عمدا خالی: این برنامه فقط یک بار «معاینه» می‌کند
}
  1. همه چیزهایی که از دیتاشیت آمده، بالای برنامه. پین‌ها، آدرس رجیستر ID و مقداری که انتظار داری. برای قطعه بعدی (مثلا سنسور نور BH1750 یا شتاب‌سنج MPU6050) فقط همین چهار خط را عوض می‌کنی. قالب خوب یعنی قسمت متغیر در یک جا جمع شده باشد.
  2. اسکنر I2C. به هر آدرس از ۱ تا ۱۲۶ «سلام» می‌کند. اگر قطعه‌ای جواب بدهد (ACK)، endTransmission() صفر برمی‌گرداند و آدرس چاپ می‌شود. این سوال «آیا سیم‌کشی و تغذیه درست است؟» را از «آیا کتابخانه درست است؟» جدا می‌کند. اگر اسکنر چیزی پیدا نکند، هیچ کتابخانه‌ای کمکت نمی‌کند؛ مشکل سخت‌افزاری است.
  3. خواندن یک رجیستر. اول شماره رجیستر را می‌نویسد، بعد بدون آزاد کردن باس (endTransmission(false) یعنی Repeated Start) یک بایت درخواست می‌کند. تقریبا همه قطعه‌های I2C دنیا همین الگوی «بنویس شماره رجیستر، بعد بخوان» را دارند. وقتی این تابع را فهمیدی، هر دیتاشیتی را می‌توانی مستقیما آزمایش کنی.
  4. Wire.begin با پین صریح. Wire.begin(SDA_PIN, SCL_PIN). پین‌های پیش‌فرض I2C روی هر تراشه فرق دارد (ESP32: 21 و 22؛ S3 و C3: 8 و 9). نوشتن صریح پین‌ها باعث می‌شود با عوض کردن برد، فقط خطوط ۴ و ۵ را تغییر دهی.
  5. شکست زود و با پیام روشن. اگر چیزی پیدا نشد، دقیقا می‌گوید چه چیزهایی را چک کنی و متوقف می‌شود. پیام «nothing found» بی‌فایده است؛ پیام «VCC، GND، جابه‌جایی SDA و SCL، Pull-up را چک کن» یک چک‌لیست است. به خودِ آینده‌ات چک‌لیست بده، نه معما.
  6. مقایسه ID با دیتاشیت. اگر 0x60 بود یعنی BME280 اصل داری؛ اگر 0x58 بود یعنی BMP280 (بدون رطوبت) خریده‌ای. این دو خط ده‌ها ساعت سردرگمی را حذف می‌کنند: «چرا کتابخانه رطوبت را NaN می‌دهد؟» جواب: چون سنسور تو اصلا رطوبت ندارد.
  7. loop خالی. این برنامه فقط یک بار معاینه می‌کند. برای تکرار معاینه، دکمه EN (ریست) را بزن. ساده نگه داشتن اسکچ آزمایشی یعنی اگر خراب شد، می‌دانی مشکل از قطعه است نه از منطق پیچیده برنامه.
[1] I2C scan: device at 0x76 [2] Reading ID register 0xD0 at 0x76... ID = 0x58 (expected 0x60) -> DIFFERENT chip! [3] Now install the library and run its example.

قانون یک تغییر، مثل آشپزی با دستور جدید

اگر در یک دستور پخت همزمان نمک، زمان پخت و نوع روغن را عوض کنی و غذا خراب شود، نمی‌دانی کدام مقصر بود. اگر هر بار فقط یک چیز را عوض کنی و بچشی، همیشه می‌دانی. در کد: یک تغییر، کامپایل، آپلود، آزمایش. اگر خراب شد، فقط همان تغییر آخر را برگردان.

وقتی گیر کردی: درست سوال بپرس

در انجمن‌ها (esp32.com، Reddit، Arduino Forum) یا از هوش مصنوعی (درس ۶.۲)، کیفیت جواب دقیقا به کیفیت سوال بستگی دارد. این قالب را پر کن:

  1. محیط دقیق. مدل برد، نسخه هسته و IDE. نصف جواب‌های اشتباه در اینترنت مال نسخه ۲.x هسته است. وقتی نسخه را بگویی، جواب‌دهنده (انسان یا هوش مصنوعی) کد درست می‌دهد.
  2. سیم‌کشی به صورت متن. نه «مثل عکس وصل کردم». بیشتر مشکل‌ها در همین خط پیدا می‌شوند؛ گاهی خودت هنگام نوشتنش متوجه اشتباه می‌شوی.
  3. مشاهده، شواهد و آزمایش‌های انجام‌شده. نشان می‌دهد تلاش کرده‌ای و جواب‌دهنده وقتش را روی پیشنهادهایی که امتحان کرده‌ای هدر نمی‌دهد.
  4. کد حداقلی. کوتاه‌ترین برنامه کاملی که مشکل را نشان می‌دهد، نه هزار خط پروژه. در ۵۰٪ موارد، ساختن این کد کوتاه خودش مشکل را پیدا می‌کند. این خودش یک تکنیک عیب‌یابی است.

۵. کتاب راهنمای عیب‌یابی

عیب‌یابی حدس زدن نیست. یک فرایند است: علامت را ببین ← علت‌های محتمل را فهرست کن ← با یک آزمایش ساده یکی را رد یا تأیید کن. این نقشه، رایج‌ترین علامت‌ها را پوشش می‌دهد:

ریست بی‌پایان: اول دلیل ریست را بخوان

ESP32 هر بار که ریست می‌شود، دلیلش را در یک رجیستر نگه می‌دارد. این «جعبه سیاه» مثل هواپیماست: بعد از سقوط، اولین کار خواندن آن است. این اسکچ دلیل ریست را چاپ می‌کند، سطح‌های مختلف لاگ را نشان می‌دهد و به تو اجازه می‌دهد عمدا یک کرش بسازی تا خواندن Guru Meditation را تمرین کنی.

// DebugStart.ino — دلیل ریست + لاگ سطح‌دار + ایجاد عمدی کرش برای تمرین
#include <Arduino.h>
#include "esp_system.h"

RTC_NOINIT_ATTR uint32_t crashCount;   // با ریست نرم‌افزاری پاک نمی‌شود

const char *resetReasonText(esp_reset_reason_t r) {
  switch (r) {
    case ESP_RST_POWERON:   return "POWERON  (power was applied)";
    case ESP_RST_EXT:       return "EXT      (external reset pin)";
    case ESP_RST_SW:        return "SW       (ESP.restart() was called)";
    case ESP_RST_PANIC:     return "PANIC    (crash / Guru Meditation)";
    case ESP_RST_INT_WDT:   return "INT_WDT  (interrupt watchdog)";
    case ESP_RST_TASK_WDT:  return "TASK_WDT (a task blocked too long)";
    case ESP_RST_WDT:       return "WDT      (other watchdog)";
    case ESP_RST_DEEPSLEEP: return "DEEPSLEEP (woke up from deep sleep)";
    case ESP_RST_BROWNOUT:  return "BROWNOUT (supply voltage dropped!)";
    default:                return "OTHER/UNKNOWN";
  }
}

void setup() {
  Serial.begin(115200);
  delay(1500);                          // فرصت برای باز شدن Serial Monitor
  Serial.setDebugOutput(true);          // لاگ‌های log_x هم به همین Serial بیایند

  esp_reset_reason_t why = esp_reset_reason();
  if (why == ESP_RST_POWERON) crashCount = 0;   // بعد از قطع برق، مقدارش تصادفی است
  if (why == ESP_RST_PANIC || why == ESP_RST_TASK_WDT ||
      why == ESP_RST_INT_WDT || why == ESP_RST_BROWNOUT) crashCount++;

  Serial.printf("\n=== Boot. Reset reason: %s\n", resetReasonText(why));
  Serial.printf("=== Abnormal resets since power-on: %lu\n", (unsigned long)crashCount);
  Serial.printf("=== Chip: %s, free heap: %lu bytes\n",
                ESP.getChipModel(), (unsigned long)ESP.getFreeHeap());

  log_e("ERROR level: shown if Core Debug Level >= Error");
  log_w("WARN  level: shown if Core Debug Level >= Warn");
  log_i("INFO  level: shown if Core Debug Level >= Info");
  log_d("DEBUG level: shown if Core Debug Level >= Debug");
  log_v("VERBOSE level: shown only at Verbose");

  Serial.println("Send 'c' = crash, 'r' = restart, 'h' = heap");
}

void loop() {
  static unsigned long last = 0;
  if (millis() - last >= 5000) {        // هر ۵ ثانیه یک «ضربان»
    last = millis();
    uint32_t heap = ESP.getFreeHeap();
    log_i("alive, uptime=%lus heap=%lu", millis() / 1000, (unsigned long)heap);
    if (heap < 20000) log_w("heap is getting low!");
  }

  if (Serial.available()) {
    char cmd = Serial.read();
    if (cmd == 'c') {
      Serial.println("Crashing on purpose (null pointer write)...");
      Serial.flush();
      volatile int *p = nullptr;
      *p = 42;                          // نوشتن در آدرس صفر → Guru Meditation
    } else if (cmd == 'r') {
      ESP.restart();
    } else if (cmd == 'h') {
      Serial.printf("heap now=%lu, lowest ever=%lu\n",
                    (unsigned long)ESP.getFreeHeap(),
                    (unsigned long)ESP.getMinFreeHeap());
    }
  }
}
  1. متغیری که ریست نرم‌افزاری را زنده می‌ماند. RTC_NOINIT_ATTR متغیر را در حافظه RTC می‌گذارد و هنگام بوت آن را صفر نمی‌کند. متغیر معمولی با هر ریست صفر می‌شود، پس نمی‌توانستی کرش‌ها را بشماری. این متغیر بعد از کرش یا ESP.restart() مقدارش را نگه می‌دارد؛ فقط با قطع برق مقدار تصادفی می‌گیرد، برای همین در خط ۲۸ آن را صفر می‌کنیم.
  2. ترجمه کد ریست به متن. esp_reset_reason() یکی از مقدارهای ESP_RST_... را برمی‌گرداند. مهم‌ترین‌ها: PANIC یعنی برنامه کرش کرد؛ BROWNOUT یعنی ولتاژ افت کرد (مشکل سخت‌افزاری!)؛ TASK_WDT یعنی یک کار زیادی طول کشید؛ POWERON یعنی برق تازه وصل شد. همین یک کلمه نصف مسیر عیب‌یابی را مشخص می‌کند.
  3. Serial و setDebugOutput. Serial.setDebugOutput(true) لاگ‌های داخلی و log_x را هم به همین Serial می‌فرستد. روی ESP32 معمولی لاگ‌ها به هر حال روی UART0 می‌آیند. روی C3 و S3 با CDC On Boot فعال، بدون این خط ممکن است لاگ‌ها به UART0 بروند و در Serial Monitor نبینی‌شان.
  4. شمارش ریست‌های غیرعادی. بعد از روشن شدن صفر، و با هر کرش، Watchdog یا Brownout یکی زیاد می‌شود. دستگاهی که روی دیوار نصب شده و «بعضی وقت‌ها» ریست می‌شود را این عدد لو می‌دهد. می‌توانی آن را در MQTT هم بفرستی (درس ۵.۱) تا از راه دور ببینی.
  5. پنج سطح لاگ. log_e (خطا)، log_w (هشدار)، log_i (اطلاعات)، log_d (اشکال‌زدایی) و log_v (پرحرف). این‌ها فقط وقتی چاپ می‌شوند که در Tools › Core Debug Level سطح برابر یا بالاتر انتخاب شده باشد. پیش‌فرض None است، پس هیچ‌کدام چاپ نمی‌شوند. مزیت بزرگ: در نسخه نهایی سطح را None می‌کنی و این خطوط اصلا کامپایل نمی‌شوند؛ نه جا می‌گیرند نه وقت. با Serial.println چنین کاری ممکن نیست. هر خط لاگ خودش اسم فایل، شماره خط و اسم تابع را هم نشان می‌دهد.
  6. ضربان قلب. هر ۵ ثانیه زمان روشن بودن و حافظه آزاد (heap) را لاگ می‌کند، بدون delay. اگر heap آرام‌آرام کم شود، «نشت حافظه» داری (مثلا String بزرگی که مدام ساخته می‌شود). دستگاهی که بعد از ۳ روز کرش می‌کند، معمولا همین مشکل را دارد.
  7. کرش عمدی. با فرستادن حرف c از Serial Monitor، در آدرس صفر (اشاره‌گر تهی) می‌نویسد. بهترین زمان برای یاد گرفتن خواندن Guru Meditation، وقتی است که خودت می‌دانی علت چیست. volatile جلوی این را می‌گیرد که کامپایلر این خط «احمقانه» را حذف کند. Serial.flush() مطمئن می‌شود پیام قبل از کرش کامل ارسال شود.
  8. ریست نرم‌افزاری و گزارش حافظه. r ریست تمیز می‌کند (بعد دلیل ریست SW است)؛ h حافظه فعلی و کمترین حافظه‌ای که تا حالا آزاد بوده را نشان می‌دهد. getMinFreeHeap() بدترین لحظه را نشان می‌دهد؛ اگر به چند کیلوبایت رسیده، حتی اگر الان خوب است، دستگاهت روی لبه پرتگاه است.

بعد از فرستادن c روی یک ESP32 معمولی چیزی شبیه این می‌بینی (با Core Debug Level روی Info):

EXCVADDR: 0x00000000 LBEG : 0x4008a5e1 LEND : 0x4008a5f1 LCOUNT : 0x00000000 Backtrace: 0x400d1f2b:0x3ffb2260 0x400d4b0d:0x3ffb2290 0x4008d1e2:0x3ffb22b0 Rebooting... ... === Boot. این متن را این‌طور بخوان:

  • Guru Meditation Error: اسم بامزه Espressif برای «برنامه کرش کرد» (از پیام خطای کامپیوترهای قدیمی Amiga گرفته شده).
  • StoreProhibited: نوع خطا. یعنی «نوشتن در آدرسی که اجازه‌اش نیست». EXCVADDR: 0x00000000 می‌گوید آن آدرس صفر بوده: یک اشاره‌گر تهی. LoadProhibited یعنی خواندن از آدرس ممنوع. روی تراشه‌های RISC-V (C3، C6، H2) اسم‌ها فرق دارد: Store access fault و Load access fault.
  • Backtrace: فهرست آدرس‌های توابعی که به ترتیب صدا زده شده بودند؛ مثل ردپا روی برف. این آدرس‌ها برای انسان بی‌معنی‌اند، پس باید «ترجمه» شوند.

ترجمه Backtrace با ESP Exception Decoder

در Arduino IDE 1.x ابزاری به اسم EspExceptionDecoder بود. برای Arduino IDE 2.x جایگزین آن افزونه esp-exception-decoder از dankeboy36 است:

  1. دانلود. از صفحه Releases همان مخزن GitHub، آخرین فایل .vsix از نسخه 1.x را بگیر. طبق README خود پروژه، نسخه‌های 2.x برای VS Code ساخته شده‌اند و در Arduino IDE اجرا نمی‌شوند (حتی ممکن است IDE را از کار بیندازند).
  2. نصب. فایل را در پوشه plugins داخل پوشه .arduinoIDE در پوشه کاربری‌ات بگذار (ویندوز: C:\Users\نام‌کاربری\.arduinoIDE\plugins؛ لینوکس و مک: ~/.arduinoIDE/plugins). اگر پوشه نیست، بساز. IDE را کامل ببند و باز کن.
  3. استفاده. همان اسکچی که کرش کرده باز باشد و همان برد انتخاب شده باشد (Decoder به فایل کامپایل‌شده همین اسکچ نیاز دارد). کلیدهای Ctrl+Shift+P را بزن، ESP Exception Decoder: Show Decoder Terminal را اجرا کن و متن کرش را از Serial Monitor در آن بچسبان.
  4. نتیجه. به جای آدرس، اسم تابع و شماره خط می‌بینی، مثلا loop() at DebugStart.ino:61. همان خط کرش ماست.
اطمینان از نسخه ابزار

این افزونه یک پروژه جامعه است، نه محصول رسمی Arduino یا Espressif، و روش نصبش ممکن است در آینده عوض شود. همیشه README همان مخزن را برای نسخه IDE خودت بخوان. روی تراشه‌های RISC-V، خروجی کرش به جای یک خط Backtrace ساده، یک «Stack memory» طولانی دارد؛ همه آن را کپی کن.

Brownout و «با USB کار می‌کند، با باتری نه»

پیام Brownout detector was triggered یعنی ولتاژ تغذیه تراشه لحظه‌ای از حد مجاز پایین‌تر رفت و ESP32 برای حفاظت از خودش ریست شد. تقریبا همیشه هنگام روشن شدن Wi-Fi اتفاق می‌افتد، چون همان لحظه جریان ناگهان تا حدود ۲۵۰ میلی‌آمپر بالا می‌رود.

  • کابل USB بلند و نازک: مقاومت سیم‌ها ولتاژ را زیر بار می‌اندازد. کابل کوتاه و کلفت امتحان کن.
  • پورت USB ضعیف یا هاب بدون آداپتور.
  • باتری با رگولاتور نامناسب: رگولاتور AMS1117 روی خیلی از بردها حدود ۱ ولت افت دارد. یک لیتیوم ۳٫۷ ولتی که به ۳٫۶ رسیده، بعد از رگولاتور فقط حدود ۲٫۶ ولت می‌دهد: کمتر از حد لازم. (درس ۶.۱ و ۱.۴)
  • راه‌حل موقت کمکی: یک خازن الکترولیت ۱۰۰ تا ۴۷۰ میکروفاراد بین 3V3 و GND، نزدیک برد، جهش‌های کوتاه را صاف می‌کند.
Brownout را خاموش نکن

در اینترنت کدی می‌بینی که با نوشتن در یک رجیستر، آشکارساز Brownout را غیرفعال می‌کند. این مثل کندن باتری آژیر دود است چون زیاد صدا می‌دهد. تراشه با ولتاژ ناکافی ممکن است رفتار عجیب کند یا حتی فلش را خراب بنویسد. مشکل تغذیه را حل کن، نه پیام را.

ابزارهای اندازه‌گیری

مولتی‌متر (درس ۱.۴): سه اندازه‌گیری که ۸۰٪ مشکلات سخت‌افزاری را پیدا می‌کنند: (۱) ولتاژ 3V3 نسبت به GND وقتی Wi-Fi روشن است (باید بالای ۳٫۱ ولت بماند)؛ (۲) ولتاژ پایه تغذیه سنسور، روی خود سنسور نه روی برد؛ (۳) پیوستگی (بوق) هر سیم مشکوک.

تحلیلگر منطقی (Logic Analyzer): وقتی سوال این است «آیا اصلا چیزی روی سیم I2C یا SPI یا UART می‌رود؟»، مولتی‌متر کمکی نمی‌کند، چون سیگنال میلیون‌ها بار در ثانیه عوض می‌شود. یک تحلیلگر منطقی ارزان «24MHz 8 کانال» (کلون‌های مبتنی بر تراشه CY7C68013A) به همراه نرم‌افزار رایگان PulseView سیگنال‌ها را ضبط می‌کند و حتی پروتکل را رمزگشایی می‌کند: «ESP32 به آدرس 0x76 نوشت، سنسور ACK نداد». قانون نمونه‌برداری: دست‌کم ۴ برابر سرعت سیگنال؛ برای I2C با ۴۰۰ کیلوهرتز یعنی حداقل ۲ تا ۴ مگاهرتز نمونه‌برداری. ورودی‌های این ابزار برای سطح منطقی ۳٫۳ و ۵ ولت هستند؛ هرگز به ولتاژ بالاتر وصلش نکن و GND آن را حتما به GND مدار بزن.

مولتی‌متر و تحلیلگر منطقی

مولتی‌متر مثل عکس گرفتن از یک خیابان است: می‌گوید «الان» چه خبر است. تحلیلگر منطقی مثل دوربین فیلم‌برداری آهسته است: هر ماشین را که رد می‌شود، با زمان دقیقش ضبط می‌کند. برای ترافیک پرسرعت پروتکل‌ها، به فیلم نیاز داری.

آزمون این درس

روی یک ESP32-C3 SuperMini (بدون تراشه مبدل USB) برنامه آپلود می‌شود ولی Serial Monitor هیچ چیز نشان نمی‌دهد. محتمل‌ترین علت چیست؟

  1. سرعت Serial Monitor اشتباه است
  2. C3 اصلا Serial ندارد
  3. گزینه USB CDC On Boot خاموش است، پس Serial روی UART0 می‌رود نه USB
  4. درایور CP2102 نصب نیست
روی بردهای USB بومی، Serial فقط وقتی به USB وصل است که USB CDC On Boot روی Enabled باشد.

پروژه‌ات به دوربین، Wi-Fi و حافظه زیاد برای پردازش تصویر نیاز دارد. بهترین انتخاب کدام است؟

  1. ESP32-C3
  2. ESP32-S3 با PSRAM
  3. ESP32-H2
  4. ESP32-C6
S3 رابط دوربین (LCD_CAM)، PSRAM و دو هسته ۲۴۰ مگاهرتزی دارد. P4 قوی‌تر است ولی Wi-Fi داخلی ندارد.

چرا #if SOC_DAC_SUPPORTED بهتر از #if CONFIG_IDF_TARGET_ESP32 برای محافظت از dacWrite است؟

  1. چون برنامه سریع‌تر اجرا می‌شود
  2. چون CONFIG_IDF_TARGET_ESP32 روی ESP32 تعریف نشده
  3. چون SOC_ هنگام اجرا بررسی می‌شود
  4. چون درباره «قابلیت» می‌پرسد؛ اگر تراشه دیگری (مثل S2) هم DAC داشته باشد، خودکار درست کار می‌کند
ESP32-S2 هم DAC دارد. با ماکروی قابلیت، کد تو روی S2 هم بدون تغییر DAC را استفاده می‌کند.

در Serial این خط را می‌بینی: Guru Meditation Error: Core 1 panic'ed (LoadProhibited) و EXCVADDR: 0x00000000. معنی‌اش چیست؟

  1. برنامه از یک اشاره‌گر تهی (آدرس صفر) خواند
  2. ولتاژ تغذیه افت کرد
  3. یک حلقه بی‌پایان باعث Watchdog شد
  4. فایل کامپایل خراب است
Load یعنی خواندن و EXCVADDR صفر یعنی آدرس خطا صفر بوده: یک اشاره‌گر یا شیء که مقداردهی نشده. با Exception Decoder خط دقیق را پیدا کن.

ماژولی که به اسم «BME280» خریده‌ای در اسکنر روی 0x76 است ولی کتابخانه رطوبت را NaN می‌دهد. قدم منطقی بعدی چیست؟

  1. یک کتابخانه دیگر نصب کنی
  2. آدرس را به 0x77 تغییر دهی
  3. رجیستر chip ID (0xD0) را بخوانی تا ببینی 0x60 است یا 0x58
  4. سیم‌ها را عوض کنی
0x58 یعنی BMP280 که اصلا سنسور رطوبت ندارد. دیتاشیت + یک رجیستر، سوال را قطعی جواب می‌دهد.

روی ESP32-C3 یک دکمه با Pull-down بیرونی به GPIO9 وصل کرده‌ای. چه اتفاقی می‌افتد؟

  1. هیچ، GPIO9 یک پین معمولی است
  2. هنگام روشن شدن، GPIO9 پایین است و برد به حالت دانلود می‌رود؛ برنامه اجرا نمی‌شود
  3. فلش خراب می‌شود
  4. USB قطع می‌شود
GPIO9 پین بوت C3 است (همان دکمه BOOT). LOW بودن آن هنگام ریست یعنی حالت دانلود. دکمه را به پین دیگر ببر، یا با Pull-up و فعال با LOW وصلش کن و هنگام روشن کردن فشارش نده.

تمرین‌ها

تمرین ۱: PRD و جدول پین برای پروژه خودت

یکی از پروژه‌های نردبان (پیشنهاد: پله ۱ یا ۳) را انتخاب کن. قالب PRD را کامل پر کن، سنسورها و عملگرها را با ولتاژ و رابطشان فهرست کن، تراشه را با درخت تصمیم انتخاب کن و جدول پین با ستون «دلیل» بنویس. بودجه توان را هم با عدد حساب کن.

راهنمایی

برای هر پین سه سوال بپرس: Strapping است؟ روی ADC1 است (اگر آنالوگ است)؟ به فلش، PSRAM یا USB وصل است؟ PRD را به هوش مصنوعی بده و بخواه «ایرادهایش را بگیرد»، نه این که برایت بنویسد (درس ۶.۲).

چه باید ببینی؟

PRD درست یکتا وجود ندارد، پس PRD خودت را با این معیارها نمره بده. قبولی اگر همه‌شان درست باشند:

  • هر Must قابل اندازه‌گیری است (یک عدد، یک زمان یا یک تست بله/خیر)، نه یک آرزو مثل «گلدان را خوب آب بدهد».
  • حداقل دو معیار پذیرش، هر کدام تستی که واقعا می‌شود اجرا کرد.
  • کنار هر سنسور و عملگر، ولتاژ، رابط و جریانش نوشته شده.
  • هیچ پینی بدون دلیل نیست؛ هیچ ورودی آنالوگی روی پین ADC2 (۰، ۲، ۴، ۱۲ تا ۱۵، ۲۵ تا ۲۷) وقتی پروژه Wi-Fi دارد؛ هیچ بار سنگینی مستقیم روی پین.
  • جریان بیشینه و میانگین با عدد، و منبع تغذیه‌ای که از روی جریان بیشینه انتخاب شده.

چک سریع عددها: با یک پمپ کوچک، جریان بیشینه حدود ۴۰۰ تا ۵۰۰ میلی‌آمپر است (Wi-Fi حدود ۲۵۰ به‌علاوه پمپ)، پس منبع ۱ آمپری. یک ESP32 همیشه‌روشن با Wi-Fi در میانگین چند ده میلی‌آمپر می‌کشد که یک باتری ۲۰۰۰ میلی‌آمپر ساعتی را حدود یک روزه خالی می‌کند. اگر پروژه باتری‌خورت بدون خواب عمیق چند هفته عمر وعده داده، عددها اشتباه‌اند.

باید انجام دهد (Must):

خوب است داشته باشد (Nice):

  - N2: یک OLED با رطوبت و زمان گذشته از آخرین آبیاری

  - تغذیه: USB، آداپتور ۵ ولت ۱ آمپر (پمپ ۵ ولت می‌خواهد)

  • بیشینه: Wi-Fi حدود ۲۵۰ + پمپ ۲۰۰ + سنسور ۵ + LED ۶ + OLED ۲۰ ≈ ۴۸۰ میلی‌آمپر. با حاشیه اطمینان: آداپتور ۵ ولت ۱ آمپر.

// PortableDemo.ino — یک اسکچ، چهار تراشه: ESP32، ESP32-S3، ESP32-C3، ESP32-C6
#include <Arduino.h>
#include "soc/soc_caps.h"   // ماکروهای SOC_… (قابلیت‌های سخت‌افزاری هر تراشه)

// ---------- ۱) پین‌ها: فقط این بخش برای هر تراشه فرق می‌کند ----------
#if CONFIG_IDF_TARGET_ESP32
  const int LED_PIN    = 4;    // خروجی PWM
  const int BUTTON_PIN = 27;
  const int POT_PIN    = 34;   // ADC1_CH6
  const int TOUCH_PIN  = 32;   // T9
  const int DAC_PIN    = 25;   // DAC1
#elif CONFIG_IDF_TARGET_ESP32S3
  const int LED_PIN    = 5;
  const int BUTTON_PIN = 4;
  const int POT_PIN    = 1;    // ADC1_CH0
  const int TOUCH_PIN  = 7;    // T7
#elif CONFIG_IDF_TARGET_ESP32C3
  const int LED_PIN    = 6;
  const int BUTTON_PIN = 7;
  const int POT_PIN    = 3;    // ADC1_CH3
#elif CONFIG_IDF_TARGET_ESP32C6
  const int LED_PIN    = 18;
  const int BUTTON_PIN = 19;
  const int POT_PIN    = 2;    // ADC1_CH2
#else
  #error "This sketch supports ESP32, ESP32-S3, ESP32-C3 and ESP32-C6 only"
#endif

// ---------- ۲) گزارش قابلیت‌ها ----------
void printChipInfo() {
  Serial.printf("Chip: %s rev %d, %d core(s) @ %lu MHz\n",
                ESP.getChipModel(), ESP.getChipRevision(),
                ESP.getChipCores(), (unsigned long)ESP.getCpuFreqMHz());
  Serial.printf("Flash: %lu KB, PSRAM: %lu KB\n",
                (unsigned long)(ESP.getFlashChipSize() / 1024),
                (unsigned long)(ESP.getPsramSize() / 1024));
#if SOC_DAC_SUPPORTED
  Serial.println("DAC: yes");
#else
  Serial.println("DAC: no  -> PWM only");
#endif
#if SOC_TOUCH_SENSOR_SUPPORTED
  Serial.println("Touch: yes");
#else
  Serial.println("Touch: no");
#endif
#if SOC_BT_CLASSIC_SUPPORTED
  Serial.println("Bluetooth Classic: yes (BluetoothSerial OK)");
#else
  Serial.println("Bluetooth Classic: no  -> use BLE");
#endif
#if ARDUINO_USB_CDC_ON_BOOT
  Serial.println("Serial = native USB (CDC)");
#else
  Serial.println("Serial = UART0");
#endif
}

// ---------- ۳) setup ----------
void setup() {
  Serial.begin(115200);
  unsigned long t0 = millis();
  while (!Serial && millis() - t0 < 3000) delay(10);  // صبر برای USB، حداکثر ۳ ثانیه

  pinMode(BUTTON_PIN, INPUT_PULLUP);
  ledcAttach(LED_PIN, 5000, 8);        // core 3.x: پین، فرکانس، رزولوشن
  printChipInfo();
}

// ---------- ۴) loop ----------
void loop() {
  int raw  = analogRead(POT_PIN);      // 0..4095
  int duty = raw >> 4;                 // 0..255
  bool pressed = (digitalRead(BUTTON_PIN) == LOW);
  ledcWrite(LED_PIN, duty);

#if SOC_DAC_SUPPORTED
  dacWrite(DAC_PIN, duty);             // ولتاژ آنالوگ واقعی 0 تا 3.3V
#endif

  Serial.printf("pot=%4d  button=%s", raw, pressed ? "DOWN" : "up  ");
#if SOC_TOUCH_SENSOR_SUPPORTED
  Serial.printf("  touch=%lu", (unsigned long)touchRead(TOUCH_PIN));
#endif
#ifdef RGB_BUILTIN
  if (pressed) rgbLedWrite(RGB_BUILTIN, 40, 0, 0);  // قرمز
  else         rgbLedWrite(RGB_BUILTIN, 0, 40, 0);  // سبز
#endif
  Serial.println();
  delay(200);
}

  2. شاخه جدید. قبل از #else قرار گرفته. ترتیب شاخه‌ها مهم نیست، چون در هر کامپایل فقط یکی از پرچم‌های CONFIG_IDF_TARGET_ تعریف شده است.
  3. پین‌های امن C6. GPIO18 و ۱۹ ورودی/خروجی معمولی‌اند؛ GPIO2 کانال ADC1_CH2 است. نه Strapping (۴، ۵، ۸، ۹، ۱۵)، نه فلش (۲۴ تا ۳۰)، نه USB (۱۲، ۱۳). پین لمسی و DAC تعریف نشده، چون C6 هیچ‌کدام را ندارد و ماکروهای SOC آن بخش‌ها را خودکار حذف می‌کنند. اگر بردت (مثلا XIAO C6) این پین‌ها را بیرون نیاورده، با همین قانون‌ها از روی پین‌اوت همان برد جایگزین انتخاب کن.

پروژه تمرینی: انتقال ایستگاه به ESP32-C3

ایستگاه درس ۶.۳ روی ESP32 کار می‌کند. حالا کسی نسخه‌ای کوچک‌تر و ارزان‌تر روی ESP32-C3 می‌خواهد. اگر اسکچ را کپی کنی و شماره پین‌ها را دستی عوض کنی، تا ابد دو برنامه برای نگهداری داری. به جایش آن را به یک اسکچ تبدیل می‌کنی که برای هر دو تراشه کامپایل می‌شود: پین‌ها بر اساس تراشه، و قابلیت‌ها بر اساس توانایی تراشه انتخاب می‌شوند؛ دقیقا مثل PortableDemo در کارگاه انتقال.

نیازمندی‌ها

  1. یک فایل منبع. شماره پین‌ها فقط در یک بلوک #if CONFIG_IDF_TARGET_ESP32 / #elif CONFIG_IDF_TARGET_ESP32C3 هستند؛ هر تراشه دیگری ساخت را با #error متوقف می‌کند.
  2. پین‌های C3 قانون‌های C3 را رعایت می‌کنند: LDR روی یک پین ADC1 (GPIO0 تا 4)، هیچ چیز روی پین‌های Strapping (2، 8، 9)، پین‌های فلش (12 تا 17) یا پین‌های USB (18، 19)؛ و پین‌های I2C صریحا به Wire.begin(SDA, SCL) داده می‌شوند.
  3. setup() حداکثر ۳ ثانیه منتظر پورت Serial (USB بومی) می‌ماند و بعد یک گزارش کوتاه چاپ می‌کند: مدل تراشه، تعداد هسته‌ها، پین‌های به‌کاررفته، و «Chip temperature sensor: yes/no» که یک ماکروی SOC_ تعیینش می‌کند.
  4. قابلیتی که فقط یکی از تراشه‌ها دارد: سنسور دمای داخلی C3 خوانده می‌شود و در خط آخر OLED و در خط Serial نمایش داده می‌شود، ولی فقط جایی که SOC_TEMP_SENSOR_SUPPORTED درست است؛ روی ESP32 این خط‌ها اصلا کامپایل نمی‌شوند.
  5. برای هر دو esp32:esp32:esp32 و esp32:esp32:esp32c3 کامپایل می‌شود (Verify با هر کدام از بردها) و در Wokwi روی هر دو یکسان رفتار می‌کند: هشدار بالای ۳۵ درجه، رفع هشدار زیر ۳۳ درجه، دکمه بی‌صدا و OLED.

قطعه‌ها

  • قطعه‌های ایستگاه درس ۶.۳: DHT22، ماژول LDR (یا LDR با مقاومت ۱۰ کیلواهم)، نمایشگر OLED SSD1306، LED هشدار با مقاومت ۲۲۰ اهم، بازر پسیو، دکمه فشاری
  • Wokwi (مسیر پیش‌فرض، مثل کارگاه). اختیاری: یک برد ESP32-C3 برای منتقل کردن قطعه‌ها

کد شروع

این بخش محلی ایستگاه درس ۶.۳ است (سنسورها، هشدار با هیسترزیس، بازر، دکمه بی‌صدا، OLED) که پین‌های ESP32 مستقیم در آن نوشته شده‌اند. بخش Wi-Fi و MQTT عمدا کنار گذاشته شده: WiFi.h و PubSubClient روی C3 بدون تغییر کار می‌کنند، پس انتقال آن‌جا خراب نمی‌شود. وقتی بخش محلی قابل حمل شد، آن‌ها را همان‌طور که هستند برگردان.

// ایستگاه، بخش محلی (۶.۳): فقط ESP32. کد شروع: قابل حملش کن (TODO 1 تا 4)
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>
// TODO 1: "soc/soc_caps.h" را include کن

// TODO 1: این پین‌ها را به یک بلوک #if CONFIG_IDF_TARGET_... ببر
//         (ESP32 و ESP32-C3، #error برای هر تراشه دیگر)، به‌علاوه PIN_SDA/PIN_SCL
const int PIN_DHT = 13;
const int PIN_LDR = 35;                        // ADC1
const int PIN_LED = 4;
const int PIN_BUZ = 25;
const int PIN_BTN = 27;                        // دکمه بی‌صدا

const float TEMP_HIGH = 35.0, TEMP_CLEAR = 33.0;
DHT dht(PIN_DHT, DHT22);
Adafruit_SSD1306 oled(128, 64, &Wire, -1);
float tempC = NAN, hum = NAN;
int lightPct = 0;
bool alarmOn = false, muted = false, oledOk = false;
uint32_t tSensor = 0;

void readSensors() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) { tempC = t; hum = h; }
  lightPct = map(analogRead(PIN_LDR), 4095, 0, 0, 100);   // نور بیشتر = ولتاژ کمتر
}

void updateAlarm() {
  if (isnan(tempC)) return;
  if (!alarmOn && tempC > TEMP_HIGH) { alarmOn = true; muted = false; }
  else if (alarmOn && tempC < TEMP_CLEAR) alarmOn = false;
}

void driveOutputs() {
  if (alarmOn && digitalRead(PIN_BTN) == LOW) muted = true;
  bool blink = (millis() / 250) % 2;
  digitalWrite(PIN_LED, alarmOn && blink);
  static bool buzzing = false;
  bool wantBuzz = alarmOn && !muted && blink;
  if (wantBuzz != buzzing) {
    ledcWriteTone(PIN_BUZ, wantBuzz ? 2000 : 0);
    buzzing = wantBuzz;
  }
}

void drawDisplay() {
  if (!oledOk) return;
  oled.clearDisplay();
  oled.setTextSize(2);
  oled.setCursor(0, 0);
  if (isnan(tempC)) oled.print("T: ERR");
  else { oled.print(tempC, 1); oled.print(" C"); }
  oled.setCursor(0, 20);
  if (isnan(hum)) oled.print("H: ERR");
  else { oled.print(hum, 0); oled.print(" %"); }
  oled.setTextSize(1);
  oled.setCursor(0, 44);
  oled.printf("Light %d%%  %s", lightPct, alarmOn ? (muted ? "ALARM(m)" : "ALARM!") : "normal");
  // TODO 4: دمای تراشه در خط آخر (y = 56)، فقط اگر تراشه سنسور دارد
  oled.display();
}

void setup() {
  Serial.begin(115200);
  // TODO 3: حداکثر ۳ ثانیه منتظر Serial بمان، بعد گزارش قابلیت‌ها را چاپ کن
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  ledcAttach(PIN_BUZ, 2000, 8);                // API هسته ۳.x
  analogReadResolution(12);
  dht.begin();
  Wire.begin();                                // TODO 2: پین‌های SDA و SCL را بده
  oledOk = oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  if (oledOk) oled.setTextColor(SSD1306_WHITE);
  else Serial.println("OLED not found, continuing without display");
}

void loop() {
  if (millis() - tSensor >= 2000) {
    tSensor = millis();
    readSensors();
    updateAlarm();
    drawDisplay();
    Serial.printf("T=%.1f C  H=%.0f %%  light=%d %%  %s\n",
                  tempC, hum, lightPct, alarmOn ? "ALARM" : "normal");
    // TODO 4: اگر پشتیبانی می‌شود، دمای تراشه را هم چاپ کن
  }
  driveOutputs();
}
  1. پین‌ها، مستقیم نوشته‌شده. همان عددهای جدول پین ۶.۳. دام این‌جاست: این کد شروع برای C3 هم کامپایل می‌شود. امتحانش کردیم: کامپایلر سیم‌کشی تو را نمی‌شناسد. C3 اصلا GPIO13، 25، 27 یا 35 ندارد؛ پس روی C3 برنامه اجرا می‌شود و فقط کار اشتباه می‌کند. انتقال یک کار طراحی است، نه یک خطای کامپایل.
  2. منطق ایستگاه. خواندن، هیسترزیس، خروجی‌ها و نمایشگر، مثل EnvStation. هیچ‌کدام از این خط‌ها اسمی از تراشه نمی‌برند و هیچ‌کدام #if لازم نخواهند داشت. هدف این است که همین‌طور بماند: فقط تفاوت‌ها را حصار بکش.
  3. هنوز منتظر Serial نمی‌ماند. روی C3 با USB بومی، خط‌های اول معمولا قبل از این که کامپیوتر پورت را باز کند چاپ می‌شوند و گم می‌شوند (خرابی ۵).
  4. Wire.begin() بدون پین. آن‌وقت از پین‌های پیش‌فرض I2C برد استفاده می‌کند. روی ESP32 این‌ها 21/22 هستند و برای همین الان کار می‌کند. روی «ESP32C3 Dev Module» این‌ها GPIO8 و GPIO9 هستند: هر دو از پین‌های Strapping.

اول کد شروع را روی ESP32 معمولی اجرا کن تا رفتاری را که منتقل می‌کنی بشناسی. کتابخانه‌های DHT sensor library و Adafruit SSD1306 را از زبانه Library Manager اضافه کن. روی DHT22 کلیک کن و دما را بالای ۳۵ ببر.

راهنمایی ۱

از سطر C3 در جدول Strapping و فهرست ADC1 در خرابی ۳ شروع کن. اول جدول پین C3 را روی کاغذ بنویس، برای هر پین یک دلیل، دقیقا مثل قدم ۵ روش. فقط بعد از آن شاخه #elif را تایپ کن.

راهنمایی ۲

ماکروی SOC_ی که تعریف نشده، در #if صفر حساب می‌شود، بدون هیچ هشداری. برای همین #include "soc/soc_caps.h" اول می‌آید. برای دیدن این که یک تراشه چه ماکروهایی دارد، فایل soc_caps.h همان تراشه را (در فایل‌های نصب‌شده هسته) باز کن و دنبال TEMP_SENSOR بگرد.

راهنمایی ۳

بررسی انتقال بدون برد C3: در Arduino IDE گزینه Tools › Board › ESP32C3 Dev Module را انتخاب کن و فقط Verify (✓) را بزن. بعد در Wokwi یک پروژه ESP32-C3 تازه باز کن، همان اسکچ و diagram.json مخصوص C3 را از جواب بچسبان و ▶ را بزن.

// ایستگاه قابل حمل، بخش محلی (۶.۳): یک اسکچ برای ESP32 و ESP32-C3

#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <DHT.h>
#include "soc/soc_caps.h"                      // ماکروهای قابلیت SOC_...

#if CONFIG_IDF_TARGET_ESP32
  const int PIN_DHT = 13, PIN_LDR = 35, PIN_LED = 4, PIN_BUZ = 25, PIN_BTN = 27;
  const int PIN_SDA = 21, PIN_SCL = 22;
#elif CONFIG_IDF_TARGET_ESP32C3
  const int PIN_DHT = 1, PIN_LDR = 3, PIN_LED = 10, PIN_BUZ = 4, PIN_BTN = 5;
  const int PIN_SDA = 6, PIN_SCL = 7;          // نه پیش‌فرض 8/9 (Strapping)
#else
  #error "This station supports the ESP32 and the ESP32-C3 only"
#endif

void printReport() {
  Serial.printf("Chip: %s, %d core(s)\n", ESP.getChipModel(), ESP.getChipCores());
  Serial.printf("Pins: DHT %d, LDR %d, LED %d, buzzer %d, button %d, I2C %d/%d\n",
                PIN_DHT, PIN_LDR, PIN_LED, PIN_BUZ, PIN_BTN, PIN_SDA, PIN_SCL);
#if SOC_TEMP_SENSOR_SUPPORTED
  Serial.println("Chip temperature sensor: yes");
#else
  Serial.println("Chip temperature sensor: no");
#endif

void setup() {
  Serial.begin(115200);
  unsigned long t0 = millis();

  printReport();

  1. include کردن soc_caps.h. بدون آن، SOC_TEMP_SENSOR_SUPPORTED تعریف نشده است، #if آن را صفر حساب می‌کند، و C3 بی‌سروصدا قابلیتش را از دست می‌دهد.
  2. یک بلوک پین برای هر تراشه، و #error برای بقیه. هر شاخه همان هفت اسم را تعریف می‌کند. چون اسم‌ها یکسان‌اند، هیچ خطی در ادامه لازم نیست بداند روی کدام تراشه است. ساخت برای S3 یا C6 با صدای بلند شکست می‌خورد، به جای این که با پین‌های بی‌معنی اجرا شود.
  3. chipC، دمای خود تراشه. جایی که سنسور نیست، NAN می‌ماند. متغیر روی هر دو تراشه وجود دارد تا کد مشترک بتواند از آن استفاده کند؛ فقط خط‌هایی که پرش می‌کنند و نمایشش می‌دهند حصار کشیده شده‌اند.
  4. خواندن سنسور فقط جایی که تراشه آن را دارد. هسته ESP32 معمولی هم یک temperatureRead() دارد، ولی از یک سنسور قدیمی و بی‌مستند استفاده می‌کند که روی بیشتر بردها یک عدد ثابت بی‌معنی برمی‌گرداند، و فهرست قابلیت‌های Espressif هم می‌گوید «ندارد». پرسیدن از قابلیت، نه از اسم تراشه، این را برای تراشه‌های آینده هم خودکار درست می‌کند.
  5. خط آخر OLED، فقط برای C3. همان الگوی خط‌های DAC و لمس در PortableDemo: کد هر قابلیت داخل ماکروی همان قابلیت زندگی می‌کند.
  6. گزارش قابلیت‌ها. مدل تراشه، هسته‌ها، همه پین‌ها، و جواب درباره سنسور دما. یک نگاه به Serial Monitor می‌گوید کدام شاخه کامپایل شده. اگر روزی شماره پین‌های ESP32 را روی C3 دیدی، برد اشتباهی را در IDE انتخاب کرده‌ای.
  7. حداکثر ۳ ثانیه صبر برای Serial، بعد گزارش. روی C3 با CDC On Boot فعال، این جلوی گم شدن گزارش را می‌گیرد. روی ESP32 شرط فورا برقرار است، و با باتری و بدون کامپیوتر، صبر بعد از ۳ ثانیه تمام می‌شود.
  8. LEDC برای بازر، بدون تغییر. ledcAttach و ledcWriteTone در هسته ۳.x روی هر دو تراشه وجود دارند. برای همین انتقال به خط‌های خیلی کمی دست می‌زند.
  9. Wire.begin(PIN_SDA, PIN_SCL). پین‌های صریح از جدول، هرگز پیش‌فرض‌های برد: روی C3 پیش‌فرض‌ها از پین‌های Strapping هستند.
  10. خط Serial در سه تکه. بخش مشترک، دمای تراشه مخصوص C3، و بعد پایان خط. شکستن printf اجازه می‌دهد بخش اختیاری داخل #if خودش بنشیند، بدون تکرار کل خط.

اثبات این که برای هر دو کامپایل می‌شود، با arduino-cli و هسته 3.3.12، دقیقا مثل compile.sh بالا: esp32:esp32:esp32 موفق، esp32:esp32:esp32c3 موفق، و esp32:esp32:esp32s3 همان‌طور که طراحی شده با #error "This station supports the ESP32 and the ESP32-C3 only" متوقف می‌شود.

  2. هر بیداری با کارهای ارزان شروع می‌شود: رطوبت خاک به صورت ۰ تا ۱۰۰ درصد (پتانسیومتر روی GPIO34 که فقط هنگام خواندن از GPIO26 برق می‌گیرد) و ولتاژ باتری بر حسب میلی‌ولت (یک تقسیم‌کننده ۲۰ کیلواهم + ۲۰ کیلواهم روی GPIO32)؛ هر دو چاپ می‌شوند.
  3. بیداری با تایمر (هر ۱۵ دقیقه) یا روشن شدن: یک پیام JSON به شکل {"soil":..,"bat":..,"low":0/1,"n":..,"fails":..} به topic خودت، با میانبر Wi-Fi دیتالاگر ۶.۱ و هرگز بیشتر از ۸ ثانیه Wi-Fi. شکست شمرده می‌شود و نتیجه برای نمایشگر به خاطر سپرده می‌شود.
  4. بیداری با دکمه (GPIO27، EXT0): OLED درصد خاک، ولتاژ باتری، LOW BATTERY! زیر ۳٫۴ ولت، و موفق بودن یا نبودن آخرین ارسال را ۳ ثانیه نشان می‌دهد؛ بعد نمایشگر خاموش می‌شود. در این مسیر Wi-Fi روشن نمی‌شود.
  5. قبل از خواب: پین برق سنسور روی LOW قفل می‌شود، دکمه رها شده است، هر دو منبع بیداری تنظیم شده‌اند، و Awake <ms> ms چاپ می‌شود.
  6. اندازه بگیر: مدت بیداری را از Serial Monitor و جریان خواب را با مولتی‌متر (مثل بخش اندازه‌گیری ۶.۱)، بعد عمر باتری را با عددهای خودت دوباره حساب کن.
  7. بازبینی کن: کد تمام‌شده‌ات را با چک‌لیست ده قدمی درس ۶.۲ بسنج: برای هر قدم قبول یا رد، با دلیل.
  8. قابل حمل: همان فایل برای ESP32-C3 هم کامپایل می‌شود، با شاخه پین خودش، EXT0 فقط جایی که SOC_PM_SUPPORT_EXT0_WAKEUP می‌گوید تراشه آن را دارد، و در غیر این صورت بیدار شدن با GPIO مخصوص C3.

راهنمایی ۱

بودجه توان از فرمول درس ۶.۱ روی یک دور ۹۰۰ ثانیه‌ای استفاده می‌کند: I_avg = (I_awake × t_awake + I_sleep × t_sleep) ÷ 900. هر جریانی را که در خواب برقرار است فهرست کن: تراشه، جریان بی‌باری رگولاتور، تقسیم‌کننده (V_bat ÷ 40 kΩ) و OLED خاموش. یکی از آن‌ها غافلگیرت می‌کند.

راهنمایی ۳

C3 حالت EXT0 ندارد. بیدار شدن از خواب عمیق با یک پین در C3 با esp_deep_sleep_enable_gpio_wakeup(1ULL << pin, ESP_GPIO_WAKEUP_GPIO_LOW) است، و فقط GPIO0 تا 5 این کار را می‌کنند. بعد از بیدار شدن به این روش، علت ESP_SLEEP_WAKEUP_GPIO است، نه EXT0. دو نسخه را در #if SOC_PM_SUPPORT_EXT0_WAKEUP / #else بگذار.

۳. بودجه توان، یک دور = ۱۵ دقیقه = ۹۰۰ ثانیه. بیداری تایمری: حدود ۲ ثانیه با میانگین ۱۲۰ میلی‌آمپر با Wi-Fi (عدد درس ۶.۱) = ۲۴۰ mA·s. دکمه: فرض کن روزی ۴ بار × ۳٫۲ ثانیه × ۵۰ میلی‌آمپر (پردازنده + OLED) = ۶۴۰ mA·s در روز ÷ ۹۶ دور ≈ ۷ mA·s در هر دور. خواب روی یک ساخت کم‌مصرف (ماژول خالی + HT7833): تراشه ۰٫۰۱ + رگولاتور حدود ۰٫۰۰۵ + تقسیم‌کننده ۳٫۷ ولت ÷ ۴۰ کیلواهم = ۰٫۰۹۳ + OLED خاموش حدود ۰٫۰۱ ≈ ۰٫۱۲ میلی‌آمپر × ۸۹۸ ثانیه ≈ ۱۰۸ mA·s.

  • I_avg = (۲۴۰ + ۷ + ۱۰۸) ÷ ۹۰۰ ≈ ۰٫۳۹ میلی‌آمپر ← ۱۰۰۰ ÷ ۰٫۳۹ ≈ ۲۵۶۰ ساعت ≈ ۱۰۷ روز؛ واقع‌بینانه (× ۰٫۷۵) ≈ ۸۰ روز. R6 قبول است.
  • غافلگیری: تقسیم‌کننده تقریبا یک‌چهارم کل بودجه است (۸۳ از ۳۵۵ mA·s). با ۲ مقاومت ۱ مگااهمی (به‌اضافه یک خازن ۱۰۰ نانوفاراد از GPIO32 به GND تا ADC درست بخواند) به ۰٫۰۰۲ میلی‌آمپر می‌رسد و عمر واقع‌بینانه حدود ۱۰۰ روز می‌شود.
  • بدون پین برق، یک سنسور خازنی واقعی (حدود ۵ میلی‌آمپر) همیشه روشن می‌ماند: I_avg ≈ ۵٫۴ میلی‌آمپر، یعنی حدود ۶ روز. همین یک تصمیم طراحی ۱۴ برابر فرق می‌کند.
  • روی DevKitC (حدود ۶ میلی‌آمپر در خواب): (۲۴۰ + ۷ + ۶ × ۸۹۸) ÷ ۹۰۰ ≈ ۶٫۳ میلی‌آمپر ← حدود ۵ روز واقع‌بینانه. کد همان است؛ برد نه.

// ---------- حافظه RTC: بعد از خواب عمیق می‌ماند ----------
RTC_DATA_ATTR uint32_t bootCount = 0;
RTC_DATA_ATTR uint32_t failCount = 0;
RTC_DATA_ATTR bool lastSendOk = false;
RTC_DATA_ATTR uint8_t savedChannel = 0;          // میانبر Wi-Fi (درس ۶.۱)
RTC_DATA_ATTR uint8_t savedBssid[6];

int readSoilPct() {
  gpio_hold_dis((gpio_num_t)PIN_PWR);            // قفل خواب قبلی را آزاد کن
  pinMode(PIN_PWR, OUTPUT);
  digitalWrite(PIN_PWR, HIGH);                   // برق سنسور فقط حالا روشن
  delay(100);                                    // فرصت پایدار شدن سنسور
  int raw = analogRead(PIN_SOIL);                // 0..4095
  digitalWrite(PIN_PWR, LOW);                    // و دوباره خاموش
  return constrain(map(raw, SOIL_DRY, SOIL_WET, 0, 100), 0, 100);
}

int readBatteryMv() {
  uint32_t sum = 0;
  for (int i = 0; i < 8; i++) sum += analogReadMilliVolts(PIN_BAT);  // میانگین ۸ خواندن
  return (sum / 8) * 2;                          // تقسیم‌کننده 20k/20k نصفش می‌کند
}

bool connectWiFiFast() {
  WiFi.mode(WIFI_STA);
  WiFi.persistent(false);
  if (savedChannel != 0) WiFi.begin(WIFI_SSID, WIFI_PASS, savedChannel, savedBssid);
  else WiFi.begin(WIFI_SSID, WIFI_PASS);
  uint32_t start = millis();
  while (WiFi.status() != WL_CONNECTED) {
    if (millis() - start > WIFI_TIMEOUT_MS) { savedChannel = 0; return false; }
    delay(20);
  }
  savedChannel = WiFi.channel();
  memcpy(savedBssid, WiFi.BSSID(), 6);
  return true;
}

bool publishReading(int soil, int batMv) {
  if (!connectWiFiFast()) return false;
  mqtt.setServer(MQTT_HOST, 1883);
  String id = "plant-" + WiFi.macAddress() + "-" + String(esp_random() & 0xFFFF, HEX);
  if (!mqtt.connect(id.c_str())) return false;
  char msg[80];
  snprintf(msg, sizeof(msg), "{\"soil\":%d,\"bat\":%d,\"low\":%d,\"n\":%lu,\"fails\":%lu}",
           soil, batMv, batMv < LOW_BAT_MV, (unsigned long)bootCount, (unsigned long)failCount);
  bool ok = mqtt.publish(TOPIC, msg);
  mqtt.loop();
  delay(50);                                     // فرصت خروج بسته
  mqtt.disconnect();
  if (ok) Serial.printf("Sent: %s\n", msg);
  return ok;
}

void showOnOled(int soil, int batMv) {
  Wire.begin(PIN_SDA, PIN_SCL);
  if (!oled.begin(SSD1306_SWITCHCAPVCC, 0x3C)) { Serial.println("OLED not found"); return; }
  oled.clearDisplay();
  oled.setTextColor(SSD1306_WHITE);
  oled.setTextSize(2);
  oled.setCursor(0, 0);
  oled.printf("Soil %d%%", soil);
  oled.setCursor(0, 22);
  oled.printf("%.2f V", batMv / 1000.0);
  oled.setTextSize(1);
  oled.setCursor(0, 48);
  oled.print(batMv < LOW_BAT_MV ? "LOW BATTERY! " : "");
  oled.print(lastSendOk ? "last send OK" : "last send FAILED");
  oled.display();
  delay(3000);                                   // تنها صبر طولانی: کاربر می‌خواند
  oled.ssd1306_command(SSD1306_DISPLAYOFF);      // OLED روشن‌مانده باتری را خالی می‌کند
}

void sleepNow() {
  WiFi.mode(WIFI_OFF);
  gpio_hold_en((gpio_num_t)PIN_PWR);             // برق سنسور در خواب LOW می‌ماند
  gpio_deep_sleep_hold_en();
  pinMode(PIN_BTN, INPUT_PULLUP);
  while (digitalRead(PIN_BTN) == LOW) delay(10); // صبر تا دکمه رها شود
  esp_sleep_enable_timer_wakeup(SLEEP_MIN * 60ULL * 1000000ULL);
#if SOC_PM_SUPPORT_EXT0_WAKEUP
  esp_sleep_enable_ext0_wakeup((gpio_num_t)PIN_BTN, 0);   // ESP32: EXT0 با LOW
  rtc_gpio_pullup_en((gpio_num_t)PIN_BTN);
  rtc_gpio_pulldown_dis((gpio_num_t)PIN_BTN);
#else
  esp_deep_sleep_enable_gpio_wakeup(1ULL << PIN_BTN, ESP_GPIO_WAKEUP_GPIO_LOW);  // C3
#endif
  Serial.printf("Awake %lu ms. Sleep %llu min\n", millis(), SLEEP_MIN);
  Serial.flush();
  esp_deep_sleep_start();
}

void setup() {
  Serial.begin(115200);
  bootCount++;
  analogReadResolution(12);
  int soil = readSoilPct();                      // اول کارهای ارزان
  int batMv = readBatteryMv();
  Serial.printf("#%lu soil=%d %% bat=%d mV\n", (unsigned long)bootCount, soil, batMv);
  esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause();
  if (cause == ESP_SLEEP_WAKEUP_EXT0 || cause == ESP_SLEEP_WAKEUP_GPIO) {
    showOnOled(soil, batMv);                     // دکمه: نمایش، بدون Wi-Fi
  } else {                                       // تایمر یا روشن شدن: ارسال
    lastSendOk = publishReading(soil, batMv);
    if (!lastSendOk) { failCount++; Serial.println("Not sent, will retry next wake"); }
  }
  sleepNow();
}
