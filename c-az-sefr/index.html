1 · سؤال شروع

چطور به یه میکروکنترلر بگیم چیکار کنه؟

فرض کن می‌خوای به یه میکروکنترلر مثل ESP32 بگی یه پیام رو از پورت سریال بفرسته یا یه LED رو روشن کنه. میکروکنترلر فقط صفر و یک می‌فهمه، نه فارسی و نه انگلیسی. برای همین یه زبون واسط لازم داریم که هم برای آدم قابل فهم باشه، هم بشه تبدیلش کرد به چیزی که تراشه می‌فهمه. یکی از پرکاربردترین این زبون‌ها برای دنیای embedded، زبان C است.

فعلا کدهامون رو روی خود کامپیوترت اجرا می‌کنیم، نه روی یه برد واقعی — چون دیباگ کردن روی کامپیوتر خیلی ساده‌تره. وقتی زبان رو محکم بلد شدی (طبق نقشه راهی که قبلا با هم چیدیم)، همین دقیقا کدها رو می‌بریم روی ESP32 و STM32.

از کد تا اجرا شدن

وقتی یه فایل C می‌نویسی (بهش می‌گن Source Code)، یه برنامه به اسم Compiler (مثلا GCC، همون چیزی که داخل OnlineGDB کار می‌کنه) اون رو می‌خونه و تبدیلش می‌کنه به زبان تراشه (Machine Code — یعنی یه دنباله از صفر و یک، مثلا چیزی شبیه 10110000 01100001). بعد پردازنده (CPU — روی کامپیوترت یه تراشه‌ی Intel یا AMD است، روی ESP32 یه هسته Xtensa، روی STM32 یه هسته Cortex-M) اون رو اجرا می‌کنه. به تبدیل‌شدن می‌گن Compile و به اجرا شدنش می‌گن Run.

3 · مثال — روی هر خط بزن

برنامه اولت

این کاملترین و کوچیک‌ترین برنامه ممکنه. روی هر خط بزن تا ببینی دقیقا چیکار می‌کنه.

hello.c
#include <stdio.h>

#include یعنی «یه فایل دیگه رو بیار اینجا اضافه کن». stdio.h یه فایل آماده است که توش دستور printf تعریف شده. بدون این خط، کامپایلر اصلا نمی‌دونه printf چیه.

int main(void)

main نقطه شروع هر برنامه C است. وقتی برنامه اجرا می‌شه، اولین جایی که وارد می‌شه همینجاست — هر چقدر هم فایلت بزرگ باشه.

int قبلش یعنی این تابع در پایان یه عدد صحیح برمی‌گردونه. void داخل پرانتز یعنی این تابع هیچ ورودی نمی‌گیره.

{

این آکولاد باز، شروع بدنه تابع main است — یعنی از اینجا به بعد، دستورهایی که داخل main هستن نوشته می‌شن.

    printf("Hello, World!\n");

printf یعنی «چاپ کن». هر چی بین " " باشه، دقیقا همونطوری روی صفحه چاپ می‌شه.

\n یه کاراکتر خاصه، یعنی «برو خط بعد» — دقیقا مثل زدن Enter.

; آخر خط یعنی «این دستور تموم شد». در C، تقریبا آخر هر دستور باید ; بذاری، وگرنه کامپایلر گیج می‌شه.

    return 0;

این یعنی «برنامه با موفقیت تموم شد». عدد 0 به سیستم‌عامل می‌گه هیچ خطایی پیش نیومده — همون عددی‌یه که بالا با int قول داده بودیم برگردونیم.

}

این آکولاد بسته، پایان تابع main است — یعنی برنامه اینجا تموم می‌شه.

اگه ; رو جا بندازی چی می‌شه؟

کد اشتباه
printf("Hello, World!\n") return 0;

این خطا رو می‌بینی: expected ';' before 'return'

یعنی کامپایلر می‌گه «من انتظار داشتم قبل از return یه ; ببینم، ولی نبود». نکته مهم: کامپایلر خط printf رو (جایی که واقعا ; جا افتاده) به عنوان مشکل نشون نمی‌ده، بلکه خط بعدی رو نشون می‌ده. پس وقتی خطای شبیه این دیدی، همیشه یه خط بالاتر رو هم چک کن.

Variable: جعبه‌ای برای نگه داشتن یه مقدار

هر برنامه واقعی باید یه جایی مقدارها رو نگه داره. اینجا یاد می‌گیری چطور.

1 · سؤال شروع

عدد رو کجا نگه داریم؟

فرض کن یه حسگر فاصله مثل HC-SR04 (دقیقا همون که رو پروژه خودت داری) هر لحظه یه عدد فاصله برمی‌گردونه. برای این که بتونی بعدا باهاش تصمیم بگیری (مثلا «اگه فاصله کمتر از 10 سانتی‌متر شد، آژیر بزن»)، اول باید یه جا نگهش داری. این «جا»، یه Variable (متغیر) است.

2 · توضیح ساده

Variable چیه؟

Variable رو مثل یه جعبه با اسم در نظر بگیر که یه مقدار توش نگه می‌داری. برای ساختنش سه چیز لازمه: نوع مقدار، اسم جعبه، و خود مقدار.

variable.c
int distance = 25;
int — نوع داده: یعنی این جعبه فقط عدد صحیح (بدون اعشار) نگه می‌داره.
distance — اسم جعبه: هر اسمی که بخوای، به شرطی که با عدد شروع نشه.
= 25 — مقداردهی اولیه (Initialization): مقداری که همون لحظه داخل جعبه می‌ذاریم.

می‌تونی تعریف کردن و مقداردهی رو هم جدا کنی — به این می‌گن Declaration (تعریف) و بعدش Assignment (مقداردهی):

variable.c
int distance; distance = 40;
3 · مثال

چاپ کردن مقدار یه Variable

hello.c
#include <stdio.h> int main(void) { int distance = 25; printf("Distance: %d cm\n", distance); return 0; }
%d — تو رشته چاپی، یعنی «اینجا یه عدد صحیح بذار». مقداری که جاش می‌شینه، از distance که بعد از کاما نوشتیم میاد. بعدا تو درس Input/Output کامل درباره %d و بقیه‌شون توضیح می‌دیم.

انواع داده: چه اندازه‌ای برای چه مقداری؟

هر Variable باید یه نوع داشته باشه. اینجا یاد می‌گیری کدوم نوع رو کِی انتخاب کنی.

1 · سؤال شروع

یه عدد صحیح با یه عدد اعشاری فرق داره

مبدل آنالوگ‌به‌دیجیتال (ADC) یه میکروکنترلر معمولا یه عدد صحیح بین 0 تا 4095 برمی‌گردونه، ولی دمای هوا می‌تونه اعشاری باشه، مثلا 24.5. اگه برای هر دو از یه نوع داده استفاده کنی، یا جا حروم می‌کنی یا داده‌ات ناقص می‌شه. برای همین C چند نوع داده مختلف داره.

2 · توضیح ساده

نوع‌های اصلی

اندازه دقیق هر نوع بین کامپایلرها و سیستم‌ها کمی فرق می‌کنه؛ اینا رایج‌ترین اندازه‌ها روی یه کامپیوتر معمولی و اکثر میکروکنترلرهای ARM هستن.

int — عدد صحیح، معمولا 4 بایت (مثلا -2000000000 تا +2000000000 تقریبا)
float — عدد اعشاری، معمولا 4 بایت (مثلا 24.5)
double — عدد اعشاری با دقت بیشتر، معمولا 8 بایت
char — یک کاراکتر یا عدد کوچیک، 1 بایت (مثلا 'A' یا عدد 0 تا 255)
short / long — نسخه کوچیک‌تر و بزرگ‌تر int
unsigned — می‌شه جلوی هر نوع صحیح گذاشت؛ یعنی «فقط مثبت»، در ازاش رنج مثبتش دو برابر می‌شه
const — یعنی این مقدار بعد از تعریف دیگه قابل تغییر نیست
3 · مثال

استفاده ترکیبی از چند نوع

types.c
#include <stdio.h> int main(void) { unsigned int sensorValue = 2048; float temperature = 24.5; const int MAX_DISTANCE = 400; printf("ADC: %u\n", sensorValue); printf("Temp: %.1f C\n", temperature); printf("Max range: %d cm\n", MAX_DISTANCE); printf("Size of int: %zu bytes\n", sizeof(int)); return 0; }
%u — برای چاپ unsigned int استفاده می‌شه (نه %d)
%.1f — یعنی «عدد اعشاری رو با فقط یک رقم بعد از اعشار چاپ کن»
sizeof(int) — یه عملگره که اندازه واقعی نوع رو بهت می‌ده، بر حسب بایت

عملگرها: کار با مقدارها

برای این که بشه با مقدارها حساب کرد و مقایسه‌شون کرد، به عملگر نیاز داریم.

2 · توضیح ساده

دسته‌های اصلی عملگر

+ - * / % — محاسباتی: جمع، تفریق، ضرب، تقسیم، و باقی‌مانده تقسیم
> < >= <= == != — مقایسه‌ای: نتیجه‌شون همیشه 1 (درست) یا 0 (غلط) است
&& || ! — منطقی: و، یا، نقیض (برای ترکیب چند شرط)
++ -- — افزایش و کاهش یک واحدی
+= -= *= /= — تخصیص ترکیبی: x += 5 دقیقا مثل x = x + 5 است
3 · مثال

مقایسه و محاسبه

operators.c
#include <stdio.h> int main(void) { int temperature = 33; int isHot = temperature > 30; int average = (28 + 33) / 2; printf("Is hot: %d\n", isHot); printf("Average: %d\n", average); printf("Doubled: %d\n", temperature * 2); return 0; }

(28 + 33) / 2 — پرانتز دقیقا مثل ریاضی، اولویت محاسبه رو مشخص می‌کنه.

شرط‌ها: تصمیم گرفتن تو کد

حالا که می‌تونی مقایسه کنی، وقتشه بر اساس نتیجه‌اش یه کار متفاوت انجام بدی.

1 · سؤال شروع

اگه دما بالا رفت، چیکار کنیم؟

درس قبل یاد گرفتی چطور مقایسه کنی. حالا سؤال اینه: بر اساس نتیجه اون مقایسه، چطور بگیم «اگه درست بود این کارو بکن، وگرنه اون یکی رو»؟ جوابش if و else است.

2 · توضیح ساده

if / else / else if / switch

if (شرط) { ... } — اگه شرط درست بود، بلوک اجرا می‌شه
else { ... } — وقتی شرط غلط بود، این بلوک اجرا می‌شه
else if (شرط 2) — برای بررسی چند حالت پشت سر هم
switch / case / default — وقتی یه Variable می‌تونه چند حالت مشخص داشته باشه (مثلا حالت‌های یه دستگاه)، خواناتر از یه رشته else if است
3 · مثال

کنترل فن با if / else

fan.c
#include <stdio.h> int main(void) { int temperature = 33; if (temperature > 30) { printf("Fan: ON\n"); } else { printf("Fan: OFF\n"); } return 0; }

و وقتی حالت‌های مشخص و از پیش تعریف‌شده داری (نه فقط یه مقایسه ساده)، switch تمیزتره — مثلا حالت‌های یه دستگاه:

state.c
#include <stdio.h> int main(void) { int state = 1; switch (state) { case 0: printf("State: OFF\n"); break; case 1: printf("State: RUNNING\n"); break; case 2: printf("State: ERROR\n"); break; default: printf("State: UNKNOWN\n"); } return 0; }
break — یعنی «از سوییچ بیا بیرون». بدونش، اجرا به case بعدی هم سر می‌ره (به این می‌گن Fall-through).
default — وقتی هیچ‌کدوم از case ها با مقدار state جور در نیاد، این اجرا می‌شه.

حلقه‌ها: تکرار بدون کپی کردن کد

1 · سؤال شروع

سنسور رو 5 بار بخونیم چطور؟

فرض کن می‌خوای یه سنسور فاصله رو 5 بار پشت سر هم بخونی (این تکنیک رو Oversampling می‌گن — برای دقیق‌تر شدن نتیجه). نمی‌خوای همون خط کد رو 5 بار کپی کنی. اینجا Loop (حلقه) به کمکت میاد.

2 · توضیح ساده

for / while / do-while

while (شرط) — وقتی نمی‌دونی چند بار، فقط یه شرط داری (مثلا «تا وقتی دکمه فشرده نشده»)

رشته‌ها: متن تو C چطور کار می‌کنه

C نوع مخصوص برای متن نداره — رشته یه ترفند ساده با آرایه char است.

1 · سؤال شروع

یه دستور متنی رو کجا نگه داریم؟

2 · توضیح ساده

String واقعا یه Array از char است

C برخلاف خیلی زبون‌های دیگه، نوع جدا برای متن نداره. یه String فقط یه آرایه از char است که با یه کاراکتر خاص و نامرئی به اسم Null Terminator (نوشته می‌شه \0) تموم می‌شه. یعنی char message[] = "Hello"; در واقع 6 تا خونه‌ست: 'H','e','l','l','o','\0' — نه 5 تا. همین \0 است که به توابعی مثل printf می‌گه «رشته اینجا تموم شد».

3 · مثال

خواندن و مقایسه یه دستور

string.c
#include <stdio.h> #include <string.h> int main(void) { char command[] = "ON"; printf("Command: %s\n", command); printf("Length: %d\n", (int)strlen(command)); if (strcmp(command, "ON") == 0) { printf("Turning LED on\n"); } return 0; }
%s — فرمت مخصوص چاپ String
strlen — طول واقعی متن رو می‌ده (بدون احتساب \0)
strcmp(a, b) == 0 — یعنی دو رشته دقیقا برابرن. توجه کن: نتیجه‌اش 0 یعنی «برابر»، نه یعنی «غلط» — برعکس چیزی که شاید فکر کنی!

ساختار یه تابع

Scope: یه Variable کجا زنده‌ست؟

هر Variable یه محدوده داره که توش «وجود داره». به این محدوده Scope می‌گن.

1 · سؤال شروع

اگه دو تا تابع، هر دو یه Variable با اسم مشابه داشته باشن چی؟

فرض کن هم تو main هم تو یه تابع دیگه یه Variable به اسم i داری. آیا به هم گیر می‌کنن؟ جواب نه — چون هر کدوم فقط تو محدوده خودشون «دیده می‌شن».

Local، Global و static

Local — Variable ای که داخل یه تابع (یا یه بلوک { }) تعریف شده؛ فقط همونجا وجود داره و بعد از تموم شدن تابع از بین می‌ره
Global — بیرون از همه توابع تعریف می‌شه؛ همه‌جای فایل قابل دیدنه و تا آخر عمر برنامه زنده‌ست
static — یه Local Variable که جلوش static بذاری، برخلاف بقیه، مقدارش بین صدا زدن‌های مختلف تابع از بین نمی‌ره
3 · مثال

یه شمارنده خطای Global

scope.c
#include <stdio.h> int errorCount = 0; void checkSensor(int distance) { if (distance < 0) { errorCount++; printf("Invalid reading! Errors so far: %d\n", errorCount); } } int main(void) { checkSensor(25); checkSensor(-5); checkSensor(-1); printf("Total errors: %d\n", errorCount); return 0; }
int errorCount = 0; — بیرون همه توابع نوشته شده، پس Global است و همه جا در دسترسه
distance — یه پارامتر Local است؛ فقط داخل checkSensor معنی داره

Pointer: قلب واقعی Embedded C

این مهم‌ترین درس این دوره است. آروم و دقیق جلو برو — بدون این، درس‌های Bitwise و Memory برات بی‌معنی می‌مونن.

1 · سؤال شروع

چطور مستقیم به یه خونه حافظه دسترسی داشته باشیم؟

هر Variable که تعریف می‌کنی، یه جایی تو حافظه (RAM) ذخیره می‌شه — و اون جا یه آدرس داره، دقیقا مثل آدرس یه خونه. تا الان همیشه با اسم Variable باهاش کار کردیم. حالا سؤال اینه: چطور می‌تونیم مستقیم با اون آدرس کار کنیم؟ جوابش Pointer است — و دلیل اهمیتش تو embedded: هر register سخت‌افزاری داخل یه میکروکنترلر (مثلا کنترل یه پایه GPIO) دقیقا یه آدرس حافظه ثابته. بدون Pointer، اصلا نمی‌شه مستقیم با سخت‌افزار حرف زد.

2 · توضیح ساده — قدم به قدم

Value، Address و Pointer

فرض کن این متغیر رو داریم: int distance = 25;

اسم: distance — مقدار: 25
این متغیر یه آدرس هم داره، مثلا
آدرس: چیزی شبیه 0x7ffee3ab2a1c

دو تا عملگر جدید لازم داریم:

&distance — یعنی «آدرس distance رو بده» (عملگر address-of)
int *ptr = &distance; — ptr رو می‌سازیم و آدرس distance رو توش می‌ذاریم. اینجا ptr خودش یه Variable است، فقط به‌جای عدد معمولی، یه آدرس نگه می‌داره
*ptr — یعنی «برو سراغ آدرسی که ptr نگه داشته، مقدار همونجا رو بده» (عملگر dereference)

نکته مهم: علامت * دو تا معنی کاملا متفاوت داره بسته به جاش — موقع تعریف (int *ptr) یعنی «این یه Pointer است»، ولی موقع استفاده (*ptr) یعنی «برو سراغ اون آدرس». این جاییه که اکثر مبتدی‌ها گیج می‌شن.

3 · مثال — روی هر خط بزن

تغییر دادن یه مقدار از طریق Pointer

pointer.c
int distance = 25;

یه Variable معمولی با مقدار 25.

int *ptr = &distance;

ptr رو می‌سازیم و آدرس distance رو (با &) توش می‌ذاریم. از این لحظه، ptr «می‌دونه» distance کجای حافظه‌ست.

printf("Address: %p\n", (void *)&distance);

%p فرمت مخصوص چاپ آدرسه. این خط، آدرس واقعی distance تو حافظه رو نشون می‌ده.

printf("Pointer holds: %p\n", (void *)ptr);

این هم آدرسیه که ptr نگه داشته — باید دقیقا با خط قبلی یکی باشه، چون هر دو دارن آدرس distance رو نشون می‌دن.

printf("Dereferenced: %d\n", *ptr);

اینجا *ptr یعنی «برو سراغ آدرسی که ptr داره، مقدار همونجا رو بیار». چون اون آدرس همون distance است، نتیجه 25 می‌شه.

*ptr = 40;

این خط کلیدیه: از طریق ptr، مستقیم می‌ریم سراغ آدرس distance و مقدارش رو به 40 تغییر می‌دیم — بدون این‌که اسم distance رو مستقیم ببریم!

printf("New value: %d\n", distance);

چون *ptr = 40 واقعا خونه حافظه distance رو عوض کرد، حالا خود distance هم 40 شده. این دقیقا قدرت Pointer است.

Dereference کردن یه Pointer بی‌مقدار

کد خطرناک
int *ptr; printf("%d\n", *ptr);

اینجا ptr هیچ‌وقت مقداردهی نشده — یعنی معلوم نیست به کدوم آدرس اشاره می‌کنه. *ptr یعنی «برو سراغ اون آدرس نامعلوم و بخون» — نتیجه‌اش می‌تونه یه Crash (به اسم Segmentation Fault) باشه یا یه مقدار کاملا بی‌معنی. همیشه قبل از Dereference کردن، مطمئن شو Pointer به یه آدرس معتبر اشاره می‌کنه.

اینجاست که همه چیز به هم وصل می‌شه

Register آدرس‌دار

هر register کنترلی داخل یه میکروکنترلر (مثلا رجیستری که وضعیت یه پایه GPIO رو کنترل می‌کنه) دقیقا یه آدرس ثابت تو حافظه است — مثلا چیزی شبیه 0x40020000. برای نوشتن مستقیم روی همچین رجیستری، دقیقا از همین Pointer که امروز یاد گرفتی استفاده می‌شه:

register.c (پیش‌نمایش — تو نقشه راهت به این می‌رسیم)
volatile uint32_t *reg = (volatile uint32_t *)0x40020000; *reg = 0x1;

دقیقا همون int *ptr و *ptr = 40 که بالا نوشتیم — فقط آدرسش به‌جای یه Variable معمولی، یه register واقعی سخت‌افزاریه. کلمه volatile رو تو درس 16 کامل توضیح می‌دیم.

Struct: چند Variable مرتبط، یک بسته

وقتی چند مقدار مختلف به هم مربوطن، بهتره یه‌جا نگه‌شون داری.

1 · سؤال شروع

دما و رطوبت یه اتاق رو چطور با هم نگه داریم؟

یه سنسور دما-رطوبت واقعی همیشه دو تا مقدار مرتبط برمی‌گردونه. نگه داشتن‌شون تو دو تا Variable کاملا جدا (temperature و humidity) کار می‌کنه، ولی هیچ ارتباطی بین‌شون تو کد نشون داده نمی‌شه. Struct یه بسته واحد برای چند مقدار مرتبط می‌سازه.

2 · توضیح ساده

Struct چیه؟

Struct یعنی تعریف یه نوع داده جدید و شخصی‌سازی‌شده، که از چند فیلد (حتی با نوع‌های متفاوت) تشکیل شده. بعد از تعریفش، می‌تونی مثل هر نوع دیگه (int، float) ازش Variable بسازی.

3 · مثال

یه Struct برای سنسور

struct.c
#include <stdio.h> struct Sensor { int temperature; int humidity; }; int main(void) { struct Sensor room = {24, 55}; printf("Temp: %d C\n", room.temperature); printf("Humidity: %d %%\n", room.humidity); room.temperature = 26; printf("Updated temp: %d C\n", room.temperature); return 0; }
struct Sensor { ... }; — تعریف یه نوع جدید به اسم Sensor با دو فیلد؛ خودش هنوز هیچ حافظه‌ای نمی‌گیره
struct Sensor room = {24, 55}; — الان یه Variable واقعی از نوع Sensor ساختیم، با 24 برای فیلد اول و 55 برای دومی
room.temperature — عملگر نقطه، برای دسترسی به یه فیلد خاص داخل Struct
%% — چون % تو printf معنی خاص داره، برای چاپ یه علامت % واقعی باید دو بار بنویسیش

Enum چیه؟

Enum یه لیست از اسم‌های معنی‌دار می‌سازه که هر کدوم پشت پرده یه عدد صحیح‌ان. اگه خودت عددی مشخص نکنی، از 0 شروع می‌شه و هر عضو بعدی یکی بیشتره.

3 · مثال

enum.c
#include <stdio.h> enum State { STATE_OFF, STATE_STARTING, STATE_RUNNING, STATE_ERROR }; int main(void) { enum State current = STATE_RUNNING; if (current == STATE_RUNNING) { printf("System is running\n"); } printf("State number: %d\n", current); return 0; }
STATE_OFF, STATE_STARTING, ... — به ترتیب مقدار 0, 1, 2, 3 می‌گیرن، خودکار
current == STATE_RUNNING — خیلی خواناتر از current == 2 است، با این‌که پشت پرده دقیقا همون مقایسه‌ست

عملگرهای بیتی: زبان واقعی سخت‌افزار

این یکی از مهم‌ترین درس‌های این دوره برای embedded است — کنترل مستقیم پایه‌های سخت‌افزاری دقیقا با همین عملگرها انجام می‌شه.

1 · سؤال شروع

چطور فقط یه پایه رو روشن کنیم، بدون دست زدن به بقیه؟

فرض کن یه رجیستر 8 بیتی داری که هر بیتش وضعیت یه پایه GPIO جدا رو کنترل می‌کنه. می‌خوای فقط پایه شماره 3 رو روشن کنی — بدون این‌که به وضعیت 7 تا پایه دیگه دست بزنی. نمی‌تونی کل رجیستر رو بازنویسی کنی، چون بقیه بیت‌ها هم مهمن. جواب: Bitwise Operators.

2 · توضیح ساده

عملگرهای بیت‌به‌بیت

باینری یعنی نمایش یه عدد فقط با 0 و 1. مثلا عدد 10 می‌شه 00001010. عملگرهای بیتی، دقیقا بیت‌به‌بیت روی این صفر و یک‌ها کار می‌کنن:

00001010 (10) & 00000110 (6) ----------- 00000010 (2)
& (AND) — نتیجه هر بیت فقط وقتی 1 است که هر دو بیت 1 باشن
| (OR) — کافیه یکی از دو بیت 1 باشه
^ (XOR) — فقط وقتی دقیقا یکی از دو بیت 1 باشه (نه هر دو، نه هیچ‌کدوم)
~ (NOT) — همه بیت‌ها رو معکوس می‌کنه (0 می‌شه 1 و برعکس)
<< (Shift Left) — بیت‌ها رو به چپ می‌بره؛ 1 << 3 یعنی عدد 00001000 (یعنی 8)
>> (Shift Right) — بیت‌ها رو به راست می‌بره
3 · مثال — روی هر خط بزن

روشن، خاموش و Toggle کردن یه بیت

bitwise.c
unsigned char portB = 0x00;

یه رجیستر فرضی 8 بیتی می‌سازیم، همه بیت‌هاش صفر (00000000).

portB = portB | (1 << 3);

1 << 3 یعنی 00001000. با OR کردنش با portB، فقط بیت شماره 3 روشن می‌شه — بقیه بیت‌ها چون با 0 اور می‌شن، دست‌نخورده می‌مونن.

portB = portB & ~(1 << 3);

~(1 << 3) یعنی همه بیت‌ها 1 هستن به‌جز بیت 3 که 0 است. با AND کردن، فقط بیت 3 خاموش می‌شه — بقیه بیت‌ها (چون با 1 اند شدن) دست‌نخورده می‌مونن.

portB = portB ^ (1 << 3);

XOR کردن یه بیت با 1، اون بیت رو برعکس می‌کنه — اگه خاموش بود روشن می‌شه، اگه روشن بود خاموش. به این می‌گن Toggle.

استفاده از = به‌جای |=

کد خطرناک
portB = (1 << 3);

این کامپایل می‌شه، ولی کاری که واقعا می‌کنه با نیتت خیلی فرق داره: به‌جای «فقط بیت 3 رو روشن کن»، کل portB رو پاک می‌کنه و فقط بیت 3 رو می‌ذاره! اگه بیت‌های دیگه‌ای هم روشن بودن (مثلا پایه‌های دیگه‌ای که داشتن کار می‌کردن)، همه‌شون خاموش می‌شن. راه درست همیشه portB |= (1 << 3); است، نه portB = (1 << 3);. این یکی از رایج‌ترین و خطرناک‌ترین اشتباهات واقعی embedded است.

حافظه: کجا زندگی می‌کنیم؟

هر چیزی که تو C تعریف می‌کنی، یه‌جایی تو حافظه قرار می‌گیره. اینجا یاد می‌گیری کجا.

1 · سؤال شروع

وقتی یه Variable می‌سازی، دقیقا کجا می‌ره؟

روی کامپیوترت، حافظه (RAM) عملا نامحدود حس می‌شه. ولی خیلی از میکروکنترلرها فقط چند ده کیلوبایت RAM دارن. برای همین باید بدونی هر متغیری که می‌سازی، دقیقا کجای این فضای محدود قرار می‌گیره.

2 · توضیح ساده

نقشه حافظه یه برنامه

+-----------------------+ | Stack | ← Local variable ها، هر تابع | ↓ رشد می‌کنه | | | | ↑ رشد می‌کنه | | Heap | ← حافظه‌ای که دستی می‌گیری (malloc) +-----------------------+ | Global / Static Data | ← Variable های Global و static +-----------------------+ | Code | ← خود برنامه کامپایل‌شده +-----------------------+
Stack — هر بار یه تابع صدا زده می‌شه، Local Variable هاش اینجا ساخته می‌شن؛ به محض تموم شدن تابع، خودکار پاک می‌شن
Heap — حافظه‌ای که خودت دستی درخواست می‌کنی (با malloc)؛ خودت هم باید آزادش کنی
Global / Static — همون جاییه که Variable های Global و static (درس Scope) زندگی می‌کنن؛ تا آخر عمر برنامه پابرجان
3 · مثال

مقایسه Local و Global، و اندازه‌گیری فضا

memory.c
#include <stdio.h> int globalCounter = 0; void localExample(void) { int localValue = 10; printf("Local value: %d\n", localValue); } int main(void) { globalCounter++; localExample(); printf("Global counter: %d\n", globalCounter); printf("Size of 100 ints: %zu bytes\n", sizeof(int) * 100); return 0; }
globalCounter — تو بخش Global / Static زندگی می‌کنه
localValue — تو Stack ساخته می‌شه، بعد از تموم شدن localExample از بین می‌ره
sizeof(int) * 100 — دقیقا نشون می‌ده یه آرایه فرضی 100 تایی از int چند بایت حافظه می‌گیره — روی یه میکروکنترلر با RAM محدود، این محاسبه حیاتیه

volatile: وقتی سخت‌افزار خودش مقدار رو عوض می‌کنه

این یکی از تخصصی‌ترین و مهم‌ترین کلمه‌های کلیدی C برای embedded است.

1 · سؤال شروع

اگه سخت‌افزار خودش یه Variable رو عوض کنه چی؟

فرض کن یه فلگ داری که مقدارش نه با یه خط کد تو خود تابع، بلکه توسط یه Interrupt (یا مستقیم سخت‌افزار) تغییر می‌کنه. کامپایلر برای سریع‌تر کردن کد، معمولا فرض می‌کنه اگه خودش نبینه یه Variable عوض می‌شه، پس عوض نمی‌شه — و ممکنه یه کپی قدیمیش رو تو رجیستر CPU نگه داره به‌جای این‌که هر بار از حافظه بخونه. این می‌تونه فاجعه‌بار باشه. volatile دقیقا برای همین مشکل ساخته شده.

2 · توضیح ساده

سه کلمه کلیدی که قاطی می‌شن

volatile — به کامپایلر می‌گه: «این Variable ممکنه هر لحظه از بیرون (سخت‌افزار، Interrupt) تغییر کنه؛ هر بار واقعا از حافظه بخونش، هیچ بهینه‌سازی‌ای روش نکن.»
static — (یادآوری از درس Scope) یه Local Variable که مقدارش بین صدا زدن‌ها باقی می‌مونه
const — (یادآوری از درس Data Types) یه مقدار که بعد از تعریف دیگه قابل تغییر نیست

نکته مهم: این سه تا کاملا مستقلن و هیچ ربطی به هم ندارن — فقط چون اسم‌شون شبیه هم به نظر می‌رسه (همه‌شون یه کلمه قبل از نوع داده)، مبتدی‌ها قاطی‌شون می‌کنن.

3 · مثال

یه فلگ که قراره با Interrupt عوض بشه

volatile.c
volatile int sensorReady = 0;

این Global Variable، تو یه پروژه واقعی، توسط یه Interrupt Service Routine (وقتی سنسور آماده می‌شه) به 1 تغییر می‌کنه — نه توسط خط کدی که تو main می‌بینیم.

while (sensorReady == 0)

روی یه میکروکنترلر واقعی، این حلقه واقعا منتظر می‌مونه تا Interrupt مقدار رو عوض کنه. بدون volatile، کامپایلر ممکنه این حلقه رو طوری بهینه کنه که انگار همیشه ثابته و هیچ‌وقت از حافظه دوباره نخونه.

یه نکته صادقانه: چون OnlineGDB یه کامپایلر ساده‌ست و Interrupt واقعی نداره، این مثال فقط سینتکس درست volatile رو نشونت می‌ده — خود اثر بهینه‌سازی رو نمی‌تونی اینجا ببینی. برای دیدن اثر واقعیش باید رو یه میکروکنترلر واقعی باشی، دقیقا مرحله بعدی نقشه راهت.

2 · توضیح ساده

#include و #define

Preprocessor یه مرحله است که قبل از خود Compile اجرا می‌شه و صرفا متن کدت رو دستکاری می‌کنه — نه چیزی رو واقعا «اجرا» می‌کنه. #include رو از درس 1 می‌شناسی (یه فایل دیگه رو میاره تو). #define هم یه اسم رو با یه متن جایگزین می‌کنه، همه‌جای فایل، قبل از این‌که کامپایلر اصلا کدت رو ببینه.

3 · مثال

اسم‌گذاری با #define

define.c
#include <stdio.h> #define LED_PIN 13 #define MAX_DISTANCE 400 int main(void) { printf("LED is on pin %d\n", LED_PIN); printf("Max distance: %d cm\n", MAX_DISTANCE); return 0; }
#define LED_PIN 13 — از این خط به بعد، هر جای فایل که LED_PIN نوشته بشه، قبل از Compile با 13 جایگزین می‌شه. توجه کن: بدون ; در آخر — دستورهای Preprocessor فرق دارن
تفاوت با const — #define یه جایگزینی متنی خامه، نه یه Variable واقعی؛ هیچ نوع داده و (معمولا) هیچ فضای RAM مشخصی نداره

6 · خطای رایج

Macro با پرانتز، وگرنه فاجعه

کد خطرناک
#define SQUARE(x) x * x ... int result = SQUARE(3 + 2); // انتظار: 25 — واقعیت: 11

چون #define فقط جایگزینی متنیه، SQUARE(3 + 2) واقعا می‌شه 3 + 2 * 3 + 2 — که با اولویت ضرب روی جمع، نتیجه‌اش 11 می‌شه، نه 25! این یکی از کلاسیک‌ترین تله‌های Macro است. راه درست همیشه اضافه کردن پرانتز اضافه‌ست: #define SQUARE(x) ((x) * (x)).

بخش 18 · Debugging

وقتی کد کار نمی‌کنه، چیکار کنیم؟

آخرین درس این دوره: یاد می‌گیری چطور یه باگ رو سیستماتیک پیدا کنی — یکی از مهم‌ترین مهارت‌های هر برنامه‌نویس embedded.

1 · سؤال شروع

کد Compile شد، اجرا شد، ولی جواب غلطه — حالا چی؟

تا اینجا یاد گرفتی چطور کد درست بنویسی. ولی واقعیت اینه: یه روز کدی می‌نویسی که هیچ خطایی نمی‌ده، عادی هم اجرا می‌شه، ولی نتیجه‌اش اشتباهه. این سخت‌ترین نوع مشکله — چون هیچ پیامی بهت نمی‌گه کجا رو نگاه کنی.

2 · توضیح ساده

چهار نوع مشکل، چهار حس متفاوت

Syntax Error — کدت اصلا ساختار درست C رو نداره (مثلا یه ; جا افتاده)؛ کامپایلر حتی اجازه Compile نمی‌ده
Warning — کامپایلر یه چیز مشکوک می‌بینه (مثل = به‌جای ==) ولی بازم اجازه اجرا می‌ده — هیچ‌وقت این‌ها رو نادیده نگیر
Runtime Error — کد کامپایل می‌شه ولی وسط اجرا کرش می‌کنه (مثلا Dereference یه Pointer بی‌مقدار)
Logic Error — کد کامل و بدون خطا اجرا می‌شه، ولی نتیجه غلطه. سخت‌ترین نوع، چون هیچ پیامی نمی‌گیری
3 · مثال

پیدا کردن یه Logic Error با Print Debugging

debug.c
#include <stdio.h> int main(void) { int r1 = 20, r2 = 22, r3 = 24; printf("DEBUG: sum = %d\n", r1 + r2 + r3); int average = (r1 + r2 + r3) / 2; printf("Average: %d\n", average); return 0; }
printf("DEBUG: sum = %d\n", ...) — یه خط printf موقت که فقط برای فهمیدن یه مقدار واسط اضافه کردیم. به این می‌گن Print Debugging — رایج‌ترین روش دیباگ برای مبتدی‌ها و برای embedded (چون اونجا معمولا ابزار پیچیده دیباگ در دسترس نیست)
