تا اینجا فقط با عدد کار کرده‌ای. ولی دستگاه‌ها با آدم‌ها حرف می‌زنند: «دما ۲۳٫۵ درجه»، «خطا: سنسور جواب نداد»، یا فرمانی که از کامپیوتر می‌رسد: «LED ON». متنِ C اسمش «رشته» است و ظاهر ساده‌ای دارد، اما بیشترین باگ و حفرهٔ امنیتی تاریخ برنامه‌نویسی از همین‌جا آمده است. در این درس یاد می‌گیری رشته در حافظه چه شکلی دارد، چطور امن با آن کار کنی، printf را کامل بشناسی و متن را بدون خطر به عدد تبدیل کنی.

ایده اصلی: قطاری از حرف‌ها

کامپیوتر فقط عدد می‌فهمد. پس متن را هم باید به عدد تبدیل کند: هر حرف یک عدد کوچک است. حالا فرض کن می‌خواهی کلمهٔ «Hi» را نگه داری. دو حرف داری، پس دو خانهٔ پشت‌سرهم در حافظه (آرایه‌ای که در درس ۲.۷ دیدی). اما یک مشکل هست: کامپیوتر از کجا بفهمد کلمه کجا تمام می‌شود؟ خانه‌های بعدی هم مقدار دارند، شاید بقایای یک متن قدیمی.

مثال از زندگی روزمره

یک قطار باری را تصور کن. هر واگن یک حرف را حمل می‌کند. ناظر ایستگاه فقط یک واگن پس از دیگری را می‌بیند و نمی‌داند قطار چند واگن دارد. برای همین آخرین واگن را پرچم قرمز می‌زنند: «قطار اینجا تمام می‌شود». ناظر تا پرچم قرمز را نبیند، واگن بعدی را هم می‌خواند؛ حتی اگر واگن بعدی مالِ قطار دیگری باشد!

در C همین کار را کرده‌اند. رشته یعنی آرایه‌ای از char که با یک خانهٔ حاوی عدد صفر تمام می‌شود. این صفر را «پایانگر» می‌گوییم و با '\0' می‌نویسیم. بدون آن، هیچ تابعی نمی‌داند رشته کجا تمام می‌شود.

برای این‌که این تعریف رسمی در ذهنت بماند: رشتهٔ C = چند char پشت‌سرهم + یک پایانگر '\0'. این خانهٔ صفر «حرف» نیست؛ فقط علامت پایان است.

حرف هم یک عدد است

نوع char یک بایت است (درس ۲.۲) و یک عدد کوچک نگه می‌دارد. وقتی آن را با %c چاپ کنی، حرفِ همان عدد را می‌بینی؛ با %d خودِ عدد را. جدول قرارداد عددی حرف‌ها را ASCII می‌گویند. کل جدول را لازم نیست حفظ کنی؛ فقط این چند مورد را بشناس:

#include <stdio.h>

int main(void)
{
    char letter = 'A';      // تک‌کوتیشن = یک حرف
    char digit = '7';       // این حرف «۷» است، نه عدد هفت!

    printf("letter as char   : %c\n", letter);
    printf("letter as number : %d\n", letter);
    printf("digit as char    : %c\n", digit);
    printf("digit as number  : %d\n", digit);
    printf("digit value      : %d\n", digit - '0');
    printf("next letter      : %c\n", letter + 1);
    return 0;
}
  1. کتابخانهٔ ورودی/خروجی. برای printf.
  2. تابع main. نقطهٔ شروع برنامه.
  3. یک حرف. 'A' با تک‌کوتیشن یعنی «کد ASCII حرف A» که ۶۵ است. متغیر letter فقط همان عدد ۶۵ را نگه می‌دارد. C برای حرف نوع جدا ندارد؛ char همان عدد کوچک است. فقط نحوهٔ نمایش (%c یا %d) تعیین می‌کند حرف ببینی یا عدد.
  4. رقم ۷ به‌عنوان حرف. '7' عدد هفت نیست؛ حرفی است که شکلش ۷ است و کدش ۵۵ است. صفحه‌کلید به برنامه حرف می‌فرستد، نه عدد. وقتی کاربر «۷» را می‌زند، برنامه ۵۵ می‌بیند.
  5. یک متغیر، دو نمایش. %c حرف را چاپ می‌کند، %d عدد را.
  6. همین آزمایش برای رقم. ۷ به‌شکل حرف، ۵۵ به‌شکل عدد.
  7. ترفند تبدیل رقم به مقدار. '7' - '0' یعنی ۵۵ − ۴۸ = ۷. چون رقم‌های '0' تا '9' در جدول پشت‌سرهم‌اند، فاصلهٔ هر رقم تا '0' برابر خودِ رقم است.
  8. حرف بعدی. ۶۵ + ۱ = ۶۶ که کد 'B' است. با %c حرف را می‌بینی.
  9. return 0. پایان موفق.

'A' یک حرف است (یک بایت، عدد ۶۵). "A" یک رشته است: دو بایت، یعنی 'A' و بعد '\0'. اگر جای هم بنویسیشان، یا خطای کامپایل می‌گیری یا رفتار عجیب. قاعده: یک حرف ← ' ' و متن ← " ".

اولین رشته‌ها

ساده‌ترین راه ساختن رشته این است که آرایهٔ char را با یک متن مقدار بدهی. کامپایلر خودش حرف‌ها را می‌چیند و '\0' را هم آخرش اضافه می‌کند. آرایه‌ای که برای نگه‌داشتن متن (و شاید تغییر متن) می‌سازیم، اغلب بافر (buffer) نام دارد: جای موقت برای داده. این کد را اجرا کن:

#include <stdio.h>
#include <string.h>

int main(void)
{
    char name[] = "Ali";        // کامپایلر خودش '\0' را اضافه می‌کند
    char box[8] = "Hi";         // جا برای ۸ بایت؛ بقیه صفر می‌شود

    printf("name = %s\n", name);
    printf("sizeof(name) = %zu, strlen(name) = %zu\n", sizeof(name), strlen(name));
    printf("sizeof(box)  = %zu, strlen(box)  = %zu\n", sizeof(box), strlen(box));

    for (int i = 0; i < 8; i++) {
        printf("box[%d] = %d\n", i, box[i]);
    }
    return 0;
}
  1. دو هدر. stdio.h برای printf و string.h برای strlen و بقیهٔ توابع رشته.
  2. تابع main.
  3. اندازه را کامپایلر می‌شمارد. در name[] عدد داخل کروشه را ننوشته‌ایم. کامپایلر «Ali» را می‌بیند: سه حرف، به‌اضافهٔ پایانگر = ۴ خانه. اگر خودت بنویسی name[3]، جایی برای '\0' نمی‌ماند و رشته «بی‌پایان» می‌شود. با خالی گذاشتن کروشه از این اشتباه در امانی.
  4. آرایهٔ بزرگ‌تر از متن. ۸ خانه گرفتیم ولی فقط «Hi» گذاشتیم. C در این حالت همهٔ خانه‌های باقی‌مانده را صفر می‌کند. این قانون برای مقداردهی اولیهٔ آرایه است. پس رشته حتما پایانگر دارد و بقیه هم تمیز است.
  5. چاپ رشته با %s. printf از خانهٔ اول شروع می‌کند و حرف‌ها را چاپ می‌کند تا به '\0' برسد.
  6. sizeof در برابر strlen. sizeof اندازهٔ آرایه را می‌گوید (کل قطار، با واگن‌های خالی). strlen طول رشته را می‌گوید (تعداد حرف‌ها تا پایانگر، بدون شمردن خود پایانگر). این دو فقط وقتی برابرند که آرایه دقیقا به اندازهٔ رشته + ۱ باشد. یکی را جای دیگری به کار نبر.
  7. دیدن تک‌تک خانه‌ها. هر خانه را به‌صورت عدد چاپ می‌کنیم تا قطار واقعی را ببینی.

حالا با دست هم ببین که رشته‌ای که خودت خانه‌به‌خانه می‌سازی چه می‌شود. روی «بعدی» بزن:

strlen از کجا می‌داند؟

هیچ جادویی در کار نیست. strlen فقط خانه‌ها را یکی‌یکی می‌شمارد تا اولین صفر. خودت هم می‌توانی بنویسی:

#include <stdio.h>

// شمردن حرف‌ها تا رسیدن به '\0'
int count_chars(const char text[])
{
    int n = 0;
    while (text[n] != '\0') {
        n++;
    }
    return n;
}

int main(void)
{
    char word[] = "sensor";
    printf("%d\n", count_chars(word));
    printf("%d\n", count_chars(""));
    return 0;
}
  1. تابع شمارنده. پارامتر text[] یعنی «یک آرایهٔ char». const می‌گوید تابع نباید متن را تغییر بدهد (فقط می‌خواند). آرایه به تابع کپی نمی‌شود؛ خودِ آرایه را می‌دهی (درس ۲.۷). برای همین طول را نمی‌داند و باید بر پایانگر تکیه کند.
  2. شمارنده. از صفر شروع می‌کنیم.
  3. تا پایانگر جلو برو. تا وقتی خانهٔ n صفر نشده، شمارنده را یکی زیاد کن. اگر رشته پایانگر نداشته باشد، این حلقه از آرایه بیرون می‌زند و حافظهٔ دیگران را می‌خواند؛ تا خانه‌ای صفر پیدا کند.
  4. رشتهٔ عادی. شش حرف: «sensor».
  5. رشتهٔ خالی. "" فقط یک پایانگر دارد. خانهٔ اول صفر است، پس طول ۰.
  6. main و بازگشت.

اگر پایانگر نباشد چه می‌شود؟

هر تابعی که رشته را می‌خواند (printf("%s")، strlen، strcpy و بقیه) بدون پایانگر از انتهای آرایه رد می‌شود و بایت‌های همسایه را هم جزو متن می‌گیرد. نتیجه یکی از این‌هاست: آشغال در خروجی، عدد طول غلط، یا کرش. چون رفتارش به حافظهٔ اطراف بستگی دارد، ممکن است روی رایانهٔ تو سالم کار کند و روی میکروکنترلر خراب شود. قاعدهٔ ساده: هر آرایه‌ای که قرار است رشته شود، همیشه یک خانه بیشتر از حرف‌هایش بگیر.

متن‌های ثابت داخل کد

وقتی در کد می‌نویسی "hello"، به آن رشتهٔ ثابت (string literal) می‌گویند. کامپایلر این متن را یک‌جا در حافظه می‌گذارد. در میکروکنترلر آن جا Flash است (درس ۲.۱: حافظهٔ ماندگار و فقط‌خواندنی‌شونده)، نه RAM. این خبر خوبی است: متن‌های طولانی RAM ارزشمندت را اشغال نمی‌کنند. ولی یک قید دارد: نباید تغییرشان بدهی.

راه اول (const char *msg) را فعلا مثل یک الگوی آماده ببین: علامت * یعنی «نشانیِ اولین حرف»؛ msg اسمی برای شروع همان متن ثابت است. معنی دقیقش را در درس ۳.۲ (اشاره‌گر) می‌فهمی. حالا ببین اگر متن ثابت را بخواهی عوض کنی چه می‌شود:

#include <stdio.h>

int main(void)
{
    const char *msg = "hello";   // متن ثابت در Flash
    msg[0] = 'H';                // تلاش برای تغییر متن ثابت
    printf("%s\n", msg);
    return 0;
}
  1. const char *. «متنِ ثابتِ فقط‌خواندنی». const می‌گوید: از این نشانی فقط بخوان، ننویس. متن در Flash است. Flash را برنامه در حال اجرا نمی‌تواند مثل RAM بنویسد.
  2. تلاش برای نوشتن. کامپایلر جلویت را می‌گیرد.
lit_err.c: In function 'main':
lit_err.c:6:12: error: assignment of read-only location '*msg'

این خطا لطف کامپایلر است. اگر const را برمی‌داشتی (char *msg = "hello";)، کامپایلر C ساکت می‌ماند، ولی نتیجه بدتر بود: روی PC برنامه هنگام اجرا با خطای دسترسی می‌ترکد؛ روی میکروکنترلر یا نوشتن بی‌اثر می‌ماند یا به HardFault می‌رسد (درس ۶.۱). برای همین قاعدهٔ حرفه‌ای‌ها: اشاره به متن ثابت را همیشه با const بنویس. اگر متنی قرار است تغییر کند، یک کپی در آرایه بگیر:

#include <stdio.h>

int main(void)
{
    char copy[] = "hello";      // آرایه: یک کپی در RAM
    copy[0] = 'H';              // تغییر کپی مجاز است
    printf("%s\n", copy);
    return 0;
}
  1. آرایه با مقدار اولیه. این‌بار خود آرایه ۶ خانه در RAM می‌گیرد و «hello» را در آن کپی می‌کند. کپی در RAM هزینه دارد (۶ بایت RAM)، ولی آزادی تغییر می‌دهد.
  2. تغییر مجاز. اولین خانه از 'h' به 'H' عوض می‌شود.
  3. چاپ. متن کپی را می‌بینیم، نه متن اصلی را.
$ gcc -std=c11 -Wall -Wextra -o lit_ok lit_ok.c
$ ./lit_ok
Hello
آرایه را نمی‌شود با = پر کرد

مقدار دادن با = فقط هنگام ساختن آرایه مجاز است (char s[8] = "hi";). بعدا نمی‌توانی بنویسی s = "hi";؛ آرایه را یکجا نمی‌شود جایگزین کرد. کامپایلر می‌گوید:

array_assign.c:6:9: error: assignment to expression with array type

برای پر کردن بعدی از strcpy/snprintf (پایین‌تر) استفاده کن. همین دلیل باعث می‌شود مقایسهٔ رشته‌ها هم با == ممکن نباشد؛ در بخش بعد می‌بینی.

جعبه‌ابزار string.h

چون آرایه را نمی‌شود با = کپی یا با == مقایسه کرد، فایل string.h تابع‌های آماده دارد. هر کدام از خانه‌ها شروع می‌کند و کارش را تا پایانگر ادامه می‌دهد (یا تا تعداد مشخص). در جدول، dst مقصد است و src منبع. علامت * را فعلا «آدرس شروع آرایه» بخوان.

#include <string.h>

int main(void)
{
    char a[] = "apple";
    char b[] = "banana";
    char line[16] = "LED";           // جا برای ۱۵ حرف + '\0'

    // مقایسه: فقط علامت نتیجه مهم است
    printf("apple before banana: %s\n", strcmp(a, b) < 0 ? "yes" : "no");
    printf("apple vs apple     : %d\n", strcmp(a, "apple"));
    printf("apple vs app (3)   : %d\n", strncmp(a, "app", 3));

    // چسباندن
    strcat(line, " ");
    strcat(line, "ON");
    printf("line = \"%s\" (len %zu)\n", line, strlen(line));

    // جستجو
    printf("has letter 'O'     : %s\n", strchr(line, 'O') != NULL ? "yes" : "no");
    printf("has \"OFF\"          : %s\n", strstr(line, "OFF") != NULL ? "yes" : "no");

    // بایت‌های خام (بدون توجه به '\0')
    unsigned char raw[6];
    memset(raw, 0xAA, sizeof(raw));   // همه ۶ بایت را 0xAA کن
    memcpy(raw, "AB", 2);             // دو بایت اول را کپی کن
    for (size_t i = 0; i < sizeof(raw); i++) {
        printf("%02X ", raw[i]);
    }
    printf("\n");
    return 0;
}
  1. هدرها. string.h همهٔ توابع بالا را می‌آورد.
  2. سه آرایه. line ۱۶ خانه دارد و فعلا فقط «LED» در آن است؛ جای خالی برای ادامه. قبل از چسباندن، همیشه بشمار جای کافی هست. اینجا «LED ON» ۶ حرف + پایانگر است؛ ۱۶ خانه بسیار کافی است.
  3. strcmp با علامت. «apple» در ترتیب الفبا قبل از «banana» است، پس نتیجه منفی است و < 0 درست درمی‌آید.
  4. برابری. دو رشتهٔ یکسان نتیجهٔ 0 می‌دهند. از همین‌جا: strcmp(a, b) == 0 یعنی «برابرند». صفر در C «نادرست» است، پس if (strcmp(a,b)) یعنی «برابر نیستند»! خیلی‌ها این را اشتباه می‌فهمند؛ همیشه با == 0 بنویس.
  5. strncmp. فقط سه حرف اول «apple» و «app» را مقایسه می‌کنیم؛ برابرند.
  6. چسباندن. «LED» + فاصله + «ON» = «LED ON».
  7. چاپ با گیومه. \" داخل رشته یعنی خودِ علامت گیومه را چاپ کن.
  8. جستجو. حرف 'O' هست؛ زیررشتهٔ «OFF» نیست. نتیجهٔ NULL یعنی پیدا نشد.
  9. بایت خام. ابتدا شش بایت را 0xAA می‌کنیم، بعد دو بایت اول را با «AB» عوض می‌کنیم. memcpy پایانگر نمی‌گذارد. اینجا اصلا رشته نداریم؛ فقط یک تکه بایت.
  10. چاپ هگز. %02X یعنی هگز بزرگ با حداقل دو رقم (صفر جلویش). ۴۱ و ۴۲ کد A و B هستند.
  11. main.

تلهٔ strncpy

اسم strncpy «کپی امن» را در ذهن می‌آورد ولی این‌طور نیست. کدش برای متن‌های قدیمی با طول ثابت ساخته شده. ببین چه می‌کند وقتی متن دقیقا به اندازهٔ بافر باشد:

#include <stdio.h>
#include <string.h>

int main(void)
{
    char dst[4];
    memset(dst, '#', sizeof(dst));      // همه را '#' کن تا ببینیم چه می‌شود

    strncpy(dst, "abcd", sizeof(dst));  // دقیقا ۴ حرف؛ جایی برای '\0' نمانده
    for (size_t i = 0; i < sizeof(dst); i++) {
        printf("%02X ", (unsigned char)dst[i]);
    }
    printf("\n");

    // روش امن: یک خانه کمتر کپی کن و خودت پایان را بگذار
    strncpy(dst, "abcd", sizeof(dst) - 1);
    dst[sizeof(dst) - 1] = '\0';
    printf("safe copy: %s\n", dst);
    return 0;
}
  1. آماده‌سازی. ۴ خانه را با '#' پر می‌کنیم تا هر تغییری دیده شود.
  2. کپی ۴ حرفی در بافر ۴ خانه‌ای. هر چهار حرف کپی می‌شوند و جایی برای '\0' نمی‌ماند. strncpy فقط تا n حرف کپی می‌کند. وقتی منبع به n برسد، پایانگر نمی‌گذارد. کامپایلر هم می‌فهمد و هشدار می‌دهد (پایین‌تر).
  3. دیدن بایت‌ها. چهار عدد هگز چاپ می‌شود: هیچ صفری آخرش نیست.
  4. راه درست. یک خانه کمتر کپی می‌کنیم (sizeof - 1) و آخرین خانه را خودمان '\0' می‌کنیم. این الگو همیشه تضمین می‌کند بافر پایانگر دارد، حتی اگر متن ورودی خیلی بلند باشد؛ فقط متن بریده می‌شود.
  5. چاپ امن. فقط «abc» چاپ می‌شود.

سرریز بافر: بزرگ‌ترین خطر رشته‌ها

سرریز بافر وقتی رخ می‌دهد که متنی بلندتر از آرایه‌اش را در آن بریزی. C جلوی نوشتن را نمی‌گیرد؛ حرف‌های اضافه روی هر چه بعد از آرایه است می‌نشینند. فرض کن یک آرایهٔ ۸ خانه‌ای برای اسم و بعدش در حافظه یک متغیر flag باشد:

در PC ممکن است سیستم‌عامل جلوی بدترین خرابی را بگیرد. روی میکروکنترلر هیچ سیستم‌عاملی نگهبان نیست: متن اضافه روی متغیر دیگری، روی وضعیت موتور یا حتی روی آدرس برگشت یک تابع می‌نشیند. علاوه بر باگ، این یکی از رایج‌ترین راه‌های نفوذ به دستگاه‌های متصل به شبکه است. سه قاعدهٔ ساده جلویش را می‌گیرد:

  1. اندازه را همیشه همراه بافر بدان. با sizeof(buf) اندازه را از خود آرایه بگیر، نه از عدد نوشته‌شده در جای دیگر.
  2. به‌جای strcpy/strcat/sprintf، نسخه‌های اندازه‌دار بخواه: snprintf (پایین‌تر) یا الگوی امن strncpy + پایانگر دستی. یا پیش از strcpy بررسی کن strlen(src) < sizeof(dst).
  3. ورودی بیرونی را باور نکن. هر متنی که از UART، شبکه یا کاربر می‌رسد ممکن است هر طولی داشته باشد. بلندی‌اش را پیش از کپی چک کن.

بخشنوشتناثر

دقت (precision).2 با %fتعداد رقم‌های اعشار (گرد می‌شود)

#include <stdio.h>

int main(void)
{
    int v = 42;
    double t = 3.14159;

    printf("[%d]\n", v);
    printf("[%6d]\n", v);       // عرض ۶، راست‌چین
    printf("[%-6d]\n", v);      // چپ‌چین
    printf("[%06d]\n", v);      // پر کردن با صفر
    printf("[%+d]\n", v);       // علامت مثبت هم بیاید
    printf("[%.2f]\n", t);      // دو رقم اعشار
    printf("[%8.3f]\n", t);     // عرض ۸ و سه رقم اعشار
    printf("[%.3s]\n", "microcontroller");   // فقط ۳ حرف اول
    printf("[%-8s]\n", "led");
    printf("[%*d]\n", 5, v);    // عرض از آرگومان می‌آید
    printf("[%04X]\n", 0xEF);
    return 0;
}
  1. دو مقدار. یک عدد صحیح و یک اعشاری.
  2. بدون قید. فقط خودِ عدد. کروشه‌ها را برای دیدن مرز چاپ گذاشته‌ایم.
  3. عرض ۶. ۴ فاصله جلوی «42» می‌آید (راست‌چین).
  4. چپ‌چین. فاصله‌ها بعد از عدد می‌روند.
  5. صفر پر کن. 000042؛ برای چاپ کد‌ها و ساعت‌ها (مثل ۰۵:۰۷) مفید است.
  6. علامت مثبت. +42.
  7. دقت اعشار. %.2f عدد ۳٫۱۴۱۵۹ را به ۳٫۱۴ گرد می‌کند. در %8.3f کل خروجی ۸ خانه است که سه‌تایش اعشار است.
  8. دقت با رشته. فقط سه حرف اول «microcontroller» چاپ می‌شود. این قالب وقتی رشته شاید پایانگر نداشته باشد یا خیلی بلند باشد برای برش امن بودن به کار می‌آید.
  9. رشتهٔ چپ‌چین. برای ستون‌بندی جدول‌های متنی.
  10. عرض از آرگومان. * یعنی «عرض را از آرگومان بعدی بگیر»؛ اینجا ۵.
  11. هگز با صفر پر. چهار رقم هگز بزرگ: 00EF.

اندازهٔ آرگومان: length

حرف‌های l، ll، z و ... قبل از نوع می‌گویند آرگومانت از کدام نوع پهن‌تر یا باریک‌تر است. printf نوع آرگومان‌ها را نمی‌داند؛ فقط به قالبی که نوشتی اعتماد می‌کند و همان‌قدر بایت از آرگومان‌ها برمی‌دارد. اگر قالب با نوع نخواند، خروجی بی‌معنی می‌شود.

lengthیعنیمثال
(هیچ)int / unsigned / double%d ، %u ، %f
hhمقدار را مثل char ببین (فقط بایت پایین)%hhu
hمثل short%hd
llong / unsigned long%ld ، %lu ، %lx
lllong long (۶۴ بیت)%lld ، %llu
zsize_t (نتیجهٔ sizeof و strlen)%zu
j ، tintmax_t ، ptrdiff_t%jd ، %td (کم‌کاربرد)
Llong double%Lf

مشکل بزرگ: uint32_t در دو دنیا دو نوع متفاوت است. کامپایلر این محیط را پرسیدیم:

نوعروی PC (x86-64، gcc)روی STM32 (arm-none-eabi-gcc)
uint32_tunsigned intunsigned long
size_tunsigned longunsigned int

هر دو ۳۲ بیت‌اند ولی نام‌شان فرق دارد، پس قالبی که در PC درست است روی STM32 هشدار می‌دهد و برعکس. راه حل رسمی، ماکروهای inttypes.h است: PRIu32، PRId32، PRIx32 و ... . هر کدام یک تکه رشته‌اند که روی هر پلتفرم قالب درست را می‌سازند و به رشتهٔ قالب می‌چسبند. این ماکروها بیرون از گیومه نوشته می‌شوند:

#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void)
{
    uint8_t  small = 200;
    uint32_t big = 4000000000U;
    long long huge = 9000000000LL;
    size_t bytes = sizeof(big);

    printf("uint8_t   : %u\n", small);
    printf("uint32_t  : %" PRIu32 "\n", big);
    printf("hex32     : 0x%08" PRIX32 "\n", (uint32_t)0xBEEF);
    printf("long long : %lld\n", huge);
    printf("size_t    : %zu\n", bytes);
    printf("as uchar  : %hhu\n", 300);
    return 0;
}
  1. دو هدر. stdint.h برای uint32_t و inttypes.h برای ماکروهای PRI....
  2. چند نوع. از ۸ بیتی تا ۶۴ بیتی و size_t.
  3. uint8_t. هر مقدار کوچک‌تر از int پیش از رسیدن به printf خودکار به int بزرگ می‌شود؛ پس %u کافی است. قاعدهٔ ارتقا (promotion) در C: آرگومان‌های کوچک‌تر از int را به int تبدیل می‌کند. برای همین برای uint8_t و uint16_t لازم نیست ماکرو بنویسی.
  4. PRIu32. قالب به سه تکه جدا می‌شود: "uint32_t : %" ، ماکرو، "\n". کامپایلر آن‌ها را به هم می‌چسباند. روی این PC PRIu32 برابر "u" است و روی STM32 برابر "lu".
  5. هگز ۳۲ بیتی. 0x%08 + PRIX32: هشت رقم هگز بزرگ با صفر پر می‌شود. هشت رقم هگز = ۳۲ بیت؛ برای چاپ رجیستر و آدرس عالی است.
  6. long long. ll برای ۶۴ بیت.
  7. size_t. برای نتیجهٔ sizeof و strlen از %zu استفاده کن.
  8. hh. عدد ۳۰۰ (که در یک بایت جا نمی‌شود) با %hhu فقط بایت پایینش را نشان می‌دهد: ۳۰۰ − ۲۵۶ = ۴۴.

  2. قالب اشتباه. %d فقط ۳۲ بیت برمی‌دارد، ولی ما ۶۴ بیت فرستادیم. printf فقط به رشتهٔ قالب اعتماد می‌کند. کامپایلر gcc ولی قالب را می‌خواند و با نوع‌ها می‌سنجد. این دقیقا دلیل -Wall است.
fmt_err.c: In function 'main':
fmt_err.c:6:14: error: format '%d' expects argument of type 'int', but argument 2 has type 'long long int' [-Werror=format=]

ما هشدار را با -Werror=format به خطا تبدیل کردیم. بدون آن فقط هشدار می‌گیری و برنامه ساخته می‌شود. روی همین PC چاپ می‌شد 705032704، یعنی ۳۲ بیت پایین عدد. روی یک پلتفرم دیگر ممکن بود چیز دیگری بشود، چون رفتار رسما تعریف‌نشده است. هشدار «format» را هرگز نادیده نگیر.

ساختن متن: snprintf

گاهی متن را نمی‌خواهی چاپ کنی؛ می‌خواهی بسازی و در آرایه بگذاری (مثلاً برای فرستادن روی UART). خانوادهٔ printf چند عضو دارد:

تابعمقصدایمنی
printf(fmt, ...)خروجی استاندارد (در PC صفحه؛ در MCU هرجا تنظیم کنی)بی‌خطر
sprintf(buf, fmt, ...)آرایهخطرناک: اندازهٔ بافر را نمی‌داند. هرگز استفاده نکن
snprintf(buf, size, fmt, ...)آرایهامن: بیشتر از size-1 حرف نمی‌نویسد و همیشه پایانگر می‌گذارد

نتیجهٔ snprintf یک عدد است: طولی که متن کامل نیاز داشت (بدون پایانگر)، حتی اگر بریده شده باشد. اگر آن عدد بزرگ‌تر یا مساوی اندازهٔ بافر باشد، یعنی متن بریده شده است. این ویژگی امکان می‌دهد ببینی جا کم بود یا نه:

#include <stdio.h>

// می‌سازد: "name=value" و طول لازم را برمی‌گرداند
static int make_text(char out[], size_t size, const char name[], int value)
{
    return snprintf(out, size, "%s=%d", name, value);
}

int main(void)
{
    char buf[12];

    int need = make_text(buf, sizeof(buf), "temp", 235);
    printf("text = \"%s\", needed = %d, buffer = %zu\n", buf, need, sizeof(buf));

    need = make_text(buf, sizeof(buf), "temperature", 123456);
    printf("text = \"%s\", needed = %d, buffer = %zu\n", buf, need, sizeof(buf));

    if (need >= (int)sizeof(buf)) {
        int lost = need - ((int)sizeof(buf) - 1);
        printf("cut off! %d characters were lost\n", lost);
    }
    return 0;
}
  1. تابع کمکی. «نام=مقدار» را در out می‌سازد و خروجی snprintf را برمی‌گرداند. اندازه را به‌عنوان پارامتر می‌گیرد (size)، چون داخل تابع sizeof(out) اندازهٔ آرایه را نمی‌دهد (درس ۲.۷).
  2. بافر ۱۲ خانه‌ای. جای ۱۱ حرف + پایانگر.
  3. متن کوتاه. «temp=235» هشت حرف است و جا می‌شود. برگشتی ۸ است.
  4. متن بلند. متن کامل ۱۸ حرف می‌شد. فقط ۱۱ حرف اول (به‌علاوهٔ پایانگر) در بافر می‌نشیند؛ ولی برگشتی همچنان ۱۸ است.
  5. تشخیص برش. اگر need >= size، یعنی بریده شده. تعداد حرف‌های ازدست‌رفته = need منهای ۱۱ حرفی که جا شد. این شرط را حتماً بنویس: در ارتباط سریال، پیام نصفه‌شده می‌تواند دستگاه مقابل را گیج کند.
  6. main.

تبدیل امن متن به عدد

کاربر یا دستگاه دیگر برایت متن می‌فرستد: «250». ولی کامپیوتر برای محاسبه عدد می‌خواهد نه متن. کار تبدیل متن به ساختار قابل‌محاسبه را پارس (parse) می‌گویند. سه تابع اول که به ذهن می‌رسد:

  • atoi("123"): ساده و بد. اگر متن غلط باشد ("abc") هم 0 برمی‌گرداند؛ نمی‌توانی بفهمی خطا بود یا واقعا «0» فرستاده شده بود. سرریز را هم نمی‌گوید.
  • sscanf: قدرتمند ولی پیچیده و پرهزینه‌تر در Flash؛ در MCU معمولا دور است.
  • strtol: انتخاب درست. هم عدد می‌دهد، هم می‌گوید تا کجا خوانده و هم می‌گوید سرریز شد یا نه.
مثال از زندگی روزمره

فرض کن مسئول ثبت‌نام یک کلاس هستی و کاربرگه‌ای پر شده: «سن: ۱۲abc». atoi کارمندی است که هر چه بفهمد عدد می‌نویسد و اصلا نمی‌گوید کاربرگه خراب بود. strtol کارمند دقیقی است که می‌گوید: «تا اینجا را عدد خواندم؛ بقیهٔ نوشته را نتوانستم بخوانم. کجا ایستادم؟ اینجا.» تو از همین «کجا ایستادم» برای رد کردن کاربرگه استفاده می‌کنی.

ما یک تابع parse_int می‌سازیم که «موفق» یا «رد» می‌گوید و عدد را در جایی که تو نشان بدهی می‌نویسد. این تابع دو چیز دارد که هنوز ندیده‌ای: علامت * و &. آن‌ها را مثل یک الگوی آماده کپی کن؛ معنی دقیقشان در درس ۳.۲ می‌آید. فعلا همین‌قدر بدان: int *out یعنی «نشانی یک جعبهٔ int که تابع اجازه دارد در آن بنویسد»، و &n یعنی «نشانی جعبهٔ n». با این کار تابع می‌تواند هم «موفق/ناموفق» را برگرداند، هم عدد را تحویل بدهد.

#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <limits.h>
#include <stdbool.h>

// رشته را به int تبدیل می‌کند. true یعنی موفق؛ عدد در *out نوشته می‌شود.
bool parse_int(const char text[], int *out)
{
    char *end;
    long value;

    if (text[0] == '\0') {
        return false;               // رشتهٔ خالی
    }
    errno = 0;
    value = strtol(text, &end, 10);
    if (end == text) {
        return false;               // هیچ رقمی پیدا نشد
    }
    if (*end != '\0') {
        return false;               // بعد از عدد، آشغال مانده
    }
    if (errno == ERANGE || value > INT_MAX || value < INT_MIN) {
        return false;               // عدد از محدوده بیرون است
    }
    *out = (int)value;
    return true;
}

int main(void)
{
    const char tests[][24] = {
        "42", "-17", "+8", "12abc", "", "abc", "3.5",
        "2147483648", "99999999999999999999", " 5"
    };
    int count = (int)(sizeof(tests) / sizeof(tests[0]));

    for (int i = 0; i < count; i++) {
        int n = 0;
        if (parse_int(tests[i], &n)) {
            printf("\"%s\" -> OK, %d\n", tests[i], n);
        } else {
            printf("\"%s\" -> rejected\n", tests[i]);
        }
    }
    printf("atoi(\"abc\") = %d, atoi(\"0\") = %d\n", atoi("abc"), atoi("0"));
    return 0;
}
  1. هدرها. stdlib.h برای strtol و atoi؛ errno.h برای متغیر خطا errno و ERANGE؛ limits.h برای INT_MAX و INT_MIN؛ stdbool.h برای bool.
  2. امضای تابع. نتیجه bool است. ورودی رشته و «جعبهٔ خروجی» است. نتیجه را در خروجی تابع نمی‌گذاریم چون هر int (حتی ۰ و منفی) یک عدد معتبر است؛ جایی برای «خطا» باقی نمی‌ماند.
  3. دو متغیر کمکی. end بعد از خواندن نشان می‌دهد strtol تا کدام حرف رسید. value عدد long می‌ماند.
  4. رشتهٔ خالی. اگر خانهٔ اول پایانگر باشد، عددی وجود ندارد؛ رد.
  5. errno را صفر کن. strtol فقط در صورت خطا errno را می‌نویسد؛ اگر از قبل عدد کهنه‌ای در آن مانده باشد، به‌اشتباه فکر می‌کنیم خطا شده است.
  6. خواندن. سه ورودی: متن، جایی برای گزارش نقطهٔ توقف (&end)، و مبنای عدد (۱۰ یعنی ده‌دهی).
  7. هیچ رقمی نبود. اگر توقف در همان حرف اول بود (end == text)، مثل «abc» یعنی حتی یک رقم هم خوانده نشد.
  8. آشغال بعد از عدد. اگر جایی که ایستاده‌ایم پایانگر نباشد، متن تمیز نیست (مثل «12abc» یا «3.5»). اگر این چک را نگذاری، «12abc» بی‌سروصدا ۱۲ می‌شود و خطای کاربر پنهان می‌ماند.
  9. محدوده. اگر عدد از long بیرون بود، errno برابر ERANGE می‌شود. اگر در long جا شد ولی در int نه (روی PC که long ۶۴ بیت است) هم رد می‌کنیم.
  10. تحویل. عدد را در جعبهٔ خروجی می‌نویسیم و «موفق» برمی‌گردانیم.
  11. آرایهٔ دوبعدی از رشته‌ها. ده متن آزمایشی؛ هر کدام حداکثر ۲۴ خانه. (آرایهٔ دوبعدی در درس ۲.۷ بود؛ تعداد را با تقسیم sizeof ها می‌شماریم.)
  12. امتحان همه. هر متن را پارس می‌کنیم و نتیجه را چاپ می‌کنیم.
  13. مقایسه با atoi. «abc» و «0» هر دو ۰ می‌شوند؛ از رویشان نمی‌شود فهمید کدام درست بود.
  14. main.

ctype.h: سؤال دربارهٔ حرف

تابع‌های ctype.h دربارهٔ یک حرف سؤال می‌کنند یا آن را تبدیل می‌کنند:

تابعجواب می‌دهد
isdigit(c)رقم ۰ تا ۹ است؟
isalpha(c)حرف الفبای انگلیسی است؟
isalnum(c)حرف یا رقم است؟
isspace(c)فاصله، تب یا خط جدید (\n \r \t) است؟
isupper(c) ، islower(c)بزرگ / کوچک است؟
toupper(c) ، tolower(c)معادل بزرگ / کوچک را برمی‌گرداند

پاسخ‌های «آره/نه» عدد صفر (نه) یا غیرصفر (آره) هستند؛ در if همین کافی است.

#include <stdio.h>
#include <ctype.h>

int main(void)
{
    char text[] = "Room 42: led on";
    int letters = 0;
    int digits = 0;
    int spaces = 0;

    for (int i = 0; text[i] != '\0'; i++) {
        unsigned char c = (unsigned char)text[i];
        if (isalpha(c)) {
            letters++;
        } else if (isdigit(c)) {
            digits++;
        } else if (isspace(c)) {
            spaces++;
        }
        text[i] = (char)toupper(c);
    }
    printf("%s\n", text);
    printf("letters=%d digits=%d spaces=%d\n", letters, digits, spaces);
    return 0;
}
  1. هدر ctype.
  2. متن و سه شمارنده.
  3. حلقه تا پایانگر. شرط text[i] != '\0' همان الگوی strlen است.
  4. تبدیل به unsigned char. حرف را قبل از دادن به توابع ctype به unsigned char تبدیل می‌کنیم. این توابع فقط مقدار ۰ تا ۲۵۵ (یا EOF) را قبول دارند. char در بعضی پلتفرم‌ها علامت‌دار است و حرف غیر ASCII منفی می‌شود؛ آن‌وقت رفتار تابع تعریف‌نشده است.
  5. شمردن. هر حرف به یکی از سه دسته می‌رود.
  6. بزرگ کردن در جا. حرف را بزرگ می‌کنیم و در همان خانه برمی‌گردانیم. (char) نتیجهٔ int را دوباره به char برمی‌گرداند.
  7. چاپ نتیجه.

پروژهٔ کوچک: پارسر فرمان «LED ON»

وقتی به یک میکروکنترلر با UART وصل می‌شوی و می‌نویسی «LED ON»، برنامه باید متن را بخواند و تصمیم بگیرد. کارهای لازم را قدم‌به‌قدم می‌سازیم:

  1. خط را به یک بافر کپی کن (پس از چک طول، تا سرریز نشود).
  2. تمیزکاری: فاصله و \r\n انتهای خط را حذف کن؛ همهٔ حرف‌ها را بزرگ کن تا «led on» و «LED ON» یکی شوند.
  3. مقایسهٔ کل خط با strcmp برای فرمان‌های ثابت («LED ON»، «LED OFF»).
  4. مقایسهٔ پیشوند با strncmp برای فرمان‌هایی که عدد می‌گیرند («BLINK 250») و بعد پارس عدد با strtol.
  5. هر شاخه جواب بدهد: «OK ...» یا «ERR ...».
#include <stdio.h>
#include <string.h>
#include <ctype.h>
#include <stdlib.h>
#include <errno.h>
#include <stdbool.h>

#define LINE_MAX_LEN 32

static bool led_on = false;
static int  blink_ms = 500;

// حذف فاصله و \r \n از انتهای خط، و بزرگ کردن حرف‌ها
static void normalize(char line[])
{
    size_t n = strlen(line);
    while (n > 0 && isspace((unsigned char)line[n - 1])) {
        line[n - 1] = '\0';
        n--;
    }
    for (size_t i = 0; i < n; i++) {
        line[i] = (char)toupper((unsigned char)line[i]);
    }
}

static bool parse_ms(const char text[], int *out)
{
    char *end;
    errno = 0;
    long v = strtol(text, &end, 10);
    if (end == text || *end != '\0' || errno == ERANGE || v < 10 || v > 5000) {
        return false;
    }
    *out = (int)v;
    return true;
}

static void handle_line(const char raw[])
{
    char line[LINE_MAX_LEN];

    if (strlen(raw) >= sizeof(line)) {
        printf("ERR too long\n");
        return;
    }
    strcpy(line, raw);
    normalize(line);

    if (strcmp(line, "LED ON") == 0) {
        led_on = true;
        printf("OK led=on\n");
    } else if (strcmp(line, "LED OFF") == 0) {
        led_on = false;
        printf("OK led=off\n");
    } else if (strncmp(line, "BLINK ", 6) == 0) {
        int ms;
        if (parse_ms(&line[6], &ms)) {
            blink_ms = ms;
            printf("OK blink=%d ms\n", blink_ms);
        } else {
            printf("ERR bad number\n");
        }
    } else {
        printf("ERR unknown command\n");
    }
}

int main(void)
{
    const char input[][64] = {
        "led on\r\n", "LED OFF", "blink 250", "BLINK abc", "BLINK 99999",
        "dance", "this line is far too long to fit in the buffer"
    };
    int count = (int)(sizeof(input) / sizeof(input[0]));

    for (int i = 0; i < count; i++) {
        handle_line(input[i]);
    }
    printf("final: led=%d blink=%d\n", led_on, blink_ms);
    return 0;
}
  1. هدرها. همان توابعی که در این درس دیدی.
  2. نام برای عدد. #define یک نام را با یک عدد جایگزین می‌کند (ماکرو، درس ۴.۱). اینجا طول بیشینهٔ خط ۳۲ است. عدد را یک جا می‌نویسیم تا بعدا فقط همین‌جا عوضش کنیم.
  3. وضعیت دستگاه. دو متغیر سراسری: LED روشن است یا نه؛ فاصلهٔ چشمک‌زدن. static یعنی فقط داخل این فایل دیده شوند (درس ۲.۶).
  4. حذف فاصله‌های انتها. از آخر رشته شروع می‌کنیم؛ تا وقتی حرف آخر فاصله، \r یا \n است، آن را پایانگر می‌کنیم و رشته کوتاه می‌شود. ترمینال‌های سریال معمولا با Enter حرف \r یا \r\n می‌فرستند. اگر حذفش نکنی، «LED ON\r» هرگز با «LED ON» برابر نمی‌شود و فرمان کار نمی‌کند؛ باگی که ساعت‌ها وقت می‌گیرد.
  5. بزرگ کردن. همه چیز بزرگ می‌شود تا مقایسه ساده شود.
  6. پارس عدد با محدوده. همان الگوی strtol، این‌بار همه شرط‌ها در یک if و محدودهٔ مجاز ۱۰ تا ۵۰۰۰ میلی‌ثانیه. فقط «عدد بودن» کافی نیست. چشمک‌زدن با فاصلهٔ ۰ یا ۹۹۹۹۹ میلی‌ثانیه بی‌معنی است. محدودهٔ منطقی را همیشه چک کن.
  7. تابع پردازش یک خط. ورودی raw فقط‌خواندنی است (const).
  8. بافر کاری. ۳۲ خانه؛ کپی ما اینجاست و می‌شود آن را تغییر داد.
  9. چک طول. اگر خط ورودی به ۳۲ حرف یا بیشتر برسد، جایی برای پایانگر نیست؛ خطا می‌دهیم و کپی نمی‌کنیم. این همان قانون «ورودی بیرونی را باور نکن» است. شرط >= است نه >، چون پایانگر هم یک خانه می‌خواهد.
  10. کپی و تمیز کردن. حالا که مطمئنیم جا هست، strcpy امن است.
  11. فرمان اول. اگر کل خط «LED ON» باشد، وضعیت را عوض می‌کنیم و پاسخ می‌دهیم. (روی سخت‌افزار واقعی همین‌جا پایهٔ GPIO را ۱ می‌کردی.)
  12. فرمان دوم. «LED OFF».

printf در میکروکنترلر

روی PC، printf به صفحه می‌رود. ولی روی میکروکنترلر «صفحه» وجود ندارد! printf باید یک جایی متن را بفرستد. جای معمول UART است: سیمی که بایت‌ها را یکی‌یکی می‌فرستد و ST-LINK روی برد Nucleo (یا مبدل USB روی برد ESP32) آن را به USB رایانه می‌رساند. UART را کامل در درس ۵.۵ می‌سازیم؛ اینجا فقط مسیر متن را ببین:

کتابخانهٔ C همراه arm-none-eabi-gcc (که اسمش newlib است) خودش printf را دارد. آخرِ کارِ printf وقتی متن ساخته شد، بایت‌های آن را به تابعی به اسم _write می‌دهد و فرض می‌کند تو آن را نوشته‌ای. این تابع اینجا به USART2 بایت می‌فرستد (روی Nucleo-F411RE، USART2 از پایه‌های PA2/PA3 به ST-LINK وصل است). ثبات‌های زیر از دفترچهٔ RM0383 است: SR در آفست ۰ و بیت ۷ آن TXE (یعنی «ثبات ارسال خالی است»)، و DR در آفست ۴. فرض این کد این است که UART قبلا تنظیم و روشن شده است (کلاک، پایه‌ها، سرعت)؛ کار درس ۵.۵ است.

#include <stdint.h>

#define USART2_BASE  0x40004400UL
#define USART2_SR    (*(volatile uint32_t *)(USART2_BASE + 0x00UL))
#define USART2_DR    (*(volatile uint32_t *)(USART2_BASE + 0x04UL))
#define USART_SR_TXE (1UL << 7)

// newlib هر printf را در نهایت به _write می‌رساند
int _write(int fd, const char *buf, int len)
{
    (void)fd;
    for (int i = 0; i < len; i++) {
        while ((USART2_SR & USART_SR_TXE) == 0) {
            // منتظر بمان تا دیتاریجستر خالی شود
        }
        USART2_DR = (uint32_t)(unsigned char)buf[i];
    }
    return len;
}
  1. نوع‌های اندازه‌ثابت. برای uint32_t.
  2. نام برای ثبات‌ها. #define نام‌های خوانا می‌سازد: پایهٔ USART2 برابر 0x40004400 است. SR در آفست ۰ و DR در آفست ۴. (1UL << 7) یعنی بیت شمارهٔ ۷ (TXE). نوشتار *(volatile uint32_t *) یعنی «این آدرس را مثل یک جعبهٔ ۳۲ بیتی ببین که هر لحظه ممکن است سخت‌افزار عوضش کند». این‌ها ابزارهای درس‌های ۳.۱ (بیت‌ها)، ۳.۶ (volatile) و ۴.۱ (ماکرو) هستند. فعلا فقط شکل کلی را ببین.
  3. تابع _write. newlib آن را با شمارهٔ فایل، آرایهٔ بایت‌ها و تعدادشان صدا می‌زند.
  4. نادیده گرفتن fd. fd می‌گوید stdout است یا stderr؛ ما هر دو را به یک UART می‌فرستیم. (void)fd; هشدار «پارامتر بی‌استفاده» را ساکت می‌کند.
  5. حلقه روی همهٔ بایت‌ها.
  6. صبر تا آماده. تا وقتی TXE صفر است (ثبات هنوز مشغول ارسال بایت قبلی است)، همین‌جا بچرخ. اگر منتظر نمانی، بایت جدید روی بایتی که هنوز در راه است نوشته می‌شود و حرف‌ها گم می‌شوند.
  7. ارسال بایت. نوشتن در DR ارسال را شروع می‌کند.
  8. گزارش موفقیت. تعداد بایت‌های فرستاده‌شده را برمی‌گردانیم.
دو نکتهٔ عملی
  • متن printf را همیشه با \n تمام کن. کتابخانه ممکن است تا دیدن خط جدید متن را در بافر نگه دارد و تو فکر کنی برنامه هنگ کرده.
  • در CubeIDE (ST) معمولا فایلی به‌نام syscalls.c هست که _write را به تابع __io_putchar وصل می‌کند؛ کافی است آن را پر کنی. اسم و جزئیات را در مستندات همان ابزار ببین.

هزینهٔ printf و newlib-nano

printf کامل، مخصوصا با پشتیبانی اعشار، ده‌ها کیلوبایت از Flash را می‌گیرد؛ در تراشه‌ای که ۵۱۲ کیلوبایت یا کمتر دارد، این سهم بزرگی است و پشته (stack) هم بیشتر مصرف می‌کند. برای همین بسیاری از پروژه‌های STM32 با گزینهٔ --specs=nano.specs ساخته می‌شوند که نسخهٔ سبک‌تر کتابخانه (newlib-nano) را می‌آورد. نکتهٔ مهم: در نسخهٔ nano، printf("%f") به‌طور پیش‌فرض کار نمی‌کند (چیزی چاپ نمی‌شود). راه رسمی‌اش افزودن گزینهٔ لینک -u _printf_float است که بخش اعشار را با هزینهٔ Flash برمی‌گرداند. بهتر است همیشه اندازهٔ واقعی را با arm-none-eabi-size ببینی (درس ۶.۵).

در ESP-IDF شرایط فرق دارد: printf پیش‌فرض برای ESP32 اعشار را پشتیبانی می‌کند، ولی همان‌جا هم گزینه‌هایی برای کاهش حجم هست که در menuconfig پیدا می‌شود. جزئیات را در مستندات رسمی ESP-IDF ببین. برای لاگ در ESP32 معمولا ESP_LOGI را به‌جای printf ترجیح می‌دهند:

  3. app_main. نقطهٔ شروع برنامه در ESP-IDF، به‌جای main.
  4. دما به‌صورت عدد صحیح. ۲۳٫۵ را به‌صورت ۲۳۵ نگه می‌داریم (ضرب در ۱۰).
  5. ESP_LOGI. پیام سطح «اطلاعات» چاپ می‌کند؛ قالبش همان قالب printf است، به‌علاوهٔ زمان و اسم برچسب. سطح‌های دیگر: ESP_LOGW (هشدار)، ESP_LOGE (خطا) و ... سطح‌بندی به تو اجازه می‌دهد در نسخهٔ نهایی پیام‌های کم‌اهمیت را بدون تغییر کد خاموش کنی.

چاپ ۲۳٫۵ بدون float

راه حرفه‌ای‌ها: دما را به‌صورت عدد صحیحِ «دهم درجه» نگه دار (۲۳٫۵ ← ۲۳۵). برای چاپ، بخش صحیح (تقسیم بر ۱۰) و باقیمانده را جدا چاپ کن. هزینهٔ float ندارد و دقتش هم دقیقا همان است که سنسور می‌دهد. ولی یک تله دارد: علامت منفی.

#include <stdio.h>
#include <stdlib.h>

// دما به دهم درجه: 235 یعنی 23.5
static int format_temp(char out[], size_t size, int t10)
{
    int a = abs(t10);
    if (t10 < 0) {
        return snprintf(out, size, "-%d.%d", a / 10, a % 10);
    }
    return snprintf(out, size, "%d.%d", a / 10, a % 10);
}

int main(void)
{
    const int samples[] = { 235, 50, 5, 0, -5, -235, -1000 };
    char buf[12];

    for (size_t i = 0; i < sizeof(samples) / sizeof(samples[0]); i++) {
        format_temp(buf, sizeof(buf), samples[i]);
        printf("%5d -> %s C\n", samples[i], buf);
    }
    int t10 = -5;
    printf("naive: %d.%d\n", t10 / 10, abs(t10 % 10));
    return 0;
}
  1. تابع قالب‌بندی. دما به دهم درجه و بافر مقصد را می‌گیرد.
  2. قدر مطلق. abs علامت را برمی‌دارد و کار را روی عدد مثبت انجام می‌دهیم. در C تقسیم و باقیمانده برای عدد منفی، نتیجهٔ منفی می‌دهد. مثلا -5 / 10 برابر ۰ است و علامت منفی گم می‌شود.
  3. حالت منفی. خودمان یک - در ابتدا می‌گذاریم.
  4. حالت مثبت. بخش صحیح، نقطه، یک رقم اعشار.
  5. نمونه‌ها. از حالت‌های مرزی: ۰٫۵ (بخش صحیح صفر)، ۰ و منفی.
  6. چاپ. عدد خام با عرض ۵ و متن ساخته‌شده کنار هم.
  7. روش ساده‌لوحانه. برای -5 همان دو تقسیم بدون مدیریت علامت چاپ می‌کند: صفر و ۵. علامت منفی گم شده است!

جواب کامل با توضیح 
#include <stdio.h>
#include <string.h>
#include <ctype.h>

// شمردن حروف صدادار
static int count_vowels(const char text[])
{
    int n = 0;
    for (int i = 0; text[i] != '\0'; i++) {
        char c = (char)tolower((unsigned char)text[i]);
        if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') {
            n++;
        }
    }
    return n;
}

// وارونه کردن در جا: اولی با آخری، دومی با ماقبل آخر، ...
static void reverse(char text[])
{
    size_t len = strlen(text);
    for (size_t i = 0; i < len / 2; i++) {
        char tmp = text[i];
        text[i] = text[len - 1 - i];
        text[len - 1 - i] = tmp;
    }
}

int main(void)
{
    char s[10] = "cat";
    printf("sizeof=%zu strlen=%zu s[3]=%d s[9]=%d\n", sizeof(s), strlen(s), s[3], s[9]);

    char word[] = "microcontroller";
    printf("%s has %d vowels\n", word, count_vowels(word));
    reverse(word);
    printf("reversed: %s\n", word);
    return 0;
}
  1. حلقه تا پایانگر. همان الگوی این درس.
  2. کوچک‌کردن حرف. با یک tolower، «A» و «a» یکی می‌شوند. تبدیل به unsigned char برای ctype لازم است.
  3. پنج حرف صدادار. اگر یکی بود شمارنده زیاد می‌شود.
  4. طول یک بار. strlen را یک بار حساب می‌کنیم، نه در هر دور حلقه. strlen هر بار کل رشته را می‌شمارد؛ در شرط حلقه یعنی کار اضافه.
  5. تعویض جفت‌ها. تا len / 2. اگر تا آخر بروی، هر جفت دو بار عوض می‌شود و رشته به حالت اول برمی‌گردد! پایانگر جایش را تغییر نمی‌دهد؛ فقط حرف‌های واقعی جابه‌جا می‌شوند.
  6. الف. چهار مقدار پرسش را چاپ می‌کند.
  7. استفاده. شمارش، وارونه‌سازی و چاپ.

جواب کامل با توضیح 
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <string.h>

// "T=23.5C\r\n" را در out می‌سازد؛ اگر جا کم بود false برمی‌گرداند
static bool format_reading(char out[], size_t size, int t10)
{
    int a = abs(t10);
    const int need = snprintf(out, size, "T=%s%d.%dC\r\n",
                              (t10 < 0) ? "-" : "", a / 10, a % 10);
    return need >= 0 && (size_t)need < size;
}

int main(void)
{
    char big[16];
    char small[10];

    if (format_reading(big, sizeof(big), -235)) {
        printf("big   : ok\n");
    }
    printf("small : %s\n", format_reading(small, sizeof(small), -235) ? "ok" : "TRUNCATED");
    printf("small : %s\n", format_reading(small, sizeof(small), 7) ? "ok" : "TRUNCATED");
    return 0;
}
  1. امضا. بافر، اندازه و دما؛ خروجی bool که می‌گوید جا شد یا نه.
  2. قدر مطلق. بخش صحیح و اعشار را روی عدد مثبت می‌گیریم.
  3. ساختن متن. %s یا «-» می‌گذارد یا «» (رشتهٔ خالی). \r\n در انتهای قالب. یک snprintf برای همهٔ حالت‌ها بهتر از دو قالب جدا است؛ کمتر جای اشتباه دارد.
  4. تشخیص برش. جا شد اگر طول لازم منفی نباشد (خطای قالب) و کوچک‌تر از size باشد.
  5. دو بافر. ۱۶ و ۱۰ خانه.
  6. امتحان. بافر بزرگ جا دارد؛ بافر کوچک برای -235 کم است و برای 7 کافی.
$ ./ex3

حرف مربی

رشته‌ها در C ظاهری ساده دارند ولی سه جا مبتدی‌ها بیش از همه گیر می‌کنند. اول پایانگر: باور نمی‌کنند یک بایت صفر مخفی همه چیز را نگه داشته است، تا وقتی آشغال روی صفحه می‌بینند. دوم مقایسه با ==: در زبان‌های دیگر کار می‌کند، در C نه. سوم سرریز بافر: چون معمولا اولین بار «کار می‌کند» و بعد هفته‌ها بعد خراب می‌شود. اگر امروز فقط یک عادت با خودت ببری: هر بافری را همراه اندازه‌اش (sizeof) ببین و هر ورودی بیرونی را قبل از کپی، از نظر طول بسنج. و -Wall -Wextra را همیشه روشن نگه دار؛ در این درس بارها دیدی چطور کامپایلر جلوی همین اشتباه‌ها را گرفت.

خلاصه یک‌دقیقه‌ای

  • رشته = آرایهٔ char که با '\0' تمام می‌شود. sizeof کل آرایه، strlen حرف‌ها تا پایانگر.
  • 'A' یک حرف (عدد ۶۵)، "A" رشته با دو بایت است. رقم به عدد: c - '0'.
  • متن ثابت در Flash است: با const char * بخوان؛ برای تغییر، در آرایه کپی کن. آرایه را با = پر نمی‌کنیم.
  • مقایسه: strcmp(a, b) == 0. کپی امن: snprintf یا strncpy + پایانگر دستی. strcpy/sprintf فقط وقتی طول از قبل بررسی شده.
  • قالب printf: %[پرچم][عرض][.دقت][length]نوع. با نوع بخوان: %zu ، %lld ، PRIu32. هشدار format را جدی بگیر.
  • snprintf «طول لازم» را برمی‌گرداند؛ اگر ≥ اندازهٔ بافر، متن بریده شده.
  • متن به عدد: strtol + چک end == text ، *end != '\0' ، ERANGE و محدودهٔ منطقی. atoi نه.
  • روی MCU: printf با _write به UART می‌رود، در nano اعشار ندارد؛ دما را به‌صورت عدد صحیح ضرب‌در‌۱۰ نگه دار و علامت را جدا مدیریت کن. در ESP32 از ESP_LOGI استفاده کن.
