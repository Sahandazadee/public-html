تقریبا هر دستگاه واقعی «حالت» دارد: چراغ راهنما سبز است یا قرمز، ماشین لباس‌شویی در حال شست‌وشو است یا آبکشی، درِ گاراژ باز است یا در حال بسته شدن. برنامه‌ای که این حالت‌ها را با چند متغیر بولی پراکنده نگه دارد، خیلی زود به هم می‌ریزد. در این درس یاد می‌گیری چطور رفتار دستگاه را به‌صورت ماشین حالت بنویسی: ساختاری که کدش کوتاه است، همه‌چیزش روی یک نمودار جا می‌شود و می‌شود آن را روی PC با آرایه‌ای از رویدادها کامل آزمایش کرد.

🎯 بعد از این درس می‌توانی

  • حالت، رویداد و گذار را تعریف کنی و یک مسئله را به نمودار حالت تبدیل کنی
  • ماشین حالت را با enum و switch بنویسی و با جدول و اشاره‌گر تابع هم
  • عمل ورود و خروج را در جای درست بگذاری
  • فیلتر پرش دکمه (debounce) و پارسر فریم سریال را با ماشین حالت بسازی
  • ماشین حالت را روی PC با آرایه‌ای از رویدادها آزمایش کنی
  • توضیح بدهی چرا چند فلگ بولی خطرناک‌اند

🧰 پیش‌نیاز و وسایل

  • درس ۲.۴ (if و switch) و ۳.۴ (enum، struct)
  • درس ۴.۳ (اشاره‌گر به تابع) و ۴.۲ (پروژهٔ چندفایلی)
  • درس ۴.۵ (بافر حلقوی) برای بخش «رویداد از کجا می‌آید؟»
  • فقط gcc روی PC

ایدهٔ اصلی: دروازهٔ چرخان مترو

دروازهٔ ورودی مترو را یادت بیاور. وقتی قفل است، هل بدهی هیچ اتفاقی نمی‌افتد. کارت که بزنی، قفل باز می‌شود. هل که بدهی و رد شوی، دوباره قفل می‌شود. دو نکته اینجا مهم است:

  • دروازه در هر لحظه فقط در یک وضعیت است: قفل یا باز.
  • یک کار (مثل «هل دادن») بسته به وضعیت فعلی، نتیجهٔ متفاوت دارد: در حالت قفل بی‌اثر است، در حالت باز یک نفر را رد می‌کند.
مثال از زندگی روزمره

آسانسور هم همین‌طور است. دکمهٔ طبقهٔ پنجم را وقتی در ایستاده‌ای بزنی، آسانسور راه می‌افتد. همان دکمه را وقتی در حال حرکت است بزنی، فقط یادداشت می‌شود. «دکمه» ثابت است، ولی «کاری که می‌کند» به اینکه الان در چه حالتی هستی بستگی دارد. ماشین حالت یعنی همین را صریح در کد بنویسی.

پس سه چیز لازم داریم؛ نام‌هایشان در دنیای برنامه‌نویسی:

  • حالت (state): وضعیتی که سیستم الان در آن است؛ مثل LOCKED. سیستم در هر لحظه دقیقا یک حالت دارد.
  • رویداد (event): چیزی که از بیرون یا از زمان می‌رسد؛ مثل COIN (سکه انداخته شد) یا PUSH. رویداد کاری از خودش نمی‌کند؛ فقط خبر است.
  • گذار (transition): قاعدهٔ «در حالت الف، اگر رویداد ب رسید، برو به حالت پ و این کار را بکن». همراه گذار می‌توان یک عمل (action) هم اجرا کرد؛ مثل «یک سکه بشمار».

مجموعهٔ همین سه چیز را ماشین حالت متناهی (Finite State Machine، خلاصه FSM) می‌نامند: «متناهی» چون تعداد حالت‌ها محدود و از قبل معلوم است.

بدون ماشین حالت: اسپاگتی فلگ‌ها

قبل از راه‌حل، خود مشکل را ببین. تازه‌کارها معمولا برای هر «وضعیت» یک متغیر bool می‌گذارند و هر رویداد آن‌ها را عوض می‌کند. مثلا کنترل یک موتور با سه فلگ:

#include <stdio.h>
#include <stdbool.h>

static bool running = false;
static bool paused  = false;
static bool error   = false;

static void on_start(void)  { running = true; }
static void on_pause(void)  { paused = true; }
static void on_error(void)  { error = true; running = false; }
static void on_resume(void) { paused = false; running = true; }

static void show(const char *ev)
{
    printf("%-7s running=%d paused=%d error=%d\n", ev, running, paused, error);
}

int main(void)
{
    on_start();  show("start");
    on_pause();  show("pause");
    on_error();  show("error");
    on_resume(); show("resume");
    if (running && error) {
        printf("BUG: motor is running while in error!\n");
    }
    return 0;
}
  1. سه فلگ. «در حال کار»، «مکث» و «خطا»، هر کدام یک bool جدا. سه متغیر دوحالته یعنی ۲×۲×۲ = ۸ ترکیب ممکن. ولی فقط چهار وضعیت معنی دارند (بیکار، کار، مکث، خطا). ۴ ترکیب دیگر مثل «کار و خطا هم‌زمان» بی‌معنی‌اند ولی کد جلویشان را نمی‌گیرد.
  2. یک تابع برای هر رویداد. هر تابع فقط فلگ‌هایی را عوض می‌کند که نویسنده در همان لحظه یادش بود. در on_pause فراموش شد که running را خاموش کنیم، و در on_resume فراموش شد که «خطا نیست؟» را بپرسیم.
  3. چاپ وضعیت. برای دیدن همهٔ فلگ‌ها پس از هر رویداد.
  4. یک سناریو. شروع، مکث، خطا، ادامه.
  5. تشخیص وضعیت غیرممکن. اگر کار و خطا هم‌زمان باشند، هشدار می‌دهیم.

راه‌حل ماشین حالت: یک متغیر (یک enum) که حالت فعلی را می‌گوید. چون فقط یک مقدار می‌گیرد، «کار و خطا هم‌زمان» اصلا وجود ندارد و ترکیب غیرممکن نمی‌شود ساخت.

پیاده‌سازی اول: enum و switch

ساده‌ترین قالب: حالت‌ها یک enum، رویدادها یک enum دیگر، و یک تابع که با switch روی حالت و بعد شرط روی رویداد کار می‌کند. دروازهٔ چرخان را به‌صورت یک ماژول چندفایلی (درس ۴.۲) می‌سازیم. اول هدر:

#ifndef TURNSTILE_H
#define TURNSTILE_H

typedef enum {
    ST_LOCKED,
    ST_UNLOCKED
} turn_state_t;

typedef enum {
    EV_COIN,
    EV_PUSH
} turn_event_t;

typedef struct {
    turn_state_t state;
    unsigned coins;         /* چند سکه گرفته شده */
    unsigned passed;        /* چند نفر رد شده‌اند */
} turnstile_t;

void turnstile_init(turnstile_t *t);
void turnstile_handle(turnstile_t *t, turn_event_t ev);
const char *turn_state_name(turn_state_t s);
const char *turn_event_name(turn_event_t e);

#endif /* TURNSTILE_H */
  1. include guard. مثل همیشه.
  2. حالت‌ها. یک enum با نام‌های خوانا. مقدارها به‌ترتیب ۰ و ۱ هستند. به‌جای «حالت ۰ و ۱»، نام می‌گذاریم. پیشوند ST_ نام‌ها را از نام‌های دیگر پروژه جدا می‌کند.
  3. رویدادها. فقط دو رویداد: سکه و هل دادن.
  4. وضعیت کامل ماشین. علاوه بر state دو شمارنده هم داریم؛ به چنین داده‌های کنار حالت گفته می‌شود داده‌های جانبی (شمارنده‌ها، مهلت‌ها). حالت را نباید با همین‌ها یکی گرفت: حالت «کجا هستم» را می‌گوید، شمارنده «چقدر شده».
  5. چهار تابع. ساخت، رسیدگی به یک رویداد، و دو تابع نام برای چاپ.
#include "turnstile.h"

void turnstile_init(turnstile_t *t)
{
    t->state = ST_LOCKED;
    t->coins = 0;
    t->passed = 0;
}

void turnstile_handle(turnstile_t *t, turn_event_t ev)
{
    switch (t->state) {
    case ST_LOCKED:
        if (ev == EV_COIN) {
            t->coins++;
            t->state = ST_UNLOCKED;     // سکه انداختی: قفل باز شد
        }
        break;                          // فشار به قفل: هیچ اتفاقی نمی‌افتد

    case ST_UNLOCKED:
        if (ev == EV_PUSH) {
            t->passed++;
            t->state = ST_LOCKED;       // یک نفر رد شد: دوباره قفل
        } else if (ev == EV_COIN) {
            t->coins++;                 // سکهٔ اضافه: می‌گیریم، حالت عوض نمی‌شود
        }
        break;

    default:                            // مقدار خراب (باگ، bit-flip): امن‌ترین حالت
        t->state = ST_LOCKED;
        break;
    }
}

const char *turn_state_name(turn_state_t s)
{
    static const char *const names[] = { "LOCKED", "UNLOCKED" };
    return ((unsigned)s < sizeof names / sizeof names[0]) ? names[s] : "?";
}

const char *turn_event_name(turn_event_t e)
{
    static const char *const names[] = { "COIN", "PUSH" };
    return ((unsigned)e < sizeof names / sizeof names[0]) ? names[e] : "?";
}
  1. شروع. ماشین همیشه در یک حالت شروع مشخص شروع می‌کند: قفل. حالت اولیهٔ نامعلوم همان «مقدار آشغال» درس ۲.۱ است. حتما مقدار اولیه بده.
  2. تابع رسیدگی. رویداد را می‌گیرد و بسته به حالت فعلی رفتار می‌کند. هر بار که رویدادی برسد، این تابع یک‌بار صدا زده می‌شود.
  3. حالت LOCKED. اگر سکه آمد: یک سکه بشمار (عمل) و برو به UNLOCKED (گذار). هر رویداد دیگر (هل دادن) بی‌اثر است و حالت عوض نمی‌شود. هر case با break تمام می‌شود. بدون آن اجرا به case بعدی می‌ریزد (fall-through) که در تمرین ۲ خرابکاری‌اش را می‌بینی.
  4. حالت UNLOCKED. هل دادن: یک نفر رد شد، بشمار و قفل کن. سکهٔ اضافه: فقط بشمار.
  5. حالت ناشناخته: default. اگر state به هر دلیل مقداری بیرون enum بگیرد (سرریز بافر همسایه، bit-flip، فراموشی init)، ماشین به امن‌ترین حالت برمی‌گردد. بدون default ماشین بی‌صدا «هیچ‌کاری» می‌کرد و تا ابد گیر می‌ماند. در دستگاهی که موتور یا قفل دارد، حالت خراب را باید صریح به یک حالت امن (یا حالت خطا) ببری. نکته: با default دیگر کامپایلر برای case فراموش‌شده هشدار -Wswitch نمی‌دهد؛ پس این‌جا که همهٔ حالت‌ها نوشته شده‌اند فقط برای داده‌ی خراب است.
  6. نام‌ها برای چاپ. آرایه‌ای از رشته‌ها که با خود enum اندیس می‌خورد. این کار به این دلیل درست است که ترتیب نام‌ها با ترتیب enum یکی است. اگر حالت جدیدی وسط اضافه کنی، باید نام را هم در همان جا اضافه کنی. شرط < اندازه از خواندن بیرون آرایه (رفتار تعریف‌نشده) جلوگیری می‌کند و برای مقدار خراب "?" برمی‌گرداند.

حالا برنامهٔ آزمایش. نکتهٔ مهم: رویدادها را از یک آرایه می‌خوانیم، نه از سخت‌افزار. به این ترتیب هر سناریو، هر بار یکسان تکرار می‌شود و می‌شود خروجی را وارسی کرد.

#include <stdio.h>
#include "turnstile.h"

int main(void)
{
    static const turn_event_t events[] = {
        EV_PUSH, EV_COIN, EV_COIN, EV_PUSH, EV_PUSH, EV_COIN, EV_PUSH
    };
    turnstile_t gate;

    turnstile_init(&gate);
    for (unsigned i = 0; i < sizeof(events) / sizeof(events[0]); i++) {
        turn_state_t before = gate.state;
        turnstile_handle(&gate, events[i]);
        printf("%-4s: %-8s -> %s\n", turn_event_name(events[i]),
               turn_state_name(before), turn_state_name(gate.state));
    }
    printf("coins=%u passed=%u\n", gate.coins, gate.passed);
    return 0;
}
  1. سناریوی آزمایش. آرایه‌ای ثابت از رویدادها: هل بدون سکه، سکه، سکهٔ اضافه، عبور، هل بی‌اثر، سکه، عبور. آرایهٔ ثابت یعنی «آزمایش قابل‌تکرار». همین ایده را در فصل ۶ به تست واحد می‌رسانیم.
  2. ساخت. دروازه را می‌سازیم و در حالت قفل شروع می‌کنیم.
  3. اجرای هر رویداد. حالت قبل را نگه می‌داریم، رویداد را می‌دهیم، و حالت قبل و بعد را چاپ می‌کنیم.
  4. داده‌های جانبی. پایان کار: سکه‌ها و عبورها.

$ ./turnstile

خروجی را با شکل بالا تطبیق بده: هل در حالت قفل، خودش را به خودش می‌فرستد (LOCKED -> LOCKED)؛ سکهٔ دوم در حالت باز هم همین‌طور. سه سکه گرفته شد ولی فقط دو نفر رد شدند: سکهٔ دوم را وقتی قفل از قبل باز بود انداختند و هدر رفت. با دست بشمار و خودت مطمئن شو.

اگر break را فراموش کنی؟

کامپایلر GCC با -Wextra (که همیشه می‌گوییم استفاده کن) هشدار this statement may fall through می‌دهد. اگر می‌خواهی عمدا از یک case به بعدی بریزی، کنارش کامنت /* fall through */ بگذار تا هم هشدار خاموش شود و هم خواننده بفهمد عمدی بوده. این را در تمرین ۲ می‌بینی.

پیاده‌سازی دوم: جدول گذار

وقتی حالت‌ها و رویدادها زیاد می‌شوند، switch تودرتو طولانی می‌شود و پیدا کردن «از حالت الف با رویداد ب به کجا می‌روم؟» سخت. راه دیگر: همهٔ گذارها را در یک جدول بنویس. سطرها حالت‌ها، ستون‌ها رویدادها، و هر خانه حالت بعدی. اگر خانه‌ای «همان حالت» بود، رویداد نادیده گرفته می‌شود.

نمونه: چراغ راهنما با یک دکمهٔ عابر. زمان هر حالت با «شمارش tick» اندازه گرفته می‌شود. tick یعنی یک ضربهٔ منظم ساعت نرم‌افزار (مثلا هر ۱۰۰ میلی‌ثانیه)؛ روی برد واقعی تایمر آن را می‌سازد (درس ۵.۴). اینجا تیک‌ها را از آرایه می‌خوانیم.

  • سبز: ۴ تیک، بعد زرد. اگر عابر دکمه را زد، زودتر زرد می‌شود.
  • زرد: ۲ تیک، بعد قرمز. دکمه اینجا بی‌اثر است.
  • قرمز: ۳ تیک (عابر رد می‌شود)، بعد سبز. دکمه بی‌اثر است.
#ifndef TRAFFIC_H
#define TRAFFIC_H

typedef enum {
    S_GREEN,
    S_YELLOW,
    S_RED,
    S_COUNT             /* تعداد حالت‌ها؛ حالت واقعی نیست */
} light_state_t;

typedef enum {
    E_TIMEOUT,          /* زمان حالت فعلی تمام شد */
    E_PED_BUTTON,       /* عابر دکمه را زد */
    E_COUNT
} light_event_t;

typedef struct {
    light_state_t state;
    unsigned remaining; /* چند tick تا پایان این حالت */
} light_t;

void light_init(light_t *l);
void light_tick(light_t *l);                    /* یک tick زمان گذشت */
void light_dispatch(light_t *l, light_event_t ev);
const char *light_state_name(light_state_t s);

#endif /* TRAFFIC_H */
  1. حالت‌ها با نگهبان. آخرین عضو S_COUNT حالت واقعی نیست؛ چون enum از صفر شروع می‌شود، مقدارش برابر تعداد حالت‌هاست (ترفند درس ۳.۴). با این عدد اندازهٔ جدول‌ها را می‌نویسیم. حالت جدید که وسط اضافه کنی، اندازه‌ها خودشان بزرگ می‌شوند.
  2. رویدادها. «مهلت تمام شد» و «دکمهٔ عابر». همان ترفند E_COUNT.
  3. وضعیت. حالت فعلی و چند تیک تا پایان آن.
  4. API. ساخت، یک تیک، ارسال رویداد، و نام حالت برای چاپ.
#include <stdio.h>
#include "traffic.h"

typedef void (*action_fn)(void);

/* جدول گذار: سطر = حالت فعلی، ستون = رویداد، خانه = حالت بعدی */
static const light_state_t next_state[S_COUNT][E_COUNT] = {
    /*             E_TIMEOUT  E_PED_BUTTON */
    /* S_GREEN  */ { S_YELLOW, S_YELLOW },
    /* S_YELLOW */ { S_RED,    S_YELLOW },
    /* S_RED    */ { S_GREEN,  S_RED    },
};

static const unsigned duration[S_COUNT] = { 4, 2, 3 };

static void enter_green(void)  { printf("  enter GREEN\n"); }
static void enter_yellow(void) { printf("  enter YELLOW\n"); }
static void enter_red(void)    { printf("  enter RED (walk on)\n"); }
static void exit_red(void)     { printf("  exit RED (walk off)\n"); }

static const action_fn entry_action[S_COUNT] = { enter_green, enter_yellow, enter_red };
static const action_fn exit_action[S_COUNT]  = { NULL, NULL, exit_red };

static void go_to(light_t *l, light_state_t next)
{
    if (exit_action[l->state] != NULL) {
        exit_action[l->state]();
    }
    l->state = next;
    l->remaining = duration[next];
    if (entry_action[next] != NULL) {
        entry_action[next]();
    }
}

void light_init(light_t *l)
{
    l->state = S_RED;
    l->remaining = duration[S_RED];
    if (entry_action[S_RED] != NULL) { entry_action[S_RED](); }
}

void light_dispatch(light_t *l, light_event_t ev)
{
    if ((unsigned)l->state >= S_COUNT || (unsigned)ev >= E_COUNT) {
        return;                         // بیرون از جدول: نادیده
    }
    light_state_t next = next_state[l->state][ev];
    if (next != l->state) {
        go_to(l, next);
    }
}

void light_tick(light_t *l)
{
    if (l->remaining > 0U) {
        l->remaining--;
    }
    if (l->remaining == 0U) {
        light_dispatch(l, E_TIMEOUT);
    }
}

const char *light_state_name(light_state_t s)
{
    static const char *const names[S_COUNT] = { "GREEN", "YELLOW", "RED" };
    return ((unsigned)s < S_COUNT) ? names[s] : "?";
}

عمل ورود و عمل خروج

عمل‌هایی که به «رسیدن به یک حالت» یا «ترک آن» مربوط‌اند را عمل ورود و خروج (entry/exit action) می‌نامند. مثال چراغ راهنما: «چراغ عابر را روشن کن» دقیقا هنگام ورود به قرمز است و «خاموش کن» هنگام خروج از آن. اگر آن را روی هر گذار جدا بنویسی، باید در هر ۳ جایی که به قرمز می‌رسی و هر جایی که از آن می‌روی تکرارش کنی و یکی را فراموش می‌کنی. با عمل ورود و خروج، یک بار می‌نویسی و همیشه اجرا می‌شود؛ اینکه چطور به قرمز رسیده‌ای فرقی نمی‌کند.

در go_to ترتیب چهار قدم مهم است: اول خروج از حالت قدیم، بعد ورود به حالت جدید؛ نه برعکس. اگر این دو جابه‌جا شوند، برای لحظه‌ای هر دو عمل هم‌زمان فعال‌اند: مثل اینکه چراغ عابر روشن شود و بعد خاموش، در حالی که باید فقط یکی باشد.

پروژهٔ واقعی ۱: فیلتر پرش دکمه (debounce)

دکمهٔ مکانیکی وقتی می‌فشاریش، دو تیغهٔ فلزی به هم می‌خورند و مثل توپ چندبار جهش می‌کنند. برای چند میلی‌ثانیه (معمولا کمتر از ۲۰ میلی‌ثانیه) سیگنال سریع بین بالا و پایین می‌پرد. به این پدیده پرش تماس (bounce) می‌گویند. میکروکنترلر که سریع نمونه می‌گیرد، هر جهش را «یک فشردن» می‌بیند: با یک فشار، ممکن است ده رویداد بگیری و مثلا LED ده بار عوض شود.

#include "button.h"

void button_init(button_t *b)
{
    b->state = BTN_RELEASED;
    b->count = 0;
}

btn_event_t button_step(button_t *b, bool raw_pressed)
{
    btn_event_t ev = BTN_EV_NONE;

    switch (b->state) {
    case BTN_RELEASED:
        if (raw_pressed) {
            b->state = BTN_PRESS_CANDIDATE;
            b->count = 1;
        }
        break;

    case BTN_PRESS_CANDIDATE:
        if (!raw_pressed) {
            b->state = BTN_RELEASED;            // فقط نویز بود
        } else if (++b->count >= BTN_STABLE_TICKS) {
            b->state = BTN_PRESSED;
            ev = BTN_EV_PRESS;                  // معتبر شد
        }
        break;

    case BTN_PRESSED:
        if (!raw_pressed) {
            b->state = BTN_RELEASE_CANDIDATE;
            b->count = 1;
        }
        break;

    case BTN_RELEASE_CANDIDATE:
        if (raw_pressed) {
            b->state = BTN_PRESSED;             // پرش دکمه، هنوز پایین است
        } else if (++b->count >= BTN_STABLE_TICKS) {
            b->state = BTN_RELEASED;
            ev = BTN_EV_RELEASE;
        }
        break;

    default:                                    // حالت خراب: بازگشت به رها
        b->state = BTN_RELEASED;
        b->count = 0;
        break;
    }
    return ev;
}

{
    static const char *const names[] = {
        "RELEASED", "PRESS_CANDIDATE", "PRESSED", "RELEASE_CANDIDATE"
    };
    return ((unsigned)s < sizeof names / sizeof names[0]) ? names[s] : "?";
}

  2. حالت RELEASED. اگر نمونه «پایین» بود، به کاندید برو و شمارنده را ۱ کن. در غیر این صورت هیچ.
  3. حالت PRESS_CANDIDATE. اگر نمونه «بالا» بود، نویز بوده؛ برگرد. اگر پایین بود، یکی بشمار؛ رسید به آستانه؟ فشرده شد و رویداد PRESS صادر می‌شود. عملگر ++b->count اول یکی اضافه می‌کند و بعد مقایسه می‌شود؛ پس نمونهٔ اول (که در RELEASED شمرده شد) هم جزو سه‌تا حساب می‌شود.
  4. حالت PRESSED. تا وقتی «پایین» است هیچ اتفاقی نمی‌افتد. اولین نمونهٔ «بالا» شروع کاندید رها شدن است.

پروژهٔ واقعی ۲: پارسر فریم سریال

ماشین حالت فقط برای دکمه و چراغ نیست. هر وقت داده‌ای به‌صورت رشته‌ای از بایت‌ها می‌رسد (مثل UART)، برای فهمیدن ساختارش به ماشین حالت نیاز داری. فرض کن دستگاهی فریم‌هایی به این شکل می‌فرستد: $ در ابتدا، چند رقم، و \n در پایان؛ مثلا $305\n. بین فریم‌ها ممکن است هر آشغالی برسد. پارسر باید فقط فریم‌های سالم را قبول کند. حالت لازم: «منتظر شروع» و «در حال خواندن رقم».

رویداد از کجا می‌آید؟

تا اینجا رویدادها را از آرایه می‌خواندیم. روی میکروکنترلر واقعی از دو جا می‌آیند: سخت‌افزار (دکمه، UART، تایمر) و زمان (tick). قاعدهٔ حرفه‌ای این است که رویداد در ISR فقط ساخته و در صف گذاشته شود و ماشین حالت در حلقهٔ اصلی اجرا شود. صف همان بافر حلقوی درس ۴.۵ است: تولیدکننده ISR، مصرف‌کننده main.

ماشین حالت از قاعدهٔ اجرا تا پایان (run-to-completion) پیروی می‌کند: هر رویداد کامل پردازش می‌شود (گذار، خروج، ورود) قبل از اینکه رویداد بعدی شروع شود. نتیجه: هیچ‌وقت وسط یک گذار نیستی و حالت هیچ‌وقت نیمه‌کاره نیست. برای همین در رسیدگی به رویداد نباید منتظر ماند (delay یا حلقهٔ انتظار درس ۲.۵): اگر یک عمل زمان‌بر لازم است، آن را به حالت جدید و رویداد «تمام شد» تبدیل کن.

هر حالت انتظار، مهلت لازم دارد

مدل‌های خروجی: Mealy و Moore

در ماشین حالت، «خروجی» (عمل) را دو جا می‌شود گذاشت:

  • مدل Moore: خروجی وابسته به حالت است. مثل عمل ورود: «در حالت قرمز، چراغ عابر روشن است».
  • مدل Mealy: خروجی وابسته به گذار (حالت + رویداد) است. مثل «سکه شمرده شد» که فقط وقتی سکه رسید اتفاق می‌افتد، یا رویداد PRESS که فقط روی یک گذار خاص صادر می‌شود.

در کد واقعی معمولا هر دو را با هم می‌بینی و لازم نیست نامش را بدانی؛ ولی وقتی در مستندات یا کتاب‌ها این دو اسم را دیدی، معنیشان همین است.

تمرین ۱: درِ گاراژ

درِ گاراژ چهار حالت دارد: بسته (G_CLOSED)، در حال باز شدن (G_OPENING)، باز (G_OPEN) و در حال بسته شدن (G_CLOSING). رویدادها: دکمهٔ ریموت، سوئیچ انتهای باز، سوئیچ انتهای بسته و مانع (GE_OBSTACLE: چیزی در مسیر است). قاعده‌ها:

  • در حال بسته شدن + مانع ← دوباره در حال باز شدن.
  • هر رویداد دیگر در هر حالت: نادیده.

    switch (s) {

        }
        break;
    case G_OPENING:

            return G_OPEN;
        }

تمرین ۲: باگ fall-through

این ماشین سه حالت دارد: بیکار، در حال کار و خطا. سناریو: شروع، ریست، خطا، ریست. انتظار: ریست در حالت «در حال کار» نادیده گرفته شود (نباید کاری را وسط راه ریست کرد) و فقط در حالت خطا به بیکار برگردد.

        break;

            s = S_ERROR;

تمرین ۳: پارسر فریم سریال

جواب الف: دو فریم سالم (۱۲ و ۳۰۵) و سه فریم خراب: $7a (حرف a)، $ بدون رقم و $1234567 (بیش از ۵ رقم). شماره‌ها اندیس بایت خراب در رشته‌اند.

جواب کامل با توضیح 
#include <stdio.h>

typedef enum { P_WAIT_START, P_DIGITS } pstate_t;
typedef enum { R_NONE, R_OK, R_BAD } presult_t;

typedef struct {
    pstate_t state;
    unsigned value;
    unsigned digits;
} parser_t;

static presult_t feed(parser_t *p, char c)
{
    if (c == '$') {                         // شروع تازه، از هر حالتی
        p->state = P_DIGITS;
        p->value = 0;
        p->digits = 0;
        return R_NONE;
    }
    switch (p->state) {
    case P_WAIT_START:
        break;                              // آشغال بین فریم‌ها؛ نادیده
    case P_DIGITS:
        if (c >= '0' && c <= '9' && p->digits < 5U) {
            p->value = p->value * 10U + (unsigned)(c - '0');
            p->digits++;
        } else if (c == '\n' && p->digits > 0U) {
            p->state = P_WAIT_START;
            return R_OK;
        } else {
            p->state = P_WAIT_START;
            return R_BAD;
        }
        break;
    default:                                // حالت خراب: از نو شروع
        p->state = P_WAIT_START;
        break;
    }
    return R_NONE;
}

int main(void)
{
    const char stream[] = "xx$12\n$7a\n$305\n$\n$1234567\n";
    parser_t p = { P_WAIT_START, 0, 0 };

    for (unsigned i = 0; stream[i] != '\0'; i++) {
        presult_t r = feed(&p, stream[i]);
        if (r == R_OK) {
            printf("frame ok: %u\n", p.value);
        } else if (r == R_BAD) {
            printf("bad frame at index %u\n", i);
        }
    }
    return 0;
}
  1. حالت‌ها و نتیجه‌ها. دو حالت؛ و سه نتیجه: «چیزی نشد»، «فریم سالم»، «فریم خراب».
  2. وضعیت پارسر. حالت و دو داده جانبی: مقدار جمع‌شده و تعداد ارقام.
  3. علامت شروع. هر $ پارسر را از اول می‌کند و مقدار را صفر. این بررسی قبل از switch است چون در هر حالتی رفتار یکسانی دارد؛ قاعدهٔ «هم‌زمان‌سازی مجدد» فریم‌ها را از گم شدن بایت نجات می‌دهد.
  4. حالت انتظار. هر چیز دیگر بین فریم‌ها نادیده گرفته می‌شود.
  5. رقم معتبر. مقدار را با ۱۰ ضرب و رقم را اضافه می‌کنیم؛ شرط digits < 5 جلوی سرریز را می‌گیرد. ۵ رقم حداکثر ۹۹۹۹۹ است که در unsigned ۳۲ بیتی جا می‌شود. بدون این حد، فریمی بلند می‌توانست سرریز کند (درس ۲.۲).
  6. پایان درست. خط جدید با حداقل یک رقم: به حالت انتظار برمی‌گردیم و R_OK می‌دهیم.
  7. هر چیز دیگر. نویسهٔ نامعتبر، خط جدید بدون رقم، یا رقم ششم: فریم خراب.
  8. حالت خراب: default. مقدار ناشناخته در state را به حالت انتظار برمی‌گرداند تا پارسر با اولین $ بعدی دوباره سالم شود.
  9. آزمایش. رشته‌ای پر از فریم سالم، خراب و آشغال؛ هر بایت به feed می‌رود.

جواب پ: اگر بایتی وسط ارقام گم شود، پارسر مقدار کمی متفاوت می‌سازد و فریم را سالم می‌داند. این خطا را فقط با یک جمع کنترلی (checksum یا CRC) می‌توان تشخیص داد. اگر \n پایانی گم شود، پارسر در حالت DIGITS می‌ماند تا فریم بعدی با $ برسد و آن او را دوباره هم‌زمان کند؛ ولی فریم قبلی از دست رفته است. برای مهلت (timeout) هم می‌توان یک شمارندهٔ tick اضافه کرد.

حرف مربی

دو جا معمولا گیر می‌کنند. اول «این‌همه کار برای یک if ساده؟»: برای یک دکمهٔ ساده حق با توست. اما وقتی سومین فلگ را می‌گذاری و متوجه می‌شوی باید همهٔ توابع را دوباره بخوانی، وقت ماشین حالت است. قاعدهٔ من: اگر «حالت» در ذهنت دارد و نام برایش انتخاب می‌کنی، آن را یک enum کن. دوم «رویداد و حالت را یکی می‌گیرند»: رویداد چیزی است که اتفاق می‌افتد (دکمه فشرده شد، مهلت تمام شد)؛ حالت چیزی است که هستی (در حال شست‌وشو). قبل از کدنویسی، نمودار را روی کاغذ بکش؛ اگر نتوانستی بکشی، کد هم نمی‌توانی بنویسی.

خلاصه یک‌دقیقه‌ای

  • ماشین حالت = حالت (یک enum) + رویداد + گذار (حالت فعلی و رویداد ← حالت بعدی و عمل). فقط یک حالت در هر لحظه.
  • چند فلگ bool ۲n ترکیب دارند که بیشترشان بی‌معنی‌اند؛ «اسپاگتی فلگ‌ها» باگ‌های نادر می‌سازد.
  • پیاده‌سازی: switch روی حالت (ساده، برای ماشین‌های کوچک) یا جدول گذار next[state][event] با اشاره‌گر تابع (برای ماشین‌های بزرگ).
  • عمل ورود و خروج، یک‌بار در go_to: خروج قدیم، عوض کردن، ورود جدید. گذار بی‌تغییر، عملی ندارد.
  • debounce: حالت‌های «کاندید» و شمارندهٔ پایداری؛ رویداد فقط یک بار در لحظهٔ گذار. پارسر فریم: هر بایت یک رویداد و $ برای هم‌زمان‌سازی.
  • روی MCU: ISR فقط رویداد را در صف (بافر حلقوی) می‌گذارد؛ ماشین حالت کامل و بدون انتظار در main اجرا می‌شود. رویدادها را می‌شود از آرایه شبیه‌سازی و روی PC آزمایش کرد.
  • Moore = خروجی وابسته به حالت؛ Mealy = وابسته به گذار.
