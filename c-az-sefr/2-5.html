در درس قبل برای چهار خوانش دمای پشت‌سرهم، چهار بار همان بلوک را کپی کردیم. اگر هزار خوانش داشتیم چه؟ هیچ برنامه‌نویسی هزار بار کپی نمی‌کند. کامپیوتر برای تکرار ساخته شده: می‌تواند میلیون‌ها بار یک کار را بدون خستگی و بدون غر زدن انجام دهد. در این درس یاد می‌گیری چطور به او بگویی «این کار را تکرار کن».

🎯 بعد از این درس می‌توانی

  • با while، for و do-while یک کار را چندین بار تکرار کنی
  • بدانی هر حلقه دقیقا چند بار اجرا می‌شود و از «یکی کم یا یکی زیاد» جلوگیری کنی
  • با break و continue حلقه را وسط کار کنترل کنی
  • بفهمی چرا حلقه‌ی بی‌نهایت در میکروکنترلر عادی است و در PC معمولا باگ
  • حلقه‌ی انتظار با timeout و میانگین‌گیری از چند خوانش بنویسی

🧰 پیش‌نیاز و وسایل

  • درس ۲.۴ (شرط‌ها)؛ حلقه‌ها همیشه یک شرط دارند
  • درس ۲.۱ (متغیر و انتساب) و ۲.۳ (عملگرها؛ به‌ویژه ++ و %)
  • یک کامپایلر روی رایانه‌ات یا کامپایلر آنلاین
  • هیچ سخت‌افزاری لازم نیست

ایده اصلی: دور زدن

فرض کن مربی به تو می‌گوید «دور زمین بدو، ۵ دور». تو برای هر دور دستور جدید نمی‌گیری. یک قانون در ذهنت می‌ماند: «دور را بشمار؛ تا وقتی به ۵ نرسیده‌ای ادامه بده». به هر بار اجرای این کار می‌گویند یک تکرار (iteration) و به کل این ساختار، حلقه (loop).

هر حلقه‌ی درست سه چیز دارد:

  1. شروع. از کجا شروع کنیم؟ (مثلا دور شماره‌ی ۱)
  2. شرط ادامه. تا کی ادامه بدهیم؟ (تا وقتی دور کمتر یا مساوی ۵ است)
  3. گام. بعد از هر تکرار چه چیزی عوض می‌شود تا کار کم‌کم تمام شود؟ (دور بعدی)

اگر هر کدام از این سه را فراموش کنی، حلقه یا اصلا شروع نمی‌شود یا هیچ‌وقت تمام نمی‌شود.

مثال از زندگی روزمره

ماشین لباس‌شویی را ببین. برنامه‌ی «آبکشی» می‌گوید: «تا وقتی آب داخل تمیز نشده و کمتر از ۳ بار آبکشی شده، لباس‌ها را بچرخان». او دفتر دستورالعملی با هزار خط ندارد؛ فقط یک قانون تکرارشونده دارد. برنامه‌ی میکروکنترلر داخل لباس‌شویی هم دقیقا همین ساختار را در C دارد.

حلقه‌ی while: «تا وقتی که...»

ساده‌ترین حلقه در C، while (به معنی «تا وقتی که») است. قالبش:

while (شرط) {
    بدنه‌ی حلقه
}

کامپیوتر اول شرط را می‌پرسد (همان شرط بله/نه درس قبل). اگر «بله» بود بدنه را یک‌بار اجرا می‌کند و دوباره برمی‌گردد و شرط را می‌پرسد. تا وقتی جواب «نه» شود.

#include <stdio.h>

int main(void)
{
    int count = 3;

    while (count > 0) {
        printf("count = %d\n", count);
        count = count - 1;
    }
    printf("liftoff\n");
    return 0;
}
  1. شروع. شمارنده‌ی count را ۳ می‌کنیم. هر حلقه‌ای که با شمارنده کار می‌کند، اول باید مقدار شروع داشته باشد. بدون آن با «آشغال» شروع می‌شود (درس ۲.۱).
  2. شرط ادامه. «۳ > ۰؟» بله. بدنه اجرا می‌شود. پایان بدنه (}) دوباره به همین سؤال برمی‌گردد. شرط قبل از هر تکرار پرسیده می‌شود. پس اگر از همان اول نادرست باشد، بدنه حتی یک‌بار هم اجرا نمی‌شود.
  3. کار اصلی. مقدار فعلی شمارنده چاپ می‌شود.
  4. گام. شمارنده یکی کم می‌شود. این خط مهم‌ترین خط حلقه است. اگر این خط را فراموش کنی، count همیشه ۳ می‌ماند، شرط همیشه درست است و حلقه هرگز تمام نمی‌شود (حلقه‌ی بی‌نهایت).
  5. بعد از حلقه. وقتی count صفر شد، شرط «۰ > ۰؟» نادرست است و اجرا از حلقه بیرون می‌آید.
$ gcc -std=c11 -Wall -Wextra -o countdown countdown.c
$ ./countdown
count = 3
count = 2
count = 1
liftoff

حلقه‌ی for: همه‌چیز در یک خط

الگوی «شروع، شرط، گام» آن‌قدر رایج است که C برایش یک حلقه‌ی مخصوص دارد: for. هر سه تکه را در یک جا، داخل پرانتز و با ; جدا می‌نویسی:

کد زیر اعداد ۱ تا ۵ را جمع می‌کند و هر مرحله را نشان می‌دهد:

#include <stdio.h>

int main(void)
{
    int sum = 0;

    for (int i = 1; i <= 5; i++) {
        sum = sum + i;
        printf("i = %d, sum = %d\n", i, sum);
    }
    printf("total = %d\n", sum);
    return 0;
}
  1. انباره‌ی جمع. sum از صفر شروع می‌کند، مثل ماشین‌حساب که با ۰ روشن می‌شود. صفر عضو خنثای جمع است. اگر با آشغال شروع می‌کردیم، جمع نهایی هم آشغال می‌شد.
  2. سرصفحه‌ی for. int i = 1 یک شمارنده می‌سازد (فقط یک‌بار). i <= 5 شرط ادامه. i++ یعنی «i را یکی زیاد کن» (همان i = i + 1؛ در درس ۲.۳ دیدی). نام i سنت قدیمی برنامه‌نویس‌هاست (از index یا integer). وقتی معنی خاصی دارد، اسم بهتری بگذار.
  3. جمع کردن. مقدار فعلی i به sum اضافه می‌شود. این همان الگوی score = score + 10 درس ۲.۱ است.
  4. چاپ هر دور. برای دیدن حلقه‌ی در حال اجرا، هر دور یک خط می‌نویسد. چاپ داخل حلقه، ساده‌ترین روش دیباگ است. به همین علت اولین کاری که می‌کنی وقتی حلقه‌ات درست کار نمی‌کند، همین است.
  5. بعد از حلقه. وقتی i برابر ۶ شد، شرط 6 <= 5 نادرست است و اجرا به اینجا می‌رسد. جمع نهایی چاپ می‌شود.
$ ./sum_for
i = 1, sum = 1
i = 2, sum = 3
i = 3, sum = 6
i = 4, sum = 10
i = 5, sum = 15
total = 15
متغیر داخل for فقط همان‌جا زنده است

چون int i داخل پرانتز for ساخته شده، بعد از } دیگر وجود ندارد. اگر بعد از حلقه بنویسی printf("%d", i) کامپایلر می‌گوید 'i' undeclared. به این می‌گویند حوزه‌ی دید (scope) و در درس ۳.۵ کامل می‌آید. اگر بعد از حلقه به i نیاز داری، آن را بیرون از for تعریف کن.

حالا با دستان خودت اجرا را دنبال کن. روی «بعدی» بزن و ببین sum و i در حافظه چطور عوض می‌شوند:

حلقه‌ی do-while: اول انجام بده، بعد بپرس

در while اول سؤال می‌پرسند و بعد بدنه را اجرا می‌کنند. گاهی می‌خواهی بدنه حداقل یک‌بار اجرا شود، و بعد ببینی تکرار لازم است یا نه. مثلا یک سنسور را یک‌بار می‌خوانی و بعد تصمیم می‌گیری دوباره بخوانی یا نه. برای این کار do-while ("انجام بده، تا وقتی که") را داریم. توجه: بعد از while(...) در انتها ; لازم است.

#include <stdio.h>

int main(void)
{
    int tries = 0;
    int reading;

    do {
        tries = tries + 1;
        reading = tries * 10;
        printf("try %d: reading = %d\n", tries, reading);
    } while (reading < 25);

    while (reading < 25) {
        printf("this line is never printed\n");
    }
    return 0;
}
  1. دو متغیر. تعداد تلاش‌ها و آخرین خوانش. reading عمدا مقدار اولیه ندارد؛ در دور اول، قبل از هر استفاده مقدار می‌گیرد. این یکی از استثناهای معقول قانون «همیشه مقدار اولیه» است، چون بدنه‌ی do مطمئنا قبل از شرط اجرا می‌شود. اگر نگران بودی، صفر بگذار؛ ضرری ندارد.
  2. do ... while. بدنه اول اجرا می‌شود و شرط در انتها پرسیده می‌شود.
  3. بدنه. یک شمارنده‌ی تلاش، یک «خوانش شبیه‌سازی‌شده» که هر بار ۱۰ تا بیشتر می‌شود (مثل سنسوری که گرم می‌شود)، و چاپ آن.
  4. شرط پایانی. بعد از دور اول: خوانش ۱۰ است، کمتر از ۲۵ است، پس تکرار. دور دوم ۲۰، باز تکرار. دور سوم ۳۰؛ دیگر کمتر از ۲۵ نیست، تمام. ببین بدنه ۳ بار اجرا شد. شرط ۳ بار پرسیده شد، اما فقط بعد از هر اجرای بدنه.
  5. مقایسه با while. همان شرط، ولی با while معمولی. چون reading الان ۳۰ است و شرط از قبل نادرست، بدنه یک‌بار هم اجرا نمی‌شود. این تفاوت اصلی است: while ممکن است صفر بار اجرا شود، do-while حداقل یک بار.
$ ./do_while
try 1: reading = 10
try 2: reading = 20
try 3: reading = 30

break و continue: کنترل وسط راه

گاهی وسط دور می‌فهمی که کاری باید کرد:

  • break یعنی «همین الان از کل حلقه بیرون بیا». مثل وقتی که وسط دویدن دور زمین، دوستت صدا می‌زند و کلا بی‌خیال بقیه‌ی دورها می‌شوی.
  • continue یعنی «بقیه‌ی همین دور را رها کن و برو سراغ دور بعد». مثل وقتی در ردیف کالاها که چیزی خراب دیدی، همان را رد می‌کنی و می‌روی سراغ بعدی.
#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 10; i++) {
        if (i % 2 == 0) {
            continue;
        }
        if (i > 7) {
            break;
        }
        printf("i = %d\n", i);
    }
    printf("finished\n");
    return 0;
}
  1. حلقه‌ی ۱ تا ۱۰. قرار است ده دور بزند، اما دو خط داخلش می‌توانند این را عوض کنند.
  2. continue برای زوج‌ها. i % 2 == 0 یعنی «باقیمانده‌ی تقسیم بر ۲ صفر است» یعنی زوج. اگر زوج بود، continue بقیه‌ی بدنه (شامل چاپ) را رد می‌کند و می‌رود سراغ i++ و دور بعد. continue به گام (i++) می‌رود، نه به اول برنامه. برای همین در حلقه‌ی for شمارنده همچنان جلو می‌رود.
  3. break برای بزرگ‌ها. وقتی i به ۹ رسید (اولین فرد بزرگ‌تر از ۷)، حلقه کامل قطع می‌شود.
  4. چاپ. فقط عددهای فرد ≤ ۷ به اینجا می‌رسند: ۱، ۳، ۵، ۷.
  5. بعد از حلقه. چه حلقه تمام شود چه با break قطع شود، اجرا به اینجا می‌آید.
$ ./break_continue
i = 1
i = 3
i = 5
i = 7
finished

یک نکته‌ی مهم: break فقط از نزدیک‌ترین حلقه‌ی دربرگیرنده بیرون می‌آید، نه از همه‌ی حلقه‌های تودرتو. (و در switch هم همان کاری را می‌کند که در درس ۲.۴ دیدی.)

حلقه‌ی تو در تو

بدنه‌ی یک حلقه می‌تواند خودش یک حلقه باشد. مثل ساعت: عقربه‌ی دقیقه‌شمار ۶۰ بار می‌چرخد تا عقربه‌ی ساعت‌شمار یک قدم برود. حلقه‌ی درونی کامل اجرا می‌شود به ازای هر تکرار حلقه‌ی بیرونی.

#include <stdio.h>

int main(void)
{
    for (int row = 1; row <= 3; row++) {
        for (int col = 1; col <= 4; col++) {
            printf("%3d", row * col);
        }
        printf("\n");
    }
    return 0;
}
  1. حلقه‌ی بیرونی. سطر را انتخاب می‌کند: ۱، ۲، ۳.
  2. حلقه‌ی درونی. برای هر سطر، همه‌ی ستون‌ها از ۱ تا ۴ را می‌رود. یعنی جمعا ۳×۴ = ۱۲ بار بدنه‌اش اجرا می‌شود. تعداد کل تکرارها حاصل‌ضرب تعداد تکرارهای دو حلقه است. در میکروکنترلر که هر ثانیه ارزش دارد، به این ضرب دقت کن؛ ۱۰۰۰×۱۰۰۰ یعنی یک میلیون.
  3. چاپ حاصل‌ضرب. %3d یعنی «عدد را در یک ستون به عرض ۳ کاراکتر چاپ کن». اگر عدد کوتاه باشد جلویش فاصله می‌آید تا ستون‌ها صاف شوند.
  4. رفتن به خط بعد. بعد از تمام شدن یک سطر (یعنی بعد از حلقه‌ی درونی) یک \n چاپ می‌شود. این خط داخل حلقه‌ی بیرونی است اما بیرون از درونی. جای آکولاد معنی را عوض می‌کند.
$ ./nested
  1  2  3  4
  2  4  6  8
  3  6  9 12

خطای یکی-کم-یکی-زیاد (Off-by-one)

بگذار یک سؤال از تو بپرسم. یک مسیر ۱۰ متری را می‌خواهی با نرده‌ی یک‌متری ببندی. چند «تیرک» لازم است؟ خیلی‌ها ۱۰ می‌گویند. ولی جواب ۱۱ است: یک تیرک اول هم لازم است. این اشتباه ذهنی معروف را «خطای نرده و تیرک» (fence-post) می‌گویند. در برنامه‌نویسی نامش off-by-one است و رایج‌ترین باگ حلقه‌هاست.

#include <stdio.h>

int main(void)
{
    int count_a = 0;
    int count_b = 0;

    for (int i = 0; i < 5; i++) {
        count_a++;
    }
    for (int i = 0; i <= 5; i++) {
        count_b++;
    }
    printf("i < 5 runs %d times\n", count_a);
    printf("i <= 5 runs %d times\n", count_b);
    return 0;
}
  1. دو شمارنده‌ی تعداد. فقط برای اینکه بشماریم هر حلقه چند بار اجرا می‌شود.
  2. با < . i مقدارهای ۰، ۱، ۲، ۳، ۴ را می‌گیرد (۵ مقدار) و وقتی ۵ شد شرط نادرست می‌شود. پس ۵ بار. قانون طلایی: برای N بار تکرار، از صفر شروع کن و با i < N ادامه بده. (بعدا در آرایه‌ها می‌بینی چرا: ایندکس آرایه هم از صفر شروع می‌شود.)
  3. با <= . ۰ تا ۵ یعنی ۶ مقدار. پس ۶ بار. اگر قصدت ۵ بار بود، یکی زیاد اجرا کرده‌ای. در دنیای واقعی یعنی یک عنصر بیشتر خواندن، یک بایت اضافه نوشتن، یا یک موتور که یک قدم اضافه می‌رود.
$ ./off_by_one
i < 5 runs 5 times
i <= 5 runs 6 times
می‌خواهیبنویسمقدارهای i
N بار تکرارfor (i = 0; i < N; i++)۰ تا N−۱
شمردن از ۱ تا Nfor (i = 1; i <= N; i++)۱ تا N
شمارش معکوس N تا ۱for (i = N; i > 0; i--)N تا ۱

راه دفاع: قبل از اجرا با یک مقدار کوچک (مثل N برابر ۲ یا ۳) دستی حلقه را دنبال کن. اگر مرز را اشتباه بگیری، همان‌جا معلوم می‌شود.

حلقه‌ای که تمام نمی‌شود، بی‌آنکه بفهمی

یک دام دیگر به نوع کوچک بستگی دارد. در درس ۲.۲ می‌بینی uint8_t فقط اعداد ۰ تا ۲۵۵ را نگه می‌دارد و بعد از ۲۵۵ دوباره به ۰ برمی‌گردد. حالا این حلقه را ببین:

#include <stdint.h>
#include <stdio.h>

int main(void)
{
    int count = 0;

    for (uint8_t i = 0; i <= 255; i++) {
        count++;
    }
    printf("%d\n", count);
    return 0;
}
  1. شمارنده. فقط برای اینکه ببینیم حلقه چند بار می‌چرخد.
  2. شرط همیشه درست. uint8_t هرگز از ۲۵۵ بزرگ‌تر نمی‌شود؛ بعد از ۲۵۵ به ۰ برمی‌گردد. پس i <= 255 هیچ‌وقت نادرست نمی‌شود و حلقه تا ابد می‌چرخد. این باگ در برنامه‌های میکروکنترلر واقعی زیاد دیده می‌شود، چون آنجا دائم از نوع‌های کوچک ۸ بیتی استفاده می‌کنند.
$ gcc -std=c11 -Wall -Wextra -Werror=type-limits -o u8_loop u8_loop.c
u8_loop.c: In function 'main':
u8_loop.c:8:27: error: comparison is always true due to limited range of data type [-Werror=type-limits]

خوشبختانه -Wextra این مورد را می‌گیرد؛ ما هشدار را به خطا تبدیل کردیم تا نشانش بدهیم. اگر می‌خواستی ۰ تا ۲۵۵ (۲۵۶ مقدار) را بروی، نوع int یا شرط i < 256 با نوع بزرگ‌تر لازم بود.

حلقه‌ی بی‌نهایت: باگ روی PC، قانون روی میکروکنترلر

وقتی شرط هیچ‌وقت نادرست نشود، حلقه تمام نمی‌شود. روی رایانه‌ی شخصی این معمولا باگ است (برنامه «هنگ می‌کند»). اما روی میکروکنترلر داستان فرق دارد.

در درس ۱.۴ دیدی روی میکروکنترلر سیستم‌عاملی نیست که بعد از پایان برنامه کار را دست بگیرد. اگر main تمام شود، بسته به کد راه‌انداز، پردازنده یا در یک حلقه‌ی بی‌فایده گیر می‌کند یا به جای نامربوطی می‌پرد. پس برنامه باید هرگز تمام نشود: بعد از راه‌اندازی، برای همیشه در یک حلقه بماند و ورودی‌ها را بخواند، منطق را اجرا کند، خروجی‌ها را بنویسد. به این حلقه حلقه‌ی بی‌نهایت (که در میکروکنترلر «حلقه‌ی اصلی» یا super loop هم می‌گویند) می‌گویند و دو شکل معمول دارد: while (1) و for (;;). عدد ۱ همیشه «درست» است و for بدون شرط هم همیشه ادامه می‌دهد.

مثال از زندگی روزمره

نگهبان شب یک ساختمان را تصور کن. او یک‌بار اول شب چراغ‌ها و در را بررسی می‌کند (راه‌اندازی)، بعد تا صبح دور می‌زند: در را نگاه کن، حیاط را نگاه کن، دوربین‌ها را نگاه کن، دوباره از اول. این «دور زدن بی‌پایان» همان حلقه‌ی اصلی میکروکنترلر است.

برای تمرین روی PC، همان الگو را با یک راه خروج (فقط برای اینکه برنامه‌ی آزمایشی ما تمام شود) می‌نویسیم:

#include <stdio.h>

int main(void)
{
    int round_no = 0;

    for (;;) {
        round_no = round_no + 1;
        printf("round %d: read inputs, update, write outputs\n", round_no);
        if (round_no == 3) {
            break;
        }
    }
    printf("stopped after %d rounds\n", round_no);
    return 0;
}
  1. شمارنده‌ی دور. فقط برای آزمایش.
  2. for بدون شرط. هر سه بخش داخل پرانتز خالی است. شرط خالی یعنی «همیشه درست». حلقه هرگز خودش تمام نمی‌شود. روی میکروکنترلر همین ساختار را می‌بینی. for (;;) و while (1) از نظر معنا یکی هستند؛ اولی را بعضی‌ها ترجیح می‌دهند، چون بعضی ابزارها برای while (1) هشدار «شرط ثابت» می‌دهند.
  3. کار هر دور. در برنامه‌ی واقعی: خواندن ورودی‌ها (دکمه‌ها، سنسورها)، تصمیم‌گیری، نوشتن خروجی‌ها (LED، موتور).
  4. راه خروج فقط برای آزمایش. بعد از سه دور break حلقه را می‌شکند تا برنامه‌ی ما روی PC تمام شود. روی میکروکنترلر واقعی این خروج را نمی‌گذارند.
$ ./super_loop
round 1: read inputs, update, write outputs
round 2: read inputs, update, write outputs
round 3: read inputs, update, write outputs
stopped after 3 rounds

و شکل واقعی روی یک میکروکنترلر این است. اسم تابع‌ها فرضی است؛ فقط ساختار مهم است:

int main(void)
{
    clock_init();            // یک بار: تنظیم ساعت
    gpio_init();             // یک بار: تنظیم پایه‌ها

    for (;;) {               // تا وقتی برق هست
        read_inputs();
        update_logic();
        write_outputs();
    }
}
  1. راه‌اندازی. کارهایی که فقط یک‌بار لازم‌اند، قبل از حلقه. اگر داخل حلقه می‌گذاشتی، هر دور دوباره تنظیم می‌شد؛ هم اتلاف وقت و هم گاهی خطرناک (مثلا LED یا موتور مدام ریست می‌شد).
  2. حلقه‌ی اصلی. بی‌پایان. هیچ returnی بعد از آن لازم نیست، چون به آن نمی‌رسد.
  3. سه گام تکراری. ورودی‌ها را بخوان، منطق را اجرا کن، خروجی‌ها را بنویس. تمام برنامه‌های embedded ساده روی همین اسکلت ساخته می‌شوند.

این همان ساختاری است که در درس‌های ۵.۲ (STM32) و ۵.۶ (ESP32) دوباره می‌بینی. در ESP32 با ESP-IDF، تابع app_main معمولا تمام می‌شود و کارها داخل «تسک»های FreeRTOS در حلقه‌های بی‌پایان خودشان اجرا می‌شوند؛ ولی هر تسک باز هم یک for (;;) دارد.

حلقه‌ی تأخیر مشغول؛ چرا بد است؟

فرض کن می‌خواهی LED هر ثانیه چشمک بزند. ساده‌ترین فکر: «یک میلیون بار حلقه‌ی خالی بزن تا زمان بگذرد». به این کار می‌گویند انتظار مشغول (busy-wait): پردازنده وقت را با کار بیهوده «می‌سوزاند». چیزی شبیه این:

/* الگوی نامناسب؛ فقط برای شناخت */
led_on();
for (int i = 0; i < 1000000; i++) {
    /* هیچ کاری نمی‌کند */
}
led_off();
for (int i = 0; i < 1000000; i++) {
}
  1. LED را روشن کن. تابع فرضی.
  2. انتظار با شمردن. یک میلیون بار جمع کردن. زمان واقعی این حلقه به سرعت پردازنده، سطح بهینه‌سازی کامپایلر و حتی نوع دستورهای تولیدشده بستگی دارد. پس نمی‌شود از قبل فهمید چند میلی‌ثانیه است. اگر کامپایلر ببیند حلقه‌ای کاری نمی‌کند، ممکن است کلا آن را حذف کند و زمان صفر شود (علتش را در درس ۳.۶ با volatile می‌فهمی).
  3. LED را خاموش کن و باز صبر کن.

سه ایراد انتظار مشغول:

  1. دقت نامعلوم. زمان به کامپایلر، ساعت و بهینه‌سازی بستگی دارد. اگر دستگاه را روی برد دیگری ببری، زمان‌ها عوض می‌شود.
  2. کور و کر. در این مدت پردازنده به هیچ چیز واکنش نشان نمی‌دهد: نه دکمه، نه سنسور، نه فرمان UART.
  3. مصرف برق. پردازنده تمام مدت با توان کامل کار می‌کند. در دستگاه باتری‌دار مهم است.

راه بهتر را در درس ۵.۴ می‌سازیم: یک تایمر سخت‌افزاری زمان را می‌شمارد و ما فقط می‌پرسیم «چقدر گذشت؟». در ESP32 هم vTaskDelay به‌جای خشک‌شمردن، تسک را می‌خواباند تا پردازنده کار دیگری بکند. اما برای اینکه با ایده‌اش آشنا شوی، یک شکل کاملا امن از انتظار را الان یاد می‌گیریم.

حلقه‌ی انتظار با timeout

گاهی واقعا باید منتظر بمانی: مثلا سنسور بعد از روشن‌شدن چند میلی‌ثانیه طول می‌کشد تا «آماده» شود. کار درست: بپرس آماده‌ای؟ و اگر نه، دوباره بپرس؛ اما یک timeout (سقف زمانی/تعداد) هم بگذار. بدون سقف، اگر سنسور خراب باشد یا سیمش قطع شده باشد، برنامه‌ی تو تا ابد در آن حلقه می‌ماند و دستگاه «قفل» می‌کند. به این کار پرسیدن مکرر می‌گویند polling.

#include <stdio.h>

int main(void)
{
    int ready_at = 7;
    int timeout = 5;
    int attempts = 0;
    int ready = 0;

    while (attempts < timeout && !ready) {
        attempts = attempts + 1;
        if (attempts >= ready_at) {
            ready = 1;
        }
    }

    if (ready) {
        printf("sensor ready after %d checks\n", attempts);
    } else {
        printf("timeout after %d checks\n", attempts);
    }
    return 0;
}
  1. سنسور شبیه‌سازی‌شده. فرض می‌کنیم سنسور در بررسی هفتم آماده می‌شود. در برنامه‌ی واقعی این عدد را نمی‌دانیم؛ این بخش را با خواندن یک بیت وضعیت از سنسور عوض می‌کنیم.
  2. سقف. حداکثر ۵ بار می‌پرسیم.
  3. وضعیت. تعداد بررسی‌ها و پرچم «آماده شد». هر دو با صفر.
  4. شرط دوتایی. ادامه بده اگر هنوز به سقف نرسیده‌ای و سنسور هنوز آماده نیست. هر کدام نادرست شد حلقه تمام می‌شود. دو دلیل برای خروج داریم: موفقیت یا تسلیم. همین ساختار در تقریبا هر درایور واقعی هست.
  5. یک بررسی. شمارنده بالا می‌رود و اگر شرط آماده‌بودن برقرار بود پرچم را ۱ می‌کنیم.
  6. تصمیم بعد از حلقه. باید بفهمیم حلقه به کدام دلیل تمام شد. اگر ready نشد، خطای timeout. فراموش‌کردن این بررسی یکی از باگ‌های رایج است: کد بعدی فرض می‌کند سنسور آماده است، در حالی که فقط صبرمان تمام شده.
$ ./wait_timeout
timeout after 5 checks

سنسور در بررسی هفتم آماده می‌شد، ولی ما فقط ۵ فرصت دادیم، پس timeout رخ داد. اگر ready_at را ۳ کنی، پیام «sensor ready after 3 checks» را می‌بینی.

میانگین‌گیری از چند خوانش

سنسورهای واقعی نویز دارند: اگر دمای اتاق را ۵ بار پشت‌سرهم بخوانی، ۵ عدد کمی متفاوت می‌گیری. راه ساده‌ی کم کردن نویز: چند خوانش بگیر و میانگینشان را حساب کن. جمع را در یک حلقه می‌سازیم، سپس بر تعدادشان تقسیم می‌کنیم:

#include <stdio.h>

int main(void)
{
    const int n = 5;
    int total = 0;

    for (int i = 0; i < n; i++) {
        int reading = 500 + i * i;
        total = total + reading;
    }
    int average = total / n;

    printf("total = %d\n", total);
    printf("average = %d\n", average);
    return 0;
}
  1. تعداد خوانش‌ها. const چون نباید وسط کار عوض شود (درس ۲.۱).
  2. انباره‌ی جمع. با صفر.
  3. حلقه‌ی خوانش. با i < n و شروع از صفر دقیقا پنج بار می‌چرخد. هر بار یک «خوانش شبیه‌سازی‌شده» می‌سازد: ۵۰۰، ۵۰۱، ۵۰۴، ۵۰۹، ۵۱۶ و به جمع اضافه می‌کند. متغیر reading داخل حلقه ساخته می‌شود و هر دور تازه است. جمع کل بیرون حلقه می‌ماند تا دورها با هم جمع شوند.
  4. میانگین. جمع تقسیم بر تعداد. تقسیم int اعشار را دور می‌اندازد (۲۵۳۰ ÷ ۵ = ۵۰۶ دقیقا؛ ولی در حالت کلی برش می‌خورد). در میکروکنترلر هم همین تقسیم صحیح معمول است. دقت بیشتر لازم داشتی، مقیاس را بزرگ‌تر کن (درس ۴.۷).
  5. چاپ. جمع و میانگین.
$ ./average
total = 2530
average = 506
مراقب سرریز جمع باش

اگر total از نوع ۱۶ بیتی بی‌علامت بود و خوانش‌های ADC تا ۴۰۹۵ می‌رسیدند، جمع ۱۶ خوانش (۶۵۵۲۰) هنوز جا می‌شد؛ ولی جمع ۱۷ خوانش نه، و عدد بعد از ۶۵۵۳۵ دوباره از صفر شروع می‌شد. همیشه بپرس «بیشترین جمع ممکن چند است؟» و نوع را بر اساس آن انتخاب کن (درس ۲.۲).

در STM32 و ESP32 حلقه‌ها کجا می‌نشینند؟

الگوکجاچرا
for (;;) اصلیانتهای main در STM32؛ داخل هر تسک در ESP32برنامه هرگز نباید تمام شود
حلقه‌ی timeoutهر جا منتظر سخت‌افزار هستی (سنسور، بیت وضعیت UART)قطع سیم یا خرابی نباید دستگاه را قفل کند
حلقه‌ی for با شمارندهمیانگین‌گیری، ارسال N بایت، روشن کردن N LEDتکرار قابل‌پیش‌بینی
انتظار مشغولفقط تأخیرهای بسیار کوتاه (میکروثانیه) یا اولین آزمایشزمان‌بندی دقیق و کاربرد دائمی از تایمر می‌آید

حواست باشد: هر حلقه‌ی داخل حلقه‌ی اصلی، وقتی خیلی طول بکشد، بقیه‌ی برنامه را می‌خواباند. در دستگاهی که همزمان دکمه، نمایشگر و ارتباط سریال دارد، هیچ حلقه‌ای نباید ده‌ها میلی‌ثانیه پردازنده را در انحصار بگیرد. این اصل در درس‌های ۵.۳ و ۵.۴ به «وقفه» و «تایمر» می‌رسد.

آزمون این درس

حلقه‌ی for (int i = 0; i < 4; i++) بدنه‌اش را چند بار اجرا می‌کند؟

  1. ۳ بار
  2. ۵ بار
  3. ۴ بار (i برابر ۰ و ۱ و ۲ و ۳)
  4. بی‌نهایت
مقدارهای i عبارت‌اند از ۰، ۱، ۲، ۳ و وقتی ۴ شد شرط نادرست است. برای N بار تکرار: از صفر شروع کن با i < N.

اگر شرط از همان ابتدا نادرست باشد، کدام حلقه بدنه‌اش را دقیقا یک‌بار اجرا می‌کند؟

  1. while
  2. do-while
  3. for
  4. هر سه دقیقا یک بار
در do-while شرط بعد از بدنه پرسیده می‌شود، پس بدنه دست‌کم یک‌بار اجرا می‌شود.

این کد چه چاپ می‌کند؟
for (int i = 1; i <= 5; i++) {
  if (i == 2) continue;
  if (i == 4) break;
  printf("%d ", i);
}

  1. ۱ ۳
  2. ۱ ۳ ۵
  3. ۱ ۲ ۳
  4. ۱
دور ۱ چاپ می‌شود. دور ۲ با continue رد می‌شود. دور ۳ چاپ می‌شود. دور ۴ با break کل حلقه را قطع می‌کند.

چه چیزی در این حلقه اشتباه است؟
for (int i = 0; i < 3; i++);
{
  printf("hello\n");
}

  1. شرط اشتباه نوشته شده
  2. printf نمی‌تواند داخل حلقه بیاید
  3. کامپایل نمی‌شود
  4. نقطه‌ویرگول بعد از پرانتز، بدنه‌ی حلقه را «خالی» کرده است و hello فقط یک‌بار چاپ می‌شود
علامت ; بعد از for(...) یعنی بدنه یک دستور خالی است. حلقه ۳ بار بی‌کار می‌چرخد و بعد بلوک {...} فقط یک‌بار اجرا می‌شود.

چرا در میکروکنترلر «حلقه‌ی بی‌نهایت» در انتهای main عادی است ولی روی PC معمولا باگ؟

  1. چون میکروکنترلر حلقه‌ی بی‌نهایت را سریع‌تر اجرا می‌کند
  2. چون روی میکروکنترلر سیستم‌عاملی نیست که بعد از پایان main ادامه را مدیریت کند؛ برنامه باید تا وقتی برق هست کار کند
  3. چون کامپایلر ARM هشداری برای آن نمی‌دهد
  4. چون حلقه‌ی بی‌نهایت برق مصرف نمی‌کند
بعد از بازگشت از main روی میکروکنترلر کسی نیست که کار را ادامه دهد. برای همین برنامه‌ها خودشان همیشه در یک حلقه می‌مانند.

تمرین‌ها

تمرین ۱: جمع اعداد

می‌خواهیم جمع عددهای ۱ تا ۱۰ را با یک حلقه حساب کنیم، و سپس جمع فقط عددهای زوج.

  1. پیش‌بینی: بدون اجرا، جمع ۱ تا ۱۰ چند است؟ (راهنمایی: زوج‌ها ۲، ۴، ۶، ۸، ۱۰.)
  2. حل: با یک حلقه‌ی for جمع ۱ تا ۱۰ را حساب کن و چاپ کن.
  3. تغییر: جمع عددهای زوج ۲ تا ۱۰ را با i += 2 (همان i = i + 2) در قسمت گام حساب کن.
راهنمایی

الگوی sum = sum + i را از این درس یادت هست. برای جمع زوج‌ها، شمارنده را از ۲ شروع کن و در هر دور ۲ تا زیاد کن.

چه باید ببینی؟ 
$ ./sum10
sum of 1..10 = 55
sum of evens = 30

جواب قسمت الف: ۵۵. (۱+۲+...+۱۰ = ۵۵) و زوج‌ها: ۲+۴+۶+۸+۱۰ = ۳۰.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int sum_all = 0;
    int sum_even = 0;

    for (int i = 1; i <= 10; i++) {
        sum_all = sum_all + i;
    }
    for (int i = 2; i <= 10; i += 2) {
        sum_even = sum_even + i;
    }
    printf("sum of 1..10 = %d\n", sum_all);
    printf("sum of evens = %d\n", sum_even);
    return 0;
}
  1. دو انباره. هر جمع، متغیر مستقل خودش را دارد و هر دو با صفر شروع می‌شوند.
  2. جمع همه. i از ۱ تا ۱۰ (مساوی هم مجاز است چون ۱۰ باید جمع شود).
  3. جمع زوج‌ها. i از ۲ شروع می‌شود و هر بار ۲ تا جلو می‌رود: ۲، ۴، ۶، ۸، ۱۰. بعد ۱۲ می‌شود و شرط نادرست است. گام می‌تواند هر چیزی باشد، نه فقط ۱. اینجا ۲ است. یک راه دیگر: از ۱ تا ۱۰ برو و با continue فردها را رد کن.
  4. چاپ. دو نتیجه.
$ ./sum10
sum of 1..10 = 55
sum of evens = 30
تمرین ۲: سه حلقه‌ی خراب

همکارت می‌گوید «هر سه حلقه‌ام مشکل دارد». نیت او این بود که هر حلقه دقیقا سه خط چاپ کند: شماره‌های ۰، ۱، ۲.

int a = 0;
while (a < 3) {
    printf("a = %d\n", a);
}

for (int b = 0; b <= 3; b++) {
    printf("b = %d\n", b);
}

for (int c = 0; c < 3; c++);
{
    printf("c = %d\n", c);
}
  1. حلقه‌ی a: چرا تمام نمی‌شود؟ درستش کن.
  2. حلقه‌ی b: چه چیزی را چاپ می‌کند که نباید؟ درستش کن.
  3. حلقه‌ی c: چه چیزی اشتباه است؟ (راهنمایی: به کامپایل‌شدن هم فکر کن.) درستش کن.
راهنمایی

برای a: «گام» کجاست؟ برای b: دقت به <= در برابر <. برای c: علامت ; بعد از پرانتز.

چه باید ببینی؟

جواب تشخیص: (الف) گام a++ فراموش شده؛ a همیشه ۰ است و بی‌نهایت چاپ می‌کند. (ب) <= یک دور اضافه (b=3) دارد. (پ) نقطه‌ویرگول بعد از پرانتز، بدنه را خالی کرده و بلوک بعدی یک بلوک معمولی است. علاوه بر آن، c بیرون از حلقه وجود ندارد و کامپایلر خطای 'c' undeclared می‌دهد.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int a = 0;
    while (a < 3) {
        printf("a = %d\n", a);
        a++;
    }

    for (int b = 0; b < 3; b++) {
        printf("b = %d\n", b);
    }

    for (int c = 0; c < 3; c++) {
        printf("c = %d\n", c);
    }
    return 0;
}
  1. a: گام اضافه شد. a++ داخل بدنه. حالا بعد از سه دور a برابر ۳ می‌شود و شرط نادرست. در while گام روی عهده‌ی توست. در for گام در سرصفحه است و فراموش نمی‌شود؛ یکی از دلایل ترجیح for برای شمارش.
  2. b: شرط اصلاح شد. < 3 به‌جای <= 3؛ بدنه فقط برای ۰، ۱، ۲.
  3. c: نقطه‌ویرگول حذف شد. حالا بلوک بعد از پرانتز، بدنه‌ی خود حلقه است و c هم در دسترس.

تمرین ۳: چشمک‌زن و دکمه‌ی منتظر (میکروکنترلری)

روی برد، LED باید ۳ بار چشمک بزند (هر چشمک: یک روشن و یک خاموش). در PC فقط وضعیت را چاپ می‌کنیم. بعد از چشمک‌ها منتظر فشرده‌شدن دکمه می‌مانیم، ولی حداکثر ۱۰ بار می‌پرسیم.

  1. پیش‌بینی: ۳ چشمک کامل چند خط «LED ON/OFF» چاپ می‌کند؟
  2. حل: با یک حلقه‌ی for و متغیر led که با led = !led عوض می‌شود، ۳ چشمک را چاپ کن.
  3. چالش: یک حلقه‌ی انتظار با timeout بنویس: دکمه‌ی فعال-پایین (درس ۲.۴) از بررسی چهارم به بعد فشرده است (سطح ۰) و بقیه‌ی وقت ۱. اگر در ۱۰ بار پرسیدن دکمه فشرده شد، «pressed after N checks» و وگرنه «timeout» چاپ کن.
راهنمایی

برای ۳ چشمک، ۶ تغییر وضعیت داریم: حلقه‌ای که ۶ بار می‌چرخد. برای انتظار: ساختار مثل wait_timeout.c همین درس است؛ فقط شرط «آماده» را با level == 0 بساز.

چه باید ببینی؟ 
$ ./blink_wait

جواب قسمت الف: ۶ خط (۳ بار ON و ۳ بار OFF).

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int led = 0;

    for (int step = 0; step < 6; step++) {
        led = !led;
        if (led) {
            printf("LED ON\n");
        } else {
            printf("LED OFF\n");
        }
    }

    int checks = 0;
    int button_level = 1;

    while (checks < 10 && button_level != 0) {
        checks = checks + 1;
        if (checks >= 4) {
            button_level = 0;
        }
    }

    if (button_level == 0) {
        printf("pressed after %d checks\n", checks);
    } else {
        printf("timeout\n");
    }
    return 0;
}
  1. وضعیت LED. ۰ = خاموش.
  2. شش تغییر وضعیت. هر دور led را برعکس می‌کند (!led: ۰ ← ۱ و ۱ ← ۰) و وضعیت جدید را چاپ می‌کند. ۶ دور = ۳ چشمک کامل. روی برد واقعی به‌جای printf پایه‌ی LED را می‌نویسی و بین هر دو تغییر باید زمان بگذرد (درس ۵.۴). بدون آن چشمک‌ها آن‌قدر سریع‌اند که دیده نمی‌شوند.
  3. مقدار اولیه‌ی انتظار. دکمه‌ی رهاشده سطح ۱ می‌دهد (فعال-پایین).
  4. حلقه‌ی انتظار. تا وقتی کمتر از ۱۰ بار پرسیده‌ایم و دکمه فشرده نیست ادامه می‌دهیم. از بررسی چهارم دکمه «فشرده» شبیه‌سازی شده است.
  5. تفکیک دو خروج. باید چک کنیم حلقه به‌خاطر فشردن دکمه تمام شد یا به‌خاطر timeout.

حرف مربی

حلقه‌ها را همه راحت یاد می‌گیرند؛ سختی کار در «مرزها» است: شروع از ۰ یا ۱؟ < یا <=؟ آخرین مقدار چیست؟ اگر برنامه‌ات یک عدد اضافه یا کم می‌دهد، ۹۰٪ وقت‌ها مشکل مرز حلقه است. یک عادت ساده: قبل از اجرا، با N=۲ حلقه را روی کاغذ دنبال کن. و یک قانون میکروکنترلری: هر حلقه‌ی انتظار باید راه خروج (timeout) داشته باشد. سیم‌ها قطع می‌شوند، سنسورها می‌سوزند؛ دستگاهی که تا ابد منتظر می‌ماند، یک دستگاه خراب است.

خلاصه یک‌دقیقه‌ای

  • حلقه = شروع + شرط ادامه + گام. while: اول شرط. for: هر سه در یک خط. do-while: حداقل یک‌بار.
  • N بار تکرار: for (i = 0; i < N; i++). مرزها را با N کوچک وارسی کن (off-by-one).
  • break از حلقه بیرون می‌آید؛ continue فقط این دور را رد می‌کند.
  • حلقه‌ی تودرتو: تعداد کل = حاصل‌ضرب تعدادها.
  • روی میکروکنترلر for (;;) اصلی عادی است و main هرگز تمام نمی‌شود.
  • انتظار مشغول بد است (دقت نامعلوم، پردازنده کور و کر). هر حلقه‌ی انتظار سخت‌افزار باید timeout داشته باشد.

درس بعد: ۲.۶ توابع — کدهایی که بارها لازم داری را یک‌بار با نام بنویس و هر جا صدا بزن.
