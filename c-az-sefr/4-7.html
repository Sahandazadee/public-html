میکروکنترلر ماشین‌حساب علمی نیست. بعضی‌هایشان اصلا دستور «تقسیم» ندارند و بعضی‌ها اعشار را با یک کتابخانهٔ کند شبیه‌سازی می‌کنند. خبر خوب این است که برای بیشتر کارهای واقعی (خواندن سنسور، ساختن موج، بستهٔ داده، بررسی خطا) به عدد صحیح و چند ترفند نیاز داری. در این درس ریاضیِ «به‌صرفه» را یاد می‌گیری: چه چیزی گران است، چه چیزی ارزان، و چطور بدون سرریز و بدون خطا حساب کنیم.

ایدهٔ اصلی: قیمت را به سنت بنویس

فروشگاه‌ها قیمت «۱۹٫۹۹ دلار» را در پایگاه داده به‌شکل ۱۹۹۹ سنت نگه می‌دارند. چرا؟ چون با عدد صحیح هیچ خطای گردکردنی وجود ندارد: ۱۰ سنت + ۲۰ سنت همیشه دقیقا ۳۰ سنت است. اما اعشار در کامپیوتر (مبنای دو) دقیقا همین‌قدر ساده نیست:

#include <stdio.h>

int main(void)
{
    double a = 0.1;
    double b = 0.2;
    printf("float:  0.1 + 0.2 == 0.3 ? %s\n", (a + b == 0.3) ? "yes" : "no");

    int a_cent = 10;                 // ۰٫۱۰ به‌صورت ده سنت
    int b_cent = 20;                 // ۰٫۲۰ به‌صورت بیست سنت
    printf("cents:  10 + 20 == 30 ? %s\n", (a_cent + b_cent == 30) ? "yes" : "no");
    return 0;
}
  1. دو عدد اعشاری. 0.1 و 0.2 را در نوع double نگه می‌داریم. در مبنای دو، عدد ۰٫۱ مثل ۱/۳ در مبنای ده است: بی‌پایان تکرار می‌شود. کامپیوتر ناچار نزدیک‌ترین عدد قابل‌ذخیره را می‌گذارد.
  2. مقایسه. آیا a + b برابر 0.3 است؟ جمع دو مقدار «تقریبی» و مقایسه با مقدار تقریبی سوم، هم‌ارز نیست. جواب «نه» است (درس ۲.۴ دربارهٔ مقایسهٔ float گفته بود).
  3. همان مقدارها به سنت. ۱۰ و ۲۰ دو عدد صحیح‌اند و 10 + 20 دقیقا ۳۰ است.
  4. مقایسه. اینجا جواب «بله» است و همیشه هم بله می‌ماند.

هزینهٔ float: هر تراشه یک داستان دارد

اول ببینیم چرا اصلا به این ترفندها نیاز داریم. ضرب دو عدد اعشاری در C فقط یک ستاره است (a * b)، ولی روی سخت‌افزار ممکن است یک دستور باشد یا یک تابع صدها دستوری. کامپایلر arm-none-eabi-gcc را روی سه تابع ساده اجرا می‌کنیم و اسمبلی واقعی را می‌بینیم:

float  mul_f(float a, float b)   { return a * b; }
double mul_d(double a, double b) { return a * b; }
int    mul_i(int a, int b)       { return a * b; }
  1. ضرب float. تک‌دقت (۳۲ بیتی).
  2. ضرب double. دوبل‌دقت (۶۴ بیتی).
  3. ضرب int. عدد صحیح ۳۲ بیتی. این سه تابع را با سه «تراشه» ترجمه می‌کنیم و اسمبلی‌شان را با هم مقایسه می‌کنیم.

یک بار برای هستهٔ Cortex-M4F (مثل STM32F411، با واحد اعشاری FPU تک‌دقت) و یک بار برای Cortex-M0+ (بدون FPU) ساخته‌ایم. فقط دستورهای اصلی را نگه داشته‌ایم:

پس سه نکتهٔ مهم:

  • روی Cortex-M0/M0+ هر عمل float یک تابع نرم‌افزاری است (soft-float): ده‌ها تا صدها چرخهٔ ساعت به‌جای یک تا چند چرخه.
  • روی STM32F411 (M4F) و ESP32 واحد اعشاری فقط تک‌دقت است. float سریع است، ولی double هنوز نرم‌افزاری و کند است.
  • روی AVR (آردوینو Uno) هم FPU نیست. int همیشه ارزان‌ترین است.
تله: 0.1 یک double است، نه float

در C عدد اعشاری بدون پسوند double است. اگر بنویسی x * 0.1 و x از نوع float باشد، کامپایلر x را به double تبدیل می‌کند، به روش نرم‌افزاری ضرب می‌کند، و دوباره به float برمی‌گرداند. حتی روی M4F که FPU دارد! پسوند f را فراموش نکن (درس ۲.۲):

float scale_bad(float x)  { return x * 0.1;  }
float scale_good(float x) { return x * 0.1f; }
  1. نسخهٔ بد. 0.1 بدون پسوند: ضرب float × double. قانون C: وقتی دو نوع ترکیب شوند، نوع «کوچک‌تر» به بزرگ‌تر تبدیل می‌شود.
  2. نسخهٔ خوب. 0.1f: هر دو float هستند. پسوند f با یک حرف، صدها چرخه صرفه‌جویی می‌کند.
$ arm-none-eabi-gcc -mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard -O2 -S -o - lit.c
scale_bad:
    push {r3, lr}
    vmov r0, s0
    bl __aeabi_f2d
    adr r3, .L4
    ldrd r2, [r3]
    bl __aeabi_dmul
    bl __aeabi_d2f
    vmov s0, r0
    pop {r3, pc}
scale_good:
    vldr.32 s15, .L7
    vmul.f32 s0, s0, s15
    bx lr

در scale_bad سه بار تابع کتابخانه صدا زده می‌شود (__aeabi_f2d، __aeabi_dmul، __aeabi_d2f)؛ در scale_good فقط یک vmul.f32. برای پیدا کردن چنین جاهایی به کامپایلر بگو: -Wdouble-promotion. (خروجی واقعی روی همین کد: «implicit conversion from 'float' to 'double' to match other operand of binary expression».)

زیر کاپوت: FPU باید روشن شود

در Cortex-M4 واحد اعشاری بعد از reset خاموش است. اگر کدی که دستور اعشاری دارد اجرا شود و FPU روشن نشده باشد، CPU خطای «UsageFault» می‌دهد و معمولا به HardFault می‌رسد. روشن‌کردنش وظیفهٔ کد استارت‌آپ است (در فایل CMSIS شرکت ST داخل SystemInit). در درس ۵.۱ استارت‌آپ را می‌نویسیم و این نکته را دوباره می‌بینی.

ثابت‌ممیز: عدد صحیح با ممیز خیالی

ایده ساده است: یک عدد صحیح معمولی را در نظر بگیر و قرارداد کن که ممیز در جای معینی از آن قرار دارد. مثل «قیمت به سنت»: عدد ۱۹۹۹ را می‌بینیم ولی می‌دانیم منظور ۱۹٫۹۹ است. سخت‌افزار هیچ‌چیز از این قرارداد نمی‌داند؛ فقط برنامه‌نویس آن را رعایت می‌کند.

در مبنای دو، «مقیاس» یک توان دو است تا ضرب و تقسیم مقیاس با شیفت انجام شود. نام‌گذاری استاندارد Qm.n است: m بیت صحیح، n بیت کسری. مقدار واقعی = عدد ذخیره‌شده ÷ ۲n.

جمع و تفریق ساده‌اند: اگر دو عدد هم‌قالب‌اند، فقط عدد صحیحشان را جمع کن (۰٫۵ + ۰٫۲۵: ‏16384 + 8192 = 24576 که در Q15 همان ۰٫۷۵ است). ولی ضرب و تقسیم کمی مراقبت می‌خواهد. ابزارک زیر ضرب Q15 را قدم‌به‌قدم نشان می‌دهد:

حالا کد کامل. روی هر تابع دقت کن: نوع پهن‌تر، شیفت، و اشباع.

#include <stdio.h>
#include <stdint.h>

typedef int16_t q15_t;              // Q1.15: مقدار واقعی = raw / 32768
typedef int32_t q16_t;              // Q16.16: مقدار واقعی = raw / 65536

static q15_t q15_from_double(double x)
{
    double r = x * 32768.0;
    if (r >  32767.0) r =  32767.0;         // اشباع
    if (r < -32768.0) r = -32768.0;
    return (q15_t)(r < 0 ? r - 0.5 : r + 0.5);
}

static q15_t q15_mul(q15_t a, q15_t b)
{
    int32_t p = (int32_t)a * (int32_t)b;    // نتیجه Q30 است، در ۳۲ بیت جا می‌شود
    p += 1 << 14;                           // نصفِ آخرین بیتِ دورریختنی: گرد کردن
    p >>= 15;                               // برگشت به Q15
    if (p > 32767) p = 32767;               // فقط (-1)*(-1) اینجا می‌رسد
    return (q15_t)p;
}

static q16_t q16_mul(q16_t a, q16_t b)
{
    int64_t p = (int64_t)a * b;             // Q32 در ۶۴ بیت
    return (q16_t)((p + 32768) >> 16);      // گرد کردن؛ >> روی منفی در GCC حسابی است
}

static q16_t q16_div(q16_t a, q16_t b)
{
    if (b == 0) {                           // تقسیم بر صفر: اشباع، نه کرش
        return (a < 0) ? INT32_MIN : INT32_MAX;
    }
    return (q16_t)(((int64_t)a * 65536) / b);   // اول بزرگ کن، بعد تقسیم
}

/* چاپ بدون float؛ علامت را جدا می‌کنیم تا منفی‌ها هم درست چاپ شوند */
static void q16_print(q16_t v)
{
    int64_t m = v;                          // در ۶۴ بیت منفی کردن امن است
    if (m < 0) {
        putchar('-');
        m = -m;
    }
    printf("%d.%03d", (int)(m >> 16), (int)(((m & 0xFFFF) * 1000) >> 16));
}

int main(void)
{
    q15_t half = q15_from_double(0.5);
    q15_t neg  = q15_from_double(-0.75);
    q15_t m1   = q15_from_double(-1.0);

    printf("half = %d, neg = %d, m1 = %d\n", half, neg, m1);
    printf("0.5 * 0.5   -> raw %d\n", q15_mul(half, half));
    printf("0.5 * -0.75 -> raw %d\n", q15_mul(half, neg));
    printf("-1 * -1     -> raw %d (saturated)\n", q15_mul(m1, m1));

    q16_t a = (q16_t)(3.25 * 65536);        // 3.25
    q16_t b = (q16_t)(2.5  * 65536);        // 2.5
    q16_t c = q16_mul(a, b);                // 8.125
    q16_t n = q16_mul(a, -b);               // -8.125
    printf("q16: %d * %d -> %d\n", a, b, c);
    printf("as text: ");
    q16_print(c);
    printf("\nas text: ");
    q16_print(n);
    printf("\nnaive  : %d.%03d (wrong)\n", n >> 16, ((n & 0xFFFF) * 1000) >> 16);
    printf("q16: %d / %d -> %d\n", c, b, q16_div(c, b));
    return 0;
}
  1. دو نام برای دو قالب. q15_t همان int16_t است ولی نامش به خواننده می‌گوید «این ثابت‌ممیز است». اگر همه‌جا int16_t بنویسی، هیچ‌کس (حتی خودت) نمی‌فهمی کدام عدد Q15 است و کدام عدد صحیح معمولی.
  2. تبدیل از اعشار (فقط برای تست/جدول). عدد را در ۳۲۷۶۸ ضرب می‌کند، به بازهٔ مجاز می‌بُرد و به نزدیک‌ترین عدد صحیح گرد می‌کند. ۱٫۰ در Q15 قابل نمایش نیست (بیشینه ۳۲۷۶۷ است)؛ پس اشباع لازم است. در تراشه‌ای بدون FPU این تابع را روی PC اجرا کن و نتیجه را در جدول const بگذار.
  3. ضرب Q15. اول هر دو را به int32_t تبدیل می‌کنیم، ضرب می‌کنیم (Q30)، نیم واحد اضافه می‌کنیم، ۱۵ بیت شیفت می‌دهیم، و به ۱۶ بیت برمی‌گردانیم. ضرب در همان ۱۶ بیت سرریز می‌کرد. تبدیل باید قبل از ضرب باشد، نه بعد از آن (بعد از آن دیگر دیر است).
  4. حالت خاص. تنها ورودی که از بازه بیرون می‌زند ‏(-1) × (-1) = +1 است. عدد ۳۲۷۶۸ در ۱۶ بیت علامت‌دار جا نمی‌شود؛ پس به ۳۲۷۶۷ اشباع می‌کنیم. بدون این خط، نتیجه به -32768 می‌پیچید (یعنی ۱− به‌جای ۱+). این یک باگ کلاسیک صدا و کنترل است.
  5. ضرب Q16.16. حاصل‌ضرب دو عدد ۳۲ بیتی ۶۴ بیت می‌شود؛ پس از int64_t استفاده می‌کنیم، نیم واحد برای گرد کردن اضافه می‌کنیم و ۱۶ بیت راست را دور می‌ریزیم. (شیفت راستِ منفی در استاندارد «تعریف‌شده توسط پیاده‌ساز» است؛ GCC آن را حسابی انجام می‌دهد، بخش «تقسیم، شیفت و گرد کردن» را ببین.) روی Cortex-M4 ضرب ۳۲×۳۲ با نتیجهٔ ۶۴ بیتی یک دستور است؛ روی M0 چند دستور.
  6. تقسیم Q16.16. اگر مخرج صفر باشد به بیشینه/کمینه اشباع می‌کنیم (تقسیم صحیح بر صفر در C رفتار تعریف‌نشده است و روی بعضی تراشه‌ها trap می‌دهد). وگرنه اول صورت را ۶۵۵۳۶ برابر می‌کنیم و بعد تقسیم می‌کنیم. اگر اول تقسیم کنی، قسمت کسری از بین می‌رود (۸٫۱۲۵ ÷ ۲٫۵ می‌شد ۳ به‌جای ۳٫۲۵). ضرب با * 65536 نوشته شده، نه << 16، چون شیفت به چپِ عدد منفی در C رفتار تعریف‌نشده دارد.
  7. سه عدد Q15. ۰٫۵ و ‏−۰٫۷۵ و ‏−۱.
  8. چاپ خام. ‏۰٫۵×۰٫۵ = ۸۱۹۲ (یعنی ۰٫۲۵)، ‏۰٫۵×(−۰٫۷۵) = ‏−۱۲۲۸۸ (یعنی ‏−۰٫۳۷۵) و حالت اشباع.
  9. Q16.16. ۳٫۲۵ × ۲٫۵ = ۸٫۱۲۵. مقدار خام 532480 است (۸٫۱۲۵ × ۶۵۵۳۶). با -b هم ضرب می‌کنیم تا ‏−۸٫۱۲۵ (خام -532480) را برای آزمون چاپ داشته باشیم.
  10. چاپ بدون float (با علامت جدا). اول علامت را جدا می‌کنیم و قدر مطلق را در int64_t می‌گیریم؛ بعد بخش صحیح = m >> 16 و بخش کسری = (۱۶ بیت پایین × ۱۰۰۰) ÷ ۶۵۵۳۶. چرا علامت جدا؟ شیفت راست یک عدد منفی به سمت منفی‌بی‌نهایت گرد می‌شود و بخش کسری (& 0xFFFF) نسبت به همان عدد گردشدهٔ پایین حساب می‌شود: برای ‏−۸٫۱۲۵ می‌شود -9 و ۸۷۵ که کنار هم چاپ شوند «‏−۹٫۸۷۵» خوانده می‌شود؛ (‏−۹ + ۰٫۸۷۵ = ‏−۸٫۱۲۵ درست است، ولی چاپِ کنار هم غلط است.) نتیجه بدون هیچ هشدار. printf با %f روی newlib-nano معمولا پشتیبانی نمی‌شود و کد سنگینی دارد (درس ۲.۸)؛ این ترفند سبک و کافی است. int64_t برای این است که منفی‌کردن INT32_MIN هم سرریز نکند.
  11. چاپ هر دو و نمونهٔ غلط. مثبت و منفی با q16_print درست چاپ می‌شوند؛ خط «naive» همان فرمول ساده بدون جدا کردن علامت است و ‏−۹٫۸۷۵ می‌دهد.
  12. تقسیم. ۸٫۱۲۵ ÷ ۲٫۵ = ۳٫۲۵ که خام‌اش 212992 است.

تبدیل خروجی ADC: رگبار ریزه‌کاری

مبدل آنالوگ به دیجیتال (ADC) ولتاژ را به عدد تبدیل می‌کند. روی STM32F411 ADC تا ۱۲ بیت است: عدد raw بین ۰ تا ۴۰۹۵ با ولتاژ مرجع ۳٫۳ ولت (فرض ما). فرمول:

mV = raw × 3300 ÷ 4095

سه تله در این یک خط هست:

  1. سرریز میانی. 4095 × 3300 = 13 513 500. در ۳۲ بیت جا می‌شود، ولی در int ۱۶ بیتی (AVR) نه. پس قبل از ضرب به uint32_t تبدیل کن.
  2. ترتیب. ضرب اول، تقسیم آخر. اگر raw / 4095 * 3300 بنویسی، تقسیم صحیح همیشه ۰ می‌دهد (به جز خود ۴۰۹۵).
  3. گرد کردن. تقسیم صحیح می‌بُرد. با اضافه کردن نصف مقسوم‌علیه قبل از تقسیم، به نزدیک‌ترین گرد می‌شود.
#include <stdio.h>
#include <stdint.h>

#define VREF_MV 3300u
#define ADC_MAX 4095u

/* ADC 12 بیتی به میلی‌ولت، با گرد کردن به نزدیک‌ترین */
static uint32_t adc_to_mv(uint16_t raw)
{
    return ((uint32_t)raw * VREF_MV + ADC_MAX / 2u) / ADC_MAX;
}

/* همان محاسبه با بریدن (بدون گرد کردن) */
static uint32_t adc_to_mv_trunc(uint16_t raw)
{
    return ((uint32_t)raw * VREF_MV) / ADC_MAX;
}

int main(void)
{
    const uint16_t samples[] = { 0, 1, 620, 2048, 4095 };

    for (unsigned i = 0; i < sizeof samples / sizeof samples[0]; i++) {
        printf("raw=%4u  trunc=%4u mV  round=%4u mV\n",
               (unsigned)samples[i],
               (unsigned)adc_to_mv_trunc(samples[i]),
               (unsigned)adc_to_mv(samples[i]));
    }
    return 0;
}
  1. ثابت‌ها با پسوند u. ولتاژ مرجع و بیشینهٔ ADC بی‌علامت‌اند. با u عبارت raw * VREF_MV بی‌علامت می‌شود و سرریزش تعریف‌شده است؛ ضمنا تبدیل نوع مخلوط علامت‌دار/بی‌علامت پیش نمی‌آید (درس ۲.۲).
  2. تبدیل با گرد کردن. (uint32_t)raw اول، ضرب در ۳۳۰۰، جمع با ۲۰۴۷ (= ۴۰۹۵ ÷ ۲ با تقسیم صحیح)، بعد تقسیم بر ۴۰۹۵. ۲۰۴۷٫۵ با تقسیم صحیح می‌شود ۲۰۴۷. خطای این تقریب ناچیز است و نتیجه هنوز به نزدیک‌ترین گرد می‌شود.
  3. همان بدون گرد کردن. برای مقایسه.
  4. نمونه‌ها. صفر، کمترین گام، یک مقدار میانی، نصف بازه و بیشینه.
  5. چاپ هر دو نتیجه. sizeof samples / sizeof samples[0] تعداد عضوها را می‌دهد (درس ۲.۷).

سرریز: نگذار حساب‌هایت بپیچد

در درس ۲.۲ دیدی سرریز بی‌علامت می‌پیچد (wraparound) و سرریز علامت‌دار رفتار تعریف‌نشده است (درس ۶.۲ عمیق‌تر می‌گوید). در سیستمی که موتور می‌چرخاند، پیچیدنِ ناگهانی «۲۵۵ به ۰» فاجعه است: ولوم صدا از بلندترین به صفر می‌پرد، PWM ناگهان خاموش می‌شود. سه راه داری:

  1. نوع پهن‌تر. در uint32_t یا int64_t حساب کن و بعد برگردان.
  2. بررسی قبل از عمل. ببین جواب جا می‌شود یا نه. بعد انجام بده.
  3. اشباع (saturation). اگر جا نشد، به نزدیک‌ترین مقدار مجاز بچسب (به‌جای پیچیدن).
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>

/* جمع امن: قبل از جمع بررسی می‌کند که جا می‌شود یا نه */
static bool add_i32_checked(int32_t a, int32_t b, int32_t *out)
{
    if ((b > 0 && a > INT32_MAX - b) ||
        (b < 0 && a < INT32_MIN - b)) {
        return false;                       /* سرریز می‌شد */
    }
    *out = a + b;
    return true;
}

/* جمع اشباعی بی‌علامت ۸ بیتی: از ۲۵۵ رد نمی‌شود */
static uint8_t add_sat_u8(uint8_t a, uint8_t b)
{
    unsigned sum = (unsigned)a + b;         /* در نوع پهن‌تر جمع می‌کنیم */
    return (sum > 255u) ? 255u : (uint8_t)sum;
}

/* جمع اشباعی علامت‌دار ۱۶ بیتی */
static int16_t add_sat_i16(int16_t a, int16_t b)
{
    int32_t sum = (int32_t)a + b;
    if (sum > INT16_MAX) return INT16_MAX;
    if (sum < INT16_MIN) return INT16_MIN;
    return (int16_t)sum;
}

int main(void)
{
    int32_t r = 0;

    printf("wrap u8 : %u\n", (unsigned)(uint8_t)(250 + 10));
    printf("sat  u8 : %u\n", (unsigned)add_sat_u8(250, 10));
    printf("sat  i16: %d\n", add_sat_i16(30000, 5000));
    printf("sat  i16: %d\n", add_sat_i16(-30000, -5000));

    if (add_i32_checked(2000000000, 2000000000, &r)) {
        printf("sum = %ld\n", (long)r);
    } else {
        printf("overflow detected\n");
    }
    if (add_i32_checked(1000, 2000, &r)) {
        printf("sum = %ld\n", (long)r);
    }
    return 0;
}
  1. جمع علامت‌دار با بررسی. اگر b مثبت است و a بزرگ‌تر از INT32_MAX - b باشد، جواب جا نمی‌شود. برای منفی‌ها حالت قرینه. اگر جا شد در *out می‌نویسد و true برمی‌گرداند. چرا INT32_MAX - b؟ چون خودِ این تفریق هرگز از بازه بیرون نمی‌زند (وقتی b مثبت است). مقایسه را طوری نوشته‌ایم که هرگز خودش سرریز نکند. اگر می‌نوشتی a + b > INT32_MAX دیر بود؛ جمع قبلا رفتار تعریف‌نشده داشت.
  2. اشباع بی‌علامت ۸ بیتی. اول در unsigned (پهن‌تر) جمع می‌کنیم؛ اگر از ۲۵۵ بیشتر شد، ۲۵۵ برمی‌گردانیم. در C عملوندهای uint8_t قبل از جمع خودبه‌خود به int ارتقا پیدا می‌کنند (promotion، درس ۲.۲). پس خود جمع سرریز نمی‌کند؛ مشکل در ذخیرهٔ نتیجه در ۸ بیت است.
  3. اشباع علامت‌دار ۱۶ بیتی. جمع در ۳۲ بیت، بعد به بازهٔ INT16_MIN تا INT16_MAX می‌چسبانیم. این همان کاری است که یک ولوم صوتی یا کنترل‌کننده لازم دارد.
  4. نسخهٔ معمولی. (uint8_t)(250 + 10) می‌شود ۴ (چون ۲۶۰ منهای ۲۵۶).
  5. نسخهٔ اشباعی. ۲۵۵ و ‏۳۲۷۶۷ و ‏−۳۲۷۶۸.
  6. جمع ۲ میلیارد + ۲ میلیارد. جا نمی‌شود (بیشینهٔ int32_t حدود ۲٫۱۴۷ میلیارد است). تابع «سرریز» گزارش می‌کند. ۱۰۰۰ + ۲۰۰۰ درست جمع می‌شود.

ابزار آماده

GCC و Clang توابع داخلی __builtin_add_overflow(a, b, &result) و مشابه برای ضرب و تفریق دارند که سرریز را با دستور درست پردازنده تشخیص می‌دهند. وقتی فقط به کامپایلرهای GCC/Clang کار می‌کنی، خواناتر و سریع‌تر از کد دستی‌اند (اما استاندارد C11 نیستند و در MISRA ممنوع می‌شوند).

روی Cortex-M4 دستورهای اشباع سخت‌افزاری مثل SSAT و USAT هم هست (CMSIS آن‌ها را به‌شکل __SSAT و __USAT عرضه می‌کند). Cortex-M0 این دستورها را ندارد و کد C بالا لازم است.

دو تلهٔ نهان: ضرب دو uint16_t و مقایسهٔ علامت‌دار با بی‌علامت

بالا دیدی uint8_t پیش از جمع به int ارتقا می‌یابد و به همین خاطر سرریز نمی‌کند. همین قاعده برای uint16_t خطرناک می‌شود: روی Cortex-M و ESP32 که int سی‌ودو بیتی است، a * b با دو uint16_t هر دو را به int علامت‌دار تبدیل می‌کند. حاصل‌ضرب 65535 × 65535 = 4294836225 از بیشینهٔ int (۲۱۴۷۴۸۳۶۴۷) بیشتر است؛ پس سرریز علامت‌دار = رفتار تعریف‌نشده (UBSan دقیقا همین را گزارش می‌دهد؛ درس ۶.۲). با بهینه‌سازی، نتیجه پیش‌بینی‌ناپذیر می‌شود. در کد ADC/DSP که دو مقدار ۱۶ بیتی را ضرب می‌کنی، این تله واقعی است. قاعده: قبل از ضرب، دست‌کم یک طرف را به uint32_t ببر.

تلهٔ دوم: وقتی int و unsigned را مقایسه کنی، int به بی‌علامت تبدیل می‌شود و ‏-1 می‌شود ۴۲۹۴۹۶۷۲۹۵. برای Python‌کار که «عدد، عدد است» غاپرچمیرکننده است (و حلقهٔ for (size_t i = n - 1; i >= 0; i--) هرگز تمام نمی‌شود، چون size_t هیچ‌وقت منفی نمی‌شود). همین مشکل در ماکرو MAX(-1, 1u) درس ۴.۱ بود. کامپایلر با -Wsign-compare (داخل -Wextra) هشدار می‌دهد؛ هشدار را جدی بگیر.

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint16_t a = 65535, b = 65535;

    /* a * b به‌تنهایی: هر دو به int (علامت‌دار ۳۲ بیتی) ارتقا می‌یابند و جا نمی‌شود = UB */
    uint32_t good = (uint32_t)a * b;        // یک طرف را قبل از ضرب پهن کن
    printf("good = %lu\n", (unsigned long)good);

    int i = -1;
    unsigned u = 1u;
    printf("-1 < 1u : %d\n", i < u);        // -1 به unsigned تبدیل می‌شود

    size_t n = 3;
    for (size_t k = n; k-- > 0; ) {         // شمارش معکوس امن با بی‌علامت
        printf("k=%zu\n", k);
    }
    return 0;
}
  1. دو مقدار ۱۶ بیتی بیشینه. بیشترین مقدار uint16_t؛ بدترین حالت برای ضرب.
  2. ضرب امن. (uint32_t)a را قبل از ضرب می‌گیریم؛ پس b هم به uint32_t ارتقا می‌یابد و ضرب بی‌علامت ۳۲ بیتی است (که سرریزش هم تعریف‌شده است). اگر می‌نوشتی uint32_t bad = a * b; ضرب در int علامت‌دار انجام می‌شد و تبدیل به uint32_t دیر بود. این خطای رایج را اینجا عمدا اجرا نکردیم، چون رفتار تعریف‌نشده است.
  3. مقایسه. -1 < 1u نادرست (۰) است، چون ‏-1 به unsigned تبدیل می‌شود. کامپایلر هشدار -Wsign-compare می‌دهد (در این بلاک عمدا پذیرفته شده است).
  4. شمارش معکوس امن. k-- > 0 اول شرط را با مقدار فعلی می‌سنجد و بعد کم می‌کند؛ پس k هیچ‌وقت زیر صفر نمی‌رود.

تقسیم، شیفت و گرد کردن

در C99 به بعد تقسیم صحیح به سمت صفر بریده می‌شود: 7/2 = 3 و -7/2 = -3 (نه ‏−۴). ولی شیفت به راست یک عدد منفی، به سمت منفی‌بی‌نهایت می‌رود (روی GCC و همهٔ ARMها): -7 >> 1 = -4. پس «شیفت به‌جای تقسیم بر دو» برای اعداد منفی یکی نیست.

شیفت راست علامت‌دار رفتار «تعریف‌شده توسط پیاده‌ساز» دارد

استاندارد C نمی‌گوید شیفت به راست عدد منفی چه می‌کند. GCC برای ARM «شیفت حسابی» می‌کند (بیت علامت را حفظ می‌کند). کدی که به این وابسته است، قابل‌حمل نیست. ساده‌ترین راه: بنویس / 2 و به کامپایلر اعتماد کن؛ برای عدد ثابت توان دو، خودش بهترین دستور را (با اصلاح برای منفی‌ها) می‌سازد.

#include <stdio.h>
#include <stdint.h>

/* تقسیم صحیح با گرد کردن به نزدیک‌ترین (برای اعداد مثبت) */
static uint32_t div_round(uint32_t n, uint32_t d)
{
    return (n + d / 2u) / d;
}

/* نسخهٔ علامت‌دار: نیم را در جهت علامت نتیجه اضافه می‌کنیم */
static int32_t div_round_s(int32_t n, int32_t d)
{
    return (((n < 0) == (d < 0)) ? (n + d / 2) : (n - d / 2)) / d;
}

int main(void)
{
    printf("7 / 2          = %d\n", 7 / 2);
    printf("-7 / 2         = %d\n", -7 / 2);
    printf("-7 >> 1        = %d\n", -7 >> 1);
    printf("7u >> 1        = %u\n", 7u >> 1);
    printf("div_round(7,2) = %u\n", (unsigned)div_round(7, 2));
    printf("div_round(9,4) = %u\n", (unsigned)div_round(9, 4));
    printf("div_round_s(-7,2) = %d\n", div_round_s(-7, 2));
    printf("div_round_s(-9,4) = %d\n", div_round_s(-9, 4));

    printf("pct trunc = %u, pct round = %u\n",
           (unsigned)(v * 100u / mx), (unsigned)div_round(v * 100u, mx));
    return 0;
}
  1. گرد به نزدیک‌ترین (مثبت). نیمِ مقسوم‌علیه را به صورت اضافه کن، بعد تقسیم کن. (7+1)/2 = 4 و (9+2)/4 = 2 (چون ۲٫۲۵ به ۲ نزدیک‌تر است). این معادل round(n / d) است، بدون هیچ float. برای مقدارهای بسیار بزرگ (n + d/2 نزدیک بیشینه) سرریز می‌کند؛ مراقب باش.
  2. گرد به نزدیک‌ترین (علامت‌دار). اگر علامت صورت و مخرج یکی است، نیم را اضافه می‌کند؛ وگرنه کم می‌کند. جواب منفی است؛ پس برای دور شدن از صفر باید «نیم» هم منفی باشد. اگر همیشه اضافه می‌کردی، منفی‌ها به سمت صفر گرد می‌شدند و مثبت‌ها از صفر دور؛ نامتقارن!

Python // را به سمت منفی‌بی‌نهایت گرد می‌کند و باقیماندهٔ % هم‌علامت مقسوم‌علیه است. C تقسیم را به سمت صفر می‌برد و باقیمانده هم‌علامت مقسوم است. فقط برای مثبت‌ها یکی‌اند:

    int py_mod = ((a % b) + b) % b;         // مثل Python، برای b مثبت
    printf("py-like: %d\n", py_mod);

    printf("INT_MIN = %d\n", INT_MIN);
    return 0;
}

  2. باقیمانده به‌سبک Python. یک بار دیگر b را اضافه می‌کنیم و دوباره باقیمانده می‌گیریم؛ نتیجه برای b مثبت همیشه بین ۰ و b-1 است.

جدول جستجو و درون‌یابی

محاسبهٔ sin(x) با سری‌های ریاضی (یا sinf() کتابخانه‌ای) برای میکروکنترلر گران است. جایگزین قدیمی و مؤثر: یک بار حساب کن، در جدول const بگذار، هر بار فقط بخوان (جدول جستجو؛ جدول در Flash می‌ماند و RAM را نمی‌گیرد، درس ۳.۵).

مثال از زندگی روزمره

تابلوی کیلومتر کنار جاده را ببین: هر ۱۰ کیلومتر یک تابلو. اگر بدانی بین تابلوی ۴۰ و ۵۰ هستی و از تابلو ۳ کیلومتر جلو آمده‌ای، می‌گویی «حدود ۴۳». اسم این کار درون‌یابی (interpolation) خطی است: بین دو نقطهٔ معلوم، فرض می‌کنیم مقدار روی یک خط مستقیم حرکت می‌کند.

#include <stdio.h>
#include <stdint.h>
#include <math.h>

/* sin(0..90 درجه) هر ۱۰ درجه، در قالب Q15 (۳۲۷۶۷ = ۱٫۰) */
static const int16_t sin_tab[10] = {
    0, 5690, 11207, 16383, 21062, 25101, 28377, 30791, 32269, 32767
};

/* زاویه ۰ تا ۹۰ درجه؛ بین دو نقطهٔ جدول خطی درون‌یابی می‌کند */
static int16_t sin_q15(uint8_t deg)
{
    if (deg >= 90u) {
        return sin_tab[9];                  /* از انتهای جدول بیرون نزنیم */
    }
    uint8_t  i    = deg / 10u;              /* کدام بازه */
    uint8_t  frac = deg % 10u;              /* چند دهم راه رفته‌ایم (۰ تا ۹) */
    int32_t  y0   = sin_tab[i];
    int32_t  y1   = sin_tab[i + 1];
    return (int16_t)(y0 + (y1 - y0) * frac / 10);
}

int main(void)
{
    const uint8_t test[] = { 0, 5, 15, 30, 45, 60, 89, 90 };
    for (unsigned k = 0; k < sizeof test; k++) {
        printf("deg=%2u  table=%5d  exact=%7.1f\n", (unsigned)test[k],
               sin_q15(test[k]), 32767.0 * sin(test[k] * 3.14159265358979 / 180.0));
    }

    int maxerr = 0;
    for (uint8_t d = 0; d <= 90; d++) {
        int e = (int)(sin_q15(d) - 32767.0 * sin(d * 3.14159265358979 / 180.0));
        if (e < 0) e = -e;
        if (e > maxerr) maxerr = e;
    }
    printf("max error = %d of 32767\n", maxerr);
    return 0;
}
  1. جدول ۱۰ ‌نقطه‌ای. sin در زاویه‌های ۰، ۱۰، ...، ۹۰ درجه، در قالب Q15 (۳۲۷۶۷ یعنی ۱٫۰). با const در Flash می‌ماند. این عددها را یک بار با یک برنامهٔ PC ساخته‌ایم. ۱۰ عدد ۱۶ بیتی = ۲۰ بایت؛ ولی کل ۹۱ زاویه را در حافظه نگه نمی‌داریم.
  2. نگهبان انتها. اگر زاویه ۹۰ یا بیشتر بود، همان آخرین عدد را برمی‌گردانیم. بدون این خط، برای ۹۰ درجه i برابر ۹ می‌شود و sin_tab[i + 1] از جدول بیرون می‌زند (بیرون از محدوده، درس ۲.۷)؛ خطایی که کامپایلر خبر نمی‌دهد.
  3. کدام بازه و چقدر جلو. i = شمارهٔ نقطهٔ سمت چپ (زاویه÷۱۰) و frac = باقیمانده (۰ تا ۹) یعنی چند دهم راه تا نقطهٔ بعد.
  4. فرمول درون‌یابی. y0 + (y1 - y0) * frac / 10: از y0 شروع کن، frac/10 از اختلاف را اضافه کن. همهٔ محاسبات در int32_t است. ضرب قبل از تقسیم (تا اعشار از بین نرود) و در ۳۲ بیت (تا سرریز نشود): ‏(y1 - y0) * frac تا حدود ۶۰۰۰×۹ = ۵۴۰۰۰ می‌شود، که در ۱۶ بیت جا نمی‌شد.
  5. چند نمونه. جدول در برابر مقدار دقیق (با sin از math.h روی PC).
  6. بیشینهٔ خطا. روی همهٔ زاویه‌های صحیح ۰ تا ۹۰ اجرا می‌کنیم. هرگز نگو «دقتش خوب است». اندازه بگیر و عدد را بنویس. اگر ۱۲۴ از ۳۲۷۶۷ کافی نیست، جدول را ریزتر کن یا به Q31 برو.

ترتیب بایت‌ها: endianness

یک عدد ۳۲ بیتی چهار بایت است. کدام بایت در آدرس کمتر بنشیند؟ در درس‌های ۱.۲ و ۳.۳ دیدی STM32، ESP32 و PC همه little-endian هستند: کم‌ارزش‌ترین بایت اول. اما بسیاری از پروتکل‌های شبکه و چیپ‌های سنسور بایت پرارزش را اول می‌فرستند: big-endian.

مثال از زندگی روزمره

تاریخ را در ایران «۱۴۰۵/۰۷/۱۰» (سال، ماه، روز؛ بزرگ‌ترین واحد اول) می‌نویسیم، ولی در بعضی جاها «۱۰/۰۷/۱۴۰۵» (کوچک‌ترین واحد اول). هر دو درست‌اند؛ فقط باید همه قبول کنند کدام را دارند. در بایت‌ها هم همین است.

#include <stdio.h>
#include <stdint.h>

static uint32_t swap32(uint32_t x)
{
    return  (x << 24)
          | ((x & 0x0000FF00u) << 8)
          | ((x >> 8) & 0x0000FF00u)
          |  (x >> 24);
}

/* خواندن عدد ۱۶ بیتی big-endian از بافر، بدون وابستگی به ماشین */
static uint16_t read_be16(const uint8_t *p)
{
    return (uint16_t)(((uint16_t)p[0] << 8) | p[1]);
}

int main(void)
{
    uint32_t v = 0x12345678u;
    const uint8_t *b = (const uint8_t *)&v;     /* دید بایتی به همان حافظه */

    printf("bytes in memory: %02X %02X %02X %02X\n", (unsigned)b[0], (unsigned)b[1], (unsigned)b[2], (unsigned)b[3]);
    printf("swap32(0x12345678) = 0x%08lX\n", (unsigned long)swap32(v));
    printf("builtin            = 0x%08lX\n", (unsigned long)__builtin_bswap32(v));

    const uint8_t packet[] = { 0x01, 0x90, 0xFF, 0x38 };   /* دو عدد big-endian */
    printf("be16 #0 = %u\n", (unsigned)read_be16(&packet[0]));
    printf("be16 #1 = %u\n", (unsigned)read_be16(&packet[2]));
    return 0;
}
  1. جابه‌جایی چهار بایت. بایت ۰ به جای بایت ۳، بایت ۱ به جای ۲ و بالعکس، با شیفت و ماسک (درس ۳.۱). هر | یک بایت را در جای جدیدش قرار می‌دهد. ماسک‌ها فقط بایت‌های میانی را جدا می‌کنند.
  2. خواندن big-endian از بافر. بایت اول را ۸ بیت به چپ می‌بریم و با بایت دوم | می‌کنیم. این روش مستقل از ماشین است. روی little-endian و big-endian یک جواب می‌دهد. بهتر از تبدیل اشاره‌گر uint16_t* که ناهم‌ترازی و strict-aliasing دارد (درس ۳.۳).
  3. دید بایتی. اشاره‌گر uint8_t* به همان متغیر ۳۲ بیتی. خواندن حافظه با نوع بایتی همیشه مجاز است. این تنها «دید» مجاز به یک شیء با نوع دیگر است.
  4. چاپ بایت‌های حافظه. ‏78 56 34 12 یعنی little-endian.
  5. دو راه جابه‌جایی. تابع خودمان و __builtin_bswap32 (GCC/Clang) نتیجهٔ یکسان می‌دهند.
  6. بستهٔ نمونه. بایت‌های 01 90 یعنی ۴۰۰؛ ‏FF 38 یعنی ۶۵۳۳۶ (بی‌علامت). اگر این دو بایت یک عدد علامت‌دار ۱۶ بیتی بودند، جوابش -200 می‌شد.

ترفندهای بیتی: شمارش، برعکس، توان دو

شمارش بیت‌های ۱ (popcount)، وارونه‌کردن بیت‌ها و تشخیص توان دو: چند کار کوچک که مدام لازم می‌شود و با ماسک و شیفت (درس ۳.۱) سریع انجام می‌شود:

#include <stdio.h>
#include <stdint.h>

static unsigned popcount_loop(uint32_t x)
{
    unsigned n = 0;
    while (x != 0u) {
        x &= x - 1u;            /* پایین‌ترین بیت ۱ را پاک می‌کند */
        n++;
    }
    return n;
}

static uint8_t reverse8(uint8_t x)
{
    uint8_t r = 0;
    for (int i = 0; i < 8; i++) {
        r = (uint8_t)((r << 1) | (x & 1u));
        x >>= 1;
    }
    return r;
}

static int is_pow2(uint32_t x)
{
    return x != 0u && (x & (x - 1u)) == 0u;
}

int main(void)
{
    printf("popcount(0xF0F0) = %u\n", popcount_loop(0xF0F0u));
    printf("popcount(0x80000001) = %u\n", popcount_loop(0x80000001u));
    printf("builtin(0xF0F0) = %d\n", __builtin_popcount(0xF0F0u));
    printf("reverse8(0x01) = 0x%02X\n", (unsigned)reverse8(0x01));
    printf("reverse8(0x2C) = 0x%02X\n", (unsigned)reverse8(0x2C));
    printf("is_pow2: 64->%d 96->%d 0->%d\n", is_pow2(64), is_pow2(96), is_pow2(0));
    return 0;
}
  1. شمارش بیت‌های ۱ (popcount). تا وقتی عدد صفر نشده: x &= x - 1 پایین‌ترین بیت ۱ را پاک می‌کند و یکی می‌شماریم. چرا؟ x - 1 همهٔ صفرهای انتهایی را به ۱ و اولین ۱ را به ۰ تبدیل می‌کند. & با x فقط آن یک بیت را پاک می‌کند. تعداد دورها = تعداد بیت‌های ۱، نه ۳۲.
  2. وارونه کردن ۸ بیت. هر دور، پایین‌ترین بیت x را به انتهای r می‌چسباند. بعد از هشت دور، ترتیب برعکس شده. در بعضی پروتکل‌ها (مثلا UART و SPI) اول بیت پرارزش می‌آید و در بعضی اول کم‌ارزش. وقتی سخت‌افزار خلاف انتظار می‌فرستد، وارونه‌سازی کمک می‌کند.
  3. آیا توان دو است؟ عدد مثبت و x & (x-1) == 0 (فقط یک بیت ۱ دارد). اندازهٔ بافر حلقوی را در درس ۴.۵ توان دو می‌گیریم تا % N با & (N-1) جایگزین شود؛ این تابع بررسی‌اش می‌کند.

CRC-8: کد تشخیص خطا

وقتی بایت‌ها روی سیم (UART، I2C) یا رادیو جابه‌جا می‌شوند، ممکن است یک بیت خراب شود. راه ساده: به آخر بسته یک عدد کوچک «امضا» اضافه کن که از همهٔ بایت‌ها حساب شده. گیرنده دوباره حساب می‌کند؛ اگر با امضای رسیده نخواند، بسته خراب است.

مثال از زندگی روزمره

رقم آخر شمارهٔ کارت‌های بانکی یا کد ملی «رقم کنترل» است که از بقیهٔ ارقام حساب می‌شود. اگر یک رقم را اشتباه بنویسی، رقم کنترل نمی‌خواند. CRC همان ایده است، ولی با بیت‌ها و خیلی قوی‌تر.

CRC (Cyclic Redundancy Check) در اصل «باقیماندهٔ تقسیم» یک عدد بزرگ (کل پیام) بر یک چندجمله‌ای مولد در ریاضیات مبنای دو است. ولی لازم نیست ریاضی‌اش را بدانی؛ الگوریتم فقط XOR و شیفت است:

#include <stdio.h>
#include <stdint.h>
#include <stddef.h>

/* CRC-8 بیت‌به‌بیت. چندجمله‌ای x^8+x^2+x+1 = 0x07، مقدار اولیه ۰ */
static uint8_t crc8_bitwise(const uint8_t *data, size_t len, uint8_t poly, uint8_t init)
{
    uint8_t crc = init;
    for (size_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (int bit = 0; bit < 8; bit++) {
            if (crc & 0x80u) {
                crc = (uint8_t)((crc << 1) ^ poly);
            } else {
                crc = (uint8_t)(crc << 1);
            }
        }
    }
    return crc;
}

static uint8_t crc_table[256];

static void crc8_make_table(uint8_t poly)
{
    for (unsigned n = 0; n < 256u; n++) {
        uint8_t byte = (uint8_t)n;
        crc_table[n] = crc8_bitwise(&byte, 1, poly, 0);
    }
}

static uint8_t crc8_table(const uint8_t *data, size_t len)
{
    uint8_t crc = 0;
    for (size_t i = 0; i < len; i++) {
        crc = crc_table[crc ^ data[i]];
    }
    return crc;
}

int main(void)
{
    const uint8_t msg[] = { '1', '2', '3', '4', '5', '6', '7', '8', '9' };
    crc8_make_table(0x07);

    printf("crc8 bitwise = 0x%02X\n", (unsigned)crc8_bitwise(msg, sizeof msg, 0x07, 0x00));
    printf("crc8 table   = 0x%02X\n", (unsigned)crc8_table(msg, sizeof msg));
    printf("table[1..3]  = 0x%02X 0x%02X 0x%02X\n",
           (unsigned)crc_table[1], (unsigned)crc_table[2], (unsigned)crc_table[3]);

    const uint8_t w[] = { 0xBE, 0xEF };
    printf("poly 0x31 init 0xFF over BE EF = 0x%02X\n",
           (unsigned)crc8_bitwise(w, sizeof w, 0x31, 0xFF));
    return 0;
}
  1. تابع بیت‌به‌بیت. چندجمله‌ای (poly) و مقدار اولیه (init) پارامترند. crc از مقدار اولیه شروع می‌شود. دو چیپ با چندجمله‌ای یا مقدار اولیهٔ متفاوت، جواب متفاوت می‌دهند. باید دقیقا همانی را بنویسی که datasheet گفته.
  2. برای هر بایت. بایت را با crc XOR می‌کنیم.
  3. هشت بیت. اگر بیت بالا ۱ است، یک بیت شیفت به چپ و XOR با poly؛ وگرنه فقط شیفت. این همان «تقسیم» است، بیت به بیت: XOR با مولد در جایی که بیت بالا ۱ است.
  4. ساخت جدول ۲۵۶ تایی. CRC هر بایت ممکن را یک بار حساب می‌کنیم. با جدول، به‌جای ۸ دور برای هر بایت، فقط یک جست‌وجو داریم. هزینه‌اش ۲۵۶ بایت حافظه است (در Flash با const بهتر است).
  5. نسخهٔ جدولی. برای هر بایت: crc = table[crc ^ byte]. بسیار سریع.
  6. آزمون استاندارد. رشتهٔ 123456789 را CRC می‌کنیم. برای CRC-8 با چندجمله‌ای 0x07 و مقدار اولیهٔ صفر، «مقدار بررسی» شناخته‌شده 0xF4 است. هر نسخهٔ CRC را با این رشته و مقدار بررسی‌اش آزمایش می‌کنند. اگر ندهد، الگوریتم غلط است.
  7. نمونه از دنیای واقعی. بسیاری از سنسورهای شرکت Sensirion (مثل سری SHT3x) از CRC-8 با چندجمله‌ای 0x31 و مقدار اولیهٔ 0xFF استفاده می‌کنند؛ برای دو بایت BE EF جواب 0x92 می‌شود.

CRC برای خطای تصادفی خوب است، نه برای مهاجم. کسی که بسته را دستکاری می‌کند، CRC را هم دوباره حساب می‌کند. برای امنیت باید از HMAC و امضا استفاده کرد (درس ۷.۲ اشاره می‌کند).

عدد شبه‌تصادفی سبک: LFSR

گاهی یک «جریان بیت شبیه تصادفی» می‌خواهی: نویز برای آزمایش، الگوی تست برای ارتباط، پخش‌کردن رنگ LEDها. rand() کتابخانه‌ای سنگین است. یک LFSR (شیفت‌رجیستر با پس‌خوراند خطی) با چند دستور کار می‌کند: هر بار یک بیت شیفت بده و اگر بیتی که بیرون می‌افتد ۱ بود، با یک ماسک ثابت XOR کن.

#include <stdio.h>
#include <stdint.h>

/* LFSR ۱۶ بیتی نوع Galois با ماسک 0xB400 (چندجمله‌ای بیشینه‌طول) */
static uint16_t lfsr_next(uint16_t s)
{
    uint16_t lsb = s & 1u;
    s >>= 1;
    if (lsb) {
        s ^= 0xB400u;
    }
    return s;
}

int main(void)
{
    const uint16_t seed = 0xACE1u;
    uint16_t s = seed;

    printf("first states:");
    for (int i = 0; i < 5; i++) {
        s = lfsr_next(s);
        printf(" %04X", (unsigned)s);
    }
    printf("\n");

    s = seed;
    unsigned period = 0;
    do {
        s = lfsr_next(s);
        period++;
    } while (s != seed);
    printf("period = %u\n", period);
    return 0;
}
  1. یک قدم. بیت کم‌ارزش را نگه می‌داریم، یک شیفت به راست می‌دهیم، و اگر آن بیت ۱ بود XOR با 0xB400. ماسک 0xB400 از چندجمله‌ای‌ای انتخاب شده که ماشین را از همهٔ ۶۵۵۳۵ حالت غیرصفر بگذراند. اگر ماسک دیگری بگذاری، چرخه کوتاه می‌شود.
  2. بذر (seed). هر عدد غیرصفر. صفر ممنوع؛ چون از صفر شیفت و XOR هرگز به جای دیگری نمی‌رود.
  3. پنج حالت اول. دنباله بی‌نظم به‌نظر می‌رسد.
  4. طول چرخه. می‌شماریم چند قدم لازم است تا دوباره به بذر برسیم: دقیقا ۶۵۵۳۵ = ۲۱۶−۱. یعنی هر عدد ۱۶ بیتی غیرصفر دقیقا یک بار دیده می‌شود، بعد تکرار. ضمنا این یعنی قابل‌پیش‌بینی است؛ برای رمزنگاری یا شانس واقعی مناسب نیست.

  2. ‏-4 -4
  3. ‏-3 -3

کدام خط در تابع میانگین زیر باگ سرریز دارد؟

  2. نوع برگشتی uint32_t
  3. عبارت a + b (ممکن است از ۳۲ بیت رد شود و بپیچد)
  4. اعلان پارامترها
اگر a و b هر دو ۳ میلیارد باشند، مجموع ۶ میلیارد در ۳۲ بیت جا نمی‌شود و می‌پیچد. حل: a + (b - a) / 2 (اگر b ≥ a) یا uint64_t.

روی STM32 (little-endian) عدد uint32_t v = 0x12345678; در حافظه به‌ترتیب آدرس از کم به زیاد چه بایت‌هایی دارد؟

  1. ‏12 34 56 78
  2. ‏78 56 34 12
  3. ‏56 78 12 34
  4. ‏34 12 78 56
little-endian: کم‌ارزش‌ترین بایت (0x78) در کمترین آدرس. بستهٔ big-endian را با (p[0] << 8) | p[1] بخوان تا به این قضیه وابسته نباشی.

یک ADC ۱۲ بیتی با مرجع ۳٫۳ ولت داری. کدام نوشتن، مقدار میلی‌ولت را روی یک AVR (که int آن ۱۶ بیتی است) درست می‌دهد؟

  1. ‏int mv = raw * 3300 / 4095;
  2. ‏int mv = raw / 4095 * 3300;
  3. ‏uint32_t mv = (uint32_t)raw * 3300u / 4095u;
  4. ‏float mv = raw * 3.3f / 4.095f;
تبدیل به uint32_t قبل از ضرب، ضرب قبل از تقسیم. روی ۳۲ بیتی‌ها هم همین کد درست و قابل‌حمل است.

تمرین ۱: درصد باتری

#include <stdio.h>
#include <stdint.h>

#define MV_EMPTY 3000
#define MV_FULL  4200

/* درصد باتری (فرض تمرینی: خطی بین ۳۰۰۰ و ۴۲۰۰ میلی‌ولت) */
static int battery_percent(int mv)
{
    if (mv <= MV_EMPTY) return 0;
    if (mv >= MV_FULL)  return 100;
    int span = MV_FULL - MV_EMPTY;
    return ((mv - MV_EMPTY) * 100 + span / 2) / span;
}

/* نسخهٔ خراب: تقسیم زودتر از ضرب */
static int battery_percent_bad(int mv)
{
    if (mv <= MV_EMPTY) return 0;
    if (mv >= MV_FULL)  return 100;
    return (mv - MV_EMPTY) / (MV_FULL - MV_EMPTY) * 100;
}

int main(void)
{
    const int test[] = { 2900, 3000, 3300, 3600, 3900, 4100, 4300 };
    for (unsigned i = 0; i < sizeof test / sizeof test[0]; i++) {
        printf("%4d mV -> %3d %%   (bad: %3d %%)\n",
               test[i], battery_percent(test[i]), battery_percent_bad(test[i]));
    }
    return 0;
}

  3. نسخهٔ خراب. اول (mv - 3000) / 1200 تقسیم صحیح است؛ برای هر مقدار زیر ۴۲۰۰ می‌شود ۰. حاصل‌ضرب صفر است. قانون: تقسیم را همیشه آخر انجام بده مگر اینکه دلیل داشته باشی.
  4. آزمون. ۳۶۰۰ mV → ۵۰٪ و ‏۴۱۰۰ mV → ‏۹۲٪ (۹۱٫۶٧ گرد می‌شود).

/* میانگین بدون سرریز، بدون نیاز به نوع پهن‌تر */
static uint32_t avg_u32(uint32_t a, uint32_t b)
{
    return (a & b) + ((a ^ b) >> 1);      /* بیت‌های مشترک + نصفِ تفاوت */
}

static uint32_t avg_wide(uint32_t a, uint32_t b)
{

int main(void)
{
    uint32_t a = 3000000000u;
    uint32_t b = 3000000000u;
    printf("bit trick = %lu\n", (unsigned long)avg_u32(a, b));
    printf("uint64    = %lu\n", (unsigned long)avg_wide(a, b));
    printf("7 and 10  = %lu\n", (unsigned long)avg_u32(7u, 10u));
    return 0;
}
  1. ترفند بیتی. a & b بیت‌هایی است که در هر دو ۱ هستند (میانگینشان خودشان است). a ^ b بیت‌هایی که فقط در یکی ۱ هستند (میانگینشان نصف). پس میانگین = مشترک‌ها + نصف تفاوت‌ها. هیچ‌کدام از دو عبارت از ۳۲ بیت بیرون نمی‌زند؛ پس سرریز محال است. مثال: ۷ و ۱۰ → ‏(7&10)=2 و (7^10)>>1=13>>1=6 → ‏۸.
  2. راه ساده‌تر. در uint64_t جمع کن و برگردان. روی Cortex-M4 ارزان است؛ روی AVR ۸ بیتی گران.
  3. آزمون. هر دو نسخه ۳ میلیارد می‌دهند و ۷ و ۱۰ می‌شود ۸ (۸٫۵ بریده شد).
تمرین ۳: فیلتر پایین‌گذر با شیفت

خوانش ADC نویز دارد. فیلتر ساده: میانگین متحرک نمایی. acc = acc + x - (acc >> K) و خروجی acc >> K. با K = 3 تقریبا میانگین ۸ نمونهٔ اخیر است، بدون هیچ ضرب یا تقسیم.

  1. پیش‌بینی: اگر ورودی همیشه ۱۰۰۰ باشد و acc از صفر شروع کند، اولین خروجی چند است؟ (راهنمایی: ۱۰۰۰ ÷ ۸.)
  2. حل: برنامه را اجرا کن. بعد از چند قدم خروجی به ۱۰۰۰ نزدیک می‌شود؟
  3. ارتباط با سخت‌افزار: اگر ورودی ADC ۱۲ بیتی باشد (بیشینه ۴۰۹۵)، acc حداقل چند بیت باید باشد؟ آیا uint16_t کافی است؟
راهنمایی

acc در حالت پایدار برابر x << K است (اگر x ثابت بماند). برای ۱۰۰۰ می‌شود ۸۰۰۰.

خروجی هر قدم به ۱۰۰۰ نزدیک‌تر می‌شود (سرعتش با K تنظیم می‌شود). با ۱۲ قدم فقط به ۷۹۸ رسیده‌ایم؛ چون ثابت زمانی حدود ۸ قدم است.

جواب کامل با توضیح 
#include <stdio.h>
#include <stdint.h>

#define K 3                                  /* میانگین‌گیری روی ۲^۳ = ۸ نمونه */

typedef struct {
    uint16_t acc;                            /* ۱۲ بیت ADC + ۳ بیت اضافه = ۱۵ بیت */
} lpf_t;

static uint16_t lpf_update(lpf_t *f, uint16_t x)
{
    f->acc = (uint16_t)(f->acc + x - (f->acc >> K));
    return (uint16_t)(f->acc >> K);
}

int main(void)
{
    lpf_t f = { 0 };
    for (int i = 1; i <= 12; i++) {
        printf("step %2d: y = %u\n", i, (unsigned)lpf_update(&f, 1000u));
    }
    return 0;
}
  1. ثابت K. ‏2^K = تعداد نمونه‌های موثر.
  2. ساختار حالت. فقط یک عدد ۱۶ بیتی. ۱۲ بیت ADC + ۳ بیت K = ۱۵ بیت؛ بیشینه ۴۰۹۵×۸ = ۳۲۷۶۰ که در uint16_t (حتی در int16_t) جا می‌شود.
  3. به‌روز‌رسانی. ‏acc را با ورودی جدید جمع می‌کند و یک هشتم خودش را کم می‌کند. خروجی هشتمِ acc است. تفریقِ acc >> K نقش «فراموشی» را دارد. بدون آن acc همیشه بالا می‌رفت.
  4. مشاهده. ورودی ثابت ۱۰۰۰ بدهیم، خروجی آرام‌آرام بالا می‌رود: ۱۲۵، ۲۳۴، ۳۳۰، ...

همین تابع را برای Cortex-M4 (بدون main و printf) هم کامپایل می‌کنیم؛ همان کدی که در برنامهٔ واقعی می‌نشیند:

#include <stdint.h>

#define K 3                                     // ۲^۳ = ۸ نمونه

typedef struct { uint16_t acc; } lpf_t;

uint16_t lpf_update(lpf_t *f, uint16_t x)
{
    f->acc = (uint16_t)(f->acc + x - (f->acc >> K));
    return (uint16_t)(f->acc >> K);
}
  1. ثابت K. همان مقدار قبلی.
  2. ساختار حالت. همان ۱۶ بیت.
  3. تابع بیرونی. بدون static تا فایل‌های دیگر (مثلا کد وقفهٔ ADC) صدایش بزنند.
  4. به‌روزرسانی. دقیقا همان محاسبه؛ فقط بدون printf و main.
حرف مربی

در این درس همه ساده به نظر می‌رسند، ولی خطاهای واقعی از جای دیگری می‌آیند: ‏سرریز در محاسبهٔ میانی و ترتیب ضرب و تقسیم. قبل از هر فرمول ریاضی بپرس: «بزرگ‌ترین مقدار هر مرحله چند است و در نوع من جا می‌شود؟» بعد از نوشتن، با مقدارهای مرزی (صفر، بیشینه، منفی) امتحان کن. هرگز «دقتش خوب است» نگو؛ خطا را اندازه بگیر و بنویس. و اگر float می‌خواهی، اول ببین تراشه‌ات FPU دارد یا نه.

خلاصه یک‌دقیقه‌ای

  • روی M0 و AVR هر float نرم‌افزاری است. روی M4F و ESP32 فقط float (نه double) سخت‌افزاری است. 0.1 یعنی double؛ برای float بنویس 0.1f.
  • ثابت‌ممیز: عدد صحیح با ممیز خیالی. Q15 در int16_t، Q16.16 در int32_t. ضرب: نوع پهن‌تر، بعد شیفت (و گرد کردن).
  • مقیاس دهدهی (mV، دهم درجه) اغلب ساده‌ترین است. ضرب را قبل از تقسیم و در نوع پهن‌تر انجام بده. با + d/2 گرد کن.
  • سرریز را با نوع پهن‌تر، بررسی پیش از عمل، یا اشباع مهار کن. سرریز علامت‌دار رفتار تعریف‌نشده دارد.
  • تقسیم منفی‌ها به سمت صفر می‌رود؛ شیفت راست به سمت منفی بی‌نهایت. با / بنویس و به کامپایلر اعتماد کن.
  • جدول const + درون‌یابی خطی جای تابع گران را می‌گیرد؛ خطا را اندازه بگیر.
  • پروتکل‌ها اغلب big-endian‌اند: با شیفت بخوان ((p[0] << 8) | p[1]). x & (x-1) پایین‌ترین بیت ۱ را پاک می‌کند. CRC-8 و LFSR فقط XOR و شیفت‌اند.
