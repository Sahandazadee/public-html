تصور کن دستور پخت یک غذای پیچیده را هر بار که می‌خواهی بپزی، از اول تا آخر در آشپزخانه روی کاغذ بنویسی. خسته‌کننده است، و اگر یک جا اشتباه بنویسی، فقط همان یک نسخه غلط می‌ماند. آدم‌ها این مشکل را با «دفترچه رسپی» حل کردند: یک‌بار می‌نویسی، اسم می‌گذاری و هر وقت خواستی می‌گویی «رسپی قورمه‌سبزی را اجرا کن». در C این دفترچه‌ها را «تابع» می‌گویند. در این درس یاد می‌گیری تابع بسازی، صدا بزنی، و بفهمی وقتی صدایش می‌زنی درون حافظه دقیقا چه اتفاقی می‌افتد.

🎯 بعد از این درس می‌توانی

  • تابعی با پارامتر و مقدار برگشتی بنویسی و صدا بزنی
  • فرق «تعریف» و «اعلان (پروتوتایپ)» تابع را بگویی و بدانی هر کدام کجا لازم است
  • توضیح بدهی چرا تغییر پارامتر داخل تابع، متغیر بیرون را عوض نمی‌کند
  • با کشیدن «پشته فراخوانی» بگویی بازگشت (recursion) چطور کار می‌کند و چرا در میکروکنترلر خطرناک است
  • توابع کوچک کاربردی مثل clamp و map_range بنویسی و اسم‌های حرفه‌ای برایشان انتخاب کنی

🧰 پیش‌نیاز و وسایل

  • درس ۲.۱ (متغیر و حافظه) و درس ۲.۳ (عملگرها)
  • درس ۲.۴ (if)؛ چند مثال از آن استفاده می‌کند
  • درس ۲.۲ (نوع‌های uint16_t و uint32_t) برای مثال‌های آخر درس
  • یک کامپایلر روی رایانه‌ات؛ سخت‌افزار لازم نیست

ایدهٔ اصلی: ماشین نوشابه

ماشین نوشابه‌ای را در ذهنت بیاور. تو کاری به داخلش نداری: سکه می‌اندازی، دکمه را می‌زنی و نوشابه می‌گیری. ماشین یک‌بار ساخته شده و هزاران نفر روزی چندبار از آن استفاده می‌کنند، بدون اینکه هیچ‌کس دوباره «ساختن نوشابه» را یاد بگیرد.

مثال از زندگی روزمره

تابع (function) همین ماشین است. یک تکه کد است که اسم دارد، چیزهایی می‌گیرد (ورودی)، کاری انجام می‌دهد و یک چیز پس می‌دهد (خروجی). هر جای برنامه بنویسی «ماشین را صدا بزن»، همان تکه کد اجرا می‌شود. اگر بعدا خطایی در کار ماشین پیدا کنی، فقط یک جا را درست می‌کنی، نه صد جا را.

خبر خوب: تو تا حالا هم تابع دیده‌ای! printf یک تابع است که کسی دیگر نوشته و تو فقط صدایش می‌زنی. main هم یک تابع است، همان که سیستم شروع برنامه را به آن می‌سپارد. در این درس یاد می‌گیری خودت تابع بسازی.

تابع از چه تکه‌هایی ساخته می‌شود؟

وقتی یک ماشین را می‌سازی باید چهار چیز را مشخص کنی: چه چیزی پس می‌دهد، اسمش چیست، چه چیزهایی می‌گیرد، و داخلش چه کار می‌کند. در C هم همین چهار تکه را می‌نویسی:

  • نوع برگشتی: نوع چیزی که تابع پس می‌دهد. int یعنی «یک عدد صحیح پس می‌دهم». اگر چیزی پس نمی‌دهد، void (یعنی «هیچ») می‌نویسی.
  • نام: برچسب تابع، با همان قانون‌های اسم متغیر (درس ۲.۱).
  • پارامتر (parameter): «سوراخ‌های ورودی» ماشین. هر پارامتر نوع و اسم دارد و فقط داخل همان تابع شناخته می‌شود. مثل قفسه‌ای که موقع صدا زدن ساخته می‌شود.
  • آرگومان (argument): مقدار واقعی که موقع صدا زدن به پارامتر می‌دهی. در add(2, 3) اعداد ۲ و ۳ آرگومان‌اند و x و y پارامتر. (پارامتر «ظرف» است، آرگومان «چیزی که در ظرف می‌ریزی».)
  • مقدار برگشتی (return value): چیزی که تابع با return پس می‌دهد. return دو کار می‌کند: مقدار را می‌فرستد و همان لحظه تابع را تمام می‌کند. هر خطی که بعد از آن باشد اجرا نمی‌شود.

اولین تابع من

ماشین square را بسازیم و دو بار از آن استفاده کنیم. توجه کن که تعریف تابع بالای main آمده؛ دلیلش را چند بخش بعد می‌گوییم.

#include <stdio.h>

int square(int n)
{
    return n * n;
}

int main(void)
{
    int a = square(4);
    int b = square(a);
    printf("square(4) = %d\n", a);
    printf("square(16) = %d\n", b);
    return 0;
}
  1. کتابخانهٔ چاپ. برای printf، مثل همیشه.
  2. سرِ تابع. «تابعی به اسم square که یک int به نام n می‌گیرد و یک int پس می‌دهد.» آکولادها بدنه را قاب می‌گیرند. تا این‌جا هیچ‌چیز اجرا نشده. تعریف تابع فقط ماشین را می‌سازد، مثل نوشتن دستور پخت در دفترچه. غذا وقتی پخته می‌شود که کسی صدایش کند.
  3. کار تابع. n * n را حساب کن و همان را پس بده. n هر عددی باشد که صدازننده داده. اسم n فقط داخل همین آکولادها معنی دارد. متغیرِ همنام در جای دیگر، قفسهٔ دیگری است.
  4. تابع main. همان نقطهٔ شروعی که از درس‌های قبل می‌شناسی. حالا می‌فهمیم main هم تابعی است که int برمی‌گرداند و پارامتر ندارد (void یعنی «پارامتری ندارد»).
  5. صدا زدن با عدد ۴. square(4): برنامه به داخل square می‌پرد، n را می‌سازد و ۴ در آن می‌گذارد، ۱۶ حساب می‌کند و برمی‌گردد. ۱۶ همان‌جا که صدا زده بودی جای square(4) می‌نشیند و در a ذخیره می‌شود. صدا زدن تابع یک «عبارت» است که مقدار دارد. به همین دلیل می‌شود آن را سمت راست = گذاشت.
  6. آرگومان می‌تواند متغیر باشد. این بار مقدار فعلی a (یعنی ۱۶) به تابع می‌رود و ۲۵۶ برمی‌گردد. تابع نمی‌داند و نیازی ندارد بداند که مقدار از یک عدد ثابت آمده یا از متغیر. فقط یک مقدار دریافت می‌کند.
  7. چاپ نتیجه‌ها. هر کدام با %d که در درس ۲.۱ دیدی.
  8. پایان main. صفر یعنی موفقیت.
$ gcc -std=c11 -Wall -Wextra -o square square.c
$ ./square
square(4) = 16
square(16) = 256

خودت هم می‌توانی جریان را تصور کنی: برنامه از main شروع می‌شود، به square می‌پرد، برمی‌گردد و از همان جا که بود ادامه می‌دهد؛ درست مثل اینکه وسط خواندن کتاب بروی جواب سؤالی را در دفترچه بخوانی و بعد به همان سطر کتاب برگردی.

تابعی که چیزی پس نمی‌دهد، و ترتیب نوشتن

همهٔ ماشین‌ها خروجی ندارند. ماشین چاپگر فقط کاری می‌کند (کاغذ چاپ می‌کند) و «چیزی» به تو پس نمی‌دهد. چنین تابعی نوع برگشتی void دارد و لازم نیست return بنویسی. یا اگر ورودی نمی‌خواهد، داخل پرانتز void می‌گذاری: void say_hello(void).

چرا (void) و نه ()؟

در C، پرانتز خالی () در تعریف قدیمی یعنی «هر تعداد آرگومان را بپذیر و چک نکن»، که خطرناک است. (void) صریحا می‌گوید «هیچ پارامتری ندارم» و کامپایلر شمارهٔ آرگومان‌ها را چک می‌کند. در C جدید (C23) این فرق برداشته شده، ولی نوشتن (void) در همهٔ نسخه‌ها درست است و عادت خوبی است.

حالا مشکل ترتیب: کامپایلر فایل را از بالا به پایین می‌خواند. اگر main بالا باشد و add پایین‌تر، وقتی به add(2, 3) می‌رسد هنوز اسمی از آن نشنیده! راه‌حل این است که قبل از استفاده، فقط سرِ تابع را با نقطه‌ویرگول اعلام کنی. به این کار «اعلان» یا پروتوتایپ می‌گویند. پروتوتایپ یعنی: «قول می‌دهم این ماشین بعدا ساخته شود، اسمش و ورودی‌ها و خروجی‌اش این است.»

#include <stdio.h>

int add(int x, int y);
void say_hello(void);

int main(void)
{
    say_hello();
    printf("2 + 3 = %d\n", add(2, 3));
    return 0;
}

void say_hello(void)
{
    printf("hello from a function\n");
}

int add(int x, int y)
{
    return x + y;
}
  1. دو پروتوتایپ. فقط سرِ تابع + ;، بدون بدنه. حالا کامپایلر می‌داند add دو int می‌گیرد و int پس می‌دهد و say_hello نه چیزی می‌گیرد و نه چیزی پس می‌دهد. با این اطلاعات کامپایلر می‌تواند هر صدا زدن را چک کند: تعداد آرگومان درست است؟ نوعش می‌خواند؟ بدون پروتوتایپ این چک را نمی‌تواند بکند.
  2. main اول آمده. عمدا: در پروژه‌های واقعی main را بالا می‌گذارند تا خواننده اول «داستان کلی» را ببیند و بعد جزئیات را.
  3. تابع بدون خروجی. صدا زدنش فقط یک دستور است؛ چیزی برای ذخیره‌کردن نیست.
  4. تابعی که مقدار دارد، وسط عبارت. add(2, 3) جای خودش عدد ۵ می‌نشیند و printf آن را چاپ می‌کند.
  5. پایان main. با return 0;.
  6. تعریف say_hello. اینجا بدنه‌اش آمده. نوع برگشتی void است، پس return لازم نیست.
  7. تعریف add. سر تابع باید دقیقا با پروتوتایپ یکی باشد (نام، تعداد و نوع پارامترها، نوع برگشتی). اگر یکی نباشند، کامپایلر خطای «تعارض نوع‌ها» می‌دهد. این همان چک ایمنی است که پروتوتایپ برایت می‌خرد.
$ ./proto
hello from a function
2 + 3 = 5
پروتوتایپ‌ها بعدا به هدر می‌روند

در پروژه‌های بزرگ، پروتوتایپ‌ها را در فایل جدایی به نام .h (هدر) می‌گذارند و هر فایل که می‌خواهد آن توابع را صدا بزند آن را #include می‌کند. stdio.h هم همین است: فهرستی از پروتوتایپ‌های printf و دوستانش. این کار را در درس ۴.۲ کامل می‌سازیم.

آرگومان کپی می‌شود

یک سؤال مهم: وقتی تابع پارامتر را عوض می‌کند، متغیر اصلیِ من هم عوض می‌شود؟ جواب: نه. C موقع صدا زدن مقدار آرگومان را کپی می‌کند و کپی را در قفسه‌ای تازه (پارامتر) می‌گذارد. به این می‌گویند «ارسال با مقدار» (pass by value).

مثال از زندگی روزمره

یک کپی از شناسنامه‌ات را به اداره می‌دهی. اگر آنها روی کپی خط‌خطی کنند، شناسنامهٔ اصلی توی جیب تو سالم می‌ماند. پارامتر همان کپی است و متغیر اصلی، شناسنامهٔ اصل.

خودت ببین. با «بعدی» خط‌به‌خط برو و به دو قفسه x نگاه کن. دو قفسه هم‌اسم‌اند اما آدرس‌شان فرق دارد:

#include <stdio.h>

void try_to_change(int x)
{
    x = 99;
    printf("inside:  x = %d\n", x);
}

int main(void)
{
    int x = 5;
    try_to_change(x);
    printf("outside: x = %d\n", x);
    return 0;
}
  1. تابعی با پارامتر x. این x فقط داخل try_to_change وجود دارد. اسم را عمدا مثل متغیر main گذاشتیم تا نشان بدهیم دو قفسهٔ جدا هستند.
  2. تغییر پارامتر. فقط قفسهٔ کپی عوض می‌شود.
  3. چاپ داخل تابع. ۹۹ را می‌بیند، چون کپی خودش را می‌بیند.
  4. قفسهٔ اصلی و صدا زدن. ۵ در x گذاشته می‌شود و کپی آن به تابع می‌رود.
  5. چاپ بیرون. هنوز ۵. اگر C به‌جای کپی خود قفسه را می‌داد، هر تابع می‌توانست بی‌خبر متغیرهای تو را خراب کند. کپی کردن، هر تابع را از بقیه جدا نگه می‌دارد. همین جداسازی است که کد را قابل فهمیدن می‌کند.
$ ./copy_arg
inside:  x = 99
outside: x = 5
زیر کاپوت: پس چطور تابع متغیر بیرون را عوض کند؟

گاهی واقعا می‌خواهی تابع مقدار متغیر تو را تغییر بدهد (مثلا تابعی که دو متغیر را جابه‌جا می‌کند). راه‌حل این است که به‌جای خود مقدار، آدرس قفسه را به تابع بدهی: «این هم کلید کمد من، خودت داخلش را عوض کن.» این ابزار «اشاره‌گر» نام دارد و در درس ۳.۲ می‌آید. تا آن روز، تابع فقط می‌تواند با return یک نتیجه پس بدهد.

متغیر محلی و متغیر سراسری

تا اینجا همهٔ متغیرها را داخل یک تابع تعریف کردیم. به آن‌ها متغیر محلی (local) می‌گویند: وقتی تابع شروع می‌شود قفسه‌اش ساخته می‌شود، فقط خود آن تابع آن را می‌بیند و وقتی تابع تمام شد، قفسه خالی و دور انداخته می‌شود. (پارامترها هم محلی‌اند؛ برای همین در بخش قبل دو x هم‌اسم قاطی نشدند.)

ولی C اجازه می‌دهد متغیر را بیرون از همهٔ تابع‌ها هم تعریف کنی. به آن متغیر سراسری (global) می‌گویند: از لحظهٔ شروع برنامه تا پایانش زنده است و همهٔ تابع‌هایی که زیرش نوشته شده‌اند آن را می‌بینند. اگر مقدار اولیه ندهی، مقدارش صفر است (برخلاف محلی که «آشغال» دارد، درس ۲.۱).

مثال از زندگی روزمره

متغیر محلی مثل یادداشتی است که روی میز خودت می‌نویسی و آخر وقت دور می‌ریزی. متغیر سراسری مثل تختهٔ اعلانات راهرو است: همه می‌خوانندش، همه می‌توانند رویش بنویسند، و تا بردارند همان‌جا می‌ماند.

#include <stdio.h>

int counter = 0;

void count_up(void)
{
    int calls = 0;
    calls = calls + 1;
    counter = counter + 1;
    printf("calls = %d, counter = %d\n", calls, counter);
}

int main(void)
{
    count_up();
    count_up();
    count_up();
    return 0;
}
  1. متغیر سراسری. بیرون از هر تابع تعریف شده؛ پس count_up و main هر دو آن را می‌بینند و تا پایان برنامه می‌ماند. چون مقدار اولیه‌اش را صریح نوشتیم (= 0) خیالمان راحت است؛ در کد حرفه‌ای هم همین را می‌نویسند.
  2. متغیر محلی. calls هر بار که count_up صدا زده می‌شود از نو ساخته و صفر می‌شود و یکی اضافه می‌گیرد. پایان تابع قفسه را دور می‌اندازد، پس هیچ‌چیز از دفعهٔ قبل در آن نمی‌ماند.
  3. تغییر سراسری. counter هر بار یکی زیاد می‌شود و بین فراخوانی‌ها مقدارش را نگه می‌دارد.
  4. چاپ. هر دو مقدار را نشان می‌دهد تا تفاوتشان را ببینی.
  5. سه بار صدا زدن. calls همیشه ۱ می‌ماند ولی counter ۱ و ۲ و ۳ می‌شود.
$ gcc -std=c11 -Wall -Wextra -o scope scope.c
$ ./scope
calls = 1, counter = 1
calls = 1, counter = 2
calls = 1, counter = 3
سراسری = تختهٔ اعلانات؛ وسوسه‌انگیز ولی خطرناک

اگر در main بنویسی calls = 5; کامپایلر خطا می‌دهد ('calls' undeclared)، چون calls بیرون از count_up وجود ندارد. در مقابل، هر تابعی می‌تواند بی‌خبر counter را عوض کند، و وقتی عدد غلط شد پیدا کردن مقصر سخت است. قاعده: تا می‌توانی محلی بنویس و فقط برای چیزی که واقعا باید بین تابع‌ها بماند (مثل شمارندهٔ زمان یا بافر دریافت) سراسری بگذار. در میکروکنترلر سراسری‌ها تا آخر عمر برنامه یک جای ثابت از RAM را اشغال می‌کنند؛ درس ۲.۷ بیشتر می‌گوید.

اگر خراب شد چه می‌شود؟

دو اشتباه رایج توابع را ببین. اول: تعداد آرگومان‌ها را اشتباه بدهی. کامپایلر، به کمک همان پروتوتایپ یا تعریف، جلویت را می‌گیرد:

#include <stdio.h>

int add(int x, int y)
{
    return x + y;
}

int main(void)
{
    printf("%d\n", add(2));
    return 0;
}
  1. add دو پارامتر می‌خواهد. این «قرارداد» است.
  2. فقط یک آرگومان. عدد ۲ برای x هست ولی برای y چیزی نداده‌ایم. اگر C اجازه می‌داد، y یک مقدار آشغال می‌گرفت (درس ۲.۱) و جواب نامعتبر می‌شد. خطای کامپایل بهتر از باگ ساکت است.
too_few.c: In function 'main':
too_few.c:10:20: error: too few arguments to function 'add'

دوم، خطرناک‌تر: تابعی که باید مقدار پس بدهد ولی در بعضی مسیرها return ندارد.

#include <stdio.h>

int triple_if_positive(int n)
{
    if (n > 0) {
        return n * 3;
    }
}

int main(void)
{
    printf("%d\n", triple_if_positive(4));
    return 0;
}
  1. تابعی که int قول داده است. یعنی هر مسیر اجرا باید عددی پس بدهد.
  2. یک مسیر return دارد. اگر n مثبت باشد، عدد را سه‌برابر پس می‌دهد.
  3. انتهای تابع بدون return. اگر n صفر یا منفی باشد، از انتهای تابع بیرون می‌رود بدون اینکه چیزی پس بدهد. نتیجهٔ چنین تابعی در C «رفتار تعریف‌نشده» است: هر مقدار آشغالی ممکن است برگردد، و گاهی در آزمایش‌های تو درست به‌نظر می‌رسد.
$ gcc -std=c11 -Wall -Wextra -Werror=return-type -o return_missing return_missing.c
return_missing.c: In function 'triple_if_positive':
return_missing.c:8:1: error: control reaches end of non-void function [-Werror=return-type]

در حالت عادی این فقط یک هشدار (warning) است و برنامه ساخته می‌شود. ما آن را با -Werror=return-type به خطا تبدیل کردیم تا نشان بدهیم چقدر جدی است. قاعده: هشدار control reaches end of non-void function را هرگز نادیده نگیر.

پشتهٔ فراخوانی: حافظه‌ای که تابع‌ها قرض می‌گیرند

وقتی main تابعی را صدا می‌زند و آن تابع تابع دیگری را، برنامه باید یادش بماند «بعد از تمام شدن هر کدام، به کجا برگردم» و «متغیرها و پارامترهای هر تابع کجاست». این یادداشت‌ها را روی یک پشته (stack) می‌گذارد.

مثال از زندگی روزمره

یک دسته بشقاب: بشقاب تازه را همیشه روی دسته می‌گذاری و همیشه از بالا برمی‌داری. آخرین‌چیزی که گذاشتی، اولین‌چیزی است که برمی‌داری. هر صدا زدن تابع یک بشقاب (برگه) تازه روی دسته است که پارامترها و متغیرهای محلی آن تابع روی آن نوشته شده. با برگشتن تابع، بشقاب بالایی برداشته می‌شود. بهش می‌گویند پشتهٔ فراخوانی (call stack) و هر بشقاب یک «فریم» (frame).

بهترین مثال برای دیدن پشته، تابعی است که خودش را صدا می‌زند. به این بازگشت (recursion) می‌گویند. مثل فرهنگ لغتی که معنی یک کلمه را با کلمه‌های دیگرش می‌گوید و تو مجبوری کلمه‌ها را یکی‌یکی دنبال کنی تا به کلمهٔ ساده برسی. مثال کلاسیک، فاکتوریل است: 5! = 5 × 4 × 3 × 2 × 1. می‌شود آن را این‌طور گفت: «فاکتوریل n برابر است با n ضرب در فاکتوریل (n-1)، و فاکتوریل ۱ برابر ۱ است.»

#include <stdio.h>

int factorial(int n)
{
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

int main(void)
{
    printf("factorial(5) = %d\n", factorial(5));
    return 0;
}
  1. حالت پایه (base case). اگر n به ۱ رسید، بدون صدا زدن دوباره جواب بده. بدون این خط، تابع تا ابد خودش را صدا می‌زند و فریم‌ها روی هم انباشته می‌شوند تا پشته پر شود و برنامه بمیرد. هر تابع بازگشتی باید «راه توقف» داشته باشد.
  2. گام بازگشتی. factorial(n - 1) مسئله را کوچک‌تر می‌کند. تا جواب آن نیاید، ضرب انجام نمی‌شود، پس فریم فعلی منتظر می‌ماند. هر انتظار یعنی یک فریم زنده روی پشته؛ همین است که حافظه مصرف می‌کند.
  3. ماشین فاکتوریل. پارامتر n در هر فریم مقدار خودش را دارد.
  4. شروع کار. factorial(5) پنج فریم می‌سازد (۵، ۴، ۳، ۲، ۱) و بعد یکی‌یکی برمی‌گردند: ۱، ۲×۱، ۳×۲، ۴×۶، ۵×۲۴ = ۱۲۰.
$ ./fact
factorial(5) = 120
در میکروکنترلر بازگشت را با احتیاط (یا اصلا نه)

روی PC پشته چند مگابایت است. روی میکروکنترلر پشته بخشی از همان RAM کوچک است (درس ۲.۱؛ ۱۲۸ کیلوبایت در STM32F411 برای همه‌چیز) و اغلب چند صد بایت تا چند کیلوبایت به آن اختصاص داده می‌شود. اگر پشته از این مقدار بیشتر رشد کند، روی داده‌های دیگر می‌نویسد و رفتار برنامه غیرقابل‌پیش‌بینی می‌شود؛ هیچ پیام خطایی هم نمی‌گیری. به همین دلیل استانداردهای ایمنی کد (مثل MISRA C که در درس ۶.۳ می‌آید) بازگشت را ممنوع یا محدود می‌کنند. بهتر است هر مسئله‌ای که بازگشتی حل می‌شود را با for و while بنویسی.

تابع خوب چه تابعی است؟

هر کس یاد می‌گیرد تابع بنویسد، وسوسه می‌شود همه‌چیز را در یک تابع بریزد. چند قاعدهٔ حرفه‌ای:

  • هر تابع یک کار. اگر برای توضیح تابع مجبوری بگویی «و... و... و»، آن را به چند تابع بشکن. تابعی که فقط «دما را از ADC به درجه تبدیل می‌کند» را می‌شود تست کرد؛ تابعی که «می‌خواند، تبدیل می‌کند، چاپ می‌کند و LED را روشن می‌کند» را نه.
  • کوتاه باشد. اگر بدنه از یک صفحهٔ نمایشگر بلندتر شد، احتمالا چند کار می‌کند.
  • اسمش فعل باشد و کارش را بگوید: read_temperature بهتر از temp یا func1.
  • پارامترهای کم. بیش از ۴ پارامتر معمولا نشانهٔ طراحی ضعیف است (راه‌حلش struct در درس ۳.۴).

اسم‌گذاری ماژولی

در برنامهٔ میکروکنترلر ده‌ها تابع داریم: مربوط به LED، UART، سنسور، تایمر... اگر همه init و send اسم داشته باشند، معلوم نیست کدام مال کیست. پیشوند ماژول اسم را روشن می‌کند:

ضعیفبهترچرا؟
init()uart_init()معلوم است کدام قطعه راه‌اندازی می‌شود
send(c)uart_send_byte(c)پیشوند ماژول + فعل + مفعول
on()led_on()در پروژهٔ بزرگ ده چیز می‌تواند «on» شود
calc(v)adc_to_mv(v)اسم واحد ورودی و خروجی را می‌گوید

کتابخانه‌های حرفه‌ای هم همین کار را می‌کنند: در ESP-IDF همهٔ توابع GPIO با gpio_ شروع می‌شوند (مثل gpio_set_level) و در کتابخانهٔ HAL شرکت ST با HAL_GPIO_.

توابع کمکی کوچک: جعبه‌ابزار هر برنامه‌نویس

بعضی توابع کوچک را در هر پروژهٔ میکروکنترلری خواهی نوشت. سه‌تایشان را بسازیم:

  • clamp: عدد را در یک بازه «نگه می‌دارد» (مثل بست کردن سرعت موتور بین ۰ تا ۱۰۰٪).
  • map_range: عددی را از یک بازه به بازهٔ دیگر می‌برد (مثلا ADC که ۰ تا ۴۰۹۵ است را به ۰ تا ۱۰۰٪).
  • celsius_to_f: تبدیل دما، همان فرمول درس ۲.۱ ولی این‌بار در یک تابع.
#include <stdio.h>

static int clamp(int v, int lo, int hi)
{
    if (v < lo) {
        return lo;
    }
    if (v > hi) {
        return hi;
    }
    return v;
}

static int map_range(int x, int in_lo, int in_hi, int out_lo, int out_hi)
{
    return (x - in_lo) * (out_hi - out_lo) / (in_hi - in_lo) + out_lo;
}

static int celsius_to_f(int c)
{
    return c * 9 / 5 + 32;
}

int main(void)
{
    printf("clamp(150, 0, 100) = %d\n", clamp(150, 0, 100));
    printf("clamp(-7, 0, 100)  = %d\n", clamp(-7, 0, 100));
    printf("clamp(42, 0, 100)  = %d\n", clamp(42, 0, 100));
    printf("map_range(2048, 0, 4095, 0, 100) = %d\n", map_range(2048, 0, 4095, 0, 100));
    printf("celsius_to_f(100) = %d\n", celsius_to_f(100));
    return 0;
}
  1. کلمهٔ static قبل از تابع. یعنی «این تابع فقط برای همین فایل است». فایل‌های دیگر پروژه آن را نمی‌بینند. فعلا آن را مثل یک کلمهٔ جادویی بی‌ضرر بنویس؛ چندفایلی را در درس ۴.۲ می‌بینی و تا آن موقع حذفش هم مشکلی ایجاد نمی‌کند. در پروژهٔ چندفایلی (درس ۴.۲) ممکن است دو فایل هر کدام تابع کمکی clamp خودشان را داشته باشند. با static با هم نمی‌جنگند. تابع‌هایی که نمی‌خواهی بیرون بروند را همیشه static کن.
  2. clamp: دو مقایسه. اگر عدد از کف کمتر است، کف را بده؛ اگر از سقف بیشتر است، سقف را بده؛ وگرنه خود عدد را. از if با return استفاده کردیم و else ننوشتیم؛ چون return تابع را تمام می‌کند. به این سبک «شرط محافظ» می‌گویند و کد را تخت و خوانا نگه می‌دارد.
  3. map_range. اول عدد را نسبت به ابتدای بازهٔ ورودی می‌سنجد، در طول بازهٔ خروجی ضرب می‌کند، بر طول بازهٔ ورودی تقسیم می‌کند و به ابتدای بازهٔ خروجی اضافه می‌کند. فکرش کن «چند درصد راه را آمده‌ام؟»: ۲۰۴۸ از ۴۰۹۵ تقریبا نصف راه است؛ نصفِ بازهٔ خروجی (۰ تا ۱۰۰) می‌شود ۵۰. مثال دیگر: ورودی ۱۰ در بازهٔ ۰ تا ۲۰ و خروجی بازهٔ ۱۰۰ تا ۲۰۰: (۱۰−۰)×(۲۰۰−۱۰۰)÷(۲۰−۰) + ۱۰۰ = ۱۵۰، یعنی دقیقا وسط. ضرب قبل از تقسیم است تا اعشار دورریخته نشود (تقسیم صحیح، درس ۲.۳). ولی حواست به سرریز باشد: روی Arduino Uno که int دو بایتی است، 4095 × 100 از ۳۲۷۶۷ بیشتر می‌شود.
  4. celsius_to_f. همان فرمول ۲.۱، اما حالا نام دارد و در هر جا از برنامه یک خط است.
  5. main. بدنهٔ اصلی و آکولادها.
  6. سه آزمون clamp. بالا، پایین و داخل بازه.
  7. نیمهٔ ADC. ۲۰۴۸ تقریبا وسط بازه ۰ تا ۴۰۹۵ است، پس تقریبا ۵۰٪ برمی‌گردد: ۲۰۴۸ × ۱۰۰ ÷ ۴۰۹۵ = ۵۰٫۰۱ که اعشارش دور ریخته می‌شود.
  8. آخرین آزمون و پایان. آب می‌جوشد؛ ۲۱۲ درجه فارنهایت.

در STM32 و ESP32 تابع یعنی چه؟

در میکروکنترلر همه‌چیز تابع است: هر «درایور» (کدی که با یک قطعه سخت‌افزار حرف می‌زند) مجموعه‌ای از توابع است، و main فقط آنها را صدا می‌زند. دو نکته:

  • هزینهٔ صدا زدن. هر صدا زدن یک فریم روی پشته می‌سازد، آرگومان‌ها را کپی می‌کند و بعد برمی‌گردد. برای کارهای کوچک، مثل روشن کردن یک LED، این هزینه از خود کار بیشتر است.
  • راه‌حل: inline. اگر static inline بنویسی، به کامپایلر پیشنهاد می‌دهی «به‌جای پریدن به تابع، بدنه‌اش را همان‌جا که صدا زده شده کپی کن.» مثل اینکه به‌جای تماس گرفتن با رستوران، رسپی را همان‌جا روی میز خودت باز کنی.

مثال زیر برای STM32F411 است: LED کاربر (LD2) روی پایهٔ PA5 است. رجیستر GPIOA_BSRR را در درس ۳.۶ کامل می‌فهمی؛ فعلا فقط بدان نوشتن یک عدد در آن، یک پایه را روشن (بیت ۵) یا خاموش (بیت ۲۱) می‌کند. تمرکز روی شکل تابع است:

#include <stdint.h>

#define GPIOA_BSRR (*(volatile uint32_t *)0x40020018u)

static inline void led_on(void)
{
    GPIOA_BSRR = 1u << 5;
}

static inline void led_off(void)
{
    GPIOA_BSRR = 1u << 21;
}

void led_pulse(void)
{
    led_on();
    led_off();
}
  1. نوع‌های اندازه‌ثابت. برای uint32_t (درس ۲.۲).
  2. نام برای یک رجیستر. این خط یک «ماکرو» است؛ فعلا فقط بخوان: «هر جا GPIOA_BSRR نوشتم، یعنی خانهٔ ۳۲ بیتی در آدرس 0x40020018». جزئیاتش در درس‌های ۳.۶ و ۴.۱.
  3. تابع روشن‌کردن LED. نوع برگشتی void، بدون پارامتر. static inline: فقط برای این فایل و پیشنهاد کپی در محل. اسم led_on برای خواننده روشن است، در حالی که GPIOA_BSRR = 1u << 5; نه. تابع کوچک به کد معنی می‌دهد بدون آنکه هزینه‌ای داشته باشد.
  4. تابع خاموش‌کردن LED. بیت ۲۱ = (۱۶ + ۵)، یعنی «Reset کردن پایهٔ ۵».
  5. تابع ترکیبی. دو تابع کوچک را پشت هم صدا می‌زند: یک پالس کوتاه.

برای ESP32 (ESP-IDF) همین ایده با تابع آمادهٔ gpio_set_level که سازندگان ESP-IDF نوشته‌اند و تو فقط صدایش می‌زنی:

#include "driver/gpio.h"

static void led_set(int on)
{
    gpio_set_level(GPIO_NUM_2, on);
}
  1. هدر درایور GPIO. پروتوتایپ gpio_set_level اینجاست.
  2. تابع تک‌کاره. پارامتر on ۱ یا ۰ است. GPIO2 روی بسیاری از بردهای DevKit ارزان به LED وصل است (روی برد تو ممکن است فرق کند). اگر فردا LED را به پایهٔ دیگر بردی، فقط همین یک خط عوض می‌شود، نه صد جای برنامه. این است قدرت تابع.
زیر کاپوت: inline واقعا چه می‌کند؟

همان led.c را با arm-none-eabi-gcc -O1 -c ساختیم و با objdump -d خواندیم:

آزمون این درس

تابع int square(int n) را با square(4) صدا زده‌ایم. «۴» چه نام دارد و «n» چه نام؟

  1. ۴ پارامتر است و n آرگومان
  2. ۴ آرگومان است و n پارامتر
  3. ۴ مقدار برگشتی است و n آرگومان
  4. هر دو فقط «ورودی» هستند و اسم جدا ندارند
آرگومان مقدار واقعی است که هنگام صدا زدن می‌دهی؛ پارامتر ظرفی است که در تعریف تابع تعیین می‌شود تا آن را بگیرد.

خروجی این برنامه چیست؟
void bump(int v) { v = v + 1; }
int main(void) { int n = 7; bump(n); printf("%d", n); }

  1. ۸
  2. ۰
  3. برنامه کامپایل نمی‌شود
  4. ۷
پارامتر v کپی n است. افزایش v فقط کپی را عوض می‌کند و n در main همان ۷ می‌ماند.

در تابع زیر چه مشکلی هست؟
int abs_val(int x) { if (x < 0) { return -x; } }

  1. وقتی x صفر یا مثبت باشد، تابع چیزی پس نمی‌دهد و رفتارش تعریف‌نشده است
  2. اسم x برای پارامتر خیلی کوتاه است
  3. تابع نباید int برگرداند
  4. if بدون else مجاز نیست
هر مسیر اجرا در تابعی که نوع برگشتی دارد باید به return ختم شود. راه‌حل: return x; را بعد از if اضافه کن.

چرا در یک میکروکنترلر کوچک (مثل Arduino Uno با ۲ کیلوبایت RAM) بازگشت (recursion) خطرناک است؟

  1. چون باید آرایهٔ بزرگی برای نتایج ساخت
  2. چون میکروکنترلرها بازگشت را اجرا نمی‌کنند
  3. چون هر فراخوانی یک فریم روی پشته می‌سازد و عمق زیاد می‌تواند پشته را پر کند
  4. چون بازگشت خیلی کند است
پشته کوچک است و سرریزش هیچ پیام خطایی نمی‌دهد. فریم‌های عمیق روی داده‌های دیگر می‌نویسند.

اگر main بالا باشد و add پایین‌تر تعریف شود، بدون پروتوتایپ مشکل کجاست؟

  1. برنامه دو برابر کندتر اجرا می‌شود
  2. کامپایلر فایل را از بالا به پایین می‌خواند و هنگام دیدن add(...) هنوز آن را نمی‌شناسد
  3. مقدار برگشتی همیشه صفر می‌شود
  4. هیچ مشکلی نیست، ترتیب مهم نیست
پروتوتایپ چیزی است که قبل از استفاده، سر تابع را به کامپایلر معرفی می‌کند. بعد از آن مکان تعریف مهم نیست.

تمرین‌ها

تمرین ۱: بزرگ‌ترین از سه عدد

می‌خواهیم تابعی بنویسیم که بزرگ‌ترین عدد از سه عدد را پیدا کند. اما به‌جای نوشتن سه if پیچیده، از یک تابع ساده‌تر کمک بگیریم.

  1. پیش‌بینی: برای 3, 9, 5 و برای -4, -8, -1 بزرگ‌ترین کدام است؟
  2. حل: تابع max_of_two(a, b) را بنویس و سپس max_of_three را با دو بار صدا زدن آن بساز.
  3. چالش: max_of_three را بدون if (فقط با صدا زدن max_of_two) بنویس. چرا این کار ممکن است؟
راهنمایی

مقدار برگشتی max_of_two یک عدد است و می‌تواند مستقیم آرگومان تابع دیگر شود: max_of_two(max_of_two(a, b), c).

چه باید ببینی؟ 
$ ./max3
max_of_three(3, 9, 5) = 9
max_of_three(-4, -8, -1) = -1
جواب کامل با توضیح 
#include <stdio.h>

int max_of_two(int a, int b)
{
    if (a > b) {
        return a;
    }
    return b;
}

int max_of_three(int a, int b, int c)
{
    return max_of_two(max_of_two(a, b), c);
}

int main(void)
{
    printf("max_of_three(3, 9, 5) = %d\n", max_of_three(3, 9, 5));
    printf("max_of_three(-4, -8, -1) = %d\n", max_of_three(-4, -8, -1));
    return 0;
}
  1. تابع پایه. اگر a بزرگ‌تر است آن را می‌دهد و وگرنه b را.
  2. ساختن از روی تابع پایه. اول بین a و b برنده را پیدا می‌کند و بعد برنده را با c مقایسه می‌کند. هر تابع یک کار می‌کند و توابع بزرگ‌تر از ترکیب توابع کوچک‌تر ساخته می‌شوند. همین‌طور برنامه‌های چندهزارخطی را می‌سازند.
  3. دو آزمون. یکی مثبت و یکی منفی. آزمودن عددهای منفی همیشه ایده‌ی خوبی است.
$ ./max3
max_of_three(3, 9, 5) = 9
max_of_three(-4, -8, -1) = -1
تمرین ۲: باگ را پیدا کن

دوستت تابعی نوشته که میانگین دو عدد را حساب کند. برنامه کامپایل می‌شود ولی عدد درست چاپ نمی‌کند:

#include <stdio.h>

int average(int a, int b)
{
    int sum = a + b;
    sum / 2;
}

int main(void)
{
    int avg = average(10, 20);
    printf("average = %d\n", avg);
    return 0;
}
  1. هشدارها: با -Wall -Wextra کامپایل کن. کامپایلر چه دو هشداری می‌دهد؟ هر کدام به کدام خط اشاره می‌کند؟
  2. رفع باگ: نسخهٔ درست را بنویس.
  3. فکر کن: چرا این برنامه گاهی «درست» کار می‌کند و گاهی نه، هرچند خطایی نمی‌دهد؟
راهنمایی

خط ۶ را با دقت بخوان: sum / 2; یک عبارت است که حساب می‌شود ولی هیچ‌جا نمی‌رود. تابع باید مقدار را پس بدهد.

چه باید ببینی؟ 
average_bug.c: In function 'average':
average_bug.c:6:9: warning: statement with no effect [-Wunused-value]
average_bug.c:7:1: warning: control reaches end of non-void function [-Wreturn-type]

نسخهٔ درست باید average = 15 چاپ کند. اگر خود برنامهٔ باگ‌دار را اجرا کنی ممکن است عدد دیگری (مثلا ۳۰) ببینی، چون تابع بدون return مقدار تصادفی برمی‌گرداند. شمارهٔ خط‌ها هم بسته به خط‌های خالی فایل تو ممکن است یکی کم‌وزیاد باشد.

جواب کامل با توضیح

دو هشدار دیدی: خط ۶ «بی‌اثر است» چون محاسبه‌ای می‌کند که نتیجه‌اش دور ریخته می‌شود، و انتهای تابع بدون return است. باگ در واقع یکی است: return فراموش شده. در برنامه‌های PC معمولا آخرین محاسبه‌ای که در رجیستر پردازنده مانده به‌طور اتفاقی برمی‌گردد و گاهی جواب درست می‌آید؛ ولی این تصادفی است و با تغییر کامپایلر یا سطح بهینه‌سازی می‌شکند.

#include <stdio.h>

int average(int a, int b)
{
    return (a + b) / 2;
}

int main(void)
{
    int avg = average(10, 20);
    printf("average = %d\n", avg);
    return 0;
}
  1. تابع درست. جمع می‌کند، تقسیم می‌کند و نتیجه را return می‌کند؛ همه در یک خط. متغیر sum لازم نبود. گاهی ساده‌ترین اصلاح، حذف کد اضافه است.
  2. استفاده. نتیجه در avg می‌نشیند و چاپ می‌شود.
$ ./average_fixed
average = 15

هشدارها را هرگز نادیده نگیر: هر دو هشدار همین باگ را از قبل اعلام کرده بودند.

تمرین ۳: خوانش ADC به ولت و درصد

در STM32 یک ADC ۱۲ بیتی عددی بین ۰ تا ۴۰۹۵ برمی‌گرداند (۰ = صفر ولت، ۴۰۹۵ = ولتاژ مرجع). فرض می‌کنیم ولتاژ مرجع ۳٫۳ ولت است. می‌خواهیم دو تابع بسازیم: یکی تبدیل خوانش به میلی‌ولت و دیگری میلی‌ولت به درصد.

  1. پیش‌بینی: برای خوانش ۲۰۴۸ (تقریبا نیمه)، چند میلی‌ولت و چند درصد انتظار داری؟
  2. حل: توابع adc_to_mv و mv_to_percent را بنویس. برای اطمینان از سرریز، حساب را با uint32_t انجام بده. یک تابع void show(uint16_t raw) هم بساز که هر دو نتیجه را چاپ کند.
  3. فکر کن: اگر روی Arduino Uno (با int دو بایتی) حساب raw * 3300 را با int می‌نوشتی، چه بلایی سرش می‌آمد؟
راهنمایی

ولتاژ برابر است با raw × 3300 ÷ 4095 میلی‌ولت. اول ضرب کن، بعد تقسیم. قبل از ضرب raw را به uint32_t تبدیل کن تا حاصل‌ضرب (تا حدود ۱۳٫۵ میلیون) در ۳۲ بیت جا شود.

چه باید ببینی؟ 
$ ./adc
raw=   0  mv=   0  percent=  0
raw=2048  mv=1650  percent= 50
raw=4095  mv=3300  percent=100

جواب قسمت پ: ۴۰۹۵ × ۳۳۰۰ = ۱۳٬۵۱۳٬۵۰۰ که خیلی بیشتر از ۳۲٬۷۶۷ (بزرگ‌ترین int دوبایتی) است. حاصل سرریز می‌کند و عدد بی‌معنی می‌شود.

جواب کامل با توضیح 
#include <stdio.h>
#include <stdint.h>

static uint32_t adc_to_mv(uint16_t raw)
{
    return (uint32_t)raw * 3300u / 4095u;
}

static int mv_to_percent(uint32_t mv)
{
    return (int)(mv * 100u / 3300u);
}

static void show(uint16_t raw)
{
    uint32_t mv = adc_to_mv(raw);
    printf("raw=%4u  mv=%4u  percent=%3d\n", (unsigned)raw, (unsigned)mv, mv_to_percent(mv));
}

int main(void)
{
    show(0);
    show(2048);
    show(4095);
    return 0;
}
  1. هدرها. stdio.h برای چاپ و stdint.h برای نوع‌های اندازه‌ثابت.
  2. تبدیل به میلی‌ولت. (uint32_t)raw اول خوانش را ۳۲ بیتی می‌کند و بعد ضرب و تقسیم انجام می‌شود. پسوند u روی عددها یعنی «بی‌علامت». اگر تبدیل نوع نبود ولی ضرب در نوع کوچک‌تر انجام می‌شد، روی پردازنده‌های ۸ و ۱۶ بیتی سرریز می‌کرد. روی STM32 (که int سی‌ودوبیتی است) هم اصل این است که نوع را صریح و محافظه‌کارانه انتخاب کنی.
  3. تبدیل به درصد. ضرب در ۱۰۰ قبل از تقسیم بر ۳۳۰۰. نتیجه صحیح است و اعشار دور ریخته می‌شود.
  4. تابع نمایش. void است چون فقط چاپ می‌کند. دو تابع دیگر را به هم وصل می‌کند: خروجی adc_to_mv ورودی mv_to_percent می‌شود. تبدیل نوع (unsigned) برای printf است: قالب %u نوع unsigned int می‌خواهد، و uint16_t و uint32_t ممکن است با آن یکی نباشند. جزئیات را در درس ۲.۸ می‌بینیم.
  5. سه آزمون. کف، وسط و سقف: همیشه مرزها را امتحان کن.
$ ./adc
raw=   0  mv=   0  percent=  0
raw=2048  mv=1650  percent= 50
raw=4095  mv=3300  percent=100
حرف مربی

شاگردها در این درس معمولا سه جا گیر می‌کنند. اول: فکر می‌کنند تابع می‌تواند متغیر بیرون را عوض کند. تا اشاره‌گر نیاید، نمی‌تواند (تنها استثنا آرایه‌هاست که در ۲.۷ می‌آید)؛ به کپی بودن آرگومان فکر کن. دوم: پروتوتایپ و تعریف را قاطی می‌کنند. سرِ تابع با ; اعلان است و با { } تعریف. سوم: فراموش می‌کنند return بگذارند و هشدار کامپایلر را نمی‌خوانند. عادت خوب: بعد از هر کامپایل، فهرست هشدارها را از بالا بخوان. و یک تمرین ذهنی روزانه: هر وقت دیدی سه خط پشت سر هم تکرار شده‌اند، بپرس «این یک تابع نیست؟».

خلاصه یک‌دقیقه‌ای

  • تابع = ماشین با نام: ورودی (پارامتر) می‌گیرد، کاری می‌کند و با return یک چیز پس می‌دهد.
  • سر تابع: نوع_برگشتی نام(پارامترها)؛ بدنه بین { }. void یعنی «هیچ».
  • پروتوتایپ = سر تابع با ;. قبل از استفاده معرفی می‌کند تا کامپایلر تعداد و نوع آرگومان‌ها را چک کند.
  • آرگومان‌ها کپی می‌شوند؛ تغییر پارامتر متغیر بیرون را عوض نمی‌کند (تا درس اشاره‌گر؛ فقط آرایه‌ها استثنا هستند، درس ۲.۷).
  • هر صدا زدن یک فریم روی پشتهٔ RAM می‌سازد؛ بازگشت عمیق در MCU خطرناک است و به حالت پایه نیاز دارد.
  • هر تابع یک کار؛ اسم فعل‌دار با پیشوند ماژول (uart_send_byte)؛ توابع فقط‌برای‌فایل را static کن؛ برای تابع‌های کوچک سخت‌افزاری static inline بنویس.
