در درس قبل یاد گرفتی اشاره‌گر یعنی «یک عدد که آدرس یک خانه است». حالا می‌رسیم به جایی که اشاره‌گر واقعا به درد می‌خورد: راه رفتن روی حافظه. با یک اشاره‌گر می‌توانی از اولین عنصر آرایه شروع کنی، قدم‌به‌قدم جلو بروی، یک بافر ۲۵۶ بایتی را به تابع بدهی، یک رشته را تا آخرش بخوانی و حتی بایت‌های یک عدد ۳۲ بیتی را یکی‌یکی ببینی. همین مهارت است که کدهای درایور و پروتکل را ممکن می‌کند. و همین‌جا هم هست که مبتدی‌ها بیشترین باگ‌های «یک‌بار در ماه خراب می‌شود» را می‌سازند؛ پس هر قاعده را با دلیلش می‌آموزیم.

🎯 بعد از این درس می‌توانی

  • بگویی چرا a[i] و *(a + i) دقیقا یک چیزند
  • با اشاره‌گر روی آرایه راه بروی و بدانی p + 1 چند بایت جلو می‌رود
  • فرق const int *p و int *const p را از روی نوشتن بخوانی
  • بافر و طولش را درست به تابع بدهی و از تله sizeof در پارامتر بپرهیزی
  • بدانی چرا آدرس متغیر محلی را نباید برگرداند و چرا داده ناهم‌تراز خطرناک است
  • پکت را امن بخوانی؛ و (اختیاری) بایت‌های یک عدد را در حافظه ببینی (little-endian)

🧰 پیش‌نیاز و وسایل

  • درس ۳.۲ (آدرس، &، * و NULL)
  • درس ۲.۷ (آرایه و ایندکس) و ۲.۶ (توابع و پارامتر)

ایده اصلی: خیابان پلاک‌دار

یک خیابان را تصور کن که ۴ خانه پشت سر هم دارد و پلاک‌ها از ۱۰۰ شروع می‌شود. اگر به تو بگویند «از پلاک ۱۰۰ شروع کن و ۲ خانه جلوتر برو»، بی‌آنکه هیچ نقشه‌ای ببینی می‌دانی مقصد کجاست. آرایه در حافظه دقیقا همین خیابان است: عنصرها پشت سر هم و بی‌فاصله چیده شده‌اند. پس اگر آدرس اولین خانه را داشته باشی، به همه خانه‌های دیگر می‌رسی، فقط با جمع و تفریق.

مثال از زندگی روزمره

تصور کن خانه‌های آن خیابان همه هم‌اندازه‌اند، ولی «پلاک» شماره بایت است و هر خانه ۴ بایت جا دارد. پس پلاک‌ها ۱۰۰، ۱۰۴، ۱۰۸، ۱۱۲ هستند. وقتی می‌گویی «یک خانه جلوتر»، منظورت ۱ پلاک نیست، ۴ پلاک است. C همین کار را برایت می‌کند: p + 1 یعنی «یک عنصر جلوتر»، نه «یک بایت جلوتر». اندازه یک عنصر را از نوع اشاره‌گر می‌فهمد.

آرایه و اشاره‌گر: دو روی یک سکه

در C اگر اسم یک آرایه را در بیشتر جاها بنویسی، کامپایلر آن را به آدرس اولین عنصر تبدیل می‌کند. یعنی a همان &a[0] می‌شود. به این تبدیل خودکار می‌گویند تبدیل آرایه به اشاره‌گر (به انگلیسی array decay). استثناها را کمی بعد می‌بینی؛ فعلا مهم این است که می‌شود نوشت:

int a[4] = {10, 20, 30, 40};
int *p = a;        /* یعنی int *p = &a[0]; */

و از آن لحظه p به اولین قفسه اشاره می‌کند. حالا سه راه برای رسیدن به عنصر شماره ۲ داری، و هر سه یک چیزند:

نوشتارمعنیمقدار
a[2]عنصر شماره ۲ آرایه۳۰
*(a + 2)دو عنصر جلوتر از آدرس a برو، آنجا را بخوان۳۰
*(p + 2)همان کار، با اشاره‌گر p۳۰
p[2]براکت روی اشاره‌گر هم کار می‌کند۳۰

در واقع کامپایلر a[i] را همان لحظه به *(a + i) ترجمه می‌کند. براکت فقط یک نوشتار کوتاه و خوانا است. حالا ببین با کد واقعی:

#include <stdio.h>

int main(void)
{
    int a[4] = {10, 20, 30, 40};
    int *p = a;                    // اشاره‌گر به عنصر اول

    printf("a[2]     = %d\n", a[2]);
    printf("*(a + 2) = %d\n", *(a + 2));
    printf("*(p + 2) = %d\n", *(p + 2));
    printf("p[2]     = %d\n", p[2]);
    printf("bytes between p and p+1: %d\n", (int)((char *)(p + 1) - (char *)p));
    printf("elements between p and p+3: %d\n", (int)((p + 3) - p));
    return 0;
}
  1. کتابخانه چاپ. فقط برای printf لازم است.
  2. تابع main. همه کد بین آکولادها به ترتیب از بالا به پایین اجرا می‌شود.
  3. آرایه چهارتایی. چهار قفسه int پشت سر هم در حافظه، با مقدارهای ۱۰ تا ۴۰. «پشت سر هم» تضمین C است. بدون این تضمین حساب اشاره‌گر معنی نداشت.
  4. اشاره‌گر به اولین عنصر. اسم a به آدرس a[0] تبدیل می‌شود و در p می‌نشیند. نیازی به & نیست. اگر &a می‌نوشتی، آدرس کل آرایه بود که نوع دیگری دارد (اشاره‌گر به آرایه چهارتایی). اشتباه رایج است.
  5. راه اول: براکت. عنصر شماره ۲ (سومین قفسه).
  6. راه دوم: حساب روی اسم آرایه. a + 2 آدرس عنصر ۲ است و ستاره مقدار آن را می‌خواند. پرانتز لازم است. *a + 2 یعنی «مقدار a[0] را بخوان، بعد ۲ تا جمع کن» که ۱۲ می‌شود، نه ۳۰.
  7. راه سوم: حساب روی p. همان چیز با اشاره‌گر.
  8. راه چهارم: براکت روی اشاره‌گر. p[2] یعنی *(p + 2). به همین دلیل می‌توانی تابعی که اشاره‌گر می‌گیرد را مثل آرایه استفاده کنی.
  9. فاصله بر حسب بایت. هر دو اشاره‌گر را به char * تبدیل می‌کنیم (char یک بایت است)، پس تفاضل آنها بایت می‌شود: ۴. این‌جا نشان می‌دهد p + 1 یک بایت نیست، یک int است.
  10. فاصله بر حسب عنصر. تفاضل دو اشاره‌گر از یک نوع، «چند عنصر فاصله» است: ۳، نه ۱۲.
  11. پایان.

روی اشاره‌گر فقط چند عمل معنی دارد، و همه از قانون «گام = اندازه یک عنصر» می‌آیند:

قانون «یکی بعد از آخر»

فقط این آدرس‌ها مجازند: عنصرهای خود آرایه، و یک خانه بعد از آخرین عنصر (فقط برای مقایسه؛ خواندنش ممنوع است). مثلا برای int a[4] آدرس a + 4 را می‌شود ساخت و با آن مقایسه کرد، ولی *(a + 4) خواندن بیرون آرایه است. رفتن به a + 5 یا a - 1 حتی بدون خواندن هم طبق استاندارد C رفتار تعریف‌نشده است. دلیل: کامپایلر مجاز است فرض کند اشاره‌گر هیچ‌وقت از آرایه‌اش بیرون نمی‌رود و بر اساس همین فرض بهینه‌سازی کند. مثال واقعی: بررسی «سرریز» به شکل if (p + len < p) را ممکن است بهینه‌ساز حذف کند، چون طبق قاعده p + len هیچ‌وقت نمی‌تواند از p کوچک‌تر باشد.

نمونه‌ای ببین که این قانون را عملا به کار می‌برد: اشاره‌گر end را «یکی بعد از آخر» می‌گیریم و تا وقتی p < end جلو می‌رویم. این الگو در کد C حرفه‌ای بسیار رایج است چون شماره ایندکس لازم ندارد.

#include <stdio.h>

int main(void)
{
    int data[5] = {3, 8, 1, 9, 4};
    int *end = data + 5;           // یکی بعد از آخرین عنصر
    int sum = 0;
    int max = data[0];

    for (int *p = data; p < end; p++) {
        sum += *p;
        if (*p > max) {
            max = *p;
        }
    }
    printf("sum = %d, max = %d\n", sum, max);
    return 0;
}
  1. داده. آرایه پنج‌تایی.
  2. اشاره‌گر پایان. data + 5 یعنی آدرسی که یک قفسه بعد از آخرین عنصر است. فقط برای مقایسه به‌کار می‌رود. ما هرگز *end را نمی‌خوانیم. همین «یکی بعد از آخر» تنها آدرس بیرونی است که استاندارد می‌گذارد بسازی.
  3. مجموع و بیشینه. max را با اولین عنصر شروع می‌کنیم، نه با صفر. اگر همه عددها منفی باشند، شروع با صفر جواب غلط می‌دهد.
  4. حلقه با اشاره‌گر. p از اول شروع می‌کند، تا وقتی به end نرسیده ادامه می‌دهد و هر دور یک عنصر جلو می‌رود (p++). شرط < است نه <=. با <= یک دور اضافه اجرا می‌شود و *end خوانده می‌شود، یعنی خواندن بیرون آرایه.
  5. مقدار عنصر جاری. *p عنصری است که p الان روی آن ایستاده.
  6. به‌روز کردن بیشینه. اگر عنصر جاری بزرگ‌تر بود جایگزین می‌شود.
  7. چاپ. ۳+۸+۱+۹+۴ = ۲۵ و بزرگ‌ترین ۹.

وقتی آرایه را به تابع می‌دهی، فقط آدرس می‌رود

در درس ۲.۶ دیدی پارامتر تابع کپی آرگومان است. اگر آرایه ۲۵۶ بایتی را کپی می‌کرد، در میکروکنترلر (که RAM کم دارد) گران بود. C این کار را نمی‌کند: وقتی اسم آرایه را به تابع می‌دهی، همان تبدیل به اشاره‌گر رخ می‌دهد و فقط آدرس اولین عنصر کپی می‌شود. یعنی تابع روی خود آرایه اصلی کار می‌کند، نه یک کپی.

نتیجه‌اش یک تله بزرگ است: تابع دیگر نمی‌داند آرایه چند عنصر دارد. یک اشاره‌گر فقط یک آدرس است. ببین کامپایلر چه می‌گوید وقتی داخل تابع از sizeof استفاده می‌کنیم:

#include <stdio.h>

static void show(int arr[4])
{
    printf("inside function: %zu\n", sizeof(arr));
}

int main(void)
{
    int a[4] = {1, 2, 3, 4};
    printf("in main: %zu\n", sizeof(a));
    show(a);
    return 0;
}
  1. پارامتر به شکل آرایه. int arr[4] در پارامتر تابع فقط ظاهر آرایه دارد؛ کامپایلر آن را int *arr می‌بیند. عدد ۴ نادیده گرفته می‌شود. پارامتر آرایه‌ای وجود ندارد چون کپی کردن آرایه گران است. این نوشتار فقط یک «راهنمای خواننده» است.
  2. sizeof روی اشاره‌گر. جواب اندازه اشاره‌گر است (۴ بایت روی STM32 و ESP32، ۸ روی PC ۶۴ بیتی)، نه ۱۶ بایت آرایه. gcc این اشتباه را می‌شناسد و هشدار می‌دهد. ما هشدار را با -Werror=sizeof-array-argument به خطا تبدیل کردیم تا آن را ببینی.
  3. در تابع صاحب آرایه. اینجا a واقعا آرایه است و sizeof(a) می‌شود ۱۶ (چهار int چهار بایتی).
  4. صدا زدن. show(a) فقط آدرس اولین عنصر را می‌فرستد.

آرایه کِی «اشاره‌گر نمی‌شود»؟ و &a چه نوعی دارد؟

تبدیل خودکار آرایه به اشاره‌گر سه استثنا دارد؛ در این سه جا اسم آرایه هنوز «کل آرایه» است:

جانتیجه
sizeof aاندازهٔ کل آرایه (۱۶ بایت برای چهار int)، نه اشاره‌گر
&aآدرس کل آرایه؛ نوعش int (*)[4] است («اشاره‌گر به آرایهٔ چهارتایی از int»)، نه int *
رشتهٔ ثابت برای مقداردهی آرایه: char s[] = "Hi";متن در آرایه کپی می‌شود (اشاره‌گر ساخته نمی‌شود)

تفاوت &a و a در گام است: آدرس هر دو یکی است، ولی a + 1 یک عنصر جلو می‌رود و &a + 1 یک آرایهٔ کامل:

#include <stdio.h>

int main(void)
{
    int a[4] = {10, 20, 30, 40};
    int *p = a;
    int (*whole)[4] = &a;

    printf("sizeof a = %zu\n", sizeof a);
    printf("sizeof *whole = %zu\n", sizeof *whole);
    printf("a + 1 moves %td bytes\n", (char *)(a + 1) - (char *)a);
    printf("&a + 1 moves %td bytes\n", (char *)(&a + 1) - (char *)&a);
    printf("(*whole)[2] = %d, p[2] = %d\n", (*whole)[2], p[2]);
    return 0;
}
  1. دو دید به یک آرایه. p آدرس اولین عنصر است (int *)؛ whole آدرس کل آرایه است (int (*)[4]). پرانتز دور *whole لازم است؛ بدون آن int *whole[4] یعنی «آرایهٔ چهارتایی از اشاره‌گر».
  2. sizeof. هر دو ۱۶ می‌شوند، چون sizeof a و sizeof *whole هر دو «کل آرایه» را می‌سنجند.
  3. گام. اختلاف آدرس را به‌صورت بایت (با تبدیل به char *) می‌شماریم: ۴ و ۱۶.
  4. رسیدن به مقدار. برای عنصر شمارهٔ ۲ از راه whole اول ستاره می‌زنیم تا آرایه شود ((*whole)) و بعد اندیس.

قاعده: بافر را همیشه همراه طولش بفرست

هر تابعی که آرایه یا بافر می‌گیرد باید دو پارامتر داشته باشد: اشاره‌گر و تعداد عنصرها، مثل (const uint8_t *data, size_t len). نوع size_t نوع مخصوص اندازه و شمارش است (بی‌علامت). طول را همان جایی حساب کن که آرایه واقعی است، با sizeof a / sizeof a[0] برای تعداد عنصر یا sizeof a برای تعداد بایت.

const و اشاره‌گر: دو قفل متفاوت

در درس ۲.۱ دیدی const قفسه را قفل می‌کند. با اشاره‌گر دو چیز داریم که می‌شود قفل کرد: خود اشاره‌گر (که آدرس دارد) و چیزی که به آن اشاره می‌کند. مثل کارت دسترسی: یکی می‌گوید «به این اتاق فقط نگاه کن، چیزی را جابه‌جا نکن» و دیگری می‌گوید «این کارت فقط به همین یک اتاق می‌خورد و به اتاق دیگر عوض نمی‌شود».

نوشتارخواندن از راست به چپعوض کردن *pعوض کردن p
int *pp اشاره‌گر است به intمجازمجاز
const int *pp اشاره‌گر است به int که فقط‌خواندنی استممنوعمجاز
int *const pp یک اشاره‌گر ثابت است به intمجازممنوع
const int *const pاشاره‌گر ثابت به int فقط‌خواندنیممنوعممنوع

ترفند حفظ کردن: هر const به چیزی که «سمت چپش» است می‌چسبد (اگر چیزی سمت چپش نبود، به سمت راست). در int *const p کلمه const به * چسبیده، یعنی خود اشاره‌گر ثابت است. در const int *p چیزی سمت چپ نیست، پس به int می‌چسبد؛ داده فقط‌خواندنی است. نوشتن int const *p هم دقیقا همان const int *p است.

ببین کامپایلر هر کدام را چطور می‌گیرد:

#include <stdio.h>

int main(void)
{

#include <stdint.h>
#include <stdio.h>

static uint8_t checksum(const uint8_t *data, size_t len)
{
    uint8_t sum = 0;
    for (size_t i = 0; i < len; i++) {
        sum = (uint8_t)(sum + data[i]);
    }
    return sum;
}

int main(void)
{
    const uint8_t packet[] = {0x01, 0x02, 0xFF, 0x10};
    uint8_t cs = checksum(packet, sizeof packet);
    printf("checksum = 0x%02X\n", cs);
    return 0;
}
  1. بافر به‌علاوه طول. const uint8_t *data یعنی «آدرس بایت‌هایی که فقط می‌خوانم» و size_t len تعدادشان. static یعنی تابع فقط در همین فایل دیده می‌شود. const در امضای تابع مثل برچسب روی جعبه است: هرکس ببیند می‌داند این تابع داده‌اش را نمی‌شکند. کامپایلر هم اگر خودت اشتباها بنویسی data[i] = 0 خطا می‌دهد.
  2. بدنه تابع.
  3. مجموع اولیه. صفر؛ مثل همیشه متغیر بدون مقدار اولیه نمی‌گذاریم.
  4. جمع بایت‌ها. هر بایت با data[i] خوانده می‌شود (همان *(data + i)). حاصل جمع به uint8_t برمی‌گردد، پس از ۲۵۵ که بگذرد دور می‌زند (مثل ساعت). cast صریح (uint8_t) نشان می‌دهد این کوتاه شدن عمدی است. جمع دو uint8_t در C ابتدا به int تبدیل می‌شود (درس ۲.۲).
  5. آرایه const. بسته چهار بایتی. روی MCU چنین جدول ثابتی می‌تواند در Flash بماند.
  6. صدا زدن با sizeof. اینجا packet واقعا آرایه است و sizeof packet می‌شود ۴. آرایه به const uint8_t * تبدیل می‌شود. طول را در جایی حساب کردیم که آرایه هنوز آرایه است، نه اشاره‌گر.

void *: اشاره‌گر بدون نوع

گاهی تابعی می‌خواهی که «هر نوع بافری» بگیرد: کپی بایت‌ها، ارسال روی UART، پر کردن با صفر. کتابخانه استاندارد برای این کار void * دارد. اشاره‌گر void * یعنی «آدرس چیزی، ولی نمی‌گویم چه نوعی». چون نوع ندارد، اندازه گام هم ندارد: نه می‌شود با آن ستاره زد (*p) و نه p + 1 نوشت (در استاندارد C مجاز نیست). برای کار کردن با محتوایش باید اول آن را به اشاره‌گر بایتی تبدیل کنی. در C این تبدیل از void * به هر اشاره‌گر دیگر خودکار است. (gcc به‌عنوان افزونه به void * هم گام ۱ بایتی می‌دهد و p + 1 را می‌پذیرد؛ در کد واقعی زیاد می‌بینی، ولی استاندارد نیست و با -Wpedantic هشدار می‌گیرد؛ خودت از uint8_t * استفاده کن.)

#include <stdint.h>
#include <stdio.h>

static void copy_bytes(void *dst, const void *src, size_t n)
{
    uint8_t *d = dst;
    const uint8_t *s = src;
    while (n > 0) {
        *d++ = *s++;
        n--;
    }
}

int main(void)
{
    int32_t from[3] = {7, 8, 9};
    int32_t to[3] = {0, 0, 0};
    copy_bytes(to, from, sizeof from);
    printf("%d %d %d\n", (int)to[0], (int)to[1], (int)to[2]);
    return 0;
}
  1. امضای تابع. مقصد void *dst (هر نوع)، مبدأ const void *src (هر نوع، فقط‌خواندنی) و n تعداد بایت. const فقط روی مبدأ است چون تابع آن را نمی‌نویسد. این دقیقا شبیه امضای memcpy در string.h است.
  2. بدنه تابع.
  3. دید بایتی. دو اشاره‌گر بایتی می‌سازیم تا بتوانیم یکی‌یکی جلو برویم. uint8_t * گام ۱ بایتی دارد. فقط با اشاره‌گری که اندازه عنصرش را می‌داند می‌توان جلو رفت؛ void * این را نمی‌داند. توجه کن const را در s نگه داشتیم تا از داده مبدأ محافظت شود.
  4. حلقه کپی. تا وقتی بایتی مانده: *d++ = *s++; یعنی «بایت جاری s را در جای جاری d بنویس، بعد هر دو یک قدم جلو برو». n-- شمارنده را کم می‌کند. *d++ یعنی *(d++): اول مقدار قبلی اشاره‌گر برای ستاره استفاده می‌شود، بعد اشاره‌گر جلو می‌رود. این عبارت کوتاه در کد C خیلی رایج است.
  5. دو آرایه. از نوع int32_t؛ هر کدام ۳ عنصر ۴ بایتی = ۱۲ بایت.
  6. صدا زدن. to و from خودکار به void * تبدیل می‌شوند و طول را به بایت می‌دهیم: sizeof from = ۱۲. اشتباه رایج: گذاشتن تعداد عنصرها (۳) به‌جای تعداد بایت‌ها؛ آن‌وقت فقط ۳ بایت (یک عنصر و کمی بیشتر) کپی می‌شود.
  7. چاپ. نشان می‌دهد هر سه عنصر رسیده‌اند.

هزینه void *: کامپایلر دیگر نمی‌تواند نوع را چک کند. اگر آدرس یک float را بدهی و فکر کنی int است، هیچ هشداری نمی‌گیری. پس فقط وقتی به آن پناه ببر که واقعا «هر نوعی» می‌خواهی.

یک نکتهٔ مهم: copy_bytes بالا فرض می‌کند مبدأ و مقصد هم‌پوشانی ندارند. اگر ممکن است دو بافر روی هم بیفتند (مثلا جابه‌جاکردن داده‌ها داخل یک آرایه)، memcpy رفتار تعریف‌نشده دارد و باید memmove بنویسی؛ آن بایت‌ها را به ترتیب درست کپی می‌کند.

#include <stdio.h>

static size_t my_strlen(const char *s)
{
    const char *p = s;
    while (*p != '\0') {
        p++;
    }
    return (size_t)(p - s);
}

int main(void)
{
    const char *name = "STM32";
    char buf[] = "ESP32";
    buf[0] = 'e';
    printf("%s has %zu chars\n", name, my_strlen(name));
    printf("%s has %zu chars\n", buf, my_strlen(buf));
    return 0;
}
  1. strlen خودمان. اشاره‌گر s را نگه می‌داریم و یک کپی p از آن جلو می‌بریم؛ آخر فاصله p - s همان طول است. چون s را عوض نمی‌کنیم، فاصله را می‌توان حساب کرد. تفاضل دو اشاره‌گر در همان آرایه، تعداد عنصر است و نوعش ptrdiff_t (علامت‌دار) است؛ با cast به size_t می‌بریمش.
  2. شروع. const char *p = s;: دومین اشاره‌گر به همان جا؛ const چون فقط می‌خوانیم.
  3. تا رسیدن به NUL. تا وقتی حرف جاری '\0' نیست، یک گام جلو. اگر رشته '\0' نداشته باشد (مثلا بافری که کامل پر شده)، حلقه از آرایه بیرون می‌رود و هر چیزی را می‌خواند تا به یک صفر برسد؛ سرریز خواندن.
  4. اشاره‌گر به literal. name فقط به متن ثابت اشاره می‌کند و const جلوی نوشتن اشتباهی را می‌گیرد.
  5. آرایه قابل‌تغییر. متن در buf کپی می‌شود و حرف اول را عوض می‌کنیم؛ اشکالی ندارد. اگر همین کار را روی name می‌کردی (بدون const هم کامپایل می‌شود!)، روی PC معمولا برنامه می‌افتد و روی میکروکنترلر متن در Flash است و نوشتن بی‌اثر یا HardFault می‌شود.

ادامه برای کنجکاوها: آرایهٔ دوبعدی، آرایه‌ای از رشته‌ها، و const با دو ستاره

آرایهٔ دوبعدی در C فقط «آرایه‌ای از آرایه‌ها» است و ردیف‌به‌ردیف پشت هم می‌نشیند. اسم آن به اشاره‌گر به ردیف تبدیل می‌شود، نه اشاره‌گر به int: برای int m[2][3] نوع m می‌شود int (*)[3]. برای جدول‌ها و فریم‌بافر مفید است. آرایه‌ای از اشاره‌گرها هم برای فهرست رشته‌ها رایج است: const char *names[] یعنی هر عنصر یک اشاره‌گر به متن.

#include <stdio.h>

int main(void)
{
    int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int (*row)[3] = m;
    const char *names[] = {"red", "green", "blue"};

    printf("%d %d\n", row[1][2], *(*(m + 1) + 2));
    printf("%zu %zu\n", sizeof m[0], sizeof m);
    printf("%s %c\n", names[1], names[2][0]);
    return 0;
}
  1. جدول و اشاره‌گر به ردیف. m دو ردیف سه‌تایی است؛ row اشاره‌گر به یک ردیف است و row + 1 یک ردیف کامل (۱۲ بایت) جلو می‌رود.
  2. آرایهٔ رشته‌ها. سه اشاره‌گر، هرکدام به یک متن ثابت.
  3. دو راه برای m[1][2]. هر دو ۶ می‌دهند: row[1][2] و *(*(m + 1) + 2).
  4. اندازه. sizeof m[0] یک ردیف (۱۲ بایت) و sizeof m کل جدول (۲۴ بایت) است.
  5. رشته‌ها. names[1] کل متن «green» و names[2][0] حرف اول «blue» است.

ادامه برای کنجکاوها: بایت‌ترتیب (little-endian) و دیدن بایت‌های یک عدد

بایت‌های یک عدد را ببین

یک uint32_t چهار بایت است. در حافظه کدام بایت اول می‌آید؟ در STM32، ESP32 و PC (x86) کم‌ارزش‌ترین بایت اول می‌آید. به این ترتیب little-endian می‌گویند (در درس ۱.۲ اسمش را شنیدی). اشاره‌گر بایتی راهی است که این را با چشم خودت ببینی: آدرس عدد را می‌گیری و به‌جای یک uint32_t، چهار uint8_t می‌خوانی.

#include <stdint.h>
#include <stdio.h>

int main(void)
{
    uint32_t value = 0x12345678;
    const uint8_t *b = (const uint8_t *)&value;

    for (int i = 0; i < 4; i++) {
        printf("byte %d = 0x%02X\n", i, b[i]);
    }
    return 0;
}
  1. عدد آزمایشی. هگز 0x12345678؛ بایت‌ها از پرارزش به کم‌ارزش: 12، 34، 56، 78.
  2. دید بایتی. &value آدرس چهار بایتی است؛ آن را به const uint8_t * تبدیل می‌کنیم تا بشود بایت‌به‌بایت خواند. خواندن یک شیء از راه اشاره‌گر بایتی (char و unsigned char؛ و uint8_t هم عملا، چون در gcc و clang و کامپایلر ARM یک نام دیگر برای unsigned char است) مجاز است. این تنها استثنای مطمئن قانون aliasing است که پایین‌تر می‌آید.
  3. چاپ بایت‌ها. b[i] همان *(b + i) است، پس بایت شماره i از آدرس عدد.

هر جا داده را از بیرون می‌گیری (پکت شبکه، ثبات سنسور روی I2C، فایل)، ترتیب بایت‌ها قرارداد بین دو طرف است، نه سلیقه پردازنده تو. کد امن ترتیب را صریح با شیفت می‌نویسد، همان کاری که پایین در تمرین ۳ می‌کنیم.

تراز حافظه: هر داده جای مناسب خودش را می‌خواهد

پردازنده حافظه را در تکه‌های ۴ بایتی می‌خواند (روی این پردازنده‌ها). فرض کن قفسه‌های انبار چهارتایی گروه‌بندی شده‌اند. اگر یک عدد ۴ بایتی دقیقا در یک گروه بنشیند، یک دسترسی کافی است. اگر وسط دو گروه بیفتد، باید دو گروه خوانده و بایت‌ها چسبانده شوند. به این می‌گویند تراز (alignment): عدد N بایتی باید در آدرسی باشد که بر N بخش‌پذیر است. یعنی uint16_t در آدرس زوج، uint32_t در آدرس مضرب ۴.

پردازندهدسترسی ناهم‌تراز به uint32_t با دستور معمولی
x86 (PC)کار می‌کند، کمی کندتر
Cortex-M3 / M4 (مثل STM32F411)برای بارگذاری‌های ساده کار می‌کند ولی چند سیکل بیشتر می‌برد؛ بعضی دستورها (مثل LDM/STM/LDRD) همچنان ناهم‌تراز را قبول نمی‌کنند
Cortex-M0 / M0+خطا می‌دهد: HardFault
ESP32 (Xtensa)ممکن است استثنا بدهد؛ کد عملا باید هم‌تراز بماند. در مستندات ESP-IDF و مرجع فنی بخوان

ثبات‌های محیطی (مثل SR و DR در UART) استثنا هستند: همیشه هم‌تراز و با پهنای کامل (۳۲ بیت برای رجیسترهای ۳۲ بیتی) به آن‌ها دسترسی بزن. دسترسی ناهم‌تراز یا با پهنای نادرست به ناحیهٔ محیطی‌ها حتی روی Cortex-M4 ممکن است خطا بدهد یا رفتار دیگری داشته باشد (طبق مرجع فنی RM0383 و راهنمای Cortex-M4 هر ثبات را با پهنای تعریف‌شده‌اش بخوان).

نتیجه عملی: کدی که روی PC و STM32F4 «کار می‌کند» ممکن است روی M0 یا ESP32 بیفتد. راه امن برای خواندن عددی از وسط یک بافر بایتی: هرگز آدرس را cast نکن؛ بایت‌ها را با memcpy در یک متغیر واقعی کپی کن. کامپایلر می‌داند چه کار کند و روی پردازنده‌ای که اجازه می‌دهد آن را به یک دستور تبدیل می‌کند.

#include <stdint.h>
#include <stdio.h>
#include <string.h>

static uint32_t read_u32(const uint8_t *p)
{
    uint32_t v;
    memcpy(&v, p, sizeof v);
    return v;
}

int main(void)
{
    uint8_t buf[8] = {0, 0x78, 0x56, 0x34, 0x12, 0, 0, 0};
    printf("value = 0x%08X\n", (unsigned)read_u32(buf + 1));
    printf("alignof(uint32_t) = %zu\n", _Alignof(uint32_t));
    return 0;
}
  1. خواندن امن عدد ۳۲ بیتی. بافر را با const uint8_t * می‌گیریم و ۴ بایت را در متغیر واقعی v کپی می‌کنیم. به‌جای *(const uint32_t *)p که اگر p ناهم‌تراز باشد رفتار تعریف‌نشده است (و مشکل aliasing هم دارد). memcpy به هر آدرسی قانونی است.
  2. بافر آزمایشی. بایت‌های 78 56 34 12 از اندیس ۱ شروع می‌شوند، یعنی درست همان جایی که ناهم‌تراز است.
  3. خواندن از اندیس ۱. buf + 1 آدرس فرد است. نتیجه 0x12345678 چون این دستگاه little-endian است. این خط روی ماشین big-endian نتیجه دیگری می‌داد. برای پروتکل‌های واقعی باید ترتیب را صریح بنویسی (تمرین ۳).
  4. پرسش از کامپایلر. _Alignof تراز مورد نیاز نوع را می‌دهد (در C11).
$ ./align
value = 0x12345678
alignof(uint32_t) = 4
ادامه برای کنجکاوها: قانون aliasing و memcpy
زیر کاپوت: aliasing

قانون strict aliasing در C می‌گوید: کامپایلر می‌تواند فرض کند دو اشاره‌گر از انواع ناسازگار (مثلا float * و uint32_t *) هیچ‌وقت به یک حافظه اشاره نمی‌کنند، و بر همین اساس دستورها را جابه‌جا یا حذف کند. اگر با cast اشاره‌گر، همان حافظه را با نوع دیگر بخوانی، طبق استاندارد رفتار تعریف‌نشده است و -O2 ممکن است کد را «خراب» کند. استثنا: خواندن هر شیء از راه char یا unsigned char (و uint8_t، که عملا در gcc و clang و کامپایلرهای ARM همان unsigned char است؛ خود استاندارد این استثنا را فقط به نوع‌های کاراکتری داده است). اگر کدی قدیمی داری که این قاعده را می‌شکند و نمی‌توانی درستش کنی، gcc سوئیچ -fno-strict-aliasing دارد که این فرض را خاموش می‌کند؛ ولی راه درست memcpy است. برای دیدن بیت‌های یک float راه درست memcpy است:

#include <stdint.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    float f = 1.0f;
    uint32_t bits;
    memcpy(&bits, &f, sizeof bits);
    printf("1.0f = 0x%08X\n", (unsigned)bits);
    return 0;
}
  1. دو متغیر مستقل. عدد اعشاری و یک عدد صحیح ۳۲ بیتی که بیت‌ها را می‌گیرد.
  2. کپی بایت‌ها. بیت‌های f بی‌تغییر به bits می‌روند. این کار قانونی است و کامپایلرهای بهینه معمولا آن را به یک دستور ساده تبدیل می‌کنند. نوشتن *(uint32_t *)&f همان کار را ظاهرا می‌کند، ولی تعریف‌نشده است و ممکن است با بهینه‌سازی نتیجه غلط بدهد.
  3. چاپ. بیت‌های استاندارد IEEE 754 برای ۱٫۰ تک‌دقت: 0x3F800000.
$ ./alias
1.0f = 0x3F800000

هرگز آدرس متغیر محلی را برنگردان

متغیرهای محلی تابع روی پشته می‌نشینند و وقتی تابع تمام شد، آن قفسه‌ها به بقیه برنامه پس داده می‌شوند (درس ۲.۶ و بعدا ۳.۵). اگر آدرس یکی از آنها را برگردانی، آدرسی به «مکان خراب‌شده» در دست کسی می‌ماند که صدا زده است: dangling pointer (اشاره‌گر آویزان). مثل اینکه شماره اتاقی در هتل را به دوستت بدهی که همین الان تخلیه‌اش کرده‌ای؛ فردا مسافر دیگری آنجاست.

#include <stdio.h>

static int *make_id(void)
{
    int id = 7;
    return &id;
}

int main(void)
{
    int *p = make_id();
    printf("%d\n", *p);
    return 0;
}
  1. تابع بد. id متغیر محلی است و فقط تا پایان make_id زنده می‌ماند.
  2. برگرداندن آدرس محلی. بعد از return، آن قفسه پشته دوباره قابل‌استفاده است. gcc اینجا معمولا هشدار می‌دهد؛ ما آن را به خطا تبدیل کردیم. ولی هر جا مسیر پیچیده‌تر باشد، ممکن است هشدار نیاید. باید خودت بدانی.
  3. استفاده در main. اگر برنامه ساخته می‌شد، *p هر چیزی می‌توانست باشد: مقدار قدیمی، مقدار آشغال، مقدار یک تابع دیگر، یا حتی کرش (مثلا ابزارهای تشخیص خطا و بهینه‌ساز گاهی آدرس را NULL می‌کنند و برنامه می‌ترکد). رفتار تعریف‌نشده است.
dangling.c: In function 'make_id':
dangling.c:6:12: error: function returns address of local variable [-Werror=return-local-addr]

سه راه درست: (۱) جواب را به مقدار برگردان (int)؛ (۲) از صدا زننده بخواه فضا بدهد و آدرسش را بگیر؛ (۳) متغیر را static کن (هزینه: یک نسخه مشترک برای همه فراخوانی‌ها). روش ۲ در embedded محبوب‌ترین است:

#include <stdio.h>

static void make_id(int *out)
{
    *out = 7;
}

int main(void)
{
    int id;
    make_id(&id);
    printf("%d\n", id);
    return 0;
}
  1. خروجی از راه اشاره‌گر. تابع آدرس قفسه‌ای را می‌گیرد که مال صدا زننده است و مقدار را داخلش می‌نویسد. به این پارامتر «پارامتر خروجی» می‌گویند. قفسه id در main زنده است و بعد از برگشتن تابع هم می‌ماند.
  2. ساختن و فرستادن آدرس. با &id آدرس قفسه محلی main داده می‌شود.
  3. چاپ.
$ ./dangling_fixed
7

در STM32 و ESP32 یعنی چه؟

هر درایور ارتباطی شکل «بافر + طول» دارد. مثال STM32: تابعی که بایت‌ها را روی USART2 می‌فرستد. اعداد این کد از درس ۵.۵ می‌آیند؛ اینجا فقط ببین اشاره‌گر چه نقشی دارد. ثبات‌ها آدرس ثابت دارند و ما از راه اشاره‌گر به آنها می‌رسیم (جزئیاتش درس ۳.۶ است؛ volatile را هم آنجا می‌فهمی).

#include <stddef.h>
#include <stdint.h>

#define USART2_BASE 0x40004400u
#define USART2_SR   ((volatile uint32_t *)(USART2_BASE + 0x00u))
#define USART2_DR   ((volatile uint32_t *)(USART2_BASE + 0x04u))
#define TXE_BIT     (1u << 7)

static void uart_send(const uint8_t *data, size_t len)
{
    for (size_t i = 0; i < len; i++) {
        while ((*USART2_SR & TXE_BIT) == 0u) {
            // منتظر خالی شدن ثبات ارسال
        }
        *USART2_DR = data[i];
    }
}

void app_send_hello(void)
{
    static const uint8_t msg[] = {'H', 'i', '\r', '\n'};
    uart_send(msg, sizeof msg);
}
  1. آدرس ثبات‌ها. پایه USART2 روی STM32F411 برابر 0x40004400 است. ثبات وضعیت (SR) آفست ۰ و ثبات داده (DR) آفست ۴ دارد. بیت ۷ در SR یعنی «ثبات ارسال خالی است» (TXE). هر ماکرو یک اشاره‌گر به آدرس ثابت می‌سازد. volatile می‌گوید مقدار این آدرس بدون اطلاع برنامه هم عوض می‌شود (سخت‌افزار). دلیل کامل در ۳.۶ می‌آید.
  2. تابع ارسال. بافر فقط‌خواندنی و طول: همان الگوی این درس. const داده را محافظت می‌کند. اگر msg در Flash باشد، بدون const نمی‌توانستی آن را بدهی.
  3. حلقه روی بایت‌ها. ایندکس i هر بار یک بایت را انتخاب می‌کند: data[i].
  4. انتظار برای آماده شدن. تا وقتی بیت TXE صفر است صبر کن. اگر بایت بعدی را زودتر بنویسی، بایت قبلی بی‌صدا گم می‌شود.
  5. نوشتن روی ثبات داده. نوشتن بایت روی DR سخت‌افزار را روشن می‌کند تا آن را بفرستد.
  6. استفاده. پیام ثابت در static const (معمولا در Flash) و ارسال با sizeof msg.
این کد به‌تنهایی روی برد کار نمی‌کند

uart_send فقط «نمونهٔ اشاره‌گر» است. برای اینکه روی USART2 واقعا چیزی خارج شود باید اول کلاک را روشن کنی (RCC_APB1ENR بیت ۱۷)، پین‌های PA2 و PA3 را روی عملکرد جایگزین AF7 بگذاری، نرخ baud را در BRR بنویسی و بیت‌های UE و TE را در CR1 روشن کنی؛ همه در درس ۵.۵ می‌آید. همچنین بعد از آخرین بایت باید منتظر پرچم TC (پایان کامل ارسال) بمانی، وگرنه اگر برنامه فوری برود به خواب یا ریست، بایت آخر بریده می‌شود.

همین الگو در کتابخانه‌های رسمی هم هست. در ESP-IDF تابع uart_write_bytes یک const void * و یک طول می‌گیرد؛ در HAL شرکت ST تابع HAL_UART_Transmit یک اشاره‌گر به بایت‌ها (uint8_t *) و یک طول می‌گیرد. امضای دقیق و نسخه را در مستندات رسمی هر کدام ببین.

خلاصه سخت‌افزاری

بافر UART، بسته شبکه، جدول رنگ صفحه: همه «آدرس + طول‌اند». تابع‌هایی که فقط می‌خوانند const می‌گیرند. تبدیل به عددهای چندبایتی با شیفت یا memcpy انجام می‌شود، نه cast اشاره‌گر. آدرس متغیر محلی هرگز از تابع بیرون نمی‌رود.

آزمون این درس

اگر int a[5]; تعریف شده باشد، کدام عبارت با a[3] دقیقا یکی است؟

  1. *a + 3
  2. *(a + 3)
  3. a + 3
  4. &a[3]
کامپایلر a[i] را به *(a + i) ترجمه می‌کند. پرانتز لازم است چون ستاره تقدم بالاتری از جمع دارد.

خروجی چیست؟
int a[] = {5, 6, 7, 8}; int *p = a + 1; printf("%d", *(p + 2));

  1. ۶
  2. ۷
  3. ۸
  4. ۵
p روی a[1] است؛ p + 2 می‌شود a[3] که مقدارش ۸ است. یعنی اندیس ۱ با ۲ جمع می‌شود: *(p + 2) با a[1 + 2] یکی است. (دو اشاره‌گر را نمی‌شود با هم جمع کرد؛ فقط اشاره‌گر + عدد مجاز است.)

اشاره‌گر uint16_t *p روی آدرس 0x1000 است. p + 3 کدام آدرس است؟

  1. 0x1006
  2. 0x1003
  3. 0x100C
  4. 0x1012
هر گام ۲ بایت است، پس ۳ گام = ۶ بایت: 0x1000 + 6 = 0x1006.

در این قطعه کدام خط خطای کامپایل می‌دهد؟
int x = 1, y = 2;
int *const p = &x;
*p = 3;
p = &y;

  1. خط ۲: int *const p = &x;
  2. خط ۳: *p = 3;
  3. هیچ‌کدام
  4. خط ۴: p = &y;
int *const p یعنی خود اشاره‌گر ثابت است؛ نمی‌توانی آدرسش را عوض کنی ولی می‌توانی از راه آن روی x بنویسی.

تابع void f(int a[]) داخل خودش sizeof(a) / sizeof(a[0]) را برای شمردن عنصرها به‌کار برده است. چرا غلط است؟

  1. چون sizeof فقط برای متغیرهای محلی کار می‌کند
  2. چون a داخل تابع در واقع int * است و sizeof اندازه اشاره‌گر را می‌دهد، نه آرایه
  3. چون نمی‌شود sizeof را تقسیم کرد
  4. چون آرایه هنگام صدا زدن کپی می‌شود و اندازه‌اش عوض می‌شود
پارامتر آرایه‌ای در واقع اشاره‌گر است. طول را باید جدا بفرستی: void f(const int *a, size_t n).

چرا برای خواندن یک uint32_t از وسط بافر پکت، توصیه می‌شود از memcpy یا شیفت بایت‌ها استفاده کنیم، نه cast اشاره‌گر؟

  1. چون cast خیلی کند است
  2. چون cast اشاره‌گر در C کامپایل نمی‌شود
  3. فقط چون ترتیب بایت‌ها عوض می‌شود
  4. چون آدرس ممکن است ناهم‌تراز باشد (روی Cortex-M0 خطا)، cast قانون aliasing را می‌شکند و ترتیب بایت هم به پردازنده بستگی دارد
هر سه مشکل واقعی‌اند. تراز: آدرسی که مضرب ۴ نیست روی بعضی هسته‌ها خطا می‌دهد (بخش تراز). aliasing: خواندن حافظه با نوع ناسازگار طبق استاندارد تعریف‌نشده است. بایت‌ترتیب: ترتیب بایت‌ها به پردازنده بستگی دارد (دو بخش اختیاری «ادامه برای کنجکاوها» را اگر نخوانده‌ای بعدا ببین). memcpy اولی و دومی را حل می‌کند و شیفت صریح، سومی را.

تمرین ۱: برعکس کردن آرایه با دو اشاره‌گر

می‌خواهیم آرایه {1, 2, 3, 4, 5} را در جا برعکس کنیم (بدون آرایه دوم). ایده: یک اشاره‌گر از اول و یکی از آخر، عنصرها را عوض کنند و به هم نزدیک شوند.

  1. پیش‌بینی: در شروع، lo و hi به کدام عنصرها اشاره می‌کنند؟ برای ۵ عنصر چند بار جابه‌جایی لازم است؟
  2. حل: تابع reverse(int *v, size_t n) بنویس و در main آرایه را چاپ کن.
  3. فکر کن: اگر n صفر باشد v + n - 1 به کجا اشاره می‌کند؟ چرا باید تابع قبل از آن برگردد؟
راهنمایی

حلقه را تا وقتی ادامه بده که lo < hi. هر دور: دو مقدار را با متغیر موقت عوض کن (همان الگوی تمرین ۱ در درس ۲.۱)، بعد lo++ و hi--.

چه باید ببینی؟ 
$ ./reverse
data[0] = 5
data[1] = 4
data[2] = 3
data[3] = 2
data[4] = 1

جواب الف: lo روی data[0] و hi روی data[4]. فقط ۲ جابه‌جایی لازم است (عنصر وسط سر جای خودش می‌ماند). جواب پ: v + 0 - 1 یعنی یک خانه قبل از شروع آرایه، که طبق قانون «یکی بعد از آخر» ساختنش هم رفتار تعریف‌نشده است.

جواب کامل با توضیح 
#include <stdio.h>

static void reverse(int *v, size_t n)
{
    if (n < 2) {
        return;                    // چیزی برای برعکس کردن نیست
    }
    int *lo = v;                   // اشاره‌گر به اولین عنصر
    int *hi = v + n - 1;           // اشاره‌گر به آخرین عنصر
    while (lo < hi) {
        int tmp = *lo;
        *lo = *hi;
        *hi = tmp;
        lo++;
        hi--;
    }
}

int main(void)
{
    int data[5] = {1, 2, 3, 4, 5};
    reverse(data, 5);
    for (int i = 0; i < 5; i++) {
        printf("data[%d] = %d\n", i, data[i]);
    }
    return 0;
}
  1. نگهبان. آرایه خالی یا تک‌عنصری چیزی برای عوض کردن ندارد؛ زودتر برمی‌گردیم. بدون این خط، با n برابر صفر، v + n - 1 قبل از شروع آرایه می‌رود.
  2. دو سر آرایه. lo اولین عنصر و hi آخرین عنصر.
  3. شرط ادامه. تا وقتی lo قبل از hi است. وقتی به هم رسیدند یا رد شدند، تمام است. اگر شرط lo != hi بود، برای تعداد زوج عنصر هیچ‌وقت برابر نمی‌شدند و از آرایه بیرون می‌رفتند.
  4. عوض کردن. مقدار *lo را نگه می‌داریم، *hi را جایش می‌گذاریم و مقدار نگه‌داشته را به *hi می‌دهیم.
  5. نزدیک شدن. lo یک عنصر جلو و hi یک عنصر عقب.
  6. امتحان. آرایه پنج‌تایی را برعکس و چاپ می‌کنیم.
$ ./reverse
data[0] = 5
data[1] = 4
data[2] = 3
data[3] = 2
data[4] = 1
تمرین ۲: سه باگ در یک تابع

این تابع باید بشمارد چند عدد از limit بزرگ‌ترند. سه اشتباه دارد که هر کدام با یک قاعده همین درس ارتباط دارد. پیدایشان کن.

static int count_over(const int v[], int limit)
{
    int n = sizeof(v) / sizeof(v[0]);
    int count = 0;
    for (const int *p = v; p <= v + n; p++) {
        if (*p > limit) {
            *p = limit;
            count++;
        }
    }
    return count;
}
  1. خط ۳: چه اشتباهی دارد؟ چه چیزی را باید عوض کنی؟
  2. خط ۵: شرط حلقه چه می‌کند وقتی p به v + n می‌رسد؟
  3. خط ۷: این خط با const چه تناقضی دارد و کامپایلر چه می‌گوید؟
راهنمایی

پارامتر آرایه‌ای در واقع چیست؟ آخرین عنصر معتبر کجاست؟ تابعی که فقط می‌شمارد باید چیزی را عوض کند؟

ب<= باعث می‌شود *(v + n) (بیرون آرایه) هم خوانده شودشرط را p < v + n کن
پتابع فقط‌خواندنی است ولی روی *p می‌نویسدخط را حذف کن؛ شمردن نیاز به نوشتن ندارد
#include <stdio.h>

static int count_over(const int *v, size_t n, int limit)
{
    int count = 0;
    for (const int *p = v; p < v + n; p++) {
        if (*p > limit) {
            count++;
        }
    }
    return count;
}

int main(void)
{
    int temps[6] = {21, 35, 28, 40, 19, 33};
    size_t n = sizeof temps / sizeof temps[0];
    printf("over 30: %d\n", count_over(temps, n, 30));
    return 0;
}
  1. امضای درست. بافر و طولش جدا می‌آیند. const می‌ماند چون تابع فقط می‌خواند.
  2. حلقه کامل. p از v تا یکی مانده به v + n؛ شرط <.
  3. فقط شمارش. دیگر روی *p نمی‌نویسیم.
  4. طول در جای درست. در main temps واقعا آرایه است، پس sizeof temps / sizeof temps[0] می‌شود ۶؛ ۳۵ و ۴۰ و ۳۳ از ۳۰ بزرگ‌ترند.
$ ./count_over
over 30: 3
تمرین ۳: نوشتن و خواندن امن پکت (کار با سخت‌افزار)

یک فریم ۶ بایتی داریم: بایت شروع 0xAA، بعد یک شناسه ۳۲ بیتی، بعد بایت پایان 0x55. قرارداد پروتکل: شناسه با little-endian فرستاده می‌شود، در هر پردازنده‌ای.

  1. پیش‌بینی: اگر شناسه 0xDEADBEEF باشد، بایت‌های فریم به ترتیب چه هستند؟
  2. حل: دو تابع write_u32_le(uint8_t *p, uint32_t v) و read_u32_le(const uint8_t *p) بنویس که فقط از شیفت و ماسک استفاده کنند، و رفت‌وبرگشت را امتحان کن.
  3. چالش: سه دلیل بیاور که چرا *(uint32_t *)(frame + 1) بد است.
راهنمایی

بایت i ام از v برابر (v >> (8*i)) & 0xFF است (درس ۳.۱). برای خواندن، هر بایت را به uint32_t تبدیل کن، به اندازه لازم شیفت بده و با | بچسبان.

چه باید ببینی؟ 
$ ./packet

back = 0xDEADBEEF

جواب پ: (۱) شناسه از frame + 1 شروع می‌شود که فرد است، پس ناهم‌تراز است؛ (۲) خواندن uint8_t آرایه با نوع uint32_t قانون aliasing را می‌شکند؛ (۳) ترتیب بایت‌ها را پردازنده تعیین می‌کند، نه قرارداد پروتکل.

جواب کامل با توضیح 
#include <stdint.h>
#include <stdio.h>

static void write_u32_le(uint8_t *p, uint32_t v)
{
    p[0] = (uint8_t)(v & 0xFFu);
    p[1] = (uint8_t)((v >> 8) & 0xFFu);
    p[2] = (uint8_t)((v >> 16) & 0xFFu);
    p[3] = (uint8_t)((v >> 24) & 0xFFu);
}

static uint32_t read_u32_le(const uint8_t *p)
{
    return (uint32_t)p[0]
         | ((uint32_t)p[1] << 8)
         | ((uint32_t)p[2] << 16)
         | ((uint32_t)p[3] << 24);
}

int main(void)
{
    uint8_t frame[6] = {0xAA, 0, 0, 0, 0, 0x55};
    write_u32_le(frame + 1, 0xDEADBEEFu);
    for (int i = 0; i < 6; i++) {
        printf("%02X ", frame[i]);
    }
    printf("\n");
    printf("back = 0x%08X\n", (unsigned)read_u32_le(frame + 1));
    return 0;
}
  1. نوشتن. هر بایت شناسه جدا از عدد بیرون کشیده می‌شود: شیفت به راست، ماسک 0xFF، تبدیل به uint8_t. بایت کم‌ارزش‌تر در آدرس پایین‌تر. ترتیب را کد تعیین می‌کند، نه پردازنده. این کد روی little-endian و big-endian یکسان کار می‌کند.
  2. خواندن. هر بایت اول به uint32_t تبدیل می‌شود، بعد شیفت. اگر cast نمی‌کردی، p[3] << 24 در حساب int انجام می‌شد و برای بایت‌های ≥ 0x80 به علامت ۳۲ بیتی می‌خورد (تعریف‌نشده). درس ۳.۱ را ببین.
  3. فریم. بایت شروع و پایان ثابت‌اند و چهار بایت میانی خالی.
  4. نوشتن در وسط فریم. frame + 1 آدرس بایت شماره ۱ است.
  5. چاپ فریم. %02X هر بایت را دو رقمی هگز می‌نویسد.
  6. خواندن دوباره. باید همان مقدار اول برگردد.

حرف مربی

دو جا معمولا گیر می‌کنند. اول، فراموش کردن اینکه p + 1 «یک عنصر» است: وقتی نوع را عوض می‌کنی (مثلا از uint8_t * به uint32_t *) گام هم عوض می‌شود. اگر واقعا بایت می‌خواهی، اشاره‌گر بایتی بساز. دوم، constهای زیاد در امضای تابع: اول غافلگیرت می‌کنند، بعد عادت می‌شود. قاعده ساده: تابعی که فقط می‌خواند، const می‌گیرد. اگر کامپایلر اعتراض کرد، یک بار جدی فکر کن که آیا تابع واقعا فقط می‌خواند. اشکال‌های اشاره‌گر معمولا فوراً نمی‌ترکند؛ چند ساعت بعد، روی برد، یک مقدار عجیب ظاهر می‌شود. برای همین، هر بار با -Wall -Wextra کامپایل کن.

خلاصه یک‌دقیقه‌ای

  • اسم آرایه (در بیشتر جاها) می‌شود آدرس اولین عنصر. a[i] یعنی *(a + i).
  • p + n یعنی n عنصر جلو، یعنی n × اندازه نوع بایت. تفاضل دو اشاره‌گر، تعداد عنصر است. فقط تا «یکی بعد از آخر» مجاز است.
  • آرایه را به تابع بدهی، فقط آدرس می‌رود؛ طول را جدا بفرست و sizeof را همان جایی که آرایه واقعی است حساب کن.
  • const T *p: داده قفل. T *const p: اشاره‌گر قفل. تابع فقط‌خوان، const می‌گیرد.
  • void * یعنی «هر نوع»؛ برای کار کردن باید به اشاره‌گر بایتی تبدیل شود.
  • رشته‌ها تا '\0' ادامه دارند؛ char * به literal فقط‌خواندنی است، char[] کپی قابل‌تغییر.
  • عددهای چندبایتی را با memcpy یا شیفت صریح بخوان (تراز، aliasing و بایت‌ترتیب). آدرس متغیر محلی را برنگردان.
