متغیر فقط قفسه است؛ کاری نمی‌کند. برای اینکه برنامه «کار» کند باید بتواند با مقدارها حساب کند، آن‌ها را مقایسه کند و نتیجه را جایی بگذارد. ابزار همهٔ این کارها عملگرها هستند: علامت‌های کوچکی مثل +، /، == و &&. در این درس یاد می‌گیری هر کدام دقیقا چه می‌کنند، به چه ترتیبی اجرا می‌شوند و کدام‌شان مبتدی‌ها را زمین می‌زنند؛ از جمله «چرا ۷ تقسیم بر ۲ می‌شود ۳؟».

🎯 بعد از این درس می‌توانی

  • عبارت‌های حسابی را بنویسی و نتیجه‌شان را در ذهن حساب کنی
  • تقسیم صحیح و باقیمانده (/ و %) را، حتی برای عدد منفی، پیش‌بینی کنی
  • ترتیب انجام عملگرها (تقدم) را بشناسی و با پرانتز کنترل کنی
  • فرق = و ==، و فرق i++ و ++i را بگویی
  • شرط‌های ترکیبی با && و || بنویسی و «میان‌بُر» را بفهمی
  • خوانش ADC را بدون سرریز به میلی‌ولت تبدیل کنی

🧰 پیش‌نیاز و وسایل

  • درس ۲.۱ (متغیر و انتساب) و درس ۲.۲ (نوع‌ها و سرریز)
  • یک کامپایلر gcc
  • هیچ سخت‌افزاری لازم نیست

ایدهٔ اصلی: ماشین‌حساب و پرسش‌های بله/خیر

ماشین‌حساب جیبی را ببین. چند دکمهٔ حساب دارد: جمع، تفریق، ضرب، تقسیم. به هر دکمه یک «کار» می‌گوییم. زبان C هم دکمه‌هایی مثل این دارد و به هر کدام عملگر (operator) می‌گوید. چیزهایی که عملگر رویشان کار می‌کند عملوند (operand) نام دارند. در 3 + 4 علامت + عملگر است و ۳ و ۴ عملوندند.

دو دسته عملگر داریم که باید در ذهنت جدا نگه داری:

  • عملگر حسابی: جواب یک عدد است. مثل 7 + 2 ← ۹.
  • عملگر مقایسه‌ای و منطقی: جواب یک بله/خیر است. مثل «۷ بزرگ‌تر از ۲ است؟» ← بله. C بله را با 1 و خیر را با 0 نشان می‌دهد.

هر ترکیبی از مقدار و عملگر که یک جواب بدهد، یک عبارت (expression) است. مثلا age + 1 یک عبارت است و age > 18 هم.

مثال از زندگی روزمره

تصور کن در سوپرمارکت هستی. «سه بسته شیر، هرکدام ۲۰ هزار تومان» یک حساب است (3 * 20)؛ جواب یک عدد است. «آیا پولم برای خرید کافی است؟» یک مقایسه است (wallet >= total)؛ جواب بله یا خیر است. «کارت اعتباری دارم و رمزش را یادم هست؟» یک شرط ترکیبی است (&&). برنامه‌های میکروکنترلر هم فقط همین را می‌کنند، فقط عددها از سنسور می‌آیند.

حساب: جمع، تفریق، ضرب، تقسیم و باقیمانده

پنج عملگر حسابی داریم:

عملگرکارمثالجواب
+جمع17 + 5۲۲
-تفریق17 - 5۱۲
*ضرب (ستاره، نه ×)17 * 5۸۵
/تقسیم17 / 5۳ (نه ۳٫۴!)
%باقیمانده (modulo)17 % 5۲

دو ردیف آخر جای صحبت دارند. وقتی هر دو عملوند عدد صحیح باشند، / یک تقسیم صحیح است: فقط «چند بار جا می‌شود» را می‌گوید و قسمت اعشار را می‌اندازد. باقیمانده را هم % می‌دهد. مثل تقسیم آب‌نبات‌ها بین بچه‌ها:

#include <stdio.h>

int main(void)
{
    int a = 17;
    int b = 5;

    printf("a + b = %d\n", a + b);
    printf("a - b = %d\n", a - b);
    printf("a * b = %d\n", a * b);
    printf("a / b = %d\n", a / b);
    printf("a %% b = %d\n", a % b);
    printf("-a / b = %d\n", -a / b);
    printf("-a %% b = %d\n", -a % b);
    printf("a / 5.0 = %.1f\n", a / 5.0);
    return 0;
}
  1. دو ورودی. ۱۷ و ۵ را در دو متغیر می‌گذاریم تا عبارت‌ها با نام کار کنند.
  2. جمع، تفریق، ضرب. ساده‌اند. printf جواب را با %d چاپ می‌کند.
  3. تقسیم صحیح. هر دو int‌اند، پس جواب ۳ است و ۰٫۴ دور ریخته می‌شود. C نوع جواب را از نوع عملوندها می‌فهمد، نه از آنچه تو دلت می‌خواهی. دو int جواب int می‌دهد.
  4. باقیمانده. در رشتهٔ قالب باید %% بنویسی تا printf یک علامت % چاپ کند. خود عملگر % در a % b همان باقیمانده است. در printf علامت % شروع یک قالب است (مثل %d)، پس برای خود % باید دوتایی نوشت.
  5. عدد منفی. C جواب تقسیم را به سمت صفر می‌بُرد: -17 / 5 می‌شود -3 (نه ۴-). و باقیمانده هم همان علامت عدد اول را می‌گیرد: -17 % 5 می‌شود -2. قاعده همیشه برقرار است: (a / b) * b + a % b == a. اینجا: -3 * 5 + (-2) = -17.
  6. تقسیم اعشاری. 5.0 از نوع double است، پس جواب هم double می‌شود: ۳٫۴. کافی است یک عملوند اعشاری باشد تا تقسیم اعشاری شود. عملوند صحیح خودکار اعشاری می‌شود (درس ۲.۲).
  7. پایان.

تقسیم بر صفر

تقسیم عدد صحیح بر صفر در C رفتار تعریف‌نشده است: روی لپ‌تاپ معمولا برنامه با پیام «Floating point exception» می‌افتد و روی بعضی میکروکنترلرها نتیجهٔ بی‌معنی می‌دهد یا حتی بی‌صدا ادامه می‌دهد؛ رفتار به پردازنده بستگی دارد. راهش: پیش از هر / یا % که مخرج از بیرون می‌آید (سنسور، کاربر، UART)، بررسی کن صفر نباشد.

در میکروکنترلر: تقسیم گران است

در Cortex-M4 (STM32F411) یک دستور تقسیم سخت‌افزاری وجود دارد که چند چرخه طول می‌کشد. در Cortex-M0 چنین دستوری نیست و کامپایلر یک تکه کد کتابخانه‌ای برای هر / و % می‌گذارد که ده‌ها چرخه هزینه دارد. اگر مخرج ثابتِ توانی از ۲ باشد (مثل ۸ یا ۱۶)، کامپایلر خودش تقسیم را به شیفت تبدیل می‌کند و ارزان می‌شود؛ ولی برای عدد دلخواه مثل ۴۰۹۵ نه. نتیجه: در حلقه‌های پرتکرار به / و % حساس باش، ولی برای خوانایی هم زیاد نگران نشو؛ اول درست بنویس، بعد اندازه بگیر (درس ۶.۵).

تقدم: کدام عملگر اول انجام می‌شود؟

در ریاضی مدرسه یاد گرفتی «ضرب قبل از جمع». C هم همین قانون را دارد و اسمش تقدم (precedence) است. در 2 + 3 * 4 اول 3 * 4 حساب می‌شود (۱۲) و بعد 2 + 12 (۱۴). اگر برعکس بخواهی، پرانتز می‌گذاری: (2 + 3) * 4 می‌شود ۲۰.

وقتی دو عملگر هم‌تقدم باشند (مثل 10 - 4 - 3)، به آن‌ها شرکت‌پذیری می‌گویند: بیشتر عملگرها از چپ به راست کار می‌کنند؛ پس (10 - 4) - 3 می‌شود ۳. برای انتساب برعکس است (از راست به چپ). جدول تقدم را از بالا (اول) به پایین (آخر) بخوان:

ردیفعملگرهاجهتیادداشت
۱() [] . -> ++ -- (پسوندی)چپ ← راستپرانتز، آرایه و…
۲! ~ - (منفی) ++ -- (پیشوندی) * & sizeof (نوع)راست ← چپعملگرهای یک‌عملوندی
۳* / %چپ ← راستضرب و تقسیم
۴+ -چپ ← راستجمع و تفریق
۵<< >>چپ ← راستشیفت بیتی (درس ۳.۱)
۶< <= > >=چپ ← راستمقایسهٔ ترتیبی
۷== !=چپ ← راستمقایسهٔ برابری
۸&چپ ← راستAND بیتی (درس ۳.۱)
۹^چپ ← راستXOR بیتی
۱۰|چپ ← راستOR بیتی
۱۱&&چپ ← راست«و» منطقی
۱۲||چپ ← راست«یا» منطقی
۱۳?:راست ← چپسه‌تایی (درس ۲.۴)

لازم نیست جدول را حفظ کنی. قاعدهٔ مهندسی‌ها: وقتی مطمئن نیستی، پرانتز بگذار. پرانتز اضافه هزینه‌ای ندارد و خواننده را از حدس‌زدن نجات می‌دهد.

#include <stdio.h>

int main(void)
{
    printf("2 + 3 * 4       = %d\n", 2 + 3 * 4);
    printf("(2 + 3) * 4     = %d\n", (2 + 3) * 4);
    printf("10 - 4 - 3      = %d\n", 10 - 4 - 3);
    printf("100 / 10 * 5    = %d\n", 100 / 10 * 5);
    printf("100 / (10 * 5)  = %d\n", 100 / (10 * 5));
    printf("-2 * 3 + 1      = %d\n", -2 * 3 + 1);
    return 0;
}
  1. ضرب جلوتر از جمع. ۱۴ در برابر ۲۰؛ فقط پرانتز فرق ایجاد کرد.
  2. از چپ به راست. اول 10 - 4 = ۶ و بعد 6 - 3 = ۳. اگر از راست می‌رفت ۹ درمی‌آمد (۱۰ − ۱).
  3. ترتیب ضرب و تقسیم. 100 / 10 * 5 از چپ می‌رود: ۱۰ × ۵ = ۵۰. اما 100 / (10 * 5) = 100 / 50 = ۲. با پرانتز، جواب ۲۵ برابر شد! این تله برای فرمول‌هایی مثل «مقدار ÷ (a × b)» جدی است. اگر پرانتز را فراموش کنی، ضرب به‌جای مخرج به صورت می‌رود.
  4. منفی یک‌عملوندی. علامت منفی جلوی ۲ اول اعمال می‌شود (ردیف ۲) و بعد ضرب: (−۲)×۳ = ۶−، و بعد + ۱ = ۵−.

انتساب ترکیبی، ++ و --

در درس ۲.۱ دیدی age = age + 1; یعنی «مقدار را بخوان، یکی اضافه کن، برگردان». این الگو آن‌قدر پرتکرار است که C میان‌بُر دارد. به این میان‌بُرها انتساب ترکیبی می‌گوییم:

میان‌بُریعنی
x += 5;x = x + 5;
x -= 5;x = x - 5;
x *= 2;x = x * 2;
x /= 2;x = x / 2;
x %= 4;x = x % 4;
x++; و ++x;x = x + 1;
x--; و --x;x = x - 1;

ولی x++ و ++x یک تفاوت باریک دارند وقتی نتیجه‌شان را در جای دیگری استفاده کنی. مثل دو خبرنگار که یکی «قبل از ورود» و دیگری «بعد از ورود» عدد را می‌خواند:

  • a = i++; (پسوندی): اول مقدار فعلی i به a برود، بعد i یکی زیاد شود.
  • b = ++i; (پیشوندی): اول i یکی زیاد شود، بعد مقدار جدید به b برود.

خودت قدم به قدم ببین:

#include <stdio.h>

int main(void)
{
    int i = 5;
    int a = i++;
    int b = ++i;
    int total = 10;

    total += 5;
    total *= 2;
    total -= 6;
    total /= 4;
    total %= 4;

    printf("a = %d, b = %d, i = %d\n", a, b, i);
    printf("total = %d\n", total);
    return 0;
}
  1. شروع. i برابر ۵.
  2. پسوندی. a مقدار ۵ می‌گیرد و بعد i می‌شود ۶.
  3. پیشوندی. ابتدا i می‌شود ۷، بعد b همان ۷ را می‌گیرد.
  4. زنجیرهٔ میان‌بُرها. ۱۰ ← += 5 ← ۱۵ ← *= 2 ← ۳۰ ← -= 6 ← ۲۴ ← /= 4 ← ۶ ← %= 4 ← ۲. هر خط همان قفسهٔ total را با مقدار جدید پر می‌کند. مقدار قبلی می‌رود، همان که در درس ۲.۱ گفتیم.
  5. چاپ و پایان.
$ ./incdec
a = 5, b = 7, i = 7
total = 2
قاعدهٔ ایمن برای ++

تا وقتی تازه‌کاری، i++ را به‌تنهایی در یک دستور بنویس (مثل i++;) و هرگز نتیجه‌اش را در همان خط جای دیگری استفاده نکن. خوانندهٔ کد حواسش به «قبل یا بعد» نمی‌ماند و باگ کمتر می‌شود. در حلقه‌ها (درس ۲.۵) i++ تنها رایج‌ترین شکل است.

مقایسه: پرسش بله/خیر

عملگرهای مقایسه‌ای شش تا هستند: < کوچک‌تر، <= کوچک‌تر یا مساوی، > بزرگ‌تر، >= بزرگ‌تر یا مساوی، == مساوی، != نامساوی. دقت کن: «مساوی» با دو علامت == نوشته می‌شود، چون یک علامت = قبلا برای انتساب رزرو شده. جواب هر مقایسه در C یک int است: 1 اگر درست باشد و 0 اگر نادرست.

عملگر ! («نه» منطقی) هم داریم: !x اگر x صفر باشد ۱ می‌دهد و اگر غیرصفر باشد ۰. یعنی C هر عدد غیرصفر را «درست» می‌داند و فقط صفر را «نادرست». !!x هر عدد را به ۰ یا ۱ تبدیل می‌کند.

#include <stdio.h>

int main(void)
{
    int x = 7;

    printf("x > 3   -> %d\n", x > 3);
    printf("x == 7  -> %d\n", x == 7);
    printf("x != 7  -> %d\n", x != 7);
    printf("x <= 6  -> %d\n", x <= 6);
    printf("!x      -> %d\n", !x);
    printf("!!x     -> %d\n", !!x);
    return 0;
}
  1. مقایسه‌ها. هر مقایسه خودش یک عدد است (۱ یا ۰) که مستقیم به printf داده می‌شود. در زبان C نوع ویژه‌ای برای بله/خیر در خود عملگر نیست؛ جوابْ int است. به همین دلیل می‌شود مقایسه را در محاسبه هم به کار برد.
  2. نفی. ۷ غیرصفر است، پس «درست»؛ !x می‌شود ۰.
  3. نفیِ نفی. هر مقدار غیرصفر را به ۱ تبدیل می‌کند. در کد رجیستر زیاد می‌بینی.
$ ./rel
x > 3   -> 1
x == 7  -> 1
x != 7  -> 0
x <= 6  -> 0
!x      -> 0
!!x     -> 1
تله‌ای که از ریاضی می‌آید: 3 < x < 5

در ریاضی «۳ < x < ۵» یعنی x بین ۳ و ۵ است. در C این را به‌صورت (3 < x) < 5 می‌خواند: اول 3 < x می‌شود ۰ یا ۱ و بعد آن با ۵ مقایسه می‌شود، که همیشه درست است!

#include <stdio.h>

int main(void)
{
    int x = 7;

    printf("3 < x < 5  -> %d\n", 3 < x < 5);
    printf("x is between 3 and 5? -> %d\n", 3 < x && x < 5);
    return 0;
}
  1. زنجیرهٔ ریاضی‌وار. ۷ به‌وضوح بین ۳ و ۵ نیست، ولی جواب ۱ است: 3 < 7 می‌شود ۱ و 1 < 5 درست است. کامپایلر این را هشدار می‌دهد (-Wbool-compare)؛ هشدار را جدی بگیر.
  2. شکل درست. دو مقایسه را با && («و») به هم می‌بندیم. پایین‌تر کامل توضیح می‌دهیم.
$ gcc -std=c11 -Wall -Wextra -o chain chain.c
chain.c:7:40: warning: comparison of constant '5' with boolean expression is always true [-Wbool-compare]

$ ./chain
3 < x < 5  -> 1
x is between 3 and 5? -> 0

شرط ترکیبی: &&، || و میان‌بُر

گاهی یک پرسش کافی نیست: «دما بالای ۲۵ است و فن خاموش است؟» یا «دکمه A فشرده شده یا دکمه B؟». اینجا سه عملگر منطقی داریم:

عملگراسمدرست است وقتی…
a && bو (AND)هر دو درست باشند
a || bیا (OR)دست‌کم یکی درست باشد
!aنه (NOT)a نادرست باشد

یک ویژگی مهم: C برای صرفه‌جویی، وقتی جواب معلوم شد، بقیه را اصلا حساب نمی‌کند. اسمش ارزیابی میان‌بُر (short-circuit) است. مثل بازرس فرودگاه: اگر بلیت نداری، دیگر پاسپورتت را نگاه نمی‌کند. یعنی:

  • a && b: اگر a نادرست باشد، جواب حتما نادرست است و b اجرا نمی‌شود.
  • a || b: اگر a درست باشد، جواب حتما درست است و b اجرا نمی‌شود.
#include <stdio.h>

int main(void)
{
    int den = 0;
    int b = 5;

    int r1 = (den != 0) && (100 / den > 3);
    printf("r1 = %d\n", r1);

    int r2 = (den == 0) || (++b > 0);
    printf("r2 = %d, b = %d\n", r2, b);

    int r3 = (den == 0) && (++b > 0);
    printf("r3 = %d, b = %d\n", r3, b);
    return 0;
}
  1. دو مقدار. den که مخرج بالقوه است (صفر!) و b که می‌خواهیم ببینیم دست می‌خورد یا نه.
  2. محافظ تقسیم بر صفر. den != 0 نادرست است؛ پس طرف راست && اصلا اجرا نمی‌شود و تقسیم 100 / den هرگز رخ نمی‌دهد. نتیجه ۰. این الگو همه‌جا استفاده می‌شود: «اول بررسی کن ایمن است، بعد انجام بده» در یک خط. ترتیب مهم است! اگر ترتیب را برعکس کنی، تقسیم بر صفر اجرا می‌شود.
  3. یای میان‌بُر. den == 0 درست است؛ پس جواب «یا» معلوم است (۱) و طرف راست اجرا نمی‌شود. ++b اتفاق نمی‌افتد و b هنوز ۵ است.
  4. و با شرط اول درست. اول درست است؛ پس برای دانستن جواب باید طرف راست هم سنجیده شود. ++b اجرا می‌شود و b می‌شود ۶. پس عملگرهای منطقی می‌توانند اثر جانبی (تغییر متغیر) را «بپرند». برای همین در طرف راست && و || تغییر متغیر ننویس؛ خواننده را گیج می‌کند.

دو & یا یک &؟

&& و || منطقی‌اند (بله/خیر). & و | (تک‌علامتی) بیتی‌اند و بیت‌های دو عدد را جدا جدا ترکیب می‌کنند (درس ۳.۱). اشتباه گرفتن‌شان جواب‌های عجیب می‌دهد؛ مثلا 2 & 1 برابر ۰ است ولی 2 && 1 برابر ۱. و & میان‌بُر ندارد.

پنج تله‌ای که همه در آن می‌افتند

تلهٔ ۱: = به‌جای ==

این مشهورترین باگ C است. if (mode = 1) مقدار ۱ را در mode می‌گذارد و بعد ۱ (درست) را می‌سنجد. شرط همیشه درست می‌شود و mode هم خراب می‌شود. کامپایلر سرنخ می‌دهد:

#include <stdio.h>

int main(void)
{
    int mode = 2;

    if (mode = 1) {
        printf("mode is one\n");
    }
    printf("mode = %d\n", mode);
    return 0;
}
  1. انتساب در شرط. mode = 1 یک انتساب است، نه مقایسه. مقدار عبارت خود انتساب ۱ است. در C انتساب هم یک عبارت است و مقدار دارد (مقداری که ریخته شد). برای همین قانونی است و کامپایلر فقط هشدار می‌دهد.
  2. بدنه. همیشه اجرا می‌شود.
  3. تباهی. mode دیگر ۲ نیست.

هشدار پیش‌فرض -Wall اینجا را می‌گیرد؛ ما برای نمایش، آن را به خطا تبدیل کردیم (-Werror=parentheses). عادت مفید: مقدار ثابت را سمت چپ بنویس (if (1 == mode))؛ اگر یک = را جا بیندازی، کامپایلر خطا می‌دهد چون نمی‌شود در ۱ چیزی گذاشت. (این سبک را «Yoda condition» می‌نامند.)

تلهٔ ۲: تقسیم صحیح در جای نادرست

تقسیم صحیح را دیدی. تله وقتی است که «اول تقسیم و بعد ضرب» بنویسی: done / total * 100 برای درصد. چون 30 / 120 صحیح است و ۰ می‌شود، جواب ۰ است. باید اول ضرب کنی: done * 100 / total (تمرین ۲ همین است).

تلهٔ ۳: ترتیب ارزیابی نامشخص

C ترتیب انجام دو نیمهٔ یک عبارت را همیشه تعیین نمی‌کند. بدتر: اگر در یک عبارت یک متغیر را دو بار تغییر بدهی یا هم بخوانی و هم تغییر بدهی، نتیجه تعریف‌نشده است:

#include <stdio.h>

int main(void)
{
    int i = 1;

    i = i++ + i;
    printf("%d\n", i);
    return 0;
}
  1. تغییر و خواندنِ همزمان. در همین یک دستور، i هم با i++ تغییر می‌کند، هم در سمت راست خوانده می‌شود، هم در سمت چپ انتساب می‌شود. C نمی‌گوید کدام اول است. هر کامپایلر (و حتی هر سطح بهینه‌سازی) می‌تواند جواب متفاوتی بدهد. قاعده: در هر دستور، هر متغیر را حداکثر یک بار تغییر بده و اگر تغییرش دادی جای دیگر همان دستور نخوانش.

تلهٔ ۴: تقدم مقایسه در برابر بیتی

در جدول دیدی == (ردیف ۷) از & (ردیف ۸) تقدم بیشتری دارد. پس x & 1 == 0 یعنی x & (1 == 0) یعنی x & 0 که همیشه ۰ است، نه «آیا بیت صفر خاموش است؟». درمان: (x & 1) == 0 با پرانتز. این تله در کد رجیستر همه‌جا هست و در درس ۳.۱ به آن برمی‌گردیم.

تلهٔ ۵: سرریز میانی

حساب‌هایی مثل a * b / c ممکن است در وسط راه از ظرف بزرگ‌تر شوند حتی اگر جواب نهایی کوچک باشد. مثال بعدی، درست همین است و به شکل تمرین برای میکروکنترلر درمی‌آید.

مثال واقعی میکروکنترلر: از ADC به میلی‌ولت

یک ADC (مبدل آنالوگ به دیجیتال، درس ۲.۲) ولتاژ ورودی را به یک عدد صحیح تبدیل می‌کند. فرض کن ADC ۱۲ بیتی است: عدد ۰ یعنی ۰ ولت و عدد ۴۰۹۵ یعنی ولتاژ مرجع، مثلا ۳٫۳ ولت = ۳۳۰۰ میلی‌ولت. رابطهٔ خطی است: mv = adc * 3300 / 4095. ولی ببین ترتیب و نوع چه می‌کنند:

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint16_t adc = 4095;
    uint32_t good = (uint32_t)adc * 3300U / 4095U;
    uint32_t zero = adc * (3300U / 4095U);
    uint16_t narrow = (uint16_t)(adc * 3300U);

    printf("good   = %u\n", (unsigned)good);
    printf("zero   = %u\n", (unsigned)zero);
    printf("narrow = %u\n", (unsigned)narrow);
    return 0;
}
  1. خوانش ADC. بیشینهٔ ۱۲ بیتی؛ بدترین حالت برای سرریز.
  2. روش درست. اول adc را به uint32_t می‌بریم و بعد در ۳۳۰۰ ضرب می‌کنیم: ۱۳٬۵۱۳٬۵۰۰ که در ۳۲ بیت جا می‌شود. بعد تقسیم بر ۴۰۹۵ ← ۳۳۰۰. ضرب پیش از تقسیم دقت را نگه می‌دارد؛ ولی به ظرف بزرگ‌تر نیاز دارد. این معامله همیشگی «دقت در برابر ظرفیت» است.
  3. روش خراب ۱: تقسیم اول. 3300U / 4095U تقسیم صحیح است و ۰ می‌شود. هر ضربی در صفر، صفر است.
  4. روش خراب ۲: ظرف کوچک. حاصل‌ضرب ۱۳٬۵۱۳٬۵۰۰ را به uint16_t بریزیم، فقط ۱۶ بیت پایینش می‌ماند: ۱۳۰۸۴. روی STM32 و ESP32 می‌توانی این باگ را با ضرب در ۳۲ بیت پنهان کنی، اما کد همین منطق روی AVR (Arduino Uno) با int ۱۶ بیتی واقعا رخ می‌دهد.
  5. چاپ. با cast به unsigned (درس ۲.۲).

یک ریزه‌کاری دیگر: تقسیم صحیح همیشه قسمت اعشار را می‌اندازد؛ یعنی نتیجه همیشه «رو به پایین» گرد می‌شود. برای نتیجهٔ نزدیک‌ترین عدد، نصف مخرج را پیش از تقسیم به صورت اضافه کن:

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint32_t raw = 2000;
    uint32_t floored = raw * 3300U / 4095U;
    uint32_t rounded = (raw * 3300U + 4095U / 2U) / 4095U;

    printf("exact value  = 1611.72...\n");
    printf("floor result = %u\n", (unsigned)floored);
    printf("round result = %u\n", (unsigned)rounded);
    return 0;
}
  1. بریده‌شده. مقدار دقیق ۱۶۱۱٫۷۲ است ولی تقسیم صحیح ۰٫۷۲ را دور می‌اندازد.
  2. گردشده. 4095U / 2U (= ۲۰۴۷) را قبل از تقسیم اضافه می‌کنیم. چرا کار می‌کند؟ اگر اعشار ≥ ۰٫۵ باشد، جمع نیم مخرج یک واحد کامل روی جواب اضافه می‌کند، وگرنه نه.
  3. چاپ. ۱۶۱۱ در برابر ۱۶۱۲.
$ ./round
exact value  = 1611.72...
floor result = 1611
round result = 1612

حالا همین محاسبه را برای کامپایلر ARM (Cortex-M4) بنویس تا مطمئن شویم روی بردی مثل Nucleo-F411RE هم کامپایل می‌شود:

#include <stdint.h>

uint16_t adc_to_mv(uint16_t adc)
{
    return (uint16_t)(((uint32_t)adc * 3300U) / 4095U);
}

uint32_t second_of_minute(uint32_t uptime_s)
{
    return uptime_s % 60U;
}
  1. تابع تبدیل. ورودی و خروجی ۱۶ بیتی‌اند، ولی حساب میانی ۳۲ بیتی است. cast نهایی به uint16_t امن است چون جواب حداکثر ۳۳۰۰ است. قانون: «داده کوچک، حساب بزرگ». ورودی و خروجی را به اندازهٔ داده نگه دار و حساب میانی را در نوع پهن‌تر انجام بده.
  2. باقیمانده. ثانیهٔ درون دقیقه از روی زمان کل: مثال % در دنیای واقعی. (نوشتن تابع را در درس ۲.۶ می‌آموزی؛ اینجا فقط به شکلش نگاه کن.)

این کد فقط کامپایل می‌شود؛ خروجی ندارد.

در ESP32 چه؟

ESP32 هم ۳۲ بیتی است و همین قواعد را دارد: ترتیب ضرب و تقسیم، نوع میانی پهن‌تر و گردکردن. فقط بدان که ADC آن کاملا خطی نیست، و ESP-IDF برای تبدیل دقیق‌تر به میلی‌ولت ابزار کالیبراسیون دارد. جزئیاتش را در مستندات رسمی ESP-IDF ببین.

ESP32 هم ۳۲ بیتی است و همین قواعد را دارد. ADC آن معمولا ۱۲ بیتی است (۰ تا ۴۰۹۵)، ولی نمی‌گذارد یک دستور ساده مثل adc * 3300 / 4095 کافی باشد، چون رابطهٔ ولتاژ با عدد ADC خطی کامل نیست و در ESP-IDF کتابخانهٔ کالیبراسیون دارد که میلی‌ولت را برایت حساب می‌کند. جزئیات را در مستندات رسمی ESP-IDF ببین. آنچه اینجا آموختی (ترتیب، نوع میانی، گرد کردن) در هر دو تراشه لازم است.

آزمون این درس

مقدار 17 % 5 + 17 / 5 * 2 چند است؟

  1. ۸٫۸
  2. ۱۰
  3. ۸
  4. ۱۷
% و / هم‌تقدم‌اند و از چپ می‌روند؛ * هم. ۱۷%۵ = ۲؛ ۱۷/۵ = ۳؛ ۳×۲ = ۶؛ ۲ + ۶ = ۸.

خروجی چیست؟
int i = 3; int r = i++ * 2; printf("%d %d", r, i);

  1. ۶ و ۴
  2. ۸ و ۴
  3. ۶ و ۳
  4. خطای کامپایل
پسوندی یعنی «مقدار قدیمی را استفاده کن، بعد افزایش بده». پس ضرب ۳×۲ = ۶ و بعد i می‌شود ۴.

کدام خط باگ دارد؟

  1. if (level == 100) {
  2. total = a + b * 2;
  3. if (x > 0 && y > 0) {
  4. if (state = 0) {
state = 0 انتساب است؛ مقدار ۰ در state می‌نشیند و شرط همیشه نادرست می‌شود. باید state == 0 باشد.

با uint16_t adc = 3000; روی STM32 (int ۳۲ بیتی)، کدام عبارت میلی‌ولت را (با فرض ۳۳۰۰ mV برای ۴۰۹۵) درست می‌دهد؟

  1. adc * (3300 / 4095)
  2. (uint32_t)adc * 3300U / 4095U
  3. 3300 / 4095
  4. adc > 3300
اول ضرب در ظرف ۳۲ بیتی، بعد تقسیم؛ جواب برای ۳۰۰۰ برابر ۲۴۱۷ mV است.

در if (n != 0 && total / n > 10) چرا نوشتن n != 0 در سمت چپ مهم است؟

  1. چون سریع‌تر می‌شود
  2. چون && همیشه هر دو طرف را اجرا می‌کند
  3. چون اگر n صفر باشد، میان‌بُر مانع اجرای تقسیم می‌شود
  4. چون ترتیب اهمیتی ندارد
اگر n == 0 شرط اول نادرست است و طرف راست اجرا نمی‌شود، پس تقسیم بر صفر رخ نمی‌دهد.

تمرین‌ها

تمرین ۱: ثانیه به ساعت و دقیقه

یک دستگاه با تراشهٔ STM32 مدت کارکرد را به ثانیه نگه می‌دارد (مثلا ۷۳۸۴ ثانیه). می‌خواهیم آن را به «ساعت، دقیقه، ثانیه» تبدیل کنیم.

  1. پیش‌بینی: با ماشین‌حساب ۷۳۸۴ را به ساعت و دقیقه و ثانیه تبدیل کن (هر ساعت ۳۶۰۰ ثانیه).
  2. حل: فقط با / و % برنامه بنویس که بگوید ۷۳۸۴ ثانیه چند ساعت، چند دقیقه و چند ثانیه است.
  3. چالش: برنامه را طوری تغییر بده که روز را هم جدا کند (۸۶۴۰۰ ثانیه = ۱ روز).
راهنمایی

ساعت‌ها = total / 3600. باقیماندهٔ total % 3600 ثانیه‌هایی است که به ساعت کامل نرسیده؛ آن را بر ۶۰ تقسیم کن تا دقیقه بیاید. ثانیهٔ آخر = total % 60.

#include <stdio.h>

int main(void)
{
    int total = 7384;
    int hours = total / 3600;
    int minutes = total % 3600 / 60;
    int seconds = total % 60;

    printf("%d s = %d h %d m %d s\n", total, hours, minutes, seconds);
    return 0;

  1. ساعت. ۷۳۸۴ ÷ ۳۶۰۰ = ۲ (باقی ۱۸۴)؛ تقسیم صحیح بقیه را می‌اندازد.
  2. دقیقه. % و / هم‌تقدم‌اند و از چپ می‌روند؛ پس این (total % 3600) / 60 است: ۱۸۴ ÷ ۶۰ = ۳. پرانتز اضافه (total % 3600) / 60 خواناتر است؛ حتما در کد واقعی بگذار.
  3. ثانیه. باقیماندهٔ تقسیم بر ۶۰: چون ۷۳۸۴ = ۱۲۳ × ۶۰ + ۴، جواب ۴ است.
  4. چاپ. ۲ ساعت و ۳ دقیقه و ۴ ثانیه: ۲×۳۶۰۰ + ۳×۶۰ + ۴ = ۷۳۸۴ ✓

برنامهٔ نوار پیشرفت باید ۲۵٪ نشان بدهد (۳۰ کار از ۱۲۰ انجام شده). ولی چیز دیگری چاپ می‌کند.

  2. پیدا کردن: علت را با کلمات «تقسیم صحیح» و «ترتیب» توضیح بده.

تمرین ۳: دما از سنسور آنالوگ

یک سنسور دمای آنالوگ (مثل TMP36) ولتاژ خروجی ۵۰۰ میلی‌ولت در ۰ درجه دارد و به‌ازای هر درجه ۱۰ میلی‌ولت اضافه می‌کند. پس دما بر حسب «دهم درجه» برابر است با mv - 500 (چون هر میلی‌ولت = ۰٫۱ درجه). خوانش ADC (۱۲ بیتی، مرجع ۳٫۳ ولت) عدد ۹۳۰ است.

  1. پیش‌بینی: با ماشین‌حساب: ۹۳۰ × ۳۳۰۰ ÷ ۴۰۹۵ = ؟ میلی‌ولت، و دما = ؟
  2. حل: برنامه بنویس که با int32_t میلی‌ولت و دما (به دهم درجه) را حساب کند و به شکل 24.9 C چاپ کند (صحیح = t / 10، اعشار = t % 10).
  3. چالش: اگر دما ۲٫۵- درجه (یعنی tenths = -25) باشد، همان چاپ چه می‌نویسد؟ آن را اجرا کن و خطا را توضیح بده.
راهنمایی

ضرب را در int32_t انجام بده: (int32_t)adc * 3300 / 4095. برای چاپ از دو %d با یک نقطه بینشان استفاده کن. یادت باشد برای منفی‌ها / به سمت صفر می‌بُرد و % علامت عدد اول را می‌گیرد.

چه باید ببینی؟ 
$ ./ex3
adc = 930, mv = 749
temp = 24.9 C
negative: -2.-5 C
جواب کامل با توضیح 
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint16_t adc = 930;
    int32_t mv = (int32_t)adc * 3300 / 4095;
    int32_t tenths = mv - 500;

    printf("adc = %d, mv = %d\n", (int)adc, (int)mv);
    printf("temp = %d.%d C\n", (int)(tenths / 10), (int)(tenths % 10));

    tenths = -25;
    printf("negative: %d.%d C\n", (int)(tenths / 10), (int)(tenths % 10));
    return 0;
}
  1. خوانش خام. ۹۳۰ از ۴۰۹۵.
  2. میلی‌ولت. cast به ۳۲ بیتی علامت‌دار، ضرب، بعد تقسیم؛ ۷۴۹ (۷۴۹٫۶ بریده شد). علامت‌دار انتخاب شد چون در خط بعد تفریق ممکن است نتیجه را منفی کند.
  3. دهم درجه. ۷۴۹ − ۵۰۰ = ۲۴۹؛ یعنی ۲۴٫۹ درجه. بدون اعشاری کار کردیم.
  4. چاپ صحیح و اعشار. ۲۴۹ ÷ ۱۰ = ۲۴ و ۲۴۹ % ۱۰ = ۹.
  5. باگ منفی‌ها. ‎-25 / 10 می‌شود ‎-2 و ‎-25 % 10 می‌شود ‎-5 (علامت دارد)؛ چاپ می‌شود «‎-2.-5»، که اشتباه است: باید «‎-2.5» باشد. راه درست: علامت را جدا کن (اگر منفی است، یک بار ‎- چاپ کن و مقدار را مثبت کن)، بعد جزء صحیح و اعشار را چاپ کن. شرط را در درس بعد یاد می‌گیری.

حرف مربی

در این درس معمولا دو چیز مغز آدم را قفل می‌کند: «چرا ۷/۲ می‌شود ۳؟» و «کدام اول حساب می‌شود؟». جواب اولی این است که C نوع جواب را از نوع عملوندها می‌گیرد، نه از خواسته‌ات. جواب دومی: پرانتز بگذار! هیچ برنامه‌نویس حرفه‌ای جدول تقدم را کامل حفظ نیست؛ همه پرانتز می‌گذارند. عادتی که از اینجا با خودت ببر: هر بار در عبارت، عدد صحیح و تقسیم دیدی، ضرب را جلو بینداز و اندازهٔ نوع میانی را بررسی کن. و هرگز نتیجهٔ i++ را در همان خط جای دیگری استفاده نکن.

خلاصه یک‌دقیقه‌ای

  • عملگر روی عملوند کار می‌کند؛ ترکیب‌شان یک عبارت است که مقدار دارد.
  • / روی دو عدد صحیح، تقسیم صحیح است (اعشار را می‌اندازد و به سمت صفر می‌بُرد)؛ % باقیمانده است و علامت عدد اول را می‌گیرد. تقسیم بر صفر تعریف‌نشده است.
  • تقدم: ضرب/تقسیم/باقیمانده قبل از جمع/تفریق؛ همه از چپ به راست. وقتی مطمئن نیستی پرانتز بگذار.
  • +=، -=، *= و… میان‌بُر انتساب‌اند. i++ مقدار قدیمی، ++i مقدار جدید را به عبارت می‌دهد.
  • مقایسه‌ها ۱ یا ۰ می‌دهند؛ صفر نادرست و هر عدد غیرصفر درست است. = انتساب است، == مقایسه. زنجیرهٔ 3 < x < 5 کار نمی‌کند؛ از && استفاده کن.
  • && و || میان‌بُر دارند: طرف راست فقط در صورت نیاز اجرا می‌شود. شرط محافظ را سمت چپ بگذار.
  • در حساب میکروکنترلر: ضرب را پیش از تقسیم انجام بده، نوع میانی را بزرگ‌تر بگیر، و برای گردشدن نصف مخرج را اضافه کن.
