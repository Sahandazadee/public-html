هر برنامه‌ای که تا حالا دیده‌ای، از بازی گوشی تا ماشین لباس‌شویی، مجبور است چیزی را به یاد بسپارد: امتیاز، دما، اینکه در باز است یا بسته. در C، جای یادداشت‌کردن این چیزها را «متغیر» می‌گویند. در این درس یاد می‌گیری متغیر دقیقا چیست، در کدام نقطه از حافظه می‌نشیند و چرا بسیاری از باگ‌های مبتدی‌ها از سوءتفاهم با همین موضوع می‌آید.

🎯 بعد از این درس می‌توانی

  • متغیر بسازی، مقدار بدهی و مقدارش را عوض کنی
  • فرق «تعریف»، «مقدار اولیه» و «انتساب» را بگویی
  • اسم درست برای متغیر انتخاب کنی و اسم‌های غلط را تشخیص بدهی
  • توضیح بدهی متغیر در RAM میکروکنترلر چند بایت جا می‌گیرد و کجاست
  • پیام خطای کامپایلر برای const و متغیر بدون مقدار را بفهمی

🧰 پیش‌نیاز و وسایل

  • درس ۱.۴ (اولین برنامه، main و printf)
  • درس ۱.۲ (بیت و بایت). اگر فراموش کرده‌ای، «هر بایت = ۸ بیت» را یادت باشد
  • یک کامپایلر روی رایانه‌ات، یا سایت‌های آنلاین معرفی‌شده در ۱.۳
  • هیچ سخت‌افزاری لازم نیست

ایده اصلی: قفسه‌ای با برچسب

یک انبار بزرگ را تصور کن که میلیون‌ها قفسه کوچک دارد. هر قفسه یک شماره دارد، مثل ۰، ۱، ۲، ... و فقط یک عدد کوچک در خودش نگه می‌دارد. حافظه (RAM) کامپیوتر و میکروکنترلر دقیقا همین است.

حالا اگر بخواهی «سن کاربر» را نگه داری، لازم نیست شماره قفسه را حفظ کنی. یک برچسب می‌زنی: روی قفسه بنویس age. از این به بعد فقط می‌گویی «برو سراغ age». همین برچسب + قفسه + چیزی که داخلش است، یعنی متغیر.

مثال از زندگی روزمره

کمدهای رختکن باشگاه را ببین: هر کمد شماره دارد (آدرس)، اندازه‌اش مشخص است (نوع) و تو با یک برچسب اسم خودت روی آن می‌شناسیش (نام). داخل کمد چیزی می‌گذاری (مقدار) و فردا می‌توانی آن را عوض کنی. کمد همان کمد است؛ فقط محتویاتش عوض می‌شود. به همین دلیل اسمش را «متغیر» گذاشته‌اند: چیزی که مقدارش می‌تواند تغییر کند.

یک خط، چهار تکه

ساختن یک متغیر در C همیشه چند تکه دارد. با int age = 25; شروع می‌کنیم:

  • نوع (type): به کامپایلر می‌گوید چه مقدار جا بگیرد و آن جا را چطور تفسیر کند. int یعنی «عدد صحیح» (بدون اعشار).
  • نام (identifier): برچسبی که خودت انتخاب می‌کنی.
  • مقدار اولیه: چیزی که همان لحظه ساخته‌شدن در قفسه گذاشته می‌شود.

اولین برنامه با متغیر

این برنامه را روی رایانه‌ات (یا کامپایلر آنلاین) اجرا کن. اگر هنوز با main و printf راحت نیستی، درس ۱.۴ را یک بار دیگر ورق بزن. اینجا فقط لازم است بدانی printf("%d", x) مقدار عددی x را چاپ می‌کند.

#include <stdio.h>

int main(void)
{
    int age = 25;       // ساختن متغیر و مقدار اولیه دادن
    int year;           // فقط ساختن (هنوز مقدار معتبر ندارد!)
    year = 2026;        // بعدا مقدار دادن

    printf("age = %d\n", age);
    printf("year = %d\n", year);

    age = age + 1;      // مقدار قدیمی را بخوان، یکی اضافه کن، برگردان
    printf("next age = %d\n", age);
    return 0;
}
  1. کتابخانه ورودی/خروجی. #include <stdio.h> به کامپایلر می‌گوید تعریف printf را از فایل stdio.h بردار. بدون آن، کامپایلر printf را نمی‌شناسد. C عمدا کوچک است و هیچ چیز را خودکار نمی‌آورد. هر قابلیتی را خودت صریح می‌خواهی.
  2. تابع main. نقطه شروع برنامه. هر چیزی بین { و } به ترتیب از بالا به پایین اجرا می‌شود. این ترتیب «بالا به پایین» تنها قانونی است که کامپایلر برایت تضمین می‌کند. جای خط‌ها مهم است.
  3. تعریف با مقدار اولیه. یک قفسه ۴ بایتی به اسم age بساز و همان لحظه عدد ۲۵ را داخلش بگذار. بهترین عادت: هر متغیر را همان لحظه ساختن مقدار بده. قفسه‌ای که تازه ساخته شده، مثل کمد دست‌دوم است و ممکن است چیز عجیبی داخلش باشد.
  4. تعریف بدون مقدار. قفسه year ساخته می‌شود ولی محتویاتش نامعلوم است. به این محتوی مبهم «مقدار آشغال» (garbage) می‌گویند. C برای سرعت، قفسه را پاک نمی‌کند. پاک‌کردن هم زمان می‌برد و در میکروکنترلر هر میکروثانیه ارزش دارد. پس مسئولیتش با توست.
  5. انتساب (assignment). عدد ۲۰۲۶ را داخل قفسه year بگذار. علامت = در C یعنی «بگذار داخل»، نه «برابر است با». این بزرگ‌ترین تفاوت با ریاضی است. در ریاضی x = x + 1 غلط است؛ در C یعنی «مقدار x را بخوان، یکی اضافه کن، دوباره در x بگذار».
  6. چاپ مقدارها. %d جای یک عدد صحیح را نگه می‌دارد و printf آن را با مقدار واقعی متغیر جایگزین می‌کند. \n یعنی «برو خط بعد». قالب‌ها (مثل %d) به printf می‌گویند بایت‌های خام حافظه را چطور بخواند. اگر قالب با نوع متغیر نخواند، خروجی بی‌معنی می‌شود. در درس ۲.۸ همه را می‌آموزیم.
  7. تغییر مقدار. سمت راست = اول حساب می‌شود (۲۵ + ۱ = ۲۶)، بعد نتیجه در قفسه age گذاشته می‌شود و مقدار قدیمی از بین می‌رود. قفسه فقط یک مقدار نگه می‌دارد. مقدار جدید که آمد، قدیمی برای همیشه رفته است.
  8. return 0. به سیستم‌عامل می‌گوید برنامه موفق تمام شد. روی میکروکنترلر معمولا main هرگز تمام نمی‌شود؛ بعدا می‌بینی. صفر در دنیای C یعنی «همه چیز درست بود». هر عدد دیگر یعنی خطا.
$ gcc -std=c11 -Wall -Wextra -o variables variables.c
$ ./variables
age = 25
year = 2026
next age = 26

متغیرها از هم مستقل‌اند

یک سوءتفاهم بسیار رایج: فکر می‌کنند اگر بنویسی b = a، «b همیشه همراه a می‌ماند». این‌طور نیست! b = a فقط یک بار مقدار فعلی a را می‌خواند و یک کپی در قفسه b می‌گذارد. بعد از آن، دو قفسه هیچ ارتباطی ندارند.

خودت ببین. روی «بعدی» بزن و اجرا را خط‌به‌خط دنبال کن:

#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = a;          // کپی مقدار فعلی a
    a = 9;              // فقط a عوض می‌شود
    printf("a = %d, b = %d\n", a, b);
    return 0;
}
  1. قفسه a. مقدار اولیه ۵.
  2. کپی به b. مقدار فعلی a خوانده و در قفسه تازه b گذاشته می‌شود. قفسه b آدرس متفاوتی دارد (در شکل بالا ۴ بایت آن‌طرف‌تر). پس عوض‌کردن یکی، دیگری را لمس نمی‌کند.
  3. تغییر فقط a. ۹ جای ۵ را می‌گیرد و b دست‌نخورده می‌ماند.
  4. چاپ هر دو. نشان می‌دهد که مقدارها جدا شدند.
$ ./copy
a = 9, b = 5

اسم‌گذاری: قانون‌ها و عادت‌ها

اسم متغیر (به اصطلاح شناسه) برچسبی است که خودت می‌گذاری، اما C چند قانون سخت دارد:

قانونمجازغیرمجازچرا؟
فقط حرف انگلیسی، رقم و _sensor_1sensor-1، دما- علامت تفریق است؛ حروف فارسی مجاز نیست

عادت حرفه‌ای‌ها
  • اسم را معنی‌دار بگذار: battery_mv از b و x1 بهتر است. شش ماه بعد خودت هم یادت نمی‌آید x1 چه بود.
  • واحد را در اسم بیاور: timeout_ms، temp_c. در پروژه‌های واقعی میلیون‌ها دلار بر اثر اشتباه واحد از بین رفته است.
  • اسم‌ها با snake_case (کلمه‌ها با زیرخط) در کد embedded رایج‌تر از camelCase است (مثلا temp_c در برابر tempC). مهم‌تر از سبک، یکنواختی در کل پروژه است.
  • _ وسط یا آخر اسم مجاز است، ولی اسمی که با _ شروع می‌شود (مخصوصا _ + حرف بزرگ یا دو زیرخط) جزو اسم‌های رزروشدهٔ C و کتابخانه‌هاست؛ پس اسم خودت را با _ شروع نکن.

قفسه قفل‌شده: const

بعضی مقدارها نباید هرگز عوض شوند؛ مثلا حداکثر دمای مجاز یک موتور. با کلمه const (از constant، یعنی ثابت) به کامپایلر می‌گویی «این قفسه را بعد از پر شدن قفل کن». اگر بعدا (حتی بی‌خیالی) مقدارش را عوض کنی، کامپایلر جلویت را می‌گیرد:

#include <stdio.h>

int main(void)
{
    const int max_temp = 80;
    max_temp = 90;              // خطا! قفسه قفل است
    printf("%d\n", max_temp);
    return 0;
}
  1. const. این متغیر فقط‌خواندنی است. مقدارش فقط همین‌جا داده می‌شود. تو نمی‌خواهی یک اشتباه تایپی در خط ۲۰۰ برنامه، حد ایمنی یک دستگاه را عوض کند. const این اشتباه را از زمان اجرا (خطرناک) به زمان کامپایل (بی‌خطر) می‌آورد.
  2. تلاش برای عوض‌کردن. کامپایلر این را نمی‌پذیرد و برنامه اصلا ساخته نمی‌شود. خطای کامپایل بهترین نوع خطاست: قبل از اینکه هیچ کاربری با آن روبه‌رو شود پیدایش می‌کنی.
const_error.c: In function 'main':
const_error.c:6:14: error: assignment of read-only variable 'max_temp'

نشانی خطا را بخوان: const_error.c:6:14 یعنی «فایل، خط ۶، ستون ۱۴». پیام می‌گوید «انتساب به متغیر فقط‌خواندنی». در میکروکنترلر const یک مزیت ویژه دارد که در درس ۳.۵ می‌بینی: مقدارهای ثابت می‌توانند در Flash (ارزان) بمانند و RAM (کم) را اشغال نکنند.

وقتی مقدار نداده‌ای: بلای «مقدار آشغال»

یادت هست گفتیم قفسه‌ای که تازه ساخته می‌شود پاک نیست؟ ببین اگر از آن استفاده کنی چه می‌شود:

#include <stdio.h>

int main(void)
{
    int reading;                // مقدار نداده‌ایم!
    int doubled = reading * 2;  // از آشغال استفاده می‌کنیم
    printf("%d\n", doubled);
    return 0;
}

$ gcc -std=c11 -Wall -Wextra -Werror=uninitialized -o garbage garbage.c
garbage.c: In function 'main':
garbage.c:6:9: error: 'reading' is used uninitialized [-Werror=uninitialized]

بالا دستور دقیق را می‌بینی: گزینهٔ -Werror=uninitialized هشدار کامپایلر را به‌عمد به خطا تبدیل کرده تا برنامه ساخته نشود. اگر همین فایل را با دستور همیشگی gcc -std=c11 -Wall -Wextra garbage.c -o garbage (بدون آن گزینه) کامپایل کنی، به‌جای error فقط یک warning: 'reading' is used uninitialized می‌بینی، برنامه ساخته می‌شود و هر بار عدد عجیبی چاپ می‌کند (عدد تو با عدد دوستت فرق دارد)؛ این بدترین حالت ممکن است چون باگ فقط گاهی ظاهر می‌شود. برای همین همیشه با -Wall -Wextra کامپایل کن و هشدارها را جدی بگیر.

در میکروکنترلر خطرناک‌تر است

روی PC آشغالِ قفسه معمولا چیزی بی‌ضرر است. روی میکروکنترلر ممکن است آشغالِ یک متغیر باعث شود موتور با سرعت کامل بچرخد یا رله ناگهان وصل شود. قاعده طلایی: هیچ متغیری را بدون مقدار اولیه نگذار.

روی لپ‌تاپ هم همین است

وقتی برنامه را روی لپ‌تاپ اجرا می‌کنی هم قفسه‌ها همین‌جورند؛ فقط انبار (RAM) چند گیگابایت است و سیستم‌عامل جای قفسه‌ها را برایت انتخاب می‌کند. در بخش بعد به انبار کوچک میکروکنترلر نگاه می‌کنیم.

در STM32 و ESP32 متغیر من کجاست؟

یادت هست گفتیم حافظه یک انبار خانه‌های شماره‌دار است؟ در میکروکنترلر این انبار دو بخش اصلی دارد:

FlashRAM (اینجا متغیرها زندگی می‌کنند)
شبیهکتاب چاپ‌شدهتخته‌سفید
با خاموشیمی‌ماندپاک می‌شود
سرعت نوشتنکند و محدودسریع
محتواکد برنامه و ثابت‌هامتغیرها
حجم در STM32F411۵۱۲ کیلوبایت۱۲۸ کیلوبایت (شروع از 0x20000000)

توجه کن: ۱۲۸ کیلوبایت یعنی ۱۲۸ هزار خانه. اگر ۴۰ هزار متغیر int بسازی، RAM پر می‌شود. در PC با چندین گیگابایت هیچ‌وقت به این فکر نمی‌کردی؛ در میکروکنترلر هر متغیر یک هزینه دارد.

پرسش رایج: مگر int همیشه ۴ بایت است؟

نه! اندازه int را استاندارد C ثابت نکرده. در STM32 و ESP32 چهار بایت (۳۲ بیت) است، ولی در Arduino Uno (پردازنده AVR ۸ بیتی) فقط دو بایت است و عدد ۴۰۰۰۰ جایش نمی‌شود. به همین دلیل در درس بعد یاد می‌گیریم برای کار حرفه‌ای از نوع‌هایی مثل uint32_t استفاده کنیم که اندازه‌شان تضمین‌شده است.

#include <stdio.h>

int main(void)
{
    int age = 25;
    printf("sizeof(age) = %zu bytes\n", sizeof(age));
    printf("sizeof(int) = %zu bytes\n", sizeof(int));
    return 0;
}
  1. sizeof. عملگری که «این چیز چند بایت جا می‌گیرد؟» را جواب می‌دهد. می‌توانی نام متغیر یا نام نوع را به آن بدهی. به‌جای حفظ‌کردن اندازه‌ها، از خود کامپایلر بپرس. این کد وقتی به میکروکنترلر دیگری بروی، خودش درست می‌ماند.
  2. %zu. قالب مخصوص نتیجه sizeof (نوع size_t). در درس ۲.۸ بیشتر می‌گوییم؛ فعلا فقط کپی کن.
$ ./sizes
sizeof(age) = 4 bytes
sizeof(int) = 4 bytes

آزمون این درس

دستور int count = 7; دقیقا چه کاری می‌کند؟

  1. عدد ۷ را روی صفحه چاپ می‌کند
  2. فقط اسم count را می‌سازد و خالی می‌گذارد
  3. قفسه‌ای برای عدد صحیح به اسم count می‌سازد و ۷ را در آن می‌گذارد
  4. بررسی می‌کند count برابر ۷ هست یا نه
نوع (int) + نام (count) یک قفسه می‌سازد و = 7 مقدار اولیه‌اش را می‌گذارد.

بعد از این کد، مقدار y چند است؟
int x = 4; int y = x; x = 100;

  1. ۱۰۰
  2. ۴
  3. ۰
  4. برنامه کامپایل نمی‌شود
y = x فقط یک‌بار مقدار آن لحظه را کپی می‌کند. بعدا عوض‌شدن x به y ربطی ندارد.

کدام اسم متغیر در C غیرمجاز است؟

  1. battery_level
  2. value2
  3. Speed
  4. 3rd_sensor
اسم نباید با رقم شروع شود. 3rd_sensor را کامپایلر به‌صورت عدد ۳ و بعد چیز نامفهوم می‌خواند. با sensor_3 جایگزینش کن.

چرا بهتر است int total = 0; بنویسیم به‌جای int total; و بعدا مقدار دادن؟

  1. چون قفسه‌ی بدون مقدار اولیه شامل آشغال است و استفاده از آن رفتار غیرقابل‌پیش‌بینی می‌دهد
  2. چون برنامه سریع‌تر اجرا می‌شود
  3. چون RAM کمتری مصرف می‌کند
  4. چون C بدون مقدار اولیه اجازه ساخت متغیر نمی‌دهد
C اجباری نکرده ولی بدون مقدار اولیه قفسه پر از آشغال است. این یکی از باگ‌های پرتکرار برنامه‌های embedded است.

در C عبارت score = score + 10; چه معنایی دارد؟

  1. یک معادله‌ی غلط که هرگز درست نمی‌شود
  2. بررسی می‌کند score با score+10 برابر است
  3. مقدار فعلی score را بخوان، ۱۰ تا اضافه کن، نتیجه را دوباره در score بگذار
  4. یک متغیر جدید به‌اسم score می‌سازد
علامت = یعنی «بگذار داخل». سمت راست اول حساب می‌شود، سپس نتیجه در قفسه سمت چپ می‌نشیند.

تمرین‌ها

تمرین ۱: جابه‌جا کردن دو مقدار

دو متغیر left = 10 و right = 20 داری. می‌خواهیم مقدارشان را جابه‌جا کنیم، بدون اینکه هیچ عدد جدیدی را تایپ کنیم.

  1. پیش‌بینی: اگر بنویسی left = right; right = left;، فکر می‌کنی نتیجه چه می‌شود؟ (اول حدس بزن، بعد امتحان کن.)
  2. حل: با یک متغیر کمکی temp، برنامه‌ای بنویس که مقدارها را درست جابه‌جا کند و قبل و بعد را چاپ کند.
  3. چالش: فکر کن چرا بدون temp ناممکن به‌نظر می‌رسد. (راهنمایی: قفسه فقط یک مقدار نگه می‌دارد.)
راهنمایی

مثل جابه‌جا کردن دو لیوان آب؛ یک لیوان خالی سوم لازم داری. اول چیزی را در temp نگه دار که می‌خواهی از دستش ندهی.

چه باید ببینی؟ 
$ ./swap
before: left = 10, right = 20
after:  left = 20, right = 10

جواب قسمت الف: با left = right; right = left; هر دو ۲۰ می‌شوند! چون بعد از خط اول، مقدار ۱۰ برای همیشه از بین رفته است.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int left = 10;
    int right = 20;
    int temp;

    printf("before: left = %d, right = %d\n", left, right);
    temp = left;        // ۱۰ را نجات بده
    left = right;       // حالا می‌شود ۲۰ را در left گذاشت
    right = temp;       // ۱۰ نجات‌یافته را در right بگذار
    printf("after:  left = %d, right = %d\n", left, right);
    return 0;
}
  1. سه قفسه. دو قفسه اصلی با مقدار اولیه و یک قفسه موقتی temp.
  2. نجات مقدار. ۱۰ را در temp کپی می‌کنیم تا وقتی left را رونویسی کردیم، ۱۰ از بین نرود.
  3. رونویسی. ۲۰ (مقدار right) به left می‌رود. حالا هر دو ۲۰ هستند.
  4. بازگرداندن. ۱۰ نجات‌یافته از temp به right می‌رود. این الگو در embedded بسیار رایج است: مثلا وقتی می‌خواهی مقدار قبلی سنسور را نگه داری و مقدار جدید را وارد کنی.
تمرین ۲: نام‌های خراب را پیدا کن

هر کدام از این چهار خط (در فهرست زیر) یک مشکل دارد. مشکل هر خط را بگو و نسخه درست را بنویس.

  1. int 2fast = 10;
  2. int speed limit = 60;
  3. int while = 3;
  4. int count = 5
راهنمایی

قانون‌های جدول «اسم‌گذاری» را دوباره نگاه کن. برای خط آخر به پایان دستور فکر کن.

چه باید ببینی؟

نسخه درست چهار خط برنامه را که کامپایل کنی، هیچ خطایی نمی‌گیری. نسخه غلط را اگر امتحان کنی، کامپایلر حداقل چهار پیام خطا می‌دهد.

جواب کامل با توضیح
خطمشکلاصلاح
الفاسم با رقم شروع شدهint fast2 = 10;
بفاصله دو اسم می‌سازدint speed_limit = 60;
پwhile کلمه رزرو‌شده استint loop_count = 3;
تنقطه‌ویرگول پایان دستور فراموش شدهint count = 5;
#include <stdio.h>

int main(void)
{
    int fast2 = 10;
    int speed_limit = 60;
    int loop_count = 3;
    int count = 5;

$ ./names_fixed

تمرین ۳: دمای سلسیوس به فارنهایت

فرمول F = C × 9 ÷ 5 + 32 را با متغیرهای int پیاده کن.

  1. پیش‌بینی: برای ۲۵ درجه سلسیوس چه عددی انتظار داری؟ (با ماشین‌حساب حساب کن.)
  2. حل: برنامه را بنویس، به‌گونه‌ای که سلسیوس در یک متغیر باشد و فارنهایت در متغیر دیگر.
  3. تغییر: مقدار سلسیوس را به ۱۰۰ تغییر بده. عدد فارنهایت چند می‌شود؟ (بجوش آمدن آب!)
راهنمایی

دو متغیر لازم داری: celsius و fahrenheit. اولی را مقدار بده، دومی را با یک عبارت حساب کن.

چه باید ببینی؟ 
$ ./temp
25 C = 77 F

با ۱۰۰ سلسیوس باید ۲۱۲ فارنهایت ببینی.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int celsius = 25;
    int fahrenheit = celsius * 9 / 5 + 32;

    printf("%d C = %d F\n", celsius, fahrenheit);
    return 0;
}
  1. ورودی. مقدار سلسیوس را جایی می‌گذاریم که راحت عوض شود. در برنامه واقعی این عدد از سنسور می‌آید. حالا فقط جایش را آماده کرده‌ای.
  2. محاسبه. اول ضرب در ۹ (۲۲۵)، بعد تقسیم بر ۵ (۴۵)، بعد جمع با ۳۲ (۷۷). ترتیب ضرب قبل از تقسیم مهم است. تقسیم int اعشار را دور می‌اندازد. اگر اول 9/5 را حساب کنی، جواب ۱ می‌شود و همه چیز خراب می‌شود. جزئیات در درس ۲.۳. اگر به‌جای ۷۷ عدد ۵۷ دیدی، یعنی 9 / 5 * celsius نوشته‌ای: این همان تقسیم صحیح است که ۹/۵ را ۱ می‌کند.
  3. چاپ. دو %d برای دو مقدار.
$ ./temp
25 C = 77 F
حرف مربی

تقریبا همه در همین درس دو جا گیر می‌کنند: اول فکر می‌کنند = یعنی مساوی، و دوم یادشان می‌رود متغیر را مقدار بدهند. اگر امروز فقط یک عادت با خودت ببری، این باشد: هر متغیر را همان لحظه ساخته‌شدن مقدار بده. و هر بار کامپایل کردی، -Wall -Wextra را فراموش نکن. کامپایلر رایگان‌ترین همکار توست.

خلاصه یک‌دقیقه‌ای

  • متغیر = قفسه‌ای در RAM با نوع، نام، مقدار و آدرس.
  • int age = 25; یعنی تعریف + مقدار اولیه؛ age = 26; یعنی انتساب.
  • = یعنی «بگذار داخل»، نه «برابر است با». b = a فقط یک‌بار کپی می‌کند.
  • اسم: حرف/رقم/زیرخط، بدون شروع با رقم، بدون فاصله، بدون keyword. حروف بزرگ و کوچک فرق دارند.
  • const = قفسه قفل‌شده؛ بدون مقدار اولیه = آشغال؛ همیشه مقدار اولیه بده.
  • روی STM32 و ESP32 int چهار بایت است و در RAM (تخته‌سفید) می‌نشیند، نه Flash.
