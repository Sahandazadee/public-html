تا اینجا برنامه‌های ما مثل یک فهرست خرید بودند: خط اول، خط دوم، خط سوم، بدون هیچ انتخابی. ولی دنیای واقعی پر از «اگر» است: اگر هوا گرم شد فن را روشن کن، اگر دکمه فشرده شد چراغ را وصل کن، اگر باتری ته کشید هشدار بده. در این درس یاد می‌گیری به برنامه‌ات قدرت تصمیم‌گرفتن بدهی.

🎯 بعد از این درس می‌توانی

  • با if و else و else if برنامه را به چند مسیر تقسیم کنی
  • بگویی در C چه چیزی «درست» است و چه چیزی «نادرست»
  • با switch یک عدد را بین چند حالت پخش کنی و بدانی break چرا لازم است
  • تله‌ی معروف = به‌جای == و آکولاد فراموش‌شده را بشناسی
  • منطق «هیسترزیس» ترموستات و خواندن یک دکمه در میکروکنترلر را بنویسی

🧰 پیش‌نیاز و وسایل

  • درس ۲.۱ (متغیر و انتساب) و درس ۲.۳ (عملگرهای مقایسه‌ای؛ اینجا هم یادآوری می‌کنیم)
  • یک کامپایلر روی رایانه‌ات، یا کامپایلر آنلاین معرفی‌شده در ۱.۳
  • هیچ سخت‌افزاری لازم نیست

ایده اصلی: دوراهی

صبح از خانه بیرون می‌روی. در ذهنت یک سؤال بله/خیر می‌پرسی: «باران می‌بارد؟». اگر جواب «بله» است چتر برمی‌داری. اگر «نه»، بدون چتر می‌روی. بعد از این تصمیم، هر دو حالت به یک مسیر می‌رسند: رفتن به سر کار.

برنامه هم همین کار را می‌کند. یک شرط (سؤالی که جوابش فقط «بله» یا «نه» است) را بررسی می‌کند و بر اساس جواب، یکی از چند مسیر را انتخاب می‌کند. به این انتخاب مسیر می‌گویند شاخه‌زدن (branching).

مثال از زندگی روزمره

چراغ راهنمایی یک راننده‌ی حواس‌جمع را ببین. او مدام سؤال می‌پرسد: «چراغ قرمز است؟ پس بایست. وگرنه زرد است؟ پس آهسته شو. وگرنه سبز است، برو.» این سه سؤال به ترتیب پرسیده می‌شوند و به محض اینکه یکی جواب «بله» داد، بقیه پرسیده نمی‌شوند. دقیقا همین ترتیب است که در C با if و else if و else می‌نویسیم.

میکروکنترلرها بدون تصمیم‌گرفتن کاری از پیش نمی‌برند. ترموستات باید بفهمد اتاق سرد است یا گرم. یک ماشین لباس‌شویی باید بفهمد در بسته است یا نه. حتی ساده‌ترین چراغ‌چشمک‌زن هم می‌پرسد «الان روشن است؟».

در C «درست» و «نادرست» یعنی چه؟

قبل از نوشتن اولین if باید یک واقعیت عجیب ولی ساده را بدانی. زبان C کلمه‌ای به اسم «درست» یا «نادرست» ندارد. به‌جایش از عدد استفاده می‌کند:

  • صفر یعنی نادرست (false).
  • هر عدد غیرصفر (۱، ۷، ۱۰۰، ‎-۳ ...) یعنی درست (true).

چرا این‌طور؟ چون در سخت‌افزار هم همین است: یک سیم یا صفر ولت است (خاموش) یا ولتاژ دارد (روشن). C از همان دیدگاه ساخته شده.

وقتی دو مقدار را مقایسه می‌کنی، خودِ مقایسه هم یک عدد می‌شود: ۱ اگر بله، ۰ اگر نه. عملگرهای مقایسه (که در درس ۲.۳ دیدی) این‌ها هستند:

عملگرمعنیمثالنتیجه
==برابر است با؟5 == 5۱ (درست)
!=برابر نیست با؟5 != 5۰ (نادرست)
< و >کوچک‌تر / بزرگ‌تر؟3 < 8۱
<= و >=کوچک‌تر یا مساوی / بزرگ‌تر یا مساوی؟8 <= 7۰

خودت ببین. این برنامه نتیجه‌ی چند مقایسه را چاپ می‌کند و بعد نشان می‌دهد if با «صفر» و «غیرصفر» چه می‌کند:

#include <stdio.h>

int main(void)
{
    int a = 7;
    int zero = 0;

    printf("a > 3 gives %d\n", a > 3);
    printf("a == 3 gives %d\n", a == 3);
    printf("a != 3 gives %d\n", a != 3);

    if (a) {
        printf("a = 7 counts as true\n");
    }
    if (zero) {
        printf("you will never see this\n");
    } else {
        printf("zero counts as false\n");
    }
    return 0;
}
  1. دو متغیر. a مقدار ۷ دارد و zero مقدار ۰. هر دو را با مقدار اولیه ساختیم، مثل عادتی که در درس ۲.۱ گرفتیم.
  2. مقایسه‌ی «بزرگ‌تر». a > 3 یک پرسش است: «۷ از ۳ بزرگ‌تر است؟». جواب «بله» است، پس خود عبارت برابر ۱ می‌شود و %d آن را چاپ می‌کند. این نشان می‌دهد یک مقایسه در C «جواب بله/خیر» نیست، یک عدد است. برای همین می‌شود آن را چاپ کرد یا در متغیر گذاشت.
  3. مقایسه‌ی «برابر». a == 3 می‌پرسد «۷ برابر ۳ است؟». جواب «نه» است، پس نتیجه ۰. دو تا مساوی پشت هم = پرسیدن برابری. یک مساوی = گذاشتن مقدار (انتساب). بعدا این دو را با هم قاطی می‌کنیم و می‌بینیم چه بلایی سرمان می‌آید.
  4. مقایسه‌ی «نابرابر». a != 3 می‌پرسد «۷ با ۳ فرق دارد؟». جواب بله است، پس ۱.
  5. if با عدد غیرصفر. داخل پرانتز فقط خود a آمده، یعنی عدد ۷. چون غیرصفر است، «درست» حساب می‌شود و پیام چاپ می‌شود. لازم نیست حتما مقایسه بنویسی. هر عددی می‌تواند شرط باشد. if (a) یعنی همان if (a != 0).
  6. if با صفر و else. صفر «نادرست» است، پس بدنه‌ی if رد می‌شود و بدنه‌ی else («وگرنه») اجرا می‌شود. else یعنی «اگر شرط بالا برقرار نبود». هیچ‌وقت هر دو بدنه با هم اجرا نمی‌شوند.
  7. return 0. پایان موفق برنامه، مثل درس‌های قبل.
$ gcc -std=c11 -Wall -Wextra -o truth truth.c
$ ./truth
a > 3 gives 1
a == 3 gives 0
a != 3 gives 1
a = 7 counts as true
zero counts as false
یادآوری کوتاه: و، یا، نه

گاهی یک سؤال کافی نیست. سه عملگر منطقی (از درس ۲.۳) چند شرط را به هم می‌چسبانند:

  • && یعنی «و». هر دو شرط باید درست باشند.
  • || یعنی «یا». کافی است یکی درست باشد.
  • ! یعنی «نه». درست را نادرست می‌کند و برعکس.

اولین if: فقط اگر...

قالب کلی if این است:

if (شرط) {
    کارهایی که فقط وقتی شرط درست است انجام می‌شوند
}

دو تکه‌ی مهم دارد. اول پرانتز که شرط داخلش است (بدون آن اصلا کامپایل نمی‌شود). دوم بلاک (block)، یعنی قسمتی که بین { و } است. تمام دستورهای داخل بلاک مثل یک بسته‌ی واحد رفتار می‌کنند: یا همه اجرا می‌شوند یا هیچ‌کدام.

#include <stdio.h>

int main(void)
{
    int temp_c = 32;

    if (temp_c > 30) {
        printf("fan: ON\n");
    }
    printf("done\n");
    return 0;
}
  1. دمای فعلی. متغیر temp_c (دما به سانتی‌گراد؛ پسوند _c واحد را در اسم می‌آورد) مقدار ۳۲ دارد. در برنامه‌ی واقعی این عدد از یک سنسور می‌آید. الان دستی می‌نویسیم تا نتیجه قابل‌پیش‌بینی باشد.
  2. شرط و بلاک. کامپایلر می‌پرسد «۳۲ از ۳۰ بزرگ‌تر است؟». جواب بله است، پس داخل آکولادها اجرا می‌شود و پیام فن چاپ می‌شود. اگر temp_c برابر ۲۰ بود، کامپیوتر از { تا } می‌پرید و مستقیم می‌رفت سراغ خط بعد از }.
  3. خارج از if. این خط به شرط وابسته نیست. همیشه اجرا می‌شود. جای آکولاد بسته تعیین می‌کند کدام خط‌ها تابع شرط هستند و کدام نه.
  4. return 0. پایان برنامه.
$ ./fan
fan: ON
done

حالا temp_c را ۲۰ بگذار و دوباره اجرا کن. فقط done چاپ می‌شود. خودت امتحان کن؛ بهترین راه یاد گرفتن همین است.

else و else if: چند مسیر

گاهی فقط «اگر» کافی نیست و می‌خواهی بگویی «وگرنه چه کنم؟». همان‌طور که در راننده‌ی چراغ‌قرمز دیدیم، سؤال‌ها به ترتیب پرسیده می‌شوند. کد زیر دما را به چهار دسته تقسیم می‌کند:

#include <stdio.h>

int main(void)
{
    int temp_c = 22;

    if (temp_c >= 35) {
        printf("very hot\n");
    } else if (temp_c >= 25) {
        printf("warm\n");
    } else if (temp_c >= 15) {
        printf("mild\n");
    } else {
        printf("cold\n");
    }
    return 0;
}
  1. ورودی. دما ۲۲ درجه.
  2. سؤال اول. «۲۲ ≥ ۳۵؟» نه. پس بدنه‌اش رد می‌شود و کامپیوتر می‌رود سراغ سؤال بعدی. فقط سؤال اول همیشه پرسیده می‌شود. بقیه فقط زمانی پرسیده می‌شوند که همه‌ی سؤال‌های قبلی جواب «نه» داده باشند.
  3. سؤال دوم. «۲۲ ≥ ۲۵؟» باز هم نه. رد می‌شود.
  4. سؤال سوم. «۲۲ ≥ ۱۵؟» بله! پس mild چاپ می‌شود و بقیه‌ی زنجیره کاملا نادیده گرفته می‌شود، یعنی سراغ else نمی‌رود. به همین دلیل می‌شود سؤال‌های بعدی را ساده نوشت: لازم نیست بنویسی temp_c >= 15 && temp_c < 25. اگر به سؤال سوم رسیدی، مطمئنی که دما از ۲۵ کمتر است، وگرنه سؤال دوم زودتر جواب داده بود.
  5. else. شاخه‌ی «هیچ‌کدام نشد». وقتی همه‌ی شرط‌ها نادرست بودند این بدنه اجرا می‌شود. شرط ندارد. else بدون شرط، مسیر پیش‌فرض است. برای اینکه برنامه در هر وضعیتی یک رفتار مشخص داشته باشد، معمولا یکی می‌گذاریم.
$ ./weather
mild
ترتیب مهم است

اگر سؤال‌ها را وارونه بنویسی و اول بپرسی temp_c >= 15، دمای ۴۰ درجه هم همان‌جا «بله» می‌گیرد و می‌شود «ملایم»! چون زنجیره از اولین جواب «بله» جلوتر نمی‌رود. قاعده: از شرط‌های سخت‌گیرانه‌تر به سمت شرط‌های آسان‌تر بنویس.

آکولاد را همیشه بنویس

C به تو اجازه می‌دهد وقتی بدنه‌ی if فقط یک دستور دارد، آکولاد را ننویسی. این شبیه یک میان‌بر وسوسه‌انگیز است، اما یکی از خطرناک‌ترین تله‌های زبان است. ببین:

#include <stdio.h>

int main(void)
{
    int temp_c = 20;

    if (temp_c > 30)
        printf("fan: ON\n");
        printf("alarm: overheating!\n");
    return 0;
}
  1. if بدون آکولاد. بدون آکولاد، if فقط یک دستور بعد از خودش را کنترل می‌کند، یعنی همان چاپ فن. کامپایلر جای دستور را می‌بیند، نه تورفتگی (فاصله‌های اول خط) را. تورفتگی فقط برای چشم انسان است.
  2. دام. این خط با تورفتگی زیر if نوشته شده و به نظر می‌رسد بخشی از آن است، ولی نیست! همیشه اجرا می‌شود؛ حتی وقتی دما فقط ۲۰ درجه است. در یک دستگاه واقعی یعنی آلارم خطر در دمای عادی هم به صدا درمی‌آید. باگی که مثل یک بمب ساعتی خودش را نشان نمی‌دهد.
$ gcc -std=c11 -Wall -Wextra -Werror=misleading-indentation -o braces_bug braces_bug.c
braces_bug.c: In function 'main':
braces_bug.c:7:5: error: this 'if' clause does not guard... [-Werror=misleading-indentation]

خوشبختانه کامپایلر gcc با گزینه‌ی -Wall این خطر را می‌بیند و هشدار می‌دهد. ما هشدار را عمدا با -Werror=misleading-indentation (در دستور بالا) به خطا تبدیل کردیم تا خوب دیده شود؛ بدون آن فقط warning می‌بینی، برنامه ساخته می‌شود و پیام «alarm» حتی در ۲۰ درجه چاپ می‌شود. ولی همیشه اتکا به کامپایلر کافی نیست. قانون ساده و مطمئن: بدنه‌ی if و else را همیشه با آکولاد بنویس، حتی اگر فقط یک خط باشد. استانداردهای جدی صنعتی (مثل MISRA که در درس ۶.۳ می‌آید) همین را اجباری کرده‌اند.

تله‌ی معروف: یک مساوی یا دو مساوی؟

در درس ۲.۱ دیدی = یعنی «بگذار داخل»، و در ۲.۳ (تلهٔ ۱) هم کوتاه با این باگ آشنا شدی؛ اینجا جای اصلی‌اش است. پس نوشتن if (mode = 1) یعنی «عدد ۱ را در mode بگذار، و بعد بپرس آیا نتیجه غیرصفر است؟». نتیجه همیشه ۱ است، یعنی شرط همیشه درست می‌شود و ضمنا mode را هم خراب می‌کند!

#include <stdio.h>

int main(void)
{
    int mode = 0;

    if (mode = 1) {
        printf("mode is one\n");
    }
    return 0;
}
  1. مقدار اولیه. mode برابر ۰ است، پس منطقا نباید پیام چاپ شود.
  2. یک مساوی به‌جای دو مساوی. mode = 1 عدد ۱ را داخل mode می‌ریزد و خودِ این عبارت هم برابر ۱ است. پس پیام چاپ می‌شود، حتی وقتی mode صفر بوده. C عمدا اجازه می‌دهد انتساب داخل شرط بیاید. این توانایی گاهی مفید است، ولی برای مبتدی‌ها بیشتر تله است.
$ gcc -std=c11 -Wall -Wextra -Werror=parentheses -o eq_bug eq_bug.c
eq_bug.c: In function 'main':
eq_bug.c:7:9: error: suggest parentheses around assignment used as truth value [-Werror=parentheses]

باز هم -Wall به دادمان می‌رسد: «پرانتز بگذار، مطمئنی انتساب را در جای شرط نوشتی؟». این‌جا هم -Werror=parentheses را خودمان اضافه کردیم؛ با -Wall -Wextra تنها یک warning می‌بینی و برنامه ساخته می‌شود. تا وقتی هشدارها را نادیده نگیری، این باگ زود شکار می‌شود. یک عادت قدیمی هم هست: عدد را سمت چپ بنویس، یعنی if (1 == mode). اگر یکی از مساوی‌ها را فراموش کنی، 1 = mode ساخته می‌شود که خطای کامپایل است، چون نمی‌شود در «عدد ۱» چیزی گذاشت.

چند شرط با هم

کولر گازی را در نظر بگیر: فقط وقتی روشن شود که هم هوا گرم باشد و هم کسی در خانه باشد. یا: هشدار بده اگر دما خیلی کم باشد یا خیلی زیاد. برای این کارها از && و || و ! استفاده می‌کنیم:

#include <stdio.h>

int main(void)
{
    int temp_c = 28;
    int humidity = 80;
    int person_home = 1;

    if (temp_c > 25 && humidity > 70) {
        printf("sticky weather\n");
    }
    if (temp_c < 0 || temp_c > 50) {
        printf("sensor out of range\n");
    } else {
        printf("sensor range ok\n");
    }
    if (!person_home) {
        printf("nobody home\n");
    }
    if (temp_c > 25 && person_home) {
        printf("cooler: ON\n");
    }
    return 0;
}
  1. سه ورودی. دما، رطوبت (به درصد) و اینکه کسی در خانه است یا نه (۱ = بله، ۰ = نه). برای «بله/نه» از ۱ و ۰ استفاده می‌کنیم. در درس ۲.۲ راه تمیزتری (bool) دیدی.
  2. و (&&). هر دو شرط باید درست باشند. ۲۸ > ۲۵ درست و ۸۰ > ۷۰ هم درست، پس پیام چاپ می‌شود. اگر یکی از دو تا نادرست بود، کل ترکیب نادرست می‌شد؛ مثل «هم بلیت داشته باشی و هم شناسنامه».
  3. یا (||). کافی است یکی درست باشد. ۲۸ نه از صفر کمتر است نه از ۵۰ بیشتر، پس هر دو نادرست‌اند و شاخه‌ی else اجرا می‌شود. این الگو در سخت‌افزار خیلی رایج است: «اگر عدد از هر طرف از بازه‌ی مجاز بیرون افتاد، خطا بده».
  4. نه (!). !person_home یعنی «کسی خانه نیست». چون person_home برابر ۱ است، نقیضش صفر می‌شود و بدنه رد می‌شود.
  5. ترکیب. دما بالای ۲۵ و کسی هم خانه است، پس کولر روشن می‌شود.
$ ./combine
sticky weather
sensor range ok
cooler: ON

شرط‌های تودرتو و «نگهبان»

می‌توانی if را داخل if بگذاری. مثل یک عروسک روسی: اول در را باز می‌کنی، بعد جعبه‌ی داخل را. ولی وقتی زیاد شد، کد مثل یک پله‌ی مارپیچ به سمت راست می‌رود و خواندنش سخت می‌شود:

if (sensor_ok) {
    if (temp_c <= 40) {
        if (battery_mv > 3300) {
            /* کار اصلی اینجا، سه پله عمیق */
        }
    }
}

راه بهتر: شرط‌نگهبان (guard clause). به‌جای اینکه بپرسی «همه چیز خوب است؟»، اول حالت‌های بد را بپرس و همان‌جا از تابع خارج شو. آنچه پایین می‌ماند، مسیر خوشحال برنامه است و به سمت راست نمی‌رود:

#include <stdio.h>

int main(void)
{
    int sensor_ok = 1;
    int temp_c = 24;

    if (!sensor_ok) {
        printf("error: sensor failed\n");
        return 1;
    }
    if (temp_c > 40) {
        printf("error: too hot\n");
        return 2;
    }

    printf("temperature is fine: %d\n", temp_c);
    return 0;
}
  1. وضعیت اولیه. سنسور سالم است و دما ۲۴ درجه.
  2. نگهبان اول. اگر سنسور خراب است، پیام خطا بده و return 1 کن. return اجرای main را همان‌جا تمام می‌کند و بقیه‌ی خط‌ها اجرا نمی‌شوند. عدد بازگشتی غیرصفر به سیستم می‌گوید «مشکلی پیش آمد». هر عدد، یک علت. (در درس ۲.۶ همین الگو را در تابع‌ها می‌بینی.)
  3. نگهبان دوم. اگر دما بالای ۴۰ بود، خطای دیگری با کد ۲. هر نگهبان یک چیز را چک می‌کند و بس. اضافه‌کردن نگهبان سوم فقط یک بلاک دیگر می‌شود، نه یک پله‌ی دیگر تورفتگی.
  4. مسیر اصلی. اگر به اینجا رسیدی، همه‌ی نگهبان‌ها رد شده‌اند و می‌توانی با خیال راحت کار اصلی را انجام دهی.
$ ./guard
temperature is fine: 24

switch: انتخاب از بین چند مقدار مشخص

فرض کن یک کلید سه حالته‌ی فن داری: ۰ = خاموش، ۱ = کم، ۲ = متوسط، ۳ = زیاد. می‌شود با چهار else if نوشت، ولی وقتی یک عدد را با چند مقدار ثابت مقایسه می‌کنی، C ابزار مخصوصی دارد: switch.

مثل آسانسور: دکمه‌ی طبقه را می‌زنی و آسانسور مستقیم به همان طبقه می‌پرد (نه اینکه از طبقه‌ی اول بپرسد «این توست؟»).

#include <stdio.h>

int main(void)
{
    int fan_mode = 2;

    switch (fan_mode) {
    case 0:
        printf("fan off\n");
        break;
    case 1:
        printf("fan low\n");
        break;
    case 2:
        printf("fan medium\n");
        break;
    case 3:
        printf("fan high\n");
        break;
    default:
        printf("unknown mode\n");
        break;
    }
    return 0;
}
  1. مقدار ورودی. حالت فن برابر ۲ است.
  2. switch. مقدار داخل پرانتز (فقط عدد صحیح یا کاراکتر؛ نه اعشاری) یک‌بار حساب می‌شود و بعد برنامه مستقیم به case مربوط می‌پرد. کامپایلر معمولا برای این کار یک جدول پرش می‌سازد، پس سریع‌تر یا هم‌سرعت با زنجیره‌ی else if است. ولی مهم‌تر از سرعت، خوانایی است.
  3. caseهای ۰ و ۱. برچسب‌هایی که کامپیوتر اگر به آن‌ها نرسد رد می‌شود. هرکدام با break تمام می‌شوند.
  4. case 2. مقدار ما ۲ است. برنامه اینجا فرود می‌آید و «fan medium» را چاپ می‌کند.
  5. break. یعنی «از کل switch بیرون برو». بدون آن، برنامه به case بعدی سرازیر می‌شود. جزئیات را در بخش بعد می‌بینی. اینجا کافی است بدانی که بعد از هر case معمولا break می‌آید.
  6. case 3. اجرا نمی‌شود.
  7. default. اگر هیچ‌کدام از caseها با مقدار نخواند، شاخه‌ی default اجرا می‌شود؛ معادل else. همیشه یک default بگذار. در embedded مقدار ورودی گاهی خراب می‌شود (نویز، باگ) و خوب است رفتار مشخصی برای «مقدار عجیب» داشته باشی.
$ ./switch_fan
fan medium

خطر: فراموش کردن break

فرض کن در case 1 نوشتن break را فراموش کنی:

#include <stdio.h>

int main(void)
{
    int fan_mode = 1;

    switch (fan_mode) {
    case 1:
        printf("fan low\n");
    case 2:
        printf("fan medium\n");
        break;
    default:
        break;
    }
    return 0;
}
  1. case 1 بدون break. پس از چاپ «fan low» برنامه به خط بعدی می‌رود.
  2. سرازیر شدن (fallthrough). کد case 2 هم اجرا می‌شود و «fan medium» هم چاپ می‌شود، هرچند مقدار ما ۱ بود. C عمدا این رفتار را تعریف کرده (مثلا وقتی می‌خواهی دو case یک کار کنند). ولی وقتی از روی اشتباه باشد، باگ است.
$ gcc -std=c11 -Wall -Wextra -Werror=implicit-fallthrough -o fall_bug fall_bug.c
fall_bug.c: In function 'main':
fall_bug.c:9:9: error: this statement may fall through [-Werror=implicit-fallthrough=]

گزینه‌ی -Wextra این مورد را هم به تو هشدار می‌دهد (ما برای نمایش، آن را با -Werror=implicit-fallthrough به خطا تبدیل کردیم؛ بدون آن فقط warning می‌گیری و برنامه هر دو خط «fan low» و «fan medium» را چاپ می‌کند). هشدارها را جدی بگیر. ولی یک بار هم هست که سرازیر شدن عمدی و مفید است: چند مقدار که باید یک کار کنند:

#include <stdio.h>

int main(void)
{
    int adc_zone = 3;

    switch (adc_zone) {
    case 0:
    case 1:
        printf("low zone\n");
        break;
    case 2:
    case 3:
        printf("high zone\n");
        break;
    default:
        printf("invalid zone\n");
        break;
    }
    return 0;
}
  1. مقدار. ناحیه‌ی ۳.
  2. دو case پشت هم. case 0: کد ندارد، پس مستقیم می‌افتد داخل case 1:. یعنی ۰ و ۱ هر دو «low zone» هستند. چون case بدون کد است، کامپایلر هشدار نمی‌دهد. هشدار فقط وقتی می‌آید که case کد داشته باشد و بعدش break نباشد.
  3. دو مقدار دیگر. ۲ و ۳ هر دو «high zone». مقدار ما ۳ است، پس همین چاپ می‌شود.
  4. default. هر مقدار دیگر (مثلا ۹) نامعتبر است.
$ ./zone
high zone
switch یا else if؟

switch فقط با مساوی بودن به یک مقدار ثابت کار می‌کند. نمی‌توانی بنویسی case temp_c > 30. برای بازه‌ها (مثل دمای بالا) از else if استفاده کن. برای «حالت‌های مشخص» (فرمان‌های ۰ تا ۵، وضعیت‌های یک ماشین حالت) switch عالی است؛ در درس ۴.۶ ماشین حالت را با همین می‌سازیم.

عملگر سه‌تایی: تصمیم در یک خط

گاهی فقط می‌خواهی یک مقدار را بر اساس یک شرط انتخاب کنی. C یک میان‌بر دارد: عملگر سه‌تایی (ternary) که سه بخش دارد: شرط ? اگر_درست : اگر_نادرست. بخوان: «شرط؟ اگر بله این، وگرنه آن».

#include <stdio.h>

int main(void)
{
    int temp_c = 35;
    int fan_speed = (temp_c > 30) ? 100 : 0;
    int bigger = (5 > 3) ? 5 : 3;

    printf("fan_speed = %d\n", fan_speed);
    printf("bigger = %d\n", bigger);
    return 0;
}
  1. انتخاب سرعت. اگر دما بیشتر از ۳۰ است، fan_speed برابر ۱۰۰ می‌شود، وگرنه ۰. چون ۳۵ > ۳۰ درست است، ۱۰۰ می‌شود. این معادل چهار خط if/else است، ولی بیانگر هدف است: «مقدار این متغیر را انتخاب کن».
  2. بزرگ‌تر از دو عدد. کوتاه‌ترین روش پیدا کردن بیشینه‌ی دو عدد.
  3. چاپ. نتیجه‌ی هر دو را می‌بینیم.
$ ./ternary
fan_speed = 100
bigger = 5

سه‌تایی برای انتخاب مقدار ساده عالی است. ولی داخل هم گذاشتن چند تا از آن‌ها ( a ? b : c ? d : e ) کد را نامفهوم می‌کند؛ در آن حالت if بنویس.

تله: مقایسه‌ی عدد اعشاری با ==

در درس ۲.۲ دیدی که اعداد اعشاری در کامپیوتر به‌صورت تقریبی ذخیره می‌شوند؛ مثل اینکه یک‌سوم را نمی‌شود دقیق با اعشار ده‌دهی نوشت (۰٫۳۳۳۳...). پس مقایسه‌ی آن‌ها با == اغلب جواب دلخواهت را نمی‌دهد:

#include <stdio.h>

int main(void)
{
    double a = 0.1 + 0.2;
    double diff = a - 0.3;
    double epsilon = 0.000001;

    printf("a = %.17f\n", a);
    printf("a == 0.3 gives %d\n", a == 0.3);

    if (diff < 0) {
        diff = -diff;
    }
    printf("close enough gives %d\n", diff < epsilon);
    return 0;
}
  1. جمع ساده. ۰٫۱ + ۰٫۲ را در یک متغیر double (اعشاری دقیق‌تر) می‌گذاریم.
  2. اختلاف و آستانه. اختلاف a تا ۰٫۳ را حساب می‌کنیم. epsilon یعنی «یک عدد خیلی کوچک که تفاوتش را ناچیز می‌دانیم».
  3. چاپ با ۱۷ رقم. قالب %.17f ۱۷ رقم اعشار نشان می‌دهد تا خطا دیده شود.
  4. مقایسه‌ی مستقیم. نتیجه ۰ است؛ کامپیوتر می‌گوید ۰٫۱ + ۰٫۲ برابر ۰٫۳ نیست! چون هیچ‌کدام از این سه عدد در سیستم دودویی دقیق ذخیره نمی‌شوند و خطاهای ریز جمع می‌شوند.
  5. قدر مطلق. اگر اختلاف منفی است، علامتش را برمی‌گردانیم. اختلاف فقط اندازه‌اش مهم است، نه جهتش.
  6. مقایسه‌ی «نزدیک». اگر اختلاف از epsilon کمتر باشد، دو عدد «عملا برابرند». راه استاندارد مقایسه‌ی اعشاری همین است: اختلاف را با یک آستانه مقایسه کن، نه خود دو عدد را.
$ ./float_eq
a = 0.30000000000000004
a == 0.3 gives 0
close enough gives 1

قاعده‌ی عملی: در میکروکنترلر ترجیحا اعداد اعشاری را با == مقایسه نکن. اگر ADC (مبدل آنالوگ به دیجیتال) عدد صحیح می‌دهد، همان را با عدد صحیح مقایسه کن.

مثال حرفه‌ای: ترموستات و هیسترزیس

فرض کن اتاقی را با بخاری گرم می‌کنی. ساده‌ترین قانون: «اگر دما زیر ۲۰ است بخاری را روشن کن، وگرنه خاموش». چه اتفاقی می‌افتد وقتی دما دقیقا دور و بر ۲۰ درجه نوسان می‌کند؟ بخاری هر ثانیه ده‌ها بار روشن و خاموش می‌شود. رله می‌سوزد، بخاری صدا می‌دهد و عمر دستگاه کم می‌شود.

مثال از زندگی روزمره

کولر خانه‌ات را ببین. مردم می‌گویند «۲۴ درجه»، ولی کولر نه دقیقا در ۲۴ خاموش می‌شود و نه دقیقا در ۲۴ روشن. مثلا در ۲۳ خاموش می‌شود و تا دما به ۲۶ نرسد دوباره روشن نمی‌شود. این «فاصله‌ی امن» بین روشن‌شدن و خاموش‌شدن را هیسترزیس (hysteresis) می‌گویند. یعنی رفتار امروز به تاریخچه هم بستگی دارد.

راه‌حل: دو آستانه‌ی جدا بگذار. زیر ۲۰ روشن کن. بالای ۲۴ خاموش کن. بین ۲۰ و ۲۴ به وضعیت فعلی دست نزن:

اول با هم قدم‌به‌قدم ببینیم برنامه چه می‌کند:

#include <stdio.h>

int main(void)
{
    int heater_on = 0;
    int temp_c;

    temp_c = 19;
    if (temp_c < 20) { heater_on = 1; } else if (temp_c > 24) { heater_on = 0; }
    printf("temp %d -> heater %d\n", temp_c, heater_on);

    temp_c = 22;
    if (temp_c < 20) { heater_on = 1; } else if (temp_c > 24) { heater_on = 0; }
    printf("temp %d -> heater %d\n", temp_c, heater_on);

    temp_c = 25;
    if (temp_c < 20) { heater_on = 1; } else if (temp_c > 24) { heater_on = 0; }
    printf("temp %d -> heater %d\n", temp_c, heater_on);

    temp_c = 22;
    if (temp_c < 20) { heater_on = 1; } else if (temp_c > 24) { heater_on = 0; }
    printf("temp %d -> heater %d\n", temp_c, heater_on);
    return 0;
}
  1. حافظه‌ی وضعیت. heater_on «تاریخچه» را نگه می‌دارد: بخاری الان روشن است یا نه. temp_c هر بار خوانش جدید را می‌گیرد. این متغیر همان چیزی است که هیسترزیس را ممکن می‌کند. بدون آن، برنامه نمی‌داند قبلا چه کرده.
  2. خوانش اول (۱۹). شرط اول (< 20) درست است، پس بخاری روشن می‌شود. دقت کن شاخه‌ی else if اصلا پرسیده نمی‌شود. آکولادهای تک‌خطی را فقط برای فشرده‌کردن کد این مثال گذاشتیم؛ همچنان آکولاد داریم و قانون شکسته نشده.
  3. خوانش دوم (۲۲). نه کمتر از ۲۰ است نه بیشتر از ۲۴. هیچ شاخه‌ای اجرا نمی‌شود و heater_on همان ۱ می‌ماند. نبودن else نهایی عمدی است: «در فاصله‌ی امن کاری نکن» یعنی همین.
  4. خوانش سوم (۲۵). شرط اول نادرست است ولی > 24 درست است، پس بخاری خاموش می‌شود.
  5. خوانش چهارم (۲۲). همان دمای خوانش دوم! ولی این بار heater_on برابر ۰ است و می‌ماند. این است معنی هیسترزیس: با یک ورودی یکسان، خروجی به تاریخچه بستگی دارد. بلوک تکراری بالا خسته‌کننده است؛ در درس بعد با «حلقه» یک بار می‌نویسیم و چند بار اجرا می‌کنیم.
$ ./hysteresis
temp 19 -> heater 1
temp 22 -> heater 1
temp 25 -> heater 0
temp 22 -> heater 0

در STM32 و ESP32 شرط کجا به درد می‌خورد؟

در میکروکنترلر «ورودی» معمولا یک پایه (pin) روی تراشه است که ولتاژش را می‌شود خواند: نزدیک صفر ولت یعنی سطح پایین (۰)، نزدیک ولتاژ تغذیه (۳٫۳ ولت) یعنی سطح بالا (۱). دکمه‌ها معمولا با یک مقاومت کوچک (مقاومت = قطعه‌ای که جریان را کم می‌کند) پایه را آرام به ۳٫۳ ولت می‌کشند؛ به این کار pull-up می‌گویند. «زمین» (GND) همان ۰ ولت است. وقتی دکمه فشرده شود، پایه را به زمین وصل می‌کند. پس دکمه‌ی فشرده‌شده «۰» می‌دهد و رهاشده «۱». به این طراحی می‌گویند فعال-پایین (active-low):

سطح پایه (بدون فشار)سطح پایه (فشرده)
دکمه‌ی آبی روی Nucleo-F411RE (پایه‌ی PC13)۱۰
دکمه‌ی BOOT در بسیاری از بردهای ESP32 DevKit (GPIO0)۱۰

برای همین نوشتن if (level == 0) برای «فشرده شد؟» طبیعی است، نه if (level == 1). اجازه بده روی PC شبیه‌سازی کنیم؛ عدد سطح پایه را دستی می‌نویسیم:

#include <stdio.h>

int main(void)
{
    int button_level = 0;
    int led_on = 0;

    if (button_level == 0) {
        led_on = 1;
    } else {
        led_on = 0;
    }
    printf("button level = %d, LED = %d\n", button_level, led_on);
    return 0;
}
  1. سطح پایه. ۰ یعنی دکمه فشرده است (روی برد واقعی از پایه خوانده می‌شود). اینکه سخت‌افزار چطور این عدد را به برنامه می‌رساند، در درس ۳.۶ (رجیستر) می‌آید.
  2. وضعیت LED. ۱ = روشن، ۰ = خاموش.
  3. تصمیم. چون فعال-پایین است، شرط «دکمه فشرده» یعنی سطح برابر ۰. پس LED روشن می‌شود. اگر اشتباها == 1 بنویسی، LED وقتی دکمه را رها کرده‌ای روشن می‌شود! یکی از اشتباه‌های مبتدی‌ها.
  4. چاپ. نتیجه را می‌بینیم.
$ ./button
button level = 0, LED = 1

در ESP32 با ESP-IDF نسخه‌ی ۵ همین منطق به شکل زیر است. لازم نیست الان کامل بفهمی gpio_get_level از کجا آمده؛ در درس ۵.۶ کامل می‌بینیمش. فقط ببین که شرط دقیقا همان شکل است:

/* قطعه‌ای از یک برنامه‌ی ESP-IDF (پیکربندی پایه‌ها حذف شده) */
if (gpio_get_level(GPIO_NUM_0) == 0) {
    gpio_set_level(GPIO_NUM_2, 1);   // LED روشن
} else {
    gpio_set_level(GPIO_NUM_2, 0);   // LED خاموش
}
  1. خواندن دکمه. gpio_get_level سطح پایه را به‌صورت عدد ۰ یا ۱ برمی‌گرداند و ما با == 0 مقایسه‌اش می‌کنیم.
  2. روشن کردن LED. gpio_set_level(پایه, ۱) پایه را بالا می‌برد. شماره‌ی پایه‌ی LED در بردهای مختلف فرق می‌کند؛ روی بسیاری از DevKit ها GPIO2 است.
  3. شاخه‌ی else. برعکس بالا: LED خاموش.
دکمه لرزش دارد

دکمه‌های مکانیکی وقتی فشرده می‌شوند، چند میلی‌ثانیه «لرزش» تماس دارند و پایه چند بار بین ۰ و ۱ می‌پرد. یک if ساده این‌ها را چند فشار جداگانه می‌بیند. راه‌حلش (debounce) نیاز به مفهوم زمان و ماشین حالت دارد که در درس‌های ۴.۶ و ۵.۴ می‌آید. فعلا یادت بماند: if فقط وضعیت همین لحظه را می‌بیند.

آزمون این درس

در C کدام یک از این‌ها «نادرست» (false) حساب می‌شود؟

  1. عدد ‎-۱
  2. عدد ۰
  3. عدد ۱
  4. عدد ۰٫۵
تنها مقدار نادرست، صفر است. هر چیز غیرصفر (مثبت یا منفی) درست است.

این کد چه چاپ می‌کند؟
int x = 10;
if (x > 20) { printf("A"); }
else if (x > 5) { printf("B"); }
else if (x > 0) { printf("C"); }
else { printf("D"); }

  1. A
  2. BC
  3. C
  4. B
۱۰ > ۲۰ نادرست است، ۱۰ > ۵ درست است، پس B چاپ می‌شود و بقیه‌ی زنجیره (حتی شرط x > 0 که آن هم درست است) پرسیده نمی‌شود.

کدام خط یک باگ دارد؟

  1. if (speed = 100) { brake(); }
  2. ‎if (speed == 100) { brake(); }
  3. ‎if (speed >= 100) { brake(); }
  4. ‎if (speed != 100) { brake(); }
در خط اول = به‌جای == آمده. این عبارت ۱۰۰ را در speed می‌گذارد و چون ۱۰۰ غیرصفر است، همیشه بدنه اجرا می‌شود.

وقتی در یک switch برای case 1 کد نوشتی ولی break نگذاشتی و مقدار ورودی ۱ است، چه می‌شود؟

  1. بعد از case 1 متوقف می‌شود
  2. برنامه اصلا کامپایل نمی‌شود
  3. کد case بعدی هم اجرا می‌شود (سرازیر شدن) تا به break یا انتهای switch برسد
  4. دوباره از case 0 شروع می‌شود
به این می‌گویند fallthrough. مگر عمدی باشد، باگ است. با -Wextra کامپایلر هشدار می‌دهد.

دکمه‌ای به پایه‌ای وصل است و فعال-پایین است. وقتی فشرده باشد، خواندن پایه چه عددی می‌دهد و شرط درست برای «فشرده شد» کدام است؟

  1. عدد ۱؛ if (level == 1)
  2. عدد ۰؛ if (level == 0)
  3. عدد ۰؛ if (level > 0)
  4. عدد ۰؛ if (level = 0)
دکمه‌ی فعال-پایین وقتی فشرده شود پایه را به زمین می‌برد (۰). پس شرط درست level == 0 است، با دو تا مساوی.

تمرین‌ها

تمرین ۱: وضعیت باتری

ولتاژ باتری یک دستگاه را به میلی‌ولت (mV) از یک سنسور می‌خوانی. می‌خواهی بر اساس آن یکی از چهار پیام را چاپ کنی: FULL (۴۰۰۰ به بالا)، OK (۳۶۰۰ تا ۳۹۹۹)، LOW (۳۳۰۰ تا ۳۵۹۹) و EMPTY (کمتر از ۳۳۰۰).

  1. پیش‌بینی: برای battery_mv = 3600 کدام پیام چاپ می‌شود؟ دقت کن مرزها با >= هستند.
  2. حل: با زنجیره‌ی if / else if / else برنامه را بنویس.
  3. تغییر: اگر شرط‌ها را > (بدون مساوی) بنویسی، پیام ۳۶۰۰ چه می‌شود؟ چرا؟
راهنمایی

از شرط‌های سخت‌گیرانه شروع کن: اول «۴۰۰۰ یا بیشتر»، بعد «۳۶۰۰ یا بیشتر» و همین‌طور تا else.

چه باید ببینی؟ 
$ ./battery
battery: OK

جواب قسمت الف: ۳۶۰۰ با >= 3600 «OK» است. قسمت پ: با > 3600، عدد ۳۶۰۰ به شاخه‌ی بعد می‌افتد و می‌شود «LOW»، چون دیگر بزرگ‌تر یا مساوی نیست. مرزها را همیشه با دقت انتخاب کن.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int battery_mv = 3600;

    if (battery_mv >= 4000) {
        printf("battery: FULL\n");
    } else if (battery_mv >= 3600) {
        printf("battery: OK\n");
    } else if (battery_mv >= 3300) {
        printf("battery: LOW\n");
    } else {
        printf("battery: EMPTY\n");
    }
    return 0;
}
  1. ورودی. نام battery_mv واحد را در خود دارد (میلی‌ولت).
  2. بالاترین مرز. اول ۴۰۰۰ را می‌پرسیم. اگر اول ۳۳۰۰ را می‌پرسیدیم، ولتاژ ۴۱۰۰ هم آن‌جا «بله» می‌گرفت و می‌شد LOW.
  3. مرز دوم. ۳۶۰۰ به بالا ولی کمتر از ۴۰۰۰ است (چون اولی رد شده). مقدار ما اینجا می‌افتد.
  4. مرز سوم و else. پایین‌تر از ۳۳۰۰ همه‌چیز خالی است.
$ ./battery
battery: OK
تمرین ۲: سه باگ در یک برنامه

همکارت این قطعه را نوشته و می‌گوید «کار نمی‌کند». (آن را داخل یک main بگذار و #include <stdio.h> را بالایش بنویس.) دو تا از باگ‌ها را می‌شود با کامپایلر گرفت، یکی را فقط با فکر کردن.

int heater_on = 0;
int temp_c = 18;

if (temp_c = 20)
    heater_on = 1;
    printf("heater switched on\n");

switch (heater_on) {
case 0:
    printf("off\n");
case 1:
    printf("on\n");
    break;
}
  1. پیدا کن: باگ خط ۴ را پیدا کن و بگو چرا اشتباه است.
  2. پیدا کن: باگ آکولاد در خط‌های ۴ تا ۶ و باگ switch را توضیح بده.
  3. اصلاح کن: برنامه‌ی درست را بنویس. (هدف: اگر دما کمتر از ۲۰ بود بخاری روشن شود و پیام بدهد؛ سپس با switch وضعیت چاپ شود.)
راهنمایی

در خط ۴ به تعداد مساوی‌ها نگاه کن. در خط ۵-۶ به این فکر کن که دقیقا کدام خط‌ها زیر کنترل if هستند. در switch هم دنبال break بگرد.

چه باید ببینی؟ 
$ ./heater_fixed
heater switched on
on

جواب تشخیص (بعد از تلاش خودت ببین): (الف) = به‌جای < یا == است: ۲۰ را در temp_c می‌گذارد و شرط همیشه درست است. (ب) بدون آکولاد فقط خط اول به if وابسته است؛ چاپ پیام همیشه انجام می‌شود. (پ) در case 0 هم break فراموش شده و «off» و «on» با هم چاپ می‌شوند.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int heater_on = 0;
    int temp_c = 18;

    if (temp_c < 20) {
        heater_on = 1;
        printf("heater switched on\n");
    }

    switch (heater_on) {
    case 0:
        printf("off\n");
        break;
    case 1:
        printf("on\n");
        break;
    default:
        break;
    }
    return 0;
}
  1. شرط درست. از < استفاده شد و هر دو دستور داخل آکولاد رفتند. قصد «دمای زیر ۲۰» بود؛ نوشتن = فقط یک اشتباه تایپی به‌ظاهر کوچک است ولی رفتار را کاملا عوض می‌کند.
  2. switch. حالت بخاری را بررسی می‌کند.
  3. case 0 با break. بدون break، «off» هم چاپ می‌شد.
  4. case 1 و default. مقدار ما ۱ است و «on» چاپ می‌شود. default برای ایمنی گذاشته شد.
$ ./heater_fixed
heater switched on
on
تمرین ۳: کنترل LED با دکمه و کلید حالت (میکروکنترلری)

یک دستگاه یک دکمه‌ی فعال-پایین (مثل PC13 روی Nucleo یا GPIO0 روی ESP32) و یک LED دارد. قانون: LED باید وقتی روشن شود که دکمه فشرده باشد و دستگاه در حالت «فعال» (enabled = 1) باشد. در غیر این‌صورت خاموش بماند.

  1. پیش‌بینی: اگر button_level = 0 و enabled = 0، LED چه می‌شود؟
  2. حل: با && برنامه را بنویس و LED را چاپ کن. با ترنری یا if/else هرکدام راحت‌تری.
  3. چالش: یک متغیر override = 1 اضافه کن: اگر override برابر ۱ باشد، LED بدون توجه به دکمه و enabled روشن شود. شرط جدید را با || بنویس.
راهنمایی

«دکمه فشرده» یعنی button_level == 0 (فعال-پایین). «و» بین دو شرط را با && بنویس. برای قسمت پ، کل شرط قبلی را داخل پرانتز بگذار و override را با || کنارش بیاور.

چه باید ببینی؟ 
$ ./led_ctrl
button=0 enabled=0 override=0 -> LED 0
button=0 enabled=0 override=1 -> LED 1

جواب قسمت الف: دکمه فشرده است ولی دستگاه فعال نیست، پس LED خاموش (۰) می‌ماند.

جواب کامل با توضیح 
#include <stdio.h>

int main(void)
{
    int button_level = 0;
    int enabled = 0;
    int override = 0;
    int led_on = 0;

    led_on = (button_level == 0 && enabled) ? 1 : 0;
    printf("button=%d enabled=%d override=%d -> LED %d\n",
           button_level, enabled, override, led_on);

    override = 1;
    led_on = ((button_level == 0 && enabled) || override) ? 1 : 0;
    printf("button=%d enabled=%d override=%d -> LED %d\n",
           button_level, enabled, override, led_on);
    return 0;
}
  1. ورودی‌ها. سطح دکمه، فعال‌بودن، override و وضعیت LED؛ همه با مقدار اولیه.
  2. شرط اول. دکمه فشرده (== 0) و enabled غیرصفر. با ? 1 : 0 نتیجه‌ی شرط را به ۱ یا ۰ تبدیل می‌کنیم.
  3. چاپ. printf روی دو خط شکسته شده؛ C به فاصله و خط جدید بین آرگومان‌ها اهمیت نمی‌دهد.
  4. override. پرانتزها مهم‌اند: اول دو شرط با && حساب می‌شود، بعد با override «یا» می‌شود. بدون پرانتز هم چون && از || تقدم بیشتری دارد نتیجه یکی است، ولی پرانتز نیت تو را برای خواننده روشن می‌کند. تقدم عملگرها در درس ۲.۳ آمده.
$ ./led_ctrl
button=0 enabled=0 override=0 -> LED 0
button=0 enabled=0 override=1 -> LED 1
حرف مربی

در این درس معمولا دو جا گیر می‌کنند. اول ترتیب زنجیره‌ی else if: یادت باشد سؤال‌ها از بالا به پایین پرسیده می‌شوند و اولین «بله» برنده است. دوم مساوی و دو مساوی؛ حتی حرفه‌ای‌ها هم گاهی اشتباه تایپ می‌کنند و کامپایلر نجاتشان می‌دهد. پس با -Wall -Wextra کامپایل کن و هشدارها را بخوان. اگر توضیح «چرا شرط من کار نکرد؟» را نمی‌دانی، یک printf با مقدار متغیر قبل از if بگذار؛ ساده‌ترین دیباگ دنیاست.

خلاصه یک‌دقیقه‌ای

  • شرط = سؤالی با جواب بله/نه. در C: صفر = نادرست، هر غیرصفر = درست. مقایسه، خودش ۱ یا ۰ می‌دهد.
  • if یک مسیر اختیاری می‌سازد؛ else «وگرنه»؛ else if سؤال‌های پشت‌سرهم با اولین «بله» برنده. ترتیب از سخت‌گیرانه به آسان.
  • آکولاد را همیشه بنویس. = انتساب است، == مقایسه. اعشاری را با == مقایسه نکن.
  • && «و»، || «یا»، ! «نه». شرط‌نگهبان کد را صاف می‌کند.
  • switch برای مقادیر ثابت؛ break یادت نرود؛ default بگذار. سه‌تایی c ? a : b برای انتخاب یک مقدار.
  • هیسترزیس = دو آستانه + حافظه‌ی وضعیت. دکمه‌های فعال-پایین (PC13 و GPIO0) وقتی فشرده‌اند ۰ می‌دهند.

درس بعد: ۲.۵ حلقه‌ها — چطور بلوک‌های تکراری مثل خوانش‌های بخاری را فقط یک‌بار بنویسیم.
