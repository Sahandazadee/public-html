برنامهٔ درس قبل هر ثانیه میلیون‌ها بار می‌پرسید «دکمه فشرده شد؟». بیشترِ آن پرسش‌ها بی‌جواب بودند و در همان مدت CPU کار دیگری نمی‌کرد. راه بهتر این است که به CPU بگویی «کار خودت را بکن؛ دکمه که فشرده شد، خودم صدایت می‌زنم». این «صدا زدن» را وقفه می‌گویند و تقریبا هر برنامهٔ جدی روی میکروکنترلر با آن ساخته می‌شود. در این درس می‌بینی سخت‌افزار چطور صدا می‌زند، کد ISR چطور نوشته می‌شود و چرا اشتباه‌های این بخش از سخت‌ترین باگ‌های دنیای embedded‌اند.

🎯 بعد از این درس می‌توانی

  • بگویی هنگام وقفه، CPU قدم‌به‌قدم چه می‌کند و جدول برداری چه نقشی دارد
  • وقفهٔ دکمهٔ PC13 را با EXTI و NVIC راه بیندازی
  • ISR درست بنویسی: کوتاه، بدون انتظار، با پرچم volatile
  • «رقابت» (race) را بشناسی و با بخش بحرانی جلویش را بگیری
  • اشتباه‌های رایج (پرچم پاک‌نشده، نام غلط ISR) را از علامتشان تشخیص بدهی
  • همین الگو را روی ESP32 با gpio_isr_handler_add و صف ببینی

🧰 پیش‌نیاز و وسایل

  • درس ۵.۲ (GPIO با رجیستر و دکمهٔ PC13؛ همان هدر و startup را گسترش می‌دهیم)
  • درس ۳.۶ (volatile، خواندن-تغییر-نوشتن، رجیستر write-1-to-clear)
  • درس ۴.۳ (اشاره‌گر به تابع؛ جدول برداری یک آرایه از آن‌هاست) و ۵.۱ (بوت)
  • برد Nucleo-F411RE، یا فقط کامپایلر برای ساختن و خواندن خروجی

ایدهٔ اصلی: زنگ در آشپزخانه

غذایی روی اجاق داری و می‌خواهی وقتی آماده شد بیرونش بیاوری. دو راه هست. راه اول: هر ده ثانیه سر بزنی و در ظرف نگاه کنی؛ کارِ دیگری نمی‌توانی بکنی و گاهی چند ثانیه دیر می‌فهمی. راه دوم: تایمر (زنگ) را بگذاری و بروی سراغ کارت. وقتی زنگ خورد، کار را رها می‌کنی، غذا را برمی‌داری و برمی‌گردی همان‌جا که بودی.

مثال از زندگی روزمره

راه اول پولینگ است (درس ۵.۲) و راه دوم وقفه (interrupt). زنگ آشپزخانه رویداد است، «رفتن سراغ غذا» همان ISR (Interrupt Service Routine، تابع رسیدگی به وقفه) و «برگشتن دقیقا به همان‌جا که بودی» چیزی است که سخت‌افزار برایت تضمین می‌کند. مهم‌ترین قانون آشپزخانه: وقتی زنگ خورد، فقط کار ضروری را بکن (غذا را بردار)؛ نه اینکه وسط زنگ شروع کنی سفرهٔ شام بچینی.

داخل CPU: چه اتفاقی می‌افتد؟

وقتی یک منبع (مثلا دکمه) وقفه بدهد و اجازهٔ وقفه فعال باشد، Cortex-M چند کار را خودکار و با سخت‌افزار انجام می‌دهد؛ هیچ کدی از تو لازم نیست:

  1. دستور جاری تمام می‌شود. CPU وسط یک دستور رها نمی‌کند (برای بیشتر دستورها).
  2. هشت کلمه روی پشته ذخیره می‌شود (stacking): R0، R1، R2، R3، R12، LR، PC (جایی که باید برگردیم) و xPSR (پرچم‌ها). این «قاب» یادداشت «کجا بودیم» است.
  3. آدرس ISR از جدول خوانده می‌شود. CPU از جدول برداری کلمهٔ شمارهٔ 16 + n را برمی‌دارد (n = شمارهٔ وقفه) و به آن می‌پرد.
  4. ISR اجرا می‌شود، مثل یک تابع معمولی C.
  5. بازگشت. وقتی ISR تمام شد (دستور bx lr)، سخت‌افزار مقدار ویژهٔ LR (به نام EXC_RETURN، مثلا 0xFFFFFFF9) را می‌شناسد، قاب را برمی‌دارد و برنامه دقیقا از همان‌جا ادامه می‌یابد.
چرا ISR فقط یک تابع C معمولی است؟

در Cortex-M، سخت‌افزار خودش ثبات‌هایی را ذخیره می‌کند که طبق قرارداد فراخوانی (AAPCS) هر تابع C آزاد است خراب کند (R0 تا R3، R12، LR). ثبات‌های دیگر را هر تابع C خودش نگه می‌دارد. پس تابعی مثل void f(void) که به‌طور عادی کامپایل شده، بدون هیچ صفت ویژه‌ای می‌تواند ISR باشد. در معماری‌هایی مثل AVR، ISR باید با ماکرو یا صفت ویژهٔ کامپایلر (مثل ISR()) نوشته شود. روی Cortex-M فقط نام و جایگاه در جدول مهم است.

جدول برداری و نام handler

جدول برداری همان آرایهٔ اشاره‌گر تابع است که در درس ۵.۲ در startup دیدی. ۱۶ درایهٔ اول برای رویدادهای خود هسته‌اند (مثل ریست و SysTick) و از درایهٔ ۱۶ به بعد، وقفهٔ شمارهٔ n همان درایهٔ 16 + n است:

NVIC: مدیر وقفه‌ها

وقفه‌های پریفرال‌ها به یک واحد داخل هسته می‌رسند: NVIC (Nested Vectored Interrupt Controller). NVIC برای هر وقفه سه چیز نگه می‌دارد: فعال است؟، معلق (pending) است؟ و اولویتش چند است؟ این رجیسترها جزو هستهٔ Cortex-M‌اند و آدرسشان روی همهٔ تراشه‌ها یکی است:

رجیسترآدرسکار
NVIC_ISER0، ISER10xE000E100، 0xE000E104فعال‌کردن: نوشتن ۱ در بیت، وقفهٔ همان بیت را فعال می‌کند (IRQ 0..31 در ISER0، IRQ 32..63 در ISER1)
NVIC_ICER0، ICER10xE000E180، 0xE000E184غیرفعال‌کردن (نوشتن ۱ در بیت)
NVIC_ISPR0، ICPR00xE000E200، 0xE000E280معلق‌کردن دستی / پاک‌کردن معلق‌بودن
NVIC_IPR0..0xE000E400 + nاولویت وقفهٔ n: یک بایت برای هر وقفه

دو نکتهٔ مهم. یک: رجیسترهای ISER/ICER «نوشتن ۱ = اثر، نوشتن ۰ = هیچ» هستند؛ پس فعال‌کردن یک وقفه را بدون خواندن-تغییر-نوشتن انجام می‌دهی: ISER[n >> 5] = 1u << (n & 31). (این همان فکر BSRR در درس ۳.۶ است.) دو: اولویت عدد کمتر = مهم‌تر. در STM32F4 فقط ۴ بیت بالای بایت اولویت پیاده شده؛ پس مقدار اولویت ۰ تا ۱۵ است و باید ۴ بیت به چپ شیفت داده شود.

در ابزارک، NVIC_ISER1 را ببین. برای فعال‌کردن EXTI15_10 (IRQ 40) کدام بیت را باید یک کنی؟ (راهنمایی: 40 - 32.)

از دکمه تا ISR: زنجیرهٔ EXTI

پایهٔ PC13 خودش وقفه نمی‌دهد. بین پایه و NVIC یک واحد به نام EXTI (External Interrupt controller) هست. EXTI چند «خط» دارد؛ خط‌های ۰ تا ۱۵ مخصوص پایه‌های GPIO‌اند. خط n می‌تواند به پایهٔ n از یکی از پورت‌ها وصل شود. پس PA13، PB13 و PC13 همه به خط ۱۳ می‌رسند و فقط یکی را انتخاب می‌کنیم. این انتخاب را رجیستر SYSCFG_EXTICR انجام می‌دهد.

رجیسترهای لازم (همه از RM0383؛ مقدارها با اجرای وارسی‌شدهٔ ساخت در انتهای بخش بعد چک شده‌اند):

رجیسترآدرسبیت‌ها و معنی
RCC_APB2ENR0x40023844بیت ۱۴ = SYSCFGEN (ساعت SYSCFG). بدون آن، نوشتن روی SYSCFG بی‌اثر است
SYSCFG_EXTICR40x40013814چهار فیلد ۴ بیتی برای خط‌های ۱۲..۱۵. خط ۱۳ = بیت‌های ۷..۴. مقدار: ۰=A، ۱=B، ۲=C
EXTI_IMR0x40013C00ماسک وقفه؛ بیت ۱۳ = ۱ یعنی خط ۱۳ اجازهٔ وقفه دارد
EXTI_RTSR، FTSR0x40013C08، 0x40013C0Cوقفه روی لبهٔ بالارونده (Rising) / پایین‌رونده (Falling)
EXTI_PR0x40013C14پرچم معلق. با آمدن لبه ۱ می‌شود. پاک‌کردن: نوشتن ۱ در همان بیت (write-1-to-clear)

}

{

    for (uint32_t *dst = &_sdata; dst < &_edata; ) {

    for (uint32_t *dst = &_sbss; dst < &_ebss; ) {
        *dst++ = 0u;
    }
    main();
    for (;;) {
    }
}

{

    }
}

{

        EXTI->PR = 1u << BUTTON_PIN;        /* پرچم را با نوشتن ۱ پاک کن */

    }
}

    GPIOC->PUPDR = (GPIOC->PUPDR & ~(3u << (BUTTON_PIN * 2u)))
                 | (1u << (BUTTON_PIN * 2u));

    SYSCFG->EXTICR[3] = (SYSCFG->EXTICR[3] & ~(0xFu << 4)) | (0x2u << 4);
    EXTI->FTSR |= 1u << BUTTON_PIN;
    EXTI->RTSR &= ~(1u << BUTTON_PIN);
    EXTI->PR = 1u << BUTTON_PIN;
    EXTI->IMR |= 1u << BUTTON_PIN;
    nvic_set_priority(EXTI15_10_IRQn, 5u);
    nvic_enable(EXTI15_10_IRQn);

    for (;;) {
        irq_disable();
        if (button_event == 0u) {
            wait_for_irq();
        }
        irq_enable();

        if (button_event != 0u) {
            button_event = 0u;
            press_count++;
            GPIOA->BSRR = (press_count & 1u) ? (1u << LED_PIN)
                                              : (1u << (LED_PIN + 16u));
            wait_until_released();
            EXTI->PR = 1u << BUTTON_PIN;
            EXTI->IMR |= 1u << BUTTON_PIN;
        }
    }
}

رایج‌ترین باگ این الگو: یک پرچم ساده رویدادهای نزدیک به هم را گم می‌کند. اگر ISR سه بار پشت‌سرهم صدا زده شود قبل از اینکه main نگاه کند، پرچم فقط «۱» می‌ماند. راه‌حل: شمارنده. این را با شبیه‌سازی روی PC ببین (fake_isr همان نقش ISR را دارد و با یک زمان‌بندی شبیه‌سازی‌شده صدا زده می‌شود):

#include <stdio.h>

static volatile int pending_flag;         /* نسخهٔ ۱: فقط یک پرچم */
static volatile unsigned pending_count;   /* نسخهٔ ۲: شمارنده */

static void fake_isr(void)
{
    pending_flag = 1;
    pending_count++;
}

int main(void)
{
    /* در هر «دور main» چند وقفه پیش از رسیدگی می‌رسد */
    const int irqs_per_round[] = {0, 1, 3, 0, 2, 0};
    const int rounds = (int)(sizeof irqs_per_round / sizeof irqs_per_round[0]);
    int total = 0, by_flag = 0;
    unsigned by_count = 0;

    for (int r = 0; r < rounds; r++) {
        for (int k = 0; k < irqs_per_round[r]; k++) {
            fake_isr();
            total++;
        }
        if (pending_flag) {               /* main فقط می‌فهمد «اتفاقی افتاد» */
            pending_flag = 0;
            by_flag++;
        }
        while (by_count < pending_count) {/* main همهٔ رویدادها را می‌شمارد */
            by_count++;
        }
    }
    printf("interrupts fired : %d\n", total);
    printf("seen with a flag : %d\n", by_flag);
    printf("seen with counter: %u\n", by_count);
    return 0;
}
  1. دو راه خبر دادن. یک پرچم (۰ یا ۱) و یک شمارنده.
  2. ISR شبیه‌سازی‌شده. هر بار که صدا زده شود هر دو را به‌روز می‌کند.
  3. زمان‌بندی. در هر «دور main» چند وقفه پیش از رسیدگی رسیده باشد: در دور دوم ۱، در دور سوم ۳، در دور پنجم ۲.
  4. شمارنده‌ها. کل وقفه‌ها و آنچه هر روش دیده.
  5. وقفه‌ها. در هر دور، تعداد وقفه‌های تعیین‌شده را اجرا می‌کنیم.
  6. main با پرچم. اگر پرچم ۱ بود، یک رویداد ثبت می‌کند (و پرچم را پاک).
  7. main با شمارنده. تا وقتی شمارنده از آنچه دیده بزرگ‌تر است، رویداد ثبت می‌کند.
  8. چاپ. کل وقفه‌ها و آنچه هر روش دید.

رقابت و بخش بحرانی

ISR در هر لحظه‌ای می‌تواند بین دو دستور main بیاید. اگر هر دو به یک متغیر دست بزنند، ممکن است main نصفه‌کاره دیده شود. به این وضعیت رقابت (race condition) می‌گویند. در درس ۳.۶ یک نمونه دیدی (خواندن-تغییر-نوشتن). نمونهٔ دوم ظریف‌تر است: خواندن یک مقدار ۶۴ بیتی روی CPU ۳۲ بیتی.

مثال از زندگی روزمره

شمارهٔ تلفن دوستت را در دو تکه از او می‌پرسی: «چهار رقم اول؟ ... چهار رقم آخر؟». وسط جواب‌هایش او شمارهٔ جدیدی می‌گیرد و هر دو تکه را عوض می‌کند. تو حالا نیمی از شمارهٔ قدیم و نیمی از شمارهٔ جدید را داری: شماره‌ای که هرگز وجود نداشته. یک شمارندهٔ ۶۴ بیتی دو کلمهٔ ۳۲ بیتی است و همین ماجرا برایش می‌افتد.

ببین روی حالت واقعی: شمارنده 0x00000000FFFFFFFF است و وقفه دقیقا وسط خواندن دو نیمه می‌رسد. (وقفه را با تابع fake_irq در همان نقطه شبیه‌سازی می‌کنیم؛ روی برد واقعی نقطه تصادفی است و باگ «گاهی» رخ می‌دهد.)

#include <stdio.h>
#include <stdint.h>

static uint32_t ticks_lo = 0xFFFFFFFFu;   // نیمهٔ پایین شمارنده
static uint32_t ticks_hi = 0x00000000u;   // نیمهٔ بالا

static void fake_irq(void)                // وقفه: شمارنده را یکی زیاد می‌کند
{
    ticks_lo++;
    if (ticks_lo == 0u) {
        ticks_hi++;
    }
}

int main(void)
{
    uint32_t lo = ticks_lo;               // main نیمهٔ پایین را می‌خواند
    fake_irq();                           // وقفه دقیقا همین‌جا می‌آید
    uint32_t hi = ticks_hi;               // main نیمهٔ بالا را می‌خواند

    printf("torn read : 0x%08x%08x\n", (unsigned)hi, (unsigned)lo);
    printf("real value: 0x%08x%08x\n", (unsigned)ticks_hi, (unsigned)ticks_lo);
    return 0;
}
  1. شمارندهٔ ۶۴ بیتی در دو نیمه. مقدار کامل: (hi << 32) | lo.
  2. وقفهٔ شبیه‌سازی‌شده. شمارنده را یکی زیاد می‌کند؛ اگر نیمهٔ پایین سرریز شد (صفر شد)، نیمهٔ بالا را هم یکی زیاد می‌کند.
  3. main نیمهٔ پایین را می‌خواند. 0xFFFFFFFF.
  4. وقفه می‌رسد. حالا مقدار واقعی 0x0000000100000000 است.
  5. main نیمهٔ بالا را می‌خواند. 1، یعنی نیمهٔ بالای مقدار جدید.
  6. مقایسه. مقدار خوانده‌شده و مقدار واقعی.

بخش بحرانی: وقفه‌ها را برای لحظه‌ای ببند

بخش بحرانی (critical section) قطعه‌کدی است که نباید وسطش وقفه بیاید. ساده‌ترین راه: cpsid i (بستن وقفه‌ها)، کار، سپس بازگرداندن حالت قبلی. مهم: «حالت قبلی» را ذخیره و برگردان، نه بی‌قید cpsie i؛ شاید کسی که تو را صدا زده خودش وقفه‌ها را بسته بوده.

#include <stdint.h>

volatile uint64_t ticks;

static inline uint32_t irq_save(void)
{
    uint32_t primask;
    __asm volatile ("mrs %0, primask\n\tcpsid i" : "=r" (primask) : : "memory");
    return primask;
}

static inline void irq_restore(uint32_t primask)
{
    __asm volatile ("msr primask, %0" : : "r" (primask) : "memory");
}

uint64_t read_ticks(void)
{
    uint32_t saved = irq_save();
    uint64_t copy = ticks;
    irq_restore(saved);
    return copy;
}
  1. شمارندهٔ مشترک. ۶۴ بیتی و volatile؛ ISR آن را افزایش می‌دهد.
  2. ذخیره و بستن. mrs رجیستر PRIMASK را در متغیر می‌خواند و cpsid i وقفه‌ها را می‌بندد؛ دو دستور در یک asm تا کامپایلر بینشان دستوری نگذارد. مقدار قبلی برگردانده می‌شود. PRIMASK رجیستر ویژهٔ CPU است: ۱ یعنی «وقفه‌های قابل‌ماسک بسته‌اند».
  3. بازگرداندن. msr مقدار قبلی را برمی‌گرداند؛ اگر وقفه‌ها قبلا باز بودند باز می‌شوند، وگرنه بسته می‌مانند.
  4. خواندن امن. در لحظه‌ای که وقفه‌ها بسته‌اند، نسخه‌ای کامل کپی می‌کنیم و بعد بازمی‌گردیم. هر وقفه‌ای که در این چند دستور برسد، معلق می‌ماند و بعد از irq_restore اجرا می‌شود. بنابراین دیر می‌شود ولی گم نمی‌شود.
بخش بحرانی را کوتاه نگه دار

وقتی وقفه‌ها بسته‌اند، ساعت‌ها و ارتباط‌ها هم صبر می‌کنند. بخش بحرانی باید چند دستور باشد، نه یک حلقه. اگر نیاز به کار بلند داری، معماری را عوض کن: ISR داده را در یک بافر حلقوی (درس ۴.۵) بگذارد و main آن را بردارد؛ آنجا هیچ بخش بحرانی لازم نمی‌شود چون هر طرف فقط یک انتهای بافر را می‌نویسد.

اولویت و وقفهٔ تو در تو

اگر هنگام اجرای یک ISR وقفهٔ دیگری بیاید چه می‌شود؟ NVIC اولویت‌ها را مقایسه می‌کند:

  • وقفهٔ تازه مهم‌تر (عدد اولویت کمتر) است ← ISR فعلی را قطع می‌کند (preemption). وقتی تمام شد، ISR اول ادامه می‌یابد.
  • وقفهٔ تازه هم‌اولویت یا کم‌اهمیت‌تر است ← معلق می‌ماند تا ISR فعلی تمام شود.

پیش‌فرض همهٔ وقفه‌ها اولویت ۰ است (بالاترین)؛ پس بدون تنظیم اولویت، وقفه‌ها هم‌اولویت‌اند و همدیگر را قطع نمی‌کنند. برای شروع، همین را نگه دار و فقط وقتی اولویت بگذار که دلیل داری: مثلا وقفهٔ ارتباطی با محدودیت زمانی سخت را بالاتر از وقفهٔ دکمه بگذار. هر سطح تودرتو بیشتر پشته می‌خورد؛ در سیستم‌های حرفه‌ای عمق را حساب می‌کنند.

اگر خراب شد چه می‌شود؟

باگ اول: پرچم را پاک نکردی. ISR می‌پرد، کار می‌کند، برمی‌گردد؛ و چون EXTI_PR هنوز یک است، NVIC همان لحظه دوباره صدایش می‌زند. برنامهٔ اصلی هرگز نوبت نمی‌گیرد. شبیه‌سازی ساده روی PC:

#include <stdio.h>

static unsigned pending;                  /* مثل بیت ۱۳ از EXTI_PR */

static void run(int isr_clears)
{
    unsigned isr_calls = 0, main_steps = 0;

    pending = 1;                          /* یک لبه آمده */
    for (int tick = 0; tick < 1000; tick++) {
        if (pending) {                    /* تا پاک نشود، CPU دوباره وارد ISR می‌شود */
            isr_calls++;
            if (isr_clears) {
                pending = 0;
            }
        } else {
            main_steps++;
        }
    }
    printf("clears PR: %-3s -> ISR ran %4u times, main ran %3u steps\n",
           isr_clears ? "yes" : "no", isr_calls, main_steps);
}

int main(void)
{
    run(1);
    run(0);
    return 0;
}
  1. پرچم معلق. جای بیت ۱۳ از EXTI_PR.
  2. تابع اجرا. پارامتر می‌گوید ISR پرچم را پاک می‌کند یا نه. دو شمارنده: چند بار ISR و چند قدم main.
  3. یک لبه آمده. پرچم ۱ است.
  4. هر «تیک» CPU. اگر پرچم معلق است، وارد ISR می‌شود (مثل NVIC واقعی). اگر ISR پرچم را پاک کند، بار بعد main نوبت می‌گیرد؛ وگرنه نه.
  5. گزارش. چند بار ISR اجرا شد و main چند قدم رفت.
  6. دو حالت. با پاک‌کردن و بدون آن.
$ gcc -std=c11 -Wall -Wextra -o storm storm.c
$ ./storm
clears PR: yes -> ISR ran    1 times, main ran 999 steps
clears PR: no  -> ISR ran 1000 times, main ran   0 steps

علامتش روی برد: «برنامه یک بار دکمه را دید و بعد قفل شد». LED عوض می‌شود ولی هیچ چیز دیگری (حتی چشمک دوم) اجرا نمی‌شود.

باگ دوم: نام handler را غلط نوشتی. مثلا EXTI15_10_IRQHandle یا EXTI15_10_IRQHander. کامپایلر خطا نمی‌دهد (تابع دیگری با نام دیگر تعریف کردی)، ولی جدول همچنان به Default_Handler اشاره می‌کند. علامت: دکمه را می‌زنی و برنامه می‌ایستد؛ با دیباگر می‌بینی در Default_Handler در حلقه‌ای هستی. راه مطمئن: اسم را از فایل startup رسمی (یا از خروجی nm) کپی کن.

فهرست وارسی وقتی وقفه نمی‌آید:

علامتعلت رایج
ISR هرگز اجرا نمی‌شودساعت SYSCFG خاموش؛ EXTICR اشتباه (پورت غلط)؛ IMR صفر؛ لبه (RTSR/FTSR) اشتباه؛ NVIC فعال نشده؛ بیت اشتباه در ISER (IRQ 40 = ISER1 بیت ۸)
برنامه با یک فشردن قفل می‌شودپرچم PR پاک نشده، یا نام handler غلط است (Default_Handler)
حلقهٔ انتظار در main هرگز تمام نمی‌شود (با -O2)پرچم مشترک volatile نیست
یک فشردن = چند رویدادپرش تماس. ماسک کردن خط یا بازه‌گذاری زمانی
مقدار مشترک گاهی «عجیب» استرقابت: خواندن چندبخشی بدون بخش بحرانی
HardFault هنگام وقفهدرایهٔ جدول صفر است (وقفه‌ای فعال شده که handler ندارد) یا پشته پر شده

در ESP32 چه؟

ESP32 (Xtensa) کنترلر NVIC ندارد؛ وقفه‌ها از یک «ماتریس وقفه» عبور می‌کنند و درایور ESP-IDF کارهای سخت را (تخصیص وقفه، ثبت handler) برایت می‌کند. تو فقط می‌گویی «روی این پایه، با این لبه، این تابع را صدا بزن». خود قواعد ISR عینا همان است: کوتاه، بدون انتظار، بدون printf، و رساندن کار به یک task. الگوی معمول در FreeRTOS: ISR یک پیام در صف می‌گذارد و یک task (که بلاک شده منتظر صف است) بیدار می‌شود و کار سنگین را می‌کند. (کد زیر برای ESP-IDF نسخهٔ ۵ است؛ در این محیط ساخته نمی‌شود، پس فقط frag است. نام‌ها از مستندات رسمی ESP-IDF هستند.)

#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "freertos/queue.h"
#include "esp_log.h"

#define BUTTON_GPIO GPIO_NUM_0          // معمولا دکمهٔ BOOT روی DevKit

static const char *TAG = "button";
static QueueHandle_t button_queue;

static void IRAM_ATTR button_isr(void *arg)
{
    uint32_t gpio_num = (uint32_t)arg;
    xQueueSendFromISR(button_queue, &gpio_num, NULL);
}

static void button_task(void *arg)
{
    uint32_t gpio_num;
    for (;;) {
        if (xQueueReceive(button_queue, &gpio_num, portMAX_DELAY)) {
            ESP_LOGI(TAG, "button on GPIO %lu", (unsigned long)gpio_num);
        }
    }
}

void app_main(void)
{
    gpio_config_t io = {
        .pin_bit_mask = 1ULL << BUTTON_GPIO,
        .mode = GPIO_MODE_INPUT,
        .pull_up_en = GPIO_PULLUP_ENABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type = GPIO_INTR_NEGEDGE,
    };
    gpio_config(&io);

    button_queue = xQueueCreate(10, sizeof(uint32_t));
    xTaskCreate(button_task, "button_task", 2048, NULL, 10, NULL);

    gpio_install_isr_service(0);
    gpio_isr_handler_add(BUTTON_GPIO, button_isr, (void *)BUTTON_GPIO);
}
  1. هدرها. درایور GPIO، هستهٔ FreeRTOS، task، صف و لاگ.
  2. پایهٔ دکمه. GPIO0 روی بسیاری از بردهای DevKit به دکمهٔ BOOT وصل است (برد خودت را ببین).
  3. تگ و صف. TAG برای لاگ. صف را ISR می‌نویسد و task می‌خواند.
  4. ISR. IRAM_ATTR کد را در RAM داخلی می‌گذارد. ISR باید هنگام نوشتن روی Flash هم قابل اجرا باشد، و در آن لحظه Flash در دسترس نیست. xQueueSendFromISR نسخهٔ مخصوص ISR است: پیام را در صف می‌گذارد و هرگز بلاک نمی‌شود. در ISR فقط توابع «FromISR» مجازند؛ نسخهٔ عادی (مثل xQueueSend) ممکن است بلاک شود و در ISR غیرمجاز است.
  5. task. بلاک می‌شود تا پیامی برسد (portMAX_DELAY = بی‌نهایت). وقتی رسید، در یک task (نه ISR) لاگ می‌کند؛ ESP_LOGI در ISR ممنوع است.
  6. پیکربندی پایه. ورودی با بالاکش و وقفه روی لبهٔ پایین‌رونده (GPIO_INTR_NEGEDGE). همان کارِ ما با EXTI و SYSCFG، در یک struct.
  7. صف و task. صفی با ۱۰ جا برای uint32_t؛ taskی با ۲۰۴۸ بایت پشته و اولویت ۱۰.
  8. ثبت ISR. gpio_install_isr_service یک بار سرویس وقفهٔ GPIO را نصب می‌کند و gpio_isr_handler_add تابع را به یک پایه گره می‌زند و آرگومان می‌دهد.
مقایسهٔ دو دنیا

STM32: EXTI ← NVIC ← جدول برداری ← ISR ← پرچم volatile ← main. ESP32 + FreeRTOS: درایور ← ISR ← صف (xQueueSendFromISR) ← task. در هر دو، ISR فقط «اطلاع می‌دهد» و کار در جای دیگر انجام می‌شود. درس ۵.۶ صف‌ها و task ها را کامل می‌آورد.

آزمون این درس

هنگام وقفه، کدام کار را خود سخت‌افزار انجام می‌دهد (بدون هیچ کدی از تو)؟

  1. پاک‌کردن پرچم EXTI_PR
  2. علامت‌گذاری متغیرهای مشترک با volatile
  3. ذخیرهٔ هشت ثبات روی پشته، خواندن آدرس handler از جدول و پرش به آن
  4. فعال‌کردن وقفه در NVIC
ذخیرهٔ R0..R3، R12، LR، PC، xPSR، خواندن جدول و پرش در سخت‌افزار Cortex-M خودکار است. بقیه، از جمله پاک‌کردن پرچم پریفرال، با توست.

وقفهٔ EXTI15_10 شمارهٔ ۴۰ دارد. کدام بیت از کدام رجیستر NVIC آن را فعال می‌کند؟

  1. بیت ۸ از NVIC_ISER1 (چون ۴۰ − ۳۲ = ۸)
  2. بیت ۴۰ از NVIC_ISER0
  3. بیت ۴۰ از NVIC_ISER1
  4. بیت ۸ از NVIC_ICER1
irq >> 5 = ۱ (ISER1) و irq & 31 = ۸ (بیت ۸). آدرس 0xE000E104.

کدام خط در این ISR خطای طراحی دارد؟

void EXTI15_10_IRQHandler(void)
{
    EXTI->PR = 1u << 13;
    printf("button!\n");
    button_event = 1u;
}
  1. پاک‌کردن PR با نوشتن ۱
  2. گذاشتن button_event = 1u
  3. نام تابع EXTI15_10_IRQHandler
  4. صدا زدن printf داخل ISR
printf کند است، ممکن است بلاک شود و معمولا reentrant نیست. در ISR فقط پرچم بگذار و چاپ را به main بسپار.

در main منتظری تا ISR پرچم done را یک کند: while (done == 0) { }. برنامه با -O2 هرگز جلو نمی‌رود، ولی با -O0 درست کار می‌کند. علت محتمل چیست؟

  1. نوع uint32_t برای پرچم کوچک است
  2. done غیر volatile است و کامپایلر آن را یک‌بار می‌خواند و حلقه را بی‌پایان می‌کند
  3. کامپایلر -O2 باگ دارد
  4. وقفه‌ها به‌طور پیش‌فرض بسته‌اند
از دید کامپایلر، در حلقه هیچ‌چیز done را عوض نمی‌کند، پس خواندنش را تکرار نمی‌کند. volatile این را ممنوع می‌کند (تمرین ۲).

ISR A با اولویت ۵ در حال اجراست و وقفهٔ B با اولویت ۱ می‌رسد. چه می‌شود؟

  1. B معلق می‌ماند تا A تمام شود
  2. A برای همیشه کنار گذاشته می‌شود
  3. A قطع می‌شود، B اجرا می‌شود، سپس A ادامه می‌یابد
  4. هر بار تصادفی است
عدد کمتر یعنی مهم‌تر. B (۱) بر A (۵) پیشی می‌گیرد (preemption).

چرا خواندن شمارندهٔ volatile uint64_t که ISR افزایشش می‌دهد، روی Cortex-M4 باید در بخش بحرانی باشد؟

  1. چون خواندن دو کلمهٔ ۳۲ بیتی اتمی نیست؛ وقفه بین آن‌ها می‌تواند نیمی از مقدار قدیم و نیمی از جدید را ترکیب کند
  2. چون volatile اتمی‌بودن را تضمین می‌کند ولی کند است
  3. چون CPU ۳۲ بیتی نمی‌تواند عدد ۶۴ بیتی بخواند
  4. چون خواندن ۶۴ بیت کند است
نتیجهٔ غلط از ترکیب دو نیمه می‌آید (مثل 0x00000001FFFFFFFF). بخش بحرانی یا نسخه‌برداری امن آن را حل می‌کند.

تمرین‌ها

تمرین ۱: شمارهٔ وقفه تا آدرس‌ها

برای هر IRQ، رجیستر و بیت در ISER، آدرس بایت اولویت (IPR) و آفست جدول برداری را حساب می‌کنیم. شماره‌ها از RM0383: EXTI0 = ۶، TIM2 = ۲۸، USART2 = ۳۸، EXTI15_10 = ۴۰.

  1. پیش‌بینی: برای TIM2 کدام ISER و کدام بیت؟ آفست جدول برداری‌اش چند است؟
  2. حل: برنامهٔ کوچک PC بنویس که این چهار مقدار را چاپ کند.
  3. تغییر: USART2 در کدام رجیستر ISER می‌نشیند؟ چرا بیتش ۶ است؟
راهنمایی

رجیستر = irq >> 5، بیت = irq & 31. آدرس ISER = 0xE000E100 + 4 × رجیستر. آدرس IPR = 0xE000E400 + irq. آفست جدول = 4 × (16 + irq).

چه باید ببینی؟

TIM2       irq=28  ISER0 bit 28 @ 0xE000E100  IPR @ 0xE000E41C  vector @ +0x0B0
USART2     irq=38  ISER1 bit  6 @ 0xE000E104  IPR @ 0xE000E426  vector @ +0x0D8

جواب کامل با توضیح 
#include <stdio.h>

static void show(const char *name, unsigned irq)
{
    printf("%-10s irq=%2u  ISER%u bit %2u @ 0x%08X  IPR @ 0x%08X  vector @ +0x%03X\n",
           name, irq, irq >> 5, irq & 31u,
           0xE000E100u + 4u * (irq >> 5), 0xE000E400u + irq, 4u * (16u + irq));
}

int main(void)
{
    show("EXTI0", 6);
    show("TIM2", 28);
    show("USART2", 38);
    show("EXTI15_10", 40);
    return 0;
}
  1. تابع show. با یک شمارهٔ IRQ چهار مقدار را حساب و چاپ می‌کند: irq >> 5 رجیستر است و irq & 31u بیت. %-10s نام را به عرض ۱۰ ستون چپ‌چین می‌کند.
  2. آدرس‌ها. ISER پایه 0xE000E100 و به‌ازای هر رجیستر ۴ بایت جلو می‌رود. IPR بایتی است: 0xE000E400 + irq. جدول: 4 × (16 + irq).
  3. چهار وقفه. TIM2 = ۲۸ پس ISER0 بیت ۲۸ است. USART2 = ۳۸ = ۳۲ + ۶ پس ISER1 بیت ۶ است.

پاسخ الف: TIM2 در ISER0 بیت ۲۸ و آفست 0xB0 است. پاسخ ج: ۳۸ از ۳۱ بزرگ‌تر است، پس در رجیستر دوم (ISER1) می‌نشیند؛ بیت = ۳۸ − ۳۲ = ۶.

تمرین ۲: سه باگ در یک ISR

این برنامه (برای STM32F411) کامپایل می‌شود ولی هرگز LED را روشن نمی‌کند. سه باگ دارد. فرض کن ساعت‌ها، SYSCFG و EXTI درست تنظیم شده‌اند.

static uint32_t pressed;

    /* فرض کن ساعت‌ها، SYSCFG و EXTI درست تنظیم شده‌اند */
    NVIC_ISER1 = 1u << 7;

    }
    GPIOA_BSRR = 1u << 5;

    }
}
  1. پیدا کردن: سه باگ را با شمارهٔ خط بنویس.
  2. تحلیل: با -O2، اسمبلی main فقط یک بار pressed را می‌خواند و بعد حلقهٔ بی‌نهایت است. کدام باگ این را می‌سازد؟
  3. اصلاح: برنامهٔ درست را بنویس.
راهنمایی

یک: پرچم مشترک چه ویژگی‌ای لازم دارد؟ دو: بعد از رسیدگی به EXTI باید چه چیزی را پاک کرد؟ سه: IRQ 40 کدام بیت از ISER1 است؟

#define EXTI_PR    (*(volatile uint32_t *)0x40013C14u)
#define NVIC_ISER1 (*(volatile uint32_t *)0xE000E104u)
#define GPIOA_BSRR (*(volatile uint32_t *)0x40020018u)

static volatile uint32_t pressed;

void EXTI15_10_IRQHandler(void)
{
    EXTI_PR = 1u << 13;
    pressed = 1u;
}

int main(void)
{
    /* فرض کن ساعت‌ها، SYSCFG و EXTI درست تنظیم شده‌اند */
    NVIC_ISER1 = 1u << 8;

    }
    GPIOA_BSRR = 1u << 5;

    }
}
  1. volatile. پرچم مشترک حالا همیشه از حافظه خوانده می‌شود.
  2. ISR درست. اول پرچم را با نوشتن ۱ پاک می‌کنیم، بعد خبر می‌دهیم.
  3. بیت درست. 1u << 8 = IRQ 40.
  4. حلقهٔ انتظار. حالا با هر دور مقدار تازه خوانده می‌شود.

نکتهٔ مهم: کامپایلر برای هیچ‌کدام از سه باگ خطا یا هشدار نمی‌دهد. سخت‌ترین باگ‌های embedded همین‌ها هستند: کد «درست» به نظر می‌رسد.

تمرین ۳: LED هم‌قدم با دکمه (چالش سخت‌افزاری)

می‌خواهیم LED تا وقتی دکمه فشرده است روشن باشد و با رها کردن خاموش شود، این بار با وقفه. (در درس ۵.۲ با پولینگ ساختیم.)

  1. طرح: کدام لبه‌ها لازم است؟ کدام رجیستر تغییر می‌کند نسبت به برنامهٔ toggle؟
  2. حل: برنامه را بنویس. ISR باید سطح واقعی پایه را بخواند و LED را همان‌جا تنظیم کند.
  3. فکر کن: پرش تماس اینجا مشکلی می‌سازد؟ (راهنمایی: ISR هر بار سطح واقعی را می‌خواند.)
راهنمایی

هر دو لبه لازم است: FTSR و RTSR هر دو بیت ۱۳. در ISR اگر IDR بیت ۱۳ یک است دکمه رها شده (LED خاموش)، وگرنه فشرده (LED روشن). فقط یک نوشتن BSRR؛ پس ISR کوتاه می‌ماند.

چه باید ببینی؟

روی برد: LED تا وقتی B1 را نگه داری روشن است و با رها کردن خاموش می‌شود؛ بدون تأخیر محسوس. پاسخ ج: پرش‌ها ISR را چند بار صدا می‌زنند، ولی هر بار سطح فعلی را می‌خواند و LED را با آن هم‌قدم می‌کند. آخرین ISR وضعیت نهایی را می‌گذارد؛ پس برنامه «خودترمیم» است و پرش زیانی ندارد. (نکته: این برای «هم‌قدمی وضعیت» درست است؛ برای «شمردن فشردن‌ها» نه.)

جواب کامل با توضیح 
#include <stdint.h>

#define RCC_AHB1ENR   (*(volatile uint32_t *)0x40023830u)
#define RCC_APB2ENR   (*(volatile uint32_t *)0x40023844u)
#define GPIOA_MODER   (*(volatile uint32_t *)0x40020000u)
#define GPIOA_BSRR    (*(volatile uint32_t *)0x40020018u)
#define GPIOC_PUPDR   (*(volatile uint32_t *)0x4002080Cu)
#define GPIOC_IDR     (*(volatile uint32_t *)0x40020810u)
#define SYSCFG_EXTICR4 (*(volatile uint32_t *)0x40013814u)
#define EXTI_IMR      (*(volatile uint32_t *)0x40013C00u)
#define EXTI_RTSR     (*(volatile uint32_t *)0x40013C08u)
#define EXTI_FTSR     (*(volatile uint32_t *)0x40013C0Cu)
#define EXTI_PR       (*(volatile uint32_t *)0x40013C14u)
#define NVIC_ISER1    (*(volatile uint32_t *)0xE000E104u)

void EXTI15_10_IRQHandler(void)
{
    if (EXTI_PR & (1u << 13)) {
        EXTI_PR = 1u << 13;
        if (GPIOC_IDR & (1u << 13)) {
            GPIOA_BSRR = 1u << 21;
        } else {
            GPIOA_BSRR = 1u << 5;
        }
    }
}

int main(void)
{
    RCC_AHB1ENR |= (1u << 0) | (1u << 2);
    RCC_APB2ENR |= 1u << 14;
    (void)RCC_APB2ENR;

    GPIOA_MODER = (GPIOA_MODER & ~(3u << 10)) | (1u << 10);
    GPIOC_PUPDR = (GPIOC_PUPDR & ~(3u << 26)) | (1u << 26);

    SYSCFG_EXTICR4 = (SYSCFG_EXTICR4 & ~(0xFu << 4)) | (0x2u << 4);
    EXTI_FTSR |= 1u << 13;
    EXTI_RTSR |= 1u << 13;
    EXTI_PR = 1u << 13;
    EXTI_IMR |= 1u << 13;
    NVIC_ISER1 = 1u << 8;

    for (;;) {
        __asm volatile ("wfi");
    }
}
  1. رجیسترها. بدون هدر: آدرس هر رجیستر با #define (مقادیر همان جدول‌های امروز).
  2. ISR. اگر خط ۱۳ معلق است: پرچم را پاک می‌کند، سپس سطح پایه را می‌خواند. ۱ = رها ← BSRR بیت ۲۱ (خاموش)؛ ۰ = فشرده ← بیت ۵ (روشن).
  3. main.
  4. ساعت‌ها. GPIOA و GPIOC (AHB1ENR)، SYSCFG (APB2ENR بیت ۱۴).
  5. GPIO. LED خروجی، دکمه بالاکش.
  6. EXTI. پورت C برای خط ۱۳، هر دو لبه، پاک‌کردن معلق قدیمی، باز کردن ماسک، و فعال‌کردن IRQ 40.
  7. حلقه. wfi تا وقفه بیاید. کار در ISR است. این کار با یک نوشتن BSRR ایمن است؛ اگر کار ISR پیچیده‌تر بود باید به main می‌سپردیم.

این برنامه هم مثل ۵.۲ نیاز به startup و جدول برداری دارد؛ همان startup.c، board.h (یا این تعریف‌ها) و link.ld بخش قبل را کنارش بگذار. اینجا فقط arm-none-eabi-gcc -c شد (کامپایل)، نه لینک.

حرف مربی

وقفه‌ها جایی است که بیشتر برنامه‌نویس‌ها اولین باگ «هفته‌ها» را می‌بینند: برنامه ۹۹٪ وقت درست کار می‌کند و گاهی، بدون دلیل، خراب می‌شود. علتش تقریبا همیشه یکی از این سه است: پرچم volatile نیست، متغیر مشترک چندبخشی بدون بخش بحرانی خوانده شده، یا ISR کار زیادی می‌کند. اگر یک قاعده را حفظ کنی: ISR فقط خبر می‌دهد؛ main کار می‌کند، ۹۰٪ این باگ‌ها هرگز به سراغت نمی‌آیند. و وقتی گیر کردی، دیباگر (درس ۶.۱) را روی Default_Handler و رجیستر EXTI_PR نگاه کن.

خلاصه یک‌دقیقه‌ای

  • وقفه = سخت‌افزار برنامه را قطع می‌کند، قاب هشت‌کلمه‌ای را روی پشته می‌گذارد، آدرس ISR را از جدول برداری می‌خواند و بعد از پایان دقیقا برمی‌گردد.
  • وقفهٔ n در درایهٔ 16 + n است؛ آفست 4 × (16 + n). ISR یک تابع C معمولی با نام دقیقِ startup است.
  • NVIC: ISER (فعال، «نوشتن ۱»)، IPR (اولویت، عدد کمتر = مهم‌تر، ۴ بیت بالای بایت در STM32F4).
  • دکمهٔ PC13: ساعت‌های GPIOC و SYSCFG، EXTICR4 = PC، FTSR، پاک‌کردن PR، IMR، NVIC (IRQ 40 = ISER1 بیت ۸).
  • ISR کوتاه، بدون انتظار و بدون printf؛ پرچم volatile؛ EXTI_PR را با نوشتن ۱ پاک کن.
  • مقدار مشترک چندبخشی (مثلا ۶۴ بیتی) را در بخش بحرانی (PRIMASK) بخوان؛ پرچم ساده رویدادهای پشت‌سرهم را گم می‌کند.
  • ESP32: gpio_isr_handler_add با IRAM_ATTR و xQueueSendFromISR؛ کار سنگین در task.
  • بعدی: تایمر و SysTick برای زمان‌بندی بدون قفل‌کردن main.
