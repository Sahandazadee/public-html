در درس قبل هر متغیر را «قفسه» نامیدیم و گفتیم int یعنی قفسهٔ چهار‌بایتی. ولی همهٔ چیزها که در یک قفسهٔ چهار‌بایتی جا نمی‌شوند و بعضی چیزها هم آن‌قدر کوچک‌اند که چهار بایت برایشان اسراف است. در این درس یاد می‌گیری چه اندازه‌هایی از قفسه داریم، هر کدام تا کجا عدد نگه می‌دارد، چه می‌شود اگر عدد از قفسه بزرگ‌تر باشد، و چرا برنامه‌نویس‌های میکروکنترلر تقریبا همیشه uint8_t و uint32_t می‌نویسند، نه int.

ایدهٔ اصلی: ظرف به اندازهٔ محتوا

در آشپزخانه ظرف‌های گوناگون داری: قاشق‌چایخوری، لیوان، پارچ، سطل. اگر بخواهی یک قاشق شکر بریزی، سطل انتخاب نمی‌کنی، چون جای بیهوده می‌گیرد. اگر بخواهی ده لیتر آب نگه داری، لیوان انتخاب نمی‌کنی، چون سرریز می‌شود و آب روی زمین می‌ریزد. هر ظرف ظرفیت مشخص دارد.

در C هم همین است. هر متغیر یک نوع دارد و نوع دو چیز را ثابت می‌کند: ۱) چند بایت جا بگیرد و ۲) آن بایت‌ها را چطور بخوانیم (مثلا عدد صحیح یا عدد اعشاری). بایت‌ها خودشان فقط صفر و یک‌اند؛ این نوع است که معنا می‌دهد.

مثال از زندگی روزمره

کیلومترشمار ماشین را در نظر بگیر که فقط شش رقم دارد. وقتی به ۹۹۹۹۹۹ می‌رسد و یک کیلومتر دیگر می‌رود، رقم‌ها دوباره ۰۰۰۰۰۰ می‌شوند؛ چون جایی برای رقم هفتم ندارد. نه خطایی می‌دهد، نه خبر می‌کند؛ ساده برمی‌گردد به صفر. متغیرهای C دقیقا همین‌طورند، فقط به‌جای رقم ده‌دهی، بیت دارند.

چرا ۲۵۶ برابر؟ یادت هست در درس ۱.۲ گفتیم هر بیت دو حالت دارد؟ پس ۸ بیت (یک بایت) می‌شود ۲ به توان ۸، یعنی ۲۵۶ حالت: از ۰ تا ۲۵۵. با ۱۶ بیت، ۶۵٬۵۳۶ حالت داریم و با ۳۲ بیت حدود ۴٫۳ میلیارد. هیچ جادویی نیست؛ فقط شمردن.

خودت ببین. این برنامه از خود کامپایلر می‌پرسد هر نوع چند بایت است (یادت هست sizeof در درس ۲.۱؟):

#include <stdio.h>

int main(void)
{
    printf("char      : %zu\n", sizeof(char));
    printf("short     : %zu\n", sizeof(short));
    printf("int       : %zu\n", sizeof(int));
    printf("long      : %zu\n", sizeof(long));
    printf("long long : %zu\n", sizeof(long long));
    printf("float     : %zu\n", sizeof(float));
    printf("double    : %zu\n", sizeof(double));
    printf("pointer   : %zu\n", sizeof(void *));
    return 0;
}
  1. اندازهٔ نوع‌های صحیح. برای هر نوع، sizeof تعداد بایت را می‌دهد و %zu آن را چاپ می‌کند. به‌جای حفظ‌کردن جدول، از کامپایلر بپرس. جواب او همان چیزی است که برنامهٔ تو واقعا می‌بیند.
  2. اعشاری‌ها. float و double را کمی بعدتر می‌شناسیم؛ فعلا فقط اندازه‌شان را ببین.
  3. اشاره‌گر (pointer). void * نوعی است که آدرس یک خانهٔ حافظه را نگه می‌دارد. اینجا فقط اندازه‌اش را می‌پرسیم؛ کارش را در درس ۳.۲ یاد می‌گیری. اندازهٔ آدرس به معماری بستگی دارد: ۳۲ بیت روی STM32 و ESP32، ۶۴ بیت روی لپ‌تاپ‌های امروزی.
  4. پایان برنامه. صفر برمی‌گردانیم تا بگوییم همه‌چیز خوب بود.

این خروجی از یک لینوکس ۶۴بیتی است (long = ۸). اگر همین را روی ویندوز یا روی خود میکروکنترلر بسنجی، long و اشاره‌گر چهار بایت درمی‌آید. در پایان همین درس یک قطعه‌کد می‌بینی که همین ادعا را با کامپایلر واقعی ARM وارسی می‌کند.

هر نوع تا کجا می‌رود؟ محدوده و علامت

تا اینجا فقط از «تعداد حالت» حرف زدیم. حالا سؤال بعدی: با این حالت‌ها چه عددهایی را نشان بدهیم؟ دو راه داریم و هر متغیر باید یکی را انتخاب کند:

  • بی‌علامت (unsigned): فقط عدد صفر و مثبت. یک بایت: 0 تا 255.
  • با علامت (signed): عدد منفی هم دارد. یک بایت: -128 تا 127.

تعداد حالت‌ها در هر دو ۲۵۶ است؛ فقط نیمی را به منفی‌ها داده‌ایم. حتما یادت هست که در درس ۱.۲ روش «مکمل ۲» را دیدیم: بیت سمت چپ (پرارزش‌ترین بیت) اگر ۱ باشد، عدد منفی است. همان بیت‌ها، دو خوانش:

جدول محدودهٔ نوع‌های رایج (همان که کتابخانهٔ limits.h و stdint.h با اسم‌های INT_MAX و UINT8_MAX در اختیارت می‌گذارند):

  1. کتابخانهٔ حدها. limits.h اسم‌هایی مثل INT_MAX را تعریف می‌کند که مقدار بیشینهٔ هر نوع روی همین کامپایلر است. این‌ها «ماکرو»اند (اسمی که کامپایلر قبل از ترجمه با عدد عوض می‌کند؛ در درس ۴.۱ می‌آید). فعلا مثل متغیرهای ثابت به آن‌ها نگاه کن.
  2. CHAR_BIT. تعداد بیت در یک بایت؛ روی همهٔ پلتفرم‌های این دوره ۸ است.
  3. حد پایین و بالا. %d برای عدد صحیح با علامت است. INT_MIN پایین‌ترین و INT_MAX بالاترین مقدار int است.
  4. حد بی‌علامت. برای unsigned int باید %u بنویسی. اگر با %d بچاپی، عدد بالای ۲ میلیارد را منفی نشان می‌دهد، چون همان بیت‌ها را «با علامت» می‌خواند.

وقتی عدد از ظرف بزرگ‌تر است: سرریز

برگردیم به کیلومترشمار. اگر متغیر uint8_t روی ۲۵۵ باشد و ۱ اضافه کنی چه می‌شود؟ جای نهمین بیت وجود ندارد؛ پس ۲۵۶ (یعنی 1 0000 0000) بریده می‌شود و فقط هشت بیت پایین می‌ماند: 0000 0000. جواب: صفر. به این پدیده سرریز (overflow) می‌گویند و برگشتن از سقف به کف را چرخش (wraparound) می‌نامند.

با ابزارک زیر امتحان کن. روی «+ ۱۰» بزن تا به سقف برسی و ببین چه می‌شود. بعد نوع را به int8_t عوض کن؛ آنجا با خبر خاصی روبه‌رو می‌شوی:

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint8_t level = 250;
    int i;

    for (i = 0; i < 8; i++) {
        level = level + 1;
        printf("%u ", (unsigned)level);
    }
    printf("\n");

    uint8_t zero = 0;
    zero = zero - 1;
    printf("0 - 1 = %u\n", (unsigned)zero);
    return 0;
}
  1. stdint.h. این کتابخانه نوع‌هایی مثل uint8_t را می‌شناساند (کمی بعد کامل توضیح می‌دهیم). بدون آن، کامپایلر uint8_t را نمی‌شناسد.
  2. متغیر هشت‌بیتی بی‌علامت. uint8_t یعنی «عدد بی‌علامت با ۸ بیت» (u = unsigned، int = عدد صحیح، 8 = تعداد بیت). ۲۵۰ فقط پنج قدم تا سقف فاصله دارد.
  3. شمارندهٔ حلقه. i فقط می‌شمارد که حلقه چند بار اجرا شده (حلقه‌ها را در درس ۲.۵ کامل می‌بینیم). int i; فقط یک متغیر معمولی است و i++ یعنی «یکی زیاد کن».
  4. هشت بار یکی اضافه کن. for بدنهٔ بین { و } را هشت بار تکرار می‌کند. هر بار level یکی زیاد و چاپ می‌شود. چاپ را با (unsigned) انجام می‌دهیم تا نوع با قالب %u هم‌خوان باشد. دلیل کامل‌ترش در بخش printf همین درس است.
  5. رفتن به خط بعد. بعد از حلقه یک خط‌شکن چاپ می‌کنیم.
  6. چرخش از پایین. صفر منهای یک، از کف به سقف می‌رود: ۲۵۵. مثل کیلومترشماری که به عقب بچرخد. در نوع بی‌علامت، «باقیمانده بر ۲⁸» تضمین‌شده است؛ پس ۰−۱ همیشه ۲۵۵ می‌شود.
  7. پایان. صفر یعنی موفقیت.
$ gcc -std=c11 -Wall -Wextra -o wrap wrap.c
$ ./wrap
251 252 253 254 255 0 1 2
0 - 1 = 255
با علامت فرق دارد: سرریز = رفتار تعریف‌نشده

چرخش قانونی فقط برای بی‌علامت است. اگر int روی ۲۱۴۷۴۸۳۶۴۷ باشد و یکی اضافه کنی، استاندارد C می‌گوید «رفتار تعریف‌نشده (undefined behavior)»؛ یعنی کامپایلر اجازه دارد هر کاری بکند: ممکن است منفی شود، ممکن است برنامه خراب شود، و ممکن است کامپایلر فرض کند «هرگز چنین چیزی رخ نمی‌دهد» و کدی که برای این حالت نوشته‌ای را حذف کند. جزئیاتش را در درس ۶.۲ می‌بینی. قاعدهٔ امروز: برای شمارش و حساب‌های مرزی از نوع بی‌علامت استفاده کن و مرز را خودت بررسی کن.

نوع‌های اندازه‌ثابت: stdint.h

دیدی که int روی هر پلتفرم اندازهٔ دیگری دارد. حالا وضعیتی را تصور کن که در میکروکنترلر برای یک رجیستر ۳۲بیتی (خانه‌ای در سخت‌افزار که در درس ۳.۶ می‌شناسیمش) یک متغیر می‌خواهی، یا برای یک پیام روی سیم که دقیقا ۲ بایت است. اگر بنویسی int و کد را روی Arduino Uno ببری، ناگهان ۲ بایت می‌شود و برنامه از کار می‌افتد.

راه‌حل استاندارد C از سال ۱۹۹۹: کتابخانهٔ stdint.h. اسم هر نوع، اندازه‌اش را در خودش دارد:

این نوع‌ها «همان نوع‌های قدیمی با اسم دیگر» هستند، و اینکه اسم دیگرِ کدام نوع قدیمی باشند به پلتفرم بستگی دارد. مثلا روی بیشتر کامپایلرهای PC، uint32_t همان unsigned int است؛ ولی روی arm-none-eabi-gcc (کامپایلر STM32) همان unsigned long است (هر دو ۳۲ بیتی‌اند، فقط اسمشان فرق دارد)، و روی پلتفرمی که int ۱۶ بیتی است هم unsigned long است. همین است ارزش‌شان: اندازه ثابت می‌ماند، هر اسم قدیمی‌ای که زیرش باشد. نتیجهٔ عملی: برای چاپ uint32_t حدس نزن که %u درست است؛ از PRIu32 (پایین‌تر) استفاده کن.

#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void)
{
    uint8_t  small = 200;
    int16_t  temp = -1234;
    uint32_t ticks = 4000000000U;

    printf("sizes: %zu %zu %zu\n", sizeof(small), sizeof(temp), sizeof(ticks));
    printf("small = %u\n", (unsigned)small);
    printf("temp  = %d\n", (int)temp);
    printf("ticks = %" PRIu32 "\n", ticks);
    printf("max u8 = %u, max u32 = %" PRIu32 "\n", (unsigned)UINT8_MAX, (uint32_t)UINT32_MAX);
    return 0;
}
  1. دو کتابخانه. stdint.h خود نوع‌ها را می‌سازد؛ inttypes.h قالب‌های چاپ متناسب با آن‌ها را (مثل PRIu32) می‌دهد.
  2. بایت. ۲۰۰ در بازهٔ ۰ تا ۲۵۵ جا می‌شود.
  3. عدد ۱۶ بیتی با علامت. دمای -12.34 درجه را می‌توان به‌صورت -1234 (صدم درجه) ذخیره کرد. این ترفند در میکروکنترلر بسیار رایج است تا سراغ اعشاری نرویم.
  4. پسوند U. 4000000000U با حرف U (unsigned) به کامپایلر می‌گوید این عدد را بی‌علامت بخوان. چهار میلیارد از سقف int (۲٫۱ میلیارد) بزرگ‌تر است. بدون U هم امروز کامپایلر آن را به نوع بزرگ‌تری تبدیل می‌کند، ولی صریح‌بودن بهتر است و با هشدارها هم سازگار می‌ماند.
  5. اندازه‌ها. ۱، ۲، ۴؛ دقیقا همان‌که اسم نوع‌ها می‌گفت، روی هر پلتفرمی.
  6. چاپ نوع‌های کوچک. printf اعداد کوچک‌تر از int را خودش به int بالا می‌برد؛ پس ما هم با (unsigned) و (int) صریحا همان نوع قالب را نشانش می‌دهیم. تا قالب و نوع همیشه هم‌خوان بمانند و -Wall اعتراضی نکند.
  7. PRIu32. PRIu32 رشته‌ای است که کامپایلر بسته به پلتفرم می‌سازد: روی PC معمولا "u" و روی arm-none-eabi-gcc (STM32) "lu" است. چسباندن آن به قالب ("%" PRIu32) چاپ را همه‌جا درست می‌کند. اگر %u بنویسی و uint32_t روی پلتفرمی (مثل STM32) unsigned long باشد، قالب و نوع نمی‌خواند و -Wall هشدار می‌دهد. چسباندن رشته‌ها: در C دو رشتهٔ کنار هم یکی می‌شوند ("a" "b" می‌شود "ab")؛ پس "ticks = %" PRIu32 "\n" غلط تایپی نیست، بلکه سه تکه است که کامپایلر به هم می‌چسباند.
  8. پایان. UINT8_MAX و UINT32_MAX حداکثر هر نوع‌اند.

قاعدهٔ انتخاب نوع در embedded
  1. رجیستر و پروتکل: همیشه نوع اندازه‌ثابت (uint32_t برای رجیستر ۳۲بیتی، uint8_t برای بایت).
  2. داده‌ای که علامت ندارد (شمارنده، اندیس، وضعیت): بی‌علامت.
  3. کوچک‌ترین نوعی که همهٔ مقدارهای ممکن را جا بدهد (ولی در حساب معمولی روی ۳۲بیتی‌ها، خود int هم سریع‌تر و بی‌ضرر است).
  4. int ساده فقط برای شمارنده‌های حلقه و مقدارهای کوچک محلی.
زیر کاپوت: چرا uint8_t گاهی به int بالا می‌رود

پردازنده‌های ۳۲بیتی معمولا حساب را با ۳۲ بیت انجام می‌دهند. زبان C هم قانونی دارد به اسم ارتقای صحیح (integer promotion): هر نوعی که از int کوچک‌تر است، موقع حساب اول به int تبدیل می‌شود. پس در level + 1 اول level به int بالا می‌رود، جمع در ۳۲ بیت انجام می‌شود و فقط وقتی نتیجه را دوباره در level می‌گذاری، بالای ۸ بیتش دور ریخته می‌شود. نتیجه همان چرخش است.

اگر stdint.h را نیاوری

رایج‌ترین خطای این درس، فراموش‌کردن #include <stdint.h> است. کامپایلر وقتی اسم uint8_t را می‌بیند و جایی تعریفش نکرده‌ای، این‌طور اعتراض می‌کند:

int main(void)
{
    uint8_t level = 200;
    return level;
}
  1. نوع ناشناخته. هیچ #include نیست؛ پس کامپایلر نمی‌داند uint8_t چیست. C هیچ نوعی به‌جز نوع‌های خود زبان (int، char، …) را خودکار نمی‌شناسد. uint8_t در stdint.h تعریف شده است.
nostdint.c: In function 'main':
nostdint.c:3:5: error: unknown type name 'uint8_t'

خطا را بخوان: «خط ۳، ستون ۵: نام نوع ناشناخته uint8_t». کامپایلرهای جدید حتی زیرش یک راهنمایی هم می‌نویسند («آیا #include <stdint.h> را فراموش کردی؟»). درمان: آن یک خط را به بالای فایل اضافه کن.

تبدیل نوع: وقتی دو ظرف با هم حرف می‌زنند

در برنامه‌ها مدام یک مقدار از ظرفی به ظرف دیگر می‌رود: int در uint8_t ریخته می‌شود، float به int تبدیل می‌شود، int با unsigned جمع می‌شود. به این کار تبدیل نوع (conversion) می‌گویند و دو گونه دارد:

  • ضمنی (implicit): کامپایلر خودش، بی‌سروصدا انجام می‌دهد.
  • صریح (explicit، یا cast): خودت با نوشتن نوع در پرانتز جلوی مقدار می‌خواهی: (uint8_t)big.

مثل ریختن آب از پارچ در لیوان: اگر لیوان کوچک‌تر است، بقیه ریخته می‌شود دور. C در تبدیل‌های «به ظرف کوچک‌تر» چیزی هشدار نمی‌دهد (مگر پرچم‌های خاص بگذاری). دو تبدیل خطرناک:

  • ظرف کوچک‌تر: بیت‌های بالا دور ریخته می‌شود (۳۰۰ در uint8_t می‌شود ۴۴).
  • اعشاری به صحیح: قسمت اعشار بریده می‌شود، گرد نمی‌شود (۳٫۹۹ می‌شود ۳).
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    int big = 300;
    uint8_t small = (uint8_t)big;
    float price = 3.99f;
    int whole = (int)price;
    double half = 7 / 2;

    printf("300 in uint8_t = %u\n", (unsigned)small);
    printf("3.99 as int    = %d\n", whole);
    printf("double half    = %.1f\n", half);
    return 0;
}
  1. به ظرف کوچک‌تر. ۳۰۰ در دودویی 1 0010 1100 است (۹ بیت). فقط ۸ بیت پایین (0010 1100 = ۴۴) در small می‌ماند. نوشتن (uint8_t) یعنی «می‌دانم دارم می‌برم؛ عمدی است». خود کامپایلر هم همین را انجام می‌داد، ولی صریح‌بودن نیت را برای خواننده روشن می‌کند.
  2. اعشاری به صحیح. 3.99f را با (int) به 3 تبدیل می‌کنیم؛ اعشار بریده می‌شود. حرف f در انتهای عدد یعنی «این عدد float است» (بعدا در «پسوندها»).
  3. تله: تقسیم پیش از تبدیل. 7 / 2 هر دو صحیح‌اند؛ پس تقسیم صحیح انجام می‌شود (۳) و بعد ۳ به double تبدیل می‌شود (۳٫۰). سمت چپ بودنِ double چیزی را عوض نمی‌کند. نوع نتیجه فقط از نوع دو طرف عملگر معلوم می‌شود، نه از جایی که نتیجه را می‌گذاری. برای ۳٫۵ باید یکی را اعشاری کنی: 7 / 2.0.
  4. چاپ. %.1f یعنی «اعشاری با یک رقم بعد از ممیز».
$ ./conv

3.99 as int    = 3
double half    = 3.0

دام بزرگ‌تر: مخلوط علامت‌دار و بی‌علامت

وقتی int و unsigned int در یک عبارت باشند، C اولی را به بی‌علامت تبدیل می‌کند. آن‌وقت عدد منفی، ناگهان یک عدد بسیار بزرگ می‌شود:

پیش‌نمایش: if و else

در مثال بعد if می‌بینی. if (شرط) { A } else { B } یعنی «اگر شرط درست بود A را اجرا کن، وگرنه B را». اینجا فقط همین‌قدر لازم است؛ درس ۲.۴ کامل توضیحش می‌دهد.

#include <stdio.h>

int main(void)
{
    int a = -1;
    unsigned int b = 1;

    if (a < b) {
        printf("-1 is less than 1\n");
    } else {
        printf("surprise: -1 is NOT less than 1\n");
    }
    return 0;
}
  1. دو مقدار. یکی منفی، یکی بی‌علامت.
  2. مقایسه. برای مقایسه، a به unsigned تبدیل می‌شود: بیت‌های -1 همه ۱ است، یعنی ۴۲۹۴۹۶۷۲۹۵. آن‌وقت «۴٫۲ میلیارد کوچک‌تر از ۱» نادرست است. این قانون «تبدیل حسابی معمول» است: اگر یکی بی‌علامت و هم‌اندازه باشد، دیگری هم بی‌علامت می‌شود.
  3. پایان.
$ gcc -std=c11 -Wall -Wextra -o mix mix.c
mix.c:8:11: warning: comparison of integer expressions of different signedness: 'int' and 'unsigned int' [-Wsign-compare]

$ ./mix
surprise: -1 is NOT less than 1

خوشبختانه کامپایلر این را هشدار داد (پرچم -Wextra که همیشه می‌گذاریم). برای همین می‌گوییم هشدار را جدی بگیر. درمان معمولا این است که هر دو طرف هم‌نوع باشند.

عدد اعشاری: float و double

برای عددهایی مثل ۳٫۱۴ یا ۰٫۰۰۱ نوع اعشاری (floating-point) داریم: float (۳۲ بیت) و double (۶۴ بیت). نام «شناور» از اینجا می‌آید که ممیز اعشاری در نمایش داخلی «شناور» است، مثل نمایش علمی ۱٫۲۳×۱۰⁵.

مهم‌ترین چیز: چون فقط تعداد محدودی بیت داریم، بیشتر عددهای اعشاری دقیق ذخیره نمی‌شوند؛ درست مثل اینکه ۱/۳ را در ده‌دهی نمی‌توان با تعداد محدود رقم نوشت (۰٫۳۳۳…). در دودویی ۰٫۱ چنین حالتی دارد.

#include <stdio.h>

int main(void)
{
    double x = 0.1 + 0.2;
    float big = 16777216.0f;

    printf("0.1 + 0.2 = %.17f\n", x);
    printf("equal to 0.3? %d\n", x == 0.3);
    printf("big + 1 = %.1f\n", (double)(big + 1.0f));
    printf("7 / 2 = %d, 7 / 2.0 = %.1f\n", 7 / 2, 7 / 2.0);
    return 0;
}
  1. جمع دو عدد ساده. ۰٫۱ و ۰٫۲ در دودویی بی‌پایان‌اند؛ هر کدام کمی گرد شده ذخیره می‌شوند و جمعشان دقیقا ۰٫۳ نیست.
  2. عددِ بزرگ. ۱۶۷۷۷۲۱۶ برابر ۲²⁴ است. float فقط ۲۴ بیت رقم دارد، پس بعد از این عدد فاصلهٔ بین دو عدد قابل‌نمایش ۲ است.
  3. چاپ با ۱۷ رقم. %.17f رقم‌های پنهان را نشان می‌دهد: 0.30000000000000004.
  4. مقایسه با ==. x == 0.3 نادرست است! مقایسه عدد 0 (نادرست) یا 1 (درست) می‌دهد و %d همان را چاپ می‌کند؛ پس 0 یعنی «برابر نیست». به همین دلیل اعداد اعشاری را هرگز با == مقایسه نمی‌کنیم؛ می‌پرسیم «اختلافشان از یک تلورانس کوچک کمتر است؟» (درس ۲.۴).
  5. ۱ اضافه به عدد بزرگ. big + 1.0f همان big می‌ماند: ۱ آن‌قدر کوچک است که در دقت float ناپدید می‌شود.
  6. تقسیم صحیح و اعشاری. دو صحیح ← تقسیم صحیح ۳. یکی اعشاری ← ۳٫۵. (عملگرها در درس ۲.۳ می‌آیند.)
$ ./flt
0.1 + 0.2 = 0.30000000000000004
equal to 0.3? 0
big + 1 = 16777216.0
7 / 2 = 3, 7 / 2.0 = 3.5
در میکروکنترلر: FPU

انجام حساب اعشاری برای پردازنده سخت است. بعضی تراشه‌ها یک واحد سخت‌افزاری برای آن دارند، به اسم FPU (واحد ممیز شناور). STM32F411 (هستهٔ Cortex-M4F) و ESP32 کلاسیک، FPU تک‌دقت دارند؛ یعنی float سریع است، ولی double با نرم‌افزار محاسبه می‌شود و چندین برابر کندتر است. هستهٔ Cortex-M0 اصلا FPU ندارد و حتی float را با نرم‌افزار حساب می‌کند. نتیجه: در میکروکنترلر، اگر float لازم داری همان را بگیر، به double نرو، و هر جا بشود از عدد صحیح مقیاس‌دار (مثل ۲۳۵ به‌جای ۲۳٫۵ درجه) استفاده کن.

کاراکتر: یک عدد کوچک با ظاهر حرف

کامپیوتر حرف نمی‌شناسد؛ فقط عدد. برای اینکه حرف‌ها را ذخیره کنند، به هر حرف یک کد داده‌اند (جدول ASCII؛ یادت هست در ۱.۲؟): 'A' = ۶۵، 'a' = ۹۷، '0' = ۴۸. نوع char ظرف یک‌بایتی برای همین کدهاست. یعنی char در اصل یک عدد کوچک است که printf با %c به‌صورت حرف نشانش می‌دهد و با %d به‌صورت عدد.

#include <stdio.h>

int main(void)
{
    char c = 'A';
    printf("%c is %d\n", c, c);
    c = c + 1;
    printf("%c is %d\n", c, c);
    printf("digit 7 as text: %d\n", '7' - '0');
    return 0;
}
  1. ساختن. گیومهٔ تکی 'A' یعنی «کد حرف A» (۶۵). گیومهٔ دوتایی "A" چیز دیگری است (رشته؛ درس ۲.۸).
  2. یک مقدار، دو نمایش. %c همان ۶۵ را به‌صورت حرف می‌نویسد و %d به‌صورت عدد.
  3. حرف بعدی. ۶۵+۱ = ۶۶ = حرف B. حساب روی حرف‌ها همان حساب روی عدد است.
  4. رقم متنی به عدد. کد '7' برابر ۵۵ است و کد '0' برابر ۴۸؛ اختلافشان همان ۷ واقعی است. ترفند همیشگی برای تبدیل رقم نوشته‌شده به عدد.
$ ./chr

B is 66
digit 7 as text: 7
char با علامت است یا بی‌علامت؟ معلوم نیست!

استاندارد C نگفته char ساده با علامت است یا بی‌علامت. روی بسیاری از سیستم‌های x86 با علامت است و روی ARM (مثل STM32) معمولا بی‌علامت. پس برای «عدد کوچک» از char استفاده نکن؛ int8_t یا uint8_t بنویس و char را فقط برای متن نگه دار. جزئیات در درس ۶.۲.

درست و نادرست: bool

گاهی فقط یک «بله/خیر» می‌خواهی: در باز است؟ دکمه فشرده شده؟ در C پایه نوع ویژه‌ای برای این نبود؛ صفر را «نادرست» و هر چیز دیگر را «درست» می‌گرفتند. از C99 کتابخانهٔ stdbool.h نوع bool را با مقدارهای true و false می‌دهد. کد خواناتر می‌شود:

#include <stdbool.h>

bool door_open = false;   // به‌جای int door_open = 0;

در واقع bool یک بایت در RAM جا می‌گیرد (نه یک بیت). اگر ۸ پرچم داری و RAM کم است، می‌توانی آن‌ها را در بیت‌های یک uint8_t بگنجانی؛ در درس ۳.۱ همین کار را با عملگر بیتی می‌کنیم.

در STM32 و ESP32 یعنی چه؟

سه قاعده که هر برنامه‌نویس میکروکنترلر دارد:

  1. RAM کم است. STM32F411 دارد ۱۲۸ کیلوبایت؛ اگر آرایه‌ای با ۱۰۰۰۰ عنصر int بسازی، ۴۰ کیلوبایت رفته است. اگر مقدارها همه زیر ۲۵۶ هستند، uint8_t همان آرایه را در ۱۰ کیلوبایت جا می‌دهد.
  2. رجیسترها اندازهٔ مشخص دارند. رجیستر ۳۲ بیتی ↔ uint32_t. اسم‌گذاری مطابق سخت‌افزار جلوی اشتباه را می‌گیرد (درس ۳.۶).
  3. سرریز واقعی است. اگر شمارندهٔ میلی‌ثانیه‌ات uint16_t باشد، بعد از ۶۵٫۵ ثانیه به صفر برمی‌گردد. با uint32_t حدود ۴۹ روز دوام می‌آورد. دستگاهی که ماه‌ها روشن می‌ماند باید این را حساب کند.
ادامه برای کنجکاوها: وارسی اندازه‌ها با کامپایلر ARM و _Static_assert

اگر arm-none-eabi-gcc نصب نداری، این بخش را رد کن؛ چیزی از ادامهٔ دوره کم نمی‌شود.

حالا ادعای «int در ARM ۴ بایت است» را با کامپایلر واقعی ARM (arm-none-eabi-gcc) وارسی کنیم. _Static_assert در زمان کامپایل شرطی را می‌سنجد و اگر نادرست باشد، کامپایل را متوقف می‌کند:

#include <stdint.h>

_Static_assert(sizeof(int) == 4, "int must be 32 bits");
_Static_assert(sizeof(long) == 4, "long must be 32 bits");
_Static_assert(sizeof(void *) == 4, "pointers must be 32 bits");
_Static_assert(sizeof(float) == 4, "float must be 32 bits");
_Static_assert(sizeof(double) == 8, "double must be 64 bits");

uint16_t adc_average(uint16_t a, uint16_t b)
{
    uint32_t sum = (uint32_t)a + b;
    return (uint16_t)(sum / 2U);
}
  1. پنج ادعا دربارهٔ اندازه‌ها. هر _Static_assert یک شرط و یک پیام دارد. اگر شرط نادرست باشد، کامپایل با آن پیام قطع می‌شود؛ برنامه‌ای که ساخته شود، یعنی هر پنج ادعا برای ARM Cortex-M4 درست است. این روش ارزان‌ترین راه گرفتن اشتباه انتقال کد بین پلتفرم‌هاست: زمان اجرا هزینه‌ای ندارد و اشتباه در همان کامپایل معلوم می‌شود.
  2. میانگین دو خوانش ADC. ADC (مبدل آنالوگ به دیجیتال) ولتاژ را به عدد ۰ تا ۴۰۹۵ تبدیل می‌کند؛ پس uint16_t کافی است. ولی جمع دو عدد ۱۶ بیتی ممکن است از ۶۵۵۳۵ بگذرد، پس اول به uint32_t می‌بریم (ظرف بزرگ‌تر) و بعد جمع می‌کنیم. اگر جمع را در uint16_t انجام می‌دادی، برای دو عدد بزرگ چرخش می‌شد و میانگین اشتباه درمی‌آمد.
  3. تقسیم و برگرداندن. تقسیم بر ۲ و بازگرداندن به ۱۶ بیت؛ نتیجه حتما در ۱۶ بیت جا می‌شود چون میانگین از بیشینهٔ دو عدد بزرگ‌تر نیست.

این کد فقط کامپایل می‌شود (سؤال «آیا اجرا می‌شود؟» بی‌معنی است چون تابع main ندارد و برای بارگذاری روی برد نیست)؛ خروجی نمایشی ندارد. کامپایل بدون خطا یعنی هر پنج ادعا درست است.

خلاصهٔ تصویری از مثال قفسه‌ها

قاشق (uint8_t)، لیوان (uint16_t)، پارچ (uint32_t)، سطل (uint64_t). ظرف را با حجم چیزی که می‌ریزی انتخاب کن؛ نه بزرگ‌تر از لازم (RAM کم است) و نه کوچک‌تر (سرریز می‌شود). و همیشه اسم ظرف، اندازه‌اش را بگوید.

تمرین ۱: جدول محدوده‌ها

می‌خواهیم با stdint.h خودمان محدودهٔ چهار نوع را ببینیم.

  1. پیش‌بینی: بدون اجرا، محدودهٔ int16_t چیست؟ (راهنمایی: ۱۶ بیت، نیمی منفی.)
  2. حل: برنامه‌ای بنویس که کمینه و بیشینهٔ int8_t، uint8_t، int16_t و uint16_t را با ثابت‌های INT8_MIN، INT8_MAX و… چاپ کند.
  3. چالش: حدس بزن محدودهٔ int32_t چیست و با INT32_MIN و INT32_MAX ببین درست گفتی یا نه (با cast به int مثل (int)INT32_MAX و قالب %d چاپ کن؛ چرا cast؟ چون روی ARM نوع int32_t همان long است و بدون cast، -Wall هشدار می‌دهد).
راهنمایی

ثابت‌های INTn_MIN و INTn_MAX در stdint.h هستند. چون کوچک‌تر از int‌اند، با %d چاپشان درست است. برای uint کمینه همیشه صفر است، پس آن را خودت بنویس.

چه باید ببینی؟ 
$ ./ex1

int16_t: -32768 .. 32767

جواب کامل با توضیح 
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    printf("int8_t : %d .. %d\n", INT8_MIN, INT8_MAX);
    printf("uint8_t: 0 .. %d\n", UINT8_MAX);
    printf("int16_t: %d .. %d\n", INT16_MIN, INT16_MAX);
    printf("uint16_t: 0 .. %d\n", UINT16_MAX);
    return 0;
}
  1. کتابخانه. ثابت‌های حد در stdint.h هستند.
  2. هشت بیتی‌ها. کمینه و بیشینه را از ثابت‌ها می‌گیریم، نه از حفظ. برای uint8_t کمینه صفر است. این ثابت‌ها روی هر پلتفرم درست‌اند؛ اگر عدد ۱۲۷ را دستی بنویسی، ممکن است اشتباه تایپی کنی.
  3. شانزده بیتی‌ها. UINT16_MAX (۶۵۵۳۵) کوچک‌تر از INT_MAX است، پس با %d درست چاپ می‌شود. این کار برای UINT32_MAX جواب نمی‌دهد (چهار میلیارد در int نمی‌گنجد)؛ آنجا PRIu32 لازم است.

int16_t: -32768 .. 32767

تمرین ۳: شمارندهٔ زمان میکروکنترلر

یک دستگاه با تراشهٔ STM32 هر میلی‌ثانیه یک شمارنده را یک واحد زیاد می‌کند. تیم دو طرح دارد: uint16_t یا uint32_t.

  1. پیش‌بینی: به‌نظرت شمارندهٔ ۱۶ بیتی بعد از چند ثانیه به صفر برمی‌گردد؟ (با 65535 ÷ 1000 حساب کن.)
  2. حل: برنامه‌ای بنویس که مقدار uint16_t ms16 = 65530 را ۱۰ واحد جلو ببرد و چاپ کند؛ سپس با UINT32_MAX حساب کن شمارندهٔ ۳۲ بیتی چند روز کامل دوام می‌آورد.
  3. تصمیم: برای هر مورد نوع مناسب را بگو: (۱) ولتاژ باتری تا ۴۲۰۰ میلی‌ولت، (۲) دما از ۴۰- تا ۱۲۵ درجه با دقت یک رقم اعشار به‌صورت عدد صحیح (یعنی ۴۰۰- تا ۱۲۵۰)، (۳) شمارندهٔ زمان دستگاهی که ماه‌ها روشن می‌ماند.
راهنمایی

اگر PRIu32 یادت نیست، cast به unsigned هم کافی است ((unsigned)(ms32 / 1000U / 60U / 60U / 24U) با %u). برای ب: ms32 / 1000U / 60U / 60U / 24U روز را می‌دهد (چهار تقسیم پشت هم: ثانیه، دقیقه، ساعت، روز). برای پ: ببین هر مقدار در چند بیت جا می‌شود و آیا منفی می‌شود یا نه.

چه باید ببینی؟ 
$ ./timers
16-bit ms counter after +10: 4
32-bit counter lasts 49 days
16-bit counter lasts 65 seconds

جواب پ: (۱) uint16_t (۰ تا ۴۲۰۰)، (۲) int16_t (منفی دارد و از ±۳۲۷۶۷ کم‌تر است)، (۳) uint32_t.

جواب کامل با توضیح 
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void)
{
    uint16_t ms16 = 65530;
    uint32_t ms32 = UINT32_MAX;

    ms16 = ms16 + 10;
    printf("16-bit ms counter after +10: %u\n", (unsigned)ms16);
    printf("32-bit counter lasts %" PRIu32 " days\n", ms32 / 1000U / 60U / 60U / 24U);
    printf("16-bit counter lasts %u seconds\n", (unsigned)(UINT16_MAX / 1000U));
    return 0;
}
  1. شمارندهٔ کوچک. ۶ واحد مانده تا سقف (۶۵۵۳۵).
  2. شمارندهٔ بزرگ. UINT32_MAX بیشینهٔ ۳۲ بیتی است (۴٬۲۹۴٬۹۶۷٬۲۹۵ میلی‌ثانیه).
  3. ۶۵۵۳۰+۱۰. ۶۵۵۴۰ از سقف می‌گذرد؛ ۶۵۵۴۰−۶۵۵۳۶ = ۴. شمارنده به ۴ برمی‌گردد. در دستگاه واقعی این یعنی: هر ۶۵ ثانیه ساعت داخلی ناگهان به صفر می‌رسد و هر منطقی که به «زمان گذشته» تکیه کند خراب می‌شود.
  4. تعداد روز. تقسیم‌های صحیح پشت هم روی بی‌علامت؛ نتیجه ۴۹ (اعشارش بریده شده؛ ۴۹٫۷ روز). حرف U پشت عددها تا مقایسه و حساب همه بی‌علامت بماند (دام تبدیل‌ها).
  5. حداکثر ثانیه در ۱۶ بیت. ۶۵ ثانیه.

خلاصه یک‌دقیقه‌ای

  • هر نوع = تعداد ثابتی بایت + شیوهٔ خواندن آن بایت‌ها. n بیت = ۲ⁿ حالت.
  • بی‌علامت: ۰ تا ۲ⁿ−۱. با علامت: −۲ⁿ⁻¹ تا ۲ⁿ⁻¹−۱ (مکمل ۲).
  • اندازهٔ int و long به پلتفرم بستگی دارد؛ uint8_t، int16_t، uint32_t (از stdint.h) اندازه را تضمین می‌کنند.
  • سرریز بی‌علامت می‌چرخد (قانونی)؛ سرریز با علامت رفتار تعریف‌نشده است.
  • تبدیل به ظرف کوچک‌تر بیت‌ها را می‌بُرد؛ اعشاری به صحیح اعشار را می‌بُرد؛ مخلوط int و unsigned منفی را عدد بزرگ می‌کند.
  • float تقریبی است (۰٫۱+۰٫۲ ≠ ۰٫۳)؛ آن را با == مقایسه نکن. در MCU بدون FPU کند است.
  • پسوندها: U، L، LL، f. کاراکتر 'A' در C یک int است.
  • برای چاپ uint32_t از PRIu32 استفاده کن؛ و نوع‌های کوچک‌تر را با cast به int/unsigned چاپ کن.
